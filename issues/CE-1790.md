At machine precision, a power of a float has another value when its integer exponent is computed than when the exponent is written as a number.

## Witness

```ts
const ce = new ComputeEngine();
ce.precision = 'machine';
ce.box(['Power', 1.1, 9]).evaluate();             // 2.357947691000002 (Math.pow)
ce.box(['Power', 1.1, ['Add', 4, 5]]).evaluate(); // 2.357947691
```

## Cause

`apply2()` (`boxed-expression/apply.ts`) calls the big-decimal kernel when an
operand has a big decimal, also at machine precision. An exact integer has
one (`bignumRe`), so `Power(1.1, 4 + 5)` is computed from the decimal
`1.1` at 15 digits (`ce.precision`), and the literal exponent `9` takes
the double kernel of `apply()`. The kernels round to 15 digits, so a
result can also have fewer digits than a double. Compiled code gives
`Math.pow`.

Options: (a) at machine precision, an exact safe integer alone does not
select the big-decimal kernel. This breaks the documented lane of
`Remainder` (`test/compute-engine/remainder-float-lanes.test.ts`,
`Remainder(-825977087020874, 0.7)` is `-0.1` from the decimal `0.7`) and a
pin of `ir-interval-containment.test.ts`, so the choice must be made per
operator. (b) compute this lane at `DOUBLE_DIGITS`, as CE-1761 does for a
float with a big decimal: this changes the pinned case "the cosine of π^4
in a Mod" of `ir-slice-random.test.ts`, whose classifier expects the
machine engine to give `Math.pow`.
