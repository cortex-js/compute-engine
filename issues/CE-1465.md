`RotateLeft(S, N)` with a count `N` of type `real` declines on 0.194.0; 0.193.0 compiled it.

## Witness

`RotateLeft(S, N)` with `S: list<real>` = `[1, 2, 3, 4]` and `N: real` = 2.
0.193.0 compiled: `[3, 4, 1, 2]`. 0.194.0: "a count that is not an
integer".

In Tycho, `N` is a slider, whose type is `real` (in Desmos import,
`nan | real | signed_infinity`): the Game of Life neighbour sum
`RotateLeft(S, N) + RotateLeft(S, -N) + …`.

The interpreter gives `[3, 4, 1, 2]` too: `RotateLeft` returns a lazy view,
whose printed form looks unevaluated. The instrument reads its elements.

## Expected

The compiled code takes the count with a run-time integer test, and
errors where the interpreter errors (ce-compiler's reading).

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1465: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, corrected the same day): the interpreter gives a value.
`RotateLeft` returns a lazy view, and its printed form looks unevaluated; read
element by element (`At(RotateLeft(S, N), i)`), with `N: real`, it gives
`[3, 4, 1, 2]` at `N = 2`, `[4, 1, 2, 3]` at `N = -1`, and an
`incompatible-type` error at `N = 2.4`, the same with `withValues` and
`assign`. So the decline is a regression. P3 stands (minor, medium, plus
`regression`). Disposition: proposed for the next release, with the queue of
the other regressions (CE-1469, CE-1464, CE-1466): the compiled code tests
at run time that the count is an integer and throws otherwise (a throw where
the interpreter gives an error is within the caveats). Workaround meanwhile:
declare the slider `integer`, or write `RotateLeft(S, Round(N))`; both
compile and give `[3, 4, 1, 2]` (`Round` also accepts 2.4, where the
interpreter gives an error).
