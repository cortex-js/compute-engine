A sum whose index condition reads a subscript of the index, such as `a_{k+1} > 0`, gives a type error instead of a value.

## Witness

```
ce.parse('\\sum_{k\\in\\{1,2,3\\}, a_{k+1}>0} a_k')
  ->  ["Sum", …, ["Element", "k", ["Set", 1, 2, 3],
        ["Error", ["ErrorCode", "incompatible-type", "'boolean'", "'set<integer>'"]]]]
ce.box(['Sum', ['Subscript', 'a', ['Add', 'k', 1]],
  ['Element', 'k', ['Set', 1, 2, 3], ['Greater', ['Subscript', 'a', ['Add', 'k', 1]], 0]]])
  ->  the same error   (probe 2026-11-06, HEAD de32ad1b46faa5e22375316f91418a93750032d0)
expected  ->  the sum of the terms whose condition is true
```

## Cause and options

Not traced. `canonicalIndexingSet()` (`library/utils.ts`) builds
`ce.function('Element', [index, collection, condition.canonical])`, and the
check of the third operand fails when the condition holds a `Subscript`. A
condition of a plain symbol (`a_k > 0`) does not fail.

When this is fixed, the condition must also read a subscript on the index by
value, as the body does since CE-135: the LaTeX parser (`parseBigOp()`,
`definitions-arithmetic.ts`) should apply `_subscriptBoundIndexes()` to the
clause too. Today `\sum_{k\in S, a_k>0} a_k` reads `a_k` as one name in the
condition and as `a` indexed by `k` in the body.
