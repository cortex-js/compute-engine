The last statement of an Epsil program can run for twice the time limit of a statement when its value is a lazy collection.

## Witness

With a host function `now()` that returns `Date.now()`:

```
function spin(ms) { let end = now() + ms; let i = 0; while now() < end { i = i + 1 }; ms }
do { spin(150); map(u => spin(20), 1..6) }
```

`executeEpsil(ce, source, { statementTimeLimitMs: 200 })` gives
`[20,20,20,20,20,20]` after about 270 ms. The statement takes 150 ms and the
computation of the six elements takes 120 ms: each part is under 200 ms, and
the two together are over it. The value must be
`["Error", message, "timeout"]`. `executeEpsilAsync` gives the same result.
The witness is `crafted`: the statement and its elements must each take a
large part of the limit.

## Cause and options

`executeEpsil()` computes the elements of a lazy collection that is the value
of the program (`listedFinalValue()`, `src/epsil/execute-epsil.ts`) when the
engine reports the last statement (`_epsilStatementResultHook`). The span of
the statement (`ce.withTimeLimit({ ms: ce._epsilStatementTimeLimitMs })` in
`evaluateStatements()` and `evaluateStatementsAsync()`,
`src/compute-engine/function-utils.ts`) is closed then, so the walk runs in a
second span of the same limit. The doc comment of `statementTimeLimitMs`
says so. The time is bounded: before CE-1601 the elements of a final
comprehension had no statement limit at all.

The Epsil side cannot compute the time that the statement has left: the time
from the end of the report of the statement before it includes the time
that a debugger keeps the program stopped in its statement hook (the VS Code
debugger, `vscode-epsil/src/debug-worker.ts`, blocks there and sets
`statementTimeLimitMs`), and that time must not count. A first fix that
measured from there was removed for this reason.

(a) Recommended: the statement loop gives the hook the deadline frame of the
span of the statement (a fifth argument of `_epsilStatementResultHook`), and
`listedFinalValue()` runs the walk in that frame. The two parts then share
one deadline, on the clock of the run. Size M: two statement loops and the
type of the hook.

(b) Keep the second span and the documented bound of twice the limit.
