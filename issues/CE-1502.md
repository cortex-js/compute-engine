A function of the plot variable called inside another function whose parameter has the same name no longer compiles.

## Witness

`x, y: real`; `k := Function(Add(v, x), v)` (k reads the input `x`);
`u := Function(Add(Power(k(0), 2), Power(y, 2)), x, y)`;

```
u(x, y)
```

compiled to javascript with `inputs: { x: 'real', y: 'real' }`, run at
x = 10, y = 2.

- Interpreter (0.193.0 and 0.194.x): 104, that is (0 + 10)^2 + 2^2: `k`
  reads the input `x` (lexical scope), not `u`'s parameter `x`.
- 0.193.0 compiled: 104.
- CE main 4779733bb6c5bdf3e12e30dc5e56305c8a069304: "k(0): a call of k, which
  reads the input x, where x is a local or a parameter".

CE-1479 fixed the same call where the shadowing name is a `Sum` index. The
IR README ("User functions") lists the parameter case (`h(x) := k(x)`) as
declined; compute-engine-8c (2026-11-18): a missing capability, not a
correctness rule, so a regression to fix. In Tycho, a document function or
macro whose implicit parameter is named after a plot axis calls a function
of that axis (the three tests in `source-ref`).

## Expected

The call compiles and reads the input `x`, with the interpreter's value.
