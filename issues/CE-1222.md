A compiled expression whose value is a captured list returns the array that the compiled function holds for every call: a host that writes the result changes the value of every later call.

## Witness

At `5d5060724` (main), JavaScript target, `cse: false, constantFold: false`:

```ts
const ce = new ComputeEngine();
ce.declare('L', { type: 'list<integer>', value: ['List', 10, 20, 30] });
const f = compile(ce.box('L'), { cse: false, constantFold: false });
f.code;          // "_val_L"
f.preambleOnce;  // "const _val_L = [10, 20, 30];\n"
const v = f.run({});
v[0] = 999;
f.run({});       // [999, 20, 30]
```

The value of `L` in the engine stays `[10, 20, 30]`, and the interpreter
gives `[10, 20, 30]` at each evaluation. Other places where the hoisted
array can become the value (a branch of an `If`, a local, the result of a
user function) were not checked.

The profile `numeric-kernel` returns a copy where the value can be the
array of a constant (`_tv1.slice()`, `rootYieldsUnique()` in
`structured-in-place.ts`), and gives `[10, 20, 30]` at the second call.

## Cause and options

`tryFoldKnownSymbol()` (`compile-folded-values.ts`) binds the value once
per artifact (`hoistable`) and writes its name at each read. An update
copies it (`_SYS.replaceAt`, or `_SYS.ownedCopy` before an update in
place), but a read that becomes the value of the code gives the array to
the host. Option: copy a hoisted `_val_…` array where it can be the value
of the compiled code, as the update copies it where it is written.
