In a scope where the user defines a function named `Power`, the reciprocal of a power with a symbolic exponent becomes a call of the user's function, and gives a wrong value.

## Witness

At commit `58629ce35b7bc2c501fed918294e0fe9fad23b09`:

```ts
ce.pushScope();
ce.declare('Power', 'function');
ce.assign('Power', ce.expr(['Function', ['Add', 'a', 'b', 100], 'a', 'b']));
const y = ce.symbol('y');
const x = ce.symbol('x');
const e = ce._libraryCall('Power', [y, x])!.inv();
e.json                          // ["Power", "y", ["Negate", "x"]], bound to the user Power
e.subs({ x: 2, y: 3 }).N()      // 101; must be 1/9
ce.popScope();
```

`crafted`: the program defines a user function with the capitalized name of
a library function and takes a reciprocal in its scope.

## Cause and options

`BoxedFunction.inv()` (`boxed-expression/boxed-function.ts`) writes the
reciprocal of a library `Power` (and of a library `Root`) with
`this.engine.function('Power', …)` and `this.engine.function('Root', …)`,
which bind the call by its name in the current scope. Option: build the call
with `ce._libraryCall()` when `shadowsLibraryName()` is true, with a fallback
to `ce.function()`, as `libraryPower()` in `arithmetic-mul-div.ts` does
(CE-1759). Related: CE-1792.
