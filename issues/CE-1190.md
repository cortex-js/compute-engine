A double sum whose inner range depends on the outer index gives no number.

## Witness

`Sum(i*j, Limits(i, 1, 3), Element(j, Range(1, i)))` evaluates to itself,
unevaluated. The same sum with `Limits(j, 1, i)` in place of the `Range`
gives 25, and a `Range` with constant bounds,
`Sum(i*j, Element(j, Range(1, 3)), Limits(i, 1, 3))`, gives 36. The GLSL
target compiles the first form to 25 (it nests the sum, first index
outermost), so the compiled value and the interpreter differ.

Impact `minor`: the `Limits` form is a workaround. Probability `medium`: a
triangular sum written with `Range` is a one-line program a user writes.

## Cause and options

Not traced. The `Range` index set is probably resolved once, before the
outer index has a value, and a `Range` whose bound is a symbol without a
value is not a finite set, so the sum stays unevaluated. Option: resolve a
`Range` index set at each value of the enclosing indexes, as `Limits` does
for its bounds. Size S if the evaluation of `Sum` and `Product` already has
one place that reads the index sets.
