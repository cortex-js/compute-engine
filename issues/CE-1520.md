A Tycho user who leaves a string or a bracket open in an Epsil code cell gets an error but no one-step fix.

## Witness

The instrument parses `let s = "abc`, `f(1, 2`, `let L = [1, 2` and
`if x > 0 { 1`. Against 0.193.0 each gives its error
(`string-literal-closing-delimiter-expected` [8,12],
`closing-bracket-expected` at the OPENING bracket) with `fixits []`.
Tycho's editor offers each fix-it of a diagnostic as an action (a menu entry
reached by keyboard, or a button), so a fix-it is all Tycho needs.

## Cause and options

Today the parser's only fix-its are for `asymmetric-operator-whitespace`,
`mapsto-arrow-legacy` and `match-case-separator` (ce-debugger, 2026-11-19).
Request:

- `string-literal-closing-delimiter-expected`: insert the delimiter at the
  end of the line;
- `closing-bracket-expected`: insert the closing bracket at the end of the
  input.

A fix-it is documented as a guess, so an imperfect insertion point is
acceptable. Not part of this request: a placeholder for `expression-expected`
and type names for `type-annotation-error`, which are completions (CE-1521).
Size S.

## CE answer

CE (2026-11-19): P3 confirmed, pool. Workaround: Tycho can build both fixes
itself. The first argument of the message is the missing delimiter or
bracket (`["closing-bracket-expected", ")"]`): insert it at the end of the
line for a string, at the end of the input for a bracket.

CE (2026-11-19): the insertion point of the request changes, from Tycho's
use of the workaround. At the end of the line is wrong when the line closes
a block after the string: `else if k % 5 == 0 { "Buzz }` would become
`"Buzz }"`. Rule for the fix-it, the one Tycho uses now: insert the
delimiter after the last character of the line that is neither whitespace
nor a closing bracket (`"Buzz" }`); when that position is not after the
opening quote, insert it at the end of the line. For
`closing-bracket-expected`, insert the bracket at the end of the input,
before trailing whitespace. Tycho drops its own fix when this ships.

CE (2026-11-19): a further case from Tycho: for `closing-bracket-expected`,
insert the bracket before a trailing line or block comment as well as before
trailing white space: `f(1 // note` gives `f(1) // note`, not
`f(1 // note)`, which keeps the error and changes the comment. Find the
comment with the lexer's tokens, not with a text search (a `//` inside a
string is not a comment).

CE (2026-11-20): fixed. `parseEpsil()` gives both fixits with the rules
above. Further cases: an unclosed bracket before another token (`f(1]`), an
unclosed `\(` hole and a string whose insertion would be an escape (`"C:\`)
get no fixit; a `\(…)` hole ends the scan back over closing brackets
(`"a \(x) )` gives `"a \(x)" )`); a multiline string gets `"""` on a new
line; an extended string gets `"#`.

Tycho (2026-11-20, CE 0.195.1 adoption): verified. Each case of the instrument
has a fix-it. Tycho's own closing fix (`closingAction` in
`src/graph-paper/notebook/cell-plugins/builtins/cortex-diagnostics.ts`) stays
ahead of CE's fix-it, because CE's fix-it of a string does not close it at the
caret (G11 of `requirements/todo/EPSIL_EDITOR_AND_DEBUGGER.md`). User decision
pending: (a) keep Tycho's fix and delete this file, or (b) a caret-aware
fix-it from CE.

CE (2026-11-20, decision (b)): fixed for 0.195.2. A `Fixit` has an optional
fourth element, a caret range `[start, end]`, both ends included. The fixit
of `string-literal-closing-delimiter-expected` has one for a single-line
string (`"`, `#"`) and a LaTeX island (`$`): the text after the opening
delimiter and after the last `\(…)` hole. With the caret in that range, the
editor inserts the delimiter at the caret (`{ "Buzz| }` gives
`{ "Buzz" }`); outside it, at the fixit's range, as before. A multiline string
(`"""`) has no caret range: its delimiter goes on a line of its own. The
fixit of `closing-bracket-expected` is unchanged. Adoption in Tycho: map the
fourth element `r` to `caretIn: [r[0] - 1, r[1]]` (`caretIn` excludes its
start) and remove `closingAction`. A caret just after a `\` in the range gives
an escape (`\"`), like any guess of a fixit.

## Decision

User decision 2026-11-20: (b)

Tycho half on adoption: remove `closingAction` from
`src/graph-paper/notebook/cell-plugins/builtins/cortex-diagnostics.ts`, so the
editor applies CE's fix-its, and give the instrument a `CE-1520:` line for the
caret-aware form.
