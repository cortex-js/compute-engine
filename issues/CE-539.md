Compiling an expression to a shader changes the type of its free variables to number for the rest of the session.

## Witness

```
compile a call of a user function with the free symbols x, y to a GPU target
before the compile: x, y have the type unknown;  after: number, for the life of the engine
```

## Cause and options

The GPU root inliners (`inlineCollectionValuedCallsAtRoot`, and
`inlineSharedUserFunctionCalls` in `compilation/gpu-shared-calls.ts`) substitute
the bodies of user functions with `subs()`, and as a side effect the engine
infers the free `x` and `y` as `number`. A compile must not change the
declarations of the symbols it reads.
