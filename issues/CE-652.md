A compiled sum whose bound has the same name as its index gives a wrong value, or throws when it runs.

## Witness

`Block(Declare(n); If(x > 3, n ≔ 5); Sum(n, Limits(n, 1, n)))` at `x = 5`: the
interpreter and Python give 15; JavaScript gives 1. With the lower bound
`Limits(n, n, 10)`, JavaScript throws a `ReferenceError` at run time. GLSL and
WGSL read the index in the loop test at each pass.

## Cause and options

JavaScript emits
`let n = 1; const _upper = Math.floor(n); …` (five template strings in
`javascript-target.ts`), so the bound reads the new index, and a lower bound
becomes `let n = n`. GLSL and WGSL emit
`for (int n = 1; n <= int(floor(n)); n++)`. Fix: every target evaluates the bounds before it declares the index,
or renames the index when a bound names it. `Product` too.
