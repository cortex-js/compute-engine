A series of a root of an expression that has a complex term of a high order has the wrong sign or the wrong value.

## Witness

At commit `4d9da3765bd5982bd8f48316d2d76171ca2c3554`, the value is `f − Normal(Series(f))`:

```
Series(Sqrt(-1 - i*x^20), x, 0, 3)     // i + O(x⁴)
                                       // x = −0.5: −2i;  x = 0.5: −2i
Series(Root(x + i*x^20, 3), x, 0, 3)   // ∛x + O(x^(14/3))
                                       // x = −0.5: 1.19 + 0.69i;  x = 0.5: 5e-7i
```

With the complex term at a low order, the `Series` stays unevaluated, as it must: `Series(Sqrt(-x^4 + i*x^5), x, 0, 3)`. The witness is `crafted`: the term that is not real is past the coefficients that the expansion computes.

## Cause and options

`symbolic/series.ts`, `puiseuxHoldsBelow()`: it proves that the base stays on the real axis with `hasRealCoefficients()`, which reads the coefficients up to the working window (`n + BIGO_LOOKAHEAD`) only. A term of a higher order that is not real moves the base across the cut of the root, or makes the real odd root not apply. The first program is wrong for `x > 0` too, because `−1 − i·x²⁰` is below the cut on both sides. Option (simple, sound): replace `hasRealCoefficients(ce, bs, m)` in `puiseuxHoldsBelow()` with `isRealOnRealAxis(base, x)`, which CE-1442 added for `lnLaurent()` and which reads the structure of the expression, not the window; apply the same test for a negative leading coefficient when `bothSides` is not set.
