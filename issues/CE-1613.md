An index written in another base does not round-trip through LaTeX: `Subscript(x, BaseForm(42, 2))` is written `x_{101010_{2}}`, which parses as the symbol `x_101010_2`.

## Witness

Main 2dfeb8f4c3d513647ce900bf335654cf5b008652:

```js
const e = ce.box(['Subscript', 'x', ['BaseForm', 42, 2]]);
e.json; // ["Subscript", "x", ["BaseForm", 42, 2]]
e.evaluate().json; // "x_42"
e.latex; // x_{101010_{2}}
ce.parse('x_{101010_{2}}').json; // "x_101010_2"
```

With a letter digit, `Subscript(x, BaseForm(42, 16))` is written
`x_{\text{2a}_{16}}`, which parses as the symbol `x_twoa_16`. The functional
form reads back as written: `x_{\operatorname{BaseForm}(42,16)}` parses to
`["Subscript", "x", ["BaseForm", 42, 16]]`.

The witness is crafted: no program was found that writes an index in another
base.

## Cause and options

Inside a subscript, the parser joins a numeral and its own subscript into the
name of a compound symbol, so the based numeral is not read as a number there.
Option (a): the serializer of `Subscript` writes an index that is a `BaseForm`
in the functional form, or as the plain number. Option (b): the parser reads a
based numeral inside a subscript. (a) is the smaller change.
