A function that builds a figure of Tycho's drawing library, or calls a function that the host declared, cannot be compiled, so a notebook animation that draws runs interpreted.

## Witness

On 0.195.1, after Tycho's drawing prelude (`circle`, `rotateAbout` and the
`Figure` type are Epsil definitions of the prelude) and a host function
declared with `ce.declare("hostDraw", { signature: "(any) -> nothing",
evaluate })`:

```
point     = (t: real) => (cos(t), sin(t))                → compiled
figure    = (t: real) => circle((cos(t), sin(t)), 0.2)   → declined: "the
            result of circle is not a scalar (Figure)"
moved     = (t: real) => circle((2, 0), 0.2).rotateAbout(t / 1000, (0, 0))
          → declined: "rotateAbout is not the library operator here (a user
            definition)"
callsHost = (t: real) => hostDraw(t)                     → declined: "hostDraw
            is not the library operator here (a user definition)"
```

Expected: the three compile. A figure can come back as plain data (the
MathJSON of the `Figure`, or a nested array of its fields), and a call of a
declared host function calls its `evaluate` from compiled code with the
argument converted to an expression (or to plain data).

## Cause and options

Two capabilities: (1) compiling user functions whose result is a value of a
user-declared type (`Figure`, a nominal type with a protocol), including the
protocol method `rotateAbout`; (2) calling a function declared by the host
(`ce.declare` with `evaluate`) from compiled code. (2) alone helps Tycho: a
callback could compute numbers compiled and pass them to a host function that
builds the picture. Options and their cost are for CE to assess; a plan
document may be needed for (1).

Tycho half on adoption: a notebook `timer` callback that calls `draw` with
figures compiles (`ce-notebook-evaluator.ts`, the C1 note in `finishRun`), and
the instrument prints `compiled` for `figure`, `moved` and `callsHost`.
