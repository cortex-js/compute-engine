The definitions of a scope that a host popped stay in memory while the factor memo of the engine holds an expression of that scope.

## Witness

A plain engine, with the garbage collector exposed:

```
ce.pushScope();
ce.assign('f', ce.box(['Function', ['Add', ['h', 'x'], 1], 'x']));
ce.assign('g', ce.box(['Function', ['Add', ['f', 'x'], 1], 'x']));
ce.box(['g', 2]).evaluate();
ce.popScope();
// yield to the event loop, then gc()
```

A heap snapshot then still holds the popped scope. The retainer path is
`ComputeEngine` as the key of `FACTOR_MEMO` (`boxed-expression/factor.ts`),
a `Map` entry `{ generation, input, output }`, the `input` `BoxedFunction`,
an operand `BoxedFunction` and its `_freeHeadScope`, which is the popped
scope. With `CE_CACHE_OFF=factor` the scope is collected.

The retention is bounded: the memo holds at most `MAX_FACTOR_MEMO_ENTRIES`
(4096) entries and is cleared when it is full. An entry of an older cache
generation is not served, but it stays until the memo is cleared.

## Cause and options

`factor()` stores the input and the output expressions strongly, keyed by
the digest of the input. An expression holds the scope of its free heads,
so an entry keeps the scope of each expression that was factored.

Options:

- (a) Drop the entries of an older generation at the first `factor()` call
  under a new generation. This releases a popped scope only if the pop, or
  a later edit, changes `_cacheGeneration()`: not verified. Size S.
- (b) Key the memo by the input expression in a `WeakMap`; the digest key
  then serves no lookup across equal expressions. Size S, but fewer hits.
- (c) No change: the retention is bounded by the memo size.
