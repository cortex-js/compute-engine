An incomplete `\u` escape before the closing quote of a string takes in the quote, so the string runs on to the end of the line.

## Witness

`parseEpsil('let s = "a\\u12" + 1')` gives `invalid-unicode-codepoint-string`
with the text `12"` and `string-literal-closing-delimiter-expected`, both with
the range `[8, 19]`: the string token takes in the closing `"` and ` + 1`.

## Cause and options

`scanEscapeSequence` in `src/epsil/lexer.ts` reads the 4-digit form `\uXXXX`
up to and including the first character that is not a hex digit. Stop before
that character, so that a `"` closes the string; the diagnostic text then
holds only the hex digits (`12`). The `\u{…}` form reads up to 9 characters
whatever they are and can take in the quote too (`"\u{12"`). The highlighter
(`escapeLength` in `src/epsil/highlight.ts`) copies this reading and changes
with it; the snapshots of `test/epsil/epsil-parse.test.ts` with `23g` change.
