A program that passes a range or a mapped list to a drawing function of the host runs in the slower interpreter.

## Witness

Checked at `0d3a3aba4b2401c5bb7a03ed9bbe1b885dd087be`, on JavaScript, with a
host function `hostSum: (indexed_collection<real>) -> real` that records its
argument:

```
call                               the interpreter passes     compiled
hostSum([1, 2])                    List(1, 2)                 List(1, 2)
hostSum(1..3)                      Range(1, 3, 1)             declines
hostSum(reverse([1, 2]))           Reverse(List(1, 2))        declines
hostSum(map(x => x * 2, [1, 2]))   Map(…, List(1, 2))         declines
hostSum([1, 2] + 1)                List(2, 3)                 declines
```

With Tycho's drawing prelude, `draw(1..3)` declines in the same way.

## Cause and options

A host function receives the engine's value "as the interpreter passes it"
(`docs/COMPILATION-MODEL.md`, "Functions of the host"). The interpreter passes
a lazy view, compiled code holds an array, so the compiler declines unless the
argument is a `List` or a `Tuple` literal of the program.

Compiled code passes a `List` built from its array (decided, below). The
question is what the interpreter passes.

- (a) The interpreter passes a `List` too, when the argument of a host
  function that is not `lazy` evaluates to a finite lazy indexed collection.
  The two routes then pass the same value, and the rule has no caveat. A host
  that reads `ops[0].ops` gets the elements; today it gets the bounds of a
  `Range` or the operands of a `Map`. Tycho's `curve.ts` and `bitmap.ts` read
  an argument as `isFunction(list, "List") ? list.ops : []`. A callback with
  an effect runs once per element at the call. Cost: the public contract of an
  `evaluate` handler changes (a host that wants the view declares the
  function `lazy` and evaluates the operand), and a large range is listed for
  a host that reads one element. Recommended.
- (b) Only compiled code passes a `List`. The interpreter keeps the view. The
  difference is one line in the caveats of compiled code.

Under (a), three points follow the existing rules: an endless view, or one
whose count is not known, stays a view in the interpreter and declines in
compiled code; a library function and a user function are not changed; a set
and a dictionary are not changed.

## Decision

User decision 2026-11-25: a compiled call of a host function passes a `List`
where the interpreter passes a lazy view.

User decision 2026-11-25: (a). The interpreter passes a `List` to a host
function that is not `lazy` when the argument evaluates to a finite lazy
indexed collection, with the three limits above. The change updates
`docs/COMPILATION-MODEL.md` ("Functions of the host"), the page on custom
functions in `~/dev/cortexjs.io/docs/compute-engine/`, and `CHANGELOG.md`.

User decision 2026-11-25: this issue comes before CE-1806 (`ROADMAP.md`),
which removes the array of a view at the other reads. Both apply one rule,
stated in CE-1806: a view becomes a list at a fixed set of places, and the
argument of a host function is one of them.
