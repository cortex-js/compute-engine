Assigning a function that draws a random number to a name that a declared pure function calls gives an error, where the test file says the declared contract is trusted.

## Witness

At `c8b285e9ba54984e47f7d3b9f14e84d8e96369d1` and at
`55b67c3d3b1c9619c9d6ea8890205c4907d6e8b4`, two tests of
`test/compute-engine/free-head-home-resolution.test.ts` fail ("a declared
contract over a head with no definition stays trusted", MathJSON and LaTeX):

```ts
const ce = new ComputeEngine();
ce.declare('T2', {
  signature: '() -> number',
  effects: [],
  evaluate: ce.box(['Function', ['U2']]),
});
ce.box(['Assign', 'U2', ['Function', ['Random']]]).evaluate().json;
// ["Error", ["ErrorCode", "'incompatible-type'", "'pure effects'", "'random effects'"]]
```

The test expects a `Function`: `T2` declares its effects (`effects: []`),
so its body is not checked again when `U2`, which had no definition when `T2`
was declared, gets one.

`needs-review`: either a later change made the check intentional and the
test is out of date, or the check is a regression. The board must say which
contract holds.
