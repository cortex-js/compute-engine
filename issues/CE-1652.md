A function that builds a figure of Tycho's drawing library cannot be compiled, so a notebook animation that draws figures runs interpreted.

## Witness

The instrument, after Tycho's drawing prelude (`circle`, `rotateAbout` and
the type `Figure` are Epsil definitions of the prelude):

```
figure = (t: real) => circle((cos(t), sin(t)), 0.2)
  → declined: "the result of circle is not a scalar (Figure)"
moved  = (t: real) => circle((2, 0), 0.2).rotateAbout(t / 1000, (0, 0))
  → declined: "rotateAbout is not the library operator here (a user definition)"
```

The third case of CE-1621, a call of a function of the host
(`callsHost = (t: real) => hostDraw(t)`), compiles since the fix of CE-1621.

## Cause and options

`Figure` is `tuple<kind: string, geom: list, matrix: any, fillPaint: any,
strokePaint: any, strokePx: any, dashPattern: any, alpha: any>`: a string,
a list of a length that depends on the kind, and six fields typed `any`
that hold `nothing`, a number, a string, a color or a list. The parameters
of the prelude's functions are typed `any` (`circle(c: any, r: any)`,
`figureTransform(fig: any, t: any)`), and `rotateAbout` is a method of the
protocol `Drawable`, dispatched at run time. Compiled code settles every
shape at compile time (`docs/COMPILATION-MODEL.md`, "Shapes are settled at
compile time", R3): a field typed `any` with values of several shapes has
no settled shape, so the decline is the one that the rule requires.

- (a) Keep the decline and document it with this example (recommended).
  Workaround, which CE-1621 makes possible: the callback computes the
  numbers compiled and passes them to a function of the host that builds
  the figure, `t => drawOrbit(cos(t / 1000), sin(t / 1000))`, with
  `drawOrbit` declared by the notebook with `(real, real) -> nothing`.
- (b) A plan for records with fields of settled shapes: Tycho types each
  field of `Figure` (the styles as strings or numbers, never `nothing`), CE
  compiles a tuple of a string, numbers and lists, and dispatches the
  protocol method at compile time on the static type. Cost: a new value
  kind of the IR, the result conversion to MathJSON, and the prelude
  rewritten with typed fields. Size L.
- (c) A plan for interpreter values held in compiled code: the code holds
  a boxed `Figure` as an opaque value and calls the interpreter for each
  prelude function. Cost: a new value kind, and little speed gained over
  the interpreter, since every figure operation is interpreted. Size L.

Tycho half on adoption: Tycho tries to compile every timer callback and
interprets a callback that CE declines (`compiledTick` of Tycho
`src/graph-paper/notebook/ce-notebook-evaluator.ts`, the marker that cites
CE-1652; C1 of Tycho `requirements/archive/EPSIL_ANIMATION.md`). On adoption, a
callback that draws compiles with no Tycho change to that code, once the
drawing prelude's `draw(...args)` (Tycho `drawing/prelude.ts`) compiles: on
0.197.1 the rest parameter declines first ("a parameter of draw that is not a
name"). Check AN10 of the spec and remove the marker.

## Decision

User decision 2026-11-22: (b)

User decision 2026-11-23: the plan is approved, with Q1 (c) (`run()` returns a
record as a JavaScript object with its field names; inside the compiled code it
stays an array), Q2 (b) (Tycho types each field and parameter of the prelude;
the style fields keep `nothing` in their type) and Q3 (a) (JavaScript only;
GLSL declines a record).

## Plan

The plan of option (b) is `docs/plans/2026-11-23-ce1652-records-of-settled-fields.md`
(2026-11-23): a record kind of the IR whose fields each have a settled shape
(a field that holds `nothing` has a unit type, so a style field typed
`string | color | nothing` compiles), a record result of `run()` as a JavaScript
object with the field names, protocol methods dispatched at compile time on the static type of
the receiver, rest parameters per call site, and records passed to a host
function as the engine's value. Six steps, size L. Tycho types the fields of `Figure`
and the parameters of its prelude, and declares `figureDraw`
`(any) -> nothing` (section 5).
