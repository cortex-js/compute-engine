A function that reads its list argument by position takes four times longer each time the list doubles when the list holds true and false values, where the same function over a list of numbers, points or strings takes twice as long.

## Witness

Working tree of main at `3b0b23f414e90ada33e633cb641cd9a8fb3c8ef6`:

```ts
const ce = new ComputeEngine();
const n = 4000;
// f(l) := Map(j ↦ l[j], Range(1, Length(l))), l: list<boolean>
ce.assign('f', ce.box(['Function',
  ['Map', ['Function', ['At', 'l', 'j'], 'j'], ['Range', 1, ['Length', 'l']]],
  ['Typed', 'l', 'list<boolean>']]));
ce.declare('M', { type: 'list<boolean>',
  value: ce.box(['List', ...Array.from({ length: n }, (_, i) => (i % 3 === 0 ? 'True' : 'False'))]) });
ce.box(['ListFrom', ['f', 'M']]).evaluate();   // 3,847 ms
```

| Elements | `n` = 1,000 | 2,000 | 4,000 |
| --- | --- | --- | --- |
| booleans, `f(M)` | 283 ms | 1,031 ms | 3,847 ms |
| booleans, the same `Map` written over the symbol `M` | 20 ms | 45 ms | 151 ms |
| points (`list<tuple<real, real>>`), `f(M)` | 29 ms | 42 ms | 78 ms |
| strings, `f(M)` | 8 ms | 12 ms | 22 ms |
| numbers, `f(M)` | 8 ms | 14 ms | 22 ms |

One read `At(<list of n booleans written out>, j)` in a callback costs 244,
279, 466 and 903 microseconds for `n` = 500, 1,000, 2,000 and 4,000; with a
written-out list of numbers it costs 9 to 14 microseconds at every size.

## Cause and options

Not read. The call puts the list in place of the parameter `l` in the `Map`
that it returns (`bindingKeyedSubs()`, `function-utils.ts`), so each element
of the result reads `At(<the list written out>, j)`, and that read seems to
evaluate the `n` elements of the list before it takes one. A list of machine
numbers holds its numbers unboxed and is not walked. The read over the
symbol `M` also grows faster than the size (20, 45, 151 ms), by less.

Options: the evaluation of a `List` whose elements are all values (`True`,
`False`, numbers, strings) returns the list without visiting them, with the
fact kept on the list once it is known; or `At` with a literal list and an
integer index reads the element without evaluating the list.

Workaround: pass the list to a `Map` as a source. `g(l) := Map(x ↦ Not(x), l)`
called with the same lists takes 17, 14 and 18 ms for `n` = 1,000, 2,000 and
4,000.
