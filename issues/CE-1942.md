A plot of a function defined by an integral (the chi-square tail `p(x)` of neyret/thpezd39zq) takes 31 seconds to draw one frame.

## Witness

The row is `p(x)=\int_{x}^{\infty}\frac{y^{k/2-1}e^{-y/2}}{2^{k/2}\Gamma(k/2)}dy`
with `k=1`. Bare engine, CE 0.204.3, `javascript` target:

| shape | µs per call |
| --- | ---: |
| `\int_{x}^{\infty}\frac{\exp(-\frac{y}{2})y^{\frac{k}{2}-1}}{\Gamma(\frac{k}{2})\times2^{\frac{k}{2}}}dy` (the row) | 3,865 |
| control: `\frac{1}{\Gamma(\frac{k}{2})\times2^{\frac{k}{2}}}\int_{x}^{\infty}\exp(-\frac{y}{2})y^{\frac{k}{2}-1}dy` (factor moved out by hand) | 1,455 |
| interpreter, `subs({x, k}).N()` | 6,681 |

Ratio row / control: 2.66. 64 values of `x` over the document's view
(−0.46 … 3.93), `k = 1`; each arm in a fresh process, 5 trials interleaved,
medians; spread of the trials ≤ 7 %. Load 3.9 → 3.3 on 18 cores (Apple M5 Max,
Node 26.13.0).

In Tycho's renderer the same row (Tycho's own compile, where `\Gamma` is the
document's `(x-1)!`) costs 3,823 µs per call, and one frame of an 800 × 600
view makes 8,193 calls: 31.3 s, nearly all of it in the compiled function.

The code that costs (record 18414 of the audit, `ce-0.204.3-all.json`): every
quadrature node computes the factor that does not read `y`:

```js
const v38 = _SYS.irIntegrate((v2) => {
  const v5 = ((-0.5) * v2);
  const v9 = (0.5 * _.k);
  const v11 = (v9 - 1);
  const v18 = u0_Gamma(v9);                       // per node
  const v21 = (v18 * _SYS.ir.pow(2, v9));         // per node
  const v22 = ((Math.exp(v5) * _SYS.ir.pow(v2, v11)) / v21);
  …
}, _.x, Infinity);
```

The control's code computes `0.5 * _.k` and the `Gamma · 2^…` factor once, out
of the integrand, but still computes `v3 - 1` per node.

A second shape of the same kind, neyret/pmciiapek6
`f(x)=\int_{0}^{10}I_1(t)I_2(t-\sqrt{l^2+x^2}-l)dt` (record 16024): the
`javascript` code computes `Math.sqrt(((_.l * _.l) + (_.x * _.x)))` at each
node; the `interval-js` code of the same row (record 16025) computes it once
before `_IA.integrate`. Not timed: its cost is small next to the two sums of
the integrand.

## Cause and options

The integrand lambda of `Integrate` is emitted as one body; the values in it
that read neither the integration variable nor a value that does are not
moved out of the lambda. CE (compute-engine-94, 2026-11-28) reports a fix in
progress: the `invariants` pass hoists them, 1.78 → 0.54 ms per call on the CE
source tree; the number of quadrature nodes is unchanged.

READY when row / control ≤ 1.25 per call (the instrument's line `CE-1942:`).

## Tycho half on adoption

None: no Tycho workaround. At the release, re-measure the frame cost of
thpezd39zq (`scripts/benchmark-row-frame-cost.mts --only neyret/thpezd39zq`).
The frame stays far above budget after the fix: 8,193 calls × the control's
1,455 µs is about 12 s. The number of calls per frame is a Tycho question (its
`javascript`-lane line sampler takes 8,193 samples over 800 px), handled on
the Tycho side.

## CE answer

CE (2026-11-28): the priority is the board's (needs-review stays). Fixed in the
working tree of compute-engine-94, not yet committed: the pass `invariants`
moves a pure instruction out of the body of an integrand, a numeric derivative
and a sort comparison, and `inline` treats those bodies as loop bodies, so the
body of `u0_Gamma` is copied in and its factorial moves out too. The second
shape (`Math.sqrt(l*l+x*x)` of pmciiapek6) is the same rule. The instrument
reads `CE-1942: READY` (0.60 of the control) against the CE source, at a load of
27, so its times are not citable. The interval mode keeps its integrand whole
with a literal infinite bound, where `_IA.integrate` never calls it.
