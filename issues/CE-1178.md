A traffic simulation can stop as too slow when its update is put in a helper row.

## Witness

On CE 0.184.0, the instrument compares direct Prelude calls with `P = roadstep(S,a,v)` and action `S → P, H → roadtrail(H,P)`, through Tycho's warmed firing environment. Direct: two compiled right sides, 0.28–0.93 ms evaluation. Computed: one compiled and one interpreted, 21–41 ms; an earlier cold firing exceeded 50 ms and the browser showed “This action took too long to run”.

The computed route logs that `roadstep` reads `N` bound to a different definition in the compilation scope. A fresh-engine captured-constant compilation control succeeds. The exact offending Tycho scope/projection remains unverified; investigate Tycho's computed preparation before changing CE's scope-safety refusal.

Workaround: call the Prelude functions directly, as the new traffic Showcase does. Closure requires compiled computed calls and parity with the direct action.

## Othello witness

The Othello Prelude exposes the same boundary with `L = legal(B,B[65])` and click action `B → play(B,L[index])`. The clicked gold marker carries the correct index, but the real firing spends 51–53 ms in evaluation before either compiled or interpreted lane is counted and fails its 50 ms budget. A literal board-cell argument applies in under 1 ms. The direct Prelude action `B → play(B,choosecell(B,index))`, which finds the ordinal legal move internally, applies with one compiled right side and no interpreted right side in about 1 ms.

Instrument: `scripts/repros/2026-11-09-ce1178-othello-computed-scope.mts`. Both forms use the actual firing environment, a warm-up and the unchanged 50 ms budget. This confirms the computed-collection resolution boundary; the exact responsible scope/phase still needs investigation. The direct scalar helper is the Showcase workaround.

## Tycho half on adoption

Tycho half on adoption: rerun both instruments, then simplify the click action in `src/graph-paper/onboarding/showcase-othello.js` to use the legal-move list directly and remove choosecell and its CE-1178 marker if the action stays compiled within budget. Traffic may retain its idiomatic direct calls; verify the computed alternative in its instrument.

## CE answer

Investigated 2026-11-14 at `621cb911d013ecd58ffab8d589a3b54f6ee32086`, with both instruments run against the CE source (a loader hook that maps `@cortex-js/compute-engine` to `src/`). Both still reproduce. The cause of each is in Tycho's preparation, not in CE.

**Traffic.** The compiled lane hands CE `Apply(Function(<roadtrail body>), H, roadstep(S, a, V))`: Tycho's `inlineComputedCollectionBodies` puts `P` in and inlines the value of `roadtrail`. The inlined body reads the Prelude constant `N` (`const N = 24`). `partitionFreeSymbols` (`src/graph-paper/actions/compiled-step.ts`) takes `N` as a scalar input, because the engine gives it the number 24, and `compileBody` (`src/plot-core/compiled-body.ts`) declares it, with `H, S, V, W, a`, in the scope that it pushes, and boxes the body there. So the inlined body reads a new variable `N`, while the stored body of `roadstep`, which the expression calls, reads the constant `N` of the document scope. These are two definitions of one name, and no scope gives both to a lookup by name: `compilationScope()` (`src/compute-engine/compilation/compile-scope.ts`) declines, as its contract says. The first message of the log (`the name "N" of the symbolic option is a constant`) is Tycho's first try with `N` in `symbolic`; Tycho retries without it and gets the scope decline.

The same case with CE only (a document scope with `const N = 3` and a function value `g` that reads `N`, a pushed scope that declares `S` and `H`, and `Apply(Function(H[k] + S[k]*N for k in 1..N; H, S), H, g(S))`): with `ce.declare('N', 'real')` in the pushed scope, the compilation declines with the message above; without that declaration it compiles and gives `[22, 35, 48]` for `S = [1, 2, 3]`, `H = [10, 20, 30]`, the correct value.

**Othello.** No CE compilation declines: the log has no `Compilation fallback` line, and the trace says `lane-declined` with no reason, so Tycho's lane declines before it calls `compile()`. The time is the interpreter: on the CE source, `play(B, L[1])` takes about 200 ms or more interpreted, as do `play(B, 20)` and `play(B, choosecell(B, 1))`. In a pushed scope that declares `B: list<real>` and `index: real`, CE compiles each of `play(B, L[index])`, `play(B, legal(B, B[65])[index])` and `play(B, choosecell(B, index))`.

## Options

- **A (recommended): fix in Tycho, close in CE.** `partitionFreeSymbols` does not take a name whose definition is a constant (`isConstant`) as an input, so `compileBody` does not declare it and the body reads the constant as the called functions do. Example: the CE-only case above without the declaration of `N` compiles and gives the correct value. For Othello, Tycho finds why its lane declines `play(B, L[index])` before the compilation. Cost: a few lines in Tycho, none in CE.
- **B: CE compiles a constant that a called body reads when the scope of the compilation declares the same name.** The compiler gives the occurrence in the called body the value of its constant (or a private name, as `shadowing-calls.ts` does for two functions of one name). Example: the CE-only case above with the declaration of `N` would compile. Cost: a lookup per occurrence in the compiler and a new case in `compilationScope()`, in the binding machinery that the bound-once workstream is to make smaller. It does not help Othello.

Recommendation: A. The constant `N` does not vary, and CE already refuses it as a `symbolic` name for this reason.
