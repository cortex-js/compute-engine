A sum whose lower bound holds a power and that has an upper bound is written as LaTeX that does not read back: `\sum_{k=a^2}^5 x` is written `{\sum_{k=a^2}}^5x`, which reads as an error.

## Witness

At `63089f044dd5a0a31d699439879ba8da47ac7888`:

```
ce.box(["Sum","x",["Limits","k",["Power","a",2],5]]).latex
  → {\sum_{k=a^2}}^5x
ce.parse('{\\sum_{k=a^2}}^5x').json
  → ["Tuple",["Power",["Sum",["Error","'missing'"]],5],"x"]
```

An upper bound with a power (`\sum_{k=1}^{n^2}x`) reads back correctly. The
witness is plausible: a lower bound such as `n^2` occurs in sums over a
range of squares. The workaround is to parse the LaTeX that the user typed,
`\sum_{k=a^2}^5 x`, which reads correctly.

## Cause and options

`serializeBigOp()` (`latex-syntax/dictionary/definitions-arithmetic.ts`)
adds the superscript with `supsub('^', '\sum_{k=a^2}', …)`
(`latex-syntax/tokenizer.ts`). `supsub()` puts its base in braces when the
base contains `^`, also when the `^` is inside the subscript group. Option:
in `serializeBigOp()`, join the command, the subscript and the superscript
directly (`\sum_{…}^{…}`), as each is already a group; or make `supsub()`
look only for a `^` outside braces.
