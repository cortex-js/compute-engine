A random value, or the result of a host function that changes at each call, can repeat the same value at each evaluation.

## Witness

```
q: host operator declared pure: false;  ce.declare('r', { value: ce.box(['q']) })
r                    ->  2, then 3
Reverse(List(5, r))  ->  [1, 5] at every evaluation
r := Random();  x = Reverse(List(1, r))
WithRandomSeed(3, x), then WithRandomSeed(4, x)  ->  the seed-3 draw both times
```

## Cause and options

`isPure` of a node does not follow the value of a symbol it reads, and the
store guard (`boxed-expression/store-guard.ts`) counts only host code that
states no purity, so a cache keeps the value. Four designs failed: counting
reads of impure values (a sequence workload went from 45 ms to 963 ms), a walk
of the value (misses raw values, `ReleaseHold`, `Map` literals), exempting
seeded frames (gives the seed case), counting per nondeterministic operator
(not reviewed). A design decides which caches keep one set of draws per
instance (`docs/RANDOMNESS-MODEL.md` §6), how a seeded frame is identified,
and whether the element memo may keep provisional values. Limit:
`benchmarks/evaluation-caches.ts`, no workload slower than 1.25×.
