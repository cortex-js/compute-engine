Graph Paper keeps four hooks that rewrite a row for classification. Tycho
also reproduced a curve silently using another row's formula when the new
revision reused a generated field-helper name from a cached series.

## Witness

Tycho classifies each row of a plot document (`plot-core/classify-formula.ts`)
with options that the document manager supplies:

- `threadMacroRefs` (`classify-formula.ts`, line 6064), served by
  `threadMacroRefsForRow` (`graph/document-ce-manager.ts`, line 6633): it
  writes out `with` bodies, free-name bodies and the calls that reach an
  axis;
- two `expandFunctionRefsBoxed` hooks (`modes/document/initialization.ts`,
  lines 1384 and 1463): one threads, one expands classification snapshots;
- `expandFunctionRefsStructural` and `shadowedParamsFor`.

Since the CE Document port (CE 0.200.0), Tycho also reads each row's prepared
form (`preparedRow`, `initialization.ts` line 1358), but the hooks above are
still needed: nothing in Tycho shows that the prepared revision gives the
same trees.

## Cause and options

The question for CE: for a row of a prepared revision, does CE expose (or
could it expose) the row's expression with document-function bodies, `with`
bindings and free-name bodies written out, and the names that a function
parameter shadows? For each hook, Tycho would like one of: "the prepared
revision gives this already (where)", "CE could add it", or "this stays a
host concern".

Workaround: the hooks, which work today.
Tycho half on adoption: remove each hook that the prepared revision answers
(`threadMacroRefsForRow` in `src/graph-paper/graph/document-ce-manager.ts`,
the two `expandFunctionRefsBoxed` hooks of
`src/graph-paper/modes/document/initialization.ts`), and read the row from
the prepared revision instead.

## CE answer

Priority P2 confirmed. The helper identity fix and `fieldHelper` metadata
landed in `44d4b936a` and await Tycho's check in an installed release. Keep
the classifier's existing fallback hooks while adopting the prepared data
below.

| Hook | Prepared data and remaining host work |
| --- | --- |
| `threadMacroRefs` | Structural boxing against the revision already expands CE macros. A formula's `rawRows` entry and a definition's `rawBody` already include the host's `lowerBody` rewrites. Tycho can read those rewrites directly where it currently repeats them. Axis-reaching call expansion, Desmos `with` semantics for ordinary definitions, and the choice to turn a free-name definition into a curve remain classifier policy. For that last rewrite, `fieldHelper` and `fieldParameters` now identify the exact callable. |
| `expandFunctionRefsBoxed` | `definitions[].body` supplies the checked expression, including the lexical function literal for a function row. Source and snapshot callers still choose which calls to expand. Ordinary calls retain CE's recursion, argument evaluation, and broadcasting semantics. |
| `expandFunctionRefsStructural` | `definitions[].rawBody` supplies the lowered body before canonicalization. It can replace body reparsing. Substitution and the choice of which calls to open stay with the classifier. For example, inferring an implicit curve from `y = g(1)` given `g(u) = u + 2y` is host policy. |
| `shadowedParamsFor` | `definitions[].params` gives each definition's formals, and a checked function body already binds them lexically. The set of names shadowed by a particular structural expansion comes from that expansion. Keep the hook for trees Tycho rewrites and canonicalizes itself. |

Cache bound expressions and helper-bearing MathJSON with the revision that
produced them, for use while it is open. Source MathJSON without generated
helpers can be retained as syntax. Read the new revision's prepared data and
box it in the new scope before using it to classify, compile, or render.
An unchanged LaTeX row can have different prepared data when a dependency
changes.

For example, swapping `A = x + 1` and `B = x + 10` used to let a serialized
call to A's helper resolve to B in the next revision. CE now gives each
generated binding a distinct name within the engine. To invalidate cached
series selectively, compare the helper names appearing in each snapshot
against the current definitions' `fieldHelper` values. Any absent helper
requires rebuilding that snapshot from the current revision. Keep Tycho's
ordinary source and dependency invalidation for snapshots with no helpers.
Tycho's current helper-map check will reclassify all rows when a retained
field row receives a new helper. The per-snapshot check limits that
invalidation to snapshots that actually carry an old helper. Generated
names are opaque and are local to the engine and revision.
