`Iterate` over a function whose declared default differs from the default written in its definition uses the written one, while a direct call, `Map` and `Filter` use the declared one.

## Witness

On main, `new ComputeEngine()`:

```ts
ce.declare('s', '(real, real = 5) -> real');
ce.assign('s', ce.box(['Function', ['Subtract', 'v', 'u'], 'u', ['Optional', 'v', 7]]));
ce.box(['s', 1]).evaluate();                                 // 4: the declared default 5
ce.box(['Take', ['Iterate', 's', 1], 3]).evaluate();         // [6, 1, 6]: the literal's 7
ce.box(['Map', ['List', 1], 's']).evaluate();                // [4]
```

The compiled code gives `[4, 1, 4]` for the `Iterate` (a known-limitations
line of `docs/COMPILATION-MODEL.md`).

## Cause and options

`Iterate` applies the function value (`applicable(expr.op1)` with
`iterateArgs()`, `library/collections.ts`), so the literal's default fills the
missing argument; a call is canonicalized with `fillParameterDefaults()`,
which reads the declared signature. Fix: apply the declared default in
`Iterate` as a call does, or refuse an assignment whose literal default
differs from the declared one.
