The Jacobian matrix of a list that a function returns is wrong inside a function whose argument has the name of that list.

## Witness

MathJSON, evaluated in order at `edccc20202dd5567a15031af3094240a7c52c04f`:

```
["Assign", "g", ["List", ["Multiply", "u", "v"], ["Add", "u", "v"]]]
["Assign", "F", ["Function", "g", "t"]]
["Assign", "h", ["Function", ["JacobianMatrix", ["F", 1], ["List", "u", "v"]], "g"]]
["h", 7]                      → ["List", 0, 0]
```

Expected `[[v, u], [1, 1]]`: the `g` of the body of `F` is the global list, not
the parameter `g` of `h`. Control: the same `h` with the parameter named `q`
gives `[[v, u], [1, 1]]`, and so does `JacobianMatrix(F(1), [u, v])` outside a
function.

The witness is `crafted`: it needs a function whose body is a symbol that
holds a list, called in a function with a parameter of the same name.

## Cause and options

`resolveToList()` (`src/compute-engine/boxed-expression/utils.ts`) inlines the
call `F(1)` to the symbol `g` of the body of `F`, then reads the value of that
symbol by name with `inlined.engine.lookupDefinition(inlined.symbol)`, in the
scope where `JacobianMatrix` is evaluated. That scope gives the parameter `g`
of `h`, which holds `7`, so the operand is not seen as a list and the gradient
of the symbol `g` is returned.

Option: read the definition of the symbol occurrence, with
`valueDefinitionOfOccurrence()` of the same file (added for CE-1455), in place
of the lookup by name. Size S.
