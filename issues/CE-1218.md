`symbolDeps` of a compiled closed form of an integral or a derivative misses the values and the functions that the closed form holds.

## Witness

At `114403d0b44156730f1f943b12362d0c74f90fc8`, `k := 3`,
`g(t) := t³ + sin t`, JavaScript target, `cse: false, constantFold: false`:

| Program | Code | `symbolDeps` |
| --- | --- | --- |
| `∫₀ᵃ k·t dt` | `(1.5 * (_.a * _.a))` | `[]` |
| `D(g(x), x)` | `3 * (_.x * _.x) + Math.cos(_.x)` | `[]` |
| `g'(x)` | `(((x) => 3 * (x * x) + Math.cos(x)))(_.x)` | `[]` |
| `k·x` (for comparison) | `3 * _.x` | `['k']` |

The code holds the value of `k` and the body of `g`, and `symbolDeps`,
the set that tells a cache when to compile again, names neither: after
`ce.assign('k', 4)` or a new definition of `g`, a host that caches on
`symbolDeps` keeps the old code.

## Cause and options

`compileIntegrate()`, `compileDerivative()` and the `Apply` handler of a
derivative compile a closed form computed by an evaluation, which folds
the values; no step records the names it read. Option: add to
`target.symbolDeps`, where the closed form is computed, each name of the
node whose stored definition the closed form can hold (a value that is not
a constant of the engine, a user function, and the names of their
definitions, at any depth), as the numeric-kernel profile does
(`calculusDependencies()` in `javascript-fragment-target.ts`).
