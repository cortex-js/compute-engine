The hypergeometric function ₂F₁ at machine precision can give a wrong number, with the wrong sign and size, for parameters near 100.

## Witness

```
Hypergeometric2F1(-75.504, 49.036, 69.652, -1.33).N()   // precision 'machine'
  -8.22e-23; mpmath: 9.298e22
Hypergeometric2F1(-75.504, 20.616, 69.652, 0.5708).N()
  -1.507e-50; mpmath: 1.705e-5
```

Measured 2026-11-06 at HEAD `5c97853cc5601e11b799e80274a7179d7246ab93`
and with the CE-192 change. The first point maps to the second by the
Pfaff transform.

## Cause and options

The connection formula at 1 − z in `hypergeometric2F1Real()` computes
`gamma(c−a)·gamma(c−b)` = Γ(145.156)·Γ(49.036), about 1e311: it overflows
to Infinity, so the first part becomes 0. The second part is then the
largest part, so the cancellation check passes, and the function returns a
wrong finite value instead of NaN (NaN would try the complex kernel).
Options: (a) return NaN when a Γ factor or product is not finite or is 0;
(b) compute the Γ ratios with log-gamma, with the sign kept apart.
