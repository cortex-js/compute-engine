The swept sector of the Kepler orbit example is drawn by the processor instead of the graphics card, so it draws slower.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('e', 'real<-10..10>'); ce.declare('t', 'real');
ce.declare('F', { signature: '(real) -> unknown' });
ce.assign('F', ce.box(['Function', ['Block', ['Multiply', ['Sin', 'w'],
  ['Sqrt', ['Add', ['Negate', ['Power', 'e', 2]], 1]]]], 'w']));
compile(ce.box(['Tuple', ['F', 't'], 't']),
  { to: 'glsl', callerLocals: ['t'], symbolic: ['t', 'e'] });
```

0.194.3: declines, "program: list<complex^2>: a list of complex numbers on
glsl" (diagnostic `outside-profile`). 0.192.0: compiles, `vec2(_fn_F(t), t)`.
Control: the same tuple with the body written in place,
`Tuple(Multiply(Sin(t), Sqrt(1 - e^2)), t)`, compiles on 0.194.3 to
`vec2(sin(t)·sqrt(1 - e·e), t)` (the real lane: NaN where `1 - e^2 < 0`).
The witness compiles on 0.194.3 when `F` is declared `function` instead of
`(real) -> unknown`, or when `e` is `real<0..0.7>`. The scalar call `F(t)`
alone compiles on 0.194.3 but returns a `vec2` (a complex value) from a
compile whose mode is `strict`.

Document form: Tycho declares every document function with a signature
`(real | signed_infinity | nan) -> unknown` before it assigns the body, and a
slider `e_0` as `real<-10..10>`. The sector of `showcase/kepler-orbit` is
`Tuple(A(t), B(t))`, where `B` calls `Y(w) = √(1 − e_0²)·sin(w)`; it is
compiled with `{to: 'glsl', callerLocals: ['t'], symbolic: ['t', 'x', 'y',
'e_0', 'T', 'u', 'v']}`. The expanded fallback then declines for its size
("the compile handler of Which is not asked about a node of a value of more
than 20000 nodes"). Captures: Tycho `.cache/mg-evidence/codegen-full.json`
record 528 (0.192.0, compiled) and
`.cache/macro-carriers-phase-a-ce1943/codegen-full.json` records 518 and 520
(0.194.3, declined); the planet `(X(E(T)) + …, Y(E(T)) + …)` declines the same
way (record 527) and its expanded fallback compiles.

Tycho impact: the shipped showcase entry `kepler-orbit` draws its sector on
the JavaScript band instead of the GPU band.

## Cause and options

In a `strict` compile, the result of a user function whose body has a
`complex` static type is lowered in the complex lane, and a tuple of it is a
list of complex numbers, which GLSL declines (as the IR README says). The
same body written in place stays in the real lane. Option (a, recommended):
in a `strict` compile, lower a user function's result in the real lane, as
the body in place is. Option (b): admit a tuple of complex values on GLSL
when only its real part is read; larger.
