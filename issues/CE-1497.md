A document function that takes the dot product of a point with another point is computed by the interpreter, so its plot is slower.

## Witness

`x, y: real`; `p` declared `function`,
`p := Function(PointList(Cos(a), Sin(a)), a, b)`; `d` declared
`(unknown, unknown) -> unknown`,
`d := Function(Dot(p(u, v), PointList(u, v)), u, v)`. Compile `d(x, y)` on
javascript, run at x = 0.3, y = 0.4.

- Interpreter (0.193.0 and 0.194.0): 0.40480902940221763. The boxed type of
  `d(x, y)` is `real`.
- 0.193.0 compiled: the same value.
- 4779733 (0.194.0): "Function(Block(Dot(p(u, v), PointList(u, v))), u, v):
  the result of d is not a scalar (value)".

Controls on 4779733: `d` declared `(real, real) -> unknown`, or
`(unknown, unknown) -> real`, compiles with the interpreter's value; so does
`Dot(p(x, y), PointList(x, y))` with no `d`.

Tycho declares a document function `(unknown, unknown) -> unknown` when the
row does not type its parameters (Desmos imports).

## Expected

The parameters of no stated type are real (the IR README, "User functions"),
the body `Dot` of two points is a real scalar, and the call compiles with the
interpreter's value.

`npx tsx scripts/repros/2026-11-18-ce1497-ce1498-ce1499-ce1500-ce1501-compile-gaps-probe.mts` in Tycho. `CE-1497: READY` when `d(x, y)` with the
`(unknown, unknown) -> unknown` signature compiles with the interpreter's
value. READY on 0.193.0, NOT READY on 4779733.
