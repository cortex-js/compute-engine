A replacement with a rule for a variable and a rule for an expression of that variable applies the rules one after the other, so the second rule never matches.

## Witness

```js
ce.box(['ReplaceAll', ['Add', 'x', ['Power', 'x', 2]],
  ['List', ['Rule', 'x', 2], ['Rule', ['Power', 'x', 2], 'y']]]).evaluate();
// ➔ 6, in either order of the rules; it must be y + 2
```

The description of `ReplaceAll` says the rules "are applied simultaneously in
a single pass", as `expr /. rules` in Wolfram, which gives `y + 2`.

## Cause and options

The `evaluate` handler of `ReplaceAll` (`library/core.ts`) splits the rules:
the rules whose left side is a symbol go through one `subs()` first, then the
pattern rules go through `replaceTopDown`, on the result. `x^2` is `4` by
then.

(a) Give the symbol rules to the top-down pass as well, so at each part the
first rule that matches replaces it. `subs()` avoids capture under a binder
(`Sum`, `Function`) and the pattern pass may not; the pass must keep that.
(b) Run the top-down pass with the pattern rules first and `subs()` only on
the parts that no pattern rule replaced. Each needs tests with a binder in
the target. Size M.
