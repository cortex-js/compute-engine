A function that a block defines inside a function body, and that a closure calls after the call has ended, no longer sees the variables of the block.

## Witness

At `05b589b2f021945b0bc301ff33f0f2ead15f5cf2`, with `evaluate()` and with
`evaluateAsync()`:

```ts
ce.declare('g', 'function');
ce.assign('g', ce.box(['Function', 'x', 'x']));
ce.box([
  ['Function',
    ['Block',
      ['Declare', 'c', 'real', 5],
      ['DefineFunction', 'h', ['Function', ['Add', 'c', 'k'], 'k']],
      ['Assign', 'g', ['Function', ['h', 'x'], 'x']]],
    'n'],
  1,
]).evaluate();
ce.box(['g', 10]).evaluate().json;   // ["Add", "c", 10]   (must be 15)
```

The result is the same when the closure is assigned in a `Loop` or a `Sum` of
the block.

## Cause and options

The closure leaves the call by an assignment to an outer variable, and `h` is a
function of the block, not a local value. When `g` calls `h` after the call,
`h` reads `c` in its defining scope, the block, whose run has ended. The
comment of `captureNestedLocals()` (`src/compute-engine/function-utils.ts`)
describes the same case for a closure that the block RETURNS
(`Block(Declare(c, 'real', 5), DefineFunction(h, k ↦ c + k), k ↦ h(k))`); the
closure assigned to an outer variable is not covered. Fix: when the closure is
made, give the functions of the block that it calls the copy of the run of the
block, as for the returned closure (`capturedRunOf()`). Size M: the record of a
run of a block is now made only on the asynchronous route.
