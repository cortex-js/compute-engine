In the `complex` mode, compiled code divides a real number by a real element of a broadcast list with a complex division, and the result can differ in the last bit from the real quotient.

## Witness

At `99cee49c8926048d73e590a0274567b9290e8bcc`, JavaScript target, `mode:
'complex'`, `cse: false, constantFold: false`, `x: real`, `fm` the function
`(CL: list<real>) => Sum(CL) + Max(CL) + At(CL, 1)`:

```ts
const e = ce.expr(['Divide', 1.5, ['List', 1, ['fm', ['List', 1, 'x', 0.3]], 'x']]);
compile(e, { mode: 'complex', cse: false, constantFold: false }).run({ x: 0.1 });
// [1.5, 0.4411764705882353, 15]
compile(e, { mode: 'complex', profile: 'numeric-kernel' }).run({ x: 0.1 });
// [1.5, 0.4411764705882352, 15]
```

The second element is `1.5 / 3.4000000000000004`, which is
`0.4411764705882352` in IEEE arithmetic: the profile is right. The existing
compiler computes `{ re: 1.5·d / d², im: … }` with `d` the element on the
complex lane (`_SYS.bcast` of a complex division with `_SYS.cplx(_tv2)`).

## Cause and options

The divisor is real, but the existing compiler lifts it to the complex lane
in the broadcast. Option: divide by a real element with the real quotient
(`a / d`) when the element type is real, as the scalar route does.
