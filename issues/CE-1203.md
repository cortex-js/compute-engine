Compiled code gives `NaN` for an element of a list of logarithms plus one.

## Witness

At `eac9ab939ef63e0914ba506454feb3d821c293ed`, JavaScript target, `x: real`,
default options (the same with `cse: false, constantFold: false`):

```ts
const e = ce.box(['Add',
  ['At', ['Comprehension', ['Ln', 'x'], ['Element', 'j', ['Range', 1, 2]]], 1],
  1]);
compile(e).run({ x: 3 }); // { re: NaN }
```

The interpreter gives `1 + ln(3)` (2.0986…). Other programs of the class, found
by the random tester (`scripts/js-profile-fuzz.ts`), strict mode:

| Program | Input | Compiled |
| --- | --- | --- |
| `Negate(At(Comprehension(Ln(x), Element(j, Range(1, 3))), 1))` | x = 3 | `{re: NaN, im: NaN}` |
| `Power(At(Comprehension(Log(k), Element(j, Range(1, 2))), 2), 1.5)` | k = 0 | `NaN` (the interpreter: `+Infinity`) |

The `numeric-kernel` profile gives the interpreter's value for these programs.

## Cause and options

The element type of the comprehension is not real (`Ln(x)` of a real `x` can
be complex), so the compiler reads the element as a complex value: the code
is `_SYS.atNumeric(<array of numbers>, 1, "complex | signed_infinity")`
followed by complex arithmetic that reads `.re` of a number. The array holds
the numbers of `Math.log`. Options: read the element with the lane that the
element code has (real), or convert the number to a complex value at the read.
