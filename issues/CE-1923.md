A figure drawn with a dash pattern in each frame of an animation runs interpreted, because the code checks whether the option is a list of numbers.

## Witness

On CE source after 0.204.2, compiled JavaScript declines a test of a list
type of a parameter of type `any` that holds a list:

```epsil
function h2(v: any) -> real { if v is list<real> { 1 } else { 2 } }
function look(opts: dictionary = {->}) -> real { h2(opts["dash"]) }
```

| Program (`let frame = (t: real) => …`) | CE source |
| --- | --- |
| `look({dash -> "x"}) + t` (control) | compiles; `4` |
| `h2([1, 2]) + t` | declines: `MatchesType(v, TypeFrom("list<real>")): MatchesType of a value of type any, which neither proves nor excludes list<real>` |
| `h2([t, 2]) + t` | declines, the same message |
| `look({dash -> [1, 2]}) + t` | declines, the same message |

The interpreter gives `4`, `3`, `3` and `3`. Tycho's `figureOption` tests
`k == "dash" && (v is nothing || v is list<real>)`, so
`circle(c, r, {dash -> [1, 2]})` declines here once CE-1919 and CE-1920 are
fixed.

## Cause and options

`held()` of `lower-functions.ts` holds a scalar argument at an `any`
parameter with its lane, so `matchesType()` decides `v is real` by the lane.
A list argument takes the shape of its argument (`point`), but `matchesType()`
does not decide a list type from it. The option: in the function lowered for
a list argument of a settled lane and rank, decide `v is list<T>` from that
IR type (`valueTypeOf()`), as for a point.
