After a function that another function calls is removed and declared again with a new signature, the calling function keeps the result type of the removed signature.

## Witness

```ts
const ce = new ComputeEngine();
ce.assign('f', ce.parse('x \\mapsto g(x) + 1'));
ce.declare('g', { signature: '(integer) -> integer', evaluate: ([x]) => x.mul(2) });
ce.undeclare('g');
ce.declare('g', { signature: '(real) -> real', evaluate: ([x]) => x.mul(3) });
ce.box('f').type.toString(); // (x: unknown) -> integer; a fresh engine gives -> real
ce.parse('f(1.5)').evaluate(); // 5.5, the value is right
```

The same happens when `ce.loadLibrary()` fails: a definition declared before
the failing one rebuilds `f`, and the undo of the failed load
(`undoLibraryDeclarations()`, `engine-library-bootstrap.ts`) removes the
declaration with `ce.undeclare()`, which keeps the rebuild. Before the
checkpoint API was removed, the loader restored a checkpoint, which put `f`
back.

## Cause and options

The declaration of `g` rebuilds every definition that waited on `g`
(`repairWave()`, `function-utils.ts`) and takes it off the registry of
waiting definitions (`provisional-application.ts`). `ce.undeclare()`
(`removeBinding()`, `engine-declarations.ts`) undoes neither, so the second
declaration of `g` finds no definition to rebuild. Options: (a) `undeclare()`
registers the definitions that read the removed name as waiting again, so the
next declaration rebuilds them; (b) the rebuild records what it changed on the
binding of `g`, and the removal of that binding undoes it.
