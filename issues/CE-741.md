A compiled function that receives a square root as its argument gives `NaN` or a wrong number in complex mode.

## Witness

With `y: real`, in mode `auto` or `complex` on JavaScript:

```
f := x ↦ Mod(x, 3);              f(Sqrt(y)) at y = 16 → NaN (interpreter 1)
g := x ↦ If(x > 0, Mod(x, 3), x); g(Sqrt(y)) at y = 16 → 4   (interpreter 1)
```

`Floor`, `Ceil`, `Round` and `Remainder` fail the same way, in a named function
and in an inline `Apply`.

## Cause and options

The parameter `x` has no declared type, but its use in `Mod` narrows it to
`real`, so `isComplexValued()` (`compilation/compiler-core.ts`) uses the real
kernel while the call passes a `{re, im}` object. Fix (plan
`docs/plans/2026-10-31-static-shape-compilation.md`, rule R2): add the lane of
each argument to the variant key of CE-712.2 (committed `450e1ad49`) in
`ensureSpecializedUserCallEmitted()`, and in `literalWithParameterTypes()` and
`expressionParameterVariantTypes()` (`compile-callbacks.ts`). A parameter
declared `real` stays a mismatch (rule R5). Full text: ROADMAP.md at commit
5784d4aec.
