A sum or a product whose bounds are integers far above 2^53 evaluates to a
wrong number, where a sum with bounds just above 2^53 gives an error.

## Witness

At `0e0344edb91eeffd585394edca5699d71bb9aa62`, `new ComputeEngine()`,
`ce.box(…).evaluate()`:

| Program | Result | Right |
| --- | --- | --- |
| `Sum(j, Limits(j, 2^60, 2^60 + 3))` | `1152921504606847000` | `4611686018427387910`, or the `out-of-range` error of the row below |
| `Product(j, Limits(j, 2^60, 2^60 + 2))` | `1152921504606847000` | `1532495540865888862346031014505056804636003312238329856`, or the same error |
| `Sum(j, Limits(j, 2^53, 2^53 + 3))` | `Error("out-of-range", "a bound with magnitude at most 9007199254740991", …)` | (control: the documented refusal) |
| `Sum(j, Limits(j, 1, 4))` | `10` | (control) |

The bounds are written `["Power", 2, 60]` and `["Add", ["Power", 2, 60], 3]`.
The result of the first two rows is 2^60 printed as a double: the loop made
one pass.

## Cause and options

Not investigated. The bound check that gives the `out-of-range` error at 2^53
does not fire for these bounds, and the loop then counts in doubles, where
`2^60 + 3` is `2^60`. Options: (a) make the bound check apply to every integer
bound, so that these programs give the same error (the documented rule; size
S); (b) count with exact integers when a bound is beyond 2^53.

The `ir` profile in `mode: 'bigint'` compiles these programs and gives the
exact values.
