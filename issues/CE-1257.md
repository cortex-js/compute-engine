The Riemann zeta function of a tiny negative number is minus infinity at the default precision, instead of about -1/2.

## Witness

```ts
const ce = new ComputeEngine();
ce.box(['Zeta', -1e-100]).N(); // -oo  (must be about -0.5)
ce.box(['Zeta', -1e-30]).N();  // -0.500000000000000223197
ce.box(['Zeta', 1e-100]).N();  // -0.5
ce.precision = 'machine';
ce.box(['Zeta', -1e-100]).N(); // -0.49999999999999994
```

ζ is analytic at 0 with ζ(0) = -1/2, so ζ(s) for |s| < 1e-20 is -1/2 within
1e-20. The bignum route gives -∞ for s = -1e-100 (and -1e-300); the machine
route is right. At s = -1e-30 the bignum value is off by 2.2e-16, far more than
its precision.

## Cause and options

Not investigated. Likely the reflection formula for s < 0 multiplies a factor
that overflows near the pole of ζ(1 - s) at 1 by a sine that underflows to 0 at
the working precision. Fix: for |s| below a threshold, use the series at 0
(ζ(s) = -1/2 - s·ln(2π)/2 + …).
