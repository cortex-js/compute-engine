Three operators do not compile on 0.194.0: `ColorMix` on javascript and `Cot` of a complex argument on glsl (both compiled on 0.193.0), and `LambertW` on glsl and interval-js (never compiled).

## Witness

1. `AsOklab(ColorMix(Rgb(1,0,0), Rgb(0,0,1), x))`, `x: real` = 0.25,
   javascript. 0.193.0 compiled: the interpreter's value
   `Oklab(0.58397, 0.27139, -0.00977)`. 0.194.0: "the operator ColorMix is
   not supported by the compiler".
2. `Cot(z)`, `z: complex`, glsl. 0.193.0 compiled it. 0.194.0: "Cot (the
   operation ccot) on glsl". Tycho meets it in a domain-colouring colour.
3. `LambertW(x)`, `x: real`, glsl and interval-js. 0.193.0 and 0.194.0
   decline.

## Expected

Each compiles on the named target.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1468: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, probed on 9d9931734 with `compile(…, { fallback: false })`): all four decline as stated; `LambertW` compiles on
javascript (`0.5671432904097838` at 1). P3 stands (minor, medium, plus
`regression` for the first two). Disposition: pool; `ColorMix` on javascript
first (the library kernel `lerpOklchColor` exists), then `Cot` of a complex
argument on glsl. `LambertW` on glsl and interval-js was never compiled.
Workaround for `Cot(z)`: `Cos(z)/Sin(z)`, which compiles on glsl
(CE did not run its value on a GPU).
