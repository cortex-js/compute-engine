An existing array can read the wrong field after a nominal tuple type is redefined.

## Witness

```epsil
type alias B = integer<0..255>
type Pixel = tuple<r: B, g: B, b: B, a: B>
let old = arrayFrom([Pixel(17, 23, 31, 255)], "Pixel")
let red = () => old[1].r
```

In the same engine, compile the value of `red` with fallback disabled. Both
that compiled function and interpreted `red()` initially return 17. Run
`type Pixel = tuple<g: B, r: B, b: B, a: B>` in the same scope. Interpreted
`red()` now returns 23 while the existing compiled function still returns 17.
The mutable array specification §3 says the array retains the definition from
construction, so the interpreted read should still return 17.

## Cause and options

`BoxedArray._peek()` reconstructs nominal machine cells by constructor name,
which resolves to the newer layout. Reconstruct them using the pinned
definition. Check array entry and Swap across same-name layout revisions as
well. Their compatibility checks currently accept the same printed name.
