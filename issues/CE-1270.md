A function that computes `A·B − B·A` of its two parameters gives the zero matrix for two matrices that do not commute, with no error. The same expression with the matrices written in place gives the right matrix.

## Witness

```js
const A = ['List', ['List', 1, 2], ['List', 3, 4]];
const B = ['List', ['List', 0, 1], ['List', 1, 0]];
const comm = ['Subtract', ['Multiply', 'A', 'B'], ['Multiply', 'B', 'A']];

ce.assign('f', ce.box(['Function', comm, 'A', 'B']));
ce.box(['f', A, B]).evaluate().json;
// [[0, 0], [0, 0]]        expected [[-1, -3], [3, 1]]
// the type of f: (A: unknown, B: unknown) -> number

ce.box(['Subtract', ['Multiply', A, B], ['Multiply', B, A]]).evaluate().json;
// [[-1, -3], [3, 1]]
```

The result depends on the order of the uses in the body. With a later use
that types the parameters as matrices, the value is still wrong; with the same
use first, it is right:

```js
// (A, B) ↦ (A·B − B·A, Determinant(A), Determinant(B))
// type (A: matrix, B: matrix) -> tuple<matrix, number, number>
// value ([[0, 0], [0, 0]], -2, -1)

// (A, B) ↦ (Determinant(A), Determinant(B), A·B − B·A)
// value (-2, -1, [[-1, -3], [3, 1]])
```

With `MatrixMultiply` in place of `Multiply` both orders are right.

A second program with the same cause, a use order that changes the result:

```js
// x ↦ (x + x, Length(x)) on [1, 2, 3]: a list of three tuples with errors
// x ↦ (Length(x), x + x) on [1, 2, 3]: (3, [2, 4, 6])
```

## Cause and options

The canonical form of a node of the body is built when the node is boxed,
with the type the parameter has at that moment. `A·B − B·A` is built while
`A` and `B` are `unknown`: the two products are ordered as products of
numbers, the difference cancels to `0`, and the call returns `0` for each
cell. A later use (`Determinant(A)`) types the parameter, but the node built
earlier is not built again.

Options:

- (a) Box the body a second time when the uses changed the type of a
  parameter (treatment T2 of the measurement: it gives the right value in
  both orders; the prototype cost 1.5 to 2 times in boxing time and its test
  for "nothing more required" was unfinished).
- (b) A product whose operands include an `unknown` parameter is not
  reordered or cancelled as a product of numbers. This also covers the first
  witness, where no later use types the parameters, and (a) does not.
- (c) Document that `Multiply` of untyped parameters is a product of
  numbers, and that a matrix function declares its parameters or uses
  `MatrixMultiply`.

The first witness needs (b) or (c); (a) alone leaves it wrong.
