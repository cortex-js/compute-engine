A recursive function with a typed first parameter that is called with a list as its second argument returns the list wrapped in another list.

## Witness

```js
ce.assign('r', ce.box(['Function',
  ['If', ['Equal', 'n', 0], 's', ['r', ['Subtract', 'n', 1], ['List', 1, 2]]],
  ['Typed', 'n', "'number'"], 's']));
ce.box(['r', 1, ['List', 0]]).evaluate().json;   // [[1, 2]]; expected [1, 2]
ce.box(['r', 1, ['List', 0, 7]]).evaluate().json; // [[1, 2], [1, 2]]
```

At `5eb1778b5d1643108ec473a2eb040bcbfe3fd063`. `r(1, [0])` calls `r(0, [1, 2])`,
which returns `s`, so the value is `[1, 2]`. The signature that the engine
derives is `(n: number, s: list<any>) -> unknown`.

Since the declared-locals rule, an Epsil `let r = (n: number, s) => …` goes
through the same code as a global assignment and gives the same wrong value;
the test named above is marked as a known failure for it.

## Cause and options

Not investigated. The call is mapped over the list argument of the untyped
parameter `s`, although the derived signature says that `s` is a list. The
mapping of a call over a collection argument is in
`boxed-expression/boxed-function.ts`.
