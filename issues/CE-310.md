An Epsil function redefined in a later program with another result type is refused with a type error.

## Witness

After a program with `function g(x: integer) -> integer { x }`, a later program
on the same engine with `function g(x: integer) -> string { … }` is refused
with `incompatible-type`.

## Cause and options

A redefinition across programs already replaces the effects (a later
`function g(x: integer) random -> integer { 7 }` replaces a `pure` contract),
but not the result type. User decision 2026-10-23: a redefinition replaces the
whole contract, the result type included; code that used the old result type
is checked again where it is next evaluated.
