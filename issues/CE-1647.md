A host cannot apply a function value under the debugger: it must bind the value through a host function and run a wrapper program, whose own statements call the hooks.

## Witness

On 0.196.0, with a cell `let a = 0` / `let cb = t => do { a = a + t; a }`
run with `url: "cell"` and `callback = ce.box("cb").evaluate()`:

```
ce.declare("__cb", { value: callback })
  → throws EffectContractError: Operator Definition "__cb": the body writes
    outside the function (an assignment to an outer variable, …)
wrapper route (hostCallback() returns callback):
  executeEpsilAsync(ce, "let __w = hostCallback()\n__w(5)", { url: "wrapper", debug })
  hook calls: wrapper@0 "let __w = hostCallback()", wrapper@0 "__w(5)",
              cell@1 "a = a + t", cell@1 "a"
```

The wrapper works: the callback's statements call the hooks with the cell's
`sourceContent`, and the host skips the wrapper's two statements. Its cost per
call: a parse and a static pass of the wrapper text, a host function declared
on the engine, the binding of `__w` in the current scope (the host must scope
it), and two extra hook calls.

## Ask

A public asynchronous application of a function value with the debug hooks of
`executeEpsilAsync` and a signal, for example
`applyEpsilAsync(ce, f, args, { debug, signal })`, that installs the hooks and
the pause clock as a run does, and reports a runtime failure as
`executeEpsilAsync` reports its value and diagnostics. Not
`ce._epsilDebugHooks` (internal).

Tycho half on adoption: the debug tick (`timerTickDebug` in
`ce-notebook-evaluator.ts`) calls it in place of the wrapper program and the
`figureTickCallback` host function, which are removed. The instrument reads
READY when an export of `@cortex-js/compute-engine/epsil` whose name contains
"apply", called as `f(ce, callback, [5], { debug })`, applies the callback and
calls the hooks for its two statements only.
