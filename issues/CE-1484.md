The starting state of the Turing patterns showcase is computed by the interpreter instead of compiled code, because a count computed as a square is treated as a fraction.

## Witness

The prelude of Tycho's `turing-patterns` entry
(`~/dev/tycho/graph-paper-site/showcase/en/turing-patterns.html`, field
`prelude`):

```epsil
function inSeedSquare(c: integer, r: integer) -> boolean { … }
function seedState() -> list<real> {
  let CellCount = N^2
  [if k <= CellCount {
     if inSeedSquare((k - 1) % N, floor((k - 1)/N)) { 0.5 } else { 1.0 }
   } else {
     if inSeedSquare((k - CellCount - 1) % N, floor((k - CellCount - 1)/N)) { 0.25 } else { 0.0 }
   } for k in 1..2*CellCount]
}
```

On CE main with CE-1480 (2026-11-18), compiling `seedState()` declines with
"an argument of inSeedSquare that is not integer". `CellCount = N^2` (with
`N` an integer) takes the real lane in the compiler (the rule for `Power` in
`readType()` of `lower.ts`), so `(k - CellCount - 1) % N` is real at a
parameter declared `integer`. The interpreter types `N^2` of an integer `N`
as an integer, and the call is valid. Whether 0.193.0 compiled `seedState()`
is not checked. The rest of the prelude (`grayscott`) compiles with CE-1480
and gives the interpreter's values.

## Cause and options

The IR types a `Power` of an integer base and a non-negative integer
exponent as real. Option: type it integer when the base is an integer and
the exponent a constant non-negative integer (the exact square fits the
integer lane within 2^53 on JavaScript, 2^24 on GLSL; past that, the rule of
the other integer operations applies). Workaround: the interpreter route
(fallback); `N*N` in the prelude may compile, which CE has not checked.
