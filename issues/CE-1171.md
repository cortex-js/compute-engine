Parsing a double integral whose outer sign has no differential, with parse diagnostics on, prints an internal "Assertion failed" message to the console.

## Witness

`246428a205e3b3ce594b6bfdd20734c5fcaee499`, with
`new ComputeEngine().parse(latex, { diagnostics: true })`:

```
\int_0^2\int_0^1 (c+dx)(a+bx)\,dx
  console: Assertion failed: parse-diagnostics: bound-only "a" in canonical
  result — either missing _pruneUndeclared wiring in a binder parselet, or a
  canonicalization-synthesized binder reusing a free source name
  raw: Integrate(Integrate(InvisibleOperator(Error('unexpected-differential'),
       Delimiter(Add(a, b·x))), Tuple(x, 0, 1)), Tuple(Nothing, 0, 2))
```

The value is an `unexpected-differential` error, which is correct for this
malformed input. The diagnostics list `c`, `d`, `a`, `b` as undeclared. Only
the console message is wrong.

## Cause and options

Not traced. The outer integral has no differential, so the canonical form
makes a binder for it; the assertion in `ce.parse()` that checks the
diagnostics against the canonical result reports `a` as bound only. The
first places to read are the canonical form of `Integrate` with a `Nothing`
variable and the post-check of `parse()`.
