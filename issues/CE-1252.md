In the VS Code debugger and in the inline results of the editor, an Epsil program that calls a library function by its lower-case name stays unevaluated.

## Witness

`sin(0) + sqrt(4)` gives `2` with the command-line runner and stays
symbolic in the debugger and in the inline results. Measured by a probe of
the two loops at main `3938e59385e45e9141c51d0d34c0da3242533e04`.

## Cause and options

`vscode-epsil/src/debug-worker.ts` (`run()` / `executeTopLevel()`) and
`vscode-epsil/src/inline-runner.ts` each run the statements of a program in
a loop of their own, and neither calls `resolveLibraryNames()`, which
`executeEpsil()` and the command line do. Fix: call it in both loops; or
remove both loops when a program has one route (the investigation's
option B, a user decision that is pending).
