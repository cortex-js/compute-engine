An asynchronous compiled parallel loop can return a value after its deadline expires.

## Witness

With a prewarmed Node worker pool of size 1, compile the comprehension
`[k^2 parallel for k in 1..n]`, where `n` is declared `integer`. Wrap the
worker transport so that a `call` message is delivered after 150 ms. Use a
1,000 ms worker replacement grace period.

```ts
await ce.withTimeLimit({ ms: 40, label: 'plot' }, () =>
  compiled.runAsync!({ n: 4 }, { minPasses: 1 })
);
// [1, 4, 9, 16] instead of the deadline frame's CancellationError
```

The worker receives the call after the original deadline. The delay is a
deterministic stand-in for a delayed worker or delivery. A four-pass
`parallel for` summing `k` also returns 10 under the same transport delay.

## Cause and options

The worker sets the deadline without checking it on entry. The loop only
checks during periodic ticks, so a short range can succeed. The pool accepts
that result during its replacement grace period, and the calling thread
checks the deadline only before replaying failed ranges. Check the deadline
on worker entry and when accepting a result so a late success rejects with
the original frame's attribution and does not cause replay.
