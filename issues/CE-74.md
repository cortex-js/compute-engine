A list computed by `Map` whose function can return "nothing" has a type that does not say so, so `Filter`, `Mean` and the compiled function treat it differently.

## Witness

```
m = Map(x ↦ If(x > 1, Nothing, x), [1, 2, 3])
type vector<integer^3>, but m.at(2) is Nothing
measured 2026-10-20:
Filter(m, x ↦ True)   incompatible-type cells
Mean(m)               an error (Max(m), Product(m) skip Nothing)
Total(m)              unevaluated
compiled Map          [1, null, null]
```

## Cause and options

User decision 2026-10-20: a lazy view (`Map`, `Tabulate`, `Table`, `Scan`,
`Iterate`) keeps a `Nothing` result in its display, count, `.at()` and
`.each()`; making it a list erases it. `Map`, `Filter`, the paired statistics,
the numeric aggregates and `Zip` have their policies. The design questions:

- CE-74.1: does the element type of a view include `nothing` when its
  callback can return `Nothing`?
- CE-74.2: does each reducer skip a `Nothing` element, as a list literal does,
  or treat it as an error? `Ordering(m)` depends on the answer.

CE-74.3 is CE-1002.
