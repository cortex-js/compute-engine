The generalized harmonic number of a large count with an order of 0 takes minutes to evaluate.

## Witness

`ce.function('HarmonicNumber', [ce.number(1e6), ce.number(0)]).N()` took
374 s (2026-11-19, at 4d6a88b688cab49b2ad09be6847ce3bb55784fca); the value
is `1000000`.

## Cause and options

`harmonicNumberExact()` (`src/compute-engine/library/arithmetic.ts`)
estimates its work as `n·digits` with `digits = r·n·log10(e) + 1`, which is
`n` at `r = 0`, so the estimate passes `MAX_EXACT_HARMONIC_WORK`. The
function still computes `lcm(1..n)` (about 434,000 digits). Fix: return `n`
for `r = 0`, and count the lcm loop in the work estimate. Size S.
