The LaTeX of a fourth or higher derivative of a function that is not declared reads back as a power of the function.

## Witness

In a new engine, with `f` not declared:

```
const e = ce.parse("f''''(x)");  // ["Apply", ["Derivative", "f", 4], "x"]
e.latex;                          // f^{(4)}(x)
ce.parse(e.latex).json;           // ["Multiply", "x", ["Power", "f", 4]]
```

The same happens for `["Derivative", "f", 0]`, `["Derivative", "f", "k"]` and
`["Derivative", "f", 1.5]`. Orders 1 to 3 are written with primes and read back.
When `f` is declared a function, `f^{(4)}` reads back as `Derivative`.

## Cause and options

The Lagrange trigger `^{(` in `definitions-core.ts` reads `f^{(n)}` as
`Derivative` only when `f` resolves to a function type; the serializer of
`Derivative` writes `f^{(n)}` for every order other than 1 to 3, and it cannot
see the type of `f`. Boxing `Derivative(f, 4)` does not declare `f` a function
(its type stays `unknown`).

- (a) Boxing `Derivative(f, n)` with an undeclared symbol `f` declares `f` a
  function. (The parser reads `f'` as `Prime` whatever the type of `f`.)
  Example: after
  `ce.parse("f''''(x)")`, `ce.parse('f^{(4)}')` gives `Derivative(f, 4)`.
- (b) The serializer writes a positive integer order with primes
  (`f''''`), which the parser reads for an undeclared `f`. Example:
  `Derivative(f, 4)` is `f^{\prime\prime\prime\prime}`; a symbolic order stays
  `f^{(k)}`.
- (c) The serializer writes `\operatorname{Derivative}(f, 4)` for an order
  other than 1 to 3. This changes pinned text (`f^{(4)}` in
  `issue-420-prime-base-unicode-sets.test.ts`).

Recommendation: (a), because the round-trip then needs no change of the
serialized text.
