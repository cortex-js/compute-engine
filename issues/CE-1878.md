In the Tycho code editor, `plot((sin(x), {▮` offers every name of the library at the caret, where only the four keys of a series style (`color`, `label`, `width`, `opacity`) can go.

## Witness

On CE 0.202.0, with Tycho's drawing prelude, at `plot((sin(x), {`:
`epsilCompletions` gives 701 items (`Figure`, `Plot`, …), and
`epsilSignatureHelp` gives `activeParameter: 0` and no `activeKey`. The
keys of a series style exist only in the prose of `plot`'s description.

CE-1812 documents the keys of a dictionary passed as a parameter
(`@key options.x`), which covers `plot(series, {▮`. A dictionary that is
part of an argument (the second element of a pair, an element of a list, a
field of a record) has no parameter of its own to hang `@key` on.

## Request

A way for a type to declare documented keys, so that the completion and the
signature help read them from the type expected at a dictionary literal,
wherever the literal is. For example, a named type with `@key` lines:

```
/// The style of one series.
/// @key color: string -- The color of the series.
/// @key label: string -- The name of the series in the legend.
/// @sample color "crimson"
type Style = dictionary

/// @param series an item, a pair (item, style), or a list of them
function plot(series: any | tuple<any, Style> | list<…>, options: dictionary = {})
```

Then at `plot((sin(x), {▮` the keys of `Style` not written yet are the
items (`color -> ${1:"crimson"}`), and `activeKey` and the key's
documentation are given as for an options parameter. The `@key options.x`
form of CE-1812 can stay, or become a shorthand for such a type. CE chooses
the form; the instrument writes the form above and reads NOT READY until a
form exists (update its program to the chosen form).

Tycho half on adoption: declare the style type in
`src/graph-paper/notebook/drawing/prelude.ts` and give `series` of `plot` and
`plot3d` that type.
