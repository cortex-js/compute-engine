A function that updates a variable it closes over (the state of an animation) cannot be compiled, so every tick of a notebook animation runs interpreted.

## Witness

On 0.195.1, with `let c = 0`, `let s = 0.5` and:

```
pure    = (t: real) => s + t / 1000            → compiled; value 0.516
bump    = (t: real) => do { c = c + 1 }        → declined: "Could not compile:
          Assign(c, Add(c, 1)): a write to a name that is not a local"
advance = (t: real) => do { s = s + t / 1000 } → declined: same reason
```

The control (`pure`) reads the same closed-over `s` and compiles, so reads of
closed-over names work; writes do not.

Expected: `compile(advance)` gives a runner; after `run(16)` three times, the
engine's `s` is 0.548 (machine number). An acceptable alternative for Tycho:
the runner returns the new values of the names it assigned (for example
`{ value, assigned: { s: 0.548 } }`) and the host writes them back.

## Cause and options

The compiler treats a closed-over name as an input only. Options: (a) compile
an assignment to a closed-over name as a write to a host cell (the runner
reads the name's value at entry and writes it to the engine at exit); (b) the
runner returns the assigned values and the host writes them. Either works for
Tycho; (b) keeps the compiled code free of engine access.

Tycho half on adoption: a notebook `timer` callback compiles when its other
parts do (`ce-notebook-evaluator.ts`, the C1 note in `finishRun`), its
assigned variables are written back to the kept scope when the tick ends, and
the instrument prints `compiled` for `bump` and `advance`.

## Code

The decline is in `src/compute-engine/compilation/ir/lower.ts`.

## CE answer

CE (2026-11-21): fixed with option (b) for the code and option (a) for
`run()`. A root function literal that assigns a variable of the engine
compiles to JavaScript. `result.assigns` lists the variables. `run()` reads
their values in the engine before each call and writes the new values back
after it, so the Tycho half can call `run(t)` and read the kept scope. A call
that throws writes nothing. The `code` takes the values after the arguments
and returns `[value, ...new values]`. The variable must have a declared type
of real, integer or boolean values (`let` declares one); a list state
(`g = step(g)`) still declines. A function that the callback calls and that
reads the variable also declines. `fixed-in` is the base commit of the fix:
the fix is the commit after it, with the message `CE-1620: …`.
