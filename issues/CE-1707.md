When a compilation with the `inputs` option falls back to the interpreter, and an `inputs` name is a Document row that a called function row reads, a run of the fallback throws `Cannot assign a value to the constant "k"`.

## Witness

At `0d9a40693d9bf90f0dffa57eabe4989c68ed23ff`, with the CE-1706 change in the
working tree. Rows `k = 2x_w` and `X(x) = Factor(kx)` (any operator the
compiler does not support, such as `Simplify` or `Zeta` of a complex number,
does the same). Inputs `x`, `x_w`, both `real`:

```js
ce.pushScope(revision.scope);
const r = compile(ce.box(['X', 'x']), { inputs: { k: 'real' } });
ce.popScope();
r.success;            // false: "the operator Factor is not supported"
r.run({ x: 1, k: 3 }); // throws: Cannot assign a value to the constant "k"
```

Expected: the interpreter's value of `X(1)` with `k = 3`.

Before CE-1706 the same call declined at the input check ("has no declared
type") and reached the same fallback, so the defect is older; CE-1706 lets
more compilations reach the fallback with a row in `inputs`.

Workaround: leave the row out of `inputs` (map the input it reads, `x_w`,
instead).

## Cause

Not confirmed. The fallback of the `inputs` option
(`compileExpression()`, `compilation/compile-expression.ts`, the `fallback`
closure) runs the expression in the caller's scope and gives each input its
value on the definition of that scope. A Document row is sealed (its write
admission is `'none'`), so the write is refused. The fallback could
substitute the given value for the row in a sealed revision, as the CE-1666
fallback does for a free name (`a98bb597a`).
