A host-declared constant zero divided into zero, or raised to the power 0, gives 0 or 1 instead of NaN.

## Witness

```ts
ce.declare('z', { value: 0, isConstant: true });
ce.box(['Divide', 0, 'z']).simplify().json;                // 0, expected 'NaN'
ce.box(['Divide', ['Multiply', 2, 'z'], 'z']).simplify().json; // 0, expected 'NaN'
ce.box(['Power', 'z', 0]).json;                            // 1, expected 'NaN'
ce.box(['Power', 0, 0]).json;                              // 'NaN'
ce.box(['Multiply', 'z', 'x', ['Power', 'z', -1]]).simplify().json;
// ['Multiply', 'ComplexInfinity', 'z', 'x'] after CE-1361, expected 'NaN'
```

`evaluate()` gives `NaN` for the two quotients, as expected. Measured at
6f8fa80decd0759f578c89b0674f7271418c6377. The workaround is to evaluate the
operands before building the expression.

## Cause and options

The rules read a symbol as a free variable, which may take a nonzero value,
also when the symbol is a constant whose value is 0:

- `simplify()`: the `0/a -> 0` rule of `symbolic/simplify-divide.ts`
  (`denom.symbols.length !== 0`) and the `division` rule of
  `symbolic/simplify-rules.ts`, through `div()`. `(2z)/z` reaches them
  because the simplified numerator is `0`.
- the canonical form: the `x^0 -> 1` fold of the `Product` tally
  (`arithmetic-mul-div.ts`, `term.isSame(0) === false && isZero(exp)`).

Fix: guard each rule with `isConstantThatMayBeZero()`
(`arithmetic-mul-div.ts`), which CE-1361 added for the `a/a -> 1` rules.
