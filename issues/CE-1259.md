In a function, a call of a hold function inside the held argument of another call leaves the caller's variable unevaluated in the result.

## Witness

```
hold mySum(body, bind i, n) = Sum(body, (i, 1, n))
function f(p) { let q = p; mySum(mySum(q * j, j, 2), k, 2) }
f(2)
```

Gives `6q`; main before the bound-once change gave 12. Same with a
parameter, a loop index (`[6q, 6q]` for `[6, 12]`), a local of a `do` block
and a local function in call position. At the top level it gives 12.
Measured at worktree commit `c22d678d9` (bound-once step 1, not on main
when this was filed): a regression that the change is landed with, by user
decision, because the held arguments get a design pass (ROADMAP CE-1258).

## Cause and options

The replacement of a caller's names by their values (`inlineFrameLocals`,
`function-utils.ts`) does not reach an occurrence inside the held operand
of the inner call, which has no definition yet. Fixed by CE-1258 (a held
argument is bound where it is boxed).
