The type of a call of one of two functions that call each other does not hold its value when the other one was typed first.

## Witness

```
f, g declared (unknown) -> unknown, m: integer
f := n ↦ If(n = 0, "a", g(n − 1))
g := n ↦ If(n = 0, 2, f(n − 1))
type of f(m) read first, then:
g(m)                         type number (checked 2026-11-07)
g(1)                         value "a"
```

The type of `g(m)` must hold `"a"` (`integer | string`, or `unknown`).
Checked in the worktree of CE-836 (base
`8651a23b7c9f7b38d95ba3f67caac940b4128c9f` with the CE-836 change); the
reviewer of CE-836 reports the same result at that base without the change.

At `d8e2c256ebb2dc21fe69f339ae7d223fd30bfc5f` the order above gives
`integer | string`. The order with `g` assigned first gives `g(m)` the type
`number` with either call read first, and `Tuple(g(m), f(m))` is
`tuple<number | string, number>`.

## Cause

Traced on 2026-11-08; the details, the attempts and their measurements are
in `docs/plans/2026-11-08-ce1091-mutual-recursion-type-cache.md`. The body of
`g` is typed while the result type of `f` is computed (the assignment of `f`,
or the derivation of its signature at a later read), with `f(n − 1)` left out
of the join as a recursive call (`unknownCallMayBeRecursive()`). The type
cache keeps that type under `_typeCacheFallbackGeneration()`, which moves only
with the `any` axis, and no state event happens before the next read. The
cache cannot tell a type that depends on the own computation of a function
(correct to keep: a self-recursive function is typed by its base case) from
one that depends on the computation of another function.

Two attempts that retire such types when the outermost computation ends did
not converge in review: one typed the body of every self-recursive function
again at each read; the other never cached the types of the pair (850 times
slower on repeated reads) and made `Tuple(f(m), g(m))` wrong where HEAD is
right.

## Options

(a) Record, for each such cached type, the assignments and derivations it
depends on, and retire it when the first of them ends. Sound and precise;
size L, in the hottest cache of the engine.

(b) Leave a call out of a join only for the own recursion of the function
whose result type the innermost computation computes. Mutual pairs become
`unknown`, also those that are precise today (`list<number>` in
`recursive-function-result-type.test.ts`), and compiled code that calls
them can decline. Size M; it changes the documented typing of mutual
recursion. A quick prototype that did not tell the own body from the other
body broke the base-case typing of self-recursive functions (9 tests).

(c) Record a known limitation in `docs/TYPE-SYSTEM.md` with this pair as the
example, and close. Recommended: the witness is `crafted`, and each sound
fix costs either the precision of every mutual pair or a dependency record
in the hottest cache. Option (a) if a `corpus` or `plausible` witness
appears.

An attempt is in the worktree `/tmp/wt-cebatch-1091` (attempt 2, with the
test file `test/compute-engine/ce-1091-mutual-recursion-type-order.test.ts`);
it is temporary and can be removed.
