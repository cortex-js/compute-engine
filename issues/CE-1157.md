A function declared through a type alias of a signature gives no type for its calls: `g(3)` is `unknown` where the same declaration written out gives `list<real>`.

## Witness

Repo source, 2026-11-08 (`scratchpad/probe-alias.mts` of session ce-desk):

```
ce.declareType('Fn', '(integer) -> list<real>', { alias: true });
ce.declare('g', 'Fn');
ce.parse('g(3)').type        → unknown
ce.declare('h', '(integer) -> list<real>');
ce.parse('h(3)').type        → list<real>
```

The symbol `g` types `Fn`. The application typing does not unfold the alias
before it reads the result of the signature, so the call types `unknown`. The
consequences are a compiled program that declines or reads the value as a
scalar, and no shape from `staticShape` (CE-1150), which reads the type of the
call.

## Cause and options

Not traced. The typing of an application with a value-definition head reads
the declared type of the head with `functionResult()`; a `reference` type (an
alias) is not a signature for `signatureArms()`, so the result is `unknown`.
The fix is to resolve the alias (`resolveTypeAlias()`) where the application
typing reads the head's type, as `BoxedFunction._headHasSignature()` and
`_headResultType()` do since CE-1150. A test with an alias-declared head
belongs in `test/compute-engine/ce-1150-static-shape.test.ts` once the type is
right (the fixer of the review left it out so as not to pin the defect).
