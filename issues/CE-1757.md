At machine precision, the numeric value of a product of number literals only can go through a subnormal intermediate product and lose digits: `N(10²⁰⁰·10⁻²⁰⁰·10⁻¹²³)` gives `9.88131291682493e-124`, not `1e-123`.

## Witness

At `4120983c2e0984023e08784f726b0e9979e41a52`:

```js
const ce = new ComputeEngine();
ce.precision = 'machine';
ce.box(['Multiply', { num: '1e-200' }, { num: '1e-123' }, { num: '1e200' }]).N().json;
// 9.88131291682493e-124
```

With a symbolic factor, `N(10⁻²⁰⁰·10⁻¹²³·10²⁰⁰·x)` gives `1e-123·x`
(`test/compute-engine/arithmetic-many-operands.test.ts`, "the float
coefficient of a product with a symbol does not underflow").

## Cause and options

`mulNEvaluated()` (`arithmetic-mul-div.ts`) folds a product of number
literals only with `expandProducts()`, which folds from the right:
`10²⁰⁰·(10⁻²⁰⁰·10⁻¹²³)`, and `10⁻³²³` is subnormal. The product with a
symbolic factor multiplies in the canonical order, from the left. A fix
multiplies the number literals from the left too, or folds a product whose
intermediate leaves the normal double range from the exact values, as
`foldOutOfDoubleRange()` does for one factor. The comment above the scalar
assembly says that the last digit of a machine float can change with the
order of the products, so the first option changes some last digits of
products of three or more floats.
