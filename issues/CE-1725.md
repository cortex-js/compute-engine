A breakpoint in the body of a function that has no parameters, such as `let cb = () => do { … }`, does not stop the debugger when the program calls the function.

## Witness

```ts
const ce = new ComputeEngine();
const src = "let a = 0\nlet cb = () => do {\n  a = a + 1\n  a\n}\ncb()";
await executeEpsilAsync(ce, src, {
  debug: { beforeStatement: (at) => console.log(src.slice(...at.range)) },
});
// ➔ let a = 0
// ➔ let cb = () => do { … }
// ➔ cb()
```

The statements `a = a + 1` and `a` of the body call no hook. With one
parameter (`let cb = t => do { … }` and `cb(0)`), they do. The same holds
for `applyEpsilAsync(ce, cb, [], { debug })`. `EpsilDebugHooks`
(`src/compute-engine/types-debug.ts`) lists the statements that call no hook,
and this case is not in the list.

Workaround: give the function a parameter that it does not use.

## Cause and options

`makeLambda()` (`src/compute-engine/function-utils.ts`, the nullary branch,
"(b) The body IS a scoped Block") evaluates the body with the synchronous
`evaluateStatements()`, and ignores `options.awaitStatements`. The
parameterized `invoke` path awaits the statements when `Apply` asks for it.
So an operator with only an asynchronous handler in such a body is not
awaited either.

Fix: when `options.awaitStatements` is set, run the nullary body as the
parameterized path does (`awaitedApplication()` or the asynchronous statement
list), with the same fresh scope and call frame. Test it with the witness
and with an operator that has only an `evaluateAsync` handler.
