The numeric inverse of a matrix of real numbers that is close to a singular matrix can be the inverse of another matrix.

## Witness

At commit `0bebdaee7b63afd440151e05c12684ab9151765c`, with `d = 2^-44`:

```
numberMatrixInverse([[1, 1, 0], [1, 1 + d, 1], [0, d, 2]])
  // last row: [-1, 1, 0]
  // the last row of the inverse is [1, -1, 1]
```

`Inverse(…).N()` of the same matrix gives the same rows, and so does
`Inverse` in compiled JavaScript, which calls the same function. The witness
is crafted: the entries are chosen so that the determinant is `d`.

## Cause and options

After each step of the elimination, `numberMatrixInverse()` sets an entry to
0 when its magnitude is at most `1024ε` times its running bound. The first
step leaves `d` in rows 2 and 3. In row 2 the bound is about 2, so the entry
becomes 0, and in row 3 the bound is `d`, so the entry stays and is the next
pivot. Row 2 is then never reduced with it, and the result is the inverse of
the matrix with a 0 in place of that `d`.

Option: do as `complexMatrixInverse()` of `numerics/linear-algebra-complex.ts`
does (CE-1803): keep the value of each entry, take as the pivot the largest
candidate whose magnitude is more than `1024ε` times its bound, and return
`undefined` when no candidate is. For the witness, `complexMatrixInverse()`
of the matrix times `1 + i` gives the last row `[1, -1, 1] / (1 + i)`. The
change needs the measurement of CE-1542 again (9,000 random singular integer
matrices), because the test of a pivot then reads entries that were 0
before. The 2 × 2 branch (the adjugate) is not concerned. Size S.
