A rename of a variable does not reach a code cell that uses the variable
inside a `$…$` formula, and the cell shows the old name as unresolved.

## Witness

On 0.197.1, `parseEpsil("a + $\sum_{k=1}^{n} k a$", undefined, { parseLatex })`
with the engine's `latexSyntax.parse`:

- Control: the `a` outside the island is `{ sym: "a", sourceOffsets: [0, 1] }`.
- Inside the island, `k`, `a`, `k`, `n` are bare strings of MathJSON with no
  source offsets.

A host that walks the program for the names a cell reads must also find the
free names of each island itself: `k` is bound by the sum, `a` and `n` are
free. The LaTeX syntax has many binders (`\sum`, `\prod`, `\int`, `\lim`,
`\frac{d}{dx}`, `\mapsto`, set builders with and without `\in`, filtered
limits), and a host list of them goes out of date when CE adds one.

## Cause and options

`parseLatexIsland` splices the MathJSON of the island with the island's
range only (`src/epsil/parser.ts`). CE already knows the binding sites of
its expressions (`src/compute-engine/boxed-expression/binding-sites.ts`).

Requested:

1. Source offsets on the symbols inside an island, relative to the Epsil
   source (the LaTeX parser knows the offset of each token in the island).
2. A way to get the free names of the MathJSON of an island without an
   engine, or of a parsed program with its islands, with the same binder
   rules as `binding-sites.ts`.

Tycho half on adoption: with (2), replace `walkIslandRefs` and its binder
lists (`LIMIT_BINDERS`, `LIMIT_HEADS`) in
`src/graph-paper/notebook/cortex-analysis.ts`; with (1), let
`rewriteCortexSource` rewrite names inside islands and remove
`cortexIslandMentions` and its use in `renameCortexReferences`
(`src/graph-paper/notebook/notebook-surface.ts`).

## Options for request 1 (measured at `207f1fec2368260193812106fa8dbdbc29c0316c`)

The witness reproduces: the island is
`{"fn":["Sum",["InvisibleOperator","k","a"],["Tuple","k",1,"n"]],"sourceOffsets":[4,24]}`.
No option is both small and sound, so the board chooses:

- **(a) Offsets from a side table (recommended, size L).** A new LaTeX parse
  option records the span of each node during the parse, as
  `onAmbiguity: 'error'` does (`_exprSpans` in
  `src/compute-engine/latex-syntax/parse.ts`), so the parse does not change.
  After the parse, a node gets `sourceOffsets`, and a symbol gets them only
  when exactly one recorded span of that name is in its region. The Epsil
  parser shifts them by the start of the island. Example: in
  `\sum_{k=1}^{n} k a` each name gets its range; in `\int_0^x x\,dx` the three
  `x` stay without offsets. The tokenizer must also map each token to the
  input: today the offsets index the normalized LaTeX, which differs after a
  comment or a run of spaces. Host rule: rewrite a name in an island only
  when each occurrence of it there has offsets, otherwise keep the present
  fallback (`cortexIslandMentions`).
- **(b) Decorate during the parse, as `preserveLatex` does (size M, not
  sound today).** The wrapped nodes change the parse (CE-1727: 8 of 428
  MathNet fragments, for example `\mathbb{R}^{+}` becomes
  `PseudoInverse(RealNumbers)`), and the decoration misses a one-token
  script argument and the index of a big operator: in 28 of 447 fragments a
  free name has no decoration (`2^n`, `\int_0^b t\,dt`). Possible only after
  CE-1727 is fixed and those parselets decorate.
- **(c) A rename function in CE (size L).** `renameInLatex(latex, from, to)`
  gives the new LaTeX, or `undefined` when it cannot prove the edit: it
  rewrites each candidate spelling of `from`, parses again, and compares with
  a substitution that respects the binders. A new public API; no offsets.
- **(d) No change.** Tycho keeps `cortexIslandMentions`.

## Request 2

Available today with an engine: `ce.box(islandJson).references` gives the
free names with the binder rules of the operator definitions. At the HEAD
above: `\sum_{k=1}^{n} k a` gives `a, n`; `\int_0^x x\,dx` gives `x`;
`x \mapsto x+a` gives `a`; `\{x \in S \mid x > c\}` gives `S, c`;
`\lim_{x\to c} g(x)` gives `c, g`. Without an engine the same rules are not
available: they are the `operands` roles of the library definitions. CE-1728
records a parse defect found here (`\max_{x \in S} x` reads `_` as a name).

## CE answer

CE (2026-11-23): Request 2 is available now: replace `walkIslandRefs` with
`ce.box(island).references` on each island (an engine is needed). Request 1
waits for the board: options (a) to (d) above, (a) recommended. Workaround:
keep `cortexIslandMentions`.
