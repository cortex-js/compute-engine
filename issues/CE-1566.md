The colors of a list of shapes made with a 'for' list are computed point by point instead of by compiled code when the document also has a list with the name of the loop variable.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('S', 'integer<1..20>'); ce.declare('x', 'real'); ce.declare('j', 'list<integer>');
ce.box(['Assign', 'j', ['List', 4, 5]]).evaluate();
ce.box(['Assign', 'c', ['Comprehension', ['Divide', 'j', 10],
  ['Element', 'j', ['Range', 0, ['Add', 'S', -1]]]]]).evaluate();
compile(ce.box(['Add', 'x', ['Sum', 'c']]), { to: 'javascript' });
```

0.194.3: declines, "the value of c, which reads j of another binding".
Control: the same program without the outer `j` compiles. 0.186.0 compiles
both. The `j` in the body is the bound variable of the `Element` clause, not
the outer `j`.

Found by the Tycho codegen audit of 2026-11-19: the same MathJSON, with the same options, compiled to JavaScript on CE 0.186.0 and declines on 0.194.3 and on the CE main build of 2026-11-19 16:57, in the document context and on a bare engine. Tycho's instrument `scripts/repros/2026-11-19-ce1560-js-decline-regressions.mts` prints one READY / NOT READY line per issue (READY on 0.186.0, NOT READY on 0.194.3).

## Cause and options

The dependency walk of a held value counts a name bound by `Comprehension`
(`Element`) as a read of the outer binding of the same name. Option: remove the
names bound by the clauses before the walk, as for `Sum` and `Map`.
