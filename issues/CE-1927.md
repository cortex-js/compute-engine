A compiled function whose input is declared `any` reports another cause for its decline than the tests expect, and 23 tests fail on main.

## Witness

At `244e39d468ed48ccbef084f8056b2bb750e7ef4b`, with no change in the tree,
`npx jest test/compute-engine/compile-list-element-unknown-arith.test.ts`
gives 23 failures of 165. Each one is a case
"(unknown) -> list, x: any declines: …" (`g(x)[1] + 1`, `Sin(g(x)[1])`,
a `Block` local that holds the element, …). The compilation still declines,
but `r.diagnostic.code` is `untyped-input` where the test expects
`unsettled-shape` with the message "the result of g is not a scalar"
(`expectUnsettledDecline()`, line 146).

## Cause and options

Not found. The order of the checks that refuse an input declared `any` and a
call whose result is not a scalar changed in one of the compiler commits of
2026-11-27 (the last ones are `244e39d46`, `18459c0cc`, `07b97238b`,
`c627befe7`). Both causes are valid declines. Options: (a) restore the order
that the test documents (the shape of the result of `g` first), or (b) change
the test to accept `untyped-input`, when the new order is intended. Find the
commit first (a bisect over these commits with this one test file).
