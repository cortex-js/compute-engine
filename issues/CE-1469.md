`Apply` of a function literal whose parameters are typed (`Typed(H, 'list<real>')`) declines on 0.194.0; 0.193.0 compiled it.

## Witness

```
Apply(Function(Block(Add(At(H, 1), n)), Typed(H, 'list<real>'), Typed(n, 'integer')), L, 5)
```

with `L: list<real>` = `[2, 3, 4]`. Interpreter: `7`. 0.193.0 compiled: `7`.
0.194.0: "Apply of a value that is not a function literal of one untyped
parameter per argument".

This is the form in which Tycho binds the inputs of an action body (the
`*_gpBound` names): the Life step and other actions. 81 of the declines of
Tycho's suite have it.

## Expected

A typed parameter settles the shape of its argument, so the literal can
compile (ce-compiler's reading). An untyped parameter that receives a list
can still decline, because the interpreter may map the function over it.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1469: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, probed on 9d9931734 with `compile(…, { fallback: false })`): declines as stated, and the interpreter gives 7. P1, the
table value (major, high, plus `regression`), and the largest group of the
suite (81). Disposition: proposed for the next release. The untyped form
`Apply(Function(…, H, n), L, 5)` declines too ("the interpreter may map the
function over it"), so it is not a workaround; a typed list parameter binds
the argument whole, which is the case to compile. No workaround in compiled
code.
