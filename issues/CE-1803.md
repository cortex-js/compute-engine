The numeric inverse of a singular matrix with complex entries gives huge numbers instead of saying that the matrix has no inverse.

## Witness

`ce.box(['Inverse', ['List', ['List', ['Complex', 3, 1], 2, 1], ['List', 1, 1, 1], ['List', ['Complex', 4, 1], 3, 2]]]).N()`
(row 3 = row 1 + row 2): entries of about 5e15 + 2e15i. `evaluate()` leaves
the call unevaluated, which is right. `PseudoInverse` gives the same values,
because it calls `inverse()` first.

## Cause and options

The generic elimination of `AbstractTensor.inverse()` tests a pivot for an
exact 0 (`field.isZero`), and rounding leaves a residue of about 1e-16. CE-1542
fixed this for a matrix of real machine numbers: `numberMatrixInverse()` of
`numerics/linear-algebra.ts`, with partial pivoting and a test of each pivot
relative to a running bound of its magnitude. The complex field
(`complex128`) still takes the generic path. Option: a complex version of the
same kernel, with `|z|` for the magnitudes. Size S.
