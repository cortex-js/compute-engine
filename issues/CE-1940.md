The numeric value of the greatest common divisor of a list of large integers that a variable holds is NaN.

## Witness

```ts
const ce = new ComputeEngine();
ce.assign('L', ce.box(['List', ['Power', 2, 100], ['Power', 6, 50]]));
ce.box(['GCD', 'L']).N();                                          // NaN, expected 2^50
ce.box(['GCD', ['List', ['Power', 2, 100], ['Power', 6, 50]]]).N(); // 1125899906842624
```

Read on d93dcb525e6f4228a578114a11a8f628e122039e. `LCM(L).N()` gives `NaN`
too.

## Cause and options

Under `.N()`, the elements of `L` arrive as floats. `exactIntegerOriginals()`
(`library/arithmetic.ts`) reads the exact integers from the operand as
written only when it is a literal `List`, and `L` is a symbol. The floats
then go to the tolerant float lane (`realGcd`), and the float of `2^100` has
no unit digit: the result is `NaN`.

Option: read the exact elements from the value of a symbol that holds a
list of exact integers, as for a written list. Option: when an element is a
float that came from a large exact integer and no exact value can be read,
keep the call unevaluated instead of the float lane.
