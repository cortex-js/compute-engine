After a substitution, a conditional whose other branch has no real value stays unevaluated, where the same conditional written with the values gives the value of its branch.

## Witness

At `5906581bb5a63ffcf49a8266fce9c0e173f7d3ae`:

```ts
const ce = new ComputeEngine();
ce.declare('n', 'integer');
const e = ce.box(['If', ['Less', 'n', 0], 1, ['Floor', ['Sqrt', 'n']]]);
e.subs({ n: ce.number(-1) }).evaluate().toString();
// If(-1 < 0, 1, floor(Error(ErrorCode("incompatible-type", "real | signed_infinity | ~oo", "imaginary"), i)))
ce.box(['If', ['Less', -1, 0], 1, ['Floor', ['Sqrt', -1]]]).evaluate().toString();
// 1
```

The same with `Mod(Mod(n, m), 2)` or `Abs(Mod(n, m))` in the branch at
`m = 0` (an `incompatible-type` error for the `NaN` of `Mod(n, 0)`). The
expression that `subs()` gives prints as the boxed one and is not valid
(`isValid` is `false` for both), but only the boxed one evaluates its `If`.
Compiled code gives `1` for each, in the mode `bigint` with and without the
`numeric-kernel` profile.

Expected: `1`, the value of the branch that the condition selects, as for
the boxed expression.

Workaround: assign the values (`ce.assign('n', -1)`) and evaluate the
expression, or box the expression with the values.

## Cause and options

Not investigated. `subs()` rebuilds the canonical form with the values,
which makes the operand of `Floor` an `incompatible-type` error, and
`evaluate()` of the rebuilt `If` does not reach its branches; the boxed
expression is evaluated by another path.
