The Epsil formatter can fail with "Maximum call stack size exceeded" on an expression nested 160 levels deep.

## Witness

`test/epsil/formatter.test.ts`, "EPSIL FORMATTER — deep indentation › a
160-deep application chain indents past column 2000"
(`serializeEpsil(chain(160))`), failed once on 2026-11-09 with

```
RangeError: Maximum call stack size exceeded
    at new Map (<anonymous>)
    at OffsetCache.get (src/epsil/formatter.ts:91:20)
```

The failing run was
`npx jest -w 4 -- <191 files of test/compute-engine> test/epsil`. The same
command passed in the run before it, and
`npx jest -w 2 -- test/epsil/formatter.test.ts` passed twice after it (31
tests each time). No file of `src/epsil/` or `test/epsil/` had a pending
change. The only pending source change at the failing run was in
`bindLazyArgumentLocals()` (`src/compute-engine/function-utils.ts`), which the
formatter does not call.

## Cause and options

Not found. The formatter recurses once or more per nesting level
(`OffsetCache.get()` calls `compute()`, `src/epsil/formatter.ts`), so the
depth it accepts depends on the stack that is free when the test starts. The
failure is intermittent, so 160 levels is close to that limit in a Jest
worker.

Options: (a) measure the stack depth per nesting level and reduce it, or make
the formatter iterative for an application chain; (b) reduce the depth of the
test to the smallest value that still indents past column 2000, if 160 levels
is not a depth that a real program reaches.
