A formula that adds 10 to every element of a random list can use different draws from a later read of the same list.

## Witness

Run on main at 07eb05248. The seed frame fixes the draws so the comparison is reproducible.

```ts
import { ComputeEngine } from '../src/compute-engine.ts';
import { withRandomSeedFrame } from '../src/compute-engine/boxed-expression/utils.ts';

const ce = new ComputeEngine();
const h = ce.box([
  'Comprehension', ['Random'], ['Element', 'k', ['Range', 1, 6]],
]).evaluate();
withRandomSeedFrame(ce, 42, () => {
  const q = ce.box(['Add', h, 10]).evaluate();
  const hDraws = [...h.each()].map(x => x.re);
  console.log(q.at(1)?.re, hDraws[0], ce._randomFrame?.next);
});
```

The output is `10.736730039526355 0.17852534956934796 12`. The first
element should be `hDraws[0] + 10` and the two reads should consume six
draws. Both operations read the whole of the same finite collection.

## Cause and options

The eager broadcast routes in `collection-utils.ts` pull exactly the
known count and leave their source iterators suspended. The boxed
comprehension witness takes `zip()`. A prepared row whose source resolves
to the same comprehension at evaluation takes
`broadcastOverIndexedCollections()`. The element memo commits a complete
walk when it observes completion. The other reader then starts a fresh
walk of the same collection. Finish the walks for operands consumed in
full so they can commit, and preserve the behavior of shortest-zip
consumers with longer or unknown-length operands. A caller can materialize the
list once and give both consumers that value as a workaround.
