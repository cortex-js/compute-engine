In the Tycho code editor, after the `{` of a dictionary (`plot(sin(x), { `), the gray hint at the caret says "expression" where a key and its value go, because the parser reports the same code there as for an argument of a call.

## Witness

On CE 0.202.0, `parseEpsil` at the end of the source:

```
"let d = { "         expression-expected
"let d = {a -> 1, "  expression-expected
"plot(sin(x), { "    expression-expected
"f(1, "              expression-expected   (control: an argument)
```

Tycho shows the word of the diagnostic's code at the caret
(`expression-expected` gives "expression"). In a dictionary the next thing
is an entry, `key -> value`, and since CE-1812 the completion lists the
documented keys there.

## Request

A code of its own where an entry of a dictionary literal must start (after
`{`, and after the `,` between entries): `dictionary-entry-expected`. The
value position after `->` keeps `expression-expected`, and so does an
argument of a call (the control above).

Tycho half on adoption: none in code until the release; then
`src/graph-paper/notebook/cell-plugins/builtins/cortex-diagnostics.ts`
(`expectedOf`) maps the new code to the word "key" (English and French).

## CE answer

CE (2026-11-26): Fixed for 0.203.0 at the filed priority P4. At the end of input,
the entry position reports `dictionary-entry-expected` with the
`incomplete` flag. The value and call argument positions still report
`expression-expected`.
