A function that stores the mean of its list argument in a variable returns the list itself, where the same function without the variable returns the mean.

## Witness

On main `f833b5c605146e8673ebd9dfff8bb011996de058`, with `executeEpsil()` on
a new engine:

```
function f(xs) { let m = mean(xs); m }
f([1, 3])
```

gives `[1, 3]`. It must give `2`, as these two programs do:

```
function f(xs) { mean(xs) }
f([1, 3])
```

```
function f(xs: list<number>) { let m = mean(xs); m }
f([1, 3])
```

The capitalized name gives the same wrong value
(`function f(xs) { let m = Mean(xs); m }`), so the resolution of the library
spelling is not the cause.

## Cause and options

Not investigated. The value `[1, 3]` is what a call of `f` on each element
gives (`mean(1)` is `1`, `mean(3)` is `3`): the call `f([1, 3])` is applied
to each element of the list when the body holds the `let`, and to the whole
list when it does not. A probable cause is the type that the body gives to
the parameter `xs`: with the `let`, the parameter is taken as a number, and
a function of a number parameter is applied to each element of a list
argument. `Mean` accepts a collection and a number, so its operand does not
tell that `xs` is a number.

Option (a): find where the `let` changes the inferred type of the parameter,
and give the parameter the type that the body without the `let` gives.
