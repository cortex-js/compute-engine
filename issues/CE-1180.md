A GLSL compile now refuses a user function called with a list, where the interpreter broadcasts the function over the list.

## Witness

Ten Tycho records in five documents compiled to GLSL by reference on 0.184.0
and decline since the GLSL fragment (CE-1166.3). Their rows keep a GPU route
only through Tycho's textual expansion of the function bodies; a host without
that expansion loses it.

1. A scalar function called with a list (5 records:
   `neyret/0et6fx01id` rows `\sin(P(x, y))\le0.1`, `\sin(14P(x, y))\le0.1`;
   `neyret/74cc5c82a3` rows `\vert Q(x, y)\vert\le0.02`, `Q(x, y)\ge0.2`,
   `Q(x, y)\le-0.2`). `f(x) = x mod 1` is called with `[-x, -y]`. 0.184.0
   wrote `float _fn_f(float)` and `vec2 _fn_f_each2_1(vec2 a0)`. Now: "The
   argument `[-x,-y]` of `f` has the type `list<real, 2>`, and the parameter
   `ceArg_0` has the type `real`."
2. A parameter with no type read as a vector (5 records:
   `neyret/pqflulcixs` 3 rows with `R(v, φ)`; `neyret/9pal1xuvqq` row
   `0=f(C_{A})f(C_{B})f(C_{C})`; `neyret/ra1p9naofs` row `d(B(A(P)))\le0`).
   0.184.0 wrote `vec2 _fn_R_vector_2_number(vec2, float)`,
   `float _fn_f_vector_real_3_number_number(vec3, float, float)`,
   `float _fn_d_vector_2(vec2)`. Now: "The parameter `ceArg_0` of `R` has no
   type in the GLSL fragment".

The audit data: the session scratchpad files `base-0184-all.json` and
`head-e2b-all.json` are not kept; rerun the audit with Tycho's
`scripts/audit-ce-codegen.mts --all` against 0.184.0 and this build.

## Cause and options

The fragment pass (`src/compute-engine/compilation/fragment.ts`,
`glsl-fragment.ts`) has no rule for either form; the emitter still has the
element-wise wrapper and the per-type specialization. The design is spec
decision 19 (`docs/plans/2026-11-08-glsl-fragment-spec.md`, section 6).

- Form 1: a pass rule that admits a scalar function called with a list of 2
  to 4 reals, typed as the list, with a value test against the interpreter.
- Form 2: first check what the interpreter gives for `R(v, φ)` with a list
  `v` (the body of each witness function is in the Tycho document). If the
  interpreter reads the list whole, give the parameter the list type of its
  argument, one GLSL function per set of argument types; if it maps the
  function over the elements, the 0.184.0 code gave a different value, and
  the call compiles as form 1 or is refused.
- Done when the audit shows the 10 records compiled by reference, with the
  value of each compared with the interpreter at a few points.

## Decision

User decision 2026-11-09: the compiler handles both forms, because they
reflect the broadcasting of the interpreter; a host should not need a
textual expansion to get them.
