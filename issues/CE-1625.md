A breakpoint on the last line of a function that declares a return type or an effect never stops the debugger, and a step skips that line.

## Witness

```epsil
function f(t) -> number { let k = t; k + 1 }
f(1000)
```

With `executeEpsilAsync(ce, source, { debug })`, `beforeStatement` is called
for `let k = t` and not for `k + 1`; `afterStatement` is not called for it
either. The value is right (`1001`). The same body with no return type
(`function f(t) { let k = t; k + 1 }`, or `function f(t: number) { … }`)
calls the hook for both statements. An effect specifier has the same result:
`function f(t) scope { a = a + t; b = b + 1 }` calls the hook for
`a = a + t` only, and `function f(t) scope { a = a + t }` calls none. A
function literal (`t => do { a = a + t; b = b + 1 }`) calls both. The
instrument prints six cases.

`EpsilDebugHooks` (`src/compute-engine/types-debug.ts`) says that the hooks
are called for each statement of a function body evaluated on the
asynchronous route.

## Cause and options

The parser puts the return type and the effects of a function in a `Typed`
node around its body. `src/compute-engine/function-utils.ts`, lines 1391 to
1399 ("Wrap the body Block's last statement in the return-type ascription"),
replaces the last statement with `Typed(statement, type)`, built with
`ce._fn('Typed', …)` and no metadata. The hook sites test
`op.sourceOffsets !== undefined` on the statement, which is now the wrapper:
`evaluateStatementsAsync()` (lines 4088 to 4103 and 4179 to 4205) and
`evaluateStatements()` (line 3724, the synchronous hook that the VS Code
debugger uses; that case was read, not run).

- Give the wrapper the `sourceOffsets` of the statement it wraps (one
  `metadata` argument at line 1397). Check the other readers of the offsets
  of a statement (error ranges, `_epsilStatementResultHook`). Recommended.
- Or read through a `Typed` wrapper at the hook sites, as line 4021 does for
  another purpose. More sites to change.
