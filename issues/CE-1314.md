The documentation says that `staticShape` is read without evaluating the
expression, but reading it on a lazy view calls the host functions and
callbacks that the view holds.

## Witness

`crafted`. A host function that counts its calls, and a callback with a side
effect:

```js
let calls = 0;
ce.declare('src', {
  signature: '(integer) -> list<integer>',
  evaluate: () => { calls += 1; return ce.box(['List', 3, 1, 2]); },
});
ce.box(['Join', ['src', 1], ['List', 4]]).staticShape;
// { indexed: true, count: 4, ... }, and calls is 1
```

`Filter([1, 2, 3], x ↦ b1())` with a counting `b1` runs the callback once
per element when its `staticShape` is read. Found on 2026-11-14 while trying
`canon.staticShape` in the canonical handler of `Sum`
(`library/arithmetic.ts`). There `Sum(Join(src(1), [4]))` called `src` at
canonicalization and stayed unevaluated (the value is 10), and
`Sum(Filter(…))` ran its callback twice per element
(`test/compute-engine/ce-601-shared-evaluation.test.ts`,
`test/compute-engine/lazy-callback-count.test.ts`). That edit was not kept.

## Cause and options

When `isCollection` is `true`, `staticShape` answers from the collection
facets (`types-expression.ts`, doc comment of `staticShape`, first source).
The `count` facet of a lazy view over an eager source evaluates the source.
No reader in the engine is known to be affected today, because the readers
of `staticShape` ask `isCollection` first or read it on operands that are not
views.

- (a) Correct the documentation: `staticShape` does not evaluate an
  application or a symbol, but for a collection value it reads the collection
  facets, and the `count` of a lazy view can evaluate its source. This is the
  simple fix.
- (b) Make `staticShape` of a view read the count from the static type only,
  and leave `count` undefined when the type names none. This changes the
  answer for views, and it needs a review of the readers.
