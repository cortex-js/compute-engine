The message of a dotted library call on a call receiver quotes the receiver
in a form the author did not write: `sort(xs).reverse()` says "at
`Sort("xs")`".

## Witness

On the worktree of CE-1664 (`7ea551573` plus CE-1664.5):

```ts
checkEpsil(ce, 'let xs = [3, 1, 2]; sort(xs).reverse()').diagnostics[0]
  .message[1];
// ➔ '`reverse` is not a protocol function on a value of type
//    `list<number>`: write `reverse(x)` or `x |> reverse` at `Sort("xs")`'
```

Expected: the site is the receiver as written, `sort(xs)`, or no site (the
diagnostic range already covers the call). With a symbol receiver the site
is right (`at \`xs\``), and with `g(3).sort()` it is `at \`g(3)\``.

## Cause and options

`canonicalMemberCall` (`src/compute-engine/library/collections.ts`, step 4)
passes `sym(base) ?? base.toString()` as the site of the error. For a
receiver that is a call of a library function, `base.toString()` gives the
engine name (`Sort`), and the site string is then quoted again when the
message is rendered, so the symbol `xs` shows as the string `"xs"`.

Options: (a) give no site when the receiver is not a symbol, since the
diagnostic range names the call; (b) pass the receiver expression as the
site operand, so the renderer serializes it as Epsil.
