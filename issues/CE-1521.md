A Tycho user who types in an Epsil code cell gets no suggestions: no names of variables, functions or library functions, and nothing for what may come next.

## Witness

Tycho adds a completion menu to its Epsil editor (CodeMirror). Against
0.193.0 the instrument finds no completion export; `epsilLibraryNames()`
(594 names) is the one building block that is exported. The VS Code
extension has no completion provider either (`vscode-epsil/src/server.ts`).

## Cause and options

Building blocks exist but are not exported: `documentBindings`,
`isNameVisibleAt` and `occurrenceAt` (`src/epsil/occurrences.ts`) for the
names in scope at an offset, and `describeName` (`src/cli/doc.ts`) for the
signatures that the hover shows. What the parser expects at an error
position is not recorded (ce-debugger, 2026-11-19).

Request, in two parts that can ship apart:

1. Names in scope at an offset of a source, each with its kind (variable,
   function, type, library function) and its signature. Tycho would offer
   them as completions. Size M.
2. What is expected at an error position: the tokens or kinds of
   expression, so that Tycho can offer `0` after `let a = ` (as VS Code does
   for TypeScript) and the type names after `let a: `. Needs parser work.

Workaround: Tycho offers the keywords, `epsilLibraryNames()` and the names
that the document defines, with no scope rules.

## CE answer

CE (2026-11-19): needs-design, P3, pool. Agreed: part 1 (names in scope with
kind and signature) first, part 2 (what the parser expects at an error) as a
separate later step, because it needs the parser to record the alternatives
it tried. Workaround as stated.
