In the Epsil editor, a rename of a `let` variable also changes its use in a `limit` that does not name its variable, when the engine reads that use as the limit variable.

## Witness

```
let a = 5
limit(a + h, 1)
```

The program gives `h + 1`: the engine binds `a` (the first of `a`, `h` in
sorted order), not the outer `a = 5`. In the editor, the `a` of
the limit is in the group of `let a` (`documentBindings()` in
`src/epsil/occurrences.ts`), so a rename of `let a` changes it too.

With `let L = [1, 2]` followed by `limit(total(L)*t, 0)`, the engine binds `t`,
because `L` is a list, and the `L` of the limit is correctly in the group of
`let L`.

The other case, since CE-1038: with `let L = [1, 2]` followed by
`limit(total(L), 0)`, the engine binds no name (a list is not a candidate), so
the `L` of the limit reads the outer `L`. The editor binds the `L` of the limit
as the limit variable, because it is the one candidate, so a rename of `let L`
does not change it. A rule that gives no site for a sole candidate that the
program binds would also give no site for `let h = 5` followed by
`limit(sin(h)/h, 0)`, the witness of CE-1038.

## Cause and options

`binderSitesOf()` (`src/epsil/resolve-library-names.ts`) gives no site when the
first candidate of the implicit variable is a name that the program binds and
other candidates follow: the engine's choice depends on the value of that name,
which the analysis does not know. Options: (a) read the type of the `let`
initializer when it is a literal (a number, a list, a string, a function
literal), and choose as the engine does, also for a sole candidate; (b) keep
the result. Size M for (a).
