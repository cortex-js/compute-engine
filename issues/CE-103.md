Inside a block that defines its own `Pi`, reading back the saved form of a result that contains π gives a value computed with the local `Pi`.

## Witness

```
in a block with Declare(Pi, real) and Assign(Pi, 3):
r = Sum(1/n², n, 1, ∞)    ->  π²/6 (N = 1.6449), correct
ce.box(r.json)            ->  3²/6 = 1.5      (outside the block: 1.6449)
```

## Cause and options

Only the global scope refuses a declaration of `Pi`. A result that the engine builds with
the library π serializes as `Pi`, and boxing that JSON inside the scope reads
the local.

- (a) A spelling of the library constant that a local cannot capture: a new
  MathJSON serialization rule that every consumer must read.
- (b) Each site that builds a result with π keeps it symbolic when `Pi` is
  shadowed (`holdsShadowedPi()`): many sites, and a value is lost.
- (c) Recommended: document that a JSON round trip inside such a scope reads
  the local. No code change.

If nothing is decided, the behavior stays and is not documented.

## Decision

User decision 2026-11-06: (c)

User decision 2026-11-06: Change of mind: we're going to do (a). There is another issue about having some way to access definitions shadowed in the current scope. We'll introduce the `super.symbol` syntax for Epsil and probably something like `Super:Symbol` for MathJSON.
