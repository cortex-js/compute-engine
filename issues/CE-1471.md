A recursive function that returns a list or a point, with that result declared, no longer compiles.

## Witness

1. `N: real`; `F` declared `(real) -> list<real>`,
   `F := Function(Which(k = N - 1, List(k), True, ListJoin(List(k), F(k + 1))), k)`;
   `compile(F(0), { to: 'javascript', symbolic: ['N'] })`.
2. `F` declared `(real, tuple<real, real>) -> tuple<real, real>`,
   `F := Function(Which(k = 0, p, True, F(k - 1, p) + Tuple(1, 0)), k, p)`;
   `compile(F(N, Tuple(1, 2)), …)`.

0.193.0: both compile; at N = 4 (case 1) and N = 3 (case 2) the code gives
`[0, 1, 2, 3]` and `[4, 2]`, the interpreter's values.
0.194.0: both decline, "a recursive call of F, a function with a list or tuple
result".

The IR README ("User functions") documents this decline: "Declined: a
recursive call of a function with a list result (its type is the body's)". Here
the result type is declared, so it does not have to come from the body.

## Expected

Both compile on javascript and give the interpreter's value.

`npx tsx scripts/repros/2026-11-18-ce1471-ce1472-ce1473-ce1474-ce1475-ce1476-ce1477-ce1478-compiler-regressions-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value with the interpreter's. The last line for this issue reads `CE-1471: READY` when both cases compile and give the interpreter's value.
