An Epsil variable assigned a filtered infinite range changes its value when a variable that the filter reads changes later.

## Witness

```epsil
k = 3
let big = filter(1..oo, c => c > k)
first(big)    // 4
k = 10
first(big)    // 11; it should stay 4
```

## Cause and options

An assignment stores the elements of a finite lazy collection that reads a
variable, as a list or a set (`assignedValue`, `library/core.ts`). Three cases
stay lazy and keep their variables by name:

- CE-81.1: a collection with no last element (the witness).
- CE-81.2: a `Filter` over a dictionary.
- CE-81.3: a `Filter` over a set held by a local typed `collection<any>`.

One fix covers the three: replace each variable the collection reads by its
current value, and keep the collection lazy. The replacement must reach inside
the function literal (the `k` of the predicate) without touching its
parameters. The host function `ce.assign()` keeps the live view on purpose.
