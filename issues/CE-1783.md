In Epsil, the message of an error in a written negation inside the second operand of a subtraction that is itself the second operand of a subtraction names a sum that the program does not contain.

## Witness

```
let w: any = "s"
let v = 1 - (2 - -ln(w))  ->  "in Ln argument 1, in Negate argument 1, in Add argument 1"
expected                  ->  "in Ln argument 1, in Negate argument 1, in Subtract argument 2"
                              (or with a second "in Subtract argument 2")
let v = 1 - (2 + -ln(w))  ->  "in Ln argument 1, in Add argument 1"
expected                  ->  "in Ln argument 1, in Negate argument 1, in Subtract argument 2"
```

The underline is `w`, which is correct.

## Cause and options

The inner subtraction `2 - -ln(w)` is `Add(Ln(w), 2)` in canonical form: its
negation and the written `-` cancel. The outer subtraction then distributes a
new negation, so the canonical form is `Add(Negate(Ln(w)), -1)`. The new
`Negate` has no source range, and `argumentOffsets` gives the range of
`ln(w)`, which is not the range of a written operand of the sum (the written
operand is `-ln(w)`). `rejectFramesOutsideScope`
(`src/epsil/error-location.ts`) thus accepts no frame, and
`subtractionFrames()` does not rename the `Add` frame. In `1 - (2 + -ln(w))`
the two negations cancel, and the canonical operand is `Ln(w)`, whose range
is not the range of the written operand `-ln(w)` either. Option: when the
canonical operand is a `Negate` with no source range, also compare the range
of its operand with the operand of a written `Negate` operand of the sum.
