A loop that writes the elements of a variable that holds a range of more than 10 000 elements ends with the error "Maximum call stack size exceeded".

## Witness

With the fix of CE-1796, `executeEpsil()` on a new engine with no time limit:

```
let xs: list<integer> = 1..20000
for k in 1..3000 { xs[k] = 0 }
xs[3000] + xs[3001]
```

The value is `Error("Maximum call stack size exceeded")` after 7 seconds; the
expected value is `3001`. With `1..10000` the value is correct.

`plausible`: a sieve starts from the numbers `1..n`. Workaround: start from a
list, `let xs = [k for k in 1..20000]`; the loop then gives the value.

## Cause and options

`xs[k] = v` is `Assign(xs, ReplaceAt(xs, k, v))`, and over a source of more
than 100 elements `ReplaceAt` gives a lazy view. `eagerElementsOf()`
(`library/collections.ts`) lists a chain of 32 views into a `List` when the
chain has at most `ce.maxCollectionSize` (10 000) elements, or when it is over
a `List`, whose elements are in memory already. A chain over a longer `Range`
is not listed, because a list of the elements of a range can be larger than
`ce.maxCollectionSize` allows (`1..10^9`), so it gets one view for each write,
and a read of an element goes through every view by recursion. The test "a
chain over a range of more than 10 000 elements stays a chain" in
`test/epsil/assign-to-list-element.test.ts` holds this behavior.

Option A: when the 32 views are all `ReplaceAt`, replace them with one view
over the same source that holds the written positions and values in a map; the
source is not listed, and the depth has a limit.

Option B: list the chain when its count is under a second, larger bound, and
give an error value above it.
