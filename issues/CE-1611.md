A product or a negation that holds a host-declared constant zero is read as a nonzero value: zero divided by it gives 0, and its power 0 gives 1, instead of NaN.

## Witness

```ts
ce.declare('z', { value: 0, isConstant: true });
ce.box(['Power', ['Negate', 'z'], 0]).json;                    // 1, expected 'NaN'
ce.box(['Divide', 0, ['Multiply', 'z', 'x']]).json;            // 0, expected 'NaN'
ce.box(['Power', ['Multiply', 'z', 'x'], 0]).simplify().json;  // 1, expected 'NaN'
ce.box(['Power', ['Multiply', 2, 'z'], 0]).simplify().json;    // 1, expected 'NaN'
ce.box(['Divide', ['Multiply', 'z', 'x'], ['Multiply', 'z', 'x']]).json; // 1
ce.box(['Divide', ['Power', 'z', 'n'], ['Power', 'z', 'n']]).json;       // 1
```

`evaluate()` gives `NaN` for the third and the fourth line (the canonical
form keeps the power), and the wrong value for the others. Measured on the
working tree at a0c8e81a663d367bb571c8dc7051984c2cdbc366 with the fix of
CE-1429. The witness is `crafted`: each program writes the constant zero as
a factor of a divisor or of the base of a power with the exponent 0. The
workaround is to evaluate the operand before building the expression.

## Cause and options

CE-1361 and CE-1429 guard the rules `a/a -> 1`, `0/a -> 0` and `a^0 -> 1`
with `isConstantThatMayBeZero()` (`boxed-expression/maybe-zero.ts`), which
reads only a constant symbol. An operand that holds the constant (`-z`,
`2z`, `z·x`, `z^n`) is read as an expression with a free variable, or as a
finite number:

- `canonicalPower` (`arithmetic-power.ts`, "Zero as exponent"): the base
  `-z` is a `Negate` of a symbol with a finite value, so `(-z)^0` is `1`.
- `canonicalDivide` (`arithmetic-mul-div.ts`, `0/a = 0` and `a/a = 1`): the
  divisor `z·x` has an unknown, so it is not a "constant expression", and
  the quotient folds.
- `expandPower` (`expand.ts`, `exp === 0`) gives `1` for every base that is
  not a constant symbol, and `simplify()` tries the expansion.

Options: (a) make the test read through `Negate`, a product and a power: an
operand is "a constant that may be zero" when one of its factors is. The
guards are then the same lines, and the cost is the walk of the factors in
each rule. (b) Keep the canonical form and only stop `expandPower` and the
`simplify()` rules, so that `evaluate()` gives `NaN`; `(-z)^0` and `0/(z·x)`
stay wrong in the canonical form. Recommended: (a).
