A block that adds two of its own list variables gives an unevaluated expression that names those variables when the lists have more than 100 elements.

## Witness

At `2e6ca255ba4c364ac6f159e7e21cc5a257227a2a`:

```ts
const ce = new ComputeEngine();
ce.box(['Block',
  ['Declare', 'x', { str: 'unknown' }, ['Range', 1, n]],
  ['Declare', 'y', { str: 'unknown' }, ['Range', 1, n]],
  ['Add', 'x', 'y'],
]).evaluate().json;
```

| `n` | Result |
| --- | --- |
| 100 | `["List", 2, 4, …, 200]` |
| 101, 120 | `["Map", ["Function", ["Block", ["Add", "_1", "_2"]], "_1", "_2"], "x", "y"]` |

Expected for 120: the list `[2, 4, …, 240]`. The result for 101 names `x` and
`y`, the locals of a block that has ended, so nothing can evaluate it later.
Whether 0.187.1 gave the list was not measured.

## Cause and options

Not investigated. The sum of two lists longer than 100 elements stays a lazy
`Map`, and the block returns it without making it a value, so it leaves the
block with the names of the block's locals. Options: the block materializes a
lazy result that reads one of its locals, or the lazy `Map` holds the two
lists and not their names.
