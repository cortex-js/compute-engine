A function that takes a function as a parameter and calls it, written as LaTeX and read back, multiplies by that parameter instead of calling it.

## Witness

```
f = ["Function", ["g", "x"], "g", "x"]
f.latex                       (g, x)\mapsto g(x)
ce.parse(f.latex).json        ["Function", ["Block", ["Multiply", "g", "x"]], "g", "x"]
Apply(f, x ↦ x·x, 3)          9
Apply(parsed f, x ↦ x·x, 3)   3 · (x ↦ x·x)
```

Checked 2026-11-06 at `83a2ea70eb0e2d0d4d8ee2ab932c2eefb4f4547c`. The
`\mathrm{Function}(…)` form that a literal with a tuple pattern gets has the
same result: `\mathrm{Function}(g(x), \mathrm{Tuple}(g, x))`. When the
parameter is typed as a function (`["Typed", "g", "'(real) -> real'"]`), the
round trip gives the same literal.

## Cause and options

The parser reads `g(x)` as the product `g·x` when `g` has no function
definition, and an untyped parameter has none.

- (a) The `Function` serializer writes the call of a parameter with an
  explicit application (`\mathrm{Apply}(g, x)`), which reads back as a call.
- (b) The parser reads `p(x)` as a call when `p` is a parameter of the
  enclosing literal.
