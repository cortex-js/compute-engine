On GLSL, a helper function that the caller declares free of side effects is still treated as if it had them, so some expressions that use it do not compile.

## Witness

With `F: (real) -> real`, `x: real`, `n: integer` and
`functions: { F: { source: 'myFn', pure: true } }`, compiled to `glsl` at
`d43d68f25`:

- `Cot(F(x))`: `canCompile()` refuses it ("The operand `F(x)` of `Cot`
  contains code that the caller supplies … the GLSL code writes that operand
  more than once").
- `F(x) + Sum(F(x) + k, k, 1, n)`: `canCompile()` answers `{ ok: true }` and
  `compile()` throws ("its code would be computed in a statement ahead of the
  rest of its statement, and code supplied by the caller …").

Both give the same result with `functions: { F: 'myFn' }`, so the declaration
`pure: true` has no effect on GLSL. On the JavaScript target it does: a pure
entry is not caller code there.

The workaround: compile to `javascript`, or write the helper so that the
expression does not repeat or hoist it.

## Cause and options

`reachesCallerCodeOn()` (`compile-folding.ts`) does not count an entry for
which the session's `isPureOverriddenOperator` answers `true`, as its comment
says. The JavaScript target passes that predicate in its options of the
common-subexpression pass (`javascript-target.ts`, `pureFunctions` and
`customOperator`). The GLSL target does not
(`gpu-shader-target.ts`, the `cseOptions` of the prepare stage pass
`isOverriddenOperator`, `isStringVar` and `isVarsKey` only), so every
`functions` entry counts as caller code there.

Fix: pass `isPureOverriddenOperator` in the GLSL `cseOptions`, with
`entryIsPure()` of `function-purity.ts`, as the JavaScript target does (the
GLSL target has no `operators` precedence to check, or check it the same
way). The pass reads the same options (`prepareAndType()`), so `canCompile()`
and `compile()` change together. Then a pure entry is shared by the
common-subexpression pass and is written twice without a refusal. Size S.

Related, not part of this fix: a `vars` entry
(`Record<MathJsonSymbol, TargetSource>`) has no way to declare that its
source is pure, so any source other than a plain read counts as caller code.
CE-1176 measures what binding caller code in order would cost.
