At the default precision, the numeric value of a fraction times the square root of a negative number times a symbol has a wrong last digit: `N((1/3)·√-2·x)` gives `0.471404520791031682933i·x`, where `N(√-2/3)` gives `0.471404520791031682934i`.

## Witness

At `0528fa19b` with the CE-1718 fix, default precision (21 digits):

```js
ce.box(['Multiply', ['Rational', 1, 3], ['Sqrt', -2], 'x']).N().json;
// ["Multiply", ["Complex", 0, {num: "0.471404520791031682933424928812542301650399437"}], "x"]
ce.box(['Multiply', ['Rational', 1, 3], ['Sqrt', -2]]).N().json;
// ["Complex", 0, {num: "0.47140452079103168293389633"}]
```

`√2/3` is `0.47140452079103168293389624…`. The real product
`N((1/3)·sin(1)·x)` has the same error past the 21st digit
(`0.2804903282692988355507195…`, where `sin(1)/3` is `0.2804903282692988355508341…`),
but its 21st digit rounds correctly.

## Cause and options

`mulNEvaluated()` (`arithmetic-mul-div.ts`) keeps an exact rational literal
for the fold with the float factors only when every factor is a number
literal. With a symbolic factor it rounds `1/3` first, and the product of
the rounded `1/3` and the big decimal of `√2` keeps the error of the
rounding. The comment there gives the reason: a product with a symbolic
factor must not keep an exact coefficient that `expandProducts` rebuilds into
a `Divide`. A fix folds the number factors (with the exact rationals) into
one float coefficient before the product with the symbolic factors.
