The remainder of a large whole number given as a JavaScript number is wrong: the remainder of 2^60 by 7 is -3 instead of 1.

## Witness

On main `2f35b1b78`, `new ComputeEngine()`:

```ts
const e = ce.box(['Remainder', 'x', 'y']);
e.subs({ x: ce.number(2 ** 60), y: ce.number(7) }).evaluate().toString();   // "-3" (right: 1)
e.subs({ x: ce.number(2 ** 60), y: ce.number(2.5) }).evaluate().toString(); // "0"  (right: 1)
ce.box(['Remainder', ['Power', 2, 60], 7]).evaluate().toString();           // "1"
```

A second witness with a quotient below 2^53 (found by the review of CE-1448,
session ce-interval, 2026-11-18): on `new ComputeEngine({ precision:
'machine' })`, `Remainder(-825977087020874, 0.7)` evaluates to `2`; a
remainder by 0.7 is at most 0.35 in magnitude (the interval kernel encloses
the exact value in `[-0.25, 0]`). The cancellation of `x - y * round(x / y)`
in doubles is relative to `x`, not to the remainder.

`2 ** 60` is an exact double, so the remainder has an exact value. The
compiled code (0.194.0) gives 1 for both. A similar report, not checked:
`Mod(2^60, 10)` boxed from a JavaScript number gives 0.

## Cause and options

Not investigated. The machine-number branch of `Remainder` probably computes
`x - y * round(x / y)` in doubles, which loses the low digits when `x / y` is
above 2^53. Fix: for a finite double operand, use an exact remainder
(`x % y` then the adjustment to the nearest-integer quotient, which is exact
in IEEE arithmetic), or the bignum path when `|x / y| >= 2^53`.
