A function defined inside a block gets its result type from before its definition, and the type can leave out the value.

## Witness

`Block(Assign(f, t ↦ Count(t)), f([[0, 0], 5]))` evaluates to `2`, but is
typed `list<list<unknown^2> | unknown>` (checked 2026-11-06). The type must
hold the value: `integer`, or wider.

## Cause and options

The type of the call `f(…)` is computed when the block is boxed, before the
`Assign` runs, so `f` has no definition there. A compiled function that trusts
the type can give a wrong shape. Fix: type a call of a name that the same
block assigns from the assigned value, or as `unknown`. The functions to change
are not yet identified.
