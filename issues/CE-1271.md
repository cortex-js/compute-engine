The maximum of a list declared as integers that holds 1, 2, 3, … is infinity, but its type says it is an integer.

## Witness

Run on main at `bd05d91fbc5cd3d60c88e72f0b4248dbb43ffc79` (0.188.0):

```js
ce.box(['Assign', 'f', ['Function', ['Max', 'xs'], ['Typed', 'xs', 'list<integer>']]]).evaluate();
const e = ce.box(['f', ['Range', 1, 'PositiveInfinity']]);
e.type;        // 'integer | nan'
e.evaluate();  // PositiveInfinity

ce.declare('N', 'list<integer>');
ce.box(['Max', 'N']).type;  // 'integer | nan'
ce.box(['Sum', 'N']).type;  // 'integer'
```

A symbol that HOLDS the endless range is typed from its value today
(`M: list<integer> := Range(1, +oo)`: `Max(M)` is `number`). With decision
D16 of `docs/plans/2026-11-11-bound-once-spec.md` (a static type does not
depend on a value) that case gives `integer | nan` too, so D16 makes this
visible for a declared symbol.

## Cause and options

The type handlers of the aggregates (`Sum`, `Max`, `Min`, `Mean`) give the
element tier for a declared `list<T>`, which assumes a finite list, while an
assignment to `list<integer>` and a call with a `list<integer>` parameter
admit an endless producer.

(a) A declared `list<T>` refuses an endless producer, at the assignment and
at the call: `list` means a finite list. The types of the aggregates stay
as they are. (b) The aggregates add the infinite values of the tier for a
list that is not known to be finite (`Max` of `list<integer>` is
`integer | nan | +oo | -oo`). It widens every aggregate of a declared list.
