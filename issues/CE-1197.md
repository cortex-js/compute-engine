One test of the suite fails with a timeout in a full run on a loaded machine and passes when its file runs alone.

## Witness

`test/compute-engine/ce-1102-provisional-registry-weak-references.test.ts`,
"the definitions of a discarded scope leave the registry": "Exceeded timeout
of 5000 ms for a test". Three of four runs of `npm test` in a clean worktree
on 2026-11-10 failed with it and nothing else:

| Commit | `CE_JS_PROFILE` | Result of this test |
| --- | --- | --- |
| `04c9bd783279d05a2d60eb13a1f281a06731ebf8` | `numeric-kernel` | timeout (file took 11.9 s) |
| `5f5acea425bb8347bf401aa476b7fc23c0a94991` | `numeric-kernel` | timeout (19.2 s) |
| `4422cd7bf64eca17935bd7655e6a5f0a972a3199` | `numeric-kernel` | passed |
| `4422cd7bf64eca17935bd7655e6a5f0a972a3199` | not set | timeout |

The file alone passes in about 1 s (6 tests). The nightly run at
`d50138f68d4abc6934f44890f96bc242b1cdfab6` passed. Other sessions ran tests on
the box during these runs.

## Cause and options

The test runs six passes, each with a forced garbage collection after a
`setTimeout(0)` (`collect()`), and a second loop of up to 20 collections. With
all workers busy, the collections take longer than the 5 s limit of a test.
Options: give the test a larger limit (the third argument of `test`), or
reduce the number of passes. The second test of the file has the same shape.
