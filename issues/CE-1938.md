A test or a count over a reversed sorted list with a variable element gives a wrong answer.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
const r = ['Reverse', ['Sort', ['List', 3, 'x', 1]]];
ce.expr(['Any', r, ['Function', ['Greater', 'k', 2], 'k']]).evaluate(); // False, expected True
ce.expr(['Count', ['Take', r, 2], 3]).evaluate(); // 0, expected unevaluated
ce.expr(['Count', r, ['Function', ['Greater', 'a', 2], 'a']]).evaluate(); // 0, expected 1
ce.expr(['Sum', r, ['Element', 'k', ['List', 1, 2]]]).evaluate(); // [], expected unevaluated
```

The last two were found by the review of CE-1821. The same forms over
`Sort([3, x, 1])` without `Reverse` stay unevaluated.

Read on d656f0889f874dfc5eb117f380a4d03157fc5f4e.

## Cause and options

`Sort` cannot order `x`, so its value stays `Sort([3, x, 1])`, which is not
a collection and has no elements. `Reverse` over it is a lazy view: its
`isEnumerableCollection` is `undefined` (an eager `Sort` source), so
`isEnumerableSource` (`collection-utils.ts`) evaluates the view, gets the
same view, and answers `true` because the view is a collection. The walk of
the view then yields no element, and the operator folds that empty walk:
`Any` gives `False`, the count gives `0`.

Option: in the fallback of `isEnumerableSource`, also answer `false` when a
first operand of the evaluated view, down a chain of lazy views, is not a
collection. CE-1821 removes the wrappers for the order-independent operators
(`Sum`, `Max`, `Count(xs, v)`), which hides the case for them only.
