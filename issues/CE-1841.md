A product or quotient of a numeric indexed collection and a list reports a list of numbers, but it returns a list of points when the collection holds a point.

## Witness

On main `327732c36831e48ca5463d66eabe12b84f7ee207`:

```ts
const ce = new ComputeEngine();
ce.declare('u', 'indexed_collection<number>');
const p = ce.box(['Multiply', 'u', ['List', 1, 2]]);
const q = ce.box(['Divide', 'u', ['List', 1, 2]]);
console.log(String(p.type)); // indexed_collection<number>
console.log(String(q.type)); // list<number>
ce.assign('u', ['Tuple', 1, 2]);
console.log(p.N().json); // ['List', ['Tuple', 1, 2], ['Tuple', 2, 4]]
console.log(q.N().json); // ['List', ['Tuple', 1, 2], ['Tuple', 0.5, 1]]
// p.N().type.matches(p.type) and q.N().type.matches(q.type) are both false
```

With `u := [1, 2]` both values are lists of numbers, which match the types.

## Cause and options

An `indexed_collection<number>` operand can hold a list or a point. The
broadcast lift (`broadcastLiftType`, `broadcast-lift-type.ts`) types the
application as if it holds a list. A point beside a list gives a list of
points. CE-1583 fixed the case where no other operand is a list: the result
is now `indexed_collection<…>`. For this case, the sound type is the union of
the two results, `list<number> | list<tuple>` (the arity of the point is not
known), or a wider list type.
