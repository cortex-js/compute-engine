In the exact-integer (bigint) compile mode, dividing an integer by a number that is known to divide it falls back to the interpreter.

## Witness

From the decline census on GitHub #638: 10 family operations of a
combinatorics corpus. On main f42a02d1323b9e40cf2def511715fc3034ae8d6c:

```ts
ce.declare('n', 'integer');
ce.declare('m', 'integer');
const e = ce.box(['Divide', ['Subtract', 'n', ['Mod', 'n', ['Factorial', 'm']]], ['Factorial', 'm']]);
compile(e, { mode: 'bigint', fallback: false });
// Could not compile: Divide(...): Divide of integer, integer, whose value is
// not an integer (the bigint mode)
```

`fallback: true` gives the interpreter's value (the workaround).

## Cause and options

The bigint mode lowers a `Divide` only when its value is proved an integer.
`(a − Mod(a, b)) / b` is always an integer (it is `Floor(a / b)`); a rule for
that pattern would cover these items. A general divisibility proof is not
needed.
