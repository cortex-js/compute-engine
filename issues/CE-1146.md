A function that a function body defines does not see the variables of the body when the function literal is applied inside another function.

## Witness

At `0aa4a0a4d0c9f2b53ab6924a111046541807193a`, with `evaluate()` and with
`evaluateAsync()`:

```ts
const inner = ['Function',
  ['Block',
    ['Declare', 'c', 'real', ['Multiply', 5, 'n']],
    ['DefineFunction', 'h', ['Function', ['Add', 'c', 'k'], 'k']],
    ['h', 10]],
  'n'];
ce.box([inner, 1]).evaluate().json;                                  // 15
ce.box([['Function', ['Block', ['Apply', inner, 1]]]]).evaluate().json;
// ["Add", "c", 10]   (must be 15)
```

The call of `h` happens while the call of `inner` runs.

## Cause and options

When the outer function is applied, `captureClosures()`
(`src/compute-engine/function-utils.ts`) rebuilds the literal `inner` with a
new body scope. The call frame of `inner` is the parent of that new scope. The
literal of `h` keeps the canonical body scope of `inner` as its defining scope
(`definingScopeOf()`), and that scope is not the parent of the frame, so `h`
reads `c` as a free symbol.

Option: when `h` is called, map the canonical body scope to the rebuilt scope
that stands for it (`markCallableFrame()` records that link), and use its
frame. Size M. After this fix, the closure case of CE-1094 for a nested
literal (`Assign(g, x ↦ h(x))` in `inner`, then `g(10)`) needs the same
mapping in `recordCallFrameRun()`.
