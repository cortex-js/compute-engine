An Epsil prelude function that uses `sum`, `limit` or another binding operator can compute a wrong value when Tycho's own copy of the binding rules differs from the engine's.

## Witness

`binderSitesOf(ce, node, source, members?)`
(`dist/types/epsil/resolve-library-names.d.ts`) says which operands of a library
call bind a variable and where each is visible; the `./epsil` entry does not
export it. Tycho's prelude runner (`src/plot-core/prelude-runner.ts`) must know
that `sum(k^2, k, 1, n)` binds `k` and reads `n`, and that `limit(sin(h)/h, 0)`
binds `h`. Its first version compiled `n1 = n1 + sum(k, k, 1, n1)` in a loop to
the wrong value. It now keeps a hand-written rule for five operators. Reading on 0.182.0: `row 510: NOT READY on 0.182.0
(binderSitesOf not exported)`.

Requested: export `binderSitesOf` and its `BinderSite` type from
`@cortex-js/compute-engine/epsil`.

Tycho half on adoption: replace the rule in `prelude-runner.ts` with the export,
and remove the comment that names this issue.

## CE answer

CE (2026-11-06): `binderSitesOf` exists in `src/epsil/resolve-library-names.ts`,
and the `./epsil` entry (`src/epsil.ts`) exports `resolveLibraryNames` from that
module but not `binderSitesOf`; `BinderSite` is in `src/epsil/occurrences.ts`. The
fix is two export lines and a doc comment, size S. It makes an internal function
public API, so the board decides. Proposed: P3 (the hand-written rule in Tycho
already gave one wrong value) and the next release. Workaround until then: the
five-operator rule Tycho keeps.

CE (2026-11-07): fixed. `@cortex-js/compute-engine/epsil` exports
`binderSitesOf(ce, node, source)` and the type `BinderSite`. Two limits for the
Tycho half: the function does not see the program's own bindings (call it only
when the program does not define the callee), and `limit(sin(h)/h, 0)` and
`nLimit(f, a)` give no site although the engine binds `h` (filed as CE-1038).
Keep the hand-written rule for these two forms, or write
`limit(sin(h)/h, h, 0)`.
