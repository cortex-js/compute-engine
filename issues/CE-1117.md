A curve made of many small pieces cannot be offset along its slope, because the slope of all the pieces together passes a size limit.

## Witness

Plain engine. 29 cubic Bezier pieces, each read from a literal list of 31
points (`At(P, 3⌈u⌉ + j)`). `D(v · PointX(piece_k), u)` is differentiated
for each of the 29 pieces. `D(v · PointX(List(piece_1, …, piece_n)), u)` is
differentiated for n ≤ 13 and stays `D(…)` for n = 14 (93 ms).

Corpus: the "Sorry" text of Desmos document `art/2ki2hjsouf` is a list of 29
such pieces, and two rows offset it along its normal. With CE-1115 and
CE-1116 simulated, the derivative of the list is still refused; with this
limit counted per element as well, the row evaluates to a list of 29 points
in 0.6 to 0.8 s (Tycho simulation,
`scripts/repros/2026-11-07-lj-row-reduction-probe.mts --elementwise`).

## The question

`MAX_DERIVATIVE_NODES` (25 000, `symbolic/derivative.ts`) bounds the nodes
built by one top-level differentiation. Its comment calls it a safety valve
against pathological input, such as a deeply nested radical. The derivative
of a list is the list of the derivatives of its elements, each computed
alone, so the total grows with the length of the list, not with the depth of
an element.

Options:

- (a) Recommended: when the operand of a derivative is a list (after the
  flattening of CE-1116), apply the limit to each element: reset the
  footprint per element. The pathological case, one huge element, is still
  refused. Cost: S. A list of n elements can then build up to n × 25 000
  nodes; the time stays linear in n.
- (b) Keep one limit for the whole list. Tycho would then differentiate each
  element itself, which needs Tycho to know where the list is in the formula.
