A function that adds up an element of each tuple of a list of mixed tuples has no type, so it does not compile.

## Witness

`executeEpsil(new ComputeEngine(), …)` of

```epsil
function f(n: integer) { let t = 0.5; for g in [((1, 2), 2), ((3, 4), 3)] { t = t + g[2] }; t }
```

`ce.box('f').type` is `(n: integer) -> never`, and `f(2)` evaluates to 5.5.
The compilation declines ("a body of f that is not integer"). The result
type is `number` with `t = g[2]` (no read of `t`), with a list of tuples of
tuples (`[((1, 2), (5, 6)), …]`), with a flat list of tuples (`[(1, 2.5)]`),
and outside a loop (`let g = ((1, 2), 2); t = t + g[2]`). A list local grown
from the same reads is `never` too:
`let L: list<real> = []; for g in [(A, 2), (B, n)] { L = [...L, g[1][2] * g[2]] }; L`
with `A = (-1, 0, 0)` and `B = (2, 0.5, 0)` (`f(2)` is `[0, 1]`).

## Cause and options

Not investigated: the inferred type of the local `t`, written in the loop
from its own value and from `At` of a tuple whose elements are a tuple and a
number, is `never`.
