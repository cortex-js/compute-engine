A negative power of a call of a user function named `Divide` is computed as a power of a quotient, and gives a wrong value.

## Witness

At commit `af5e9937f440434c7eb965dcb5e0e1d5320bf0bb`:

```ts
ce.pushScope();
ce.declare('Divide', 'function');
ce.assign('Divide', ce.box(['Function', 1000, 'u', 'v']));
const e = ce.box(['Power', ['Divide', 'x', 2], -2]);
e.json                              // ["Divide", 4, ["Power", "x", 2]]
e.subs({ x: 4 }).evaluate()         // 1000; must be 1000^-2 = 1e-6
ce.popScope();
```

`crafted`: the program defines a user function with the capitalized name of
a library function.

## Cause and options

The `(a/b)^{-n}` distribution of `canonicalPower` (`arithmetic-power.ts`)
tests `isFunction(a, 'Divide')`, which reads a call of a user `Divide` as a
quotient, and builds its result by the name `Divide`, which then binds to
the user function. Test the operand with `isLibraryOperator(a, 'Divide')`
(`library-shadowing.ts`), as the nested-power fold of the same function does
since CE-1109.5. The other branches of `BoxedFunction.toNumericValue()`
(`Negate`, `Multiply`, `Power`, `Sqrt`) read a call by name in the same way
(CE-1122).
