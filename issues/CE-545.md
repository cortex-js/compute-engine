A call of a function on a value of unknown type and on a value declared as "a number, a point or a list" gets two different result types.

## Witness

```
S(1, g(2))  operand typed unknown
            result number | tuple | list<number | tuple | list<any>>
T := a ↦ a + 1, y declared with that wide type
T(y)        result any
```

Tests lock the `any` answer (`broadcastable-typing.test.ts`,
`tycho-373-passthrough-broadcast-typing.test.ts`).

## Cause and options

For a body that does not work component by component,
`componentwiseTupleCallType` (`call-result-type.ts`) answers `any` for the
`tuple` member of the wide type. User decision 2026-10-27: that `tuple` is read
as a point. Question: which rule is right for such a body?

- (a) Answer `any` in both cases. Safe; can add compiled declines.
- (b) Answer the wide type in both cases. More precise; it must hold every
  value such a body can give.

Recommended by the conversion (the old entry had none): (a), because `any`
never leaves out a value. With no decision, the rules stay different.

## Decision

User decision 2026-11-06: (b) answer the wide type in both cases; the two tests that lock the any answer change.
