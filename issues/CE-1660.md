The type error for a function name used as a value shows the name twice
quoted, with a capital letter the user did not type, and the statement
between backquotes.

## Witness

On CE 0.197.1, `checkEpsil(ce, "const A : matrix = onesMatrix")` returns

```json
["static-type-error",
 "The value \"\"OnesMatrix\"\" of type \"(integer, integer?) -> matrix\" is not compatible with the declared type \"matrix\"",
 "const A: matrix = onesMatrix",
 "incompatible-type"]
```

and `epsilDiagnosticMessage` gives

```
Type error: The value ""OnesMatrix"" of type "(integer, integer?) -> matrix" is not compatible with the declared type "matrix" in `const A: matrix = onesMatrix`
```

Three flaws:

1. The value is quoted twice (`""OnesMatrix""`).
2. It is the canonical name `OnesMatrix`, not `onesMatrix` as typed.
3. The statement is quoted in backquotes, which a host that shows plain text
   shows as is, and it is the reformatted statement (`A: matrix`), not the
   source (`A : matrix`).

Every user meets it: the error shows while a function name is typed, before
its `(`. The instrument prints READY when the message has no doubled quote and
names the function as typed (exit 0); today it prints NOT READY (exit 1).

## Cause and options

Not investigated in CE. The value seems serialized as a string, then quoted
again by the template. Requested: quote the value once with the source name,
and give the statement once (or leave it out: the diagnostic's range already
covers it).
