Compiled code with the default options gives `{ re: NaN }` for a sum with a call of a local function whose body is the square root of an integer.

## Witness

At `99cee49c8926048d73e590a0274567b9290e8bcc`, JavaScript target, `x: real`,
`k: integer`, `u: real`:

```ts
const e = ce.box(['Block',
  ['DefineFunction', 'lf', ['Function', ['Sqrt', 'k'], 'v']],
  ['Add', 'x', ['lf', 'u']]]);
compile(e).run({ k: 4, u: 0.5, x: 1 }); // { re: NaN }, the value is 3
compile(e, { cse: false, constantFold: false }).run({ k: 4, u: 0.5, x: 1 }); // 3
```

With `cse: false, constantFold: false` and an `Assign` before the definition
(`Block(Assign(t, Log(u, 10)), DefineFunction(lf, …), Add(x, lf(u)))`), the
same options give `{ re: NaN, im: undefined }` at `k: 0`. The code reads the
call on the complex lane (`({ re: _.x + _tv1.re, im: _tv1.im })`) while the
local function returns the real `Math.sqrt(_.k)`. The `numeric-kernel`
profile gives the value (`1` at `k: 0, x: 1`).

## Cause and options

The type of the call (`sqrt(k)` of an integer `k` is complex in general)
and the code of the local function (a real `Math.sqrt`) disagree. Option:
compile the local function on the lane of its declared result type (a
complex `sqrt` where the result can be complex), or read the call on the
lane of the code that the function body emits.
