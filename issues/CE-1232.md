A compiled one-sided `Limit` of a function with a jump near the point gives `NaN` where the interpreter gives the limit.

## Witness

At `0eb9d4778988822bcb042e08dc984d460923e8c5`, with `a` declared `real`:

```js
const expr = ce.box(['Limit', ['Function', ['Divide', ['Abs', 't'], 't'], 't'], 'a', -1]);
const f = compile(expr, { cse: false, constantFold: false });
f.code;           // _SYS.limit(((t) => Math.abs(t) / t), _.a, -1)
f.run({ a: 0.5 }); // NaN
expr.subs({ a: 0.5 }).N(); // 1
```

At `a = -2.25`, `1.75` and `3` the compiled value is right (`-1`, `1`,
`1`). The runtime routine itself gives the value: `limit((t) => Math.abs(t)
/ t, 0.5, -1)` (`numerics/numeric.ts`) is `NaN`. The program is the form of
a test of `compile-subtree-folding.test.ts` (`Limit(|x|/x, a, -1)`), there
at points where it is right. The `numeric-kernel` profile writes the same
call since slice 4, so it gives the same `NaN`.

## Cause and options

`limit()` starts its Richardson ladder at a distance 1 from the point and
retries closer (1/8 and 1/64) only when the estimate is rejected without a
floating-point horizon; from below at 0.5 the first rungs cross the jump
at 0 (the probable cause, not traced). Options: start the ladder at a
distance that does not reach past the nearest point where the function is
not continuous (not known in general); retry closer also after a horizon;
or start at a distance relative to `|x|` for a finite non-zero point.
