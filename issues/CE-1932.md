In Epsil, a type error in a sum with a variable operand underlines the whole statement, not the sum, when the statement also holds a subtraction.

## Witness

At `597f052d84970e12887c2490f99b6e67836ead9c`, with a host function
`figureDraw` declared `(any) -> nothing`:

```
function nr(t: real) -> nothing { figureDraw(0) }
function g(t: real) -> nothing { let y = nr(t - 1)
  figureDraw(y + 1) }
```

`checkEpsil` reports `expected number, got nothing at y` with the range of the
whole `function g` statement and the snippet `function g(t: real) -> nothing
{…`. With `nr(t)` in place of `nr(t - 1)`, the range is `y` and the snippet is
`y + 1`.

## Cause and options

The error has the frame `Add argument 1`. `locateError()`
(`src/epsil/error-location.ts`) finds two calls for the frame in the written
statement: the sum `y + 1` and the subtraction `t - 1`, whose canonical form is
a sum. The walk from the outer frames cannot select one, and the comparison
with the value that the error names (`offendingValue`) selects only a literal
argument, never the symbol `y`, so the locator uses the range of the statement.
A possible fix: compare a symbol argument too, when the error names a symbol
and only one of the candidate calls has that symbol at the frame's index.
