An Epsil program run again on the same engine with a changed parameter type keeps the old type, and its call fails.

## Witness

`executeEpsil(ce, 'let f: (integer) -> integer\nfunction f(n) { 2*n }\nf(3)')`
gives `6`. Then, on the same engine,
`executeEpsil(ce, 'let f: (real) -> real\nfunction f(n) { 2*n }\nf(2.5)')`
gives `Error("no-matching-clause", f(2.5))`; a new engine gives `5`.

## Cause and options

The preparation step boxes `function f` while `f` still holds the signature of
the first program, and the `DefineFunction` canonical handler writes that old
parameter type into the literal (`declaredForParams` →
`ascribeDeclaredParameterTypes`, `library/core.ts`). Fix in
`prepareFunctionDeclarations()` (`src/epsil/execute-epsil.ts`): for example, do
not prepare a function when an earlier `let` of the program declares its name
again with another type than the program scope holds.
