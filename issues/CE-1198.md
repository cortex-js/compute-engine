Compiling an expression that reuses the same sub-expression many times, with the `numeric-kernel` profile, takes time that doubles with each level of reuse, and stops with a stack overflow or never returns.

## Witness

A doubling DAG, built as in `test/compute-engine/compile-cse-shared-subtrees.test.ts`:

```ts
let e = ce.function('Add', [ce.symbol('x'), ce.One]);
for (let k = 0; k < d; k++) e = ce._fn('Add', [e, e]); // also Arctan2(e, e), Sin(e) + Cos(e)
compile(ce.function('Floor', [e]), { profile: 'numeric-kernel', fallback: false });
```

Measured at `4422cd7bf64eca17935bd7655e6a5f0a972a3199` (ms; the existing compiler, `constantFold: false`, takes 1 to 2 ms at every depth):

| depth | `Add(e, e)` | `Arctan2(e, e)` | `Sin(e) + Cos(e)` |
| --- | --- | --- | --- |
| 12 | 37 | 38 | 49 |
| 14 | 121 | 125 | 208 |
| 16 | 83, error | 92, error | 249, error |
| 18 | 329, error | 351, error | 1015, error |

The error is `compile-error`: "Could not compile with the profile 'numeric-kernel': an internal error in the lowering phase: Maximum call stack size exceeded". At depth 40 (`compile-cse-shared-subtrees.test.ts` with `CE_JS_PROFILE_SHADOW=1`) the compilation did not return within 180 s.

## Cause and options

The structured route (`javascript-fragment-target.ts`, `javascript-structured-lower.ts`) walks the expression as a tree: a node reached on two paths is visited twice, so a DAG of depth d costs 2^d. The existing compiler had the same defect and was made linear (the header of the test file). Options: (a) memoize the walks of the preparation and the lowering by node object, and lower a node reached on several paths once, to a local (the profile has no CSE pass, so this is new work, size M); (b) decline with `outside-profile` when the expression has more than a fixed number of paths, counted by a linear walk (size S; the shadow measure skips such an expression the same way).
