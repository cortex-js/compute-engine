An error in a sine, a cosine, an exponential or a power of a variable that holds a string is reported without naming that function.

## Witness

```
let w: any = "s"
3 - Sin(w)    ->  frames Negate argument 1, Add argument 1   (no Sin frame)
3 - Ln(w)     ->  frames Ln argument 1, Negate argument 1, Add argument 1
let v = Sin(w) * 2   ->  Epsil underlines Sin(w); for Ln(w) * 2 it underlines w
```

The same for `Cos`, `Exp`, `Arctan`, `Sinh`, `Power` (`w^2`) and `Divide`
(`w/2`, frame `Add argument 1` only). `Abs`, `Floor`, `Ln`, `Sqrt`, `Log`
and `Not` give their own frame.

## Cause and options

These operators have a `canonical` handler, so the check of the evaluated
arguments against the signature (`genericRuntimeConformance()`,
`boxed-expression/boxed-function.ts`) does not run for them. Their own
`evaluate` handler makes the error with `nonNumericOperandError()`
(`boxed-expression/validate.ts`, 18 callers), which does not know the position
of the operand. Option: in `_computeValue()`, when the handler returns a bare
`incompatible-type` error whose value is the evaluated value of exactly one
operand, add the frame of that operand. Related: CE-1023 (a string factor of
`Add` or `Multiply`).
