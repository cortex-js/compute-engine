A recursive function that takes a point and a count fails with "recursion limit exceeded" when the count is a list, though each count alone gives a value.

## Witness

On main with the CE-1692 fix (Document API, no stated types):

```
g(P) = PointX(P) · (1, 0)
f(P, n) = Which(n = 0, (0, 0), True, g(P) + f(P, n - 1))
```

`f`'s parameter `P` is inferred `collection<any> | tuple`, which admits a
list, and `n` stays `unknown`.

- `f((1,2), 2)` gives `(2, 0)` (correct);
- `f((1,2), [1, 2])` throws `CancellationError: Recursion limit exceeded`;
- one call per element gives `[(1, 0), (2, 0)]`.

The same with `K(n, x) = Which(n = 0, Mean(x), True, K(n - 1, x))`:
`K([0, 1], [1, 2, 6])` throws; one call per element gives `[3, 3]`.

Older: on 0.198.0, `f(P, n) = Which(n = 0, At(P, 1), True, f(P, n - 1))` with
`formalTypes {P: 'list<number>'}`, called as `f([1,2], [1,2])`, throws the same
error. CE-1692 makes the case reachable without stated types. A Desmos user
passes a list for a count (`f(P, [1...5])`), so the witness is plausible.
Pinned by the test "a list at the other parameter is not mapped over
(pinned)" in `test/compute-engine/document-lifecycle.test.ts`.

## Cause and options

The call is not mapped over the list at `n`, because another parameter
admits a list, so the list reaches the body whole. `Which` takes its test
element by element, but evaluates the recursive arm on the whole list, and
`n = 0` never holds for every element, so the recursion does not end.

Options:

- (a) map a call over a list argument at an `unknown` parameter even when
  another parameter admits a list;
- (b) refuse such a call statically;
- (c) stop the recursion of `Which` on a list test that is true for some
  elements and false for others.

Each changes the broadcast rule (`docs/BROADCAST-MODEL.md`), so the board
decides.
