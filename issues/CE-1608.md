The derivative of some functions of a list is a list or a matrix where the value is a number or a tuple.

## Witness

With `x` declared `real` and `L = [x^2, (x-1)^2]`, `D(f, x).evaluate()`:

| `f` | Type of `f` | Type of the value of `D(f, x)` |
| --- | --- | --- |
| `MatrixMultiply(L, L)` | `real` | `list<number>` |
| `Min(x·U)`, with `U` declared `number \| list<number>` | `number` | `list<number> \| number`, value `U·Min′(U·x)` |
| `Quartiles(L)` | a tuple of 3 fields | a list of 2 tuples |
| `CharacteristicPolynomial([[x, 1], [1, x^2]])` | `number` | a 2 by 2 matrix |

Each value holds `Apply(Derivative(f, …), …)`, so it is not a closed form, but
its shape is wrong. 0.195.1 gives the same values. Read on c8bc8271e with the
CE-1602 fix, 2026-11-20.

## Cause and options

The chain rule for an operator with no derivative rule multiplies the partial
derivative by the derivative of the argument (`differentiateApplied()` in
`src/compute-engine/symbolic/derivative.ts`). For a list argument that the
operator does not apply to each element, the product has the wrong shape.
CE-1602 declines the case where the call is a number and the argument is a
collection (`isReducedCollectionDerivative()`). These four are not covered:

- `MatrixMultiply(L, L)` and `CharacteristicPolynomial(…)` have another type
  when they are read inside `D` (`matrix | number | vector`, `expression`),
  so the call is not known to be a number.
- The type of `x·U` is a union, so the argument is not known to be a
  collection.
- `Quartiles(L)` is a tuple, not a number.

Option (a), recommended: decline the chain rule for a collection argument
unless the call is known to apply the operator to each element (the call is a
collection of the same length as the argument). It gives no value where the
element-wise rule was right for a call of unknown type (`h(L)` with an
undeclared `h`). Option (b): one decline for each of the four cases.
