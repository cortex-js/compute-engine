In a notebook code cell, typing `circ` does not offer `circle`, and typing
`segm` offers a `segment` with the wrong parameters and description.

## Witness

Tycho runs its drawing prelude (`src/graph-paper/notebook/drawing/prelude.ts`,
version 23) with `executeEpsil` on the engine that answers the code editor,
then calls `epsilCompletions(ce, cellText, offset, { typeNames, protocolNames,
parseLatex })` with the cell's text only. On CE 0.200.1 (instrument, part A):

```
A circ: no item circle
A segm: item library-function (any+) -> expression "Segment primitive — opaque typed head."
```

No function of the prelude (`circle`, `rect`, `label`, `draw`, `timer`,
`plot`, …) is ever an item. For `segment`, `polygon` and `arc` the item is the
standard-library head, while a call reaches the prelude function, whose
signature is `(p: tuple<real, real>, q: tuple<real, real>) -> Figure`. The
controls hold: a function of the source is an item, and `epsilHover` on
`circle` gives the prelude function with its `///` comment.

Expected: the names that the engine defines outside the standard library, at
the scope where the source runs, are items (kind `function`, `variable` or
`type`), with their signature and their `///` comment as `documentation` and
`description`; an engine definition that shadows a library name replaces the
library item.

## Cause and options

Per compute-engine-85 (2026-11-23, main `1cb549e1f`): the items of
`epsilCompletions` (`src/epsil/completion.ts`) are the names of the source and
`libraryEntries()`, a fixed list cached per engine; no option supplies other
names. `epsilHover` reads `ce.lookupDefinition()` first (`hover.ts`
`engineHover`), hence the disagreement. Options: (a) add the definitions of
the engine's scopes above the library scope to the items, as hover does;
(b) an option with the names to offer. (a) needs no host change.

## CE answer

CE (2026-11-23): P2 confirmed (the table value for `confidence`, `high`).
Disposition: pool, for the board. Recommended option: (a), the definitions of
the engine's scopes above the library scope become items, as `engineHover()`
reads them, with no host change; an engine definition replaces the library
item of the spelling it shadows. Fix CE-1729 before CE-1730: both need the
same reading of the engine's definitions. Workaround until then: Tycho adds
its own items for the prelude's names to the menu and drops the library item
of a spelling that the prelude defines (`segment`, `polygon`, `arc`).

## Fix

CE (2026-11-23, `aae013fd3ad68b5f63c310bb1f71ed8a52a4b7f8`), option (a):
`epsilCompletions` adds the definitions of the engine's scopes above the
library scope as items (kind `function` or `variable`), described as
`epsilHover` describes them: the signature or type, and the `///` comment as
`documentation` (first line) and `description`. An engine definition
replaces the library item of its spelling; a name of the source shadows
both. On the instrument, part A: `circ` offers `circle` with
`(c: tuple<real, real>, r: real) -> Figure`, and `segm` offers the prelude's
`segment`: READY. Tycho can drop its workaround items once it adopts the
release.
