A function that reads a variable gives the value of another variable with the same name when it is mapped over residue classes inside a scope that declares that name again.

## Witness

```
ce.declare('k', 'integer'); ce.assign('k', 1)
f   = ce.box(['Function', ['Multiply', 'k', 'x'], 'x'])
src = ce.box(['List', ['ResidueClass', 2, 5], ['ResidueClass', 3, 5]])
ListFrom(ce.function('Map', [f, src]))   ->  [ResidueClass(2, 5), ResidueClass(3, 5)]   (correct)
ce.pushScope(); ce.declare('k', 'integer'); ce.assign('k', 2)
ListFrom(ce.function('Map', [f, src]))   ->  [ResidueClass(4, 5), ResidueClass(1, 5)]   (uses the inner k = 2)
Apply(f, ResidueClass(2, 5))             ->  ResidueClass(2, 5)                         (uses the outer k = 1)
(probe 2026-11-07, HEAD 0117e657f929bfcd40364fa78a0e213084f70808)
```

## Cause and options

For a kind parameter, a literal boxed before a call is canonicalized again
from its written form in the scope of the call
(`annotateCallbacksFromContextualSolve()`, `boxed-expression/box.ts`), so a
free name binds to the inner declaration. For other types, the CE-1037 fix
rebuilds only when each name has the same binding in both scopes
(`bindsAsInCurrentScope()`). Options: (a) record the scope where the literal
was boxed and canonicalize the rebuilt literal there; (b) when the bindings
differ, give an error.
