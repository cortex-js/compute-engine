A power of 2 with a huge exact exponent shows wrong trailing digits at the requested precision.

## Witness

```js
ce.precision = 30;
ce.box(['Power', 2, ['Rational', 3000000000000001, 3]]).N();
// ➔ 1.97495439177298922275641597277e+301029995663981
//   the value is 1.97495439177298922275641642908…e+301029995663981
```

The last 5 digits are wrong at 30, 50 and 100 digits (relative error 2.3e-25
at 30).

## Cause and options

The exact operand is read with 10 guard digits (`guardDigitsN`,
`library/exact-operands-under-n.ts`). The condition number of `b^x` in `x` is
`|x ln b|`, which grows with the exponent for every base. PR #619 added the
size rule (one guard digit per power of ten of the operand above 100) for
`Power` with base `e` only. Fix: apply the size rule to the exponent operand
of every `Power`, not to its base, so `Sqrt(10^600 + 1/3)` stays answered.
Size S, with tests against the value at 300 more digits.
