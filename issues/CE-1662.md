A notebook animation whose timer callback updates a list (the Game of Life of Tycho's animation spec) runs interpreted, so it cannot reach a usable tick rate.

## Witness

On 0.197.1, a function value that assigns a closed-over variable compiles
when the variable holds a real, integer or boolean (CE-1620), but declines
when it holds a list. The instrument defines, in a fresh engine per case:

```
let c = 0
let L = [0, 0, 0]
let M = [0, 0, 0]
let bump = (t: real) => do { c = c + 1 }
let addList = (t: real) => do { L = L + [1, 2, 3] }
let setElement = (t: real) => do { M[2] = M[2] + 1 }
```

and compiles each with `compile(ce.box(name).evaluate(), { to: "javascript" })`,
then calls `run(16)` 3 times and reads the variable back from the engine:

```
CE 0.197.1
bump: compiled; c = 3 after 3 calls (interpreter 3)
addList: declined (interpreter L = ["List",3,6,9]): Could not compile: Assign(L, Add(L, List(1, 2, 3))): an assignment of L, of type list<number>
setElement: declined (interpreter M = ["List",0,3,0]): Could not compile: Assign(M, ReplaceAt(M, 2, Add(At(M, 2), 1))): an assignment of M, of type list<number>
CE-1662: NOT READY (0 of 2 list cases)
```

`bump` is the positive control. The instrument prints `CE-1662: READY` when
both list cases compile and give the interpreter's state after 3 calls.

## Ask

Extend the closure write of CE-1620 (`result.assigns`: read before each
call, written back after it) to a variable whose type is a list of a
settled element type, `list<number>` and `list<list<integer>>` at least: the
whole-list assignment (`L = L + [1, 2, 3]`, `g = step(g)` with the list
function of CE-1607) and the element assignment (`M[2] = ...`, which
lowers to `Assign(M, ReplaceAt(...))`). The list's length may change
between calls (a concatenation), so the read and write-back carry the
length.

A Game of Life generation of 32 × 32 takes 707 ms interpreted and 3 ms
compiled for 100 generations (CE-1607 reading), so a compiled callback is
the difference between under 2 ticks a second and the 8 ticks a second
that the spec's acceptance AN10 asks for.

Workaround: Tycho interprets every timer callback (phase 1 of the spec).
A callback can also compute a pure function of the list compiled (CE-1607)
and keep the assignment interpreted, but the notebook does not split a
callback that way.

Tycho half on adoption: Tycho tries to compile every timer callback and
interprets a callback that CE declines (`compiledTick` of Tycho
`src/graph-paper/notebook/ce-notebook-evaluator.ts`, the marker that cites
CE-1662). On adoption, a callback that assigns a list state compiles with no
Tycho change to that code; check the Game of Life of § 1 of Tycho
`requirements/todo/EPSIL_ANIMATION.md` without its `draw` (acceptance AN10
also needs CE-1652) and remove the marker.

## CE answer

CE (2026-11-21): filed at the table value P3, as CE-1652. Disposition: in the
backlog for the board; the closure write of CE-1620 is the place to extend.
Workaround: interpret the callback (Tycho's phase 1), or compile a pure
function of the list (CE-1607) and keep the assignment interpreted.
