A function stays marked pure after a helper that it calls is given a body that draws random numbers.

## Witness

```js
const ce = new ComputeEngine();
ce.declare('h', '(number) -> number');
ce.box(['Assign', 'h', ['Function', ['Multiply', 2, 'x'], 'x']]).evaluate();
ce.box(['Assign', 'k', ['Function', ['h', 'x'], 'x']]).evaluate();
ce.box(['Assign', 'h', ['Function', ['Add', 'x', ['Random']], 'x']]).evaluate();
console.log(ce.lookupDefinition('k').operator.pure);  // true
console.log(ce.box(['k', 3]).evaluate().toString());  // 3.94…, random
```

`k` states no effects, so its effects are inferred. The inference read the
literal that `h` held when `k` was defined, and it does not run again when
`h` gets a new literal. A stated contract that calls `k` (`g` declared
`(number) pure -> number` with the body `k(x)`) reads the stale `pure` of
`k`, so the check of CE-1629 does not refuse the new literal of `h` either.

## Cause and options

In `Walker.applyNamed` (`src/compute-engine/boxed-expression/effects-inference.ts`),
the walk of a literal that a value binding holds (`storedFunctionLiteral`)
does not mark the result as derived, so the operator definition of `k`
freezes the effects (`_deriveEffects` is not installed,
`boxed-operator-definition.ts`). Option: set `consultsRegistry` in that
branch, so that `k` re-derives its effects when `ce._callableVersion`
changes. Cost: one more walk of each such body after each write of a
callable.
