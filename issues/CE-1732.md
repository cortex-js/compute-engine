A domain coloring of the Hurwitz zeta function typed as `\zeta(z, a)`, or of the digamma function `Digamma(z)`, draws nothing, while the same functions written `HurwitzZeta(z, a)` and `PolyGamma(0, z)` draw.

## Witness

CE 0.200.1, `z` declared `complex`, `a` declared `real`,
`compile(expr, { to: "glsl", mode: "complex" })`:

- `\zeta(z, a)` (parses as `["Zeta", "z", "a"]`) declines: "Could not
  compile: Zeta(z, a): Zeta of complex, real".
- `Digamma(z)` declines: "Could not compile: Digamma(z): Digamma of complex".

Controls on the same engine: `HurwitzZeta(z, a)` compiles
(`_gpu_ir_churwitz_zeta(z, vec2(a, 0.0))`), `PolyGamma(0, z)` compiles
(`_gpu_ir_cpolygamma(0.0, z)`), and the real forms compile (`Digamma(x)`,
`\zeta(x, 2)`).

## Cause and options

CE-1600 gave complex GLSL kernels to `Zeta`, `HurwitzZeta`, `PolyGamma`,
`Gamma`, `PolyLog` and `LerchPhi`; the two-argument `Zeta` and `Digamma` of a
complex argument have no lowering. `Digamma(z)` is `PolyGamma(0, z)`, so it
can use the same kernel. The two-argument `Zeta` equals `HurwitzZeta` when
`a > 0` (CE-1598 resolution: at a negative base point the two differ), so it
can use the Hurwitz kernel when `a` is known to be positive, or a kernel of
its own.

The instrument prints `READY` when both cases compile.
