A formula that calls a function of the plot variable inside a sum whose index has the same name no longer compiles.

## Witness

`x: real`; `k := Function(Add(v, x), v)` (k reads the input `x`);

```
Sum(Add(x, k(1)), Limits(x, 1, 3))
```

compiled to javascript with `inputs: { x: 'real' }`, run at x = 10.

- Interpreter (0.193.0 and 0.194.0): 39, that is (1 + 2 + 3) + 3·(1 + 10):
  `k` reads the input `x` (lexical scope), not the index of the `Sum`.
- 0.193.0 compiled: 39.
- 0.194.0: "a call of k, which reads the input x, where x is a local or a
  parameter".

In Tycho this is a document function of the plot axis called inside a sum or
a macro whose bound name is also `x` (the four tests in `source-ref`; one is
the Desmos form `f(2,3)` with an implicit parameter `x`).

The IR README ("User functions") lists this decline. ce-compiler (2026-11-18):
the semantics are not in question, and compiled code can read the input there
(`_.x`), so it is a capability gap, not a rule to change.

## Expected

The call compiles on javascript (and interval-js) and reads the input `x`,
with the interpreter's value.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1479-local-shadowed-input-call-probe.mts`
in Tycho. The last line reads `CE-1479: READY` when the compile succeeds and
gives 39. It reads READY on 0.193.0 and NOT READY on 0.194.0.
