An animation that redraws a canvas with new content in each frame runs interpreted, so each frame is slower.

## Witness

Tycho's brick-rally notebook runs `let repaint = () => draw(court.update({content -> picture()}))` in its timer callback `tick`, every 24 ms (tycho-c8, 2026-11-27). On CE source after 0.204.2 with the figure-options batch of session compute-engine-2d, compiled JavaScript declines `canvas([circle((cos(t), sin(t)), 0.2)]).update({content -> [segment((0, 0), (t, 1))]})`:

```
DictionaryFrom("pairs"): the operator DictionaryFrom is not supported by the compiler
```

The interpreter gives the canvas figure. The probability is `medium` and not the `high` of a corpus witness: one of the six notebooks in Tycho's corpus uses the pattern.

## Cause and options

`Figure.update` of a canvas calls `figureMerge(a, b)`. That function builds the merged options as a list of key/value pairs in loops over `keys(base)` and `keys(b)`, then calls `dictionaryFrom(pairs)`. Both loops unroll per key, and their tests are decided at compile time. Two parts are missing:

- a list local that grows by `[...pairs, (k, v)]`, whose pairs have values of several lanes (a list of records of no names of different fields): `do { let p = []; p = [...p, ("a", true)]; length(p) + t }` declines ("arms of two types");
- `DictionaryFrom` itself: `dictionaryFrom([("a", t), ("b", true)])` declines ("the operator DictionaryFrom is not supported by the compiler").

Options:

1. Compile `DictionaryFrom` of a list of pairs whose keys are known at compile time into a dictionary record, and let an unrolled loop grow such a list. Size L.
2. Prelude side: Tycho writes `figureMerge` without a list of pairs. Only possible if the language has a dictionary-update primitive that compiles; none does today.
