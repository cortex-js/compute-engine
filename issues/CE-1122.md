The arithmetic methods (`add`, `mul`) treat a call of a user function named `Sqrt` as a square root, and give a wrong value.

## Witness

At commit `c011cf73e62b1f8b0761e1f09fb1538ef89ee0b7`, and with the
uncommitted CE-1109.4 change:

```ts
const L = ce.box(['Sqrt', 'y']);                    // the library Sqrt
ce.pushScope();
ce.declare('Sqrt', 'function');
ce.assign('Sqrt', ce.box(['Function', ['Add', 'x', 100], 'x']));
const U = ce.box(['Sqrt', 'y']);                    // the user Sqrt
ce.popScope();
L.add(U).json                    // ["Multiply", 2, ["Sqrt", "y"]]
L.add(U).subs({ y: 4 }).N()      // 4; must be 2 + 104 = 106
U.mul(ce.number(2)).subs({ y: 4 }).N()   // 4; must be 208
```

The canonical product reads such a call by name also inside the scope of
the user function (commit `af5e9937f440434c7eb965dcb5e0e1d5320bf0bb`):

```ts
ce.pushScope();
ce.declare('Sqrt', 'function');
ce.assign('Sqrt', ce.box(['Function', 1000, 'u']));
ce.box(['Multiply', 2, ['Sqrt', 4]]).json   // 4; must be 2000
ce.popScope();
```

`crafted`: the program defines a user function with the capitalized name of
a library function and combines its call with a library call made in
another scope.

## Cause and options

`BoxedFunction.toNumericValue()` (`boxed-function.ts`) selects `Sqrt`,
`Root`, `Power` and `Abs` by name and builds its result again with
`ce.function(name, …)` in the current scope. So a call of a user `Sqrt` is
read as a square root, and a library `Sqrt` is bound again to the user
function in a scope that shadows it. Test the node with
`isLibraryOperator()` (`library-shadowing.ts`) before the name test, and keep
the call as an opaque factor otherwise. Related: CE-1113 (canonical
`Multiply` and `Join`), CE-1118 (evaluation binds an operand again by name).
