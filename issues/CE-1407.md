A quantifier over an interval tries only the integers of the interval, so `exists(x in interval(1, 2), x == 1.5)` is False.

## Witness

Epsil CLI, main 0417d3034: `exists(x in interval(1, 2), x == 1.5)` gives False;
`exists(x in interval(1, 2), x == 1)` gives True. `Interval(1, 2)` is the real
interval, which contains 1.5.

## Cause and options

`extractFiniteDomainWithReason` (`library/logic-analysis.ts`, around line 70
and 207) enumerates `Element(x, Interval(a, b))` as the integers from `a` to
`b` ("integers only"). The old Logic reference page documented this as
"integer intervals", so the fix changes a documented behavior.

- (a) Recommended: over an `Interval`, the quantifier is enumerated only when
  `x` is declared an integer; otherwise it stays unevaluated (or is decided
  by another route, for example a bound of the interval). `Range` keeps
  enumerating. Example: `exists(x in interval(1, 2), x == 1.5)` stays
  unevaluated; `forAll(n in 1..5, n > 0)` is True as today.
- (b) Keep it, and document that `Interval` in a quantifier means its
  integers. This keeps a wrong answer for a real variable.

## Decision

User decision 2026-11-16 (relayed by the cortexjs.io session cortexjs-io-f8):
`Range` is the set of integers between two bounds; `Interval` is a set of real
numbers between two bounds, open or closed. A quantifier over an `Interval` is
not enumerated as integers. Option (a) applies: integer enumeration stays with
`Range`; over an `Interval` the quantifier stays unevaluated, or is decided
from the bounds where they decide it, as for a range above the enumeration
limit. The Epsil reference (cortexjs.io `c87d5d81de78cb8ea65d155864be1b54c1296212`,
`reference-details/logic.md`, "Quantifier evaluation") already states the rule
and says that the engine still tries the integers; the fix removes that
sentence and its example there and runs `npm run verify:details`.
