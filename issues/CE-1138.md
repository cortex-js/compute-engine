A square root of a number made at a higher precision has two digits fewer after the engine is set to machine precision.

## Witness

```ts
const ce = new ComputeEngine();
ce.precision = 30;
const a = ce.parse('0.3');
ce.precision = 'machine';
ce.box(['Sqrt', a]).evaluate();     // 0.547722557505166
ce.box(['Sqrt', 0.3]).evaluate();   // 0.5477225575051661
```

The same loss shows in the Frobenius norm of a matrix that holds such a
number. With `a` as above and `b` = `0.7` made the same way:
`Norm([[a, 1], [2, b]])` is `2.36220236220354`, and `Norm([a, 1, 2, b])`
is `2.3622023622035435`. The matrix norm adds the squares with `.mul()` and
`.add()`, which keep the big decimal, and takes the square root of the
decimal `5.58`. The vector norm squares with `Power`, which gives a machine
number. Since the fix of CE-1097, the packed tensor holds such a number
boxed at machine precision, so the matrix norm reaches this route; before
that fix, the cell was a double.

## Cause and options

Not traced. The probable cause: the square root of a `BigNumericValue`
computes on big decimals at the precision of the engine, and at machine
precision that is `MACHINE_PRECISION`, 15 digits, while a double gives
about 17. Option: at machine precision, compute the square root (and the
other functions of one decimal argument) of a big decimal that a double
holds on its double, as the arithmetic of a machine number does.
