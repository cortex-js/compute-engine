An Epsil function called before a variable it reads is declared gives a string on the runner and an error in a block.

## Witness

```epsil
let a = String(g())
let c = 2
function g() { c^2 }
```

The Epsil runner gives `a = "c^2"`; the block route gives
`read-before-declaration` (measured 2026-10-21).

## Cause and options

The top level of the runner has no "declared, not yet initialized" state for a
variable, so the read of `c` stays symbolic. Fix: give the runner that state,
so that both routes give `read-before-declaration`. Plan:
`docs/plans/2026-10-21-function-declaration-hoisting.md`.

## CE answer

CE (2026-11-12): seen again with the declared-locals rule of
`docs/plans/2026-11-11-bound-once-spec.md` (D8), not on main yet. A read
before a `let` is `read-before-declaration` when the read is in the
statement itself. A read through a call is not caught: `let g = (x) => [-x,
y]`, `let a = g(3)`, `let y = "abc"`, `a` gives `[-3, "abc"]` with no
diagnostic, in a program, in a `do` block and in a host `Block`. And `let a
= String(g(1))`, `let t = 0`, `function g(k) scope { t = k + 1; t }`, `[a,
t]` gives `["2", 2]` with a run-time "already declared" error on the
runner and `["2", 0]` as a block.
