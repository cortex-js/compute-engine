`Zeta(s, a)` and `HurwitzZeta(s, a)` do not end for a very large order `s`, in the interpreter and in compiled code.

## Witness

At `5fc85eda6`:

| Program | Result |
| --- | --- |
| `ce.box(['Zeta', 1e300, 2]).N()` | no result after 20 s |
| `ce.box(['HurwitzZeta', 1e300, 2]).N()` | no result after 20 s |
| `compile(Zeta(x, y))` with `x`, `y` real, run at `x = 1e300, y = 2` (`_SYS.zetaGeneralized`) | no result after 25 s |
| `compile(HurwitzZeta(x, y))`, the same point (`_SYS.hurwitzZeta`) | no result after 25 s |

The value is `2^(-1e300) + 3^(-1e300) + …`, which is `0` in double
precision.

## Cause and options

The kernels sum terms until a tolerance that the order makes unreachable,
or iterate a count that grows with `s`. Option: for an `s` past a bound
(about 1100, where `a^(-s)` underflows for `a ≥ 2`), return the first term
`a^(-s)` (plus the next one when `a < 2`), in the interpreter's kernel and
in the runtime helpers.
