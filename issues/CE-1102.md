Each edit of a Graph Paper document with functions is slower than the one before: after ten edits one edit takes 1.3 s, against 0.15 s after a reload.

## Witness

CE 0.182.0 (installed bundle). Each pass pushes a scope, assigns 100
functions `f_i = x ↦ h_i(x) + 1` with `h_i` not declared, and pops the scope.
After a full garbage collection the heap grows about 1.5 MB a pass (29 to
45 MB in 12 passes). Control, each `h_i` declared first: 31 to 32 MB. A heap
snapshot after 10 passes finds about 150,000 objects that only the entry of
the engine in `DEPENDENTS` reaches.

In Tycho, the document's manager pops and pushes its scope at each full
registration. Each full registration of the corpus state `neyret/mou9vf6mjz`
on one manager is slower than the one before (228, 272, 407 … 1,318 ms over
ten edits; about 150 ms on a new manager), with the time in `assign` and
`_deriveSignature`. The heap snapshot of that run shows the same entry:
67,000 objects after 10 registrations, 8,000 after 2.

## Cause and options

`registerProvisionalDependents` (`provisional-application.ts`) keeps a
STRONG reference to each definition whose literal read a name provisionally.
`unregisterProvisionalDependent` runs only for a superseded half
(`updateDef`). When a scope is popped, its definitions stay in `DEPENDENTS`
and `REGISTRATIONS`, with their literals. `repairWave` with a `declaredIn`
scope never takes them (their home scope is not under it), but each later
declaration of the name walks them all.

Option: when a scope is discarded (`popScope`, the context release that
already empties `_countedDefs`), unregister each value and operator
definition of its bindings. Size S. Tycho has no workaround short of a new
engine for each registration.

## The option above does not work: decision needed

Tycho's notebook pushes a scope with `ce.pushScope()`, keeps
`ce.context.lexicalScope`, and pushes the same scope again later
(`ce-notebook-evaluator.ts`, `pushFrame()`). A pop is therefore not the end
of the scope's definitions. Example: group scope S defines
`f(x) := h(x) + 1`; the graph leaves S; `h` gets a definition; the graph
enters S again. Today `f(2)` is `h(2) + 1`. If the pop unregisters `f`, `f`
keeps the product reading `2h + 1`.

Options (details, examples and costs in
`docs/plans/2026-11-07-ce1102-registry-scope-lifetime.md`):

- (a) The registry holds weak references and prunes collected ones. Size S.
  Cost: `withValues({ k: 2 })` after a popped body applied `k` throws or not
  by the time of the last garbage collection (today it always throws).
- (b) The pop parks the definitions of the scope; a new push of the scope
  registers them again and re-derives those whose name gained a definition
  meanwhile. Size M. Cost: a second copy of the `updateDef` rule.
- (c) No CE change; the leak stays.

Recommendation: (a). An unanswered question means no change, which is (c).

A first version of the option above, which unregisters at the pop, is in
`/tmp/cebatch-1102/pop-unregister.patch`, with the test file
`ce-1102-provisional-registry-scope-pop.test.ts` there. Its leak tests can
serve (a).

## Decision

User decision 2026-11-08: (a)

CE (2026-11-08, session cebatch-1102): Fixed with option (a). The registry
(`provisional-application.ts`) holds one `WeakRef` per definition; a
collected definition is removed at the next read of its name, or by a sweep
at a registration when the set of a name reaches twice its live size (at
least 16). A definition in a popped scope that the host keeps and pushes
again is still re-derived (test
`test/compute-engine/ce-1102-provisional-registry-weak-references.test.ts`).
Two notes for the verification. (1) A `WeakRef` keeps its target alive until
the end of the job that made it (ECMAScript `AddToKeptObjects`), so the
instrument as written, twelve passes in one synchronous job, still reports
OPEN with the fix (measured: 89 to 110 MB). With
`await new Promise((r) => setTimeout(r, 0))` between the pop and `gc()` of
each pass, which is what the app does (each edit is its own task), it reports
READY: 92 MB flat over twelve passes, control 92 to 93 MB. Change the
instrument to yield between passes. (2) The last popped scope stays in memory
until a type read under another scope, a bounded retention of one scope
(CE-1152); the heap growth from pass 2 to pass 12 does not see it.

Tycho (2026-11-08): The instrument now waits for a new task
(`setTimeout(0)`) between the pop and `gc()` of each pass, and an environment
variable `CE_MODULE` selects the engine module. Readings with the yield:

engine's source at the fix commit 89 to 90 MB, control 91 MB, READY. The
fix is verified; Tycho re-checks at the adoption of the release that

So the weak references remove the cost only after a full collection. In the
app, nothing makes one run between two edits: the ten registrations above
took 6.6 seconds in total, and no collection in that time cleared the
registry. Option: at
`popScope()`, remove from the registry the definitions of the popped scope
(the scope is known at the pop), and keep the weak references for the
scopes that a host keeps and pushes again.
