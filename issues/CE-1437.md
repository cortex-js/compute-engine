A compiled integral of `x^100 e^(-x)` gives `NaN`, where the value is about `9.33e157`.

## Witness

`y` is declared `real`.

```
compile(\int_0^\infty x^{100} e^{-x} dx, { profile: 'ir' }).run({})      NaN
compile(\int_0^y x^{100} e^{-x} dx, { profile: 'ir' }).run({ y: 1500 })  NaN
```

The existing compiler gives `9.332621544394413e+157` for both, and the
interpreter's `evaluate().N()` gives `100!` (`9.33262154439441e+157`).
Run on `ef9ac4deb09e8a0dc1a1c0a80e9b03317d199b9e` (2026-11-17). The tests
that pin the existing compiler's value are
`test/compute-engine/integrate-log-space-product.test.ts` and the log-space
case of `test/compute-engine/ce-732-reserved-binding-names.test.ts` ("an
integration variable named `Math`, with the log-space form").

From release 0.194.0 the profile `ir` compiles every target, so the default
route of that release has the defect.

## Cause and options

Each factor overflows a double past `x ≈ 1200` (`x^100` is `Infinity`,
`e^(-x)` is `0`), and the sample is `Infinity·0 = NaN`, though the product
is finite. The quadrature of the profile `ir` (`compilation/ir/lower.ts`,
the `Integrate` case; `print-js.ts`) samples the integrand as written.

The existing compiler computes a non-finite sample again in log space:
`compileIntegrate` in `compilation/javascript-target.ts` builds the
log-space form with `logSpaceProduct()` (`symbolic/log-space-product.ts`)
and wraps the sample in `_SYS.finiteOr` (`compilation/javascript-runtime.ts`),
under the conditions listed there (a pure integrand, no node mapped by the
caller). The interpreter does the same (`withLogSpaceFallback`,
`library/calculus.ts`).

Options:

- (a) Lower the log-space form in the profile: the integrand carries its
  `logSpaceProduct()` form, and the sample is `finiteOr(f(x), g(x))`, under
  the same conditions. Size M.
- (b) Decline an integrand that `logSpaceProduct()` rewrites, so the
  fallback gives the interpreter's value. Size S, at the cost of a decline
  for every such product, also where no sample overflows.

The same class as the known limitation of `Coth(1000)` in
`docs/COMPILATION-MODEL.md`, "Known limitations" (an intermediate double
overflows and the code gives `NaN` where the value is finite). Related:
CE-1193 (the interpreter's `NIntegrate` skips the log-space evaluation for a
typed parameter).
