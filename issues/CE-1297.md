`Beta(-1/2, -1/2)` has the numeric value NaN; it is 0.

## Witness

On main:

```
ce.box(['Beta', ['Rational', -1, 2], ['Rational', -1, 2]]).N()   // NaN
```

B(−1/2, −1/2) = Γ(−1/2)² / Γ(−1), and Γ(−1) is a pole, so the value is 0.

GitHub #590 adds, on main at `fed2ad56317cc2a41f1124414bdc7c97d857d83a`:

```
ce.box(['Beta', -2.5, 0.5]).evaluate()                                  // NaN; 0
ce.box(['Beta', ['Rational', -5, 2], ['Rational', 1, 2]]).evaluate()    // Beta(-5/2, 1/2); 0
ce.box(['Beta', ['Rational', -5, 2], ['Rational', 1, 2]]).N()           // NaN; 0
compile(ce.box(['Beta', 'x', 'y'])).run({ x: -2.5, y: 0.5 })            // NaN; 0
```

The compiled integer pair of #590 (`x = 2, y = -3` gives `NaN` for 1/6) is
CE-1227. Both are the same kernels (`beta` in `numerics/special-functions.ts`,
`bigBeta`, `_SYS.beta`): fix them in one change. Only an exactly integer sum is
a pole: `Beta(-2.3, 0.3)` is about -1.9e-15, not 0.

## Cause and options

Not examined; the numeric kernel probably divides by Γ(a + b) at its pole. Return 0 when `a + b` is a non-positive integer and neither `a` nor `b` is. Size S.
