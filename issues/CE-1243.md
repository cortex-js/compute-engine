The JavaScript compiler compiles a root operator symbol other than `Add`, `Subtract`, `Multiply` and `Divide` to the infix lambda of its glyph: `Negate` gives `(a, b) => a - b`, and `Not` throws a `SyntaxError` from the compilation.

## Witness

At `154153fe307c9084587b86fb0f9dc364c040cc8c`:

```ts
const ce = new ComputeEngine();
const neg = compile(ce.box('Negate'), { fallback: false });
neg.code;       // "(a, b) => a - b"
neg.run(3);     // NaN      interpreter: Apply(Negate, 3) is -3
neg.run(3, 2);  // 1        interpreter: an unexpected-argument error
compile(ce.box('Not'), { fallback: false });
// throws SyntaxError "Unexpected token '!'" (no decline, no fallback)
compile(ce.box('And'), { fallback: false }).run(3, 2); // 2
```

## Cause and options

`compileToTarget()` in `src/compute-engine/compilation/javascript-target.ts`
(the `isSymbol(expr)` branch after the `bigint` check) writes
`(a, b) => a ${op[0]} b` for every symbol that `target.operators()` maps,
without the test of `BINARY_INFIX_VALUE_OPERATORS` that the nested route
(`compile-inner.ts`, the bare operator symbol) makes. A nested `Negate` is
eta-expanded (`_fn_Negate = (_tv1) => -_tv1`) and a nested `Not` declines.
Option: apply the same test at the root: the four binary arithmetic
operators keep the lambda, a unary operator takes the eta-expanded wrapper
as at a nested position, and the others decline with
`builtinCallbackRefusal()`. `Reduce` is not affected: its arity check
refuses `Negate` and `Not` before it compiles the combiner.
