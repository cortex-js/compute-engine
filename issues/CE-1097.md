A number made at a higher precision, in a list, gives another last digit after the engine is set to machine precision.

## Witness

```ts
const ce = new ComputeEngine();
ce.precision = 30;
const b = ce.parse('0.3');
ce.precision = 'machine';
ce.box(['Multiply', 3, b]).evaluate();                  // 0.9
ce.box(['Multiply', 3, ['List', b, 1.5]]).evaluate();   // [0.8999999999999999, 4.5]
ce.box(['Multiply', 3, ['List', ['List', b, 1], ['List', 2, 3]]]).evaluate();
// [[0.8999999999999999, 3], [6, 9]]
```

The scalar product multiplies the decimal of `b`, which keeps its decimal
form after the precision changes. The product with the list multiplies its
double.

## Cause and options

`b` has the value of its double, so the `array` facet of the list admits it
(`machineNumberOf()`, `boxed-expression/machine-number.ts`), and
`scaleMachineVector()` (`boxed-expression/arithmetic-mul-div.ts`) multiplies
the doubles: its `floatsAreDoubles` test reads the scalar only. A matrix takes
the packed tensor of `scaleTensor()`, whose cells are doubles. An element with
more digits than a double holds loses them too; that is CE-1048, whose first
fix was undone before 0.183.0. Fix this issue with CE-1048 and CE-1095.

Option: at machine precision, multiply the boxed elements also when an element
is a float stored as a decimal (`!isStoredAsDouble()`), before
`scaleMachineVector()`. The cost is a walk of the elements of each product
of a number and an ordinary list at machine precision.
