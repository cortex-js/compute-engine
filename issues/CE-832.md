A call of a name that is declared as a number after the expression was made evaluates to itself instead of giving an error.

## Witness

```
box g(x) + 1, then ce.declare('g', 'real')
evaluate()                  ->  g(x) + 1   (with ce.assign('g', 5) too: incompatible-type)
Sum(g(k), Limits(k, 1, 3))  ->  g(1) + g(2) + g(3)
NLimit(x ↦ g(x), 0)         ->  NaN
expected: the error expected-function, which the same expressions give when boxed after the declaration
```

## Cause and options

`BoxedFunction._canonicalToEvaluate()` (`boxed-function.ts`) evaluates a call
boxed again only when the call recorded its callee (`_reboxedForCallee()`). A
call boxed before its name had a definition is boxed again only to read its
type (`_reboxedForForwardCallee()`), which refuses a new call that is an
`Error`. Fix: when the call boxed again is the `expected-function` error,
evaluation gives that error. Then the separate check of `Integrate`, `D`,
`Limit` and `NIntegrate` (`dataSymbolCallError()`, `library/calculus.ts`) can
go if the error reaches them through their operand; today that check misses a
call below `If` (`D(If(x > 2, g(x), x^2), x)`).
