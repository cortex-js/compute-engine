A breakpoint on a line of a function that another function returned never stops the debugger when the line uses a parameter of the function that made it.

## Witness

```epsil
function mk(k) { t => do { let z = t + k; z } }
let h = mk(2)
h(5)
```

With `executeEpsilAsync(ce, source, { debug })`, `beforeStatement` is called
for `z` and not for `let z = t + k`. The value is right (`7`). With
`let z = t + 1` in place of `let z = t + k`, the hook is called for both
statements. With `let z = t + k; let w = z * k; w + k`, it is called for
none. The instrument prints these cases.

`EpsilDebugHooks` (`src/compute-engine/types-debug.ts`) says that the hooks
are called for each statement of a function body evaluated on the
asynchronous route. A function that returns a function of its argument
(a factory, a curried function) is a plausible program.

## Cause and options

After `let h = mk(2)`, the value of `h` is `(t) => { Declare(z, {"value" ->
t + 2}); z }`: the statement in which the call substituted `2` for `k` has
no `sourceOffsets`, and `z` keeps `[42,43]`. The hook sites call no hook
for a statement without offsets. The substitution at the end of a call
(`bindingKeyedSubs()`, `src/compute-engine/function-utils.ts`) rebuilds each
node it changes in `rewriteWithBinders()`
(`src/compute-engine/boxed-expression/binders.ts`, lines 1074 to 1092) with
`ce.function(…)` and no `metadata`.

- Pass `{ metadata: { sourceOffsets: expr.sourceOffsets } }` at those
  rebuilds. Pass the same array, not a copy: CE-1624 finds the source of a
  statement by that array. Check the other readers of offsets on the
  result of a call (the error ranges of `executeEpsil()`). Recommended.

The synchronous hook (`setDebugStatementHook`, the VS Code debugger) tests
the same field; that case was read, not run.
