A plot whose formula has a square root of a negative number in a branch that is never taken is computed point by point instead of by compiled code, so it draws slower.

## Witness

`x: real`. Compile to javascript:

```
Which(LessEqual(1.2, 1),
      Which(Less(x, Negate(Sqrt(Add(1, Negate(Power(1.2, 2)))))), 1, True, 0),
      True, 1)
```

0.194.3: declines, "Less(x, Negate(Sqrt(…))): Less of real, complex". 0.186.0: compiles, value 1.
Control: the same program with 0.5 in place of 1.2 in the inner arm compiles.
The first condition is the constant False, so the arm with the complex
comparison is never evaluated. In the document the 1.2 is a slider value
(`y_r`) that Tycho substitutes, and 20 rows of one shape decline.

Found by the Tycho codegen audit of 2026-11-19: the same MathJSON, with the same options, compiled to JavaScript on CE 0.186.0 and declines on 0.194.3 and on the CE main build of 2026-11-19 16:57, in the document context and on a bare engine. Tycho's instrument `scripts/repros/2026-11-19-ce1560-js-decline-regressions.mts` prints one READY / NOT READY line per issue (READY on 0.186.0, NOT READY on 0.194.3).

## Cause and options

The type check of `Less` runs on an arm that a constant condition removes.
Options: (a) fold a `Which`/`If` whose condition is a literal boolean before the
type check (recommended; it also makes the code smaller); (b) compile a
comparison with a complex constant operand as `false` in the strict mode, as
the interpreter's `NaN` comparison does.
