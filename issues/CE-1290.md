A generic function applied to a value of unknown depth is given a type that does not hold the uneven nested list it evaluates to.

## Witness

Main at `6dbc33b11a3cef2b0a09dd1f8d0d75b94f9fd1d9`, as the D16 agent reported it (not run again by the session):

```
ce.declare('g', '(x: T) -> tuple<T, T> where T');
ce.assign('g', ce.box(['Function', ['Tuple', 'x', 'x'], 'x']));
ce.declare('b', 'any');             // or: type alias lcyc = lcyc | list<integer>; b: broadcastable<lcyc>
const e = ce.box(['g', 'b']);       // broadcastable<tuple<any, any>>
e.subs({ b: [[1, 2], [3]] }).evaluate()   // [[(1, 1),(2, 2)],[(3, 3)]], which the type does not hold
```

Also `h: (v: any) -> unknown := v ↦ g(v)` is typed
`(v: any) -> tuple<unknown, unknown>`. Before D16 the held value of a
declared symbol hid the case: the type was computed from the value.

## Cause and options

`genericLiftLevels` (`boxed-expression/boxed-function.ts`): a
`broadcastable<T>` operand, and an operand of a top type, take the
shape-aware typing, which gives `broadcastable<R>`. That type holds only
rectangular values (`T | tensor<T>`). When the leaves of the operand may be
lists (`T` can hold a list, or `T` is `any`), the rows can be uneven, and
the result should be the nested form (`list<list<any> | R>`), as it is for
an operand typed `list<any>`.
