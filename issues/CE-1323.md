The random test of the new JavaScript compiler fails when its sequence of
programs changes: two programs that it does not generate today are left
unclassified.

## Witness

`test/compute-engine/ir-slice-random.test.ts` compares generated programs with
the interpreter and classes each disagreement; an `unclassified` one fails the
test. With one more random draw in the generator of
`test/compute-engine/ir-slice-oracle.ts` (which shifts every later program),
the 5,000-program run (`CE_NIGHTLY=1`) leaves these two unclassified. Both
give the same values at `3ab43b3e2c3b8c075a0865f364a155dbefa2a66c`, read with
`runSlice` (passes on) and `interpret` of the oracle.

1. The interpreter has no value (`'none'`):

   ```
   ["Filter",["Add","J",["Map",["Function",["At",["Add","D",["Map",["Function","n","z404"],"D"]],["ev",["Mod",1,9]]],"z403"],"J"]],["Function",["Less",["If",["Or","p","p"],["Which","p",0.5,"p","n","True","z405"],["Abs",-1.25]],["Min","ExponentialE",["Min","Pi","Pi"]],["Subtract",["Round","n"],["Max",-1.25,0.5]]],"z405"]]
   ```

   At `{"D":[1.5,-2,3,0.25],"J":[4,-5,6],"n":3,"p":true}` the compiled value
   is `[]`; at `{"D":[-0.5],"J":[7],"n":5,"p":true}` it is `[NaN]`. The value
   starts from an `At` at the index 0 (`ev(Mod(1, 9))`), which is NaN in
   compiled code: within the caveats, so the gap is probably in `classify()`,
   which does not flag a NaN made by `At`.

2. A difference of about 1.7e-12 relative:

   ```
   ["Mod",["Cos",["Power",["If","p","Pi","ExponentialE"],["h2",2]]],["f",2,["At",["Floor","D"],["Subtract","n",0]]]]
   ```

   At `{"D":[1.5,-2,3,0.25],"n":3,"p":true}` the compiled value is
   `6.902714258254405` and the interpreter's is `6.9027142582428285`. The
   cosine of `π^4` and a `Mod` amplify the rounding of the double; the
   `conditioning` class does not catch it.

## Cause and options

Not investigated. (a) Extend `classify()`: a NaN made by `At` is a caveat
value, and the conditioning test covers the second program. (b) If the second
difference is not the conditioning of the double arithmetic, it is a value
difference above the 1e-12 bound of the contract and needs its own look.
