Compiling `Map(Abs, zs)` over a list of complex numbers declares the symbol `_x` in the engine, so a later expression that uses `_x` gets a different type.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('zs', 'list<complex>');
ce.lookupDefinition('_x');                 // undefined
compile(ce.box(['Map', 'Abs', 'zs']), { to: 'javascript' });
ce.lookupDefinition('_x');                 // defined, type complex | infinity
ce.box(['Add', '_x', 1]).type;             // complex | infinity
```

Checked at commit `8c4ca0e8f1c8a7a5f6a837e64e9a0da18fce6dc4`. A program that
names a variable `_x` is unusual, so the probability is low.

## Cause and options

`complexElementCallbackEta()` in `compilation/compile-user-functions.ts`
builds the expansion `(_x: complex) ↦ Abs(_x)` from
`engine.symbol('_x')`. A symbol boxed alone is declared in the current scope
of the engine (usually the global scope), and the call `Abs(_x)` narrows its
type. Fix: box the expansion from MathJSON in one call
(`engine.box(['Function', [op, '_x'], ['Typed', '_x', …]])`), so that `_x` is
bound in the scope of the literal only, as `stringElementCallbackEta()` in the
same file does.
