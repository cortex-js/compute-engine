A derivative, an integral or a limit of a formula that contains a variable that holds a formula, with no variable written, works with respect to that variable instead of the variable of its formula.

## Witness

At 1ceacbf03641f2e11fa728bc2f6990accd8d9919, with `G := sin(x)` and `x` with no value:

```
ND(2G, 1)                              2                 (must be 2cos(1) ≈ 1.0806)
\int G + x                             G²/2 + G·x        (must be −cos(x) + x²/2)
\int_0^1 G + x                         unevaluated, ∫ (G + x) dG
Limit(G + 1, 0)                        the limit as G → 0, 1 (here equal to 1 by chance)
```

After the fix of CE-1772, a lone symbol that holds such a formula gives the
same wrong variable: with `H := G + x`, `\int_0^1 H` is `∫₀¹ (G + x) dG`.

## Cause and options

The candidates of the implicit variable (`implicitVariableCandidates()`,
`boxed-expression/implicit-variable-rule.ts`) include the user symbols that
the body reads and that have a value, so that `x := 4` does not change the
variable of `√x`. `G` holds the formula `sin(x)` and is such a symbol; it
sorts before `x`, so it is chosen. The symbols of its value are not
candidates, because they are not written in the body.

- (a) Recommended. A symbol that holds a formula (`loneSymbolFormula()`) is
  not a candidate; the candidates of its value are, recursively. `G + x`
  has the candidates `x`; `2G` has the candidate `x`. The free-variable walk
  (`implicitIntegralVariables()`, `binding-sites.ts`) reads the same rule.
- (b) Keep the rule and document that the variable must be written when the
  formula reads a symbol that holds a formula.
