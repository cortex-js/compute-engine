`NLimit` gives `NaN` when the engine does not compile (`ce.jit = 'off'`), for a limit that it computes when it compiles.

## Witness

```
ce.jit = 'auto'   NLimit(Function(Sin(x)/x, x), 0)          1.0000000000000002
                  NLimit(Function((Exp(x) - 1)/x, x), 0)    0.9999999999975803
ce.jit = 'off'    both                                       NaN
```

Run on `53d3b6a57de4f322b60dee2115e688834ac97800` (2026-11-10). The result
is the same with a typed parameter.

## Cause and options

Not investigated. `numericLimitValue()` in
`src/compute-engine/library/calculus.ts` uses the compiled function when
`implicitCompile()` gives one and `applicableN1(f)` otherwise; the
interpreted path gives no value for these two limits.

The JIT is off when the host sets `ce.jit = 'off'`, and after an `EvalError`
(a Content Security Policy that refuses `new Function`), so the probability
is low.

Found by a test of the `numeric-kernel` profile switch
(`test/compute-engine/implicit-compile-profile-switch.test.ts`, the `nlimit`
case, which for this reason does not compare with `ce.jit = 'off'`).
