The definite integral of x^100 times e^(-x) gives a wrong number, negative where the true value is positive.

## Witness

At commit `4c91094ef0e06de7e3abc763f4d5afe35d550539`, `test/compute-engine/ce-732-reserved-binding-names.test.ts`, "an integration variable named `Math`, with the log-space form", fails: compiled code gives `NaN` where the interpreter gives `9.33e157`. The name `Math` is not the cause:

```ts
const f = ce.box(['Function', ['Integrate', ['Multiply', ['Power', 'x', 100], ['Exp', ['Negate', 'x']]], ['Limits', 'x', 0, 'y']], ['Typed', 'y', "'real'"]]);
compile(f, { to: 'javascript' }).run(20)   // -1.2194330274671845e+142 (wrong sign)
compile(f, { to: 'javascript' }).run(1500) // NaN (the test expects 9.33e157)
```

The true value at `y = 20` is positive (the integrand is positive), about `1e121` or more. The interpreter, `ce.box(['Integrate', …, ['Limits', 'x', 0, 20]]).evaluate().N()`, gives `0`. Degree 10 is correct (`3628800` at `y = 1500`).

## Cause and options

Commit `db070db7b5f4e23d003585fbfd17593efe67e4be` (CE-1282) gives the closed form `-Σ 100!/k! x^k e^(-x)` for a polynomial of degree up to 200 times `e^(ax+b)`. Evaluated in floating point, its terms cancel catastrophically for a high degree, and they overflow (`Infinity - Infinity`) for a large bound; before, the log-space numeric route gave the value. Options: (a) keep the closed form for the symbolic result, but evaluate a definite integral numerically (or through the incomplete gamma function) when the degree is above a small limit; (b) lower the degree limit of the closed form; (c) emit the closed form in a factored, stable order (Horner form with the factor `e^(-x)` applied last still cancels at the lower bound). (a) is recommended.
