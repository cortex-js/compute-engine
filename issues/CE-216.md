The compiled square of a matrix held in a plain list squares each entry instead of giving the matrix product.

## Witness

With `p: list` holding `[[1, 2], [3, -4]]`, compiled `p^2` gives
`[[1, 4], [9, 16]]`; the interpreter gives the matrix power
`[[7, -6], [-9, 22]]`.

## Cause and options

Compiled code stores the points `[(1, 2), (3, 4)]` and that matrix as the
same array, and the interpreter powers points entry by entry, so compiled code
keeps the entry-wise code, which plots need. Types that cannot hold a point
(`tensor<number>`) dispatch on the shape. Fix: a compiled representation of points that differs
from a row. The same representation fixes:

- CE-216.1: `p·q` for operands typed bare `list` gives the entry-wise product,
  where the interpreter gives the matrix product.
- CE-216.2: `h := (t: number) ↦ [t, 2t]`; `h(x)[1]^2` squares each cell.
- CE-216.3: `Dot(g(x)[1], [1, 1])` declines.
