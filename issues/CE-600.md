With two engines in one program, each engine computes at the precision of the engine created last, not at its own.

## Witness

```ts
const a = new ComputeEngine(); a.precision = 60;
const b = new ComputeEngine(); b.precision = 21;
a.parse('\\sqrt{2}').N()   // 1.4142135623730950488 (20 digits, not 60)
```

Measured 2026-11-06. In the other order, a 3000-digit engine created after a
21-digit one makes `LogBarnesG(0.7).N()` on the 21-digit engine take 33 s
instead of 4 ms.

## Cause and options

`BigDecimal.precision` is global to the module, and creating an engine or
setting its precision writes it. `ARCHITECTURE.md` records this as an API
trap; `item-395-log-gamma-barnes-g.test.ts` restores the global after each
test, which hides the defect there only. Options:

- (a) Each engine sets the global precision when a numeric evaluation starts.
  Cheap; a nested call of another engine or an asynchronous evaluation can
  still interleave.
- (b) Pass the precision to the big-decimal operations instead of reading a
  global. Correct; a large change.
