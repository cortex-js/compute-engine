The type shown for a function that appends its argument to a range says it returns a list of integers, and it returns a list that holds the argument, which can be any number.

## Witness

At `87f8cf3e7`:

```ts
ce.assign('ap', ce.box(['Function', ['Append', ['Range', 1, 'u'], 't'], 'u', 't']));
ce.box('ap').type.toString();            // (u: unknown, t: unknown) -> list<integer>
ce.box(['ap', 2, 0.5]).type.toString();  // list<real>
ce.box(['ap', 2, 0.5]).evaluate();       // [1, 2, 0.5]
```

The inferred signature of `ap` gives the result `list<integer>`: the element
type of `Range(1, u)` alone. The parameter `t` has the type `unknown`, and the
appended element is not counted. The type of the call, with its arguments, is
right (`list<real>`), and so is the value.

## What it must give

A result type that admits what the body can return for arguments of the
parameters' types: with `t: unknown`, `list<unknown>` or `list<number>`, not
`list<integer>`.

## Impact

No value is wrong. A reader of the function's type (a host that shows it, a
compiler that takes the declared or inferred result of a user function) is
told that the list holds integers. The compilers were probed: the `ir`
profile declines `Append`, and the existing compilers read the type of the
call, so no compiled value follows from it today.

## Cause and options

Not investigated. The type handler of `Append` (or the inference of a
function literal's result) drops the type of an operand whose type is
`unknown` where it should widen the element type. Check the other operators
that build a list from a list and an element (`Prepend`, `Insert`, `Join` of
a list of `unknown`).
