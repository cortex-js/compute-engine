The type handler of `Power` changes engine state when its base is `Floor` of a `Sum`: with the purity guard on (as under Jest) the engine reports "The type handler of "Power" modified engine state while deriving a type (moved: any). A type handler must not declare, canonicalize, or evaluate anything."

## Witness

At `154153fe307c9084587b86fb0f9dc364c040cc8c`, on a fresh engine, under Jest:

```ts
const ce = new ComputeEngine();
ce.box(['Power', ['Floor', ['Sum', 'k', ['Limits', 'k', 2, 3]]], 4]);
// reports: The type handler of "Power" modified engine state while deriving
// a type (moved: any).
```

The message was reproduced on 2026-11-12 with a one-test file in `test/compute-engine/`. The guard reports through the console in that run; the slice's tester saw it as a throw from `ce.box()`.

## Impact

A type handler that declares, canonicalizes or evaluates gives a type that depends on the order of earlier reads. No wrong value is known. The witness is crafted: a generated program.

## Notes

A second report of the same kind, not reduced: evaluating `At(Divide(Add(If(Not p, M, L), Pi), Floor(Sum(E, k=2..m))), -1)` logs the same error for the type handler of `Divide` during `subs`. Both have a `Floor` of a `Sum` as an operand, so the cause may be in the type of that operand (the index `k` declared during the read) and not in `Power` or `Divide`.
