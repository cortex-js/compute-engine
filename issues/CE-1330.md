A function with a local variable that returns a condition it cannot decide yet gives a result that names the local variable, which has no value once the call has ended.

## Witness

Run on main at `7a4096fec40397675c079f519d10dcecfe0f8a2d` (Epsil):

```
function f(a) { let k = a^2; if t > 0 { k + 1 } else { 0 } }
f(5)                 // If(0 < t, k + 1, 0)
let r = f(5); let t = 1; r     // k + 1
function g(a) { let k = a^2; sum(k * i * t, i, 1, m) }
g(5)                 // Sum(i * k * t, (i, 1, m))
do { let k = 25; if t > 0 { k + 1 } else { 0 } }     // If(0 < t, k + 1, 0)
```

`t` and `m` have no value. The `k` of each result is bound to the local of
the call or of the block, so it reads no value after the call and does not
read a global `k` either.

## What it must give

`If(0 < t, 26, 0)`, then `26`; `Sum(25 * i * t, (i, 1, m))`. A parameter in
the same place is already replaced with its value: with
`function f(a) { if t > 0 { a + 1 } else { 0 } }`, `f(5)` is
`If(0 < t, 6, 0)`.

## Cause and options

When a call ends, the occurrences of the parameters that the result still
names are replaced with their values (`bindingKeyedSubs`, in `settle` of
`makeLambda`, `function-utils.ts`). The locals of the body are not, and a
`Block` that ends replaces nothing. A value that is stored does get the
values of the locals it names (`snapshotRunVariables`, the same file): the
result of a call or of a block does not.

Option: at the end of a call and of a block, replace the locals of that
call or block that the result names in a part that was not evaluated, as
`snapshotRunVariables` does for a stored value. A function value keeps the
activation it was made in and is left alone, as there: a closure reads the
last value of a local that another closure writes.

## A function literal in a branch that is not evaluated (crafted)

Until the change that removed the rebuild of closures at the end of a call
(2026-11-15), one shape of this family gave the right value: a function
literal in the branch, because the end of the call rebuilt it on the call
frame.

```js
ce.declare('C', 'boolean');
ce.assign('f', ce.box(['Function',
  ['Block', ['Declare', 'k', "'unknown'", 'a'],
    ['If', 'C', ['Function', ['Add', 'k', 'x'], 'x'], ['Function', 0, 'x']]],
  'a']));
const r = ce.box(['f', 5]).evaluate();   // the If, not evaluated
ce.assign('C', ce.symbol('True'));
ce.box(['Apply', r.evaluate(), 1]).evaluate();   // k + 1; it was 6 before the change
```

The same holds for `Which`. The same branch written `k + x` with `x` a free
name gave `k + x` before and after. The option above fixes both shapes: the
literal of the branch is not a function value, so it gets the value of `k`.
A literal of such a branch that WRITES a parameter makes the application
decline: with `mk := n ↦ If(c > 0, () ↦ Block(n := n + 1, n), 0)`, `mk(5)`
stays `mk(5)` until `c` has a value.
