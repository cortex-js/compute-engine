The interpreter gives the number `0` for a product of the literal `0`, a real and a comprehension, whose type is a list.

## Witness

At `50e3e41a43ba6c1febb9b5f291a78d2e6bc28feb`, `x: real`:

```ts
const e = ce.box(['Multiply', 0, 'x', ['Comprehension', 2, ['Element', 'j', ['Range', 1, 3]]]]);
e.type.toString();                  // 'list<real>'
e.subs({ x: 0 }).evaluate().json;   // 0
```

The value has the shape of a number, and the type of the expression is
`list<real>`. Without the factor `x` (`0·[2 for j in 1..3]`) and with a
factor `x` and no `0` (`x·[2 for j in 1..3]`), the interpreter gives
`[0, 0, 0]`. The JavaScript compiler gives `[0, 0, 0]` in the three cases
(`cse: false, constantFold: false`), and so does the `numeric-kernel`
profile. The random tester found the form
`(0·(-5/x))·[2 for j in 3..1]` at `x = -1`.

## Cause and options

Not investigated. The product of the numeric factors `0·x` is folded to the
exact `0`, which then seems to absorb the lazy comprehension operand instead
of multiplying each of its elements. Option: apply the zero to each element
of a collection operand, as the product of `0` and a list literal does.
