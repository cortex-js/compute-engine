A sum over a set and a range with an upper bound loses the upper bound when its LaTeX is parsed again.

## Witness

```
const s = ce.box(['Sum', ['Multiply', 'k', 'j'],
  ['Element', 'k', ['Set', 1, 2, 3]], ['Tuple', 'j', 1, 3]]);
s.latex                      ->  \sum_{k\in \lbrace1, 2, 3\rbrace, j=1}^3jk
s.evaluate()                 ->  36
ce.parse(s.latex).json       ->  [..., ["Element", "k", ["Set", 1, 2, 3]],
                                  ["Limits", "j", 1, "Nothing"]]
ce.parse(s.latex).evaluate() ->  sum_(j=1)(j * k)   (no value)
(probe 2026-11-07, HEAD 51e77354c1736f722d39d4eb931a144c8c05adf0)
expected  ->  the parse gives ["Limits", "j", 1, 3] and the value 36
```

The same occurs when the `Element` clause has a condition
(`\sum_{k\in \lbrace1, 2, 3\rbrace, 1\lt k, j=1}^3jk`, 30 before, no value
after). A user who writes `\sum_{k\in S, j=1}^{3}` by hand gets the same
parse. The workaround is to write the range first: `\sum_{j=1, k\in S}^{3}`.

## Cause and options

`getIndexes()` (`definitions-arithmetic.ts`) gives the superscript item
`sups[i]` to the subscript item at position `i`. `serializeBigOp()` writes a
superscript item only for a clause that has an upper bound. An `Element`
clause has no upper bound, and its condition is one more subscript item, so
the superscript `3` goes to the `Element` clause and the range `j=1` gets
none. Fix: in `getIndexes()`, use a separate position in `sups` that moves
only for a range clause, not for an `Element` clause or its condition. Check
that `\sum_{i=1, j=1}^{10, 20}` still parses as before. Size S.
