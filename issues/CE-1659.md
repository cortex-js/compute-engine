The error for an unclosed string shows the quote as `"\""`, with a backslash,
and for a `#"…"#` string it names the opening delimiter instead of the closing
one.

## Witness

On CE 0.197.1, `epsilDiagnosticMessage` of the diagnostic
`["string-literal-closing-delimiter-expected", …]` that `parseEpsil` returns:

| Source        | Message                                     | Expected                                |
| ------------- | ------------------------------------------- | --------------------------------------- |
| `print("Hello` | `Expected closing string delimiter "\""`    | `Expected closing string delimiter '"'` |
| `x = #"ab`    | `Expected closing string delimiter "#\""`   | `Expected closing string delimiter '"#'` |
| `x = ##"ab`   | `Expected closing string delimiter "##\""`  | `Expected closing string delimiter '"##'` |

The fix-it of the same diagnostics is right: `print("Hello` inserts `"` at
offset 12. The instrument prints the three messages and READY when each names
the closing delimiter without a backslash (exit 0); today it prints NOT READY
(exit 1).

Every user who types a string sees the first message: Tycho's editor shows it
at the end of the line and in the fix menu while the string is open. Tycho
works around the backslash: its message mapping
(`src/graph-paper/notebook/cell-plugins/builtins/cortex-diagnostics.ts`)
rewrites the delimiter argument of `string-literal-closing-delimiter-expected`
as `“…”`, and shows the closer of an extended string (`“"#”`).

Tycho half on adoption: remove the delimiter rewrite in `messageText` of
`src/graph-paper/notebook/cell-plugins/builtins/cortex-diagnostics.ts`.

## Cause and options

Not investigated in CE. The message argument is the delimiter, and the
message template quotes its arguments as JSON strings, so a `"` in the
argument is escaped. The `#"` argument is the opener of the string, not its
closer. Requested: name the closing delimiter, quoted so that a `"` needs no
escape (for example between single quotes, or as "a closing `"`").
