The numeric value of the integral of x^25 times e^(-x) from 0 to 10 million is 0, where the true value is about 1.55e25.

## Witness

At `fd54cbe9b80182f1b3403b9c303ab2e1baeec90d`, `new ComputeEngine()`:

```ts
ce.box(['Integrate', ['Multiply', ['Power', 'x', 25], ['Exp', ['Negate', 'x']]], ['Limits', 'x', 0, 1e7]]).N().toString(); // 0
```

The value is `25! ≈ 1.5511e25` (the tail past `1e7` is negligible). With the
upper bound `1e4` the value is right. Compiled code of
`∫₀^y x²⁵·e⁻ˣ dx` (numeric route since CE-1310) gives `0` at `y = 1e7` too. A
Gaussian peak at `x = 20` over the same interval
(`Integrate(Exp(-(x - 20)^2), Limits(x, 0, 1e7))`) gives the right value.

## Cause and options

The Codex reviewer reports that every initial sample of the quadrature has
`e⁻ˣ` rounded to 0, and that the endpoint probe sees `x²⁵` underflow, so the
check for missed area finds none and a converged 0 is accepted
(`src/compute-engine/numerics/gauss-kronrod.ts`, not verified in detail).
Options: (a) when the interval is very wide and the integrand is a product with
a decaying exponential, split the interval at the peak of `log f`
(`logSpaceProduct()` gives `log f`); (b) refuse a converged 0 when a sample
point in the interval has a nonzero value of `log f` above the double range.
