Without a workaround, a code cell that declares `let c: Figure = …` loses its dependency on the sliders it reads, and a rename of such a slider does not rewrite the cell.

## Witness

On 0.204.0, `epsilProgramSites` takes the type and protocol names that an annotation may name only from the engine (`ce._typeResolver.names`, `ce._protocolRegistry`, `compute-engine/src/epsil/program-sites.ts:278-279`). It has no `typeNames` / `protocolNames` option. `parseEpsil`, `epsilCompletions` and `epsilSignatureHelp` all take these options. Tycho's notebook analysis runs the query on a separate engine that does not run the drawing prelude, which declares `Figure`, `PlotStyle`, `Raster` and others. On that engine, a statement annotated with a prelude type is dropped, with all its sites. The result carries no diagnostic, so the host cannot tell that a statement is missing.

The instrument reads on 0.204.0:

```
control (no annotation): c:program,circle:unresolved,k:unresolved
type declared on the engine: c:program,circle:unresolved,k:unresolved
bare engine: (none)
bare engine with typeNames: (none)
CE-1907: NOT READY on CE 0.204.0
```

Source: `let c: Figure = circle((0, 0), k)`.

## Cause and options

(a) Recommended. Accept `typeNames` and `protocolNames` in the options of `epsilProgramSites`, added to the names of the engine, as the editor functions accept them. Size S.

(b) Document in the doc comment of `epsilProgramSites` that an annotation may name only the types that the engine declares, and that the statement is dropped otherwise. Also consider a `diagnostics` field on the result, so that a host can see a dropped statement.

Workaround: Tycho declares each prelude type name with `ce.declareType(name, "any")` on the analysis engine (`createSitesEngine` in `src/graph-paper/notebook/cortex-analysis.ts`).

Tycho half on adoption: in `createSitesEngine` of `src/graph-paper/notebook/cortex-analysis.ts`, remove the `declareType` loop, and pass `NOTEBOOK_EPSIL_PARSE_OPTIONS.typeNames` and `protocolNames` to `epsilProgramSites` in `programSites`.

## Fix

Option (a). `epsilProgramSites` takes `typeNames` and `protocolNames` in its options, added to the names of the engine (`src/epsil/program-sites.ts`), as `epsilCompletions` does. Test: `test/epsil/program-sites.test.ts`, "a type or protocol name of the host is known to an annotation": `let c: Figure = circle(k)` with `typeNames: ["Figure"]` gives the sites of `c`, `circle` and `k`; without the option the statement has no sites. A type name that the program does not define has no site of its own, with or without the option. The instrument `scripts/repros/2026-11-27-ce1907-sites-type-names.mts` named above is not in this repository. The result still carries no diagnostic for a dropped statement (option (b)); not done.
