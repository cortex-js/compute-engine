Under `.N()`, a user function that applies `Floor` to an expression of its parameter rounds the argument first and gives the wrong integer.

## Witness

```
f := x ↦ Floor(2x);  f((25! − 1)/48).N()          gives 25, should be 24
g := x ↦ Equal(x − 10^30, 1);  g(10^30 + 1).N()   gives False, should be True
```

`f := x ↦ Block(z := 1, Floor(x))` is correct: the last statement re-reads the
exact argument (`exact-argument-source.ts`).

## Cause and options

The exact re-read handles a parameter written alone as the operand of a jump
function. For `2x`, the recorded argument must replace the parameter before
the re-read, and `subs` replaces by name without respecting binders: the fix
needs a substitution that respects them. Today `exactRealValueOf`
(`constraint-subject.ts`) refuses such a value, so the result is the float. In
`g`, the float of `x − 10^30` is `0`, so the comparison never asks for exact
values. User decision 2026-10-18: only the last statement gets the numeric
request; a jump in an earlier statement is accepted. Related: CE-964
(collection callbacks), CE-965 (early `Return`).
