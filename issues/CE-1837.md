A compiled function of one argument with no stated type, such as the transpose of a matrix or the length of a vector, returns a wrong answer with no error when it is called with a matrix or a vector.

## Witness

Checked at `0c5858f1ae20f8abbd9de27ffc2795ada8370a7f`, on JavaScript, with
`compile(ce.box(fn), { to: 'javascript', fallback: false })` and `run(…)`:

```
fn                      type inferred for the parameter   run(arg)               interpreter
A ↦ Transpose(A)        unknown                           [[1,2],[3,4]] → [[1,2],[3,4]]   [[1,3],[2,4]]
v ↦ Norm(v)             unknown                           [3,4] → NaN                     5
```

`compile()` reports success. Controls: a parameter inferred as a shape that
is not a scalar declines ("the parameter A of no declared type, read as
matrix", `lower.ts`, the root function literal): `A ↦ Determinant(A)`,
`A ↦ Inverse(A)`, `L ↦ Sum(L)`, `(u, w) ↦ Dot(u, w)`. With a declared
type, `(A: matrix) ↦ Determinant(A)` compiles and gives -2 at
`[[1, 2], [3, 4]]`.

The known-limitations list of `docs/COMPILATION-MODEL.md` records the same
cause as `crafted` ("a root function literal whose untyped parameter is read
as a number by its type (`unknown`) but whose body threads a list there:
`w ↦ Sum(List(w))`"). The two programs above are plausible, so that line
moves here.

## Cause and options

A positional parameter of a root function literal with no declared type is
read as a real (`input()` of `lower.ts`, "A positional one of no declared
type is a real"). The decline for a parameter read as a list
(`lower.ts`, "the parameter … of no declared type, read as …") applies only
where the signature of the literal gives the parameter a type that is not a
scalar; `Transpose` (`value`) and `Norm` give `unknown`, so the parameter is
read as a real and the code applies the scalar rule (`Transpose` of a
scalar is the scalar; `Norm` of a scalar is `Math.abs`).

Option (recommended): decline a positional parameter of no declared type
whose inferred type is `unknown` or `any`, as an input of those types is
refused (`AGENTS.md`), and keep reading it as a real where the inferred type
is a number type (`x ↦ Sin(x)`). The host declares the parameter
(`(A: matrix<real>) ↦ Transpose(A)`). Then delete the known-limitations
line. Measure the tests that compile an untyped `unknown` parameter before
landing.
