A notebook code cell whose result is a pair of lists shows Tuple(…) instead of the parenthesized pair.

## Witness

On 0.194.3 the LaTeX of `Tuple(List(1, 2), List(3, 4))` is
`\operatorname{Tuple}(\bigl\lbrack1, 2\bigr\rbrack,\bigl\lbrack3, 4\bigr\rbrack)`
and that of `Tuple(1, List(2, 3))` is `\operatorname{Tuple}(1,…)`. The Epsil
program `(continuedFraction(pi, 8), continuedFraction(sqrt(2), 8))` gives a
`value.latex` that starts with `\operatorname{Tuple}(`. Control: `Tuple(1, 2, 3)`
serializes as `(1,2,3)` and parses back to the same tuple. Both forms parse
back to the same MathJSON, so only the display is wrong.

## Cause and options

From the readings, the tuple serializer uses the parenthesized form only
when every element is a scalar. Option: use `(…)` for any element. The parser already reads
`([1, 2], [3, 4])` back as the tuple. Size S.

## Options (cebatch-1599, 2026-11-23)

The premise of the option above is not correct at `df71642ae6`: the parser
reads `([1, 2], [3, 4])` as `PointList([1,2], [3,4])`, not as a tuple, and
`(1, [2, 3])` as `PointList(1, [2,3])` (`scripts/probe.ts`). The spelling
`\operatorname{Tuple}(…)` is chosen on purpose by `serializeTuple()`
(`latex-syntax/dictionary/definitions-core.ts`) and `readsAsPointList` in
`boxed-expression/latex-serialize-options.ts`, because it is the only spelling
that parses back as a `Tuple`. `\left(…\right)`, `\bigl(…\bigr)`,
`\mathopen{(}…\mathclose{)}`, `\lparen…\rparen` and a trailing comma all parse
as a `PointList` too. So to show `([1,2], [3,4])` breaks the LaTeX round trip
(`docs/REVIEW-CHECKLIST.md`, "Verify a serializer change by a round trip"),
or changes the point-list notation.

- **(a) Keep the spelling (no CE change).** `.latex` stays
  `\operatorname{Tuple}(\bigl\lbrack1, 2\bigr\rbrack,\bigl\lbrack3, 4\bigr\rbrack)`.
  Tycho shows it, or makes its own display of a tuple of lists.
- **(b) A display option that does not round-trip.** A new public serialize
  option, for example `toLatex({ tupleStyle: 'parentheses' })`, spells every
  tuple `(…)`; its doc says that the result can parse back as a `PointList`.
  Tycho sets it for the result display of a notebook cell. The default stays
  (a). Size S: the option, the `serializeTuple()` test, a test, a doc page.
- **(c) Change the parser.** `(list, list)` reads as a `Tuple`, and a point
  list needs `\operatorname{PointList}(…)`. This changes the Desmos-style
  point-list notation (`(t, [1, 2, 3])`) that Tycho imports. Not recommended.

Recommendation: (b). The display is for a person, and the host is the one that
knows that it does not parse the text back.
