Four showcase documents no longer open their picture: the prelude that builds their list of points runs on the interpreter and times out.

## Witness

Each prelude starts from a list of integer zeros and writes real values in it:

```
function fern(n: integer) {
  let points = [0 for k in 1..2*n]
  for k in 1..n {
    ...
    points = replaceAt(points, 2*k - 1, x)   // x is real
    ...
  }
  points
}
const P = fern(10000)
```

On CE main 933bda7b707c8d361f14e277e9d67b8a379c6c13 (contains CE-1462 phase 1)
the compile declines: "Assign(points, ReplaceAt(points, Add(Multiply(2, k),
-1), x)): a real value written to a list of integer elements (the interpreter
changes the type of the list)". The same decline in koch-snowflake
(`Vertices`), turing-patterns (`Next`, in `grayscott`) and galton-board
(`L`). On the interpreter the statement exceeds Tycho's prelude deadline
("Operation canceled").

0.193.0 compiled all four (barnsley-fern 315 ms, koch-snowflake 272 ms,
turing-patterns 1,663 ms, galton-board 1,661 ms for the whole prelude, one
thread).

## Expected

The compiled code gives the list the element type the interpreter ends with
(real), as the interpreter does when it changes the type of the list. If CE
prefers that the program states the type, say which form it takes
(`[0.0 for …]`, a declared `list<real>`), and Tycho changes its preludes.
