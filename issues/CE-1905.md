A curve that reads a list of sliders, such as a polynomial whose coefficients
are the list `C = [c_1, …, c_10]`, draws through the slow interpreter path
instead of compiled code.

Tycho half on adoption: rerun the instrument and the codegen audit; records
#10757 and #10758 of `neyret/fvyda0ed67` must compile. Tycho has no
workaround to remove: it does not declare the sliders.

## Witness

`compile()` with `inputs: { x: "real", c_1: "real", c_2: "real", c_3: "real" }`:

- `\sum_{i=0}^{2}[c_1,c_2,c_3][i+1]x^{i}` compiles on `javascript` and
  `interval-js` (value 7 at x = 2, every c = 1).
- After `ce.assign("C", ce.parse("[c_1,c_2,c_3]"))`,
  `\sum_{i=0}^{\operatorname{Length}(C)-1}C[i+1]x^{i}` declines on both
  targets: "the inputs `c_1`, `c_2`, `c_3` have no type (`unknown` or `any`).
  Declare the type of each input, for example with `ce.declare("c_1", "real")`."
- The same program compiles after `ce.declare(c_i, "real")` for each name.

The `inputs` option declares the names, but the type check of names that
reach the program through an assigned value does not read the option. In the
codegen audit of CE 0.204.0 this declines records #10757 (javascript) and
#10758 (interval-js) of `neyret/fvyda0ed67` (arm `ce-0.204.0-all.json` of
Tycho `3ac69325f`). At CE 0.185.0 the same row
compiled, but Tycho did not pass `inputs` then, so the `regression` flag is
not set.

Report of the whole audit, with the other decline groups for review:
`~/dev/tycho/_TASK/desmos/desmos-corpus/codegen-audit/2026-11-27-report.md`.

## Cause and options

Read the `inputs` option where the check collects the free names of assigned
values, the same way it does for names in the expression. Workaround: Tycho
can `ce.declare` each slider; it does not do that today.

## CE answer

P3, pool. Reproduced with Tycho's instrument on CE 0.204.0 and with the
current compiler source. The assigned-list form declines with
`untyped-input` on JavaScript, interval-js, and GLSL. The literal-list
and explicitly declared controls compile on all three targets. At
`x = 2` with all coefficients equal to 1, the JavaScript controls
return 7 and the interval controls enclose exactly [7, 7].

Workaround for a host that owns the slider bindings: declare each
coefficient with `ce.declare(name, "real")` before assigning the list.
The fix should carry the input types to the occurrences reached through
the assigned list while preserving lexical binding and the host's
input-only scope.

The assigned-list witness now compiles on all three targets. The
JavaScript result is 7, the interval result is [7, 7], and the coefficient
input report retains the declared type.
The temporary input declarations do not persist on the engine. Tycho can
rerun its instrument once it adopts a release containing the fix.
