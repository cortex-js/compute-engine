Converting a quantity with a complex value to another unit loses the imaginary part: `(1 + i) m` in inches is `39.37 in`.

## Witness

Main 6f8fa80decd0759f578c89b0674f7271418c6377:

```ts
ce.box(['UnitConvert', ['Quantity', ['Complex', 1, 1], 'm'], 'in']).evaluate()
// 39.37007874015748 in, must be (39.37 + 39.37i) in
```

A conversion by an integer factor keeps the value (`m` to `cm` uses the
expression arithmetic). From CE-1411 on, `(1 + i) Np` to `dB` gives
`8.685889638065037 dB` the same way.

## Cause and options

`convertQuantity()` (`src/compute-engine/library/units.ts`) takes the
numeric route for a magnitude that is not exact (or for a conversion by a
float factor), and that route reads only `magExpr.re`
(`convertUnit(mag!, …)`). Fix: send a magnitude with `im !== 0` to the
`affineMagnitude()` route, as a `Measurement` is, or give `undefined`. The
same read of `.re` is in the float path of `quantityDivide()` and of the
`Add` conversion (`quantity-arithmetic.ts`); check them with the same
witness. Size S.
