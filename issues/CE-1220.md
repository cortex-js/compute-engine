A compiled integral with a complex bound and a real closed form gives `{re: NaN, im: NaN}` in a complex operation.

## Witness

At `114403d0b44156730f1f943b12362d0c74f90fc8`, the `strict` mode,
`cse: false, constantFold: false`:

```ts
const e = ce.box(['Power', ['Integrate', 't', ['Limits', 't', 'ImaginaryUnit', 0]], 2]);
compile(e, { cse: false, constantFold: false }).code;
// (() => { const _tv1 = (0.5); const _tv1_1 = { re: _tv1.re * _tv1.re - _tv1.im * _tv1.im, im: 2 * (_tv1.re * _tv1.im) }; return _tv1_1; })()
compile(e, { cse: false, constantFold: false }).run({}); // {re: NaN, im: NaN}
```

The interpreter gives `0.25` (∫ᵢ⁰ t dt = 1/2).

## Cause and options

The parent reads the `Integrate` node on the complex lane (its bound is
complex), and the closed form `1/2` is written as a real number, so its
`.re` is `undefined`. Options: the lane of an `Integrate` node is the lane
of its closed form, as `compile-complexness.ts` does for an applied
`Derivative`; or the closed form is converted to the lane of the node. The
numeric-kernel profile declines a calculus node that holds a complex
number.
