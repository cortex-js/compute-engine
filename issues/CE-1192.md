When the callback of `ce.withValues()` throws, a failure to put back a value is not reported, so a symbol can keep its temporary value after the call, with no error.

## Witness

`withValuesFn()` (`src/compute-engine/engine-declarations.ts`) restores the
bindings in `finally` and throws the first restore error only when `fn` did
not throw (`if (failure !== undefined && !threw) throw failure.error`). When
`fn` threw and a restore failed, the caller gets only the error of `fn`.

Tycho reaches the case only by fault injection: its tests replace a
definition's internal `_restoreCheckpointSnapshot()` with a function that
throws, then throw from `fn`
(`~/dev/tycho/tests/node/graph-paper/point-coordinates-resolved-collection-binding.test.ts`,
the tests "when fn throws and the restore fails" and "when fn throws and the
restore of a collection fails"). No public program that makes a restore fail
is known, so the witness is `crafted`. Tycho still keeps about 40 lines of
repair code (`recordValuesBeforeBinding()`, `repairValuesLeftByRestore()`)
because of this gap.

## Cause and options

When both fail, report both. Option: throw the error of `fn` with the restore
failure attached (`AggregateError([fnError, restoreError])`, or the restore
error on a documented property of the thrown error). The error of `fn` stays
the first one, so a caller that reads it sees no change. Document the
behavior in the doc comment of `ce.withValues()`. When this is fixed, Tycho
can remove its repair. Size S.
