A variable that holds a filtered endless list follows a later change of a function that its filter calls.

## Witness

```js
ce.assign('k', 3);
ce.assign('g', ce.box(['Function', ['Greater', 'c', 'k'], 'c']));
executeEpsil(ce, 'let big = filter(1..oo, c => g(c))\ng = (c) => c > 100\nfirst(big)');
// 101; expected 4
```

At `5eb1778b5d1643108ec473a2eb040bcbfe3fd063`. The decision of 2026-09-30 says
that a stored collection keeps the variables that it reads at the
assignment; `big` should keep the `g` of that time.

Since the declared-locals rule, a function made with `let g = …` is a
function definition like an assigned global, so the form of the test named
above gives 101 too (it gave 4 while such a local was a value).

## Cause and options

Not investigated. The substitution of the variables that a stored lazy
collection reads (`bindingKeyedSubs`, `applicationValue`) does not replace
the head of a call whose definition is a function.
