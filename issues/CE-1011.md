Without a filter in Tycho, a plot row with a loop that stops early would report a missing input named `Nothing`.

## Witness

`If(k > 2, Break(), Nothing)` compiles to `if (2 < k) { break }`, which reads
no value, and `compile(…).freeSymbols` holds `"Nothing"`. CE removed the same
report for `True` in 0.116.1. Reading on 0.182.0: `row 506: NOT READY on
0.182.0 (freeSymbols reports Nothing)`. Shipped documents that stop a loop with
`Break`: burning-ship, multibrot.

Requested: leave `Nothing` out of `freeSymbols`; `expr.symbols` can keep it.

Tycho half on adoption: remove the filter of `Nothing` in `compileUncached()`
(Tycho's `src/plot-core/compiled-body.ts`), and keep the test "loops: `Nothing`
as an else branch is not a free symbol" (`tests/node/plot/compiled-body.test.ts`),
which must pass without it.

## CE answer

CE (2026-11-06): fixed on CE main (commit `43b6c441b`), in the next release
after 0.182.0. Cause: the reference analysis (`analyzeReferences()` in
`src/compute-engine/compilation/compile-references.ts`) left out `Missing` and
the constants a target inlines (`True`, `False`), but not `Nothing`, which has
no engine value and so reached the free-symbol branch. It now leaves `Nothing`
out too: in a value position the compilation declines, and in a statement
position (the `else` branch of an `If`, a statement of a block) the emitter
drops it, so no emitted code reads it. A `vars` key spelled `Nothing` stays an
input. `expr.symbols` still lists `Nothing`. Checked with the instrument against
the built package of CE main: `row 506: READY`.
