`Filter` with a predicate that tests whether a set contains the constant e throws, because that test is never decided.

## Witness

On main at `fed2ad56317cc2a41f1124414bdc7c97d857d83a`:

```
ce.box(['Contains', ['List', 1, 2], 'e']).evaluate()     // False; e could be 1
ce.box(['Element', 'e', ['List', 1, 2]]).evaluate()      // False
ce.box(['Contains', ['Set', 1, 2], 'e']).evaluate()      // Contains(Set(1, 2), e), right
const L = ['List', ['Set', 1, 2, 3], ['Set', 3]];
ce.box(['Length', ['Filter', L, ['Function', ['Contains', 'b', 'e'], 'b']]]).evaluate()
  // throws: Filter predicate must return "True" or "False".
ce.box(['Length', ['Filter', ['List', ['List', 1, 2], ['List', 3]],
  ['Function', ['Contains', 'b', 'e'], 'b']]]).evaluate()   // 0, from the False above
ce.box(['Length', ['Filter', ['List', 1, 2, 3], ['Function', ['Greater', 'b', 'n'], 'b']]]).evaluate()
  // Length(Filter(...)), the documented undecided result
```

Probability `medium`: a membership test with an unknown symbol.

## Cause and options

Two defects. (1) The membership test of a list compares each element with the
symbol and answers `False` when no comparison is `True`; it must stay
unevaluated when a comparison is undecided, as the `Set` case does. (2) The
undecided-predicate path of `Filter` (`library/collections.ts`) knows the
comparisons only; a predicate that stays symbolic because of a free symbol
must be undecided for every head, and the throw kept for a predicate with no
free symbol that is not a boolean. Size M.

## Findings at 2026-11-15 (`2286d6f2c8813f3222bd9f033086713aab9cb5ce`)

The symbol `e` of the witness is the constant `ExponentialE`, not an unknown.
With an unknown `x`:

```
Contains(List(1, 2), x)                        // False
Element(x, List(1, 2))                         // Element(x, List(1, 2))
Contains(Set(1, 2), x)                         // Contains(Set(1, 2), x)
IndexOf(List(1, 2), x), Count(List(1, 2), x)   // 0, 0
Length(Filter(List(Set(1,2,3), Set(3)), b ↦ Contains(b, x)))   // unevaluated, no throw
Element(ExponentialE, Set(1, 2)), Element(Pi, Set(1, 2))      // unevaluated
```

So the two parts are:

1. `Contains`, `IndexOf` and `Count(xs, v)` over a `List` compare by
   structural identity. This is the documented contract: the description of
   `Contains` (`library/collections.ts`, "structural identity, like `===`"),
   `SEARCHED_VALUE_POLICY` in the same file, and
   `cortexjs.io/docs/compute-engine/82-reference-collections.md`
   ("`Contains(xs, v)` is equivalent to `Any(xs, (e) |-> e === v)`");
   `IsSame(x, 1)` is `False`. The `Set` facet (`literalSetContains`) is
   three-valued instead, and `Element` is undecided for an unknown. A change
   of the `List` answer changes this contract.
2. The throw of `Filter` does not come from the undecided-verdict test:
   `isUndecidedVerdict` already accepts a boolean with an unknown (the `x`
   case stays unevaluated). It comes from `literalSetContains`, which is
   undecided for every target that is not a number literal or a string, also
   for a constant with a value: `Contains(Set(1, 2, 3), ExponentialE)` stays
   unevaluated, the verdict has no unknown, and `Filter` reports a malformed
   predicate. `ExponentialE.isEqual(3)` is `false`.

## Options for part 1

- (a) Keep the contract. `Contains`, `IndexOf` and `Count(xs, v)` stay
  structural searches over every collection; `Element` is the mathematical
  membership. `Contains(List(1, 2), x)` stays `False`. Only the
  documentation adds one sentence that names `Element` for a membership with
  an unknown. Part 2 is fixed as below.
- (b) Make the `contains` facet of `List` and `Tuple` three-valued, as the
  facet of `Set` is: a target with an unknown that is not `isSame` an element
  gives `undefined`. `Contains(List(1, 2), x)` stays unevaluated, and
  `Length(Filter(List(List(1, 2), List(3)), b ↦ Contains(b, x)))` stays
  unevaluated instead of `0`. This changes the documented contract, and
  `IndexOf` and `Count(xs, v)` must then change the same way or disagree with
  `Contains`.
- (c) Make the `Set` facet structural, as the `List` facet is:
  `Contains(Set(1, 2), x)` is `False`. This also makes `Element(x, Set(1, 2))`
  `False`, which is a wrong value for a mathematical membership. Not
  recommended.

Recommendation: (a). The documented `===` reading is what `Any(xs, e ↦ e ===
v)` gives, and a host that wants a membership with an unknown has `Element`.

Fix of part 2, under every option: in `literalSetContains` (and the number
branch of `indexedLiteralSetContains`), compare a target and an element that
are both numeric and have no unknowns with `isEqual`, so
`Contains(Set(1, 2, 3), ExponentialE)` is `False` and the `Filter` of the
witness gives `0`. About 10 lines of `src/`.

## Decision

User decision 2026-11-15: (a). `Contains`, `IndexOf` and `Count(xs, v)` over a `List` stay structural searches, as documented; the reference adds one sentence that names `Element` for a membership with an unknown. Fix part 2 as written above.
