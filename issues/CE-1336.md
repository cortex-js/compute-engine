`Contains` of a list and an unknown symbol is `False`, and `Filter` with a `Contains` or `Element` predicate over an unknown symbol throws.

## Witness

On main at `fed2ad56317cc2a41f1124414bdc7c97d857d83a`:

```
ce.box(['Contains', ['List', 1, 2], 'e']).evaluate()     // False; e could be 1
ce.box(['Element', 'e', ['List', 1, 2]]).evaluate()      // False
ce.box(['Contains', ['Set', 1, 2], 'e']).evaluate()      // Contains(Set(1, 2), e), right
const L = ['List', ['Set', 1, 2, 3], ['Set', 3]];
ce.box(['Length', ['Filter', L, ['Function', ['Contains', 'b', 'e'], 'b']]]).evaluate()
  // throws: Filter predicate must return "True" or "False".
ce.box(['Length', ['Filter', ['List', ['List', 1, 2], ['List', 3]],
  ['Function', ['Contains', 'b', 'e'], 'b']]]).evaluate()   // 0, from the False above
ce.box(['Length', ['Filter', ['List', 1, 2, 3], ['Function', ['Greater', 'b', 'n'], 'b']]]).evaluate()
  // Length(Filter(...)), the documented undecided result
```

Probability `medium`: a membership test with an unknown symbol.

## Cause and options

Two defects. (1) The membership test of a list compares each element with the
symbol and answers `False` when no comparison is `True`; it must stay
unevaluated when a comparison is undecided, as the `Set` case does. (2) The
undecided-predicate path of `Filter` (`library/collections.ts`) knows the
comparisons only; a predicate that stays symbolic because of a free symbol
must be undecided for every head, and the throw kept for a predicate with no
free symbol that is not a boolean. Size M.
