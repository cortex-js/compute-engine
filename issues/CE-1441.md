A series at 0 of the square root of a parameter times the variable has terms divided by zero, instead of the square root of the parameter times the square root of the variable.

## Witness

At commit `ce77809c8a52177728a4b19e85ea5b204b29ea91`:

```
Series(Sqrt(a x), x, 0, 3)
  // x·√a/0 − √a/0·x² + 3√a/0·x³ + BigO(x⁴); with a = 2, N() gives ~∞·x + …
  // expected √a·√x (the Puiseux engine), or Series(...) unevaluated
Series(Sqrt(2 x), x, 0, 3)          // √2·√x (correct)
Series(Sqrt(x + a x^2), x, 0, 3)    // √x + a/2·x^(3/2) − a²/8·x^(5/2) + … (correct)
```

## Cause and options

Not investigated. Probably `symbolic/series.ts`: a Taylor engine (`expandViaSeeds()` or `expandByDerivative()`) runs first at a regular point, and its test for a value that is not usable (`isUnusableTaylorValue()`, `hasHiddenSingularity()`) does not see `√a/0` as infinite when `a` is an unknown, so the branch point at `a·x = 0` is read as a regular point and the Laurent (Puiseux) engine is never tried. Option: treat a coefficient that holds a `Divide` by an exact 0 (or a `Power` of 0 with a negative exponent) as unusable, so that the Puiseux engine expands it. The Puiseux engine at a finite point also needs the sign of the leading coefficient `a` (CE-1308, `puiseuxHoldsBelow()`), so the result for an unknown `a` is then a decline.
