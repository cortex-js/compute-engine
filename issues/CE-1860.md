The report of a compiled program says that a list of lists input is read as `rows`, a word that the reference of the report does not list.

## Witness

Checked at `087199a6c1482d61a1ba46ea855ead0cd0a6d0bf`, on JavaScript:

```ts
const ce = new ComputeEngine();
ce.declare('g', 'list<list<real>>');
compile(ce.box(['Length', 'g']), { fallback: false }).freeSymbolTypes;
// { g: { type: 'list<list<real>>', lowered: 'rows', provenance: 'declared' } }
```

Controls: `v: list<real>` and `K: matrix<real^2x3>` give `lowered: 'array'`.
The reference of `FreeSymbolType.lowered`
(`src/compute-engine/compilation/types.ts`) lists the JavaScript values
`number`, `complex`, `boolean`, `string`, `point`, `color`, `array` and
`function`. A host that switches on these values has no case for `rows`. The
host passes the same value for all three inputs, an array of arrays.

## Cause and options

`runnerLowered()` of `src/compute-engine/compilation/ir/adapter.ts` returns
`array` for a parameter whose IR type has a shape, and the name of the lane for
the others. An input of type `list<list<real>>` is a parameter of the lane
`rows` with no shape, so the name of the lane is reported. Check the lane
`record` the same way.

- (a) Report `array` for a parameter of the lane `rows` (recommended: the host
  passes an array, and the reference stays as it is).
- (b) Add `rows` to the reference, with what it means for the host.
