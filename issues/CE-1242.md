The `numeric-kernel` profile reports an internal error (`compile-error`, "an internal error in the preparation phase") for a call of a function whose literal captured a callable that was rebound since, where it should decline (`outside-profile`).

## Witness

At `2053dc1a4c89badaff53fda9ba1a56c22a529222`, the program of
`test/compute-engine/call-head-lexical-binding.test.ts`, "a named closure
retains interpreter/compiler parity":

```ts
const ce = new ComputeEngine();
ce.pushScope();
ce.declare('h', '(real) -> real');
ce.assign('h', ce.box(['Function', 7, 'u']));
const literal = ce.box(['Function', ['h', 'x'], 'x']);
ce.popScope();
ce.assign('h', ce.box(['Function', 9, 'u']));
ce.assign('f', literal);
compile(ce.box(['f', 1]), { profile: 'numeric-kernel', fallback: false });
```

The profile throws "Could not compile with the profile 'numeric-kernel': an
internal error in the preparation phase: Could not compile `h`: the captured
callable has a different binding from the ambient function." The existing
compiler declines the same program with "the captured callable has a
different binding from the ambient function" (`compile-user-functions.ts`,
`compile-expr-handlers.ts`). The same with `Map(u ↦ h(u), [1, 2])` as the
body. The message is the same before and after the change of slices 3 to 5
(seen by the witness logger at `60e81ebee` and on that change).

## Cause and options

The preparation of the structured route calls the existing compiler's
preparation of the helper, whose throw the route classifies as an internal
error. Option: classify this refusal of the preparation as a decline with
its message (it is a decline of the existing compiler too).
