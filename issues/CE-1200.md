The type of a deep chain of calls is quadratic in its depth: the `isFinite` getter of a function expression is not cached.

## Witness

```
let e = ce.box('x');
for (let i = 0; i < 20000; i++) e = ce.function('Sin', [e]);
```

`test/compute-engine/ce-882-shared-copies.test.ts`, "A held expression deeper
than the call stack evaluates": 6 s alone with `CE_BINDING_UNITS=0`, 38 s alone
with binding units on (2026-11-10, commit
`627ed80e1ffb9768e45128ae19027ab24cd46311`).

## Cause and options

The type of each new `Sin` level reads `isFinite` of its operand. The getter
(`boxed-expression/boxed-function.ts`) is not cached, and for `Sin` it reads
`op1.isFinite` down the whole chain, with three reads of the cached type of
each level. With binding units on, each type-cache hit also checks and merges
three recorded reads, which costs about nine times a hit without them.

Fix: cache `isFinite` on the node with the keys of the type cache. This
removes the quadratic walk with and without binding units.

## Witness on a shared tree (added 2026-11-12)

CE-1200 says the `isFinite` getter of a function expression is not cached,
so a chain of 20,000 calls is quadratic. On a tree that shares its operands,
the same getter, and the sign getters (`isNegative`, `sgn`), are exponential
in the depth: each reads the getter of each operand, and both operands are
the same node.

| Tower `t_k` | Getter | d = 16 | d = 18 | d = 20 |
| --- | --- | --- | --- | --- |
| `Sin(t) + Cos(t)` | `root.isFinite` | 49 ms | 199 ms | 798 ms |
| `Power(t, t)` | `root.isFinite` | 40 ms | 160 ms | 649 ms |
| `Multiply(Sqrt(t), t)` (non-canonical) | `root.isNegative` | 19 ms | 71 ms | 286 ms |

Both compilers pay it: the type of the root is computed again under the
static typing view of a compilation, and that type reads `isFinite` of the
operands (`operandNonFiniteNumber()`, `type-handlers.ts`), from
`inlinePointValuesAtRoot()` (`point-value-inlining.ts`) and, for GLSL,
`isComplexValued()`. `compile()` of `Power(t, t)`: JavaScript default options
655 ms at depth 20; `numeric-kernel` profile 212 ms at 20 and 3.4 s at 24;
GLSL 164 ms at 18. Building the tower is exponential too
(`checkNumericArgs()` reads the type of the operands: `Power` 224 ms at 20).
The fix that CE-1200 proposes (cache `isFinite` on the node with the keys of
the type cache) covers this witness if it caches the sign getters as well.
