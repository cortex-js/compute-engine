At machine precision, the elliptic integral `EllipticF(φ, 1)` near φ = π/2 is wrong by up to ln 2.

## Witness

On main, with `ce.precision = 'machine'`:

```
ce.box(['EllipticF', 1.57079632679, 1]).N()   // 27.428776665347943
Math.log(Math.tan(1.57079632679 / 2 + Math.PI / 4))   // 26.735616979764828
```

F(φ, 1) = artanh(sin φ) = ln tan(φ/2 + π/4). At the default precision (bignum kernel of PR #557) the value is right: 26.7356232822903685461.

## Cause and options

Not examined. The machine kernel of `EllipticF` (`numerics/`) loses accuracy as `sin φ → 1` at `m = 1`; the error of exactly about ln 2 suggests a cancellation in a logarithmic form. At `m = 1` the kernel could use `ln tan(φ/2 + π/4)` directly. Size S.
