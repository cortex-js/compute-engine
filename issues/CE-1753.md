The length of a filtered list whose elements call a function that has no definition stops with the error "Not canonical" instead of giving a result.

## Witness

At 277bdef3c32b606388b9fa706a8e61acd19b781e, on a new engine where `g` is
not declared:

```ts
ce.box([
  'Length',
  [
    'Filter',
    ['Map', ['Function', ['g', 'k'], 'k'], ['Range', 1, 3]],
    ['Function', ['Less', 'k', 2.5], 'k'],
  ],
]).evaluate();
```

throws `Error: Not canonical`. The same rows in a prepared Document
(`L = Map(Function(g(k), k), Range(1, 3))`,
`P = Filter(L, Function(Less(k, 2.5), k))`, then `Length(P)`) throw the
same. A user meets it with a typo in the name of a function, or a function
that a later row defines. With `Function(k, k)` in place of `g(k)` the
value is 2.

The stack:

```
BoxedFunction.add (boxed-function.ts)          throw new Error('Not canonical')
BoxedFunction.sub (abstract-boxed-expression.ts)
orderByValue (compare.ts)
cmpWithTolerance / cmp (compare.ts)
BoxedFunction.isLess
decideLess (relational-operator.ts)
Less evaluate
... the Filter predicate, applied by the count of the Filter view
Length evaluate
```

## Cause and options

Not investigated. The `Filter` predicate `k < 2.5` receives the element
`g(1)` of the `Map`, and the comparison `orderByValue` subtracts with an
operand that is not canonical. Expected: the predicate does not decide, and
`Filter` reports that as it does for other undecided predicates, or the
expression stays unevaluated.
