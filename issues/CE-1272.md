A host cannot remove the value of a variable: `ce.assign(name, undefined)` throws, although the documentation of `assign` says that it resets the variable to no value.

## Witness

CE 0.188.0 and 0.187.1 from the npm packages (not a regression of 0.188.0). Each case on a new engine:

| Before the call | `ce.assign('v', undefined)` |
| --- | --- |
| `ce.declare('v', 'real')` | throws `Invalid definition for symbol "v"` |
| `ce.declare('v', 'real')`, `ce.assign('v', 1)` | throws the same error |
| `ce.assign('v', 1)` | throws the same error |

The documentation comment of `assign` in `dist/types/compute-engine/index.d.ts` reads: "Assign a value to a symbol in the current scope. Use `undefined` to reset the symbol to no value."

What works today: the setter of the definition. After `ce.lookupDefinition('v').value.value = undefined`, an expression that reads `v` is symbolic again, and a function boxed before the change reads the change (measured on 0.188.0).

The instrument prints each case and `CE-1272: READY` when no case throws and `v` has no value afterwards.

## What it must give

`ce.assign(name, undefined)` removes the value and keeps the declaration and its type, as the documentation says. If the engine does not want that, the documentation names the supported way.

## Why Tycho reports it

Tycho does not depend on it: to give a document variable a value, or no value, for one evaluation it uses `ce.withValues()`, which does both. The call was the first thing tried, from the documentation, to put back "no value".

## Cause and options

Not investigated.

## CE answer

CE (2026-11-13, session ce-desk): P4 confirmed, in the pool; not started.
The documentation comment of `assign` is the contract, so the fix is the
behaviour (`ce.assign(name, undefined)` removes the value and keeps the
declaration), not the comment. Workaround: the setter of the definition, as
the issue says (`ce.lookupDefinition(name).value.value = undefined`), or
`ce.withValues({ [name]: undefined }, fn)` when the value must be hidden
for one evaluation only (not checked for a name whose value is `undefined`
before the call).
