A sum over a set with two conditions after the set uses only the first condition, so it gives a wrong value.

## Witness

```
ce.parse('\\sum_{k\\in \\lbrace1,2,3\\rbrace, k>1, k<3} k').json
  ->  ["Sum", "k", ["Element", "k", ["Set", 1, 2, 3], ["Less", 1, "k"]]]
ce.parse('\\sum_{k\\in \\lbrace1,2,3\\rbrace, k>1, k<3} k').evaluate()
  ->  5
(probe 2026-11-07, worktree of CE-1051 on HEAD
 51e77354c1736f722d39d4eb931a144c8c05adf0)
expected  ->  2 (the condition k<3 is kept, joined with And)
```

No message tells the user that `k<3` was ignored. The workaround is one
condition: `k>1 \land k<3`. The serializer of `Sum` and `Product` does not
write two conditions (a canonical condition is one `And`), so only
hand-written LaTeX reaches the case.

## Cause and options

`getIndexes()` (`definitions-arithmetic.ts`) attaches to an `Element` clause
only the one subscript item that follows it, when `isElementCondition()` says
that it is a condition. The item after that goes to `getIndexAssignment()`,
which returns `undefined` for a `Less`, and the loop drops it. Fix: after an
`Element` clause, attach each next item while `isElementCondition()` is true,
and join two or more conditions with `And`. Size S.
