A local declared with a dictionary as its initial value has no value, and the error says only that the local is read before it has a value.

## Witness

Run on main at `bf715c27453a9cdd5b19f8b4268eeb6bb79ea40e`:

```js
ce.box(['Block',
  ['Declare', 'd', "'unknown'", ['Dictionary', ['KeyValuePair', "'a'", 3]]],
  'd']).evaluate();
// Error(ErrorCode("read-before-initialization", "d"))
```

The same `Declare` at the top level gives
`Error(declaration-without-value, d)`. `Declare(d, {a: 3})` in a block gives
the same `read-before-initialization` error.

Workaround: give the dictionary as the `value` attribute
(`Declare(d, Dictionary(KeyValuePair("value", {a: 3})))`, which Epsil
`let d = {"a" -> 3}` emits), or add an empty attributes dictionary
(`Declare(d, "unknown", {a: 3}, Dictionary())`). Both give `{"a" -> 3}`.

## Cause and options

By the signature of `Declare` (`src/compute-engine/library/core.ts`), a
trailing dictionary operand is the attributes bag, with the keys `type`,
`value`, `constant` and `holdUntil`. So `{a: 3}` is read as attributes, the
key `a` is ignored, and the local gets no value. In a block, a declaration
with no value reserves a slot (`declareHasValue`), so no error is given at
the declaration.

Option (a), recommended: a trailing attributes dictionary with a key that is
not an attribute name is the error `invalid-declaration-attribute` with the
key, at the declaration, in a block and at the top level. The host then
sees why the value is not stored. Size S.

Option (b): read a trailing dictionary with no attribute key as the value.
This makes the reading of an operand depend on its keys, and a dictionary
value with a key `type` or `value` is still read as attributes.
