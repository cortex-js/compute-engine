The inverse of a matrix that has an infinite entry gives a matrix of ordinary numbers.

## Witness

At commit `0bebdaee7b63afd440151e05c12684ab9151765c`:

```
Inverse([[1.5, +oo, 1], [1, 1, 1], [4, 3, 2]])   // evaluate() and N()
  // [[4, -3, -0.5], [-8, 4, 2], [4, 0, -1.5]]
Inverse([[1.5 + i, +oo, 1], [1, 1, 1], [4 + i, 3, 2]]).evaluate()
  // [[NaN, NaN, NaN], [0, 0, 0], [NaN, NaN, NaN]]
```

A matrix with an infinite entry has no inverse: the call must stay
unevaluated, as `Inverse([[1.5, +oo], [1, 1]])` does. The witness is crafted:
no ordinary program inverts a matrix with an infinite entry.

## Cause and options

The elimination of `numberMatrixInverse()` has no test for an infinite entry,
and its test of a residue (`|x| <= tiny · bound`) is true for every finite
`x` once a bound is infinite. The generic elimination of `AbstractTensor.inverse()`
(the `expression` dtype) has the same gap. `complexMatrixInverse()`
(CE-1803) returns `undefined` for a matrix with an infinite or NaN entry.

Option: `numberMatrixInverse()` returns `undefined` when an entry is
infinite, and the generic path does the same for an infinite number entry. A
NaN entry keeps its result today (a matrix of NaN). `numberMatrixInverse()`
is also the kernel of compiled JavaScript, which then gives a matrix of NaN.
