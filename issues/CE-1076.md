The compiled `Map(f, S)` of a function `f := s ↦ Length(s)` over a list of strings `S` throws a `RangeError` instead of giving the length of each string.

## Witness

With `S: list<string>` and `f := s ↦ Length(s)`, `Map(f, S)` compiles on
JavaScript (`success: true`) to
`((_f) => (_.S).map((_x) => _f(_x)))(_fn_f)`. At `S = ["xy", "z"]`, it throws
`RangeError: Length: the operand is not a list or a set at run time`; the
interpreter gives `[2, 1]`. The same map with the literal written in place,
`Map(s ↦ Length(s), S)`, gives `[2, 1]`. Checked at commit
`c805d8ece2734fbda30ad21ec993291ef954e3e0`.

## Cause and options

`s` has the inferred type `collection`. The function value compiles to the
generic `_fn_f`, whose `Length` reads `s` with `_SYS.elts`, which refuses a
string. The call `f(t)` takes a copy with `s` typed `string`
(`ensureSpecializedUserCallEmitted()`, `compilation/compiler-core.ts`).
Option: pass that copy for string elements, or decline.
