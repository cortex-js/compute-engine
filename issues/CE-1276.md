A TypeScript host that copies a compile result and gives the copy to the runtime gets a type error since 0.188.0.

## Witness

CE 0.188.0 from the npm package. In `dist/types/compute-engine/compilation/types.d.ts` the compile result has `profile?: 'numeric-kernel' | 'ir'`; in `javascript-runtime.d.ts` the stored program that `load()` and `loadBroadcast()` take has `profile?: 'numeric-kernel'`.

```ts
const result = compile(ce.number(1), { to: 'javascript' });
const copy = { ...result, valueKinds: ['host-value'] };
createJavaScriptRuntime().load(copy);
// error TS2345: Types of property 'profile' are incompatible.
//   Type '"ir" | "numeric-kernel" | undefined' is not assignable to type '"numeric-kernel" | undefined'.
```

The instrument reads the two declarations and prints `CE-1276: READY` when their `profile` types are the same.

## What it must give

Either the runtime takes a program of the profile `ir` (and declines it at run time if it cannot load it), or the type of a compile result is narrowed by the options so that a compile without `profile: 'ir'` does not have `'ir'` in its type.

## Cause and options

Not investigated.

## Tycho half on adoption

`tests/node/plot/stored-kernel.test.ts` writes `profile: undefined` on the copy. On adoption: remove that line and its comment.

## CE answer

CE (2026-11-13, session ce-desk): P4 confirmed, in the pool; not started. The two declarations must agree; which one changes depends on whether code compiled with the `ir` profile can be loaded by `runtime.load()` (the design note `docs/plans/2026-11-12-ir-profile-shippable-code.md` is about that). Workaround: the one in the issue.
