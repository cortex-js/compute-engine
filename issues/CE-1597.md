A user who types the polygamma function as ψ⁽¹⁾(1) gets the symbol ψ, with no error, and Φ(z, s, a) is not the Lerch function.

## Witness

On 0.194.3 `ce.parse()` gives:

```
\psi^{(1)}(1)  → "psi"                       want ["PolyGamma", 1, 1]
\psi^{(2)}(1)  → ["Power", "psi", 2]         want ["PolyGamma", 2, 1]
\psi^{(m)}(z)  → ["Multiply", "z", ["Power", "psi", "m"]]
\Phi(1,2,1)    → ["Phi", 1, 2, 1]             want ["LerchPhi", 1, 2, 1]
```

Controls: `\operatorname{PolyGamma}(1,1)` and `\operatorname{LerchPhi}(1,2,1)`
parse to the library operators. The instrument also prints `\psi(1)`, which
parses as `["psi", 1]`, not `Digamma`.

## Cause and options

The LaTeX dictionary has no entry for `\psi` with a parenthesized
superscript, so `^{(1)}` is read as a power and the call is lost. Option: parse
`\psi^{(m)}(z)` as `PolyGamma(m, z)` and serialize `PolyGamma` that way; parse
`\Phi` with three arguments as `LerchPhi`, and leave other arities to the
user. Whether `\psi(z)` alone becomes `Digamma` is CE's choice (`\psi` is
also a common variable name). Size S.

## Code

The LaTeX entries are in `src/compute-engine/latex-syntax/dictionary/definitions-arithmetic.ts`.
