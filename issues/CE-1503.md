A compiled function whose parameter is a list of real numbers, given a list that holds NaN or an infinity, returns a number where the interpreter reports an error.

## Witness

On CE main 50130e4aa with `E: list<nan | real>`:

```ts
compile(ce.box(['Apply', ['Function', ['Length', 'H'], ['Typed', 'H', "'list<real>'"]], 'E'])).run({ E: [NaN] });
// 1; the interpreter gives Error(incompatible-type, list<real>, vector<nan^1>)
```

With `E: list<real | infinity>` at `E = [+∞]` and a body that does not read
the elements, the compiled code gives a finite value and the interpreter an
error at the binding. CE-1483 (736f19c) binds a list argument whole at a
list parameter with no element check, because the interpreter accepts
`[2.5]` at `list<integer>`; it does check NaN and the infinities. 0.194.0
declined these calls.

## Cause and options

The CE-1483 whole binding assumes the interpreter checks no element. Options:

- (a) Decline the whole binding unless the argument's element type excludes
  NaN and the infinities, or the parameter's admits them. Sound, and the
  simple version. Cost: Tycho's buddhabrot action (`H: list<nan | real |
  signed_infinity>` at `list<integer>`, CE-1483's witness) declines again
  until Tycho narrows the row `H` (the user's ruling for CE-1485: a
  live-owned row takes the type its writers prove).
- (b) Keep the binding and add a caveat to `docs/COMPILATION-MODEL.md`. That
  changes the documented contract (a wrong finite value for inputs of their
  declared types).

Recommended: (a).
