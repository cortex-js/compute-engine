A function with a local variable, made before it is mapped over the rows of a matrix, gives one number per row where it should give a row.

## Witness

```
W = ['Function', ['Block', ['Assign', 'q', 1],
                  ['Multiply', 'q', ['Divide', 'row', 'row']]], 'row']
M = ['List', ['List', 1, 2], ['List', 3, 4]]
ListFrom(ce.function('Map', [ce.box(W), ce.box(M)]))  ->  [1, 1]              typed vector<2>
ListFrom(ce.box(['Map', W, M]))                       ->  [[1, 1], [1, 1]]    typed matrix<2x2>
(probe 2026-11-07, HEAD 0117e657f929bfcd40364fa78a0e213084f70808, and with the CE-1037 fix)
```

## Cause and options

The body of a function boxed before the call reads `row` as a number, so
`row/row` is `1`. The CE-1037 fix canonicalizes such a literal again with the
row type only when `bindsAsInCurrentScope()` (`boxed-expression/box.ts`)
proves that each name binds the same way; a `Block` local or a nested literal
makes it return `false`. Options: (a) leave out of that test the names that
the body binds itself; (b) record the scope where the literal was boxed and
canonicalize the rebuilt literal there (see CE-1078).
