In the Tycho code editor, the popup of a call says what the function does but not what each argument is, nor which keys its options dictionary takes, and an empty argument shows only the parameter's name.

## Witness

On CE 0.201.5, a parameter of the signature help has a name, a type and a
range, and nothing else. A named-argument completion item has a label only:

```
library take(: [{"name":"xs","type":"T","range":[5,10]},{"name":"count","type":"number","range":[12,25]}]
source scale(: [{"name":"x","type":"real","range":[6,13]},{"name":"k","type":"real","range":[15,22]}]
named-argument items: [{"label":"k"}]
```

The keys of an options dictionary (`plot(series, {x -> (0, 1), grid -> false})`
in Tycho's drawing prelude) exist only in the prose of the description.

## Request

Documentation and a sample value for each parameter, and for each key of a
parameter that takes a dictionary of options.

### Where it is written

- A library definition: a field next to `description` and `examples`, keyed
  by parameter name, so that the overloads of one function share it:

  ```ts
  parameters: {
    count: { description: "The number of elements to keep.", sample: "2" },
    options: {
      description: "The options of the plot.",
      keys: {
        x: { type: "tuple<real, real>", description: "The x range.", sample: "(-5, 5)" },
      },
    },
  }
  ```

  A string value is the description alone (`count: "The number of elements to keep."`).

- A `///` comment: tag lines, which leave `description` and `documentation`
  and become the same structured data:

  ```
  /// A 2D plot of functions, curves, points or histograms.
  ///
  /// @param series one item or a list of items
  /// @param options the options of the plot
  /// @key options.x the x range
  /// @sample options.x (-5, 5)
  /// @sample count 2
  ```

### What the engine returns

- `EpsilSignatureParameter`: `documentation?: string` (Markdown), `sample?: string`,
  `keys?: { name: string; type?: string; documentation?: string; sample?: string; default?: string }[]`.
- `EpsilSignatureHelp`: `activeKey?: string`, the key at the offset when it
  is in a dictionary literal passed to a parameter with documented keys
  (on the key or in its value).
- Completion items: the named-argument items (`count: `) carry the
  parameter's `documentation` and `sample`. In such a dictionary literal, the
  keys not written yet are items (`color -> `), with their type, their
  documentation and a snippet whose field holds the sample
  (`color -> ${1:"crimson"}`). A key whose type is a union of string
  literals lets the value position offer those values.

### Rules

- The documentation is that of the declared parameter: a positional
  argument and a named argument (`f(n: ▮)`) resolve to the same parameter,
  as the active parameter already does. A rest parameter has one entry for
  all the arguments it takes; the parameter filled by `|>` or by the
  receiver keeps its own.
- A sample is Epsil source in the Epsil spelling (`[1, 2, 3]`, `x => x^2`,
  `"crimson"`), not MathJSON. The test suite checks that each sample of the
  library parses and is of its parameter's type.
- The call snippet keeps the parameter names as its fields
  (`take(${1:xs}, ${2:count})`): a name left in place is an unknown name, so
  the call fails visibly, while a sample left in place runs on made-up data.
  The host shows the sample as faint text in an empty field and inserts it
  only when the user accepts it. A key's snippet holds the sample, since the
  user picked that key.
- A sample is not part of the description: the popup does not show it.

## Cause and options

Not a defect: the definitions and the `///` comments have no place for
this today. Tycho's side, after a release: the signature hint shows the
active parameter's or key's line above the summary, the empty field shows
the sample, and `plot` and `plot3d` (now `hold function plot(...args)`,
one rest parameter) declare `series` and `options` if a `hold` function
admits named parameters.

## CE answer

CE (2026-11-25): P3 confirmed. Implemented with tycho-7a. The shape agreed with Tycho: `@key
options.x: <type> -- <doc>`, an empty snippet field (`${1}`) for a key with
no sample, and `plot` declared `hold function plot(series, options = {})`. A
held argument reads the names of the caller, also when they are `series` or
`options`; `test/compute-engine/epsil-parameter-docs.test.ts` pins it. Also
added at Tycho's request: `description` on each signature, and one element
per paragraph in the `description` of a `///` function. Not covered: a
dictionary after `|>` and a member call give no key items.
