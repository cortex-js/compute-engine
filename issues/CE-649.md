An asynchronous evaluation never finishes when a host function evaluates the expression that contains it.

## Witness

```
g: host operator, pure: true, evaluateAsync handler: await node.evaluateAsync(); return 5
node = Reverse(List(1, g()))
await node.evaluateAsync()  ->  never settles
node.evaluate()             ->  [5, 1]   (the synchronous route stops the recursion)
```

## Cause and options

A second caller of the same lazy node joins the walk in progress
(`_lazyValuePending`, `boxed-expression/boxed-function.ts`), so the call of the
handler waits for the walk that waits for the handler. Three fixes failed (an
evaluation-number test, a pending-handler test, a limit per node).

Question: how does the engine know that a nested call belongs to the walk it
would wait on?

- (a) Carry the evaluation context across `await` (`AsyncLocalStorage`, in
  Node.js only), then refuse that join.
- (b) Never join a walk for a caller that host code started; two concurrent
  evaluations of one node then each run its host code.

The entry recommends neither. If nothing is decided, the hang stays.

Full text: ROADMAP.md at commit 5784d4aec.

## Decision

User decision 2026-11-06: no code change: document that a host handler must not evaluate the expression that contains it (the asynchronous route then waits for itself), in the host-function reference and ARCHITECTURE.md.
