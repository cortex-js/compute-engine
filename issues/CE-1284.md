A shader whose formula reads a point defined by a deeply nested value freezes the page for seconds to minutes before it reports that the formula is too large.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.declare('P', 'list<tuple<number, number>> | tuple<number, number>');
ce.declare('a', 'real'); ce.assign('a', 0.5);
let u = ce.box('a');
for (let i = 0; i < n; i++) u = ce.function('Add', [u, ce.function('Sin', [u])]);
ce.assign('P', ce.function('Tuple', [u, 0]));
new GLSLTarget().compileShader({ type: 'fragment',
  inputs: [{ name: 'x', type: 'float' }], outputs: [{ name: 'o', type: 'float' }],
  body: [{ variable: 'o', expression: ce.parse('P.x') }], constantFold: false });
```

Measured on commit `40ba059a8444959fbcfb94fe393d1a540d423088`, on a loaded
machine:

| n | `compileShader()` | `compile(…, { to: 'glsl' })` |
| --- | --- | --- |
| 14 | about 340 ms, compiles | about 35 ms |
| 18 | about 220 ms, then "the GLSL code … more than 50,000 nodes" | about 10 ms |
| 20 | about 0.9 s, the same error | about 10 ms |
| 22 | about 3.4 s, the same error | about 10 ms |

The review measured 27 to 59 s at n = 24. Each level shares `u` twice, so the
tree has about 2ⁿ nodes written out and n + 1 distinct nodes.
Test: `test/compute-engine/ce-593-point-or-point-list-union.test.ts`.

The witness is `crafted` (a program built to reach the case), so the
probability is `low`; the impact is `critical` because the time doubles per
level and does not stop: at 30 levels it is hours.

## Cause and options

`compileShader()` walks the body as a tree, not as a graph of shared nodes,
before it checks the size: `compileShaderBody` → `typeDeclaredBody`
(`compilation/gpu-shader-target.ts`) → `typeFragment`, `walkPoint`
(`compilation/fragment.ts`) and `callerVector`
(`compilation/glsl-fragment.ts`). The size check
(`GPU_MAX_WRITTEN_NODES`, `gpu-written-size.ts`, checked in
`gpu-shader-target.ts`) runs after that walk. `compileToSource()` checks the
size first and is fast.

- (a) Run the size check (`gpuWrittenSize`) before `typeDeclaredBody`, as
  `compileToSource()` does. The shader declines in milliseconds. Size S.
- (b) Also memoize the walk per node, so that a shared tree under the limit
  costs its distinct nodes. Size M.

(a) removes the freeze; (b) only matters for a large shared tree below the
limit.
