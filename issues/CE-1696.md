A function that only passes its argument on to a function that takes a whole list gives the list back in place of the value.

## Witness

Checked 2026-11-21 at `bd665b2589a06ea525db58684981c4851640ac22` with the
CE-1692 fix in the worktree `wt-ce-5j-1692` (the fix does not touch this
path).

Document API, no stated types, two function rows given as JSON bodies:
`S(x) = Mean(x)`, `T(x) = S(x)`.

```
S: (x: collection<number> | value) -> number     S([1, 2, 6]) → 3
T: (x: unknown) -> number                        T([1, 2, 6]) → [1, 2, 6]
expected: T([1, 2, 6]) → 3
```

The call `T([1, 2, 6])` is typed `vector<3>`: the list is broadcast over the
`unknown` parameter `x`, and each element goes to `S` alone (`Mean(1) = 1`,
...).

Plain CE gives the same wrong value when `T` is declared first:

```
ce.declare('S', 'function'); ce.declare('T', 'function');
ce.assign('S', ['Function', ['Mean', 'x'], 'x']);
ce.assign('T', ['Function', ['S', 'x'], 'x']);
T([1, 2, 6]) → [1, 2, 6]
```

Without the two `declare` calls, `T` gets `(x: collection<number> | value)
-> number` and `T([1, 2, 6])` is `3`.

## Cause and options

Not investigated. The parameter of `T` is passed whole to `S`, whose
parameter admits a list, but `T` keeps `x: unknown`, and a call broadcasts a
list argument over an `unknown` parameter. The Document path
(`prepare-document.ts`, the inferred signature of a row that is not cyclic)
and `ce.assign` onto a declared `function` both miss the narrowing that a
bare `ce.assign` makes. Options: narrow a parameter that is passed whole to a
callee from the callee's parameter type in both paths, or do not broadcast a
list argument over an `unknown` parameter that the body passes whole.
