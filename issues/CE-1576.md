A dependency graph built from a Program's expression properties treats its own recursive function as an input and misses its output.

## Witness

```js
const ce = new ComputeEngine();
ce.assign('f', ce.box(['Function', ['Add', 'm', 10], 'm']));
const json = ['Program',
  ['Declare', 'f', "'unknown'",
    ['Function', ['If', ['LessEqual', 'm', 0], 1, ['f', ['Add', 'm', -1]]], 'm']],
  ['f', 2]];
const program = ce.box(json);
program.references; // ['f']
program.defines; // []
program.evaluate().json; // 1, using the function declared by the Program
```

Verified on `2752e60e9`. Raw and canonical expressions both report
`['f']` as a reference. This can make a notebook report an external
input for its own function and fail to connect its dependent cells.

## Cause and options

The expression-property walk recognizes Block statement bindings.
Program requires its own source-order rules for incoming reads and
caller-scope outputs. A host collecting dependencies from a Program
can inspect its statements until the expression properties cover them.
