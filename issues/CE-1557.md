A protocol declaration refuses a default value that names a constant declared earlier in the same program.

## Witness

`plausible`. With CE-1554, after
`const W = 2` and, in the same program,
`protocol P { function scaled(self: Self, k: real = W) -> real }`, the
protocol statement fails with `invalid-protocol-declaration`: "the default
value W of the parameter "k": a default value is a constant: write a number,
… a constant (a library constant or a symbol declared constant) …". When
`const W = 2` runs in an earlier program on the same engine, the declaration
is accepted.

The notebook case can silently keep an older default. First run
`const W = 9`. Then run the following on the same engine:

```epsil
const W = 2
protocol P { function scaled(self: Self, k: real = W) -> real }
type real is P {
  function scaled(self: real, k: real) -> real { self * k }
}
P.scaled(3)
```

The call returns `27` with no diagnostic, even though the second program's
`W` ends with value `2`. Under source-order constant defaults, the call
should return `6`.

## Cause

`Program` canonicalizes its `DeclareProtocol` statements first (rank 0 in
`canonicalSequence`, `src/compute-engine/library/control-structures.ts`),
before it collects declaration facts and reserves the new bindings. That
pass checks whether the default names a constant and boxes the default
operand. Both operations can therefore see a binding left by an earlier
program. Collecting the names first addresses admission, while boxing the
default must also wait for the new constant's binding. The initializer
still runs in source order.

Workaround: declare the constant in an earlier program (a prelude), use a
library constant, or use a symbol that the parameter type lists.
