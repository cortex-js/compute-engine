`Join` of lists declines on 0.194.0; 0.193.0 compiled it.

## Witness

`Join(L, M)` with `L: list<real>` = `[1, 2]` and `M: list<real>` = `[3]`.
Interpreter and 0.193.0 compiled: `[1, 2, 3]`. 0.194.0: "the operator Join
is not supported by the compiler".

Tycho meets it in recursive list functions of Desmos documents:
`rf(u) = Which(u = N - 1, [u], True, Join([u], rf(u + 1)))`.

## Expected

`Join` compiles on javascript.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1466: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, probed on 9d9931734 with `compile(…, { fallback: false })`): `Join(L, M)` declines as stated. P1, the table value (major,
high, plus `regression`). Disposition: proposed for the next release. No
workaround in compiled code; the recursive `rf` form also needs the
recursive user function to compile, which is checked with the fix.
