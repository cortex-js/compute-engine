A quotient of a numeric indexed collection by a scalar reports a
list type even when it returns a point.

## Witness

On `d683bc426`:

```ts
const ce = new ComputeEngine();
ce.declare('u_x', 'indexed_collection<number>');
const quotient = ce.box(['Divide', 'u_x', 5]);
console.log(String(quotient.type)); // list<number>
ce.assign('u_x', ['Tuple', 1, 2]);
const value = quotient.N();
console.log(value.json); // ['Tuple', 0.2, 0.4]
console.log(value.type.matches(quotient.type)); // false
```

Assigning `['List', 1, 2]` instead yields `['List', 0.2, 0.4]`.
A host uses the same declared input for both because both satisfy
`indexed_collection<number>`. A host that knows the representation
in advance can declare the corresponding tuple or list type.

The scalar contract matters too. Declare `u_y` as `number` and box
`['Divide', 'u_x', 'u_y']` before assigning `u_y = NaN`. With a list
numerator, `.N()` returns a list of NaNs. With a tuple numerator,
it returns scalar `NaN`.

## Cause and options

The shape-preserving quotient rule recognizes a statically known
tuple or shaped list. A numeric indexed collection reaches the
generic collection lift, which infers a list. The original
inversion `I_nversion(x)=x/C_mod(x)^2` exposes the discrepancy when
fixed Document preparation publishes that inferred result type.

An abstract indexed result can cover both representations when the
divisor contract excludes scalar `NaN`. A broader contract needs to
account for that result as well. The compiler can check the lowered
body against a truthful bound after settling the argument shape.
Mixed or unsettled shapes follow the existing compiler decline rules.
Check the corresponding numeric indexed cases in Multiply and Mod
when evaluating a shared solution.
