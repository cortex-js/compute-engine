A Voronoi diagram built from a function that returns a point no longer draws on the GPU.

## Witness

`x, y, n: real`; `P(a, b) := (1/n)·PointList(⌊a⌋, ⌊b⌋)`,
`Q(a, b) := 2·PointList(a, b)`, `R(a, b) := PointList(a, b)` (each body in a
`Block`). The engine types each call as a point and
`[F(x, y), F(x+1, y), F(x, y+1)]` as a list of three points. On glsl:

| expression | 0.193.0 | 0.194.2 |
| --- | --- | --- |
| `P(x, y)` | compiles | compiles |
| `[P(x, y), P(x+1, y), P(x, y+1)]` | compiles | declines: "program: list<list<real^2>^3>: a list of rank 2 on glsl" |
| the same list with `Q` | compiles | declines (same message) |
| the same list with `R` | compiles | declines (same message) |

The compiler reads the result of `PointList` of two scalars as a list of
points (rank 2), where the engine's type is one point. In Tycho, the Voronoi
rows of the test in `source-ref` lose their shader.

## Expected

The lists compile on glsl, as in 0.193.0: `PointList(a, b)` of two scalars
is one point.

## Instrument

`npx tsx scripts/repros/2026-11-19-ce1538-glsl-list-of-point-calls-probe.mts`
in Tycho. `CE-1538: READY` when the four expressions compile. READY on
0.193.0, NOT READY on 0.194.2.
