In Epsil, a factor of a product that is a call returning a string underlines the whole statement instead of the call.

## Witness

```
let w: any = ["a"]
let v = w[1] * Cos(x)
error frames  ->  none ("expected `number`, got `string` at `a`")
underline     ->  the whole statement `let v = w[1] * Cos(x)`
expected      ->  the frame `Multiply argument 1`, and the underline `w[1]`
```

The same for a term of a sum. `test/epsil/reordered-call-error-location.test.ts`
holds the current behavior.

## Cause and options

The handler of `Add` or `Multiply` makes the type error for the valid value
`"a"` of the operand. `_operandValueTypeError()`
(`boxed-expression/boxed-function.ts`) adds the frame only for a symbol
operand, whose value it reads from the binding. A call operand would have to
be evaluated again to compare its value. Option: the handler records which
canonical operand it evaluated to the value that the error names.
