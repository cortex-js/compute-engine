The full test suite fails at the commit of CE-1111, so a release cannot pass its checks.

## Witness

At `949ad8a3266435d8c7fd71844cbb69b88a10225a` (CE-1111):

```
timeout -k 30 600 npx jest -w 2 -t 'a guard assigns a parameter' -- test/compute-engine/compile-admission.test.ts
  Expected: 14
  Received: 8
```

At its parent `eab0bae02d94b3d1645e710b85d87d95f7316c2a` the same test
passes. The program is `Apply(p ↦ Block(r := [i for i in [1, 2, 3] if
Block(p := p + i, i > 1)], p + 0), 2)`.

The witness is `crafted` (a guard built to assign a parameter), but the test
fails in every full-suite run, so the probability is `high`.

## Cause and options

The expected value `14` is `2 + 2 × (1 + 2 + 3)`: the guard ran two times for
each element, one time for the count and one time for the elements. CE-1111
reads the count from the walk that the element memo keeps, so the guard runs
one time for each element, and the value is `8` (`2 + 1 + 2 + 3`). The new
value looks correct, and the test expectation is outdated.

Recommended: change the expected value in `compile-admission.test.ts` from
`14` to `8`, after a check that the guard of this program runs one time for
each element (the purpose of CE-1111). Size S.
