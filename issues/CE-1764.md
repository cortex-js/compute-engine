The LaTeX of a derivative of a function that is not declared, written without its arguments, reads back as a power or as a prime of the function.

## Witness

In a new engine for each line, with `f` not declared:

```
ce.box(["Derivative", "f", 4]).latex;            // f^{(4)}
ce.parse("f^{(4)}").json;                        // ["Power", "f", 4]
ce.box(["Derivative", "f", "k"]).latex;          // f^{(k)}
ce.parse("f^{(k)}").json;                        // ["Power", "f", "k"]
ce.box(["Derivative", "f", 2]).latex;            // f^{\doubleprime}
ce.parse("f^{\\doubleprime}").json;              // ["Prime", "f", 2]
```

The unapplied form comes only from MathJSON that a host writes by hand: the
parser gives `Prime(f, 4)` for `f''''`, and the derivative of an applied
function stays applied. The applied form, `f^{(4)}(x)`, reads back since
CE-1350.

## Cause and options

The Lagrange parselet in `definitions-core.ts` reads `f^{(n)}` with no
argument list as `Derivative` only when `f` is declared a function, and the
serializer of `Derivative` cannot see the type of `f`.

- (a) Leave it: the text is the usual notation, and a declared function reads
  back.
- (b) The serializer writes `\operatorname{Derivative}(f, 4)` for an unapplied
  derivative of a symbol, as it does for a negative order. This changes the
  text for a declared function too.
