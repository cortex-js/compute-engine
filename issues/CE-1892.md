GPU drawing code has to pass the pixel array and dimensions separately and calculate a flat index to read a pixel.

## Witness

The million-cell Life notebook uses a pure kernel taking
`(cells, x, y, width, height)`. The intended authoring form is:

```epsil
board.compute((x: integer, y: integer) => nextPixel(board, x, y))
```

`Raster` is a nominal tuple with integer `width` and `height` and
`pixels: array<Pixel>`. Its pure `get` method bounds-checks the coordinates
and reads `self.pixels[y * self.width + x + 1]`. A small witness on the
installed CE 0.202.0 returns `["Pixel",20,0,0,255]` in the interpreter.
With free integer coordinates and `constantFold: false`, the GLSL target
declines direct field access, `board.get(a, b)`, and a pure
`sample(board, a, b)` helper that calls the method. All three report
`outside-profile` on the captured Raster because its `pixels` field is an
array. The control with an explicit unbound `array<Pixel>` compiles to
`highp sampler2D` with `storage: { cells: "sampler2D" }` and reports
`cells_count` alongside the sampler.

## Requested contract

Let a host expose read-only fields of a captured raster-shaped value as
GLSL inputs when compiling a pure expression. Lower pixel reads through
direct access, a pure method, or a statically known pure helper. Report the
field path and shader binding metadata the host needs to bind the sampler,
cell count and dimensions. A mutable array's contents must stay a runtime
input, including when the raster binding is a constant. Rebinding the
sampler to the next generation must require no recompile at the same shape
and types.

Start with a record containing scalar fields and one supported machine-cell
array. Field-level input declarations or specialization before GLSL lowering
would both fit the request. Tycho owns texture allocation and presentation.
CE-1893 covers when CPU code needs to see pixels produced by a shader.
