GPU drawing code has to pass the pixel array and dimensions separately and calculate a flat index to read a pixel.

## Witness

The million-cell Life notebook uses a pure kernel taking
`(cells, x, y, width, height)`. The intended authoring form is:

```epsil
board.compute((x: integer, y: integer) => nextPixel(board, x, y))
```

`Raster` is a nominal tuple with integer `width` and `height` and
`pixels: array<Pixel>`. Its pure `get` method bounds-checks the coordinates
and reads `self.pixels[y * self.width + x + 1]`. A small witness on the
installed CE 0.202.0 returns `["Pixel",20,0,0,255]` in the interpreter.
With free integer coordinates and `constantFold: false`, the GLSL target
declines direct field access, `board.get(a, b)`, and a pure
`sample(board, a, b)` helper that calls the method. All three report
`outside-profile` on the captured Raster because its `pixels` field is an
array. The control with an explicit unbound `array<Pixel>` compiles to
`highp sampler2D` with `storage: { cells: "sampler2D" }` and reports
`cells_count` alongside the sampler.

## Requested contract

Let a host expose read-only fields of a captured raster-shaped value as
GLSL inputs when compiling a pure expression. Lower pixel reads through
direct access, a pure method, or a statically known pure helper. Report the
field path and shader binding metadata the host needs to bind the sampler,
cell count and dimensions. A mutable array's contents must stay a runtime
input, including when the raster binding is a constant. Rebinding the
sampler to the next generation must require no recompile at the same shape
and types.

Start with a record containing scalar fields and one supported machine-cell
array. Field-level input declarations or specialization before GLSL lowering
would both fit the request. Tycho owns texture allocation and presentation.
CE-1893 covers when CPU code needs to see pixels produced by a shader.

## Decision

User decision 2026-11-27: the host declares the raster as an input, and CE
lowers its fields to shader inputs. Not taken: CE substitutes a captured
raster value before GLSL lowering, which ties the shader to one raster.

The contract that the fix implements:

- **The input.** On `glsl`, a free name whose declared type is a nominal
  tuple whose fields are each a real or integer number, or a mutable array of
  machine cells (`type Raster = tuple<width: integer, height: integer,
  pixels: array<Pixel>>`), is an input of the program when it has no value,
  or when the `inputs` option names it (a name that holds a raster). Its
  value is never folded into the code: the array contents stay a run-time
  input, and so do the scalar fields.
- **The lowering.** Each scalar field is one uniform named
  `<name>_<field>` (`int` or `float`). Each array field is a sampler named
  `<name>_<field>` with its count uniform `<name>_<field>_count`, bound as
  for an array input (`docs/COMPILATION-MODEL.md`, "Arrays", "On GLSL").
  `storage: { "<name>.<field>": "sampler2D" }` selects the normalized
  texture for that array field.
- **The reads.** `board.width`, `board.pixels[i]`, `length(board.pixels)`,
  and the same through a user function or a protocol method whose parameter
  is of the type (`board.get(x, y)`, `sample(board, x, y)`), compile. A user
  function takes the fields as separate arguments, as it takes a sampler and
  its count for an array. A store, a field store, the whole value as a
  result, and an equality of two such values decline.
- **The report.** `freeSymbols` lists the name; `freeSymbolTypes.<name>`
  keeps the declared type and gives `fields`: for each field its uniform
  name and `lowered` type, and for an array field its `count` uniform.
- **Rebinding.** A new generation is a new binding of the same uniforms:
  no recompile at the same shape and types.
- JavaScript is unchanged: a captured raster already compiles there.

## Fix

On `glsl`, declare the raster with no value, or name it in `inputs` (a
constant too, as in the instrument). `board.width`, `board.pixels[i]`,
`board.get(x, y)` and `sample(board, x, y)` compile. Bind the uniforms that
`freeSymbolTypes.board.fields` names: `board_width` and `board_height` are
`float` uniforms (every integer input on GLSL is a float), `board_pixels` is
the sampler and `board_pixels_count` its `int` count. Use
`storage: { 'board.pixels': 'sampler2D' }` for a normalized `RGBA8` texture.
Every field is a uniform, read or not, in declared order. The form needs at
least one array field. A store, the whole raster as a result and `Equal` of
two rasters decline. A `vars` mapping does not rename a field uniform.
