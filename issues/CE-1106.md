A function that calls a function taken from a list is reported as having no effects, even when that function prints.

## Witness

```
npx tsx src/cli/epsil.ts check --effects --eval 'let fs = [() => print(1)]
function g() { fs[1]() }
function h() { let f = fs[1]; f() }'
```

On the tree of 2026-11-07 (HEAD `a6bed7cbf` plus the uncommitted CE-1093
change), this prints `g (line 2): pure` and `h (line 3): any`. The two
functions make the same call. `g` must not be `pure`: its effects are not known
(`any`), as for `h`.

Consequence seen: a `parallel for` whose pass calls `fs[1]()` is accepted, although
its rule allows only the `random` effect (`src/epsil/docs/control-flow.md`, the
rules of `parallel for`).

## Cause and options

The effect inference (`src/compute-engine/boxed-expression/effects-inference.ts`)
gives no effect to an `Apply` whose callee is an expression, neither a name nor a
function literal. The sound answer is `any` for such a callee, as for a callee
that is a local whose value is not known. This is not the decision that keeps
unannotated parameters optimistic (`docs/EFFECTS-MODEL.md`, decision (c)): the
callee here is not a parameter. Size S: one case in the inference, and a test.
