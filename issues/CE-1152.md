The definitions of the last scope that a host popped stay in memory until the host reads a type under another scope.

## Witness

A plain engine, with the garbage collector exposed:

```
ce.pushScope();
ce.assign('f', ce.box(['Function', ['Add', ['h', 'x'], 1], 'x']));
ce.popScope();
// yield to the event loop, then gc()
```

A heap snapshot then still holds the popped context, its scope, its
bindings and the definition of `f`. The retainer path is
`ComputeEngine._evalContextStack` as the key of a `WeakMap` whose value has a
`top` property that is the popped context. A later push, definition and pop
under another scope releases it; an empty push and pop, an evaluation or a
declaration in the global scope does not.

The retention is bounded: one scope, the last one popped. It is not a leak
that grows with the number of edits. It makes a test of CE-1102 wait for a
second push and pop before it can observe that a popped scope's definitions
were collected (`test/compute-engine/ce-1102-provisional-registry-weak-references.test.ts`,
`moveTypingMemo()`).

## Cause and options

`innermostFrameMemo` in `src/compute-engine/static-typing-view.ts` memoizes,
for each evaluation-context stack, the length of the stack, its innermost
context and the call frame found by the last scan of `innermostFrame()`. The
memo holds the innermost context strongly in its `top` field. After a pop,
the memo keeps the popped context until a later scan with another innermost
context replaces it.

Options:

- (a) Key the memo by the innermost context itself (`WeakMap<context,
  { length, frame }>`): a context is a new object at each push, so the
  validity test (same length, same innermost context) is the same, and the
  memo holds nothing after the context is unreachable. Size S, about ten
  lines. Recommended.
- (b) Hold `top` in a `WeakRef`. Same effect, but `deref()` on each type
  read adds the context to the kept-objects set of the job.
- (c) No change: one scope of retention.
