Solving an equation with no domain lists only the real solutions of an exponential or a nested periodic equation, and leaves out the complex ones.

## Witness

```js
ce.box(['Solve', ['Equal', ['Power', 'ExponentialE', 'x'], 2], 'x']).evaluate();
// ➔ [ln 2]; the solutions are ln 2 + 2πik for every integer k
ce.box(['Solve', ['Equal', ['Multiply', ['Subtract', 'x', 1],
  ['Add', ['Power', 'ExponentialE', 'x'], 1]], 0], 'x']).evaluate();
// ➔ [1]; it leaves out x = (2k + 1)πi
ce.box(['Solve', ['Equal', ['Sin', ['Sin', 'x']], 0], 'x']).evaluate();
// ➔ [πk]; sin x = kπ has complex roots for k ≠ 0
```

With no domain, `Solve` answers over the complex numbers where it can:
`Solve(x^2 + 1 = 0, x)` is `[i, -i]`, and `Solve(tan x = 1, x)` gives the
family `π/4 + πk` with an `ArbitraryInteger`. The fix of #526 (an empty answer
becomes no answer when a complex root was dropped) covers only `[]`; these
answers are non-empty and still incomplete.

## Cause and options

The inversion templates of `solve.ts` read an undeclared unknown as real: the
exponential gives the real logarithm only, and the periodic inversions keep
the real branch. The `complexRootRemoved` flag that #526 added records that a
root was dropped.

(a) With no domain, give the complex family where the template has one:
`ln c + 2πik` for `e^x = c`, with an `ArbitraryInteger`, as `tan x = 1` does.
(b) When the flag is set and the answer is not empty, return no answer, as #526
does for an empty one. Simple and sound, but `Solve(e^x = 2, x)` would stay
unevaluated, which many users would find worse than `[ln 2]`.
(c) Decide that, with no domain, a transcendental equation is solved over the
reals, and document it; then `[ln 2]` is right, and `Solve(sin x = 2, x)`
should give `[]` again, which reverses #526.

(a) is the consistent choice; it needs a decision because it changes answers
that users see today.
