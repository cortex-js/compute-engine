A notebook code cell shows the warning 'Unknown function "redraw"; did you mean "draw"?' for a function that the cell defines, and the cell runs correctly.

## Witness

CE 0.201.3, fresh engine, after `executeEpsil(ce, "function draw(x) { x }")`:

```
let redraw = () => 1
let f = () => redraw()
f()
```

gives the diagnostic `["unknown-function", "redraw", "draw"]`. The same with
`let f = (e) => do { redraw() }`. Controls, same engine setup: `redraw()` at the
top level gives no warning; `let repaint = () => 1` called the same way gives no
warning (no near library name); `let f = () => redraw()` with no `redraw` bound
warns, as it should. The value of the program is correct in each case.

The CHANGELOG entry for the statement scan says that "a `let` of a function in
a later statement" and names that the program binds are not reported. A call in
the body of another lambda does not get that exemption.

In Tycho, the drawing prelude defines `draw`, so every cell that defines a
`redraw` lambda and calls it from an event handler or a timer callback shows the
warning. Tycho's workaround: another name (`repaint`).

## Cause and options

The run scans the value of each statement for unknown calls without the names
that the program binds. The value of `let f = () => redraw()` is the lambda,
whose body is not evaluated, so the call of `redraw` (a value, with no operator
definition) was reported. The scan of a function literal in a value now uses
the names that the program binds, its parameters, and the callable bindings of
the engine, as the scan of the statement does.

## CE answer

CE (2026-11-25): P1 confirmed, fixed. The witness and its `do { }` form give no
warning; `let f = () => redraw()` with no `redraw` bound still warns. The
workaround (`repaint`) is no longer necessary after the release that holds the
fix.
