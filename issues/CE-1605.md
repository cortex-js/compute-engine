A timing test of the interval mode fails when the full test suite runs on a loaded machine, and passes alone.

## Witness

`test/compute-engine/ir-interval-contract.test.ts`, "the interval mode: the
size of conditionals › a chain of 1,000 Ifs and a triple nested sum compile in
under a second or decline", asserts that compiling a `Which` of 1,000 clauses
takes less than 1,000 ms. In the full suite on univac (WSL Linux, 16 cores,
12 Jest workers) it took 1,234 ms in one run and failed again in the
`ci-nightly.sh run --remote univac.local` run at `32a6d3ba1` (1 failed of
77,624 tests). Run alone (`remote-jest.mjs --workers 2` at the same commit),
the file passes: 136 of 136. On the Mac the full suite passes.

Workaround: the publish check runs a file that failed in the full run again
alone and continues when it passes (`scripts/prepublish-check.sh`,
`second_look`).

## Cause and options

The bound is a wall-clock time measured while 11 other workers load the
machine; univac's cores are slower than the Mac's. Options: (a) raise the
bound (for example 3,000 ms), which still catches the exponential growth the
test guards against; (b) measure a count of the work (nodes lowered) instead of
the time. (a) is one line.
