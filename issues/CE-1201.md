A function literal that the host holds keeps a wider type after a definition that its body read goes away.

## Witness

```
const L = ['Function', ['List', ['Negate', 'x'], 'z'], 'x'];
const lit = ce.box(L);
ce.pushScope(); ce.assign('z', ce.string('s')); ce.popScope();
lit.type          // (x: unknown) -> list<unknown>
ce.box(L).type    // (x: unknown) -> vector<2>
```

`ce.checkpoint()` and `ce.restore()` around the assignment give the same
result. A held `[x, z]` that is not a function literal is typed as a new
boxing is.

## Cause and options

The type of the literal is cached while `z` is a string, and the pop of the
scope does not make that cache entry invalid. The type is wider than the type
of a new boxing, not wrong for a value. Fix: the cached signature of a literal
depends on the definition that each free name of its body resolves to, as the
type of a compound expression does.
