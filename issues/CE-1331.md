A sum over a list of points, nested three levels deep, gives an
`incompatible-type` error where two levels give the number.

## Witness

`ce.assign('P', ce.box(['List', ['Tuple', 0, 0], ['Tuple', 3, 4]]))`:

| Program | `N()` |
| --- | --- |
| `Sum(Map(Function(Distance(q0, At(P, 1)), q0), P))` | `5` |
| `Sum(Map(Function(Sum(Map(Function(Distance(q0, q1), q1), P)), q0), P))` | `10` |
| `Sum(Map(Function(Sum(Map(Function(Sum(Map(Function(Distance(q0, q2), q2), P)), q1), P)), q0), P))` | `Error("incompatible-type")`, with three `Add` frames in its trace |
| the same three levels with `P := List(1, 4)` and `Abs(q0 - q2)` in place of `Distance(q0, q2)` (control) | `12` |

The right value of the third row is `20`: the inner double sum is `10` and
the middle index takes two values. The compiled code of the profile `ir`
gives `20`.

## Cause and options

Not investigated. The error appears at the third level only, and only for a
list of points: the same program over a list of numbers evaluates.
