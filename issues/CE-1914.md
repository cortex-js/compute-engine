On JavaScript, a value of a declared record type does not compile: a call of its constructor function declines as a call of a host function, and a dictionary literal with a `Nothing` field declines.

## Witness

On main `e13fc32df`, with `t: real`:

| Program | JavaScript |
| --- | --- |
| `type Fig = record{__tag: string, kind: string, geom: tuple<real, real>}`, `function Fig(kind: string, x: real, y: real) { {__tag -> "Figure", kind -> kind, geom -> (x, y)} }`, entry `Fig("dot", t, 0)` through `function useFig(t: real) { Fig("dot", t, 0) }` | declines: `a call of the function Fig of the host, of type Fig, not real, integer, boolean or nothing` |
| control: the same body with no declared type, `function fx(t: real) { {__tag -> "Figure", kind -> "dot", geom -> [t, 0]} }` | compiles to `{__tag: "Figure", kind: "dot", geom: [2, 0]}` |
| `function fn(t: real) { {__tag -> "Figure", kind -> "dot", geom -> [t, 0], alpha -> nothing} }` | declines: `"Nothing": Nothing as a value` |
| control: a named tuple field set to `Nothing` (`compile-records.test.ts`, `circle`) | compiles, the field is `null` |

The constructor function of a declared type is a program function, not a
host function, so the message names the wrong cause. A named tuple type
compiles (`compilation/ir/README.md`, "Records"), and its `Nothing` field is
`null`; a declared record type and a dictionary literal with an optional
field set to `Nothing` are the record forms of the same values.

Tycho asks whether its drawing prelude's `Figure` can be a record with a
`__tag` field instead of a named tuple. With these declines it cannot
compile.

## Workaround

Keep `Figure` a named tuple, or build the tagged dictionary in an operator's
`compile` handler (CE-1904).
