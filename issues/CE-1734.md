A compiled function cannot flatten a list of lists that it receives as input, so it runs in the interpreter.

## Witness

From the decline census on GitHub #638: 204 definitions of a combinatorics
corpus decline with this message, almost always through `Flatten` of a nested
input. On main 1cff4e3134779e0d2ba311a310ad26900c9119d2, JavaScript target:

```ts
ce.declare('L', 'list<list<integer>>');
compile(ce.box(['Length', ['Flatten', 'L']]), { fallback: false });
// Could not compile: L: L of type list<list<integer>> other than in an
// element read L[i][j] or as an argument of a parameter of that type
```

`fallback: true` gives the interpreter's value (the workaround).

## Cause and options

The `rows` lane (CE-1549, 4a5cea61192dc4b16deb61ff6f978e916dc027f2, 1e8503afdce6147b6c5d852e5ce366fc3edcf257) admits a `list<list<…>>` input
only where it is read row by row. `Flatten` of such an input reads the whole
input, which the lowering refuses. Lowering `Flatten(L)` of a rows input to a
concatenation of its rows (and `Length(Flatten(L))` to the sum of the row
lengths) would read the host's array in place, as the other row readers do.
