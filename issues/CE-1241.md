Since 0.187.0 a plot whose definitions read a variable that was not declared before them takes tens of seconds to draw; on 0.186.0 it drew at once.

## Witness

Installed CE 0.187.1; the same program on 0.187.0 and 0.186.0 from the npm packages. The definitions of the Tycho showcase entry `lagrange-points` are assigned in a scope while `m_e` has no declaration (`b = m_e/(m_e + 100)`, `omega = Sqrt(m_e + 100)`, and the functions `r_s`, `r_e`, `F_x`, `Omega` of `(x, y)` that read them). Then `x`, `y` and `m_e` are declared `real` in an inner scope and a row is compiled there with `{ to: 'javascript', mode: 'strict', broadcast: true }`:

| Row | 0.186.0 | 0.187.0 | 0.187.1 |
| --- | --- | --- | --- |
| `Omega(x, y)` | 34 ms | 141 ms | 63 ms |
| `Omega(x, y)^2` | 10 ms | 497 ms | 492 ms |
| `Mod(Omega(x, y), 10) - 5` | 8 ms | 5136 ms | 4492 ms |

Reading `.type` of the last row alone takes 399 ms on 0.187.1 (0 ms on 0.186.0). Control: with `ce.declare('m_e', 'real')` before the definitions, each compile takes 6 ms to 28 ms on 0.187.1.

One difference between the releases is visible before the compile: after the assignments, `ce.lookupDefinition('m_e')` is a value definition of type `number` on 0.186.0 and `undefined` on 0.187.0. In both, `b` and `omega` have the inferred type `number`.

The instrument prints the type and the compile time of four rows for both engines, and `CE-1241: READY` when every compile of the undeclared engine takes less than 250 ms.

## What it must give

The compile times of 0.186.0: tens of milliseconds, with or without the earlier declaration.

## Cause and options

Not investigated. Stack samples in the browser show the time inside the `type` getter of a function call, which reads `isFinite` / `isNaN` / `isNumber` of the operands and reaches `_unitType` and `_readsAsVariable`, with a call depth of 115 to 200 frames; nothing is cached between the reads. CE-1240 (walks without a memo) and CE-1210 (binding units slower) may share the cause.

## Tycho half on adoption

Tycho's thumbnail and preview harness declares the entry's variables `real` before the definitions (`scripts/previews/plot-entry.mjs`); the Graph Paper app already declares its variables first, so it is not affected. A host that sets `definitions` on a bare `<math-plot>` with an undeclared name is. On adoption: run the instrument; the harness declaration stays (it matches the app), and its comment loses the reference to this issue.
