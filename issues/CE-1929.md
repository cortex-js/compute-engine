An Epsil program reports a type error for a call that runs without an error and gives the expected list.

## Witness

At `13b23c071005b1115a2aaf9e71c67ce27bf84cff`:

```js
const r = executeEpsil(ce, 'let f = (p, x: real) => p[1] + x\nf([1, 2], [10, 20])');
r.diagnostics.map((d) => d.code);  // ["incompatible-type"]
r.value.toString();                 // "[11,21]"
```

The same call with `let f = (k, x: real) => k + x` (no parameter that binds
whole) gives no diagnostic.

## Cause and options

Not confirmed. `p` is typed `tuple<number>` by its use `p[1]`, so the
signature is not all-scalar, and the static check reports the list at `x`
against `real`, while the call maps over it (`pointListParamSlots`). The
static check of a `let` call (`src/epsil/diagnostic-flow.ts` or the pinned
route of `boxed-expression/box.ts`) must use the same per-slot plan as the
evaluation of the call.
