A deep zoom on an implicit curve such as `sin(x²)+sin(y²)=0` takes hundreds of milliseconds, because its cells are refined on the CPU.

## Witness

The instrument with `--cpu`, Tycho document C37 (`sin(x²)+sin(y²)=0`), CE
0.169.2: three zoom profiles give 314 to 344 ms of sampled CPU time to contour
extraction and 214 to 245 ms to refinement. This does not show interval
evaluation as the main cost.

## Request

Assess a conservative `interval-wgsl` target that keeps the cells, the
subdivision and the output buffers on the GPU, with no CPU readback per level:
feasibility, a minimal supported set (tri-state results for restrictions and
piecewise, the partial, singular, empty and entire kinds, endpoint and builtin
error bounds, an explicit decline), and the evidence required (containment
tests for poles, tangencies, isolated zeros, branch boundaries, subnormals and
overflow on each GPU backend). No rejection may rely on uncontrolled f32
rounding.

## CE answer

CE (2026-10-27): decision — not now. The survey profile does not show interval
evaluation as the main cost, and f32 bounds on `sin`/`cos` make the enclosures
wide. CE builds it when two items arrive: a profile where interval evaluation
is the main cost, and a measured prototype (hand-written WGSL for C37 and one
trigonometric lattice against `interval-js` on the workers). The soundness
contract for such a target is in
`docs/plans/2026-10-27-tycho-rows-461-463-gpu-design-answers.md`, "What a sound
f32 interval target needs".
