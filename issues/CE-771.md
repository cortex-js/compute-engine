The compiled function `(s ↦ Length(s))(t)` with a string `t` throws a `RangeError` instead of giving the length of the string.

## Witness

With `t: string`, `(s ↦ Length(s))(t)` compiles on JavaScript (`success: true`)
to `(((s) => (_SYS.elts(s, "Length")).length))(_.t)`. At `t = "abc"` it throws
`RangeError: Length: the operand is not a list or a set at run time`; the
interpreter gives 3. `Length(t)` alone compiles and runs. Checked at commit
`5784d4aec`.

## Cause and options

Not traced. The emitted code uses the collection form of `Length`
(`_SYS.elts`), so the parameter `s` probably does not get the string type of
its argument. Options: give the parameter the type of the argument at the call
(as the variant key of CE-712.2 does), so that `Length` uses the string form,
or decline when the type of the parameter is not known to be a collection.
