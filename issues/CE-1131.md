A function that reads a variable gives the value of another variable with the same name when it is declared or assigned as a function on residue classes inside a scope that declares that name again.

## Witness

```
ce.declare('k', 'integer'); ce.assign('k', 1)
f = ce.box(['Function', ['Multiply', 'k', 'x'], 'x'])
ce.pushScope(); ce.declare('k', 'integer'); ce.assign('k', 2)
ce.declare('g', { signature: '(residue) -> residue', evaluate: f })
g(ResidueClass(2, 5))                 ->  ResidueClass(4, 5)   (uses the inner k = 2)
ce.declare('h', '(residue) -> residue'); ce.assign('h', f)
h(ResidueClass(2, 5))                 ->  ResidueClass(4, 5)   (uses the inner k = 2)
Apply(f, ResidueClass(2, 5))          ->  ResidueClass(2, 5)   (uses the outer k = 1)
(probe 2026-11-07, with the CE-1078 fix applied to HEAD f9f11f57a2dbbab23ff23698709d4edfca714813)
```

## Cause and options

`kindTypedFunctionLiteral()` (`function-utils.ts`) rebuilds a literal boxed
before the declaration from its written form
(`writtenUntypedFunctionLiteral()`), so that a parameter typed with a value
kind keeps `x/x`. Its callers, the `ce.declare()` body
(`boxed-operator-definition.ts`) and `ce.assign()`
(`engine-declarations.ts`), canonicalize the rebuilt literal in the scope of
the declaration, so a free name of the body binds to the inner declaration.
Since CE-1078, `writtenUntypedFunctionLiteral()` also gives the scope where
the literal was boxed. Option: canonicalize the rebuilt body in that scope,
as `annotateCallbacksFromContextualSolve()` (`boxed-expression/box.ts`) does
for a callback. The declaration route makes its own scope for the
parameters, whose parent must then be the scope where the literal was boxed.
