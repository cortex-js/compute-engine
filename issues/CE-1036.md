The compiled call `f(t)` of a function `f := s ↦ Length(s)` with a string `t` throws a `RangeError` instead of giving the length of the string.

## Witness

With `t: string` and `f := s ↦ Length(s)`, `f(t)` compiles on JavaScript
(`success: true`) to `_fn_f(_.t)`. At `t = "abc"` it throws
`RangeError: Length: the operand is not a list or a set at run time`; the
interpreter gives 3. A declaration `f: (collection) -> integer` does too. Checked at commit `840d04c49275ed117f0dff18c14c8cff2c5e3f12`.

## Cause and options

The parameter `s` has the type `collection`, which admits a string, and the
compiled `Length` reads it with `_SYS.elts`, which refuses a string.
`ensureSpecializedUserCallEmitted()` in `compilation/compiler-core.ts` makes
no copy of `f` for a string argument. Option: make a copy with the parameter
typed `string` when the parameter type is a collection that admits a string,
as CE-771 does for an applied function literal
(`compilation/applied-literal-types.ts`).
