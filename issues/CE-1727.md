With the option that keeps the LaTeX of each part, some formulas are read
with a different meaning.

## Witness

`ce.latexSyntax.parse(latex, { preserveLatex: true })` with the `latex` and
`sym` keys removed is not the same as `ce.latexSyntax.parse(latex)` for 8 of
the 428 fragments of `docs/mathnet/parser-test-cases.json` (measured at
`207f1fec2368260193812106fa8dbdbc29c0316c`):

| LaTeX | `preserveLatex: true` | default |
| --- | --- | --- |
| `\log_{2} 3` | `Log(3, 2)` | `Lb(3)` |
| `\mathbb{R}^{+}` | `PseudoInverse(RealNumbers)` | `PositiveNumbers` |
| `\{a_n\}_{n=1}^{\infty}` | `Power(Subscript(Set(a_n), Equal(n, 1)), PositiveInfinity)` | `IndexedSequence(a_(n), n, 1, PositiveInfinity)` |

The `Lb` row has the same value; the two others do not.

## Cause and options

`decorate()` in `src/compute-engine/latex-syntax/parse.ts` wraps each parsed
node in an object (`{ latex, fn }`, `{ latex, sym }`) during the parse, when
`preserveLatex` is on. A parselet that tests its operand with
`Array.isArray()`, `typeof x === 'string'` or `operator()` on the raw shape
then does not recognize the wrapped node, and takes another reading.

Fix: decorate after the parse, from a side table of spans (the
`_exprSpans` mechanism that `onAmbiguity: 'error'` already uses), so the
parselets see the same nodes with and without the option. Or find and fix
each parselet that does not read a wrapped node. Size M.
