In Epsil, a protocol cannot have one conformance for lists of lists of strings and another for lists of lists of integers.

## Witness

```epsil
protocol Sizer { function sizeOf(self: Self) -> string }
type list<list<string>> is Sizer { … }
type list<list<integer>> is Sizer { … }
```

The second conformance gives `protocol-conformance-overlap` ("meet
`list<list<never>>`"). Run it with `executeEpsil()`
(`src/epsil/execute-epsil.ts`).

## Cause and options

The two types share `[[]]`, which is not empty, so the conformance check
(`engine-protocols.ts`) is correct under its rule. User decision 2026-10-23: a
value whose only shared elements are empty lists counts like the empty list.
Both conformances are accepted, and a call on such a value (`[[]]`) is
ambiguous at dispatch, as a call on `[]` is.
