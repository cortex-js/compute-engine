A compiled function declared to return a matrix can return rows of different lengths.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('M', 'matrix<real>');
ce.declare('clip', '(matrix<real>) -> matrix<real>');
ce.assign('clip', [
  'Function',
  ['Map', ['Function', ['Filter', 'r', ['Function', ['Greater', 'x', 2], 'x']], 'r'], 'm'],
  'm',
]);
const call = ce.expr(['clip', 'M']);
compile(call, { fallback: false }).run!({ M: [[1, 2, 3], [4, 5, 6]] });
// [[3], [4, 5, 6]], though call.type is matrix<real>
```

The compiler should decline the function with this declared result type
under R5 in `docs/COMPILATION-MODEL.md`. The host input is rectangular.

## Cause and options

The return check in `compilation/ir/lower-functions.ts` verifies the
element lane of a general list of rows without proving uniform width.
Require a width proof for a matrix result and continue to allow ragged
returns declared as a general list of rows.
