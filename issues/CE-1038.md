In the Epsil editor, a rename or a highlight of a variable also changes the variable of a `limit` that does not name its variable.

## Witness

```
let h = 5
limit(sin(h)/h, 0)
```

The program gives `1`: the engine binds `h` in the two-operand `Limit(f, a)`
(its description in `src/compute-engine/library/calculus.ts`). But
`binderSitesOf(ce, node, source)` (`src/epsil/resolve-library-names.ts`) gives
`[]` for `limit(sin(h)/h, 0)`, so `documentBindings()` puts the two `h` of the
limit in the group of `let h` (offsets 4, 20, 23). With `limit(sin(h)/h, h, 0)`
the groups are separate. `limit(sin(h)/h, 0, 1)` and `nLimit(sin(h)/h, 0)`
also give `[]`. Since CE-1013, a host that reads `binderSitesOf` from
`@cortex-js/compute-engine/epsil` gets the same wrong answer.

## Cause and options

`binderSitesOf` reads only the binding-site selector and the explicit-variable
rule. Add the implicit-variable rule of `Limit(f, a)`
(`canonicalImplicitLimitFunction()`) on the raw tree: the first, in sorted
order, of the symbols that `f` reads from outside. Size M: the tree is
unresolved there.
