Compiled `CosIntegral(x)` of a negative `x` gives the real number `Ci(|x|)`, where the value is `Ci(|x|) + iπ`.

## Witness

At `5fc85eda6`, `x` declared `real`, `k` declared `integer`,
`compile(ce.box(['CosIntegral', 'x']), { cse: false, constantFold: false })`
(the code is `_SYS.cosIntegral(_.x)`), in the `strict` mode:

| Point | Compiled | `evaluate().N()` |
| --- | --- | --- |
| `x = -2.5` | `0.2858711963653835` | `0.2858711963653835 + 3.141592653589793i` |
| `x = -0.5` | `-0.1777840788066129` | `-0.1777840788066129 + 3.141592653589793i` |
| `k = -3` (`CosIntegral(k)`) | `0.11962978600800032` | `0.11962978600800032 + 3.141592653589793i` |
| `x = 0.5` | `-0.1777840788066129` | the same |

`Ci(-x) = Ci(x) + iπ` for `x > 0` (Abramowitz and Stegun 5.2.20). The
strict mode has no complex value, so the compiled value should be `NaN`;
the result is a finite real number with no error. A plot of
`CosIntegral(x)` over `[-5, 5]` shows the mirror image of the positive
half where the real plot has no value. The `numeric-kernel` profile
declines `CosIntegral` of an operand that is not provably non-negative,
or that names a parameter, a local or an index ("… with the operand x,
which is not provably non-negative, is not in the profile").
The complex mode was not checked.

## Cause and options

The runtime helper `_SYS.cosIntegral` is `cosIntegral()` of
`numerics/exponential-integrals.ts`, whose comment says that it returns
the real part `Ci(|x|)` for `x < 0`; the compiler calls it as the value of
the head. No caveat in `docs/COMPILATION-MODEL.md` or issue records this.
Options: (a) in the strict mode, `NaN` for `x < 0`; in the
complex mode, the complex value `Ci(|x|) + iπ` (the existing compiler
writes the head as real-only, `REAL_ONLY_BY_DEFINITION` or a string
helper, so the complex mode needs the head out of that list); (b) a
known-limitations line. Recommended: (a). When it is fixed, remove
the `domain` of the `CosIntegral` entry of `REAL_CALL_HEADS` in
`javascript-fragment-target.ts`.
