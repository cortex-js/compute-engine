An integral whose upper bound ranges over an interval is reported as having
no value anywhere, when it has a value for part of that interval.

## Witness

At `bbc28d9ca`, with `x` declared `real`:

```ts
const e = ce.box(['Integrate', ['Function', ['Sqrt', 't'], 't'], ['Limits', 't', 0, 'x']]);
const r = compile(e, { to: 'interval-js' });
r.run({ x: { lo: -0.77, hi: 1.23 } }); // { kind: 'empty' }
r.run({ x: { lo: 0.5, hi: 1.23 } });   // an interval that holds 0.908…
e.subs({ x: 1.2289 }).N();             // 0.9082043073056002
```

`Integrate(Ln(t), Limits(t, 1, x))` over the same box gives `empty` too, and
the interpreter gives 0.0244 at `x = 1.2289`. `empty` says that no point of
the box has a value; a host that plots the integral against `x` drops the
part of the curve in a box that reaches below the domain of the integrand.

## Cause and options

`src/compute-engine/interval/integrate.ts` (`propagatedKind()` and
`bracket()`, not investigated further): the partition is made from the lower
ends of the bounds, and when a piece of it has no value (`Sqrt` or `Ln` of a
negative `t`), the result is `empty`, although the box of the bound also
covers ranges of integration where every piece has a value. The result should
be `partial` (a value where the integral is defined, with the clipped side),
or `entire`. The interval library is the runtime of the existing `interval-js`
target and of the interval mode of the IR pipeline, so both give `empty`. The
mode's test pins the two programs in `NOT_CONTAINED`
(`test/compute-engine/ir-interval-integrals.test.ts`): remove the entries
with the fix. Size S.
