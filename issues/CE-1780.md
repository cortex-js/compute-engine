The hypotenuse of a point written with `PointList` and a number is not known to be a real number, while the same point written as a tuple is.

## Witness

```ts
const ce = new ComputeEngine();
ce.box(['Hypot', ['Tuple', 3, 4], 12]).type.toString();     // real
ce.box(['Hypot', ['PointList', 3, 4], 12]).type.toString(); // number
```

Both evaluate to 13. Main at `7889e50f2ba8289162a4200a1d65a7bbb145f2a3` with
the CE-1767 fix; the `Hypot` check comes from
`c2124c9dd2a6f0b5275e40af6a50039a951f00bd` (in 0.201.1), so this is not a
regression. A host that reads whether the result is `real` (Tycho's GPU
domain proof) treats the hypotenuse as possibly complex.

## Cause and options

The scalar arm of the `Hypot` type handler
(`src/compute-engine/library/trigonometry.ts`) flattens a leg into its
components with its own test, `structureOf().kind === 'tuple'`, so a
`PointList` leg is kept whole and `euclideanNormType` widens to `number`.
`Norm` and `Abs` read the components with `pointLiteralComponents()`
(`library/utils.ts`), which also accepts a call of the library `PointList`
(CE-1767). Fix: use `pointLiteralComponents(o, context.engine)` in the
`Hypot` loop. Size S.
