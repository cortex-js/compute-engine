A formula made before the user defines a function with the same name gives the value of the user's function when it is evaluated with `evaluateAsync()`, or when its function is a host function with its own evaluation code.

## Witness

With the CE-1118 fix (session cebatch-1118, 2026-11-08):

```ts
const e = ce.box(['And', 'p', ['Not', 'q']]);   // the library And
ce.pushScope();
ce.assign('And', ce.box(['Function', 'False', 'a', 'b']));
e.evaluate().json            // ["Apply", ["Module", "And"], "p", ["Not", "q"]]: correct
const a = await e.evaluateAsync();
a.json                       // ["And", "p", ["Not", "q"]], bound to the user And
ce.popScope();
a.evaluate().json            // "False"; must be p ∧ ¬q

// A host function whose handler returns a call of its own name:
ce.pushScope();
ce.declare('G', { signature: '(value) -> value',
  evaluate: (ops, { engine }) => engine._fn('G', [...ops]) });
const g = ce.box(['G', 'x']);
ce.pushScope();
ce.declare('G', { signature: '(value) -> value',
  evaluate: (_, { engine }) => engine.number(42) });
g.evaluate()                 // G(x) bound to the inner G; evaluated again: 42
```

`crafted`: the program gives a new definition to the name of a function after
a formula that calls it was made, and evaluates the formula asynchronously, or
the function is a host function declared twice in nested scopes.

## Cause and options

An `evaluate` or `evaluateAsync` handler builds its unevaluated result by name
(`engine._fn('And', …)`), and a name boxed in the current scope is bound to the
definition that the scope gives it (`docs/SCOPING-MODEL.md`, "Callable
resolution"). CE-1118 runs the synchronous handler of a pure library call in a
scope that borrows the library binding (`BoxedFunction._inOwnBinding()`,
`boxed-function.ts`). That does not work for an `evaluateAsync` handler: the
scope is popped before the promise settles. It is not done for a host handler:
the pushed scope holds the declarations and assumptions that the handler makes,
and they are lost when it is popped.

Options: (a) after the handler returns (or its promise settles), rebind a
result that is a call of the same name bound to the definition that hides the
binding of the call (`_withSameBinding()`); the operand that a lazy handler
returns unchanged must be told apart from a rebuild. (b) Bind a call to a given
definition without a borrowed scope (CE-1109.5), and use it in the handlers.
