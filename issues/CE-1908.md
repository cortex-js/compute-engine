A function that reads an element of a list given as its argument does not compile when the list's length is known only when the program runs.

## Witness

Tycho's codegen audit of CE 0.204.1: 11 records in 2 documents
(`neyret/l49l5stdag` #12820 and 6 more, `neyret/digxkh3uk8` #9581 and 3 more).
Repros: `~/dev/tycho/_TASK/desmos/desmos-corpus/codegen-audit/repros-0.204.1/12820-l49l5stdag.mts`.

```js
ce.parse('m(M,i,j) \\coloneq M[i+3(j-1)]').evaluate();
// m: (M: dictionary<any> | indexed_collection<any>, i: unknown, j: unknown) -> unknown
ce.declare('A', 'list<real>');
compile(ce.parse('\\sum_{n=1}^3 m(A, 2, n)'), { to: 'javascript' });
// declines: "the parameter M of m is not a scalar (dictionary<any> | indexed_collection<any>)"
```

The same call compiles when `A` holds a list of a stated length
(`ce.assign('A', [1, …, 9])`). With `A = [1.5, 2, …, 9.25]` the interpreter
gives 15.

## Cause and options

`define()` in `ir/lower-functions.ts`: a parameter of a loose inferred type
takes the shape of the argument of the first call. It does so for a point, a
list of points, and a flat list of a stated length only. A flat list of a
run-time length fell through to `scalarOf()` and declined. Fix: on a target
with run-time lengths (`cx.runtimeLengths`: javascript and interval-js), the
parameter takes the list with a run-time length, as a declared `list<real>`
parameter does. Size S. The test of `ir-profile.test.ts` that pinned the
decline (`len(D)`) becomes a comparison with the interpreter.
