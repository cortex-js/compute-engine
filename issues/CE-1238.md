An element-wise selection whose list condition compares two lists of different lengths returns the last arm whole, where the interpreter gives a dimension error.

## Witness

At `99cee49c8` and at `984f3e660`, with `L: list<real>`, `M: list<real>`, compiled with
`compile()` (the default options, and `cse: false, constantFold: false`):

| Program | Arguments | Compiled code gives | The interpreter gives |
| --- | --- | --- | --- |
| `If(L > M, L, M)` | `L = [1, 4, 9]`, `M = [1, 2]` | `[1, 2]` | `incompatible-dimensions` ("2 vs 3") |
| `If(L > M, L, M)` | `L = []`, `M = [1]` | `[1]` | `incompatible-dimensions` ("1 vs 0") |
| `If(L > M, L, M)` | `L = [1, 2]`, `M = [3, 0]` | `[3, 2]` | `[3, 2]` (right) |

The emitted code is
`_SYS.select(() => (_SYS.bcast((_tv1, _tv2) => ((_tv1) < (_tv2)), M, L)), () => (L), () => (true), () => (M))`.

## Cause and options

`_SYS.bcast` gives the scalar `NaN` for two lists of different lengths
(`bcastWith()` in `javascript-runtime.ts`). `selectWith()` reads a condition
that is `NaN` as an absent condition and skips its clause, so the clause
`True` selects `M` whole: a list of a wrong length and wrong values, with no
error. The caveats of compiled code allow `NaN` (or a throw) where the
interpreter gives an error, not another finite list.

Option: in `selectWith()` (and in `_SYS.restrict`), read a condition that is
the scalar `NaN` as the error of a mismatch and return `NaN` for the whole
selection, as `bcastWith()` does. A scalar condition that is `NaN` comes only
from such a mismatch or from an absent value; the second keeps its current
reading if the compiler passes a flag for a condition whose static type is a
list. The structured route (`numeric-kernel` profile) declines lists of
unstated lengths in a selection, so it does not have this defect.
