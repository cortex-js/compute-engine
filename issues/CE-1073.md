Compiled loops run up to twice as slow as the same JavaScript written by hand, because each loop is wrapped in a function that is called at once.

## Witness

```
let s = 0
for k in 1..n { let a = 0
  for m in 1..20 { a = a + k * m; if a > 100 { break } }
  s = s + a }
s
```

To `javascript` on 0.182.0 each loop becomes `(() => {\nfor (…) {…}\n})()`.
With `n = 200000`: 0.89 ms as generated, 0.61 ms with only the loop wrappers
removed; same value. Tycho's Buddhabrot step (three nested loops, 5,000
samples): 2.0 ms against 1.0 ms. A likely cause, not checked with V8
tracing: locals written inside the closure stay in a heap context.

## Cause and options

`compile-loops.ts` wraps the counted loop (line 188) and the general loop
(line 216). A loop in statement position needs no value: emit a block.
Check `return` and `break` in the body. The study, with more measured ideas
(direct indexed access, `Fract` inlined): Tycho
`roadmap/BUDDHABROT_CODE_STUDY.md` § 5 and § 6.
