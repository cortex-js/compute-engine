Compiled loops run up to twice as slow as the same JavaScript written by hand, because each loop is wrapped in a function that is called at once.

## Witness

```
let s = 0
for k in 1..n { let a = 0
  for m in 1..20 { a = a + k * m; if a > 100 { break } }
  s = s + a }
s
```

To `javascript` on 0.182.0 each loop becomes `(() => {\nfor (…) {…}\n})()`.
With `n = 200000`: 0.89 ms as generated, 0.61 ms with only the loop wrappers
removed; same value. Tycho's Buddhabrot step (three nested loops, 5,000
samples): 2.0 ms against 1.0 ms. A likely cause, not checked with V8
tracing: locals written inside the closure stay in a heap context.

## Cause and options

`compile-loops.ts` wraps the counted loop (line 188) and the general loop
(line 216). A loop in statement position needs no value: emit a block.
Check `return` and `break` in the body. The study, with more measured ideas
(direct indexed access, `Fract` inlined): Tycho
`roadmap/BUDDHABROT_CODE_STUDY.md` § 5 and § 6.

Tycho half on adoption: run Tycho's Buddhabrot probe of 2026-11-07 that
times the generated step against WASM (generated-vs-wasm), and record the
new times in section 8.7 of the Buddhabrot code study and in ROADMAP row IB.

## CE answer

CE (2026-11-07): fixed in 0.183.0. On plain JavaScript, a `Loop` that is a statement of a block or of a loop
body is now the block `{ for (…) {…} }` (`loopSource()` in
`compile-loops.ts`, `discardedValueStatement()` in
`javascript-statements.ts`). An `if … else` statement of a block with a loop
in a branch is an `if` statement. A loop that is an operand, or that has a
`Return` in its body, keeps the arrow function. Measured from source, medians
of 50 calls against HEAD `efc01f9cd`: the Buddhabrot step (5,000 samples)
2.07–2.28 ms → 1.06–1.10 ms, same counts (total 901,405 after 60 calls); the
witness with `n = 200000` 0.88–0.96 ms → 0.70–0.71 ms. Test:
`test/compute-engine/ce-1073-loop-statement-form.test.ts`. Tycho can check
the fix with `scripts/repros/2026-11-07-buddhabrot-codegen-dump.mts` after it
adopts 0.183.0.
