An assignment to one element of a list that a field of an object holds gives the message "expected `symbol`, got `integer`", which does not say what is wrong or how to write the change.

## Witness

At commit `cc0809c8976820647672d97c41337982a320dc3a`, with
`npx tsx src/cli/epsil.ts <file>`:

```
type Screen = object{w: integer, px: list<integer>}
const s = Screen(w: 2, px: [0, 0, 0, 0])
s.px[2] = 9
```

The result is `Runtime error: expected `symbol`, got `integer` at `s.px[2]``.
The parser gives `Assign(At(Field(s, "px"), 2), 9)`. With `+=` in place of
`=` the program is refused before it runs, with the diagnostic
`add-to-target`.

`plausible`: `xs[2] = 9` works on a list variable, so a user writes the same
on a list field.

## Cause and options

Not investigated. A list is immutable, so the store has no meaning as
written; the documented diagnostic for a store on an immutable value is
`immutable-value-assignment` (`src/epsil/docs/protocols.md`). Option: give
that diagnostic, at the static check where the type of the field is known,
and name the remedy `s.px = replaceAt(s.px, 2, 9)`.
