A list of random numbers made with `Map` under a fixed seed is different at each run: the seed does not reach the numbers.

## Witness

```ts
const ce = new ComputeEngine();
const m = ['Map', ['Function', ['Random'], 'k'], ['Range', 1, 3]];
const r = ce.box(['WithRandomSeed', 3, m]).evaluate();
r.json; // ["Map", ["Function", ["Block", ["Random"]], "k"], ["Range", 1, 3]]
ce.function('ListFrom', [r]).evaluate().json;
// run 1: [0.9178…, 0.5885…, 0.7076…]
// run 2: [0.8472…, 0.6556…, 0.9857…]
ce.box(['WithRandomSeed', 3, ['ListFrom', m]]).evaluate().json;
// [0.4706…, 0.3638…, 0.7936…] at every run: the seeded draws
```

Run with `npx tsx` on `412113c86586a53784f1f91c2c7845255448d9f2`. A consumer
inside the frame (`ListFrom`, `Sum`: 1.6280… at every run) reads the seeded
draws. The frame's own result does not: `WithRandomSeed` returns the `Map`
unevaluated, and its elements are drawn when the host reads them, after the
frame has ended. The same holds for `Map(f, Repeat(Random(), 3))` under a
seed.

Seen with it, not diagnosed: `Repeat(Map(Function(Random(), k), Range(1, 3)), 2)`
gives two identical inner lists, although the inner `Map` is not pure (it
may be the caching of CE-657).

## Cause and options

Not read. A `Map` over a finite source stays a lazy collection when it is
evaluated, and `WithRandomSeed` returns the value of its body as it is.

- (a) `WithRandomSeed` materializes a lazy collection of finite length that
  its body returns, before the frame ends (as `ListFrom` does), so the
  result holds the seeded draws. An unbounded one stays lazy. Recommended:
  it is what the witness expects, and it changes nothing for a body that is
  not a lazy collection. Size S.
- (b) A lazy collection made inside the frame keeps the frame's generator
  and draws from it when read. It also covers an unbounded collection; it
  ties a value to a frame that has ended.
- (c) Document that the frame seeds only what is evaluated inside it.
