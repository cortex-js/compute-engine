An edit makes a function declared pure return random values.

## Witness

```js
const ce = new ComputeEngine();
ce.declare('h', '(number) -> number');
const assign = body =>
  ce.box(['Assign', 'h', ['Function', body, 'x']]).evaluate();
assign(['Multiply', 2, 'x']);
ce.declare('g', {
  signature: '(number) pure -> number',
  evaluate: ce.box(['Function', ['h', 'x'], 'x']),
});
const read = () => ce.box(['g', 3]).evaluate().toString();
console.log(read());                                    // 6
console.log(assign(['Add', 'x', ['Random']]).operator); // Function
console.log(read(), ce.lookupDefinition('g').operator.pure);
```

The last read gives a random number between 3 and 4. The purity flag is true.
This uses an explicit signature on the mutable helper, a plausible host
contract for an editable formula.

## Cause and options

The new effectful body is accepted through the declared callable slot. The
caller's checked effect contract is not revalidated or enforced at its next
use. CE-1463 covers the case in which the helper edit already reports a
refusal. This case needs a policy for validating the affected contracts at
replacement or checking the caller before evaluation.
