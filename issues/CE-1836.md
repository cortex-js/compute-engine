In the help of a library function, the code in the text of the description uses other names than the examples below it: the text says `Join([1, 2], 3)` where the example says `join([1, 2], [3, 4])`.

## Witness

The hover of `join` in an Epsil editor, on main with CE-1813:

```
description: … A scalar operand is appended as a single element too:
             `Join([1, 2], 3)` is `[1, 2, 3]`. … `Join` is the variadic
             string concatenation.
examples:    join([1, 2], [3, 4])   join("ab", "cd")
```

The reference pages (`src/epsil/docs/reference/`) show the same mix: the
generator spells the examples (`epsilSpelling`) but writes the description as
the definition does.

## Cause and options

The descriptions are written with the MathJSON names, and only the
`examples` field is converted to the Epsil spelling (CE-1813).

- (a) Convert each inline code span of a description when it is returned and
  when the reference page is generated: a span that parses as Epsil goes
  through `epsilSpelling()` (`src/epsil/example-spelling.ts`); a span that
  is a bare library name (`` `Join` ``) gets its spelling. A span that does
  not parse is left as written. Recommended: no edit of the definitions,
  and the MathJSON documentation keeps its names.
- (b) Rewrite the descriptions in the Epsil spelling. This touches several
  hundred strings, and the MathJSON names are right for a MathJSON reader.

Size M for (a): the span conversion, its cache, and a test over the library
that every converted span parses.
