The harmonic number of a very small number evaluates to zero instead of a small value.

## Witness

On main 2c7fbcede, `ce.function('HarmonicNumber', [ce.number(x)]).N()`:

| arguments | value | expected |
| --- | --- | --- |
| `1e-30` | `0` | `1.6449e-30` (ζ(2)·n) |
| `1e-30, 2` | `0` | `2.4041e-30` (2·ζ(3)·n) |
| `1e-30, -1` | `0` | `5e-31` (`n(n+1)/2`) |
| `1e-10` | `1.64493406673e-10` | right |
| `0.001` | `0.0016437…` | right |

The compiled GLSL value is right (`1.6449e-30`).

## Cause and options

The interpreter computes ψ(1 + n) + γ, and ζ(r) − ζ(r, 1 + n), at working
precision with no series for a small n, so the difference cancels to 0. The
JavaScript kernel and the GLSL helper use the Taylor series
n·Σ ζ(j+2)(−n)^j for |n| < 0.1: use the same series in the interpreter, and
for the two-operand form its analogue (leading term r·ζ(r+1)·n).
