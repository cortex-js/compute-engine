`Integrate` with a variable bound does not compile on glsl.

## Witness

`Integrate(Function(Sin(t), t), Limits(t, 0, x))` with `x: real`, target
glsl. 0.194.0: "the region integrate (a Map, a Filter or a Range) on
glsl". 0.193.0 declined it too ("outside the GLSL fragment"), so this is
not a regression.

Tycho rows that integrate up to the plot variable (`\int_0^x \sin t\,dt`)
draw on the CPU only.

## Expected

A fixed-step quadrature loop on glsl (ce-compiler: "GLSL has no
quadrature loop yet; medium").

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1467: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, probed on 9d9931734 with `compile(…, { fallback: false })`): declines on glsl as stated and compiles on javascript
(`0.45969769413186023` at `x = 1`, which is `1 - cos 1`). Not a regression.
P4, the table value (minor, medium, no flag). Disposition: pool. Workaround:
the CPU route (javascript), as today.

## Fix

CE (2026-11-23): a definite `Integrate` compiles on glsl as the closed form
that the engine gives at compile time, under the guards of the javascript
target. The witness gives `((-cos(x)) + 1.0)`. An integral with no closed
form (`∫₀ˣ e^(sin t) dt`), one whose closed form a guard refuses
(`∫₀ˣ cos(a·t) dt`, which divides by `a`), and every `NIntegrate` still
decline on glsl: it has no quadrature. Where the closed form is `NaN` (an
integrable singularity at a bound, `∫ₐ² ln t dt` at `a = 0`), glsl gives
`NaN`; javascript runs the quadrature there
(`docs/COMPILATION-MODEL.md`, known limitations).
