A debugger that follows the documented rule for "step over" skips the statements of an `if` branch or a loop body, although no function was called.

## Witness

`EpsilDebugStatement.depth` (`src/compute-engine/types-debug.ts`) is the
number of contexts on the stack, and its doc comment says to step over by
stopping at the next statement whose depth is the same or smaller. A block
pushes contexts as a call does. Measured on `executeEpsilAsync`:

```epsil
function f(n) {
  n + 1
}
let a = 1
if a > 0 {
  a = 2
}
for i in 1..2 {
  a += f(i)
}
a
```

| statement   | depth | `"call"` contexts on `ce.contextStack` |
| ----------- | ----- | -------------------------------------- |
| `if a > 0`  | 2     | 0                                      |
| `a = 2`     | 3     | 0                                      |
| `a += f(i)` | 4     | 0                                      |
| `n + 1`     | 5     | 1                                      |

Step over from `if a > 0` skips `a = 2`; a `for` body adds 2 to the depth
and a call only 1. The same rule is in the "Debugging" section of
`src/epsil/docs/implementation.md` and in step 5 of Tycho's
`docs/COMPUTE_ENGINE.md`. Workaround (what Tycho does, B2): count the
contexts named `"call"` in `ce.contextStack`.

## Cause and options

Add `callDepth` to `EpsilDebugStatement`: the number of `"call"` contexts on
the statement's stack (0 at the top level). Step over and step out compare
`callDepth`; `depth` stays for the scopes. Correct the three texts. Size S.
