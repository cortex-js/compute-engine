The quantile of a binomial or Poisson distribution at a decimal probability just above a jump of the CDF is one support point too low.

## Witness

On main `edf36b8056ed9f258edc4c6aee5345132da429e2`:

```ts
ce.box(['Quantile', ['BinomialDistribution', 1, ['Rational', 1, 2]], 0.5000000000001]).evaluate().toString();
// "0"  (right: 1, since CDF(0) = 1/2 < p); `.N()` gives 0 too
```

With the exact probability `1/2 + 10^-13` the result is 1 (the exact search of CE-1378). With `0.50000000001` the result is 1.

## Cause and options

`discreteQuantile()` in `src/compute-engine/numerics/distributions.ts` compares the float CDF with `p − 1e-12`, an absolute tolerance, so that `Quantile(CDF(k).N())` gives `k` back when the float CDF is a few ulps below the computed `p`. Every `p` within `1e-12` above a jump gets the lower support point. Since CE-1378, `evaluate()` with a float operand also takes this search (before, it stayed symbolic). Options: (a) a tolerance of a few ulps of `p` in place of `1e-12`, which keeps the round trip and narrows the band; (b) the exact search on the rational value of each double, with the float search only when the exact one gives no value, which loses the round trip for a float CDF value computed above the exact one.
