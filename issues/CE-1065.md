The Apollonian gasket example opens about 0.4 s slower since it computes its circles in a short program, and most of that time is the compile of the program's statements.

## Witness

Tycho compiles each top-level value statement of the prelude (32 statements,
`APOLLONIAN_GASKET_PRELUDE` in Tycho's
`src/graph-paper/onboarding/showcase-geometry.js`) with `compile()` to
`javascript`. On 0.182.0, third round on a new engine:

```
compile 162 ms, of which inside compile() 149 ms (32 calls); run 39 ms
const G_i = generations(circles, i, i)   15 to 16 ms each (6 statements), run 0.3 to 1.2 ms
const K_5 = [c[4] for c in G_5]          5.7 ms, run 0.2 ms
```

First round: compile 247 ms, 227 ms inside `compile()`. The six `G_i` calls
compile the same function `generations`; each costs about the same.

## Cause and options

The function body is cheap: `compile()` writes the value of `circles` (224
tuples), a name the statement only reads, into the code. Options, per tuple:

```
(a) isColorValued() runs its 4-level subtype test also for a type with no
    `color` in it: add a pre-test (halves the fold). Size S.
(b) tryConstantFold() evaluates a tuple of number literals and runs every
    gate of the fold: emit the code of the fold without them. (Skipping
    the fold changed the code: the CSE pass shared a repeated literal.)
(c) Tycho: pass a list that a statement reads as a typed input.

0.182.0, generations(circles, 3, 3): 13.6 ms; the fold of circles 11.3 ms;
circles declared as an input: 1.6 ms.
efc01f9cd with (a) and (b), the instrument, round 10: inside compile()
151 -> 78 ms; the same emitted code for the 32 statements.
```

## CE answer

CE (2026-11-07): cause found; fix (a) and (b) proposed for 0.183.0. Option (c)
is a workaround on Tycho's side.

CE (2026-11-07): fix (a) and (b) committed in `5a5ff5fb4`. Measured on a
build of `1fcc5402c`: the fold of `circles` 14.1 -> 6.0 ms, the compile of
`generations(circles, 3, 3)` 17.6 -> 8.9 ms; the emitted code of the 32
statements does not change. Option (c) would still save about 7 ms on each
`G_i` statement.
