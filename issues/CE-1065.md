The Apollonian gasket example opens about 0.4 s slower since it computes its circles in a short program, and most of that time is the compile of the program's statements.

## Witness

Tycho compiles each top-level value statement of the prelude (32 statements,
`APOLLONIAN_GASKET_PRELUDE` in Tycho's
`src/graph-paper/onboarding/showcase-geometry.js`) with `compile()` to
`javascript`. On 0.182.0, third round on a new engine:

```
compile 162 ms, of which inside compile() 149 ms (32 calls); run 39 ms
const G_i = generations(circles, i, i)   15 to 16 ms each (6 statements), run 0.3 to 1.2 ms
const K_5 = [c[4] for c in G_5]          5.7 ms, run 0.2 ms
```

First round: compile 247 ms, 227 ms inside `compile()`. The six `G_i` calls
compile the same function `generations`; each costs about the same.

## Cause and options

Not known. Ask: why a call of an already-defined function costs about 15 ms
to compile, and whether its compiled body can be reused across calls. An
author can write the values as literal lists (the example's form before
2026-11-07); Tycho chose the program form and keeps no workaround.
