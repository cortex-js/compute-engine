A compiled function that divides by a haversine gives a wrong number.

## Witness

At `c7adda0252d93f959847dcc1b52b19833b6a2ca7`, JavaScript target, default
options (the same with `cse: false, constantFold: false`):

```ts
const fn = ce.box(['Function', ['Divide', 2, ['Haversine', 'x']], 'x']);
compile(fn).code;   // (x) => 2 / (1 - Math.cos(x)) / 2
compile(fn).run(1); // 2.1753426496700214
```

The interpreter gives `8.701370598680086` for `2 / Haversine(1)`. The compiled
value is a quarter of it. `y / Haversine(x)` has the same defect. A product, a
negation and a power of the haversine give the right value, because the
missing parentheses do not change them. With `x` a free symbol and not a
parameter, the code is an immediately called function and the value is right.

## Cause and options

The `Haversine` handler of `javascript-target.ts` passes the template
`(1 - Math.cos(${x})) / 2` to `BaseCompiler.inlineExpression()`. When the code
of the operand is a bare name, the template is written with no parentheses
around it, and the division by the parent binds first. Option: write the
template as `((1 - Math.cos(${x})) / 2)`, and check the other templates of
`inlineExpression()` whose top level is a binary operation. The structured
route of the `numeric-kernel` profile declines a haversine in a position
where the existing emitter writes this code.
