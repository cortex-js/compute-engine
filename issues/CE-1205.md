In the complex compile mode, a local variable declared complex that holds a real number gives `NaN`.

## Witness

At `1652626570dcdbb481e5ec15f5ccd890ce1b4113`, JavaScript target, `x: real`:

```ts
const e = ce.box(['Block', ['Declare', 't', { str: 'complex' }, 'x'], ['Add', 't', 1]]);
compile(e, { mode: 'complex' }).code;
// (() => { let t = _.x; return ({ re: (t).re + 1, im: (t).im }) })()
compile(e, { mode: 'complex' }).run({ x: 3 }); // { re: NaN }
```

The interpreter gives `4`. In the `strict` mode the program declines and the
interpreter fallback gives `4`. With a write after the declaration
(`Assign(t, t + 1)`) the existing compiler lifts the local and gives
`{re: 4, im: 0}`, which is right. The `numeric-kernel` profile declines the
program in the `complex` mode.

## Cause and options

The local is stored as the number `_.x`, and the read treats it as a complex
object (`(t).re`). Option: convert the initial value to the declared lane at
the declaration (`_SYS.cplx(_.x)`), as the write does.
