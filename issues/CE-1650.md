A Node test whose assertion on an expression fails can use all the memory of the
machine.

## Witness

```js
const ce = new ComputeEngine();
ce.declare('A', 'real');
assert.equal(ce.box(['Add', 'A', 'x']), undefined); // no message
```

On `8ddfe3fee`, with `--max-old-space-size=768`, the call takes 994 ms and the
resident memory grows from 263 MB to 996 MB to build a message of 557
characters. `assert.deepStrictEqual(ce.box(['Add', 'A', 'x']), undefined)` does
not finish within 40 s. `util.inspect` of the same expression with the options
that `node:assert` uses (`customInspect: false`, `getters: true`) gives 2,389
characters at depth 1, 205,296 at depth 4 and 417,941 at depth 5; `node:assert`
uses depth 1000. With a message argument (`assert.equal(e, undefined, 'm')`) the
error is built at once, but a test runner that reports the error's `actual`
formats it the same way.

In a Tycho test worker the process passed 40 GB and the machine had a kernel
panic. The test was cx-threading "a self-referential macro publishes NO lambda",
which compared `box("A").value` (an `Error` expression) with `undefined`. Tycho
now guards its runner with a memory watchdog (Tycho main
`a0322846416e32802e7aec3c9c64817dc11e16e5`); any other Node consumer that
asserts on an expression is still exposed.

Probability `medium`: it needs a failing comparison whose actual value is a
boxed expression, in Node. The impact is a crash of the host machine.

## Cause and options

`customInspect: false` makes Node ignore `[util.inspect.custom]`, so the
formatter and the deep comparison walk every own enumerable property. A boxed
expression has about 60 own enumerable fields (`Object.keys` lists `engine`,
`_def`, `_localScope`, `_lazyValueScope`, `_freeHeadScope`, `_facetMemo`,
`_effectsDeps`, ...), and `engine` and the scope and definition fields reach the
whole engine: scopes, caches, dictionaries.

- (a) Make the fields that reach the engine, its scopes, definitions and caches
  non-enumerable (`#private` fields, or properties defined with
  `enumerable: false`), so that both the formatter and `deepStrictEqual` stay on
  the expression's own data. The readonly public `engine` becomes a prototype
  getter over a private field. This changes no public API. Cost: the boxed
  expression classes in `src/compute-engine/boxed-expression/`, hot code, so a
  benchmark check is needed (`#private` access and `defineProperty` in a
  constructor can be slower than plain fields).
- (b) Only `engine` non-enumerable: smaller, but the scope and definition fields
  still reach the engine.

Expected after the fix: the instrument's three modes finish at once, with a
small message, and the resident memory stays near its starting value.

## CE answer

CE (2026-11-21): filed at the table value P2 for the board. Tycho has a
workaround in its runner (the memory watchdog; compare `.json`, not an
expression). The instrument is a CE script; Tycho may name its own repro script
here.

## Fix

The fields of an expression that reach the engine, a scope, a definition or
an environment are now `#private`, behind accessors with the same names; so
are the engine field of the definitions and the fields of the read tokens
that cache entries keep. With the instrument, `equal` takes 1 ms (message of
557 characters) and `deep` 1 ms (2,585 characters), and the RSS stays near
257 MB. `test/compute-engine/expression-inspect-size.test.ts` holds it. An
expression can no longer be read through a `Proxy` (Vue `reactive()`): see
the CHANGELOG item. Measured cost: about 2% on
`benchmarks/scalar-arithmetic.mjs` (evaluate, source mode); no change
outside noise on `benchmarks/type-derivation.mjs`.
