`Arccot` of a real number and of a complex number next to it differ by π.

## Witness

On main at `fed2ad56317cc2a41f1124414bdc7c97d857d83a`:

```
ce.box(['Arccot', -3]).N()                       // 2.8198420991931510451 (range (0, π))
ce.box(['Arccot', ['Complex', -3, 1e-12]]).N()   // -0.3217505543966422 - 1e-13i
ce.box(['Arccot', ['Complex', -3, -1e-12]]).N()  // -0.3217505543966422 + 1e-13i
compile(ce.box(['Arccot', 'x'])).run({ x: -3 })  // 2.819842099193151
```

The probability is `medium`, not the `high` of a GitHub witness: it needs a
complex argument with a negative real part.

## Cause and options

The real kernel, the exact values and the limits at infinity use the range
(0, π) (`Arccot(-1) = 3π/4`, `Arccot(-∞) = π`, `library/trigonometry.ts`
near line 2138). The complex kernel is `arctan(1/z)`, the odd branch of DLMF
4.23.9, mpmath and Wolfram (`numeric-complex.ts` near line 806). The user
reference (`94-reference-trigonometry.md`) states no range.

- (a) Keep (0, π) and make the complex value `π/2 − arctan z`: continuous on
  the whole real line, cuts on the imaginary axis beyond ±i. Changes the
  complex kernel and the complex lanes of the compile targets; no real value
  changes. `Arccot(-3 + 1e-12 i)` becomes 2.8198… Recommended: fewer changes,
  and no real value a host reads today moves.
- (b) The odd branch everywhere: `Arccot(-3)` becomes -0.3217…, `Arccot(-1)`
  becomes `-π/4`, `Arccot(0)` stays π/2 with a jump there. Changes the real
  kernel, the exact table, the limits, the simplification rules and every
  compile target; a breaking change. Matches Wolfram and mpmath.

Either way, the reference page states the range.

## Decision

User decision 2026-11-15: (a)
