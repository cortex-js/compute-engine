The n-th root with a negative degree is wrong when the radicand and the degree are variables with values: 0 instead of infinity for a zero radicand, and wrong numbers for a very large or very small radicand.

## Witness

```ts
ce.declare('x', 'real');
ce.declare('n', 'integer');
const e = ce.box(['Root', 'x', 'n']);
ce.assign('x', 0);
ce.assign('n', -2);
e.evaluate(); // 0      (must be ~oo: 0^(-1/2))
e.N();        // +oo
e.subs({ x: 0, n: -2 }).evaluate(); // ~oo
ce.box(['Root', 0, -2]).evaluate(); // ~oo
```

The same with `ce.withValues({ x: 0, n: -2 }, () => e.evaluate())`.
`Power(x, Divide(1, n))` at the same values gives `~oo`.

At `ce.precision = 'machine'`, with `y: real` and the values given by
`ce.withValues`, `Root(x, y).evaluate().N()` is wrong for other radicands with
a negative degree too: at x = 1e300, y = -3 it gives `1.3333333333333502e-100`
(the literal `Root(1e300, -3)` gives `1e-100`), and at x = -1e-300, y = -3 a
non-finite value (must be `-1e100`).

## Cause and options

Not investigated: the `evaluate()` path of `Root` with a radicand and a degree
that are symbols with values returns 0 for a zero radicand without testing the
sign of the degree. Fix: give `~oo` for a zero radicand and a negative degree,
as the literal path does. The compiled code of the IR pipeline
(`compile(…, { profile: 'ir' })`) gives `+Infinity` here; its test skips the
point (`test/compute-engine/ir-slice-js.test.ts`, "the real functions at edge
inputs").
