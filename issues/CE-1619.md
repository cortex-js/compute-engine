The type of the incomplete gamma function `Gamma(s, z)` is `real` for a negative `z`, where its value is complex.

## Witness

At commit `4d9da3765bd5982bd8f48316d2d76171ca2c3554`:

```
ce.box(['Gamma', ['Rational', 1, 2], -1]).type             // real
ce.box(['Gamma', ['Rational', 1, 2], -1]).evaluate()       // Erfc(i) * sqrt(pi), about 1.77 − 2.93i
ce.declare('z', 'real');
ce.box(['Gamma', ['Rational', 1, 2], 'z']).type            // real
```

`Gamma(1/2, -1).N()` stays `Gamma(0.5, -1)`, so no numeric value contradicts the type today. The impact is `minor` for this reason: code that reads the type to prove that a value is real is wrong for this operand. The witness is `crafted`.

## Cause and options

`library/arithmetic.ts`, the `type` handler of `Gamma`: with two or three operands it calls `specialFunctionType()`, the generic claim, which is `real` when every operand is a finite real number. With two or three operands, `Gamma` is the incomplete gamma function, which is complex for `z < 0` when `s` is not a positive integer. The Bessel operators have a handler of their own for the same reason (the comment of the function after `specialFunctionType()`). Option: with two or three operands the result type is `real` only when `z` is known to be non-negative, and `number` otherwise.
