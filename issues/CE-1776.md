In a Graph Paper notebook, moving a ball-position update into a helper can make the animation run more slowly.

## Witness

Brick Rally calls a separate physics helper from its timer. A reduced program
on installed CE 0.201.2 and 0.201.3 uses one cell variable:

```epsil
let ballX: real = 0.5
function moveBall(dt: real) scope { ballX = ballX + dt; ballX }
let tick = (dt: real) => moveBall(dt)
[tick(2), tick(3), ballX]
```

The 0.201.2 MCP evaluator returns MathJSON `["List", 2.5, 5.5, 5.5]` with no
diagnostics. The instrument initializes the scope, then compiles the boxed
`tick` function alone to JavaScript with `fallback: false`, as a host does for
a stored callback. It declines on `Assign("ballX", Add("ballX", "dt"))` with
“a write to a name that is not a local”. A helper declared as a lambda gives
the same result.

The same update directly in `tick` compiles and reads `2.5, 5.5, 5.5`.
A pure helper that returns the next value, with the assignment in `tick`,
also compiles and gives those readings. Each case uses a fresh engine for
each execution path.

## Request

Consider extending the existing JavaScript root callback writeback for typed
scalar state to a statically resolved helper. The helper and callback must
observe the same cell binding in program order, and each invocation must read
the state left by the previous one. CE-1773 concerns effects when registering
a callback. This case begins after the callback and its helper are defined.

Workaround: accept interpreter fallback, or pass state to a pure helper and
assign its return value in the callback. The reduced witness isolates one
compiler limit and does not measure the speed of the whole game.

Tycho half on adoption: run this instrument. No production workaround to remove.
