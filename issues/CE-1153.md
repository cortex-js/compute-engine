A test of the weak-reference registry fails in a full test run on a loaded machine: it counts 64 waiting references where it expects 24.

## Witness

In a full `npm test` run (1949 suites, 12 workers, 2026-11-08, on a tree
whose only change was to `boxed-expression/serialize.ts`), the test
"CE-1102: the registry of waiting definitions holds weak references › a
registration sweeps the collected references of a name that is never read"
(`test/compute-engine/ce-1102-provisional-registry-weak-references.test.ts:158`)
failed:

```
expect(_provisionalReferenceCount(ce, 'h')).toBe(24)
Expected: 24
Received: 64
```

Run alone (`npx jest -w 1 -- <the file>`), the six tests of the file pass,
in the same tree and in the main tree at the same commit. The test does not
read the serializer. `witness: crafted`: the program is the test itself,
built to reach the sweep; `probability: low`: the failure needs the load of
a full run.

## Cause and options

The test registers 40 references to the name `h` from a scope that it then
pops, calls its `collect()` helper once (one garbage collection), and asserts
that the 40 references are still counted (line 151). It then registers 24
more; the comment at line 156 says that the 64th registration sweeps the 40
collected references, and the test expects 24 to remain (line 158). The sweep
removes only a reference whose target the garbage collector has reclaimed.
Under the load of twelve parallel workers, the one collection that
`collect()` runs can leave the 40 targets alive, so the sweep removes
nothing and the count is 64. A count that depends on when the collector
runs is not deterministic.

- (a) Make the test wait for the collection: after `collect()`, repeat the
  collection until a probe reference to one of the popped definitions is
  reclaimed, with a bound on the number of attempts, before the 24
  registrations.
- (b) Assert only what does not depend on timing: after the 24 registrations
  the count is 24 or 64, and a later read of `h` gives 24.
- (c) Mark the test as a timing test (`CE_PERF=1`), which runs serially.

Option (a) is the smallest change that keeps the check.
