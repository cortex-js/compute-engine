A compiled function whose one branch returns an empty list declines, even when the other branch says what the list holds.

## Witness

From the decline census on GitHub #638: 191 items of a combinatorics corpus
(mostly maps whose base case is an empty list). On main 1cff4e3134779e0d2ba311a310ad26900c9119d2, JavaScript
target:

```ts
ce.declare('n', 'integer');
compile(ce.box(['If', ['Less', 'n', 1], ['List'], ['Range', 1, 'n']]), {
  fallback: false,
});
// Could not compile: List(): an empty list
```

`fallback: true` gives the interpreter's value (the workaround). The same
message appears for `List()` as a typed `Apply` argument or a tuple part.

## Cause and options

`List()` has no element type of its own, so its lane is not settled. In an
`If` (or `Which`) whose other arm is a list with a settled element type, the
empty arm can take that element type: the shape is then settled at compile
time, as `docs/COMPILATION-MODEL.md` (R1 to R6) requires. The same applies to
a typed `Apply` parameter or a tuple part whose declared type gives the
element type.

A related census group (5 items, "Reduce from `List()`, whose element type
the body does not fix") is the same question for the initial value of a
`Reduce` or `Fold`: the element type comes from what the body joins to the
accumulator. Its repro, `Length(Fold((a, i) ↦ Join(a, [Range(1, i)]), List(),
Range(1, n)))`, also builds a list of rows of run-time length, so it needs
CE-1736 as well.
