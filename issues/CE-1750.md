In Epsil, when an operand of a sum is a block that reads a variable that holds an error, the error of the sum is underlined in the other operand.

## Witness

```
let w: any = "s"
let y = 2
let x = y + ln(w)
let v = { x } + ln(y)    ->  underlines y   ("in Ln argument 1, in Add argument 2")
let v = { x } - ln(y)    ->  underlines y   ("in Ln argument 1, in Subtract argument 2")
expected                 ->  the underline x, or the whole statement
```

The same at HEAD 68d081b73c9af3a0b0e6696ae29c8534df1f7049, where the second
message is `in Ln argument 1, in Negate argument 1, in Add argument 2`.

## Cause and options

The frames `Ln argument 1, Add argument 2` were recorded by the statement of
`x`. `rejectFramesOutsideScope()` (`src/epsil/error-location.ts`) matches the
frame `Add argument 2` to the sum of the statement, and the canonical operand
2 of that sum has the source range of `ln(y)`, so the check of the canonical
operand passes, and the `Ln` frame then selects the `y` of `ln(y)`. The block
records no frame, so the frames do not show that the error came from `x`.
Option: when the value that the error names is not the selected literal and
the selected argument has a call of the inner frame whose argument is a
symbol that holds no error, underline the whole statement.
