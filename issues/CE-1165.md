A test of the weak-reference registry of CE-1102 can fail in a full test run on a busy machine and pass when it runs alone.

## Witness

`test/compute-engine/ce-1102-provisional-registry-weak-references.test.ts`,
"the definitions of a discarded scope leave the registry", line 80:
`expect(_provisionalDependentCount(ce, 'h_0')).toBeLessThanOrEqual(1)`
received 2 in one full `npm test` run (load average about 28 on 18 cores at
the end of the run; 1 failure in 82,882 tests). The same file passed three
times out of three when it ran alone (`npx jest -w 1 -- <file>`), on the same
source. The source of that run changed only the evaluation of impure lazy
collection views (`boxed-function.ts`), which this test does not use.

## Cause and options

Not investigated. The test counts the definitions that wait on `h_0` after it
asks for a garbage collection. The count depends on when the collector frees
the definitions of the earlier passes, which a loaded machine can delay.
Options: (a) the test repeats the collection and the yield to the event loop
until the count is at most 1, with a bound on the number of tries; (b) the
test asserts a bound that does not depend on the timing of the collector.
