In Epsil, when a list reads a variable that holds an error, the underline can be on another element of the list that did not make the error.

## Witness

```
let w: any = "s"
let x = Ln(w) * 2
let u = 4
let v = [u*2, x]   ->  underlines u    ("in Ln argument 1, in Multiply argument 2")
[u+2, x]           ->  underlines u    ("in Ln argument 1, in Add argument 1")
expected           ->  the underline x, or the whole statement
```

Reproduced at `a053e9151322f5fb7677d58a1831cda292c0b012`. `u` is 4 and did not make the error.

## Cause and options

The frames `Ln argument 1, Multiply argument 2` were recorded in the
statement of `x`. The elements of a list record no frame, so no frame of the
statement selects the element `x`. `locateError()`
(`src/epsil/error-location.ts`) matches the frame `Multiply argument 2` by
operator name to the one written product of the statement, `u*2`, and the
canonical operand 2 of `2·u` is `u`. `rejectFramesOutsideScope()` does not
reject the frame: `isStatementValue()` also treats the elements of a list
written as a statement as the value of the statement, and in the `let` form
the frame is not tested at all, because no outer frame selected a scope.

Option: use a frame whose written call is not on a known route of the error
(the value of the statement, through `Declare`, `Dictionary`, `KeyValuePair`
and `Assign` only, or the argument that an outer frame selected) only when
the argument it selects can be the value that the error names. When that is
not known, underline the whole statement. `nodesAt()` in the same file
already lists the value of the statement in this way. Tests that pin a
narrow underline in a list can change.
