Some errors read only "incompatible type: " with nothing after it, and an unknown color name also prints a message straight to the console.

## Witness

Epsil CLI, main 3400041f5:

- `color("nosuchcolor")` prints `parseColor: unrecognized color "nosuchcolor"`
  on the console, outside the CLI's output, then
  `error: Runtime error: incompatible type: ` (with a trailing space).
- `unitConvert(quantity(2, h), min)` gives the same empty message.

A checked example in the cortexjs.io reference cannot match the trailing
space.

## Cause and options

The handlers answer `ce.error('incompatible-type')` with no operand, and the
message formatter writes the separator anyway; `parseColor` warns with
`console`. Fix: the formatter drops the separator when there is no detail;
the color and unit handlers give the expected and the actual types (or the
unknown name: "unknown color name `nosuchcolor`"); `parseColor` returns
the failure instead of writing to the console.
