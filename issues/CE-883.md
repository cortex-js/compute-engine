Computing each point of a list from a formula with complex numbers costs about 3 to 4 µs per operator, because a new expression is built for each point.

## Witness

Body of Tycho document `s8ishknvhe`, `L` a list of 2,000 points, machine
precision, `tsx` from source, per element (2026-11-07, commit
`74c7f8cf35b05d515fb6b2de1eba76b234c362b1` plus the CE-883 fix):

```
i PointY(L)                                        4.5 µs   List
PointX(L) + i PointY(L)                            6.8 µs   List
PointZ(L) / (PointX(L) + i PointY(L))             10.9 µs   lazy Map
Conjugate(PointZ(L) / (PointX(L) + i PointY(L)))  12.2 µs   lazy Map
Abs(PointX(L)), PointX(L) + PointY(L), PointZ(L)/PointX(L)  0.3-0.6 µs
```

## Cause and options

`machineBroadcast()` (`boxed-expression/machine-broadcast.ts`) computes
lists of real machine numbers on doubles. A list of complex numbers has no
store of doubles, so each complex cell is a boxed function.

Option: a complex kernel for `Multiply`, `Add`, `Divide` and `Conjugate`
that reads the real and imaginary doubles and boxes each result once. Its
values must equal the interpreter's complex arithmetic bit for bit, measured
on random operands.
