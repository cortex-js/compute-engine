A Desmos piecewise with a list branch and a number branch must give a list in every case, as Desmos does.

## Request

A library operator with the clauses of `Which` and the Desmos reading of
lists. The name and the form are CE's choice; the instrument expects a
builder `(...clauses) => [<name>, ...clauses]` in its `OPERATORS.piecewise`.

Why: as for CE-1320. Tycho now does this in an `evaluate` handler and a
`compile` handler that it attaches to `Which` for documents imported from
Desmos. The new compiler declines that definition. Example documents:
`art/khpocp8io0` (`C_heckvalid*`, the guard `{f(n)[1]=-1: 0, …}` only means
something because of the broadcast).

## Meaning

Scalar condition (D-232, Desmos API 2026-08-13):

| piecewise | at | result |
| --- | --- | --- |
| `{n<3:[1,2], -1}` | 5 | `[-1,-1]` |
| `{n<3:[1,2], n<5:[1,2,3,4], -1}` | 9 | `[-1,-1,-1,-1]`: the LAST list branch's length |
| `{n<3:[1,2,3,4], n<5:[1,2], -1}` | 9 | `[-1,-1]` |
| `{n<3:[1,2], n<10:-1}` | 5 | `[-1,-1]`: no default, still a broadcast |
| `{n<3:[1,2]}` | 5 | `[NaN,NaN]`: no branch taken |
| `{n<3:[], -1}` | 5 | `-1`: an empty list branch does not broadcast |

A list condition (D-293, Desmos API 2026-10-15): selects by position, a
scalar branch broadcasts, and the result has the length of the shortest list
among the condition and every list branch, taken or not:

| piecewise | result |
| --- | --- |
| `{[1,5,2]<3:[1,2], -1}` | `[1,-1]` |
| `{[1,4,9]>100:[1], [1,4,9]<5:[1,2,3,4], -1}` | `[1]` |
| `{[1,5]<3:[1,2]}` | `[1,NaN]` |

Desmos rejects a piecewise that mixes a point-list branch with a number
branch ("Every branch must have the same type"); the operator may do the
same. The length of a list branch must come from its type or its form, never
from evaluating a branch that is not taken (it can call `random`).

Expected: the interpreter and `javascript` give the tables above. GLSL: the
scalar-condition cases, where each list branch has a length known at compile
time; a decline is acceptable elsewhere.

## Today (0.190.0)

`{n<3:[1,2], -1}` at 5 is `-1` in the interpreter, and `compile()` declines
("its branches have different shapes"). `{[1,5,2]<3:[1,2], -1}` is
`Error("incompatible-dimensions", "3 vs 2")` at canonicalization (since
0.178.0). `{[1,5]<3:[1,2]}` already gives `[1,NaN]` on both routes.

## Can existing operators express it?

The scalar-condition cases: a host could rewrite each scalar branch `s` to
`Repeat(s, n)` where `n` is the length of the last list branch, when the
length is known when the tree is built. A length that only a value gives (a
document list of unknown length) has no such rewrite without evaluating the
branch. The list-condition cut is `Take` of each list to the shortest length.
If CE judges this rewrite sufficient for lengths known from the type, and
declines the rest, Tycho will do the rewrite and this request narrows to the
lengths that only a value gives.

## CE answer

CE (2026-11-14): P3 confirmed. Disposition: a rewrite for the lengths that a
type or a form gives, and no proposal yet for a length that only a value
gives; that part needs a decision of the board.

- Scalar condition, lengths known when the tree is built. Rewriting each
  scalar branch to a list of the length of the last list branch gives the
  table: `If(k < 3, [1, 2], [-1, -1])` at `k = 5` is `[-1, -1]` in the
  interpreter, with `profile: 'ir'` and with the existing compiler (probed at
  `08ef3106ecbce52e702f1f06451ebf3bb330c926`). A piecewise with no branch
  taken is the list of `NaN` of that length, which the host writes as the
  default branch. This is the form to use.
- List condition. The cut to the shortest list and the selection by position
  are the `Map` over `Range(1, n)` of CE-1321, with the `If` of the elements
  as its body. Not probed.
- A length that only a value gives (a branch that is a document list of
  unknown length, with a scalar branch). Compiled code settles every shape at
  compile time (`docs/COMPILATION-MODEL.md`, R1 to R6), so an `If` whose arms
  are a list of run-time length and a scalar declines on every compiler, with
  or without a new operator. An operator would serve the interpreter only.
  Options: (a) no operator: Tycho keeps this case on the interpreter with its
  own evaluation of the row; (b) a library operator `Which`-like with the
  Desmos broadcast, interpreter only, declined by the compilers. Recommended:
  (a), unless Tycho's corpus shows the case in rows that must be fast; say how
  many rows have it.

One point for the three issues: the new compiler declines a definition that
has a host `compile` handler or `compileHelpers`, and it does NOT see a host
`evaluate` handler. Once the `compile` handlers are removed, a row that Tycho
does not rewrite and that reads `At` or `Which` compiles with the stock
meaning, while Tycho's `evaluate` handler gives the Desmos meaning in the
interpreter. So the `evaluate` handlers must go with the `compile` handlers
(every Desmos row rewritten before it is evaluated or compiled), or Tycho
must not compile the rows it does not rewrite.

CE (2026-11-14): Tycho counted its corpus (the same audit): 17 sites in 4
documents have a list branch next to a scalar branch, and every list length
is known without a value: 15 from the type or a literal list, 2 from the
form (`e·Range(1, 400)`, whose type is `list<nan | real>` with no
dimension). No site has a length that only a value gives, so option (a), no
operator, is taken. For the 2 sites: read the length from the form on the
Tycho side (a `Range` of literal bounds, also under an element-wise
operation). A dimension in the type of such a `Range` is a change of type
inference; file it as its own request if reading the form is not enough.
Closed with no change in the engine.
