Calling `slice` with its start and end given by name fails with an error, although the same call with positional arguments works.

## Witness

On main `976027da1`, `new ComputeEngine()`, Epsil:

```
slice([1, 2, 3, 4, 5], 2, 4)              // [2, 3, 4]
slice([1, 2, 3, 4, 5], start: 2, end: 4)  // Slice(Error("unexpected-argument", "[1,2,3,4,5]"), 2, 4)
take([1, 2, 3], count: 2)                 // [1, 2]: a signature with one arm works
```

The signature of `Slice` is an overload set of four arms:
`(value: T, span: range)` and `(value: T, start: number, end: number)` for
`T: string`, and the same two for `indexed_collection<T>`.

## Cause and options

`src/epsil/docs/syntax.md` ("When a function has several clauses or
overloads, a named argument is also a branch selector") says that the arms
that declare the written names survive and are selected as for a positional
call: here the two `start`/`end` arms, which read the names in the same
order, then the value selects the collection arm. The normalization of named
arguments (`normalizeNamedArguments()`, `boxed-expression/box.ts`) does not
reach that result for a library overload set. Find where it drops the call,
and select the surviving arms as the document says. Workaround: call
positionally.
