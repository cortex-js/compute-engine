A heatmap that uses gcd or lcm of slider-based values draws on the CPU, not the GPU, so it is slow to redraw.

## Witness

The showcase prototype colours the multiplication table mod n with
`gcd(mod(⌊nx⌋⌊ny⌋, n), n)`, where `x`, `y` and the slider `n` are `real`.
On 0.194.3 the GLSL target declines it: "GCD (the operation rgcd) on glsl".
`GCD(x, y)` and `LCM(x, y)` with real `x`, `y` decline the same way (`rlcm`).
Controls: `GCD(floor(x), floor(y))` and `LCM(floor(x), floor(y))` compile to
GLSL (`_gpu_ir_gcd`), and `GCD(x, y)` with real operands compiles to
JavaScript and gives 6 at (12, 18).

## Cause and options

The GLSL target has the integer kernel but not the real-operand one that the
JavaScript target uses (there, `GCD(12.5, 18)` gives 0.5). Option: a GLSL
`rgcd`/`rlcm` with the semantics of the JavaScript kernel; for integer
values it is the integer loop. Size S.
