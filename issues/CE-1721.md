A notebook animation whose timer callback updates a grid (a list of lists, as in the Game of Life) still runs interpreted, so it cannot reach a usable tick rate.

## Witness

CE-1662 made a callback that assigns a list of numbers compile. A grid
still declines. In Epsil:

```
let n = 8
let g = map(i => map(j => Mod(i + j, 2), Range(1, n)), Range(1, n))
count(g: list, i: integer, j: integer) = g[i][j]
step(g: list) = map(i => map(j => 1 - count(g, i, j), Range(1, n)), Range(1, n))
let tick = (t: real) => do { g = step(g) }
```

`compile(ce.box('tick').evaluate(), { to: 'javascript' })` declines with
"an assignment of g, of type list<list<number>>". The Game of Life of § 1 of
Tycho's animation spec has this form.

## Cause and options

Three gaps, each one alone declines the Game of Life:

1. `assignedNames()` of `lower.ts` accepts a list of a run-time length of
   reals, integers or booleans (`Assigned.list`), not a list of lists: the
   state would need a binding written whole whose two lengths can change
   (`wholeLocal()` keeps every length after the first).
2. `let g = map(…)` declares `g` as `list<list<number>>`. A list of lists of
   `number` is not an input type (`rowsElementLane()` takes only `integer`
   or `real` elements), so `(g: list<list<number>>) => g[2][3]` declines too.
3. A parameter typed `list` (`step(g: list)`) takes no list of lists in
   compiled code: CE-1607 compiles `step(g: list<list<integer>>)` only.

Option: a state of the lane `rows` (the input form of CE-1607) bound to the
parameter, whose writes give a rank-2 list; a branch or a loop that writes it
declines; the write-back makes a `List` of `List`s. Gaps 2 and 3 need the
element type `number` read as `real` (as `inputType()` does for a list of
`number`) and a bare `list` parameter read as the type of its argument.
Size L. Workaround: interpret the callback (Tycho's phase 1).
