`ND(Sin, 1)`, the numeric derivative of a function given by its name, stays unevaluated, also under `N`.

## Witness

`ce.box(['ND', 'Sin', 1]).N()` gives `["ND", "Sin", 1]` on main (a28dd290f)
and 0.186.0; Epsil `nd(sin, 1)` the same. `ND(Sin(x), 1)` gives
0.5403023058595877. The old reference page showed 0.5403… for the bare-name
form. Workaround: write the call `sin(x)`.

## Cause and options

Option (a): `ND` accepts a function value (a name or a function literal) and
applies it, as `NIntegrate` and `D` do. Option (b): the signature or the
reference entry says that an expression is required, and the bare name gives a
type error. (a) is the expected behavior for a function-valued operand.

## Decision

User decision 2026-11-16: (a)
