An expression written while a variable holds 4 gives a wrong number after the variable is set to 0.5 or to a negative number.

## Witness

Run on main at `ccd2f604697ac643c7a052389a921d353e066abb` (0.188.1 and three commits).

```
ce.declare('x', 'real');
ce.assign('k', 4);                       // the type of k is inferred: integer
const e = ce.parse('(x^2)^k');           // boxed as ["Power", "x", ["Multiply", 2, "k"]]
ce.assign('k', 0.5);                     // the type of k is now real
ce.assign('x', -3);
e.evaluate()                             // -3; (x^2)^k is 3
ce.parse('(x^2)^k').evaluate()           // 3: a second parse is ["Power", ["Power", "x", 2], "k"]
```

The same with a function definition, which a host keeps while a value changes:

```
ce.assign('k', 4);
ce.parse('f(x) := (x^2)^k').evaluate();
ce.assign('k', 0.5);
ce.parse('f(-3)').evaluate()             // -3; 3 is right
```

And with the sign of a value:

```
ce.assign('p', 2);
const e = ce.parse('(p^2)^{1/2}');       // boxed as "p"
ce.assign('p', -2);
e.evaluate()                             // -2; 2 is right
```

Compiled code has the same value, because it compiles the boxed form:
`compile(e, { vars: { k: '_.k' } }).run({ x: -3, k: 0.5 })` is -3. With `k`
declared `integer` and compiled with `inputs: { k: 'real' }` the result is
also -3, but there the host gave a wider type than the declared one, which
`docs/COMPILATION-MODEL.md` documents as outside the contract of `inputs`.

## Who reaches it

Measured by session `tycho-desk` on 0.188.1, 2026-11-13. Tycho's documents
do not reach it: a Graph Paper document declares its sliders and values
with a type before it boxes a row (`k` and `p` have the declared type
`nan | real | signed_infinity`), and the `<math-plot>` element declares
each value name `unknown` before it assigns the value. A host that assigns
a name with no declaration does: with `ce.assign('k', 4)` on a bare engine,
Tycho's `compileToPlotFunction` of the row `(x^2)^k`, and of `f(x)` with
`f(x) := (x^2)^k`, gives 6561 at `x = -3`, and -3 after the value record is
set to `k = 0.5` with no new compile (3 is right). Tycho keeps the boxed row
and the compiled code while a slider moves. With `k` declared `real` or
`real<0..5>` before the assignment, the result is 3. There is no corpus
witness.

## Cause and options

`canonicalPower` (`src/compute-engine/boxed-expression/arithmetic-power.ts`,
"(a^n)^m -> a^{n*m} only when mathematically safe") folds when
`b.isInteger === true` or `base.isNonNegative === true`. For a variable that
is not a constant and has no declared type, both facts come from the value
it holds at boxing: the inferred type `integer`, and the sign of the value.
A later assignment widens the inferred type, and the canonical form that was
made before stays. The other rewrites of the same file that read
`isInteger`, `isNonNegative` or `isNegative` of an operand (the `Divide`
case below it, among others) were not examined.

Options:

1. A canonical rewrite reads only a fact that an assignment cannot change:
   a declared type, a constant, a literal. This is decision D16 of
   `docs/plans/2026-11-11-bound-once-spec.md` ("a static type does not
   depend on a value") applied to the facts that canonicalization reads. An
   expression with an undeclared `k` then keeps `(x^2)^k`, and
   `(p^2)^{1/2}` with an undeclared `p` keeps its form (`Sqrt(p^2)`, which
   evaluates to 2 for `p = -2`).
2. An assignment that widens an inferred type is refused (the first value
   fixes the type). Today the type of `k` goes from `integer` to `real` at
   the second assignment (the probe above); hosts assign values of several
   types to one name, so this is a decision of the user.

Option 1 is recommended. Its cost was not measured: the count of tests and
snapshots that hold a form folded from an inferred fact.
