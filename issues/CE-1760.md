In a scope where the user defines a function named `Divide`, the power `y^{-1}` of a variable becomes a call of the user's function, and gives a wrong value.

## Witness

At commit `4c48f278c49bb3a07c9433c64062b79dff96e457`:

```ts
ce.pushScope();
ce.declare('Divide', 'function');
ce.assign('Divide', ce.expr(['Function', 1000, 'u', 'v']));
const e = ce.expr(['Power', 'y', -1]);
e.json                          // ["Divide", 1, "y"], bound to the user Divide
e.subs({ y: 4 }).evaluate()     // 1000; must be 1/4
ce.popScope();
```

`crafted`: the program defines a user function with the capitalized name of
a library function and takes a reciprocal in its scope.

## Cause and options

`BoxedSymbol.inv()` (`boxed-symbol.ts`) builds `Divide(1, y)` by name with
`ce._fn()`, so in a scope with a user `Divide` the result is a call of the
user function. The CE-1133 fix builds the reciprocal of `BoxedFunction.inv()`
with `ce._libraryCall('Divide', …)` when the scope shadows `Divide`
(`shadowsLibraryName()`); do the same in `BoxedSymbol.inv()`, and check the
other `ce._fn('Divide', …)` builds of the arithmetic code. The `(a^b)^c`
branch of `pow()` (`arithmetic-power.ts`) also reads a call by the name
`Power` with no `isLibraryOperator()` test. Related: CE-1759
(`Power` built by name in a product), CE-1114.
