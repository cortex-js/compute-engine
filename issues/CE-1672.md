A block or a function with a local that holds a dictionary, whose result is not decided yet, gives a result that names the local, which has no value after the block.

## Witness

Run on main at `4e937c458e6b7bb0fd001fd2e600e0082161be65`, with `C` declared
`boolean` and no value:

```js
ce.box(['Block',
  ['Declare', 'd', "'unknown'", ['Dictionary', ['KeyValuePair', "'a'", 3]]],
  ['Declare', 'r', "'unknown'", ['Hold', ['Pair', 'd', 1]]],
  'r']).evaluate();            // Hold((d, 1))
```

The same program with `['List', 3]` in place of the dictionary gives
`Hold(([3], 1))`. With the fix of CE-1330, the value of a block names the
values of its locals: `Block(Declare(d, {a: 3}), If(C, At(d, "a") + 1, 0))`
gives `If(C, At(d, "a") + 1, 0)`, and once `C` is `True` it gives
`Error(read-before-initialization, d)`; with a list local it gives the value.

## Cause and options

`snapshotRunVariables` (`src/compute-engine/function-utils.ts`) replaces an
occurrence of a local with the value of the local. For a local that holds a
dictionary, the occurrence stays: the cause is not found yet (`runValue` or
`current` in that function reads no value for it). The stored value of an
`Assign` or a `Declare` and the value of a block or a call (CE-1330) both go
through this function. The fix is to find why the dictionary value is not
read, and to give it as for a list.
