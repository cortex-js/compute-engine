`limit(f, NaN)` in `numerics/numeric.ts` overflows the call stack, so a compiled `Limit` at a point that is `NaN` throws a `RangeError`.

## Witness

At `edf0c42631a479230ffbb04bcd33d745725ceeed`, with `L` declared
`list<real>` and `n` declared `integer`:

```js
const e = ce.box(['Limit', ['Function', ['Exp', 't'], 't'], ['At', 'L', 'n']]);
const f = compile(e); // also with { cse: false, constantFold: false }, and with the profile
f.code;  // _SYS.limit(((t) => Math.exp(t)), _SYS.atNumeric(_.L, _.n, "real"))
f.run({ L: [1, 2], n: 5 }); // throws RangeError: Maximum call stack size exceeded
limit(Math.exp, NaN);       // throws the same RangeError
e.subs({ L: ce.box(['List', 1, 2]), n: 5 }).N(); // Limit(t ↦ e^t, At([1, 2], 5)), unevaluated
```

The index out of range gives the point `NaN` (`_SYS.atNumeric`); the
interpreter keeps the limit unevaluated. Under the caveats of compiled code
the value can be `NaN` there, or a throw that the caller can catch; a stack
overflow is neither a value nor an error of the program.

## Cause and options

The recursion of `limit()` does not end for `x = NaN` (not traced to the
line). Option: return `NaN` at the start of `limit()` when `x` or `dir` is
`NaN`, as the routine does when it finds no value.
