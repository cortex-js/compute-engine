The transpose of a list of rows of two numbers is said to have rows of two numbers, so counting its rows after a filter gives a wrong number.

## Witness

Checked at `c8de8c625a472541e8bac67aca26342952e73529`, in the interpreter:

```ts
const ce = new ComputeEngine();
ce.declare('P', 'list<list<real^2>>');
ce.box(['Transpose', 'P']).type.toString();
// 'list<vector<real^2>>'
ce.assign('P', ce.box(['List', ['List', 1, 2]]));
ce.box(['Transpose', 'P']).evaluate().json;
// ['List', ['List', 1], ['List', 2]]: two rows of one number
ce.box(['Length', ['Filter', ['Transpose', 'P'],
  ['Function', ['Greater', ['Sum', 'r'], 6], 'r']]]).evaluate().json;
// 2; no row has a sum above 6, so the value is 0
```

Controls: with the literal in place of `P`,
`Length(Filter(Transpose([[1, 2]]), r ↦ Sum(r) > 6))` gives 0, and
`Transpose(K)` with `K: matrix<real^3x2>` has the type `matrix<real^(2x3)>`.
The `Filter` of the witness stays unevaluated, and `Length` counts the rows
of its operand.

The compiled program gives 0 (since step 4 of the plan named above,
`Transpose(P)` compiles).

## Cause and options

Not investigated. The type of `Transpose` of a `list<list<real^n>>` keeps
the element type of its operand, `vector<real^n>`; the rows of the
transpose have the length of the operand, which the type does not state,
and the transpose has `n` rows. The second part, that `Length` of a
`Filter` that stays unevaluated gives the count of the operand, may be a
separate defect: check `Length(Filter(L, f))` where the predicate does not
type-check.

- (a) Give the transpose of a list of rows of a stated length the type
  `matrix<T^(n x ?)>` (or `list<list<T>>` if the type system has no such
  form).
