The sum, the maximum and the count of a value in a sorted list stay unevaluated when one of the elements is a variable.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.expr(['Sum', ['Sort', ['List', 3, 'x', 1]]]).evaluate();      // sum(Sort([3,x,1])), expected x + 4
ce.expr(['Max', ['Sort', ['List', 3, 'x', 1]]]).evaluate();      // max(Sort([3,x,1])), expected max(3, x)
ce.expr(['Count', ['Sort', ['List', 3, 'x', 1]], 1]).evaluate(); // Count(Sort([3,x,1]), 1), expected 1
```

Read on 319dc13947497b7243c95dde2bf3c1d3ea9c87aa. The same happens when a
symbol holds the sorted list (`d := Sort([3, x, 1])`, then `Sum(d)`).

## Cause and options

`Sort` cannot order `x`, so it stays `Sort([3, x, 1])`, and that form is not
a collection (`Sort` has no collection handlers). An operator that reads its
operand as a collection then has nothing to read. `Length`, `Count(xs)`,
`IsEmpty` and `Contains` strip the wrapper (`peekCountPreserving`,
`peekMembershipPreserving` in `library/collections.ts`).

Options: (a) give the inert `Sort`, `Reverse` and `RandomShuffle` forms
collection handlers that read the source in the order as written, for the
operators whose result does not depend on the order (a sum, an extremum, a
count); (b) strip the wrapper in the `canonical` and `evaluate` handlers of
each order-independent operator, as `Length` does. Workaround: leave out the
`Sort` where the order does not matter.
