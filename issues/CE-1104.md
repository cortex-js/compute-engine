Reading a number field through a key that is not there gives `Missing` with a dot and `NaN` with brackets.

## Witness

At HEAD `b2f4b0ce0`:

```epsil
const d: dictionary<record{b: integer}> = {a -> {b -> 1}}
[d.zz.b, d["zz"]["b"]]
// ["Missing", NaN]
```

With a string field (`record{b: string}`) both give `Missing`.

## Cause and options

The chained `At` gives the absent value of the final position
(`chainAbsorbMarker()`, `library/collections.ts`): the field `b` is an
integer, so `NaN`. `Field` on an absent base returns the base marker as it
is (`if (isAbsentValue(base)) return base;` in the `Field` evaluate
handler), so `Missing`, although its comment says it does exactly what a
chained `At` does. Absence in a numeric result is `NaN`
(`docs/ERROR-MODEL.md`, §1).

Fix: on an absent base, `Field` gives the absent value of its own static
type (the type of the read as written), as `At` does at its last index.
Size S.
