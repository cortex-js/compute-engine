A function that fills a list in a loop gives a broken list when the loop writes more than 100 elements: about one write in a hundred is not done.

## Witness

CE 0.201.5 (the installed bundle of Tycho), a fresh engine per shape. The
program is the MathJSON of the Epsil function
`let L = [0 for j in 1..n]; for k in 1..n { L[k] = k*k }; L`:

```json
["Block",
  ["Declare", "L", ["Dictionary", ["KeyValuePair", "value",
    ["Comprehension", 0, ["Element", "j", ["Range", 1, n, 1]]]]]],
  ["Loop", ["Block", ["Assign", "L", ["ReplaceAt", "L", "k", ["Multiply", "k", "k"]]]],
    ["Element", "k", ["Range", 1, n, 1]]],
  "L"]
```

`ce.box(program).evaluate()` gives:

| n    | `ReplaceAt` left in the value | value head  |
| ---- | ----------------------------- | ----------- |
| 100  | 0 (positive control)          | `List`      |
| 200  | 2                             | `ReplaceAt` |
| 1000 | 10                            | `ReplaceAt` |

Expected: a `List` of `n` numbers in every case. The inner `List` holds the
other writes; the unevaluated ones wrap it, for example
`["ReplaceAt", ["ReplaceAt", ["List", 1, 4, …], 199, …], 200, …]`. The count
is the same on every run, so it is not a time limit; `iterationLimit` is
`Infinity` on the engine. In Tycho, `koch-snowflake`'s prelude function
`snowflakeVertices(3)` leaves 23 writes, `(4)` 10 and `(5)` 18. A nested
loop, an `if` or trigonometry is not needed.

Tycho meets it when a plot row calls a prelude function
(`K = \operatorname{snowflakeVertices}(5)`): the document engine evaluates the
call with the interpreter, the row's value is a `ReplaceAt` expression, and
the plot that reads `K` draws nothing. A prelude constant
(`const Q = snowflakeVertices(5)`) is right, because the prelude runs compiled.

## Cause and options

Not traced. The value is right up to 100 writes, so a cap of 100 on some
evaluation step (a cache, a depth, a batch) is likely. Possibly related:
CE-1796 (the same loop over 20,000 elements exceeds the call stack).

Tycho's way around it (user ruling 2026-11-25, ROADMAP row LY): a row's call
of a prelude function will run the compiled function. The interpreter still
gives the wrong value to any other host that evaluates such a function.

## CE answer

Probed at `50d4e071555490bde47fb156a32af08abe78cca6`. No write is lost. The
value is a lazy view of the right list, as "Lazy collections" in
`docs/COLLECTIONS-MODEL.md` permits. For `n = 200`:

- `[...v.each()]` gives the 200 squares `1, 4, …, 40000`, `v.count` is 200,
  `v.at(5)` is 25, and the type is `vector<integer^200>`;
- `toString()` and `latex` print a list (`[0,1,0,3,4,...,199]` for
  `ReplaceAt(<200 elements>, 3, 0)`);
- `ce.box(program).evaluate({ materialization: true })` gives a `List` of 200
  elements.

Cause: a `ReplaceAt` (also `Insert` and `DeleteAt`) over a collection of more
than `MAX_SIZE_EAGER_COLLECTION` (100, `collection-utils.ts`) elements stays a
lazy view (`eagerElementsOf()` in `library/collections.ts`). So that a loop
does not copy the list at each turn, and a chain of views does not use up the
call stack, a chain of `MAX_REBUILD_VIEW_DEPTH` (32) views is copied into one
`List` at the next write. The value at the end of the loop therefore has
`n mod 33` views on its `List`: 2 for `n = 200` (`200 = 6·33 + 2`), 10 for
`n = 1000`, and none for a list of at most 100 elements. The count of
`ReplaceAt` in the value is not a count of lost writes.

Priority: proposed P4 (no wrong value). Disposition: proposed close, option
(a) below. Workaround for a host: read the value with `.each()` or `.at()`, or
evaluate with `{ materialization: true }`, as for any other lazy collection
(`Range`, `Comprehension`, a `Map` over a lazy source). The `head === 'List'`
test is not a test of a list value. Why Tycho's plot draws nothing for such a
value is not traced here (Tycho side).

## Options

(a) Recommended: no CE change, close. The interpreter's value is right and
follows the documented contract. Example: the witness with `n = 200` gives
`ReplaceAt(ReplaceAt(List(1, 4, …), 199, 39601), 200, 40000)`, whose 200
elements are the squares. Tycho reads it as it reads other lazy collections.

(b) A `Block` (or a call of a user function) whose result is a chain of
`ReplaceAt` views over a `List` copies the chain into one `List` before it
returns it. Example: the witness gives `List(1, 4, …, 40000)` for every `n`.
Cost: one more rule at a boundary, and a rule that is not complete: the
statement `Assign(L, ReplaceAt(L, k, v))` and the read of `L` by the host
still give a view, and the rule must not apply to the body `Block` of the
loop, or each turn copies the list.

(c) `ReplaceAt`, `Insert` and `DeleteAt` over a `List` (elements already in
memory) of at most `maxCollectionSize` elements are always eager. Example: the
witness gives a `List` for every `n`, and so does `ReplaceAt(<200-element
list>, 3, 0)`. Cost: a loop of `n` writes over a list of `n` elements copies
the list at each turn, so its time grows as `n²` (not measured), against one
copy for each 33 writes now; the current chain rule was made for loops over
lists of some thousands of elements.
