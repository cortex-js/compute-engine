`NDSolve` and `NDSolveFunction` stay unevaluated on a fresh engine unless the caller declares three internal names that it cannot know.

## Witness

```ts
ce.box(['NDSolve', ['Equal', ['D', ['y', 'x'], 'x'], ['y', 'x']], 'y',
  ['Limits', 'x', 0, 1], 1, 100]).evaluate()
```

Main (a28dd290f) and 0.186.0 give the `NDSolve` expression back, also with
`ce.declare('x', 'real')` and under `N`. It gives the list of 101 samples
only after `ce.declare` of `ndsolveystate`, `ndsolveystate0` and
`ndsolvezstate1` as `real` as well. In Epsil,
`ndSolve(D(y(x), x) == y(x), y, (x, 0, 1), 1, 100)` stays unevaluated.
`test/compute-engine/differential-equations.test.ts` declares the four names
at the top of the file, so the tests do not see the defect.

## Cause and options

`src/compute-engine/differential-equation-utils.ts` (lines 309, 370, 399)
replaces the dependent function by state symbols named `ndsolve<name>state<i>`
and compiles the right-hand side with `implicitCompileNumeric`. Compilation
refuses an input with no type, and these symbols are never declared, nor is the
independent variable. Fix: declare the state symbols and the independent
variable as `real` in a scope of their own around the compilation (or pass
their types to the compile call), then remove the four declarations from the
test file so that it covers the fresh-engine case.
