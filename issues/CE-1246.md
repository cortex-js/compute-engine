A function that reads an element of its list parameter and also uses the list in arithmetic cannot be defined.

## Witness

At `7305ef84b8e97bf25bc97dbcdaef2e6e48d81772`:

```ts
const ce = new ComputeEngine();
ce.assign('m', ce.box(['Function', ['Add', ['At', 'L', 1], 'L'], 'L']));
// throws: Invalid function (L) => Error(ErrorCode("incompatible-type", "tuple", "number"))
ce.box(['m', ['List', 3, 4]]).evaluate(); // stays ["m", ["List", 3, 4]]
```

Expected `[6, 7]`: the element `3` added to each element of the list. In
Desmos `m(L) = L[1] + L` with `m([3, 4])` is `[6, 7]` (Tycho gives it when it
inlines the body; reported by session `tycho-desk` on 2026-11-12, measured
through `DocumentCEManager.expandFunctionRefs`).

Workaround: declare the parameter, `(L: list<number>) ↦ L[1] + L`.

## Cause and options

Not investigated. The type of the undeclared parameter `L` is inferred from
the body: the read `At(L, 1)` gives it `tuple`, and the operand of `Add`
then refuses a tuple where it expects a number. With the read alone
(`L[1] + Length(L)`) the parameter is typed `tuple<number>` and the function
works. The macro-kind spec needs this for Tycho to stop inlining function
bodies (its acceptance item 4).
