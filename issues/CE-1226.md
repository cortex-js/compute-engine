Compiled `GammaRegularized(a, z)`, `Gamma(s, z)` and `AGM(a, b)` give `NaN` for a negative argument, where the interpreter has a real value.

## Witness

At `5fc85eda6`, `x`, `y` declared `real`, `k` declared `integer`, compiled
with `cse: false, constantFold: false` and with the default options (the
`numeric-kernel` profile writes the same calls), in the `strict` mode:

| Program (code) | Point | Compiled | `evaluate().N()` |
| --- | --- | --- | --- |
| `GammaRegularized(x, y)` (`_SYS.gammaQ(_.x, _.y)`) | `x = 2, y = -0.5` | `NaN` | `0.8243606353500641` (`e^0.5 · (1 - 0.5)`) |
| the same | `x = 2, y = -2.5` | `NaN` | `-18.27374094105521` (`e^2.5 · (1 - 2.5)`) |
| the same | `x = -3, y = -0.5` | `NaN` | `0` |
| `Gamma(2, y)` (`_SYS.gammaUpper(2, _.y)`) | `y = -0.5` | `NaN` | `0.8243606353500639` |
| `AGM(x, y)` (`_SYS.agm(_.x, _.y)`) | `x = -2.5, y = -0.5` | `NaN` | `-1.3020040952654703` (`-AGM(2.5, 0.5)`) |
| `AGM(k, y)` | `k = 0, y = -2.5` | `NaN` | `0` |

| `GammaRegularized(x, y)` | `x = 2, y = 0.5` | `0.9097959895689501` | the same |

`Q(n, z) = Γ(n, z)/Γ(n) = e^(-z) · Σ_{k<n} z^k / k!` for a positive integer
`n` is real for every real `z`, and `Q(a, z)` for a non-positive integer `a`
is `0`. `AGM(-a, -b) = -AGM(a, b)` and `AGM(0, b) = 0`. A plot of
`GammaRegularized(2, x)` over `[-2, 2]` shows a gap for `x < 0`. In the
`complex` mode `Gamma(2, y)` (type `real`) is the same call,
`_SYS.gammaUpper(2, _.y)`, and gives `NaN` at `y = -0.5` too.

## Cause and options

`_SYS.gammaQ`, `_SYS.gammaUpper` and `_SYS.agm` (`javascript-runtime.ts`)
compute on the domain of non-negative arguments only. Options: (a) give
the kernels the cases of the interpreter (an integer `a` and a negative
`z`: the finite sum; a non-positive integer `a`: `0`; two negative AGM
arguments: the negated AGM of their magnitudes; a zero argument: `0`);
(b) known-limitations lines. Recommended: (a), each case is a few lines.

The `numeric-kernel` profile declines these heads when the argument is not
provably non-negative (`GammaRegularized(a, z)` and `Gamma(s, z)`: `z`;
`AGM`: both operands): "… with the operand y, which is not provably
non-negative, is not in the profile". When the kernels are fixed, remove
the `domain` of `GammaRegularized`, `AGM` and `UPPER_GAMMA` in
`REAL_CALL_HEADS` (`javascript-fragment-target.ts`).
