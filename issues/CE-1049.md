The LaTeX of an integral with no bounds and no recognized variable writes no differential, so the variable is lost when the LaTeX is read back.

## Witness

At commit 01a8747d34144d72f07bafeb28cae6dcb608975e:

```
ce.box(['Integrate', ['Square', 'x'], ['Tuple', 'x', 0, 1, 5]]).latex
  → \int\,x^2\!            (expected \int x^2\,\mathrm{d}x)
ce.parse('\\int\\,x^2\\!').json
  → Integrate(Function(x^2, x), Limits(Nothing, Nothing, Nothing))
ce.box(['Integrate', ['Function', ['Multiply', 'x', 'y'], 'x', 'y']]).latex
  → \int\,xy\!             (expected two differentials)
```

The plain-text form (`toString()`) writes `int(x^2 dx)` for the same
integral since CE-1044.

## Cause and options

`serializeIntegral()` in
`src/compute-engine/latex-syntax/dictionary/definitions-calculus.ts` builds
the differentials from the limits only. An integral with no limit (the
canonical form drops a limit with four elements) gets none, and the spacing
commands around the missing differential stay. Fix: when there is no limit,
write one differential for each parameter of the integrand `Function`, the
last parameter first, as `bigOp()` in
`src/compute-engine/boxed-expression/ascii-math.ts` does.
