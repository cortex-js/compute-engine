A document row whose parameter is given a type the host declared by name stops
the whole document from loading.

## Witness

```js
const ce = new ComputeEngine();
ce.declareType('Pt', 'tuple<real, real>', { alias: true });
const imports = createDocumentEnvironment(ce, () => {}).createImports(() => {});
imports.prepare(
  [{ id: 'g', latex: 'g(q)=q+1', formalTypes: { q: 'Pt' } }],
  syntax // a DocumentSyntax whose recognize gives the head g(q), no bodyJson
);
// throws: Failed to parse type "Pt": Unknown type "Pt"
```

With `formalTypes: { q: 'tuple<real, real>' }`, the same row is prepared (it
gets a per-row error, since `q+1` of a tuple is ill-typed), and plain CE
accepts the name: `ce.declare('q', 'Pt')` and
`ce.box(['Function', 'q', ['Typed', 'q', "'Pt'"]])` give the type `Pt`. A row
given as `bodyJson` with the same `formalTypes` is prepared. Checked on
`cf862f6f0`. The Document contract says `prepare` throws only for host
contract violations and cancellation.

## Cause and options

When prepare parses a LaTeX row body, `finish()` of the definition row
(`src/compute-engine/latex-syntax/parse.ts`, about line 8432) adds each formal
with `new BoxedType(type)`, which has no type resolver, so a named type is
unknown. Pass the engine's type resolver (as `ce.type(…)` does), or parse the
formal types with `ce.type` before the row is read. A type string that still
fails to parse should give a per-row error, not a throw. Workaround: the host
spells the structural type out.
