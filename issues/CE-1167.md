A plot row with many two-branch piecewise terms compiles to interval code up to a third larger than necessary, and takes about 0.15 ms longer to load.

## Witness

`\begin{cases} A & c \\ B & \top \end{cases}` compiled to `interval-js` gives

```
(t = c) === 'true' ? _IA.res(A) : t === 'false' ? _IA.res(B) : _IA.hull(A, B)
```

The text of `B` occurs twice, often each time inside an immediately invoked
arrow function that holds its common subexpressions. Only one copy runs.

Corpus: Desmos state `neyret/4cgqofti5k`, a sum of 20 such terms (record
#2893 of Tycho's whole-corpus codegen audit at 0.184.0): 28,568 bytes of code
and preamble, 89 arrow functions. The whole corpus has 896 such sites in 35
interval-js codes at 0.184.0, against 13 in 12 codes at 0.130.0.

## Expected

Bind `B` once, inside the branch that runs when the test is not `'true'`:

```
(t = c) === 'true' ? _IA.res(A) : (b = B, t === 'false' ? _IA.res(b) : _IA.hull(A, b))
```

`B` then runs in the same cases as today.

## Measurement

The instrument applies this rewrite to the text of the witness (44 sites)
and builds both texts with the engine's own builder. Rewritten: 21,240 bytes,
45 arrow functions. `new Function` plus the first call: 0.46 to 0.48 ms
against 0.61 to 0.63 ms (median of 15). Evaluation of 1,644 interval boxes:
the same result on every box and the same time within 2 %, with no
consistent sign. So the gain is code size and parse time only, which is why
this is P3 and size S. Compute Engine 0.184.0, Node 26.13.0, Apple M5 Max.

Verification: when the fix ships, the instrument reads `sites rewritten: 0`
and stops at its positive control.

## Fix

The fix does not use the form under "Expected". The condition temporaries
(`t`, `b`) are declared once per compiled artifact and shared by every call,
so an arm that calls back into the same code (a recursive function whose body
holds the conditional) writes them again. In `(b = B, t === 'false' ? ...)`,
`B` runs before the second read of `t`, and a recursive call in `B` changes
the branch: `f(n) := n if n < 1, else f(n-1) + ...` gives a wrong value at
`n = 2`.

The fixed code reads `t` twice before it runs any arm:

```
(t = c) === 'true' ? _IA.res(A)
  : _IA.elseArm(t === 'false', t === 'false' ? null : A, B)
```

`_IA.elseArm(isFalse, a, b)` (`src/compute-engine/interval/comparison.ts`)
gives `b` where the condition is `'false'` and the hull of `a` and `b`
otherwise. The compiler keeps the shorter of the two spellings, so a short
second arm (a symbol, a number) keeps the hull form. The arms are measured
before constants are hoisted, so a constant list arm can take the `elseArm`
form although it becomes a short `_kN` name later. On the witness record
#2893: 20,580 characters of code and preamble (28,567 before), 45 arrow
functions (89 before), the same value on 93 interval boxes. Test:
`test/compute-engine/ce-1167-interval-conditional-second-arm-once.test.ts`.

The instrument looks for the `'false' ? _IA.res(B) : _IA.hull(A, B)` text;
after the fix it finds no site to rewrite and stops at its positive control.
