A heatmap whose formula sums a helper function, where the helper calls another function with the same arguments each time, draws about two times slower on the CPU than the same formula with the helper written out.

## Witness

CE 0.198.1 and 0.200.0. The rows of Tycho's showcase entry
`voronoi-diagram`, as a prepared Document with the inputs `x`, `y` and `T`
declared `real`:

```
p(k) = 1.45 sqrt((k-0.5)/16) cos(2.4k) + 0.14 cos(T + 1.9k)
q(k) = 0.95 sqrt((k-0.5)/16) sin(2.4k) + 0.1 sin(2T + 2.7k)
D(x, y, k) = (x - p(k))^2 + (y - q(k))^2
F(x, y) = Min([D(x, y, k) for k = 1..16])
n(x, y, k) = e^(-5000 (D(x, y, k) - F(x, y)))
Z(x, y) = Sum(n(x, y, k), k = 1..16)
u, v, H(x, y) = (1/Z(x, y)) Sum(<factor> n(x, y, k), k = 1..16)
B(x, y) = Sum(exp(-(D(x, y, k) - F(x, y)) / (0.015 sqrt(...))), k = 1..16)
```

The heatmap formula `Which(F(x,y) < 0.0008, 0, 1.3 < B(x,y), 0, True,
0.8H(x,y) + 0.12)` compiled to JavaScript, on a new engine each:

- `n` as a function row: 1141 calls of `Math.sin`/`Math.cos` per point,
  10.1 µs per point.
- `n` written out in Z, u, v and H, no row `n` (control): 600 calls,
  4.6 µs per point. Same value.

In the generated code of the case, the helper `H` calls the helper `n`
16 times, and each call of `n` calls the helper `F(x, y, T)` (32 trig
calls), whose arguments are the same in the 16 calls. In the control, the
common-subexpression pass computes `F` once. Expected: a call of a pure
function with the same arguments is computed once in a sum, also when it
is inside a helper (by inlining a small helper, or by hoisting the
invariant call).

In Tycho, the JavaScript batch of this heatmap takes 45 ms instead of
24 ms in the CE Document port (nine paired rounds, 2026-11-23). Before the
port, Tycho wrote out the function rows itself. The entry draws on the GPU
in a browser with WebGL; the JavaScript path draws the thumbnail and the
CPU fallback. The GLSL output was not measured.

The instrument prints `CE-1724: READY` when the case makes at most 1.25
times the sin/cos calls of the control, with the same value.

## Cause and options

Not investigated on the CE side. The compile keeps `n` as a helper in
`H` but writes it out in `Z`, `u` and `v` of the same document (their
helpers have 48 trig calls and no call of `n`).
