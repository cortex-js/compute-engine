In degrees, the numeric value of the angle of `i` is `89.9999999999999999999`, not `90`.

## Witness

On `adcfe196a8e5c200689cc972409980865dcca6b8`, at the default 21 digits:

```ts
const ce = new ComputeEngine();
ce.angularUnit = 'deg';
ce.box(['Argument', 'ImaginaryUnit']).N().json; // {num: '89.9999999999999999999'}
ce.box(['Arctan2', 1, 0]).N().json;             // {num: '89.9999999999999999999'}
ce.box(['Arctan2', 1, 0]).evaluate().json;      // 90
ce.box(['Arcsin', 1]).N().json;                 // 90
```

`.N()` gives a value correct to the working precision, and the exact value is
`90`. `Arcsin`, `Arccos` and `Arctan` give the exact angle in degrees under
`.N()`; `Arctan2` (and `Argument`, which calls it) does not. Since CE-1603 the
comparisons have no tolerance, so `Argument(i).N() = 90` is `False`.

`needs-review`: the impact is `critical` by the table (a wrong finite value,
no error), though the error is in the last digit; `confidence` is the other
reading.

## Cause and options

Under `.N()`, `Arctan2` computes the angle in radians as a float and
multiplies it by `180/π` as a float, so the rounding of `π/2` and of `180/π`
reach the last digit. The fix: convert the angle of an exact `Arctan2` to the
unit before it is rounded, as the other inverse functions do (they reduce the
exact angle in half turns), or compute the float in half turns.
