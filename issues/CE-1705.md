A plot row that calls a function defined in the document's prelude, such as g(x) = f(x) + 1, draws nothing and shows an error.

## Witness

CE 0.198.1, Document API, x a real input. `createImports` declares
`["Declare", "f", <type>, ["Function", ["Multiply", 2, "t"], "t"]]`, as a
host replays a prelude function; `reservedImportNames` holds f. Rows:
g(x) = f(x) + 1, y = f(3).

- type `'unknown'` or `'function'`: row error on g,
  `["Error", "'g: provisional heads f'"]`; g(2) is that error. y = 6.
- control, type `'(t: unknown) -> unknown'`: no row error, g(2) = 5.

The value of f is a `Function` literal, known when the import scope is
sealed, so a call of f with a row parameter as argument need not be
provisional. Expected: "open" and "function" behave as the control.

The instrument prints `CE-1705: READY` when both open types give no row
error on g and g(2) = 5.

## Cause and options

Not investigated on the CE side. The provisional-head check seems to read
the declared type only, not the sealed value of the import.

Workaround: Tycho's prelude replay declares each function with a signature
built from its `Function` literal (`signatureOfLiteral` in
`src/plot-core/prelude-replay.ts`). Every Tycho document with an Epsil
prelude function called from a row depends on it, hence `probability: high`
and `impact: minor`.

## CE answer

workaround until the fix is released. Cause not investigated yet.
