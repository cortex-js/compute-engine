The interval of the cardinal sine over a range that holds one of its turning points misses the value at that point.

## Witness

```js
import { sinc } from '@cortex-js/compute-engine/interval';
sinc({ lo: 4, hi: 5 }); // lo: -0.21723362821118977
sinc({ lo: 7, hi: 8 }); // hi:  0.12837455352568258
```

The minimum of sinc on [4, 5] is -0.2172336282112216574 (at x =
4.4934094579090641753, a root of tan(x) = x), 3.2e-14 below the lower end. The
maximum on [7, 8] is 0.1283745535258991367, 2.2e-13 above the upper end. Values
at 40 digits from `Sinc(…).N()`. Run on
`aaa780a802bf64ba831f69c1d0a03b49e1332cb2`.

## Cause and options

`sincRaw()` in `src/compute-engine/interval/trigonometric.ts` evaluates sinc at
the tabulated extrema `SINC_EXTREMA`, which have 5 or 6 digits. sinc at a point
5e-7 from the extremum is above the minimum by about 3e-14, and the one-ulp
outward rounding of `outwardUnlessExact()` does not cover that.

Options: give the extrema to the precision of a double and widen the end that an
extremum sets by a bound of the kernel's error; or widen that end by the
second-order bound |sinc''| · δ² / 2 plus a few ulps, with δ the error of the
tabulated root. Size S. The profile `ir` has no interval spelling of `Sinc`, so
compiled interval code is not affected; the public interval library is.
