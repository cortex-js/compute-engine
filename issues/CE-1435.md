A product of numbers outside the range of machine numbers, computed with `Reduce` at machine precision, gives 0 where the value is 1e-100.

## Witness

```js
const ce = new ComputeEngine();
ce.precision = 'machine';
ce.jit = 'off';
ce.box(['Reduce', ['List', ['Power', 10, 300]], 'Multiply', ['Power', 10, -400]]).N();
// 0, must be 1e-100
ce.box(['Reduce', ['List', ['Power', 10, -400], ['Power', 10, 300]], 'Multiply']).N();
// 0, must be 1e-100
ce.box(['Multiply', ['Power', 10, 300], ['Power', 10, -400]]).N();
// 1e-100
```

The same with the reducer `Function(Multiply(a, b), a, b)`. Run on
`aaa780a802bf64ba831f69c1d0a03b49e1332cb2`. With `ce.jit` on, the compiled fast
path of `Reduce` gives 1e-100 (`machineStep()` reports an underflowed element as
NaN, and `withExactFoldFallback()` recovers the value), so the interpreted fold
is reached when the reducer does not compile, when the JIT is off (a host with a
Content Security Policy), or when an element is not real.

## Cause and options

The interpreted fold of `Reduce` in `library/collections.ts` numericizes the
seed and each step to the working precision (`numeric()`): at machine precision
`10^-400` is the double 0, and the fold is then 0. `withExactFoldFallback()`
takes the exact fold only when the numeric fold is NaN or infinite, so a 0 that
is an underflow is kept. `.N()` promises a result correct to the working
precision (ARCHITECTURE.md, "What `.N()` promises"), and 1e-100 is a double.

Option: in the interpreted path, apply the test of `machineStep()` to the seed
and to each element (a double of 0 whose exact value is not 0 is an underflow)
and end the fold NaN, so that `withExactFoldFallback()` computes the exact fold,
as the fast path does. Size S.
