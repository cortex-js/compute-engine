An animation that draws a styled figure in each frame runs interpreted, because the code that applies the style keeps the figure in a variable and replaces it.

## Witness

On CE 0.204.2, compiled JavaScript declines a local whose value is a named
tuple:

```epsil
type U = tuple<kind: string, n: real>
function withLocal(f: U) -> U { let out: U = f; for k in 1..2 { out = U(out.kind, out.n + 1) }; out }
function withLocalNoType(f: U) -> U { let out = f; for k in 1..2 { out = U(out.kind, out.n + 1) }; out }
function noLocal(f: U) -> U { U(f.kind, f.n + 2) }
```

| Shape | 0.204.2 |
| --- | --- |
| `(t: real) => noLocal(U("c", t))` (control) | compiles; `{"kind":"c","n":4}` |
| `(t: real) => withLocal(U("c", t))` | declines: `Declare("out", "U", {"value" -> f}): a local of type U` |
| `(t: real) => withLocalNoType(U("c", t))` | declines: `Declare("out", {"value" -> f}): a record in the local out, which a statement writes` |

A local of type `U` with no loop (`let out: U = f; out`) declines the same
way. The interpreter gives `U("c", 4)` for each.

Tycho's drawing prelude applies the options of a figure in
`figureStyled(fig: Figure, opts: dictionary, name: string) -> Figure`:
`let out: Figure = fig`, then `out = figureOption(out, k, opts[k])` for each
`k in keys(opts)`. Every figure constructor (`circle`, `segment`, `polygon`,
`label`, `image`, …) ends with this call, also when `opts` is the default
`{->}`. With CE-1918 fixed, this is the decline that a figure constructor
meets.

## Cause and options

The local holds a whole value of a named tuple, which compiles to an object
(the control returns `{"kind":"c","n":4}`). A statement that replaces the
whole value (`out = U(…)`) needs no write to a field, so the local can be a
JavaScript `let` that holds the object, as a local of a scalar type does.
Field writes (`out.n = …`) are not needed for this shape.

Workaround: Tycho could write `figureStyled` as a recursion over the keys,
with no local. Tycho has not tried it.

Tycho half on adoption: rerun the instrument; then rerun
`scripts/repros/2026-11-20-ce-compile-figures.mts`.

## CE answer

CE (2026-11-27): P3 confirmed, pool. The decline reproduces on CE source. No
workaround was found: the recursion over the keys declines too (`a recursive
call of step, on a cycle of calls with a record parameter or result`), and
so does a host function that returns the figure (`a call of the function
hostStyle of the host, of type U, not real, integer, boolean or nothing`).
The `workaround` flag is removed.

Fixing this issue alone does not make `figureStyled` compile: its next
decline is `keys(opts)`, filed as CE-1920. The type tests in
`figureOption` (`v is string`, `v is color`) are not a blocker: a test of
the type of an `any` parameter settles per call when the argument's type is
known, and `opts["fill"]` with a constant key compiles. The board should
schedule CE-1919 and CE-1920 together, since only both make a figure
constructor compile.

## Fixed (07b97238b91a, 2026-11-27)

A block local that holds a record and that statements replace with whole
values compiles, with or without the stated type, in an `if` and across a
loop: `let out: U = f; for k in 1..2 { out = U(out.kind, out.n + 1) }; out`
gives the interpreter's value. A list field may change length between the
values, and a string field its value. These still decline: a write of one
field (`out.n = 4`), a parallel assignment, and a value whose fields have
other lanes than the first value (`fillPaint: nothing` then `"red"` in
`figureStyled`): the local would hold two shapes, which the shape rule
(R3, `docs/COMPILATION-MODEL.md`) declines. For an option that sets a field,
the prelude can build the record once with every field in its final type
(for example `fillPaint` as a string, `""` for none) instead of replacing a
`nothing` field.
