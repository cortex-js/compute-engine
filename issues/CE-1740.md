In the exact-integer (bigint) compile mode, a function that builds a list step by step falls back to the interpreter, although the same function compiles in the default mode.

## Witness

From the decline census on GitHub #638: 27 bigint items of a combinatorics
corpus. On main f42a02d1323b9e40cf2def511715fc3034ae8d6c:

```ts
ce.declare('n', 'integer');
const e = ce.box(['Drop', ['Fold', ['Function', ['Join', 'a', ['List', 'i']], 'a', 'i'], ['List', 0], ['Range', 1, 'n']], 1]);
compile(e, { mode: 'bigint', fallback: false });
// Could not compile: Reduce(...): Reduce of a list of a run-time length (the
// bigint mode)
compile(e, { fallback: false }).success; // true (double mode)
```

`fallback: true` gives the interpreter's value (the workaround).

## Cause and options

The list accumulators of `Reduce` and `Fold` (#647, PR #648) were added to
the double emitter; the bigint emitter refuses an accumulator whose length is
known only at run time. Port the same lowering, with `bigint` elements.
