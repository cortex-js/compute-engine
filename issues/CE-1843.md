A slice that starts at position 0 gives an empty list, where the description of `slice` says that an out-of-bounds index is clamped and the user expects the first elements.

## Witness

```
Slice([10, 20, 30, 40, 50], 0, 2)    // [], where clamping gives [10, 20]
Slice([10, 20, 30, 40, 50], -9, 2)   // [10, 20]: a far negative start is clamped
Slice("abcde", 0, 2)                 // "", where clamping gives "ab"
Slice([10, 20, 30, 40, 50], 1, 0)    // [10, 20, 30, 40, 50]: an end of 0 reads as the last element
```

Measured at 8995eb986cc37d4a3f2dec2459874e9dce9bc262.

## Cause and options

`computeSliceBounds()` in `src/compute-engine/library/collections.ts` reads
a bound `< 1` as counted from the end (`count + 1 + start`), so 0 becomes
`count + 1`, past the last element. The description of `Slice` says "a
negative index is counted from the end and out-of-bounds indices are
clamped".

- (a) Recommended: count from the end only a bound `< 0`, and clamp a start
  of 0 to 1, as the description says. Decide in the same change what an end
  of 0 gives (today the whole collection; clamping gives the empty slice);
  every facet that reads `sliceBounds` follows, and the compiled `Slice`
  must agree.
- (b) Keep the behavior and document that 0 counts from the end.

Size S.
