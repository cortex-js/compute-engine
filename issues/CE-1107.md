A colour formula that calls a prelude function with a list, `c(H, x, y, z)`, is drawn on the CPU: 50 ms frames against 16.7 ms.

## Witness

On 0.182.0, with H free, typed `list<(real | signed_infinity | nan)^90001>`
and `storage: { H: "sampler2D" }`, `H[k]` in the formula compiles to
`_gpu_texat90001(H, k)`. `g(H, x)`, with `g` the value of an Epsil
`function g(H: list<integer>, x: real) -> real`, declines on GLSL: "parameter
"H" has no static GLSL type". Also with `H: list<real>` and the type of H.

## Cause and options

(a) When an argument is a `sampler2D` symbol, give the helper a `sampler2D`
parameter (GLSL ES 3.0 allows it) with the width of the argument. (b) Inline
the call. WGSL needs the same for a storage buffer.

Tycho half on adoption: none in code; ROADMAP row LD lets the GPU check admit
the call.
