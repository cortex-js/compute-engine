The incomplete elliptic integral of the first kind of a complex amplitude with
a very small parameter loses about nine digits below the real axis.

## Witness

`EllipticF(0.3 − 10i, 1e-30)` at machine precision gives
`0.3000000040807729 − 10.000000012871325i`; the value is `0.3 − 10i` to 1e-16
(`F(φ|m) = φ + O(m)`). `EllipticF(0.3 + 10i, 1e-30)` is right
(`0.3000000000000007 + 9.999999999999998i`). `EllipticF(φ, 0)` is exact since
PR #606 (it returns `φ`), so only a nonzero `m` with `|m·sin²φ|` below about
1e-16 reaches the case.

## Cause and options

When `m·sin²φ` is below about 1e-16, `y = 1 − m·sin²φ` rounds to 1, so
`carlsonRFComplex(cos²φ, y, 1)` takes the shortcut to
`carlsonRCComplex(cos²φ, 1)`. The `acos` branch of `carlsonRCComplex`
(`src/compute-engine/numerics/numeric-complex.ts`) loses the digits:
`carlsonRCComplex(cos²(0.3 − 10i), 1)` is
`0.0008754941505256743 − 0.000242308608235401i` against
`φ/sin φ = 0.0008754941492996585 − 0.00024230860824400654i`.

- (a) Make the `acos` branch of `carlsonRCComplex` accurate for an `x` far from
  `y` in the lower half-plane (the cause; it also serves the other callers).
- (b) In `ellipticFComplex` and the two-operand `ellipticEComplex`, return `φ`
  when `|m·sin²φ| < 1e-16`, as for `m = 0`.
