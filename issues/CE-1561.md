A plot that scales each point of a list by its own number is computed point by point instead of by compiled code, so it draws slower.

## Witness

`p: list<tuple<real, real>>`, `n: list<real>`. Compile to javascript:
`Multiply(PointX(p), PointList(1, n))`.

0.194.3: declines, "Multiply of a list of points and a value of another shape".
The interpreter of 0.194.3 gives the element-wise product
(`[(1, 10), (3, 60)]` for `p = [(1, 2), (3, 4)]`, `n = [10, 20]`), and 0.186.0
compiled the same value. Control: `Multiply(a, PointList(1, n))` with `a: real`
compiles.

Found by the Tycho codegen audit of 2026-11-19: the same MathJSON, with the same options, compiled to JavaScript on CE 0.186.0 and declines on 0.194.3 and on the CE main build of 2026-11-19 16:57, in the document context and on a bare engine. Tycho's instrument `scripts/repros/2026-11-19-ce1560-js-decline-regressions.mts` prints one READY / NOT READY line per issue (READY on 0.186.0, NOT READY on 0.194.3).

## Cause and options

The compiled `Multiply` broadcasts a scalar over a list of points but not a
list of numbers over a list of points of the same length. Option: zip the two
lists, as the interpreter does.
