A plot that reads a list of random numbers with a fixed seed is no longer compiled, so it can stay blank until its values change, and a heatmap that reads it is computed point by point.

## Witness

`x: real`; `a := WithRandomSeed(7, RandomChoice([0, 1), 3))` (assigned);
compile `x + min(a)` to javascript.

- CE 0.193.0: compiles; two runs at x = 0 give 0.08483070468009213 both
  times.
- CE 0.194.2: declines: "a: the value of a, which has an effect".

The draw has a constant seed, so its value is the same at each evaluation.
In Tycho, a Desmos list such as `random(3, 7)` imports as such a value. Tycho
compiles a row that reads it against its symbolic form, so that the row has
a kernel before its values arrive and a hook that refreshes it when they
arrive (Tycho D-259). On 0.194.2 the row gets neither, and a heatmap that
reads the list gets no compiled kernel.

## Expected

A value whose draws all have a constant seed compiles, as in 0.193.0, and
each run gives the same value. Alternatively, CE states the form that Tycho
should compile in its place.

## Instrument

`npx tsx scripts/repros/2026-11-19-ce1524-seeded-draw-value-compile-probe.mts`
in Tycho. `CE-1524: READY` when the compile succeeds and two runs give the
same number. READY on 0.193.0, NOT READY on 0.194.2.

## Cause and options

`expression()` of `src/compute-engine/compilation/ir/lower.ts` lowers the
held value of `a` where `x + Min(a)` reads it, and declines a held value
with an effect; a seeded draw is an effect. The same draws written in place
compile, in their seeded frame, with the interpreter's value at each call.

A fix folds the held value at compile time (`v.N()`) into a literal when
its value cannot change between calls. Two review rounds (Codex and
Claude, 2026-11-19) each found a wrong finite value in the test of "cannot
change": a body that reads a name with a value, which a host supplies at
run time through `vars` (`WithRandomSeed(7, T·Random())` with `T`
assigned), and then a body that calls a user function whose body reads such
a name (`f := Function(T·Random())`, `WithRandomSeed(7, f())`). The
round-2 patch is in
`~/dev/compute-engine-recovery/ce1524/ce1524-seeded-fold-round2.patch`
(not applied).

- (a) Recommended: fold only a body made of draws over literals: the heads
  `Random`, `RandomChoice`, `RandomSample`, `List`, `Range`, `Interval`,
  `Open` and `Tuple`, number literals and constant symbols, with no host
  compile handler for any node. Tycho's `random(3, 7)` import is in this
  set. Any other held draw keeps declining.
- (b) Fold any body whose reads, through user functions and held values,
  are proved constant: a transitive walk with cycle guards. Covers more
  programs; more code and more ways to be wrong.
- (c) No change: Tycho writes the draws in place.

## CE answer

CE (2026-11-19): P2 confirmed, needs-decision (options above; CE recommends
(a)). Workaround: compile the expression with the held value written in
place, `x + Min(WithRandomSeed(7, RandomChoice([0, 1), 3)))`: it compiles on
javascript, and each run gives the interpreter's value (0.08483070468009213 at
x = 0). GLSL declines a seeded frame, so a heatmap has no workaround but
passing the drawn values as an input list. Options (a) and (b) compile on
glsl too.
