A sum over a mapped list whose source assigns a variable runs the assignment several times, and gives a wrong sum.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'integer');
ce.assign('x', 0);
const f = ['Function', ['Add', 'k', 1], 'k'];
const arm = ['Block', ['Assign', 'x', ['Add', 'x', 1]], ['List', 'x', 'x']];
ce.box(['Sum', ['Map', f, ['Sort', arm]]]).evaluate().json;
// 8, and x is 4; expected 4, and x is 1
ce.assign('x', 0);
ce.box(['ListFrom', ['Map', f, ['Sort', arm]]]).evaluate().json;
// ["List", 2, 2], and x is 1 (correct)
```

The same with the source `If(True, arm, [0])` after CE-1349. Not probed: an
`If` whose condition is not typed `boolean` (a list of conditions, a symbol
typed `unknown`) is evaluated once per walk under `ListFrom` too, because
`isSelectedCollectionSource()` in `boxed-function.ts` admits a `boolean`
condition only. Run with
`npx tsx` on `6f8fa80decd0759f578c89b0674f7271418c6377` with the CE-1349 fix.

## Cause and options

Not read in full. `Sum` does not evaluate the lazy `Map`; it reads the facets
of the view (count, finiteness) and walks it. Each read of an eager source
that is not pure evaluates the source again: `mapSource()` in
`library/collections.ts` keeps the value of a PURE source only
(`keptEagerSourceValue()` in `boxed-expression/eager-source-values.ts`), and
the walk (`BoxedFunction.each()`, the eager route) evaluates it once more.
Options: a reducer evaluates a view over an impure eager source before it
walks it (as `ListFrom` does through the operand step,
`resolveHeldEagerSources()`); or the value of an impure source is kept for
the one evaluation of the consumer.
