Compiling a plot whose list reads have a wrapped index takes up to eight times longer when the expression only doubles in size, so a document with many such reads builds in seconds.

## Witness

Tycho, row MK, CE 0.192.0, existing JavaScript compiler: in
`neyret/urbddymicb` the expansion of `D_x(t, 1)` grows from 42.7k to 81.6k
characters (258 `Abs`, 534 `Floor`) and its compilation from 205 ms to
1,677 ms. A sum of 160 reads `P[1 + mod(a + k, 4)]` with an untyped `a`:
plain 21 ms, `Max(F, 0)` 38 ms, `(F + |F|)/2` 75 ms, `Clamp(F, 0, +∞)` 45 ms.

Reproduced on the working tree of main at
`3b0b23f414e90ada33e633cb641cd9a8fb3c8ef6`, machine precision, best of three,
with `{ to: 'javascript', mode: 'strict', iterationBudget: 1e6, symbolic:
[…], fallback: false }` and the same options plus `profile: 'ir'`:

```ts
ce.declare('P', { type: 'list<real^4>', value: ce.box(['List', 'p_1', 'p_2', 'p_3', 'p_4']) });
for (const s of ['p_1', 'p_2', 'p_3', 'p_4']) ce.declare(s, 'real');
const idx = (k) => ['Add', 1, ['Mod', ['Add', 'a', k], 4]];      // a is not declared
const S = (i) => ['Floor', ['Add', i, ['Multiply', 4.440892098500626e-16, ['Max', 1, ['Abs', i]]]]];
const snapped = (i) => ['Divide', ['Add', S(i), ['Abs', S(i)]], 2];
const e = ce.box(['Add', ...Array.from({ length: 160 }, (_, k) => ['At', 'P', snapped(idx(k))])]);
compile(e, { to: 'javascript', mode: 'strict', iterationBudget: 1e6,
  symbolic: ['a', 'p_1', 'p_2', 'p_3', 'p_4'], fallback: false });
```

Compile time in ms for a sum of 40, 160 and 640 reads (the JSON of the
largest is given in characters):

| Index | existing compiler | profile `ir` |
| --- | --- | --- |
| plain `i` (30k) | 7, 19, 68 | 4, 13, 48 |
| `Max(Floor(i), 0)` (43k) | 8, 26, 96 | 6, 18, 69 |
| `(F + |F|)/2`, `F = Floor(i)` (95k) | 13, 46, 190 | 7, 25, 96 |
| `Clamp(F, 0, +∞)` (56k) | 8, 26, 97 | declines: "the operator Clamp is not in the slice" |
| `(S + |S|)/2`, `S = Floor(i + c·Max(1, |i|))` (209k) | 25, 127, 864 | 12, 49, 161 |

Both compilers give the same value (16,150 at `a = 2` for 640 reads) in
every admitted row. For the snapped index the existing compiler takes 2.0,
2.5 and 4.1 ms per thousand characters as the size grows, the profile 0.9,
0.9 and 0.8.

The document, from the dump
`~/dev/compute-engine-recovery/interval-dump/t12-javascript-glsl-document-definitions.json`
(taken before row MK; its programs already hold the snapped index in the form
`(F + |F|)/2`), loaded as `_TASKS/2026-11-14-ir-batches/replay-compile-time.mts`
does:

| `neyret/urbddymicb` | existing compiler | profile `ir` |
| --- | --- | --- |
| program 2 (2-D, 38,860 characters, 658 `Abs`, 188 `Floor`, 94 `At`), best of three | 758 ms | 48 ms |
| program 4 (38,881 characters), best of three | 793 ms | 45 ms |
| the 26 programs, one run each | 8,380 ms | 717 ms |

Both compilers admit the 26 programs. The trees of row MK itself (81.6k
characters) are made inside Tycho and were not rebuilt here.

## Cause and options

Not read: where the existing compiler spends the time that grows faster than
the size was not looked for. The profile `ir` compiles the same trees in a
time proportional to their size, and the existing compiler is being replaced
by it.

- (a) No change of the existing compiler. Tycho compiles with the profile
  `ir`. Recommended.
- (b) Profile the existing compiler on the snapped sum of 640 reads and
  remove the pass that is not linear. Size M, in code that is to be deleted.

## CE answer

CE (`ce-compiler`, 2026-11-16): P3 (a slow case with a remedy on the host's
side). Disposition: no change of the existing compiler; the profile. The
board is asked to confirm (`needs-review`).

- With `compile(expr, { profile: 'ir' })` the programs of `neyret/urbddymicb`
  compile in 717 ms in place of 8,380 ms, and program 2 in 48 ms in place of
  758 ms.
- A read that is one node at each site keeps the tree small on both
  compilers: the host function `dat(L, i)` of CE-1366 compiles on JavaScript,
  GLSL and `interval-js` with the profile.
- The profile declines `Clamp`, so an index list written
  `Clamp(Floor(I), 0, +∞)` falls back to the existing compiler; `Max(F, 0)`
  and `(F + |F|)/2` are admitted.
