The absolute value of a numeric indexed collection reports a list type, but it returns a number when the collection holds a point.

## Witness

On main `327732c36831e48ca5463d66eabe12b84f7ee207`:

```ts
const ce = new ComputeEngine();
ce.declare('u', 'indexed_collection<number>');
const a = ce.box(['Abs', 'u']);
console.log(String(a.type)); // list<real<0..> | signed_infinity>
ce.assign('u', ['Tuple', 1, 2]);
const v = a.N();
console.log(v.json); // 2.236... (the norm of the point)
console.log(v.type.matches(a.type)); // false
```

With `u := [1, 2]` the value is `[1, 2]`, which matches the type. `Hypot`, the other
head in `TUPLE_NORM_HEADS` (`boxed-function.ts`), reads a point the same way
(not probed).

## Cause and options

The visible-collection arm of `broadcastLiftType`
(`broadcast-lift-type.ts`) types an `indexed_collection<number>` trigger as a
list. A norm head reads a point as one value, and its norm is a number. So
the result is a number or a list. CE-1583 fixed the same problem for the
heads that map a point to a point (`armwiseTupleArms`), whose result is now
`indexed_collection<…>`. For a norm head, the sound type is the union of the
scalar per-element result and the list (`real | list<real>`), or
`broadcastable<real>`.
