A dot product of a list that holds `Nothing` stays unevaluated instead of reporting a type error.

## Witness

```epsil
Dot([1, Nothing], [1, 2])   // stays MatrixMultiply([1, Nothing], [1, 2])
Dot([1, "a"], [1, 2])       // incompatible-type error, as expected
```

The user decision of 2026-11-02 (`docs/ERROR-MODEL.md`, "One static error,
one dynamic non-value per domain", item 3) says that an operator that needs a
value and meets `Nothing` gives its ordinary `incompatible-type` error when
it is evaluated. The same decision types the list literal `[1, Nothing]` as
`list<integer>`, so the signature check of `Dot` accepts the operand, and
the evaluation then declines and leaves the expression unevaluated.

## Cause and options

The evaluate handler of `Dot` (or of the `MatrixMultiply` form it gives)
does not test its elements for `Nothing`. Fix: when an element of an operand
is `Nothing`, give the `incompatible-type` error that `Reduce([1, Nothing],
…)` and `Add(1, Nothing)` give. `Sort` and `Ordering` also stay unevaluated
on `Nothing`, but they do the same for any element they cannot compare
(`Sort([3, "a", 1])`), so they are not part of this issue.
