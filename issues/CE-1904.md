Graph Paper can redraw built-in polygons through the compiler, but cannot give its own geometry operators the same result behavior.

## Witness

CE 0.204.0 returns `{ __tag: "Polygon", geom: [2, 0, 0, 1, 1, 1] }`
for `Polygon((t,0),(0,1),(1,1))` at `t = 2`. The same valid inputs to
`Triangle`, and the first two points as inputs to `Segment` and
`GeometricVector`, all decline. The instrument declares `t` as `real`
and passes two values at runtime. Graph Paper plots the three operators
today by materializing their vertex operands and retaining the source head
to decide closure and arrowheads.

A nominal tuple control `type DrawingValue = tuple<kind: string, geom:
list<real>>` returns a keyed JavaScript object with `kind` and `geom`
but no nominal tag. In the real notebook, a compiled
`timer(16, t => draw(polygon([(t,0),(0,1),(1,1)])))` still hands the
renderer boxed `Figure` MathJSON through the draw host call. That path
works. Compiling the prelude polygon as the callback's returned value
declines on the optional dictionary parameter. Returning a captured
default Figure directly also declined on its string-list field.

## Host declaration witness

The instrument declares a custom `HostPolygon` operator whose existing CE
`compile` handler returns a dictionary expression with `__tag: "polygon"`
and a `geom` field carrying the operand. This is a reduced probe in which
the operand already contains the interleaved coordinates.

- A single fixed-size record already compiles and returns the host's tag.
- A single record whose geometry comes from a runtime-sized `Take` declines
  with “a record with a field of a run-time length.”
- A comprehension of even fixed-size records declines with “a record made
  in a build, a filter or a random frame.” The runtime-sized variant also
  declines.

## Design

User decision 2026-11-27: Tycho owns the mapping from `Polygon` to a
record with the `"polygon"` tag and owns the corresponding mappings for
its other geometry. CE should supply one generic mechanism that compiles
those host declarations. Use only the declared tag and field values to
emit the result. The compiler should have no branch for Polygon or for
other specific drawing operators.

Extending ordinary record lowering is an option if it supports the same
cases and bounds as the current Polygon path. A generic result-boundary
declaration that emits tagged records from compiled numeric rows also
fits. Either should handle one record, literal lists, and comprehensions
with source order, empty members and undefined slots intact. Preserve
existing parsing and results during migration. The current built-in
Polygon behavior is the parity reference for the new mechanism.

Tycho can declare a tag itself. A nominal tuple control with
`__tag: string` and a constructor that supplies `"Figure"` returns
`{ __tag: "Figure", kind: "polygon", geom: [...] }` on CE 0.204.0.
Engine-generated nominal tags are outside this request.

The instrument adds the same field to the real notebook prelude in
memory, then checks both direct-return witnesses. The constructor call
still declines on its `opts` dictionary, and the captured Figure still
declines on its string-list field. Assess those concrete restrictions
for JavaScript results. Tycho owns whether to add a field to the
production declaration or adapt the record at its result boundary.

## CE answer

Confirmed P4. Keep this in needs-design for a JavaScript result-boundary
extension to the existing operator `compile` handler. The handler already
maps a host operator to an expression. In the instrument, returning a
`Dictionary` with an explicit `__tag` and fixed-size `geom` works. The
CE-1894 implementation is a built-in Polygon path that writes the literal
`"Polygon"` in the JavaScript printer. It has no host mapping table.

Ran the instrument against the current source. The fixed-size dictionary
control compiled. A runtime-length field and a comprehension of fixed-size
records still declined at their respective record restrictions. The
notebook's draw host call still received boxed Figure MathJSON. The
direct-return call stopped at the dictionary-valued `opts` parameter,
which is a function-call restriction. The captured Figure stopped at the
string-list field, which the JavaScript profile's string-list consumer
check rejects inside a record. Adding a tag leaves both limits in place.

Recommend accepting the handler's existing dictionary expression at the
JavaScript result boundary, starting with a statically known tag and keys
and numeric fields of settled rank. Build the variable-length numeric rows
in the comprehension and assemble the declared records at return. Use the
same path for the built-in compatibility mapping so callers still receive
`"Polygon"` by default, while Tycho's mapping supplies `"polygon"`. A
general record-lowering change would also affect helper calls and other
record consumers, which the geometry witnesses do not require.

The acceptance test should include Tycho's real input, a runtime-length
list of 2-D points, since the host declaration probe supplies preflattened
coordinates. A numeric comprehension over point indices using `PointX`
and `PointY` compiled in a probe. `Flatten` of the list of point tuples
declined. Until adoption, Tycho can keep the existing Polygon path, its
vertex-materialization fallback, and the working notebook draw host call.

## Migration decision

The user approved the generic JavaScript result path and removal of the
built-in drawing operator, including its LaTeX entry. Tycho owns the
operator declaration, syntax, coordinate conversion, and tag. Its
existing `Figure` declaration and boxed notebook draw path can stay on
the host side.

The compiler now accepts the dictionary returned by a host `compile`
handler at the JavaScript entry result and in direct lists and
comprehensions. The regression tests cover a handler that interleaves
runtime-length lists of 2-D points, tags and fields chosen by the host,
and preservation of zero-length fields and non-finite slots.

An adapted run of the Tycho instrument compiled all four host result
controls against the new source. A separate probe declared the removed
drawing head with `ce.declare()` and restored its LaTeX spelling with
`ce.latexSyntax.addEntries()`. The compiled value used the host's tag.
The notebook draw control still passed. The two direct Figure return
witnesses continue to decline at the dictionary parameter and the
captured string-list field.
