The interpreter fails with "Filter predicate must return "True" or "False"." on a function that inserts tuples into a sorted list.

## Witness

`executeEpsil(new ComputeEngine(), …)` (the interpreter only):

```
const all: list<tuple<number, number, number, integer>> = [(1.5, 0.0, 0.0, 1), (2.5, 0.5, 0.0, 1), (3.5, 0.1, 0.2, 2)]
function g(all: list<tuple<number, number, number, integer>>, first: integer, last: integer) {
  let out: list<tuple<number, number, number, integer>> = []
  for c in all {
    if c[4] >= first && c[4] <= last {
      let i = count(out, e => e[4] < c[4] || (e[4] == c[4] && e[1] <= c[1]))
      out = [...take(out, i), c, ...drop(out, i)]
    }
  }
  out
}
g(all, 1, 1)
```

0.193.0 and 0.194.0 (933bda7): `["Error", "'Filter predicate must return
"True" or "False". '"]`. Each part alone evaluates: the `count` with the
same predicate over a one-element `out`, and the spread rebuild with a fixed
index, also in one loop. Not a regression: on 0.193.0 the compiled route ran
this function and the interpreter never did. Since 0.194.0 declines the
function (CE-1481), Tycho's prelude falls to the interpreter and meets it.

## Expected

`[(1.5, 0, 0, 1), (2.5, 0.5, 0, 1)]`: the generation-1 tuples, sorted by
their first component.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1480-ce1481-ce1482-showcase-prelude-probe.mts` in Tycho. `CE-1482: READY` when the witness gives that list.
NOT READY on 0.193.0 and on 933bda7.

## CE progress (2026-11-19)

The witness above gives the expected list on main 367c1236e: commit
50130e4aa9c88d947b9d2cc01a6bfcfa39c803d3 ("Preserve closed Function literals
during evaluation") changed the `Function` evaluate handler. The defect
remains with other data. Smallest reproduction (Epsil):

```
function g(c) { let i = count([2, 3], e => c > 0)
i }
g(4)
// Error("Filter predicate must return "True" or "False".")
```

A bare `count(…)` and an assignment `i = count(…)` give 2; `let` and `const`
fail. Cause: a function literal evaluated in the initializer of a `Declare`
(`declareSteps`, `declareValueSteps` in `src/compute-engine/library/core.ts`)
gets no captured function value (`captureAtCreation`), so `Count` applies
the bare literal and its body reads `c` as a free symbol (`Less(0, c)`). The
issue's witness passes only because its rows share one tuple type, so the
canonical `Filter` rebuilds the predicate with a narrowed parameter that
reads `c`. The fix is in how a literal in a `let` initializer captures the
activation of its scope, the area of the binding workstream: it waits for the
user's go-ahead or for that workstream.

Tycho's instrument compares with `["Tuple", 1.5, 0, 0, 1]`; an Epsil literal
`0.0` serializes as `{"num": "0.0"}` (an inexact real), so the instrument
reads NOT READY even with the right value: it should compare numerically.

## Decision

2026-11-19, the user: deferred after 0.194.2 (the fix is in the capture of a
function literal in a `let` initializer, the binding workstream's area).
