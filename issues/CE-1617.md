A series of the logarithm of an expression with complex coefficients that is on the negative real axis at the point is off by 2πi on one side.

## Witness

At commit `4d9da3765bd5982bd8f48316d2d76171ca2c3554`, the value is `f − Normal(Series(f))`:

```
Series(Ln(-1 - i*x), x, 0, 3)     // ln(−1) + i·x + x²/2 − i·x³/3 + O(x⁴)
                                  // x = −0.01: 0;  x = 0.01: −2πi
Series(Ln(-x - i), x, +oo, 3)     // ln(x) + ln(−1) + i/x + 1/(2x²) − i/(3x³) + O(x⁻⁴)
                                  // x = 50: −2πi;  x = 200: −2πi
```

The witness is `crafted`: the argument has a coefficient that is not real and a negative real leading term.

## Cause and options

The argument of the logarithm crosses the negative real axis, the cut of `ln`, at the point, so the function has a jump of `2πi` there and no series holds on both sides.

1. First program: the Taylor engines of `symbolic/series.ts` (`taylorCoeffs()`) differentiate `ln(g)` at a point where `g` is on the cut. Option: `computeSeries()` declines when a logarithm has, at a finite point, an argument whose value is a negative real number and that is not real for every real `x` (`isRealOnRealAxis()`, added by CE-1442).
2. Second program: `lnLaurent()` writes `ln(c₀·t^m·(1 + h)) = m·ln(t) + ln(c₀) + log1p(h)` for `t > 0`. With `c₀ < 0` and an `h` that is not real, `1 + h` moves the argument across the cut. Option: `lnLaurent()` declines when `c₀` is negative and the argument is not real for every real `x`, also when `bothSides` is not set (the expansion at ±∞ and `laurentData()`).
