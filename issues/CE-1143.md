An Epsil program with a loop that updates a list with `replaceAt` fails with "Maximum call stack size exceeded" when it is the first program that the process runs.

## Witness

At `75e9d6c930ae92f0082b1195d2a3a5e81d58f065`:
`npx jest -w 1 test/epsil/parallel-for.test.ts -t buddhabrot` fails. The
sequential form of the program (`L = replaceAt(L, c, L[c] + 1)` in nested
`for` loops, `step(step(H_0, 40), 40)`) gives the diagnostic `runtime-error`,
"Maximum call stack size exceeded". The `parallel for` form with `+=`
gives the value. With `node --stack-size=4000`, both forms give the value.
In the full test file the test passes, because the tests before it run
first in the same process. With `CE_EFFECTS_PARANOID=1` it fails also in
the full file.

Probability `medium`, not the `high` of a corpus witness: the program is
the sequential form of a reduced showcase program, and it fails only in a
process that has not run other programs first.

## Cause and options

Not investigated. The depth of the JavaScript stack that the interpreter
uses for this program is near the default limit of Node, so the result
depends on the size of the frames, which changes with the optimization
state of the functions. Find which recursion grows with the number of loop
turns or of `replaceAt` updates, and make it iterative.
