A host whose language reads a list at the floor of the index, with no reading from the end, has to wrap every index in two or more operators, which makes each read up to three times slower to create and to evaluate.

## Witness

From Tycho's row MK (mechanism 3 of `MK_DESMOS_LIST_REWRITE.md`; the states
`art/njncrg9fkv` and `neyret/urbddymicb` show the size, see CE-1367). Tycho
measured 300 reads `At(P, …)` in the interpreter: plain 22 ms,
`Max(Floor(…), 0)` 60 ms, `(F + |F|)/2` 75 ms; at machine precision 5, 33
and 55 ms.

What `At` does today (working tree of main at
`3b0b23f414e90ada33e633cb641cd9a8fb3c8ef6`), with `P = [10, 20, 30, 40]`:

| Index | 2 | 2.5 | 2.9999999999999996 | 0 | -1 | 5 | 0.5 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `At(P, i)` | 20 | `NaN` | `NaN` | `NaN` | 40 | `NaN` | `NaN` |
| `At(P, Max(Floor(i), 0))` | 20 | 20 | 20 | `NaN` | `NaN` | `NaN` | `NaN` |

The description of `At` states both rules: a negative index counts from the
end, and an index that is provably not an integer selects no element. No
operator and no option gives "floor, no reading from the end, absent below 1"
in one node. The JavaScript runtime has `_SYS.atNoWrap`
(`compilation/javascript-runtime.ts`), for a host that replaces the lowering
of `At`: no negative index, no mask, but an integer test and no floor, and no
operator of the library emits it.

Measured, 300 reads `At(P, w(1 + Mod(a + k, 4)))` with `a: real` equal to 2
and `k` from 0 to 299, each read boxed and evaluated alone, best of three,
in ms (box, evaluate):

```ts
ce.declare('P', { type: 'list<real>', value: ce.box(['List', 10.5, 20.25, 30.125, 40.0625]) });
ce.declare('a', { type: 'real', value: 2 });
const idx = (k) => ['Add', 1, ['Mod', ['Add', 'a', k], 4]];
const exprs = Array.from({ length: 300 }, (_, k) => ce.box(['At', 'P', ['Max', ['Floor', idx(k)], 0]]));
exprs.map((e) => e.evaluate().re);
```

| Form of the read | precision auto | machine precision |
| --- | --- | --- |
| `At(P, i)` | 15.6, 6.7 | 13.1, 4.2 |
| `At(P, Max(Floor(i), 0))` | 22.3, 8.1 | 19.8, 6.1 |
| `At(P, Clamp(Floor(i), 0, +∞))` | 21.7, 7.1 | 20.2, 5.9 |
| `At(P, (F + |F|)/2)`, `F = Floor(i)` | 49.2, 18.6 | 43.3, 15.5 |
| `At(P, Max(Floor(i + c·Max(1, |i|)), 0))` (Tycho's snapped index) | 42.8, 18.4 | 40.1, 14.9 |
| a host operator with a JavaScript `evaluate` handler | 11.9, 5.1 | 12.2, 4.0 |
| a host function in MathJSON, `dat(P, i)` | 12.2, 19.5 | 11.4, 17.7 |

The times are proportional to the number of reads (1,200 reads: three to
four times each number). Tycho's 60 ms for `Max(Floor(…), 0)` matches the snapped index
(2.8 times the plain read here), not the bare `Max(Floor(i), 0)` (1.3 times).

## Request

A native read with the Desmos rule (one node: floor, no reading from the end,
absent below 1), so that a rewrite does not wrap every index.

## Cause and options

Nothing is slow by itself: each added node costs its own boxing and
evaluation, and the element-wise form `(F + |F|)/2` writes the index twice.
`Max(Floor(i), 0)` is not element-wise: `Max` reduces a list of indices to
one number (`At(P, Max(Floor([2.5, -1, 0.5, 9]), 0))` is `NaN`), so a list of
indices needs `Clamp(Floor(I), 0, +∞)`, which gives `[20, NaN, NaN, NaN]`.

Options, for the day the request is taken up again:

- (a) A library operator, for example `AtFloor(xs, i)` (a name to choose):
  evaluate handler, type handler as `At`, lowering on each target (JavaScript
  can reuse `_SYS.atNoWrap` with a floor). Size M.
- (b) An option of `At`, for example `At(xs, i, {index: "floor"})`: one
  operator, but every reader of `At` (the canonical handler, the gather and
  mask cases, the compilers) must read the option. Size M to L.
- (c) No engine change: the host declares the read once, as a function in
  MathJSON or as an operator with its own handlers (what Tycho had before row
  MK). See the CE answer.

## CE answer

CE (`ce-compiler`, 2026-11-16): P3 (a request with a workaround). Disposition:
deferred by the user on 2026-11-16, see the Decision; no engine change.

Workaround, measured. For a scalar index, `At(L, Max(Floor(i), 0))` written
in place costs 1.3 times the plain read (30 ms against 22 ms for 300 reads,
box and evaluate). A list of indices needs `At(L, Clamp(Floor(I), 0, +∞))`
(29 ms for 300 reads, measured with a scalar index); the profile `ir`
declines `Clamp` ("the operator Clamp is not in the slice"), the existing
compiler compiles it.

The form to evaluate first is a host function written in MathJSON, called at
each site and not expanded at canonicalization:

```ts
ce.declare('dat', { type: '(list<real>, real) -> real',
  value: ce.box(['Function', ['At', 'L', ['Max', ['Floor', 'i'], 0]], 'L', 'i']) });
```

- Values on `[10, 20, 30]` at `i` = -1, 0, 0.5, 1, 1.5, 2.9, 3, 4: `NaN`,
  `NaN`, `NaN`, 10, 10, 20, 30, `NaN`, in the interpreter, with the existing
  JavaScript compiler and with `compile(…, { profile: 'ir' })`.
- It compiles on GLSL and on `interval-js` with the profile.
- Without the declared signature (`ce.assign('dat', …)`), the profile
  declines on the three targets: "the parameter L of dat is not a scalar
  (dictionary<any> | indexed_collection<any>)".
- Interpreter cost of 300 reads: box 12.2 ms, evaluate 19.5 ms. The total
  (32 ms) is the total of the in-place wrap (30 ms); the call moves the cost
  from boxing to evaluation, and each site is one node in the tree, which is
  what the compile time of CE-1367 depends on.
- Tycho's tolerance term (`i + c·Max(1, |i|)`) goes inside the function body,
  written once.

## Decision

User decision 2026-11-16: "Let's defer the native operators for now, but keep in mind we might need to revisit: some users other than Tycho may have used them and depending on how the migration to pure JSON works for them we might need to reconsider." Revisit when the migration of hosts from custom handlers to plain MathJSON (Tycho's and other users') shows that the existing forms are not enough.
