A selector of a tuple with a slot of type `unknown` is an `incompatible-type` error at boxing. The generic parameter of the selector is solved from the known slots, and then the `unknown` slot is refused. The argument check admits an `unknown`-typed argument at a typed parameter (`docs/TYPE-SYSTEM.md`, "Declared types and absence"), but it does not admit an `unknown` slot nested in the argument.

## Witness

```js
ce.declare('w', 'unknown');
ce.box(['Rest', ['Tuple', 'w', 1, 2]]);
// Rest(Error(incompatible-type, "indexed_collection<integer> | string",
//            "tuple<unknown, integer, integer>"))
```

The same error, with a function that returns its untyped parameter in a
tuple (a parametric curve):

```js
ce.assign('g', ce.parse('t \\mapsto (t, t^2, t^3)'));
ce.box(['Rest', ['g', 'u']]);   // the same error; also Most, Take, Drop, Reverse, RotateRight
```

The first program gives this error at main `d2f392f08`. The second one
gives it after decision D15 (nothing is inferred for a parameter from the
body), because the signature of `g` is then
`(t: unknown) -> tuple<unknown, number, number>`. Before D15 it was
`tuple<number, number, number>`. Tests:
`test/compute-engine/tycho-row-424-selectors-and-zero-points.test.ts`, "a tuple".
