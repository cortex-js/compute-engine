A unit whose name is also a function name, such as `lb` or `min`, cannot be written bare, and a unit written as a string is not accepted as the target of a conversion, so a quantity cannot be converted to minutes.

## Witness

Epsil CLI, main 3400041f5:

- `quantity(1, lb)` gives `1 Lb` and `quantity(1, min)` gives `1 Min`: the
  names resolve to library functions (`arcsec` too; `in` is a keyword).
- `unitConvert(quantity(2, h), min)` and `unitConvert(quantity(1, lbf), N)`
  give "Runtime error: incompatible type: ".
- `quantity(1, "lb")` works, and `unitConvert(quantity(1, "lb"), kg)` gives
  `0.45359237 kg`, but a string target stays unevaluated:
  `unitConvert(quantity(2, h), "min")` and `unitConvert(quantity(1, "lb"), "kg")`.
  `isCompatibleUnit` and `unitDimension` do the same with a string.

## Cause and options

Fix: `UnitConvert`, `IsCompatibleUnit` and `UnitDimension` accept a string
unit, as `Quantity` does; this is the workaround for every clashing name.
Separately, `Quantity` and `UnitConvert` could read a unit operand that is a
symbol bound to a library function as the unit of that name.
