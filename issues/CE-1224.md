The JavaScript compiler writes the selected branch of an `If` with a constant condition without parentheses, so an operator around the `If` binds to a part of the branch.

A condition has a constant type when it compares literals, or when a
ranged type decides it (`If(0 <= p·p, …)`, a slider value substituted into
a condition). The `numeric-kernel` profile declines a three-operand `If`
whose condition has a constant type and whose selected branch is not a
symbol or a number ("… has a condition of a constant type, and the
existing compiler writes the branch … that it selects with no
parentheses").

## Cause and options

Not investigated. The existing compiler selects the branch of a constant
condition with `booleanClaim()` (`compile-conditions.ts`); the
three-operand `If` path then returns the code of that branch as if it
were a primary, while the two-operand `If` and the `Which` paths keep the
parentheses. Option: wrap the selected branch's code as those paths do.
When it is fixed, remove `refuseUngroupedSelection()` from
`javascript-fragment-target.ts`.
