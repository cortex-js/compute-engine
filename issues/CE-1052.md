The third derivative of a user function computes the first and second derivatives again, so it takes about twice as long as needed.

## Witness

```
f := x ↦ √(x + √(x + … + √(x + 1)))     (depth 8, assigned with ce.assign)
Derivative(f, 1).evaluate()   43 ms
Derivative(f, 2).evaluate()   1,771 ms   closed form
Derivative(f, 3).evaluate()   3,366 ms   declines, after it repeats order 2
```

## Cause and options

The `Derivative` handler (`library/calculus.ts`) calls `derivative()` in a
scope it discards, with the hole `_`. The recorded iterates depend on `_`; the
next request declares `_` again, so `readsOwnDefinition()` rejects them and
the search for a lower order finds nothing. Option: reuse one definition of
`_` per function literal, or keep the simplified iterates in the memo of
`memoizedDerivativeResult()` and pass the highest valid one to `derivative()`.
