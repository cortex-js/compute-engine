In shipped Desmos documents, a curve that reads a list of random numbers loses its interval drawing and is drawn point by point, so a narrow peak or a jump can be drawn less exactly.

## Witness

Bare `ComputeEngine` 0.204.3, fresh engine per shape, `x: real`, compile with `{ to: 'interval-js', iterationBudget: 1e6 }`:

```
h := WithRandomSeed(660536, RandomChoice(Interval(0, Open(1)), 400))       // Desmos h=random(400)
Sum(Cos(x·2^i + 2π·At(h, i + 1)) · 2^(−i), Limits(i, 0, 10))
  -> "program: a list whose length is not one number on interval-js"

C := −1 + 2·WithRandomSeed(160521, RandomChoice(Interval(0, Open(1)), 7))  // Desmos C=2random(7)-1
Sum(At(C, i + 1) / i! · x^i, Limits(i, 0, Length(C) − 1))
  -> the same decline
```

Controls, same engine:

- the same two expressions on `javascript` compile and give the interpreter's value at x = 0.3 and 1.7 (1.173586141974973 and 0.6533156293496106 for the first);
- the first expression on `interval-js` with `h` a literal list of 400 reals compiles, and its intervals hold the interpreter's value at both points.

The count of each draw is a literal (400, 7), so the length of the list is one number.

Corpus: 3 records in 2 documents of the Tycho 0.204.3 codegen audit (neyret/vwbagbcerj `o(x)` and `s(x)`, neyret/yvwfq1kpio `P(x)`). Tycho draws these rows on the `javascript` lane, which is the workaround. These are the shapes we found.

Not this issue: neyret/cf56wfb4cm `H=random(4N)` with `N` an input. Its length reads an input, so on interval-js it is not one number, and the decline looks correct.

## Cause and options

`compilation/ir/README.md` (the paragraph on `WithRandomSeed(537911, Random())`) says that a held value of seeded draws over literals gives its interpreter value as a literal "under the same conditions", and those conditions exclude the interval mode. The held value is then lowered as written, and `plain.ts` refuses the list made in the frame ("a list whose length is not one number").

1. In the interval mode, take the interpreter's value of such a held value as a literal list of point intervals, as for a literal list. That is the same value the javascript target uses. Size S.
2. Keep the exclusion, and change the message to say that a seeded draw is not compiled in the interval mode, so that a host can see the reason.

Tycho half on adoption: none. The rows go back to the interval-js lane without a code change.

## CE answer

CE (2026-11-28): P3 confirmed. Fixed by option 1 in the working tree of
compute-engine-94, not yet committed: in the interval mode too, a held value of
seeded draws over literals is its interpreter value, a list of point intervals
(`seededFold()` of `lower.ts`), and so is the library's arithmetic of numbers
and such frames (`C := 2·WithRandomSeed(…) - 1`). The instrument reads READY on
the CE source. The workaround (the javascript lane) holds until the release.
