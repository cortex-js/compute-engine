Defining three functions that call each other in a cycle never finishes and runs out of memory.

## Witness

Each head declared `function`, then assigned in order:

```
a_2(n) = {n <= 0: 1, c_2(n - 1) + b_2(n - 1)}
b_2(n) = {n <= 0: 1, c_2(n - 1) + n^2}
c_2(n) = {n <= 0: 1, a_2(n - 1)}
d_2(x) = a_2(3) + x^2
```

On 5b9f88cf5 (and 0caa86406, the parent of cbd971112) this takes about
0.5 s and `d_2(1)` is 8; from cbd971112 on, `assign('d_2')` never returns
(Tycho: about 4 GB after 5 minutes). Turning off only the early return that
cbd971112 added to `_deriveSignatureOnce` (`if (v._isTypeInFlight?.()) {
noteReentrantSignatureRead(); return … }`) restores 0.5 s and the same
values.

## Cause and options

Inferred from the code, not traced: `noteReentrantSignatureRead()` with no
owner taints every active derivation frame
(`declared-parameter-result.ts`, "Conservatively taint all active signature
derivations"), and a tainted frame stores no `_signatureMemo`. In a cycle of
three heads each derivation reaches a literal whose type is in flight, so no
head is ever memoized and each derivation derives the others again.
Options: (a) pass the owner, `noteReentrantSignatureRead(this)`, so only the
frames opened after this definition's are tainted; (b) remove the early
return. Both are in the binding workstream's code: its owner decides.
