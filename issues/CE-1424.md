The interpreter evaluates `Random()` twice in `Tan(Arctan(Random()))`, so a seeded frame that holds it skips one value of its sequence.

## Witness

At `0ebd83c66e07630cc2c9b51ddad8dbafd6056c6e`, `new ComputeEngine()`:

```ts
ce.box(['WithRandomSeed', 7, ['List', ['Random'], ['Random'], ['Random']]]).evaluate().N();
// [0.08483070468009213, 0.19562714896013578, 0.24148300073452322]
ce.box(['WithRandomSeed', 7, ['List', ['Tan', ['Arctan', ['Random']]], ['Random']]]).evaluate().N();
// [0.19562714896013578, 0.24148300073452322]: the first value is the
// second draw, and the next draw is the third
ce.box(['WithRandomSeed', 7, ['List', ['Sin', ['Random']], ['Random']]]).evaluate().N();
// [sin(0.0848…), 0.19562714896013578]: one draw, as expected
```

The boxed form is `Tan(Arctan(Random()))` (no canonical rewrite), so the
second draw happens during evaluation. Compiled code draws once
(`WithRandomSeed(7, x + Tan(Arctan(Random())))` gives 0.0848… + x on the
profile `ir`), so it differs from the interpreter for such a frame.

## Cause and options

Not read. Probably a rule that evaluates the argument of `Tan` to test
`Tan(Arctan(u)) = u` and then evaluates `u` again. Fix: evaluate the
argument once (or apply the rule to the unevaluated argument only when it
has no effect).
