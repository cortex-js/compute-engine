At a high precision, the sum of a complex special-function value and a constant such as γ or π shows many more digits than are correct.

## Witness

With `ce.precision = 50`,
`ce.function('Add', [ce.function('Digamma', [ce.number(ce.complex(-1, 1e-20))]), ce.symbol('EulerGamma')]).N()`
gives
`["Complex", {"num": "0.99999999999999876060651209008240243104215933593992"}, 100000000000000020000]`.
Only the first 15 digits of the real part are right: the value is about
`1 + 2.0e-41 + 1e20i` (mpmath, `psi(0, 1e-20j - 1) + euler`). The same
happens with `Add(Digamma(2 + i), Pi)` and
`Subtract(Zeta(2), HurwitzZeta(2, 2 + i))`. `HarmonicNumber`, which built
these sums, evaluates them at machine precision since CE-1585.

## Cause and options

The complex kernels (`polygammaComplex`, the complex `Zeta` and
`HurwitzZeta`) return a machine complex number. `Add` cannot tell it from an
exact complex literal such as `1 + i`, so it adds the constant at the working
precision and keeps its 50 digits. Options: (a) mark the value of a machine
kernel as inexact at machine precision, and round a sum with such an operand
to machine precision; (b) give the complex kernels a big-decimal route.
(a) changes the arithmetic of every complex float above machine precision.
