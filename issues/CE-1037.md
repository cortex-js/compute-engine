A running sum over the rows of a matrix, built from separate parts, reports the type of a list of numbers, although its values are rows.

## Witness

```
fn  = ce.box(['Function', ['Add', 'a', 't'], 'a', 't'])
src = ce.box(['List', ['List', 1, 2], ['List', 3, 4]])
ce.function('Scan', [src, fn, ce.box(0)]).type     ->  vector<2>
ce.function('Reduce', [src, fn, ce.box(0)]).type   ->  number
values: [[1, 2], [4, 6]] and [4, 6] (correct)
ce.box(['Scan', src, fn, 0]).type                   ->  matrix<2x2> (correct)
(probe 2026-11-06, HEAD 20790ad269449b3e08ce8ce1ccd515d1ec4d8ef1)
```

`npx tsx scripts/probe.ts --json --routes` on the `Scan` program reports
"ROUTES DIFFER" for this reason. The compiled form declines on the
`ce.function` route, so no wrong compiled value was seen.

## Cause and options

Not investigated. On the `ce.function` route the function literal is
canonical before `Scan` sees it, so its parameter `t` keeps the type
`unknown` and its result type is `number`; the `ce.box` route types `t` from
the collection. Option: let the canonical handler of the folds type the
parameters of an already canonical function literal from the collection, as
the `ce.box` route does.
