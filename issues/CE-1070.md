In Epsil, an error in the body of a called function can underline an unrelated part of the statement that calls it.

## Witness

```
function g(x) { Ln(x) + 1 }
let y = 5
let v = y + g("a")
frames     ->  Ln argument 1, Add argument 1, Add argument 2
underline  ->  y          expected: g("a")

function g(x) { Ln(x) }             let v = Ln(y) + g("a")   ->  y
function g(x) { (e) => e * x }      let h = g("a")
                                    let v = 3 * y + h(2)     ->  y
let w2: any = Sin(q)   q = "a"      let v = w2 * Sin(x)      ->  x   expected: w2
```

The last program also fails with `Ln` in place of `Sin`.

## Cause and options

The breadcrumb has no frame for the call of `g`, so the frames of the body
come first, and `locateError()` (`src/epsil/error-location.ts`) matches
each frame to a call of the statement by operator name. The body frame
`Add argument 1` selects the `y` of the statement. Options: (a) the call of
a user function adds a frame that marks the end of its body, and the
locator drops the frames before it; (b) the locator checks each frame
against the argument of the next outer frame; a first attempt failed where
the statement does not write the canonical operator (`Exp` is `Power`).
