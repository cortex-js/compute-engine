An error inside a product names the wrong argument, so Epsil underlines the whole product instead of the part that failed.

## Witness

```
let s: any = "a";   Sin(s) * Cos(x)        (order of the operands: Sin(s)·Cos(x))
error frames  ->  Multiply argument 2, Divide argument 1
expected      ->  a frame that names Sin(s), Multiply argument 1
```

## Cause and options

`Add` and `Multiply` are lazy: their handler evaluates the operands, and
`_computeValue()` (`boxed-expression/boxed-function.ts`) reads the error out of
the result tree with `errorValue(result)`. So the index counts the operands of
the result, not of the call. The Epsil error location does not trust such an
index and underlines the whole call (`Sin(u) * Ln(w)`), unless only one
written operand can make an error. Fix: a frame that names the canonical
operand, found with `errorEvaluatedFrom` as `_deferredErrorFrame()` does.

This is CE-105.1. The other parts are CE-920 (CE-105.2) and CE-921
(CE-105.3). See also CE-109.
