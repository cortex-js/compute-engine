Some engine walks take time exponential in the depth of a tree that shares its operands, also when the compiled code is linear.
```

### Witness

A tower `t_k = F(t_(k-1), t_(k-1))` with one node object as both operands
(2^d paths, about d nodes). Times on `881716b15` plus the route fix, one run:

| Program | Walk | d = 16 | d = 18 | d = 20 | d = 22 |

| `unknowns` of `NIntegrate(Function(t, x), 0, 1)`, same `t` | same | 6 ms | 20 ms | 80 ms | |

| `compile()` of `t_k = _fn(If, t > 0, t, -t)` (declines) | the same, from `isSelectionScalar()` of `unrollFixedWidthCollections()` | 338 ms | 3.1 s | | |

Boxing the `If` tower is exponential too (1.5 s at depth 18).

Without sharing, `unknowns` of a tower outside a `Function` literal is
linear (0.1 ms at depth 20), so the memo of the walk is lost under a binder.
`loopBodyYieldsValue()` recurses into `structure.children` with no visited
set. The `numeric-kernel` profile reaches the same walks
(`prepareCompilation()` of `javascript-target.ts` reads `expr.unknowns`;
`aggregateBoundRefusal()` calls `bound.N()`).

### Cause and options

Each walk descends each operand of a node independently. Fix: a visited set
or a per-call memo keyed by node object in `getUnknowns()` under a scoped
node, in `loopBodyYieldsValue()`, and in the canonical form of `If`; `N()` of
a shared nested `Add` holds the flattened `2^d` terms, which needs the
evaluation memo of CE-601 on that path (not checked). Witness strength
`crafted`: the towers are built in code with one node object as both
operands; no corpus program was searched for this form.
