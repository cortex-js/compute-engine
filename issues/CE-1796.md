A loop that writes the elements of a long list one at a time is slow in the interpreter, and with a list of 20 000 elements it ends with the error "Maximum call stack size exceeded".

## Witness

At commit `cc0809c8976820647672d97c41337982a320dc3a`, with
`npx tsx src/cli/epsil.ts --time-limit 0 <file>`:

```
let fb: list<integer> = [0 for k in 1..20000]
for k in 1..2000 { fb[k] = k % 256 }
fb[2000]
```

The result is `Error(ErrorCode("internal-error", "Maximum call stack size
exceeded"))` after about 9 seconds; the expected value is `208`. Measured on
the same machine:

| List length | Writes | Result  | Elapsed |
| ----------- | ------ | ------- | ------- |
| 5 000       | 2 000  | `208`   | 2.7 s   |
| 20 000      | 2 000  | error   | 9.0 s   |
| 64 000      | 50     | `50`    | 1.3 s   |
| 64 000      | 2 000  | error   | 20.7 s  |

The elapsed times include about 0.6 s to start the process. The same program
compiled (`--compile`) gives `208` with no measurable run time.

`plausible`: a sieve, a histogram or a grid of cells filled by a loop is such a
program. There is no general workaround: a comprehension replaces the loop
only when each element is computed independently of the others.

## Cause and options

Not investigated past the stack of the error, which ends in
`BoxedFunction.isCollection` ← `isUnindexedCollectionValue` ←
`hasUnindexedSource` ← `at` (`library/collections.ts`) ← the `At` evaluation in
`boxed-function.ts`. The reading: `fb[k] = v` is `Assign(fb, ReplaceAt(fb, k,
v))` (`docs/EPSIL-LANGUAGE-MODEL.md`, "Parallel loops and compound
assignment"), and the variable holds a value whose read goes through the
earlier values, so the cost of a write grows with the length of the list and
the depth of a read grows with the number of writes.

Option: when `Assign` stores the result of `ReplaceAt` of the variable's own
value, store a materialized list (one copy, O(n) per write, no depth). A write
in O(1) needs the interpreter to own the array of a list variable, as the
JavaScript target does for a block local (`docs/COMPILATION-MODEL.md`, "List
updates").
