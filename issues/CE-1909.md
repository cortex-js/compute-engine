A function written in place and applied to a list of points does not compile, although the interpreter gives a value.

## Witness

Tycho's codegen audit of CE 0.204.1: 16 records of `neyret/51a4237846`
(#6134 and the others of its rows). Repro:
`~/dev/tycho/_TASK/desmos/desmos-corpus/codegen-audit/repros-0.204.1/6134-51a4237846.mts`.
In that row the parameter is written `Typed(v, "collection<any> | tuple")`.
CE writes it: the document preparation (`prepare()`,
`document-preparation/prepare-document.ts`, the `openSlot()` normalization)
replaces an untyped parameter with its open inferred type, so the compiler
reads a declared union (traced by Tycho on 0.204.1:
`~/dev/tycho/_TASK/desmos/desmos-corpus/codegen-audit/repros-0.204.1/prepare-trace.mts`).
Without the annotation, the row still declines. A program of CE alone:

```js
ce.declare('p', 'list<real>'); ce.declare('q', 'list<real>');
const f = ['Function', ['Tuple', ['Add', ['PointX', 'v'], 1], ['Multiply', 2, ['PointY', 'v']]], 'v'];
compile(ce.box(['Apply', f, ['PointList', 'p', 'q']]), { to: 'javascript' });
// declines: "PointList(p, q): a list or a tuple argument of Apply (the interpreter may map the function over it)"
// With Typed(v, "collection<any> | tuple") as the parameter: "a parameter of Apply whose type is not a scalar, a list or a tuple of numbers"
```

With `p = [1, 2]` and `q = [3, 4]` the interpreter does not map: it binds the
point list whole and gives `Tuple(List(2, 3), List(6, 8))`.

## Cause and options

The `Apply` case of `ir/lower.ts` (about line 3800) declines a list or tuple
argument of a literal whose parameter has no settled type, because the
interpreter maps a literal of scalar parameters over a list
(`applyLiteralMaps()`). A parameter that the body reads with `PointX` and
`PointY` is not scalar, so the interpreter binds the argument whole. Option:
when the body reads the parameter as a point (the case `define()` already
handles for a named user function, `pointLength()` and `paramsAreScalar`),
bind the argument whole with the argument's shape. Both parts are needed: the
compiler reads the `Typed` union that `prepare()` writes as a declared union,
which declines by the shape rule (R5). Either `prepare()` leaves a union that
is open (no settled shape) unwritten, or the compiler reads a `Typed` that
`prepare()` wrote as loose, as it reads the parameter of a named user
function (`loose()` in `ir/lower-functions.ts`).
