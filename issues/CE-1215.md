`Norm` of an element of a list of tuples has the type `list<number>`; its value is one number.

## Witness

At `3177128ed`, with `LQ: list<tuple<real, real>>` and `P: tuple<real, real>`:

| Expression | The type of the operand | The type of the `Norm` |
| --- | --- | --- |
| `Norm(At(LQ, -1))` | `tuple<real, real>` | `list<number>` |
| `Norm(At(LQ, 1))`, `Norm(First(LQ))` | `tuple<real, real>` | `list<number>` |
| `Norm(P)` | `tuple<real, real>` | `+oo \| nan \| real` |
| `Mean(At(LQ, -1))` | `tuple<real, real>` | `number` |

With `LQ = [(3, 4), (6, 8)]`, `Norm(At(LQ, -1)).evaluate()` is `10`: one
number, which the type `list<number>` does not admit.

In compiled code, the existing JavaScript compiler reads a value of a type
that admits a list with `_SYS.bcast`. So `x · (2 / Norm(At(LQ, -1)))` is
`_SYS.bcast((_tv1, _tv3, _tv4) => { const _tv2 = ((_tv3) / (_tv4)); return
(_tv1 * _tv2); }, _.x, 2, _SYS.norm(_SYS.atPoint(_.LQ, -1, 2)))`, which
computes `x · (2/n)`, where `Norm(P)` gives `_.x * 2 / _SYS.norm(_.P)`. At
`x = 0.1`, `LQ = [[0.1, -3], [2.5, 1/3], [-0, 7]]` the two orders give
`0.02857142857142857` and `0.028571428571428574`. The `numeric-kernel`
profile declines a `Norm`, `Mean`, `Median`, `Variance` or `Dot` whose type
admits a list, because of this type.

## Cause and options

The type handler of `Norm` (`library/linear-algebra.ts`) answers
`list<number>` when `isPointListOperand()` holds. That test reads the
element type of the operand (`d.facts.elementType`, or
`pointCollectionElementType()` of its type); for `At(LQ, i)` the descriptor
seems to carry the element type of `LQ`, a tuple, so the operand is read as a
list of points although its own type is the tuple. Option: test
`isTupleOperand()` on the operand's own type before `isPointListOperand()`
(it is tested first, so it fails for this `At`: check why it does not see
the type `tuple<real, real>` of the node), or read the element type only
from an operand whose type is a collection of tuples.
