When a function parameter is declared `any`, the refusal names the declaration instead of the parameter, so a host that reads the refusal to find the name to declare gets `Typed` and a printed node.

## Witness

`compile(ce.box(['Function', ['Multiply', 2, 't'], ['Typed', 't', "'any'"]]), { profile: 'ir' })`,
and the same with `to: 'interval-js'`: `success: false`, code
`unsettled-shape` (right), but `diagnostic.operator` is `'Typed'`,
`diagnostic.value` is `'Typed(t, "any")'` and `unsupported` is
`['Typed', 'Typed(t, "any")']`. The existing JavaScript compiler gives
`value: 't'` and `unsupported: ['t']`. With two parameters
(`Typed(p, 'any')`, `Typed(q, 'any')`) the profile names
`Typed(p, "any")`; the existing compiler names `p`. A host that reads
`unsupported` (or `value`) to ask the user which name to declare shows a
node, not a name. Workaround: the message text names the input
(`the input t of type any`).

## Cause and options

`input()` in `src/compute-engine/compilation/ir/lower.ts` (the decline
"the input ${name} of type …", reason `UNSETTLED_SHAPE`) calls
`decline(e, …)` with `e` the parameter node, which for a root function
literal is the `Typed` declaration; `decline()` takes the node's text as
`value` and its head as `operator`, and `interpreterFallback()` copies both
into `unsupported`. Fix: for this decline throw
`new Decline(name, cause, undefined, reason)`, so the value is the name and
there is no operator. It changes the JavaScript profile's diagnostic too
(the same lowering), which is why it was not made in the deletion work of
the existing interval target. Size S; the 15 interval-js tests of
`ce-784-declared-top-scalar-targets.test.ts` then check `unsupported` again.
