A substitution into a program that assigns a variable gives an error in place of the assignment.

## Witness

```
If(z > 0, Assign(z, 5), 0).subs({z: 7})
  today: If(7 > 0, Assign(Error(incompatible-type, symbol, 7), 5), 0)
```

## Cause and options

The doc comment of `subs()` says that it replaces exactly the names that
`freeVariables` lists, which include the target `z`. `Assign` refuses `7`.

- (a) Recommended. `subs()` keeps a name target, and each name leaf of a
  `Tuple` target, unless the replacement is a name (`z` → `w` renames it) or
  the key is a wildcard (`_x`, which rules fill with `subs()`). Result:
  `If(7 > 0, Assign(z, 5), 0)`. The doc comment gets this exception. CE-537
  implemented and reviewed it, then removed it. Size S.
- (b) No change: the error stays.
- (c) As (a), and `unknowns` no longer lists a name that is only written
  (`Assign(z, 5).unknowns` → `[]`): a host loses the outer writes.

No decision keeps (b).

## Decision

User decision 2026-11-07: (a)
