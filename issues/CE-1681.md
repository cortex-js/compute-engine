A call by name of a function held in a `let` with no type works at the top level of a program and is an error in the body of a function, and the language guide says it is an error in both.

## Witness

```epsil
let h = (x, y) => x - y
h(y: 2, x: 10)            // no diagnostic; executeEpsil gives 8
```

```epsil
function m() -> number {
  let h = (x, y) => x - y
  h(y: 2, x: 10)          // argument-names-unavailable
}
```

`src/epsil/docs/syntax.md`, "Named arguments": "an **unannotated** lambda
reached through a binding — `h := (x, y) => …` then `h(x: 1, y: 2)` declines,
because type inference drops the parameter names".

## Cause and options

At the top level the variable is a program variable with an inferred type,
and `valueCalleeSignature()` (`boxed-expression/named-arguments.ts`) reads the
signature of the value it holds, with its names. In a function body the
inferred type has no names. Options: (a) the top level declines too, as the
guide says (a program that works today gets an error); (b) the guide states
the top-level case, and the body case keeps the names of an inferred lambda
as well. Editor completion (CE-1664.3) offers no names for such a variable.
