A row that applies a point function to a list of points built from undeclared names is refused, or typed as possibly an error, although one such point is accepted.

## Witness

`X` is `nan | real | signed_infinity`;
`W: (tuple<X, X, X>, unknown) -> tuple<number, X, X>`, `W(p,s) := (s p.x, p.y, p.z)`;
`K: (unknown, unknown) -> list<tuple<integer, unknown, unknown> | tuple<unknown, unknown, integer>>`.
With `a`, `b` undeclared, on 0.182.0:

- `W((a,b,0),2)`: valid, `tuple<…>`;
- `W([(a,b,0),(1,a,b)],2)`: not valid, `incompatible-type`;
- `W(K(a,b),2)`: valid, typed `error | list<tuple<…>>`.

With `a`, `b` declared `real`, both lists are valid `list<tuple<…>>`. Reading:
`CE-1069: NOT READY`.

Requested: the list forms read as the one-point form does (the 0.177.0 rule:
map, then check each point when it is bound), with no `error` member.

Tycho half on adoption: re-run `tests/node/graph-paper/parametric-sampling-names.test.ts`
without the `real` declaration of `t`, `u`, `v` in `_preDeclareDefinitionHeads`
(Tycho's `src/graph-paper/graph/document-ce-manager.ts`); remove it if it passes.
