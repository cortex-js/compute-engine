A document that compares each of 100 distances with their minimum takes about one second to open, most of it in that comparison.

## Witness

`x`, `y` declared `real`, with no value; `P` a literal list of N points; `d`
= `(x - PointX(P))^2 + (y - PointY(P))^2`; `f` =
`Function(Block(Which(Equal(k, Min(d)), 1e9, True, k)), k)`. The time of
`evaluate()` and of reading every element of the value, on c8bc8271e with
the CE-1602 fix (2026-11-20, load 2.3 on 18 cores, `npx tsx` on the source):

| N | `Apply(f, d)` | `Map(f, d)` |
| --- | ---: | ---: |
| 20 | 109 ms | 80 ms |
| 64 | 501 ms | 452 ms |
| 100 | 1,037 ms | 1,009 ms |

With `x` and `y` assigned 0.4 and 0.6: 8, 15 and 23 ms for `Apply`, and 5, 10
and 15 ms for `Map`. So the cost is in the symbolic elements, in both forms:
about 8 to 10 ms for each element. `Map` is faster only while no element is
read.

One condition alone, boxed and evaluated: `Equal(d_1, Min(L))` with `L` the
list of the N distances takes 6.0, 13.5 and 18.3 ms at N = 20, 64 and 100;
`Min(L)` alone takes 9.5, 14.0 and 17.5 ms; `Equal(d_1, m)` with a symbol
`m` takes 0.2 ms.

In the Tycho benchmark of `neyret/lwuwgb9ic5` at N = 100, a CPU profile of
the CE-1602 fix puts 0.83 s of the fan-out probe's 0.96 s in these cells
(`issues/CE-1602.md`, "What remains").

## Cause and options

Not established. The `Min` of N symbolic sums does not reduce, and each
cell pays about the cost of one evaluation of that `Min`, although the walk
of the eager `Apply` keeps the value of a sub-expression that does not
depend on the parameter (`walk-invariant-values.ts`). Option (a): find where
the time of one cell goes with a CPU profile of the witness, and remove the
repeated work. Option (b): keep the value of `Apply` over symbolic elements
in a compact form that shares the body (the direction of the CE-only Map
diagnostic in CE-1602); it changes what `Apply` returns, so it needs a
design.
