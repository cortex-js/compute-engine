In a Tycho notebook, an animation whose timer callback styles a figure with an options dictionary, `t => draw(circle((t, 0), 1, {fill -> "red"}))`, runs interpreted instead of compiled, so it is slower.

## Witness

On CE 0.201.2, the JavaScript target declines a function whose body holds a
dictionary literal; the same body with a tuple compiles (positive control):

```epsil
function f(t: real) { let d = {w -> t, fill -> "red"}; d["w"] + 1 }
f(2)
```

The instrument prints:

```
tuple (control): interpreter 3; compiled 3
Compilation fallback for "f" (target: javascript): Could not compile: {"w" -> t, "fill" -> "red"}: not a number, a symbol or a function
dictionary: interpreter 3; compile declined []
DICT-COMPILE: NOT READY
```

The decline code (compute-engine MCP `compile`) is `outside-profile`.

## Cause and options

Tycho's drawing prelude (version 26) replaced the style methods
`.fill(c)` / `.stroke(c)` with a last options dictionary on each figure
constructor. A callback that writes the literal falls back to the
interpreter; before, `circle(…).fill("red")` in a callback compiled. The
prelude keeps the defaults and its own internals free of dictionary literals,
so a figure built outside the callback still compiles.

Ask: compile a dictionary literal whose keys are string constants and whose
values the target compiles, with `d["key"]` and `d.key` reads, at least where
the type is a `record` (a closed set of keys). Tycho does not need
iteration over keys in compiled code.

Workaround: build the styled figure outside the callback, or accept the
interpreted tick.

Tycho half on adoption: in `src/graph-paper/notebook/drawing/prelude.ts`,
give the options parameters the default `{->}`, let `badOptions` be `[]`,
and fold `figureOptionsLoop` back into `figureStyled`; check that a timer
callback that writes `{fill -> "red"}` compiles (no interpreted note).
