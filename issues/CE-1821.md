The sum and the maximum of a reversed sorted list stay unevaluated when one of the elements is a variable.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.expr(['Max', ['Reverse', ['Sort', ['List', 3, 'x', 1]]]]).evaluate(); // unevaluated, expected max(3, x)
ce.expr(['Sum', ['Reverse', ['Sort', ['List', 3, 'x', 1]]]]).evaluate(); // unevaluated, expected x + 4
ce.expr(['Length', ['Reverse', ['Sort', ['List', 3, 'x', 1]]]]).evaluate(); // 3
```

Read on 0bebdaee7b63afd440151e05c12684ab9151765c. Without the `Reverse`,
CE-1804 made `Sum`, `Product`, `Max`, `Min` and `Count(xs, v)` read the
source of the `Sort`.

Workaround: leave out the `Reverse` or the `Sort`, because the result does
not depend on the order.

## Cause and options

`Sort` cannot order `x`, so it stays `Sort([3, x, 1])`, which is not a
collection. `Reverse` over it is a lazy view: `isCollection` is true, but
it has no element to read. `orderIndependentSource` (`library/collections.ts`)
removes a wrapper only from a value that is not a collection, so it keeps
this view. Option: also remove the wrappers of a view that cannot be
enumerated, when the source below them is a collection. The test of "cannot
be enumerated" (`isEnumerableSource`) can evaluate the view, so the cost of
the test on each sum must be measured first.
