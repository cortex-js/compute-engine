A function that changes its own parameter and then returns a list built from it gives a list of the wrong length and the wrong elements.

## Witness

On CE main 0caa86406:

```
F(p) := Block(Assign(p, [1, 2]), Comprehension(At(p, k), Element(k, Range(1, Length(p)))))
F([10, 20, 30])
// [[1, 2], [1, 2], [1, 2]]; expected [1, 2]
Length(F([10, 20, 30]))   // 3; expected 2
Sum(F([10, 20, 30]))      // [3, 6]; expected 3
```

An Epsil function that reassigns its parameter and then returns a
comprehension over it reaches it. The lazy view keeps the activation of the
call, and the end of the call does not give it the written value of `p`
consistently: the length reads the argument (3 elements), each element
reads the written list.

## Cause and options

In the binding area (the end of a call and the activation a lazy view
keeps): it waits for the binding workstream or the user's go-ahead. The
expected values are those of the call with the comprehension made concrete
(`ListFrom(…)` inside the body).
