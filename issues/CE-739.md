An assignment or a `Return` inside an `If` whose condition is a list gives results that follow no rule.

## Witness

```
L = [-1, -2]:                       Block(p ≔ 0, If(L > 0, p ≔ 5), 2p)    ->  0
M: list<any>, M = [[True, False]]:  Block(p ≔ 0, If(M[1], p ≔ 5), 2p)     ->  10
```

Measured at `e3ca9c1a6`. The same for `Return`, `Break` and `Continue`.

## Cause and options

An `If` or a `Which` with a list condition selects element by element, but an
action has no value per element. A short design document chooses one rule:

- the branch runs when any element is true (`p` is a number; the compiler can emit it);
- a branch with an action needs a boolean condition, and a list there is an
  error (the compiler then declines it as invalid, as it does today);
- the assignment is done per element and `p` becomes a list (changes the type
  of `p`; hardest to compile).

Until then the compiler declines the shape (user decision 2026-11-01, CE-722)
and the results of the interpreter stand.
