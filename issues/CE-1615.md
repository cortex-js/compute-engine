With `evaluateAsync()`, a host function that has only asynchronous evaluation code is not run when its call is a value of a dictionary: the dictionary keeps the call as written.

## Witness

On main `29a48852bbdcc1b00c432a5e5840b691dad7d771`:

```ts
let n = 0;
ce.declare('g', { signature: '() -> integer', pure: false, evaluateAsync: async () => ce.number(++n) } as any);
(await ce.box(['Dictionary', ['Tuple', { str: 'a' }, ['g']]]).evaluateAsync()).toString();
// '{"a" -> g()}', n is 0  (right: '{"a" -> 1}', n is 1)
```

The same call as an entry of a list or of a tuple is run: `['Tuple', {str: 'a'}, ['g']]` gives `("a", 1)`. A host function with a synchronous handler at the same position is run on both routes (`{"a" -> 101}`).

Workaround: give the value to a variable first.
`['Block', ['Declare', 'v', 'integer', ['g']], ['Dictionary', ['Tuple', {str: 'a'}, 'v']]]` gives `{"a" -> 1}`.

## Cause and options

`BoxedDictionary` (`boxed-expression/boxed-dictionary.ts`) has an `evaluate()` and no `evaluateAsync()`. The `evaluateAsync()` it inherits (`abstract-boxed-expression.ts`) calls the synchronous `evaluate()`, which evaluates each value with `evaluate()`, and that cannot run a handler that is asynchronous only.

Fix: an `evaluateAsync()` for `BoxedDictionary` that awaits each value in the order of the entries, with the options of the evaluation (the capability registry, the context stack, the precision window), as `evaluatedListLiteralAsync()` (`listed-element.ts`) does for a list. The once-per-node record of the synchronous route (a dictionary shared by several paths is evaluated once per context) needs the same care on the asynchronous route.
