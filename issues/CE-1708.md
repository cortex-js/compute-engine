The derivative of a long function takes about 1.7 times as long when the function's parameter has the name of the plot variable, such as f(x) = …, as when it has any other name.

## Witness

CE 0.198.1. f(p) = sqrt(p + sqrt(p + … + sqrt(p))), 37 levels (the function
row of `neyret/7kn7eakzkd`); `Apply(Derivative(f, 1), a)` evaluated, median
of three runs on a new engine each:

- `x` declared `real`, parameter `p` (control): about 725 ms.
- `x` declared `real`, parameter `x`: about 1274 ms.
- parameter `x`, `x` not declared (control): about 709 ms.
- as a function row of a prepared Document whose imports declare the input
  `x`: parameter `p` 725 ms, parameter `x` 1284 ms.

The result is the same in all cases (the derivative has no closed form of at
most 10000 nodes, so each answers the unevaluated `Apply`). Only the time
differs.

The instrument prints `CE-1708: READY` when "assign x" and "row x" take at
most 1.25 times their controls.

## Cause and options

Not investigated on the CE side. The cost seems to come from resolving the
parameter against the declared outer symbol of the same name, at each step
of the differentiation.

Why it matters to Tycho: `x` is a declared input (the plot axis) of every
Graph Paper document, so `f(x) = …` is the common spelling, and a prepared
Document keeps the author's parameter names. Tycho gives one derivative
evaluation 1000 ms (`DERIVATIVE_EVAL_BUDGET_MS` in `src/plot/ce-compile.ts`),
so this case goes from 0.8 s (inside the budget) to 1.4 s (cancelled, then
computed again by the compile). Workaround: the host renames the parameter
before it evaluates the derivative.
