Editing a function variable's declaration and running it again can report an argument error against its previous signature although the new function runs correctly.

## Witness

On one engine and in one caller scope:

```ts
executeEpsil(ce, 'let k = (n: integer) => n');
checkEpsil(ce, 'let k = (s: string) => s\nk("b")');
// incompatible-type: expected integer, got string at b
executeEpsil(ce, 'let k = (s: string) => s\nk("b")');
// value "b", with the same erroneous static diagnostic
```

The instrument's `letRerun` and `constRerun` scenarios reproduce this with
both `let` and `const`. A fresh caller scope checks and runs the edited source
without a diagnostic. A second run really installs the new string function;
the issue is the false diagnostic, not its returned value. This is a plausible
notebook edit, not a measured Tycho UI run.

## Cause and options

The existing static pass checks the new call against the earlier signature.
The precise transition responsible has not been isolated. A declaration in a
later program replaces an earlier program's declaration (Program specification
P7), so the previous value's signature must not constrain the edited declaration.

Keep runtime redeclaration, and make checking use the new declaration's callable
facts. A fresh engine/scope or another name avoids the report. This analysis-only
task changes no production source; `staticDiagnostics` and its callable pinning
helpers are older code, so no fix is included here. Probability is medium for
changing a callable's parameter type between runs; confidence impact because the
observed CE result remains correct.
