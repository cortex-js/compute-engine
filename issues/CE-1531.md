Many list operations, such as appending to a list, slicing it or scanning it, no longer compile to JavaScript.

## Witness

On 0.193.0 these compiled, with the interpreter's value on javascript at one
point (glsl and interval-js were compiled, not run); on main 6801b9bcc each
declines ("the operator X is not supported" unless noted):

`Append`, `DeleteAt`, `Insert`, `Slice`, `Linspace`, `Chunk`, `Partition`, `TakeWhile`, `DropWhile`, `FlatMap`, `Scan`, `Tabulate`/`Table`, `Reduce` with an initial value ("a function value"), `Element` (membership), `Identity`, `CountIf`, `Find`, `IndexWhere`, `Position`, `RandomSample`, `ApplyWhole`; `StartsWith`, `EndsWith` and `ContainsSequence` on lists; `Drop(L, x)` and `Take(L, x)` with `x: real` ("a count that is not an integer", the class of CE-1465), on javascript.

Removed with the old compilers in 0.194.0 (`dac2ac116`); 0.193.0's tables
and runtime helpers are in `git show 384222963:src/compute-engine/compilation/`.

## Expected

Each compiles on the named targets with the interpreter's value, within the
caveats of `docs/COMPILATION-MODEL.md`.

## Cause and options

Port each operator to the IR compiler (`ir/operators.ts`, the printers, the
runtime), from 0.193.0's kernel where its value was right. Operator code is
peripheral; a change to the core of the compiler (a new lane or shape) is
designed and judged on its own.
