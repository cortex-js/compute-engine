A Tycho document that passes a point with a square-root coordinate to a user function does not compile, so it runs in the slower interpreter.

## Witness

In `neyret/hpr2q4kles`, with `A(e_0) = (1, \sqrt{1 - e_0^2})` and
`l(V) = \sqrt{V.x^2 + V.y^2}`:

```
P_0(M_0, D, d, e_0, a, T_0, r_0) = l(d_{iv}(r(M_0, -a) - C(D, d), A(e_0))) - (D + d) / 2
```

declines on JavaScript; the interpreter gives 1.024
(`compile-point-complex-coordinate.test.ts`).

## Cause and options

Under `auto`, the square root of `1 - e_0^2` (unknown sign) moves to the
complex kernel, so the inlined `d_{iv}` passes `l` a point with a `{re, im}`
coordinate, and the emitted definition reads point coordinates as real numbers.
Two changes are needed together: the inline substitution reads through the
return-type ascription around the point (`Typed(PointList(…), '…')`), and the
lane analysis of the enclosing arithmetic sees the inlined body, not the call.
Extend `isComplexValuedUserCall` to the ascription-wrapped case. Removing the
wrapper alone gave the string `"-0.39[object Object]"`. CE-244.1 is CE-837.
