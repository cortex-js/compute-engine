In the compile mode `bigint`, the existing JavaScript compiler records no name in the option `symbolDeps`: not a user function that the code calls, and not a symbol whose value it folds.

## Witness

At `4c0828dff`, JavaScript target:

```ts
const ce = new ComputeEngine();
ce.declare('n', 'integer');
ce.declare('c', 'integer');
ce.assign('c', 5);
ce.assign('g', ce.box(['Function', ['Add', 'x', 'c'], 'x']));
const deps = new Set<string>();
compile(ce.box(['g', 'n']), { mode: 'bigint', symbolDeps: deps });
[...deps]; // []
```

| Program | `mode: 'bigint'` | `mode: 'bigint'`, profile `numeric-kernel` (with the review fix) | default mode, both routes |
| --- | --- | --- | --- |
| `g(n)` | `[]` | `['c', 'g']` | `['c', 'g']` |
| `n + c` | `[]` | `['c']` | `['c']` |
| `n + 1` | `[]` | `[]` | `[]` |

The value of each is `7n` (`7` in the default mode) at `n = 2`.

## Consequence

A host that keeps compiled code and recompiles it when a name of
`symbolDeps` changes keeps stale code in the mode: after `ce.assign('c', 6)`
or a new definition of `g`, the code still computes with `c = 5` and the old
`g`, where the interpreter and a new compilation use the new values.

## Cause and options

The bigint emitter (`compile-bigint-emit.ts`) writes a folded constant from
`evaluate()` (`folded()`) and a user function as a local arrow
(`definition()`), and neither path adds a name to `target.symbolDeps`, as
`tryFoldKnownSymbol()` (`compile-folded-values.ts`) and the user-call
lowering (`compile-user-calls.ts`) do in the other modes. Option: record the
head of each `userCall` and each symbol with a value of a folded subtree
(and the names of its value and of a called body), as the structured route
does in the mode (`recordFolded()` in `javascript-structured-bigint.ts`).
