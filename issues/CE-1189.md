A loop that swaps two typed variables is reported as compilable to GLSL, but the compilation then falls back to the interpreter.

## Witness

```
Block(
  Declare(a, "real", 0),
  Declare(b, "real", 1),
  Loop(Assign((a, b), (b, a + b)), Element(k, Range(1, 5))),
  a)
```

On GLSL, `canCompile()` gives `{ ok: true }`, and `compile()` with
`to: 'glsl'` declines: "Could not compile a destructuring assignment: the
target 'a' is declared as a constant or with a declared type (a block-local
declaration, or an annotated parameter), and the compiled per-leaf write can
enforce neither." The JavaScript target declines with the same message. The
interpreter gives 5. Workaround: bind the locals with `Assign(a, 0)` and
`Assign(b, 1)` (no declared type); the block then compiles on both targets
and gives 5.

## Cause and options

The fragment pass (`walkAssign()` in
`src/compute-engine/compilation/fragment.ts`) admits a tuple assignment whose
targets are locals with a declared type. The emitter of the destructuring
assignment refuses such a target, because the interpreter checks each value
against the declared type before it writes any, and the compiled per-leaf
writes do not.

- (a) The pass refuses the same form, so `canCompile()` agrees with
  `compile()`. Size S. The decline stays.
- (b) The emitter accepts a target whose declared type the static type of its
  value already satisfies (here `real` into `real`): no run-time check is
  needed, and the block compiles on both targets. Size S to M. A value whose
  static type does not satisfy the declared type still declines, and the pass
  must refuse that case too.

Recommended: (b), with the refusal of (a) for the case that (b) still
declines.
