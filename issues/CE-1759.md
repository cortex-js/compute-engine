In a scope where the user defines a function named `Power`, the product of a variable with itself becomes a call of the user's function, and gives a wrong value.

## Witness

At commit `55a7a99d3b01231e22ef1b0ae2f7d9016a130dea`:

```ts
const y = ce.box('y');
ce.pushScope();
ce.declare('Power', 'function');
ce.assign('Power', ce.box(['Function', ['Add', 'a', 'b', 100], 'a', 'b']));
const p = y.mul(y);
p.json                       // ["Power", "y", 2], bound to the user Power
ce.popScope();
p.subs({ y: 3 }).N()         // 105; must be 9
```

`crafted`: the program defines a user function with the capitalized name of
a library function and multiplies in its scope.

## Cause and options

A `Product` (`arithmetic-mul-div.ts`) tallies the factors as a base and an
exponent and writes each grouped term again with `base.pow(exponent)`
(`termsAsExpression()`), which builds `Power` (and the denominator of a
quotient, `Divide`) by name in the current scope. In a scope with a user
`Power` the result is a call of the user function. CE-1122 made a library
`Sqrt`, `Root` or `Power` factor an opaque factor when the current scope
shadows `Sqrt` or `Root`, but a product of plain symbols reaches the rebuild
with no such factor. Option: build the powers and quotients of
`termsAsExpression()` with `ce._libraryCall()` when the current scope shadows
the name. Related: CE-1114 (derivatives built by name), CE-1133.
