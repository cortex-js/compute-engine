The Epsil documentation does not say that a function declared later in a program stays defined when the program stops early on its time or step budget.

## Witness

A program whose `function g` statement comes after a call of `g`, and which is
cancelled before that statement runs: a later program on the same engine still
sees `g`. `src/epsil/docs/evaluation.md` ("Interruptibility") does not say so.

## Cause and options

The Epsil runner installs a `function` statement before the first statement
when that is safe (`prepareFunctionDeclarations`, `src/epsil/execute-epsil.ts`),
in the program scope. User decision 2026-11-05 (old sub-item CE-312.2): keep the
behavior and document it in the Epsil documentation. Plan:
`docs/plans/2026-10-21-function-declaration-hoisting.md`. The other sub-items
are CE-1005 to CE-1008.
