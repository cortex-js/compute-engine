The interval remainder of two real numbers that are not whole numbers can give a range that does not hold the true remainder.

## Witness

On main `846a378cb`, the interval library (`IntervalArithmetic.remainder`, `interval/elementary.ts`):

```ts
_IA.remainder({ lo: -19.599995613098145, hi: -19.599995613098145 }, { lo: 0.7, hi: 0.7 });
// lower end 4.386901853337119e-6; the exact remainder of the two doubles is 4.3869018542253e-6
```

Against exact rationals, 100,465 of 200,000 random pairs of real operands miss, the worst by about 9×10^5 ulps. `Remainder(x, 0.7)` is an ordinary thing to plot, so the witness is `plausible`. Compiled code does not reach the kernel today: on `interval-js` the real-lane `Remainder` declines because of this issue (the integer lane, `remainder.int`, is spelled and sound).

## Cause and options

The kernel computes `a − b·round(a/b)` in plain doubles and then widens by 3 ulps (`remainder = liftJump(outwardUnlessExact(remainderRaw, exactIntegerGridPoint, 3))`). The subtraction cancels, so its error is relative to `a`, not to the result, and 3 ulps of the result do not cover it. Fix: compose the outward-rounded interval `div`, `mul` and `sub` (or bound the cancellation error by ulp(a)) instead of the unrounded operations plus 3 ulps. Then the real-lane spelling in `ir/print-interval.ts` is one line (`remainder: 'remainder'`).
