`epsil check` does not report a type error in a function body that reads the value of the function's own call, and the error shows only when the program runs.

## Witness

At `597f052d84970e12887c2490f99b6e67836ead9c` with the CE-1748 fix, and a host
function `figureDraw` declared `(any) -> nothing`:

```
function rec3(t: real) -> nothing { if t > 0 { let y = rec3(t - 1)
  figureDraw(y + 1) } else { figureDraw(0) } }
```

`checkEpsil` reports nothing. The run refuses the definition with "expected
`number`, got `nothing` at `y`". With a function `nr` of result `nothing`
defined before, `let y = nr(t - 1)` gives the same error in `checkEpsil`.

## Cause and options

While the body of a `function` statement is boxed, a call of the function in
its own body has the type `unknown` (the recursion knot of `DefineFunction`,
`library/core.ts`, read in `boundCallType()` of `boxed-function.ts`). The
definition runs after the function is installed, and the body is then read
against the installed signature.

The simple fix, the stated result of the literal for the self-call, is not
sound, and was withdrawn in CE-1748. It gives a static error to two valid
programs:

- a self-call that reaches a more specific clause defined later:
  `function f(x: real) -> string { if x > 0 { let y = f("s")
  String(y + 1) } else { "n" } }`, then `function f(x: string) -> real { 5 }`;
  `f(1)` is `"6"`;
- a self-call that broadcasts over a list:
  `function fib(n: integer) -> number { if n <= 1 { n } else {
  let ys = fib([n - 1, n - 2]); ys[1] + ys[2] } }`; `fib(5)` is `5`.

A sound version would read the body again in the static check after every
statement of the program is installed, or type the self-call by its stated
result only when the arguments match the clause's parameters and are scalar
and the program has no other clause of the name.
