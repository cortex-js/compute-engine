A field function that calls a user function which reads an assigned number does not compile until that number is declared `real`.

## Witness

With `a := 5` and `h(t) := t + a` (or `A := (1, 2)` and `h(t) := t + A.x`),
`compileFieldFunction(h(x))` declines. The message names the remedy:
`ce.declare('a', 'real')` (or `'tuple<real, real>'`) first.

## Cause and options

The field function reads `a` from the buffer as a real number, but the
signature of `h`, and the result types its callers read, were derived when `a`
was an integer. Accepting the wider type only in the body of `h` is unsound:
`Floor(h(x))` drops `floor`. Design: the field compile derives again the
signatures and memoized call types of the user functions that read a hidden
parameter, and restores all of them, with the captured-type snapshots of the
checkpoint journal, on every exit (`boxed-operator-definition.ts`,
`call-result-type.ts`, `checkpoint-journal.ts`).
