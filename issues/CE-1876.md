Since CE 0.202.0, the declaration `let n: real = 2`, boxed in the structural form and evaluated, gives `Nothing` and leaves `n` with no value; it gave 2 on 0.201.5.

## Witness

On CE 0.202.0:

```ts
const ce = new ComputeEngine();
const statement = ce.box(
  ["Declare", "m", { str: "real" }, ["Dictionary", ["KeyValuePair", "value", 3]]],
  { form: "structural" },
);
statement.evaluate();   // Nothing
ce.box("m").value;      // undefined
```

The engine logs `ComputeEngine: error canonicalizing `Declare`: Cannot read
properties of undefined (reading 'find')`. The same statement in the
canonical form gives 3, and so does the structural form with the attributes
as a `{dict: {value: 3}}` literal. The function-form `Dictionary` is what
`parseEpsil("let n: real = 2")` emits for the attributes (with
`sourceOffsets`), so a host that boxes a parsed Epsil declaration in the
structural form and evaluates it gets no value.

The same crash hides the error of CE-1805: with a key that is not an
attribute, `["Declare", "q", {str: "unknown"}, ["Dictionary",
["KeyValuePair", {str: "foo"}, 2]]]` in the structural form logs the same
message, and `.canonical` gives the statement unchanged with `isValid`
`true`, where `invalid-declaration-attribute` is expected. It was `false` on
0.201.5.

## Cause and options

Probably the attribute check of CE-1805 (a `Declare` whose last operand is a
dictionary with a key that is not an attribute is an error): it reads the
dictionary's entries in a form that the structural box of a function-form
`Dictionary` does not have yet. Expected: the structural statement evaluates
as the canonical one does (value 3, `m` = 3).

Tycho half on adoption: none in code; the assertion moves back into its test in
`tests/node/graph-paper/showcase-traffic.test.ts` (now a `todo` test that names
this issue).

## Fix

`invalidDeclareAttribute()` (`src/compute-engine/library/core.ts`) read the
attributes with `isDictionary()`, a type test that the structural box of a
function-form `Dictionary` passes, and then read `keys`, which that box does
not have. It now reads the function form from its pairs first. Test:
`test/compute-engine/block-locals-declaration-rules.test.ts`, "a function-form
attributes dictionary in the structural form". Tycho: move the assertion back
into the test of `showcase-traffic.test.ts` on adoption. Workaround until then:
box the parsed declaration in the canonical form.
