A large exact fraction writes its denominator in scientific notation in MathJSON.

## Witness

On main at `fed2ad56317cc2a41f1124414bdc7c97d857d83a`:

```
const r = ce.box(['Zeta', 2, -1000]).evaluate().ops[0];   // a Rational
JSON.stringify(r.json).slice(-40)   // …1014531184763904e+8"}]
r.denominator.toString()            // ends with 184763904e+8
```

The numerator is a plain integer string. A host that reads `num` as a BigInt
fails on the denominator. Probability `medium`: an exact result with a
denominator of hundreds of digits.

## Cause and options

CE (2026-11-15, cebatch-1337): located. Both parts of the rational are
bigints (`numericValue.rational` is `[bigint, bigint]`). The exponent comes
from a deliberate rule: `numberToString()` (`src/compute-engine/numerics/strings.ts`)
writes a bigint with more than five trailing zeros as `<digits>e+<n>`, and
`numberToExpression()` (`numerics/expression.ts`) uses it for every integer
past the safe range. It applies to every exact integer, not only to a
`Rational`: `ce.number(7n * 10n ** 60n).json` is `{num: "7e+60"}`, and `50!`
is `{num: "…960512e+12"}`. The MathJSON spec (`50-math-json.md`, "Numbers as
String Literals") admits this spelling, and CE reads it back as an exact
integer. The rule is pinned: the test "bignum magnitudes keep their compact
exponent form" (`roundtrip-integer-storage-hash.test.ts`) and a CHANGELOG
entry ("bignum results keep their compact exponent form"). The serializer
already writes plain digits when it adds `latex` metadata (`serialize.ts`,
the bigint branch), so two spellings exist now.

Options:

- (a) Every exact integer in MathJSON is its plain digits; `toString()` and
  the hash keep the compact form. Patch measured: two lines (the return of
  `numberToExpression()` and the no-shorthand branch of `serialize.ts` give
  `num.toString()`). Cost: 25 tests in 14 files and 3 snapshots change their
  pinned spelling (`{num: "1e+800"}` becomes 801 characters), and the LaTeX
  of `10^{199}` changes from `1\cdot10^{199}` to 200 grouped digits, because
  the LaTeX serializer reads the `num` string. So (a) also needs the LaTeX
  number serializer to compact trailing zeros itself.
- (b) Only the two parts of a `Rational` are plain digits. Smaller, but one
  integer then has two spellings by position (`10^30` as a denominator is 31
  digits, alone it is `{num: "1e+30"}`), and a host that reads a lone
  `num` as a BigInt still fails.
- (c) No change to the output: answer GitHub #594 that an exact integer's
  `num` can have a non-negative exponent, as the spec regex says, and state it
  in `50-math-json.md`.

Recommendation: (a), with the LaTeX kept compact. One rule for hosts ("the
`num` of an exact integer is its digits"), and the `latex`-metadata branch
already writes it. The cost is the size of a power of ten in JSON. The
measured patch is `/tmp/cebatch-1337.patch` (may be cleaned; it is the two
lines above). Size S.
