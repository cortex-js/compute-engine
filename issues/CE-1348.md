Compiling to GLSL an expression that reuses a part with a function in it many times takes a time that doubles at each level of reuse, so a deep one never finishes; the same compilation to JavaScript takes a few milliseconds.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
let a = ce.box('x');
for (let i = 0; i < N; i++) {
  const k = ce.box(`k${i}`);
  a = ce.function('Add', [a, ce.function('Apply', [
    ce.function('Function', [ce.function('Multiply', [k, a]), k]),
    ce.box('x'),
  ])]);
}
compile(a, { to: 'glsl', profile: 'ir', fallback: false });
```

Each level reads `a` twice (a shared graph of `2^N` paths). The GLSL
compilation takes 19 ms at `N = 12`, 45 ms at 14 and 140 ms at 16; the
JavaScript one 2 to 8 ms. With `Sum(Apply(k_i ↦ k_i + Sum(a), a))` over an
input `list<real^3>` it takes 1.9 s at 19 levels. Measured with `npx tsx` on
`3592da6cbad8f3c51dd3c7208ad9689466c804a8` plus batches G17 and G18 (the scalar
`Apply` of the first witness compiles on GLSL without them).

## Cause and options

A CPU profile puts the time in `analyzeReferences()`
(`compilation/compile-references.ts`), which `compileWithIrProfileGlsl()`
(`compilation/ir/adapter-glsl.ts`) calls after the pipeline has compiled, for
the engine types and the provenance of the inputs (`freeSymbolTypes()`); the
pipeline itself (`compileSlice()`) takes 3 ms at 14 levels. The walk seems to
enter the body of each function literal once per path. Options: a memo per
node in that walk (it records occurrences, so the memo must keep the first
occurrence of each name), or reading the input types from the pipeline's
program instead. The construction of the graph (the canonical form of the
function literals) also doubles at each level, about 3 s at 20 levels: that
is the class of CE-1345.
