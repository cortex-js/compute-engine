Tycho evaluates an expression at 17 sites only to read a property of its value, so a document opens slower than it needs to.

## Witness

An audit of Tycho's 135 `evaluate()` call sites (Tycho
`roadmap/LK_EVALUATE_CALL_SITES.md`, 2026-11-08) found 17 sites that read no
value: 11 read the shape of a collection value (`operator`, `isCollection`,
`count`, the kind of the elements), 2 read whether a definition is accepted
(`isValid`, or whether the call throws), 4 read the shape of a point list
through a shared cache.

The instrument, on 0.183.0, for `f := (n) ↦ [n, n+1, n+2, n/2]` and the call
`f(3)`:

```
unevaluated f(3): type vector<rational^4>, isCollection false, count undefined
evaluated:        type vector<rational^4>, isCollection true,  count 4
```

The static type already names the element type and the length, but
`isCollection` and `count` answer only after the evaluation. The same with
`f` declared as `(integer) -> list<real>`.

## Request

1. On an unevaluated expression whose static type is a collection type,
   `isCollection` answers `true` and `count` answers the length the type
   names (`vector<T^n>`, `list<T^n>`), or a query such as `valueShape()`
   gives `{ isCollection, count, elementType }` from the type with no
   evaluation. Tycho's readers: `classifyCollectionSchema` in
   `src/graph-paper/actions/action-lifecycle.ts` (3 sites), the Desmos
   importer's collection check, a `Tuple` check in label templates, a colour
   type check in style expressions, an `operator` check in list
   materialization and in compile.
2. A check that a definition (`g(x) := …`, a `DefineFunction` clause) is
   accepted by the engine, with its type and scope checks but without an
   evaluation of the body. Tycho's readers: a notebook check that runs the
   definition in a temporary scope, and a prelude check.

Not requested: a cheaper way to the shape of a point list in Tycho's
classification evidence. Those 4 sites cache the evaluated value and list
materialization reads the cache, so a shape query saves nothing there.

Workaround: Tycho keeps evaluating at these sites. The cost is one
evaluation per site per document pass; the instrument's single call costs
0.03 ms, but the audited sites evaluate document-function calls over lists
and the registration pass has a per-head budget for them.

Tycho half on adoption: when the instrument reads READY, replace the
`evaluate()` of the 11 shape sites (listed in request 1) with the property
read on the unevaluated expression, and add the engine pin that the type's
length and `count` agree; the 2 validity sites follow the API of request 2.

READY (the instrument's reading): the unevaluated call in the inferred case
answers `isCollection === true` and a `count` equal to the value's. The
second request has no probe until its API exists; the instrument prints the
cost of the evaluation Tycho runs for it today.
