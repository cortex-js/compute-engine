A plot author who names the values of a variable `A`, `B` and `C` gets an error, because two of the three names are read as units, not as text.

## Witness

Tycho reads `m \in \{\text{Linear}, \text{Cubic}\}` as a variable whose values
have names: the parse gives a `Set` of strings. With one-letter names that are
also unit symbols, the set is a mix:

- CE 0.195.1 (installed in Tycho): `\{\text{A}, \text{B}, \text{C}\}` parses to
  `["Set","A","C","'B'"]`: `A` and `C` are symbols, `B` is a string.
- The compute-engine MCP server (a newer build) gives
  `["Set",["__unit__","A"],"'B'",["__unit__","C"]]`.
- Positive control: `\{\text{Linear}, \text{Cubic}\}` gives
  `["Set","'Linear'","'Cubic'"]`.

Tycho refuses a set that mixes strings and other values, so the author cannot
use those names. The instrument prints `CE-1644: READY` when every operand of
the letter set is a string.

## Cause and options

Not investigated on the CE side. The question is a design one: should a bare
`\text{X}`, with no number before it, be a string, and only `5\,\text{A}` a
quantity with a unit? Tycho has no workaround and needs none urgently: the
author can choose longer names.

## Code

The parse of `	ext{…}` as a unit is in `src/compute-engine/latex-syntax/parse.ts` and `src/compute-engine/latex-syntax/dictionary/definitions-units.ts`.
