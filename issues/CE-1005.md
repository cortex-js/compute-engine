The declared signature of a function defined inside another function is not checked, so a call with a value of the wrong type gives a result.

## Witness

```epsil
function h(x) { let g: (integer) -> integer; function g(k) { 2k }; g(x) }
h(1.5)
```

gives `3` on the runner and on the block route, also when the call comes after
the `function` statement. It must refuse `1.5`.

## Cause and options

The body's `Declare` runs in a new scope for each call, so it never finds the
binding that holds the clause installed ahead, and the call reads that clause
without the declared signature. The re-install of early clauses
(`BLOCK_REINSTALLS`, `library/core.ts`) is keyed on the activation template of
a block and covers a loop body and a block run again, not a function body.
Plan: `docs/plans/2026-10-21-function-declaration-hoisting.md`.
