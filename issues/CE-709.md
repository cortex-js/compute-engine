`Solve` of an equation with a decimal number can answer that there is no solution when one exists within the rounding tolerance.

## Witness

```
Solve(x = 10.0000000000001, x ∈ Interval(-10, 10))  ->  []   but Equal(10, 10.0000000000001) is True
Solve(x² = -1e-20, x ∈ ℝ)                            ->  []   but the equation is True at x = 0
```

## Cause and options

The interpreter compares numbers within `engine.tolerance` (1e-10), but over a
real domain `Solve` lists the exact roots of an equation with a float, not the
values that the tolerance also accepts. Over a discrete domain the same case
stays unevaluated or is enumerated.

Question: what does `Solve` give over a real domain when the domain or the
real type removes an exact root?

- (a) The equation stays unevaluated. Cost: `x² = -1.5` over `ℝ` changes from
  `[]` to no answer.
- (b) Keep the current contract (exact roots only) and document it in the
  `Solve` reference with the examples above.

The entry recommends neither. If nothing is decided, (b) stays in force but is
not documented.
