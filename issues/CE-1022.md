A sum of a subscripted function over its index uses the same function for every term, so `\sum_{k=1}^{2} f_k(x)` gives `2 f_k(x)`.

## Witness

```
ce.parse('\\sum_{k=1}^{2} f_k(x)').evaluate()            ->  2·f_k(x)
ce.parse('\\sum_{k=1}^{3} c_k \\phi_k(x)').evaluate()    ->  c_1·φ_k(x) + c_2·φ_k(x) + c_3·φ_k(x)
expected  ->  f_1(x) + f_2(x), and c_1·φ_1(x) + c_2·φ_2(x) + c_3·φ_3(x)
```

## Cause and options

CE-135 made a subscript on the index of a sum read the index by value, but
not in the head of a call: the parser keeps `f_k` as one name
(`_subscriptBoundIndexes()`, `latex-syntax/parse.ts`), because a `Subscript`
head canonicalizes to a product (`f_1·x`). A fix needs a call form with a
subscripted head, for example `Apply(Subscript(f, Delimiter(k)), x)`, and a
decision on how a `resolveApplication` hook sees that head.

Two other positions keep the joined name too:

```
ce.parse('\\sum_{k=1}^{2} a_k(x)', { resolveApplication: () => 'multiply' })
  .evaluate()                                              ->  2·a_k·x
ce.parse('\\sum_{i=1}^{2} \\frac{\\partial}{\\partial x_i} x_i^2').evaluate()
                                                           ->  4·x_i
expected  ->  (a_1 + a_2)·x, and 2x_1 + 2x_2
```

The parser keeps `x_i` in the whole derivative, because it is the variable of
`D`. A `Subscript` variable needs `D` to read `Subscript(x, 1)` as `x_1`.
