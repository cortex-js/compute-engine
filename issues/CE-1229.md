A formula of the form `3z with z = z + Z` does not compile unless Tycho renames the local, so Tycho carries a renaming pass with its own fresh names.

## Witness

Installed CE 0.187.1. A block local declared with its value, where the value reads the outer name of the same spelling:

```js
ce.declare('z', 'real'); ce.declare('Z', 'real');
const b = ce.box(['Block',
  ['Declare', 'z', ['Dictionary', ['KeyValuePair', 'value', ['Add', 'z', 'Z']]]],
  ['Multiply', 3, 'z']]);
ce.withValues({ z: 2, Z: 10 }, () => b.evaluate().re);   // 36
compile(b, { to: 'javascript' }).success;                // false
// "Could not compile `Block`: a statement reads the block local "z"
//  before any statement gives it a value. …"
```

The same holds for `Declare(z, 'unknown', value)`. With the local named `w` the block compiles and gives 36. The instrument prints the three cases and `CE-1229: READY` when the compiled value equals the interpreter's for both spellings.

## What it must give

The initializer of a `Declare` that carries its value is evaluated before the local is in scope, in the compiled code as in the interpreter: `{ const z1 = z + Z; return 3 * z1; }`. Nothing then depends on "read before assigned".

## Cause and options

Not investigated. Option: the JavaScript target (and the other targets) lowers the initializer in the enclosing scope and gives the local a name of its own in the emitted code. Size S.

## Tycho half on adoption

Tycho half on adoption: run the instrument; when it reads READY, remove `renameSelfReadingBlockLocals` and its callers (`src/graph-paper/graph/block-local-rename.ts`, the `_blockRenameFreshNames` code in `src/graph-paper/graph/document-ce-manager.ts`) and the `Waits for compute-engine issue CE-1229` marker, and keep `tests/node/graph-paper/with-self-read-rename.test.ts` as a value test.
