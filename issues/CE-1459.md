The Epsil guides still say that every `let` needs a value, and the error of destructuring an unevaluated value points to the generic runtime-error page.

## Witness

Epsil CLI, main 9777d22c1:

- `src/epsil/docs/declarations.md` (table around lines 286 and 288) gives
  `let a: integer; if c { a = 1 }; a` as `declaration-without-value`; the engine
  gives 1 when `c` is true. It gives `let f: (integer) -> integer; f(2)` as
  `declaration-without-value`; the engine gives "`f` is read before it has been
  given a value".
- `src/epsil/docs/errors.md` (`## declaration-without-value`, line 271) and
  `src/epsil/error-explanations.ts` (line 203) still describe every `let`
  without a value as that error.
- `let (U, S, V) = svd([[1, 2], [3, 4]])` prints the note
  "`epsil doc runtime-error` explains this error", although its code is
  `unevaluated-tuple` (CE-1389, `boxed-expression/tuple-pattern.ts` line 121),
  which has no entry in `error-explanations.ts`.

## Cause and options

The texts predate the rule that `let` may declare a name with no value. Fix:
the two table rows give the engine's results; `errors.md` and
`error-explanations.ts` describe what `declaration-without-value` is now
(see CE-1458 for `const`) and the read-before-initialization error; add an
`unevaluated-tuple` explanation and make the note name it. The cortexjs.io
site copies these pages.
