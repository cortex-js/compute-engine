In a notebook, a code cell that has a local variable with the name of a slider shows the "stale" badge when the slider moves, and a rename of the slider renames the local variable too.

## Witness

A notebook code cell is one Epsil program. Tycho runs it with `executeEpsil()`
in a scope pushed over the scope of its section, which holds the sliders, the
tables and the formula definitions. Tycho needs to know which occurrences of a
name in the program resolve to a binding OUTSIDE the program:

- the reads, for the dependency edges and the stale badge;
- the writes, to keep them out of the section: before the run, Tycho declares a
  local copy of each outer name that the program writes;
- reads and writes together, to rewrite exactly those occurrences when the user
  renames the outer name.

CE 0.195.1 has no query for this (the instrument prints the exports of the
`epsil` entry; `binderSitesOf` is the only match, and it gives the names that
a library call such as `limit` binds, not the reads of outer names). Tycho walks the parsed tree itself
(`src/graph-paper/notebook/cortex-analysis.ts`). Its read set is every name that
occurs outside a write target and outside the body of a function whose
parameter it is. That set is too large: with a slider `k`, a cell with
`for k in 1..7 { … }` or `let k = 3` has an edge to the slider.

Two review rounds of the Tycho spec tried to state the exact rule for a walk in
the host. Both failed on CE's own resolution, which the instrument prints (outer
`k = 5`, `p = 5`; each case on a fresh engine, with its control):

| Program | Value | Fact for the host |
| --- | --- | --- |
| `function g() { k }`, `let k = 7`, `g()` | 7 | the body reads a `let` that comes after it |
| `let h = () => k`, `let k = 7`, `h()` | 7 | the same for a lambda |
| `let k = k + 1`, `k` | 6 | the initializer reads the outer `k`; the next line reads the local |
| `let j = k`, `let k = 1` | diagnostic `read-before-declaration` | a direct use before the `let` is not a read of the outer `k` |
| `for k in 1..2 { k }`, `k` | 5 | the read after the loop is the outer `k` |
| `p += 1` | outer `p` becomes 6 | a write that Tycho's list of write heads did not have |
| `(p, q) := (1, 2)` | outer `p` becomes 1 | the same, a tuple target |
| `let f = () => do { p = 9 }`, `f()` | outer `p` becomes 9 | a write from a lambda body |

`match` binders, comprehension variables, tuple loop variables, tuple and typed
declarations and function definitions are binders too. A walk in Tycho that
gets all of this right is a second copy of the engine's scoping rules, which is
what CE-1255 exists to remove for the prelude runner.

## Cause and options

CE-1255.2 (ROADMAP; draft `docs/plans/2026-11-19-program-sites.md`) is the
query that gives this: each authored name site with its role, its source range
and its resolved target, with external bindings distinct from Program
declarations and locals, and deferred sites marked. Its named consumers are
Tycho's prelude admission and diagnostics. This request adds the notebook as a
consumer and states what it needs from one prepared program:

1. The source ranges of the sites whose target is an external binding, with the
   role (read, write, or both for a compound assignment), deferred sites
   included, and the name of the binding.
2. The set of external bindings that the program writes, at any depth. Tycho
   replaces its list of write forms (`Assign` with a symbol or a `Tuple` target,
   `AddTo` with a symbol or an `At` target) by this set, so a write form that CE
   adds later is contained with no change in Tycho.
3. A statement that the same sites are the ones to rewrite when the host renames
   the external name: every site of item 1 for that binding, and no site that
   resolves to a local of the same name.

The preparation runs with the section's scope as the environment, since the
plan says that source spelling alone cannot tell two external bindings apart.

Option (a), recommended: the plan of CE-1255.2 takes the three needs as
acceptance cases, with the programs of the table. Option (b): decline. Tycho
keeps the read set of names (the badge and the rename above stay as they are;
no value is wrong) and its list of write forms.

A second way to cover item 2 only: a scope that redirects a write to an outer
binding into a local copy (copy on write). Tycho would push such a scope for a
code cell and keep no list. It does not help items 1 and 3.

Workaround in Tycho today, phase 1 of the spec: the read set stays a set of
names, and the pre-seed uses the list of write forms that the CE desk ran on
2026-11-20 (spec § 7 C3a).
