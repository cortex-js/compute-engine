The derivative of a variable that holds a formula is 0 instead of the derivative of the formula.

## Witness

Epsil: `let G = sin(x); D(G, x)` prints `0`; it must print `cos(x)`. The same
with `ce.assign('G', ce.box(['Sin', 'x']))` then
`ce.box(['D', 'G', 'x']).evaluate()`, and with `2 G` in place of `G`.
`ce.box('G').evaluate()` gives `Sin(x)`. The report used
`let F = cdf(normalDistribution(0, 1), x)`. Main (a28dd290f) and 0.186.0 give 0.

## Cause and options

`D` holds its operand and treats a symbol other than the variable as a
constant; it does not read the symbol's value. Option (a): before
differentiating, replace each symbol that holds a value (not a library constant,
not the variable) by its value, as `withAssignedValues` in
`library/calculus.ts` does for `NIntegrate`. Check first whether a documented
rule says that `D` does not read values (`docs/SCOPING-MODEL.md`) and how
CE-1219 (compiled `D(f, x)` when `x` holds a value) interacts. `Integrate`
probably has the same defect: check it in the same change.
