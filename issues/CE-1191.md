A compiled function that rounds down the product of an integer and a local that holds an exact fraction gives an integer that is 1 too small.

## Witness

```
f := (k: integer) ↦ Block(Declare(q, 'real', Rational(1, 49)), Floor(Multiply(q, k)))
f(49)   interpreter: 1
        compile(f).run(49): 0, with the default options and with cse: false, constantFold: false
```

The emitted JavaScript is `let q = 0.02040816326530612; return Math.floor(k * q)`.
The product `49 * 0.02040816326530612` is `0.9999999999999999`.

The same function with the fraction written in the product,
`Floor(Multiply(Rational(1, 49), k))`, is correct: the compiler writes
`Math.floor(k / 49)`.

## Cause and options

`docs/COMPILATION-MODEL.md` (the section on a rounding function whose operand
has an exact constant that no double holds) requires that a rational factor
is written as a division before the rounding, and that the other shapes
decline with `inexact-jump-operand`. `jumpShiftRewrite()` and the division
rule of `Multiply` (`exactRationalDivisor()` in `compiler-type-facts.ts`) read
the operand tree of the rounding function. They do not read the value of a
local that the operand names, so a constant behind a `Declare` is written as
its rounded double.

The structured route of the internal JavaScript fragment target
(`inexactJumpConstant()` in `javascript-fragment-target.ts`) has the same
limit and gives the same value.

Options:

1. Decline a rounding function whose operand reads a local with a real type
   whose value is not proved to be a double already (an input, or arithmetic
   on inputs). Simple and sound; it also declines `let h = x/2; floor(h)`
   unless the proof covers arithmetic on inputs.
2. Follow a local with one assignment to its value before the two rules run.
   It covers the witness and not a local written twice or a helper parameter.
