Three tests fail at HEAD because they expect a compilation to decline for a function that the host declared with an evaluate function, and since CE-1621 it compiles.

## Witness

At `55b67c3d3b1c9619c9d6ea8890205c4907d6e8b4` (they pass at
`c8b285e9ba54984e47f7d3b9f14e84d8e96369d1`, the parent of
`2ab53e5464df93fd4d68a44ccbe89072c10c475d`, CE-1621):

- `test/compute-engine/compile-inputs-option.test.ts`, "the interpreter
  fallback evaluates with the inputs" and "the interpreter fallback gives the
  input to a called body too": with `L2` declared with
  `signature: '(real) -> real'` and a JavaScript `evaluate`,
  `compile(L2(x) + 1, { inputs: { x: 'real' } }).success` is `true`; the test
  expects `false`.
- `test/compute-engine/compile-shadowed-named-lowering.test.ts`, "a
  redeclared If › a copy with `lazy: false`": the compilation succeeds; the
  test expects `false`.

## Cause and options

CE-1621 made compiled JavaScript call a host function declared with an
`evaluate` function, so the decline that these tests use to reach the
interpreter fallback no longer happens. If the new compilation gives the
interpreter's value, the tests are out of date: change each one to use a
function that still declines (for example one whose `evaluate` the compiler
cannot call), so that the fallback stays tested, and check the case of the
redeclared `If` with `lazy: false` against the CE-1621 rule. If the
compilation of the redeclared `If` is wrong, this is a `wrong-value` defect
instead.
