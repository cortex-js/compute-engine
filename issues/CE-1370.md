A Desmos document imported into Tycho cannot be compiled by the profile `ir`, so its plots stay on the existing compiler, which is to be deleted.

## Witness

Tycho attaches `compile` and `compileHelpers` handlers in place on `At` and
`Which` for the Desmos list rules (`src/graph-paper/graph/at-index-semantics.ts`).
The profile declines every program that holds such a definition
(`hasOwnLowering`, `compilation/ir/lower-context.ts`), also where the handler
returns `undefined`. Over 755 corpus documents on build `1a9368648`
(tycho-desk, `t13-results.json`, `item3_corpus.declineGroups`): 948 of the
1,606 JavaScript calls that fall back decline on `Which` and 438 on `At`.

Two attempts to move the rules out of the handlers in one step failed Tycho's
render gate (lost series, builds up to 28× slower; Tycho
`roadmap/MK_DESMOS_LIST_REWRITE.md`). Tycho needs to remove them one rule at
a time.

## Request

In the profile `ir`, call an operator `compile` handler with the operands:

1. it returns `undefined`: compile the node with the default lowering, as the
   existing compiler does;
2. it returns an Expression: lower that Expression, with the library
   definitions. An `At` or `Which` inside it is the library operator, never
   the handler again;
3. it returns a string, or throws: decline, as today.

Point 2 matters as much as point 1: Tycho's handler on GLSL and interval
already builds `At(L, Max(Floor(i), 0))` and compiles it, so with point 1
alone every `At` of an imported document still declines there. The instrument
reads both points on JavaScript.

## Tycho half on adoption

Run the instrument. Then ROADMAP row MK: the GLSL/interval branch of the `At`
handler returns its Expression; then `Which`; then the JavaScript `At`, one
rule per step, each with the render-audit A/B gate.

- **The rule as it landed.** In the profile `ir`, a `compile` handler is
  called with the operands, a `compile` callback and
  `{ language, typeOf }` (`language` is `'javascript'`, `'glsl'` or
  `'interval-javascript'`). `undefined`, `null` or `''`: the library's
  lowering. An expression: it is lowered in place of the node. A node the
  handler created (not an operand object, and not inside one) consults no
  handler; a node under the operands keeps its handler, also when
  canonicalization merges an operand into a new node. Text, a call of the
  callback (it gives `'0'`), a throw, or an answer that holds the node
  itself: a decline.
- **Three limits to know.** A handler on a control-flow head other than
  `Which` is ignored. `D` or `Integrate` over a node whose handler answers
  an expression declines. No handler is asked about a node of a value of
  more than 20,000 nodes as a tree, or about a node under one (the height
  map): such a node declines, as the existing compiler refuses that value.
- **The existing compilers** compile an expression result too, so one
  handler serves both during the transition.
- **Tycho half:** rerun the instrument on the tarball. Then the conversion
  `tycho-3f` proposed: the GLSL and interval branch of `At`, then `Which`,
  then the JavaScript `At`.
