After the type of a variable changes, a function that reads it still reports a result type computed with the old type.

## Witness

```ts
ce.declare('k', 'integer');
ce.declare('f', { value: ce.box(['Function',
  ['Block', ['Declare', 'c', 'unknown', ['Add', 't', 'k']], ['Tuple', 'c', 'k']],
  't']) });
ce.box(['f', 2]).type;        // tuple<integer, integer>
ce.symbol('k').type = 'string';
ce.box(['f', 2]).type;        // tuple<number, integer>
```

A new engine that declares `k` as `string` gives `tuple<error, string>`.
Both components are wrong after the retype: the second one still reads the
old type of `k`. Reproduced on the main tree at `5c97853cc` (2026-11-06).

## Cause and options

Not traced. The type write of `k` advances the type version, so a cache keyed
on it is not the cause by itself; candidates are the derived signature of `f`
and the type of the block local `c`.
