Tycho needs a fragile workaround to give symbols temporary values while it reads point coordinates.

## Witness

Tycho's `withValuelessVariablesBound()`
(`~/dev/tycho/src/plot-core/list-materialize.ts`) assigns values inside
`ce.checkpoint()` and `ce.restore()`; the checkpoint is refused during an
evaluation. Reading on 0.182.0: `CE-532: NOT READY on 0.182.0 (ce.withValues
does not exist)`. Tycho half: replace that code with `ce.withValues()`.

## Cause and options

Proposal: `ce.withValues(values, fn)` declares the values in a pushed scope
and never writes the outer definition (full text in the plan below).

## Decision

User decision 2026-11-06: approved: add ce.withValues(values, fn) as proposed.

User decision 2026-11-07: (b), write the visible binding of each name for
the call and restore it after the call, so that a stored definition such as
`f := x ↦ x + a` reads the temporary value too.

## Question for the board (2026-11-07)

That design misses stored definitions: with `f := x ↦ x + a`, `f(2)` inside
`withValues({a: 1})` gives `a + 2`. Tycho binds only for those. Options and
the worktree: `docs/plans/2026-11-07-ce532-with-values-options.md`.

## Fix (2026-11-07, option (b))

`ce.withValues(values, fn)` (`withValuesFn()`, `engine-declarations.ts`)
assigns each value to the visible binding, runs `fn`, and writes back a copy
of all the fields of each value definition in a `finally`. It works during an
evaluation. With `f := x ↦ x + a`, `f(2)` inside `withValues({ a: 1 })` gives
`3`; with `c := a + 1`, `2c` gives `4`. Tests:
`test/compute-engine/with-values.test.ts`. The instrument, run on the source:
`CE-532: READY on local source (ce.withValues binds inside fn only)`.

Tycho half: replace the checkpoint, the assignments and `restoreBinding()` in
`withValuelessVariablesBound()` with one call. These throw before any name
gets a value, so catch them and keep the substitution route: a constant, a
name bound to a function definition, a value that is a function, a value that
`ce.assign()` refuses, and a name that the body of a stored function applies
while the name has no definition (`a` in `f(t) := a(t+1)`; a value would
rewrite that body as a product).
