Opening a large Tycho document spends about 760 ms preparing its formulas, and a fifth of it finds the result type of the same function again and again.

## Witness

```
npx tsx benchmarks/tycho-document-open/rebind.ts     # COLD=1 RUNS=1 for the first run only
```

Document `art/2ki2hjsouf`, source at `69d0faf1b`: 1 994 `ce.rebind` calls,
median 762 ms. The 425-byte tree `R_3(At(PointList(… D(PointY(S_orry(u)), u) …)))`
takes 16 to 17 ms. `literalBodyResultType` is 20 % of the replay.

## Cause and options

As before: the memo of `literalBodyResultType` (`call-result-type.ts`) is keyed
on `_cacheGeneration()`, and each `D` binder advances it. CE-689 (`db796d62e`)
added a type version that a call does not advance, but a `D` binder advances
it too (2 per `D`), so it does not help here. Exempting a binder scope is
unsound (`ce-535-531-binder-declaration-cache.test.ts`). The fix needs caches
keyed on the bindings they read, the design that CE-531 needs too.

Design: `docs/plans/2026-11-06-ce-535-531-binding-keyed-memos.md`. Full text:
ROADMAP.md at commit 5784d4aec.

## Decision

User decision 2026-11-06: Isn't that already implemented?

CE (2026-11-06): No. From `21fc9505b` on, the tree took 1.7 ms only because the
fixture's `Declare(x)` with no value became an error, so `S_orry` was invalid.
The fixture is rewritten; the cost is back.
