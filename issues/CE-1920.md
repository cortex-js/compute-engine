An animation that draws a figure in each frame runs interpreted, because the code that applies the style options of the figure loops over the names of the options.

## Witness

On CE source after 0.204.2, compiled JavaScript declines `keys` of a
dictionary parameter, also when the argument is the default `{->}` or a
dictionary literal:

```epsil
function g(v: any) -> real { if v is string { 1 } else { 2 } }
function constantKey(opts: dictionary = {->}) -> real { g(opts["fill"]) }
function count(n: real, opts: dictionary = {->}) -> real {
  let s = n
  for k in keys(opts) { s = s + g(opts[k]) }
  s
}
```

| Shape | CE source |
| --- | --- |
| `(t: real) => constantKey({fill -> "red"}) + t` (control) | compiles; `3` |
| `(t: real) => count(t)` | declines: `Keys("opts"): the operator Keys is not supported by the compiler` |
| `(t: real) => count(t, {fill -> "red", opacity -> 0.5})` | declines, the same message |

The interpreter gives `2` and `5`. Tycho's `figureStyled(fig, opts, name)`
runs `for k in keys(opts) { … out = figureOption(out, k, opts[k]) }`, and
every figure constructor of the prelude calls it. With CE-1918 and CE-1919
fixed, this is the next decline of a figure constructor.

## Cause and options

A `dictionary` parameter holds the record of a dictionary literal (CE-1911),
so its keys and the type of each value are known at compile time. A `for`
over `keys(d)` of such a record can be unrolled, one copy of the body per
key, with `k` a string constant. `d[k]` is then a read by a constant key,
which compiles (the control), and a test of the type of the value
(`v is string` in `figureOption`) settles per call, as `g` shows. For `{->}`
the loop has no copy. A `keys(d)` that is not the range of a `for` can stay
a decline.

Workaround: none found. The loop cannot be a recursion over the keys:
a record on a recursive call declines, and so does a call of a host function
that returns a record.
