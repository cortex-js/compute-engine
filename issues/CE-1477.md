A function of one point, called with a list of points, no longer compiles.

## Witness

`P: list<tuple<real, real>>`; `f` declared
`(tuple<number, number>) -> tuple<number, number>`,
`f := Function(Tuple(At(p, 1) + 1, At(p, 2)), p)`;
`compile(f(P), { to: 'javascript', inputs: { P: 'list<tuple<real, real>>' } })`.

0.193.0: compiles (`_.P.map(_fn_f)`); at `P = [(1, 2), (3, 4)]` it gives
`[[2, 2], [4, 4]]`, the interpreter's value (it maps `f` over the points).
0.194.0: declines, "a list argument of f that the parameter 1, a list or a
point, would take whole (the interpreter maps the function over the list)".

The IR README ("User functions") documents the decline (`g(B)` of a list of
points `B` with `g := (p: tuple<real, real>) ↦ p[1] + p[2]`). Workaround:
`Map(f, P)` compiles and gives the same value. Tycho meets `f(P)` in
Desmos documents, where a point function applied to a point list is common.

## Expected

Compiles on javascript and gives the interpreter's value.
