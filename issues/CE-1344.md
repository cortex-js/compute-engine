Simplifying the definitions used by Voronoi plots currently requires keeping an early scalar-versus-list decision in Tycho.

## Witness

Desmos `sum(i=d..d, {d=m:10^9,d})` replaces the minimum element of `d` before taking another minimum. Tycho lowers a proven list to `Map`, otherwise to the scalar one-term identity. The decision reads registration/collection machinery that the macro migration would otherwise simplify.

One raw lowering could be:

```text
Min(Apply(Function(Which(k=m, 10^9, True, k), k), d))
```

The instrument uses runtime `x: real`, `m: real`; `d` is `x^2` or the literal list `[x^2,(x-1)^2,(x-2)^2]`. Fresh engine per target/shape. On installed CE 0.192.0:

| Form | JS | interval-js | GLSL |
| --- | --- | --- | --- |
| scalar Apply | passes, correct value | passes | declines Apply |
| fixed-list Apply | passes, correct value | declines List | declines Apply |
| fixed-list Map control | passes, correct value | passes | passes |

The request preserves Apply's existing scalar/list broadcasting semantics. It does not request parameterized macros or a Desmos-specific primitive. Fixed-width lists suffice for the shader request. G12 of the compiler plan already records scalar Apply support on the IR route and deliberate refusal of list arguments after a wrong whole-list binding; this request asks for the missing mapping behavior, not removal of that safety refusal without a lowering.

## Options

Preferred: support function-literal Apply with scalar or mapped fixed-list arguments on the required targets, or provide a portable equivalent. Then Tycho can lower the equal-bound idiom once on the raw tree before declaring macros, without asking its carrier registry for the branch. Run the instrument (READY requires all Apply cases) and the actual Voronoi render/snapshot tests before replacing the oracle in `collection-bigop-lowering.ts` and its manager caller.

Workaround: retain the current Map/scalar split and its collection oracle; macro migration is still possible with a staged lowering pass. This is a simplification request, not a newly discovered shipped wrong-value regression. No GPU execution claim is made by the compile-only instrument.

Tycho half on adoption: replace the collection-oracle split in `src/graph-paper/graph/collection-bigop-lowering.ts` only after the portable Apply instrument and all five actual Voronoi/snapshot witnesses pass; remove the manager oracle dependency if no remaining caller needs it.
