The `epsil` tool prints `sqrt(3)/2 * i` as `sqrt(3)/2i`, which Epsil reads back as `sqrt(3)/(2i)`.

## Witness

Epsil CLI, main cb12f6066: `sqrt(3)/2 * i` prints `sqrt(3)/2i`, and
`sqrt(3)/2i` evaluates to `-sqrt(3)/2i`. `x/2 * i` prints `1/2i * x`. The
`1/2i * e^…` terms of a `trigToExp` result print the same way. The
`--epsil` mode is correct (`complex(0, sqrt(3) / 2)`).

## Cause and options

The value mode (`epsilValueText` in `src/cli/format.ts`) uses the engine's
textual form (`toAsciiMath`), which joins a number denominator and `i`
without a space or a `*` (`joinMul` in
`src/compute-engine/boxed-expression/ascii-math.ts`). In Epsil an implicit
product binds tighter than `/`. Fix: in the value mode, write a product with
`i` after a fraction as `sqrt(3)/2 * i` (an override of the `Multiply` or
`Divide` handler passed to `toAsciiMath`, as CE-1387 did for `Abs`), and add
a round-trip test. Changing `joinMul` itself also changes `toString()`.
