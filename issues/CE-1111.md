The length of a random list can differ from the number of its elements when both are read.

## Witness

```
npx tsx src/cli/epsil.ts --eval 'WithRandomSeed(7, do { let v = [j for j in 1..10 if random() < 0.5]; (length(v), sum(v), v) })'
```

gives `(4, 23, [1,3,5,6,8])`: the length is 4, the list has 5 elements. With
`(sum(v), length(v), v)` the result is `(11, 5, [1,2,3,5])`: the length is 5,
the list has 4 elements. Measured 2026-11-07 on HEAD `88d6bfe72` plus the
uncommitted CE-1093 change, which does not touch this code.

The result must use one set of draws for `v`, as `docs/RANDOMNESS-MODEL.md`
§6 ("One instance, one draw set") states: the length is the number of
elements of `v`, and the sum is their sum.

## Cause and options

The count of a guarded comprehension comes from its own walk
(`comprehensionCount()` through `comprehensionEnumeratedCount()`, cached by
`_memoizedFacet('count')` in `boxed-expression/boxed-function.ts`). That walk
draws, but its elements are not stored in the element memo, so the next
complete walk draws again. Option: when the body or a guard can draw, compute
the count by a complete walk that fills the element memo, and read the count
from it. Size M: the count route and the memo, with a test for `length`,
`isEmpty` and an indexed read.
