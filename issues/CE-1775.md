In a Tycho notebook, a figure chain written over two lines, `circle((0, 0), 1)` and then `.on("click", …)` on the next line, is a syntax error ("Unexpected symbol ."), also inside parentheses.

## Witness

`Box` has a protocol method `grow`, as Tycho's figures have `.on`,
`.update`, `.translate`. On CE 0.201.2 the instrument prints:

```
one line (control): ok, Box(6)
trailing dot (control): ok, Box(6)
leading + in parentheses (control): ok, 2
leading dot in parentheses: error: closing-bracket-expected,)
leading dot at top level: error: unexpected-symbol,.
LEADING-DOT: NOT READY
```

The failing forms:

```epsil
(b.grow(2)
  .grow(3))

b.grow(2)
  .grow(3)
```

## Cause and options

Inside parentheses a line break does not end the expression (`(b.w` then
`+ 1)` parses), but a line that starts with `.` still fails, so the
parenthesized form looks like a defect of its own. At the top level a line
break ends a statement, so a leading `.` is a design question: JavaScript,
Kotlin and Swift read a line that starts with `.` as a continuation, since no
statement can start with `.`.

Options:

1. Read a line whose first token is `.` (followed by a name) as a
   continuation of the expression before it, everywhere.
2. Only inside brackets, as for other operators.

Workaround: end the first line with the `.` (`b.grow(2).` then `grow(3)`),
or keep the chain on one line.

Tycho half on adoption: none in code; the Programming Guide's note on
breaking a chain over lines ("Style and Move Figures") can then show the
leading-dot form.
