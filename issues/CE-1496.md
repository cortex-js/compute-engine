A compiled function with an integer parameter, given the floor of a value that can be infinite, returns a number where the interpreter reports an error.

## Witness

On CE main 3f1154dd63746fe94740da35a7cd776c02da5cc7:

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.declare('g', 'function');
ce.assign('g', ce.box(['Function', ['If', ['Greater', 'k', 0], 1, 2], ['Typed', 'k', "'integer'"]]));
compile(ce.box(['g', ['Floor', ['Divide', 1, 'x']]]), { fallback: false }).run({ x: 0 });
// 1; the interpreter gives Error(incompatible-type, integer, ~oo)
```

The same holds for `g(Floor(x))` with `x: real | infinity` at `+∞`, and when
the argument goes through a local. The engine type of `Floor(1/x)` is
`infinity | integer | nan`: `Floor`, `Ceil`, `Round` and `Truncate` put
`±Infinity` on the integer lane, and the named-call route checks only the IR
lane of the argument, not its engine type. A wrong finite value for inputs of
their declared types is outside the caveats of `docs/COMPILATION-MODEL.md`.

## Cause and options

The argument check of a named call compares IR lanes only. Fix: the check of
`case 'Apply'` (CE-1485): an argument passes a scalar parameter when every
value the interpreter can bind to it has an engine type that proves the
parameter's type (`provedTypes()` in `lower.ts`); otherwise the call declines.
