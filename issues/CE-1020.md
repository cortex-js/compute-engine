A document with a list of integrals that reads a slider opens about 3 times slower unless Tycho skips their evaluation when the document opens.

## Witness

`c(y,D,e) := \int_{-D}^{D} n(x,y,e)\,dx`, `E` a list of 6 numbers, `L` a
slider with no value, and four heads `\int_a^b y\,c(y,L,E)\,dy`. Their
`evaluate()` searches for an antiderivative and gives the integrals back
unevaluated; no consumer reads that result. Registration of the document:
53 ms when Tycho skips the four evaluations, 172 ms with them (medians of 5,
0.182.0, box lock). Reading on 0.182.0: `CE-1020: NOT READY on
0.182.0 (… 3.3×, limit 1.25×)`.

Requested: such an `evaluate()` costs about what boxing costs, for example
with no antiderivative search for an integrand that holds an unevaluated
integral: registration with the evaluations at most 1.25 times without.

Tycho half on adoption: remove the `Integrate` branch of
`_bigOperatorTermReachesValuelessVariable()` (Tycho's
`src/graph-paper/graph/document-ce-manager.ts`) and change test (a) of
`tests/node/graph-paper/slow-collections.test.ts`.

## Cause (2026-11-08, at `fcad2db31ca45699774e5c6cd88dc09777574ca3`)

`integrateListIntegrand()` splits each head into 6 integrals
`∫ₐᵇ y·c(y, L, eₖ) dy` (CE-604). Each one runs the definite route of
`Integrate` (`library/calculus.ts`), where `antiderivative()` treats
`c(y, L, eₖ)` as an opaque function: it does not inline `c`. The rule
search then fails, in about 4 ms per integral, mostly in rule matching.
`∫₀¹ y·f(y) dy`, with `f` declared as a function with no
definition, also stays unevaluated after a search of about 11 ms. A found primitive
that holds `Integrate` is not used for a definite integral.

Measured with the CE source in one process, warm, the median of 60 heads:
24.4 ms per head today; 4.5 ms with the search skipped. The rest is the
boxing and typing of the 6 element integrals.

The requested rule changes values. With `P(s) := ∫₀^s t dt`, `∫₀¹ P(y) dy`
is 1/6 today: the search inlines `P` and evaluates its integral. With the
search skipped for every call whose body holds an integral, it stays
unevaluated. In indefinite integrals, `∫ f(y)·∫₀^y f(t) dt dy` is
`½(∫₀^y f(t) dt)²` today.

## Options

(a) Skip `antiderivative()` in a definite integral whose integrand holds a
call that the search does not inline (`reduceTransformerHead()` leaves it)
and whose body holds an `Integrate` that reads the integration variable
through the arguments. `∫₀¹ P(y) dy` stays 1/6. A value is lost only when the
search finds a primitive written with the opaque call, for example for an
integrand that holds the call and its derivative; no such case is known.
Gain: 24.4 → 4.5 ms per head. Estimate for Tycho's reading: about 1.4×, still
above the 1.25× limit, so Tycho keeps its workaround.

(b) No change in CE (recommended). Tycho keeps its workaround, which skips
these evaluations and is correct. CE-1020 is closed with no change.

(c) Make a failed search faster for any integrand with an opaque call (the
`y·f(y)` case). This is a performance task for `ROADMAP.md`, size L, not a
fix of this item.

With no decision, CE does not change and Tycho keeps its workaround.

## CE answer

CE (2026-11-07): priority P3, confirmed by the board on 2026-11-07
(`minor`, `medium`, with a workaround). Disposition: pool; the batches take
P3 items in priority order, size M. In the witness the search finds no
antiderivative and returns the integral, so skipping the search for an
integrand that holds an unevaluated integral gives the same result there. The
fix must check that it gives the same result in every case (not checked yet).
Workaround: keep the `Integrate` branch of
`_bigOperatorTermReachesValuelessVariable()` until the instrument prints READY
on a release. Not measured again on 0.183.0.
