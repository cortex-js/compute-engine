The interval range of the log-gamma of a value that grows without bound has no upper end: plotting ln Γ(1/x) over [0, 1] gives an upper bound that is not a number instead of +∞.

## Witness

On main `23c9c4b15`, `new ComputeEngine()`, `x` declared `real`:

```ts
compile(ce.parse('\\ln\\Gamma(1/x)'), { to: 'interval-js' }).run({ x: { lo: 0, hi: 1 } });
// { kind: 'partial', value: { lo: -0.1215, hi: NaN }, ... }   (right: hi = +Infinity)
IntervalArithmetic.gammaln({ lo: 1, hi: Infinity });
// { kind: 'interval', value: { lo: -0.1215, hi: NaN } }       (right: hi = +Infinity)
```

The kernels `div`, `pow`, `remainder`, `lcm` and `add`/`sub` also give one NaN end for some operands with an infinite end, but from a finite box only the log-gamma is reached through a sub-expression (a fuzz of the `_IA` kernels by the reviewer). Inside an `If`, the join now reads such a value as `entire` (sound); outside it, the host reads a NaN bound.

## Cause and options

Probably the kernel evaluates its scalar at +Infinity (or `ln` of `gamma`'s +Infinity end through an intermediate NaN). Fix: give +Infinity for an upper end at +Infinity in `gammaln` (and check `ln(gamma(...))` with an infinite `gamma` end).
