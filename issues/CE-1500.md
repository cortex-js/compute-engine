A plot that reads a point and a name that the document defines again in a nested scope draws with the value of the outer definition.

## Witness

```ts
ce.declare('P', 'tuple<real | signed_infinity | nan, real | signed_infinity | nan> | list<…the same tuple…>');
ce.assign('P', ce.box(['Tuple', 3, 4]));
ce.declare('a', 'real'); ce.assign('a', 1);
const scope = ce.createScope(undefined);
ce.pushScope(scope); ce.declare('a', 'real'); ce.assign('a', 10); ce.popScope();
const e = ce.expr(['Add', ['PointX', 'P'], 'a'], { scope });
compile(e, { to: 'javascript' }).run({});
```

- Interpreter (`e.evaluate()`, 0.193.0 and 0.194.0): 13 (`a` = 10, the
  binding of the boxing scope).
- 0.193.0 compiled: 13.
- 4779733 (0.194.0): 4: the code is `return 4`, so the
  value of `a` came from the outer binding (`a` = 1).

The same with `P` declared `tuple<real, real>` gives 4 too. Control on
4779733: `ce.expr(['Add', 'a', 0.5], { scope })` compiles to 10.5, the
interpreter's value.

## Expected

The compiled code reads each name from the binding of its occurrence, the
binding `evaluate()` reads (the IR README: "The value is read from the
innermost binding of the name"): 13. A compilation that cannot see that
binding declines.

interpreter's (13). READY on 0.193.0, NOT READY on 4779733.
