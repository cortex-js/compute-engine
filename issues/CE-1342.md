An expression built from a symbol made with `ce.symbol()` keeps its old type after a second expression built from the same symbol narrows the symbol's type.

## Witness

Run on main at `7c74ab286db468549e092c1b0ac3f12cd2722508`:

```js
const x = ce.symbol('x');
const t = ce.function('Tuple', [x]);
t.type;                       // tuple<unknown>
ce.function('Add', [x, 1]);   // x.type is now number
t.type;                       // tuple<unknown>; must be tuple<number>
ce.function('Tuple', [x]).type;  // tuple<number>
```

With `const x = ce.box('x')` the second read of `t.type` gives
`tuple<number>`. 0.186.0 gives `tuple<number>` for the `ce.symbol()` form
too. The witness is `crafted`: the host reads the type of an expression
between two constructions that share a symbol object.

## Cause and options

A symbol made outside a boxing has no unit environment until its first
write (`this._env ??= new UnitEnvironment()`, `boxed-symbol.ts:1013` and
`:1378`). The cached type of `t` recorded its read of `x` when `x` had no
environment, and a recorded read does not see an occurrence that gains one
(`binding-unit.ts`, the read tokens).

`CE_TYPE_PARANOID=1` does not report the case: `_checkServedType()`
(`boxed-function.ts:4938`) skips a type served at the type version it was
computed at, and a write in a unit environment moves no version. The clean
runs of that check do not cover a stale type caused by an environment
write.

Options: (a) give the symbol its environment when it is made, so that the
recorded read holds a token of it; (b) leave it until the design of the
type cache is decided in CE-1210, where one counter that moves at every
environment write would remove the recorded reads and this case with them.
The paranoid check needs a mode that compares a served type also at an
unchanged version, whichever option is taken.
