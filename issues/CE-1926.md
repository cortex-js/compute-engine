The limit of a function defined by cases, written with no function literal, is the boolean `False` when a branch is the bare variable.

## Witness

```
Limit(If(x < 0, x, 5), 0)      // "False", where the limit from below is 0 and the two-sided limit does not exist
Limit(If(x != 0, x, 5), 0)     // "False", where the limit is 0
Limit(If(x == 1, 5, x), 1)     // stays unevaluated, and its LaTeX is \lim_{5\to1}x=1
```

Measured at f7fd6933908817051fd7f2b8c008fb5be249e0ad with
`npx tsx scripts/probe.ts --json '["Limit", ["If", ["Less", "x", 0], "x", 5], 0]'`.
The canonical form keeps `If(…)` as the first operand, not wrapped in a
`Function` literal (it prints `lim`). With a branch that is not a bare symbol
(`If(x != 0, x^2, 1)`), or with `Function(If(…), x)`, the canonical form is
`Limit(Function(Block(If(…)), x), 0)` and the value is right (after CE-1867).

## Cause and options

Not investigated. The `canonical` handler of `Limit`
(`src/compute-engine/library/calculus.ts`, `Limit:`) chooses the variable of
the form `Limit(f, a)`; with a bare-symbol branch it does not wrap the body
in a `Function`, and the evaluation then reads the `If` as something else.
Option: wrap the body as for any other expression that reads `x`.
