A function that changes an outer variable through a callback it gets from an expression is accepted without a `scope` declaration and reported as pure.

## Witness

On main after CE-1773, in Epsil:

```epsil
let r = 0
function f() { [x => do { r = r + x; r }][1](1) }
let a = f() + f()
[a, r]
```

The program runs with no diagnostic and gives `[3, 2]` (right), but
`ce.box(['f']).isPure` is `true` and the definition of `f` has no effects.
`function same(g) { g }` with `same(x => do { r = r + x })(1)` in the body
of `f` gives the same result. Writing the callee through a local
(`let k = same(…); k(1)`) is refused as it should be ("writes outside a
function require a declared `scope` effect").

## Cause and options

The `Apply` branch of `Walker.visit` (`effects-inference.ts`) handles the
callee only when it is a `Function` literal or a symbol (`applyNamed`), and
visits `expr.ops.slice(1)`: a callee that is another expression (an `At`, a
call) is never visited, so a literal inside it and the effects of applying
its value are lost. Fix: visit the callee, and count the application of a
computed callee as `{any}`, as an unresolved head counts (it does not set the
proven-mutation bit, so the gate does not fire; `isPure` becomes false).
Size S; measure the test changes.
