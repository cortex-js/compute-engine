In the exact-integer (bigint) compile mode, a function that rounds down half of an integer falls back to the interpreter.

## Witness

From the decline census on GitHub #638: 12 statistics of a combinatorics
corpus. On main f42a02d1323b9e40cf2def511715fc3034ae8d6c:

```ts
ce.declare('n', 'integer');
compile(ce.box(['Floor', ['Divide', 'n', 2]]), { mode: 'bigint', fallback: false });
// Could not compile: 1/2: a number that is not an integer (the bigint mode)
```

The same for `Floor(Rational(1, 2) · n)`. `fallback: true` gives the interpreter's value (the workaround). The `double` mode compiles it.

## Cause and options

The canonical form of `n/2` is `Multiply(1/2, n)`, and the bigint mode refuses
the rational `1/2` before it sees the `Floor`. `Floor`, `Ceil` and `Round` of
`(p/q) · n`, with an integer `n` and a rational constant `p/q`, are an exact
division of `p · n` by `q` in bigint arithmetic, rounded as the operator
says. Lower that form in the bigint emitter.
