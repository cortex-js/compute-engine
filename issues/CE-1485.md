A step that copies a list and then changes the copy no longer compiles, so actions such as the Othello move run on the interpreter.

## Witness

The instrument holds the MathJSON that Tycho passes to `compile` for the
action body of the Othello showcase (recorded on CE main
736f19c8863658fdd803b7e6e7c89288fc908e28, about 10.7 KB):
`Apply(Function(Block(Declare(p_gpBound, {value: At(B_gpBound, 65)}),
Declare(R_gpBound, {value: B_gpBound}), …), Typed(B_gpBound, …), …), B, …)`,
with `B: list<nan | real | signed_infinity>` (the board, 64 cells and the
player to move), options `{ to: 'javascript', symbolic: ['B'] }`.

- 0.193.0: compiles, and on an Othello start board gives the interpreter's
  value.
- 736f19c: "Declare("R_gpBound", {"value" -> "B_gpBound"}): the list local
  R_gpBound, written in place, read other than by At or Length (an alias)".

The same rule declines `Declare(L_gpBound, {value: H_gpBound})` in the
buddhabrot step of prelude-lanes, and `Declare(L1Local, {value: L1})` in the
gasket program of prelude-runner ("its loop compiled").

Relation to CE-1483: CE-1483's instrument (the buddhabrot action body) reads
READY on 736f19c, so CE-1483 can stay `fixed`; the remaining alias declines
are this issue.

## Expected

A list local initialized from a list (a parameter or an input) and then
written in place compiles: the code copies the list once at the
declaration, as the interpreter's value semantics require.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1485-ce1486-ce1487-list-alias-loop-replaceat-probe.mts` in Tycho. `CE-1485: READY` when the action body compiles and
gives the interpreter's value. READY on 0.193.0, NOT READY on 736f19c.

## CE progress (2026-11-18)

Committed in ed23edab1a2544a443f3d1a3c3db088164b5ad4b: a whole read of a list
local written in place is a copy taken at the read; only a capture in a
function literal declines. The buddhabrot step (prelude-lanes) and the
gasket runner's `Block(Declare(L1Local, {value: L1}), …, Tuple(L1Local, …))`
shape compile. The Othello action body then declines at another rule:
`p_gpBound: an argument of Apply that is not integer`, because `p_gpBound`
comes from `At(B_gpBound, 65)` and the row `B` is declared
`list<nan | real | signed_infinity>`; R5 of `docs/COMPILATION-MODEL.md`
forbids the run-time integer test the interpreter makes. Pending a ruling
of the user (Tycho asked): (a) Tycho narrows a live-owned row to the type
its definition and every action write prove (`list<integer>` here), with
no CE change; (b) a run-time integer test at an `integer` parameter, a
change of R5; (c) the body stays on the interpreter.

User decision 2026-11-18: (a). Tycho narrows the row; CE changes nothing
more for this witness, and R5 stays. CE-1485 reads READY once Tycho's
narrowing lands.

## Verification with the narrowed board, 2026-11-19

Changing only the instrument's declaration of `B` to `list<integer>` still
declines at `p_gpBound` on npm 0.194.0 and CE 35d25725c. A fixed outer width
of 65 also declines on that commit. The board's element type is only part
of the contract. The compiler accepts `At(B, 65)` directly at an integer
parameter, but declines when that same expression initializes an unannotated
local and the local is passed to the parameter.

The recorded action compiles on both versions with the integer board and
explicit integer declarations for two locals. Express their existing
initializers in the positional declaration form:
`Declare(p_gpBound, 'integer', At(B_gpBound,65))` and
`Declare(next_gpBound, 'integer', Negate(p_gpBound))`. Every subsequent
write to `next_gpBound` supplies `p_gpBound` or zero. Annotating only
`p_gpBound` moves the decline to `next_gpBound`.

Verified on a legal opening move independently of interpreter equality.
Initialize B with black (+1) at 29 and 36, white (−1) at 28 and 37,
zeros elsewhere, and +1 in slot 65. Supply 20 as the outer Apply's move
argument. Both routes return the exact 65-element board with black at
20, 28, 29, 36, white at 37, and −1 in slot 65. This is a source-level
workaround for the agreed static-contract approach. Tycho's production
emission and browser first correct redraw remain to be verified.
