A colour with a long subscripted name stops working as soon as another
definition is named like one of the letters of that name.

## Witness

On CE 0.197.0, `I_{Past}=3` parses as `["Equal","I_Past",3]`. After
`ce.declare("P", { macro: ["Add", "t", 1] })` the same LaTeX parses as

```json
["Equal", ["Subscript", "I", ["Multiply", "a", "s", "t", ["Add", "t", 1]]], 3]
```

The subscript letters are read as a product, and the macro letter `P` is
expanded inside it. `I_{aPb}=3` and `c_{P}=3` stay one symbol with the same
macro. The instrument prints each case with and without the macro, and READY
when every case parses the same (exit 0); today it prints NOT READY (exit 1).

Tycho document `art/6l8vae4zkn`: row 50 defines a colour
`I_{mSoTiredAtThisPoint…Bai}=\operatorname{rgb}(200,170,120)` (257 letters
in the subscript, including `P`), and row 36 defines the point
`P=(t+0.7,-t-0.7,gt^2+t+0.7)`, drawn as the bomb's fuse in that colour. When
Tycho declares `P` as a macro (ROADMAP MG, which replaces Tycho's value-row
threading with engine macros), row 50 parses as a `Subscript` of a product, the
colour definition is lost, and the fuse draws grey. Tycho keeps `P` on its old
path for now (admission refusal `subscript-letter`); that path is deleted at
the end of ROADMAP MG, so the workaround is temporary.

## Cause and options

Not investigated in CE. The raw parse is
`["Subscript","I",["InvisibleOperator","P","a","s","t"]]`; the canonical form
joins the letters into one symbol only while every letter stays a symbol, and
here the macro expands first. Requested: a subscript made of letters joins into
one name before any macro expansion, whether or not a letter names a macro (as
it does for `I_{aPb}`).
