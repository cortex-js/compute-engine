A color conversion of a computed list of colors in a Tycho document does not compile, so it runs in the slower interpreter.

## Witness

With `A_rg(p) := (Arg(p.x + i·p.y), Arccos(2·p.z − 1))` and `C` three points
(declared `list<tuple<number, number, number>>` or not declared):

```
AsOklab(Hsv(57.29·PointX(A_rg(C)), 1, 0.5))
```

declines on JavaScript: "a color conversion over an operand that may be a
collection at run time and whose type does not prove a color at every element
position". The interpreter gives a list of three `Oklab` values.

## Cause and options

Not traced. `AsOklab(Hsv(H, 1, 0.5))` with `H: list<real>` compiles, and
`Hsv(57.29·PointX(C), 1, 0.5)` has the type `list<color>`, so the decline comes
from the type of `Hsv(… A_rg(C) …)`. Find why that type does not prove a color
at each position. `Hsv(57.29·PointX(A_rg(C)), 1, 0.5)` alone compiles (CE-249.1
and CE-249.2 are done). CE-249.3 had no witness and was dropped. Plan: `docs/plans/2026-09-19-codegen-reassessment-ce1313.md`
(item 3).
