The compiled code of a block that defines `g := s ↦ Length(s)` and calls `g` with a string throws a `RangeError` instead of giving the number of characters.

## Witness

With `S: list<string>` and `t: string`, on the JavaScript target:

- `Block(Assign(g, s ↦ Length(s)), Map(g, S))` compiles to
  `g = ((s) => (_SYS.elts(s, "Length")).length); … (_.S).map(… g …)`.
  At `S = ["xy", "z"]` it throws
  `RangeError: Length: the operand is not a list or a set at run time`; the
  interpreter gives `[2, 1]`.
- `Block(Assign(g, s ↦ Length(s)), g(t))` throws the same error at
  `t = "abc"`; the interpreter gives `3`.

Checked at commit `8c4ca0e8f1c8a7a5f6a837e64e9a0da18fce6dc4`.

## Cause and options

`s` has the inferred type `collection`, and a block-local function has one
emission, compiled against that type: `Length` of a `collection` reads the
operand with `_SYS.elts`, which refuses a string. An engine-level function
takes a copy with the parameter typed `string` for a string argument
(`ensureSpecializedUserCallEmitted()`, `compilation/compiler-core.ts`, CE-1036)
and for string elements of a callback (`stringElementCallbackEta()`,
`compilation/compile-user-functions.ts`, CE-1076). A block-local function has
no such copy. Options: compile the block-local literal with a `string`
parameter when every call and callback use gives a string, or decline the
block-local function when its parameter is a collection type that admits a
string and a use gives a string.
