A host must parse every formula one more time to find out whether it defines a macro, because it cannot ask the engine whether any macro exists.

## Witness

Tycho declares some value rows as macros (`ce.declare(name, { macro })`,
CE 0.188.0). The head of a macro's own definition row (`A = x^2+y^2`) is not
an occurrence, so Tycho must parse that row with `A` hidden by a declaration
in a pushed scope; to know which rows need it, Tycho parses each row raw once
more and looks up each name. On an engine with no macro the extra parse is
waste, but the public API cannot say "no macro here": `lookupDefinition(name)`
answers per name, and the engine's own count is `_macroCount` /
`_macroNames`, both `@internal`. The instrument prints, on a fresh engine and
after `ce.declare('A', { macro: … })`: the public per-name answer, the
internal fields, and the public members whose name contains "macro" (none).

## Cause and options

Tycho's workaround: it records the engines it declared a macro on
(`declareEngineMacro` / `engineHasMacros`, `src/plot-core/ce-definitions.ts`),
which is coarser than the engine's state (the record is never cleared).

Options:

(a) A public read-only `ce.macroNames: ReadonlySet<string>` (the names of
the macros declared in any scope, as `_macroNames` holds), or a boolean
`ce.hasMacros`. Size S.

(b) A parse option that keeps the head of a definition row unexpanded
(`Equal(A, …)` / `Assign(A, …)` where `A` is a macro), which would remove the
need for the hide. Larger, and it makes the engine read `Equal` as a
definition, which it does not do today.

Tycho asks for (a).

Tycho half on adoption: replace the record of engines in
`src/plot-core/ce-definitions.ts` (`declareEngineMacro`, `engineHasMacros`,
`forgetEngineMacros`) by a read of `ce.macroNames`, and skip the hidden parse
of a row none of whose names is in the set.

## Decision

User decision 2026-11-15: approved, option (a), the read-only set `ce.macroNames`.

## CE answer

CE (2026-11-14): P4 confirmed; not scheduled, the board picks it. The
workaround stands and loses little: the engine's own record is as coarse as
Tycho's. `_macroNames` holds every name that was ever declared a macro on the
engine, in any scope, and never shrinks (a popped scope or a later plain
declaration of the name leaves it in the set; `types-engine.ts`,
`_macroNames`), and `_macroCount` is never decremented. So option (a) would
be documented as an upper bound: "no macro was ever declared under this
name" is exact, "this name is a macro here" is not, and
`lookupDefinition(name)` stays the exact per-name answer. What (a) adds over
`engineHasMacros` is the per-name test with no lookup, so a row none of whose
names is in the set skips the hidden parse. If the board takes it, the form
is the read-only set (`ce.macroNames`), not the boolean: the boolean is
`ce.macroNames.size > 0`. Option (b) is not planned: the engine does not
read `Equal` as a definition.

CE (2026-11-15): fixed in `7153df45286f4c394cf22b46c3f892e49a2d0e8e`, for the next
release: `ce.macroNames` is a public read-only set (`ReadonlySet<string>`),
with the meaning stated above (an upper bound that never shrinks; empty on an
engine with no macro). No boolean member: use `ce.macroNames.size > 0`.
