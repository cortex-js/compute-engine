The Apollonian gasket showcase still computes its circles with the interpreter, because a function that reads the first coordinate of an untyped circle is given a one-element tuple as its parameter type.

## Witness

On CE main 406a4db15029306debbb8fe4ce97ad95309a8eb3:

```ts
executeEpsil(ce, 'function t14(c) { let a = 1 / c[1]; a }');
ce.box('t14').type.toString(); // (c: tuple<number>) -> number
```

The parameter `c` is inferred as `tuple<number>`, a tuple of one element,
from `1 / c[1]`. In the gasket prelude, `isNewCircle(c)` is called with a
circle of four numbers and passes `c` to `touches`; compiling declines
"c: an argument of touches that is not tuple<real, real, real>". The
interpreter accepts the call. With `c` declared `tuple<number, number,
number>` the statement compiles. Close to CE-1246 (an element read of a list
parameter used in arithmetic), not the same case.

## Cause and options

An element read `c[1]` of an untyped parameter should infer a collection
type that admits any length (`list<number>` or an indexed collection), not a
tuple of the one position read. Options: (a) infer `indexed_collection<number>`
(or `list<number>`) from an element read; (b) leave the parameter `unknown`.
Workaround: declare the parameter's type.
