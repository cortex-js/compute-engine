`minimalDNF` can return a formula with more terms than needed: it gives 5 terms where 4 are enough.

## Witness

```
MinimalDNF(Or(And(a, c), And(Not(a), Not(b), d), And(Not(a), b, Not(c)),
              And(Not(a), b, Not(d)), And(b, Not(c), d)))
// a && c || !a && !b && d || !a && b && !c || !a && b && !d || b && !c && d   (5 terms)
// a 4-term cover of the same prime implicants:
// !a && !b && d || !a && b && !d || b && !c && d || a && c
```

Measured at 2a744247992202302b079eddfffd7a549164cad8. The 4-term cover was
found by an exhaustive search over the 9 prime implicants that
`PrimeImplicants` gives for the same formula. `MinimalCNF` uses the same
cover search.

## Cause and options

After the essential prime implicants, `findMinimalCover()`
(`src/compute-engine/library/logic-analysis.ts`, about line 1122) adds the
remaining primes greedily (the prime that covers the most uncovered
minterms first), which does not always give the fewest terms. The
descriptions of `MinimalDNF` and `MinimalCNF` now say "usually with few
terms" (`a7290b6da4f91ef774d216b7556da595c48b9d48`).

- (a) Recommended: an exact cover of the remaining minterms (Petrick's
  method, or a branch-and-bound search with the greedy cover as the first
  bound), with a cap on the number of remaining primes above which the
  greedy cover stays; the functions are already limited to 12 variables.
  Restore the "fewest terms" wording when the cover is exact.
- (b) Keep the greedy cover, and rename nothing: the descriptions already
  say what it gives.

Size M.
