In Epsil, a string used as a factor of a product or a term of a sum underlines the whole statement instead of the string variable.

## Witness

```
let s: any = "a"
let v = s * Cos(x)
error frames  ->  none ("expected `number`, got `string` at `a`")
underline     ->  the whole statement `let v = s * Cos(x)`
expected      ->  the frame `Multiply argument 1`, and the underline `s`
```

The same for `Cos(x) * s`, `s + Cos(x)` and `Cos(x) + s`. When the factor is
a call (`Sin(s) * Cos(x)`), the frame names the call and `Sin(s)` is
underlined.

## Cause and options

The operand `s` evaluates to the valid string `"a"`, and the handler of `Add`
or `Multiply` returns the `incompatible-type` error as its value, with no
frame for the call. The Epsil error location then has no frame to select a
call, and uses the range of the statement. Option: the handler, or
`_computeValue()` (`boxed-expression/boxed-function.ts`), adds the frame of
the canonical operand that has the wrong type. The error names the value
`"a"` but not the operand, so the operand must be found by its evaluated
value.
