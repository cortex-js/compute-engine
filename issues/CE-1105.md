On the GPU, a NaN that a prelude function receives can become 0 instead of NaN, so Tycho paints a colour where the CPU paints the fallback.

## Witness

On 0.182.0, with `z` undeclared, `t(z)` compiles to GLSL with the body
`max(0.0, v)` when `t` is `["Function", ["Block", ["Typed", ["Max", 0, "v"],
"'real'"]], ["Typed", "v", "'real'"]]`, the value of an Epsil
`function t(v: real) -> real { max(0, v) }`. With `t` declared
`(real) -> real`, the body is `_gpu_max(0.0, v)`. GLSL `max(0.0, NaN)` is not
defined. `\max(0, z)` in the formula gives `_gpu_max(0.0, z)`.

## Cause and options

The finiteness proof of `gpu-extrema.ts` reads a `Typed` parameter as finite.
(a) Read only the argument facts of the call. (b) Keep it and document that
`v: real` promises a finite argument.

## Tycho impact

None. This is an observation, not a blocker: Tycho has no workaround and needs
none. If the GLSL target gives `max` or `_gpu_max` for this case, Tycho is not
affected either way (Tycho user, 2026-11-07).

## Decision

User decision 2026-11-07: no change for Tycho and no workaround. This is an
observation, not a defect: NaN is outside the type `real`, and the compiled-code
caveats in `AGENTS.md` leave the result unspecified for an argument outside its
declared type, so the GLSL target may read a parameter typed `real` as finite
(option (b)). It is a possible optimization for CE.
