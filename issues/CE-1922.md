A function that declares a list variable with its type, and never changes it, runs interpreted.

## Witness

On CE source after 0.204.2, compiled JavaScript declines a block local of a
stated list type that no later statement writes, whether the list is empty
or not:

| Program (`let frame = (t: real) => …`) | CE source |
| --- | --- |
| `do { let b = [1]; length(b) + t }` (control) | compiles |
| `do { let b: list<real> = [1]; length(b) + t }` | declines: `Declare(b, "list<real>", {"value" -> [1]}): a local of type list<real>` |
| `do { let b: list<real> = []; length(b) + t }` | declines, the same message |
| `do { let b: list<string> = ["x"]; length(b) + t }` | declines, the same message |

The interpreter gives `3`, `2` and `3`.

## Cause and options

In the `Declare` branch of `block()` (`lower.ts`), the list type of a local
(`listType`, `wholeType`) is computed only when a later statement writes the
local. An unwritten local of a list type then reaches the decline "a local
of type …". The option: treat an unwritten local of a stated list type as a
local of no stated type whose value must prove the stated type (as a local
of a named tuple type is, CE-1919), with a `[]` of the stated element type
(`withPlacedEmptyLists()`, CE-1918).

Workaround: leave out the stated type (`let b = [1]`).
