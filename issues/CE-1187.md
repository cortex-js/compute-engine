A program that loads the main package can call `compile()` but not `canCompile()`, so a web page cannot ask whether an expression compiles to GLSL before it compiles it.

## Witness

`import { canCompile } from '@cortex-js/compute-engine'` gives `undefined`.
On the installed 0.185.1 (read by Tycho):
`typeof (await import('@cortex-js/compute-engine')).canCompile` is
`'undefined'`, and `compile` is a function there. `canCompile` is a function
on the subpath `@cortex-js/compute-engine/compile`. The main browser bundle
`dist/esm-min/compute-engine.js` contains no `canCompile`, and the object
that the main bundle stores on `globalThis` under
`Symbol.for('io.cortexjs.compute-engine')` (`ComputeEngineGlobal`,
`src/compute-engine.ts`) has `compile` and no `canCompile`.

Tycho is not blocked: its product reads the `outside-fragment` decline of
`compile()` (`issues/CE-1181.md`), and its codegen audit imports
`canCompile()` from the subpath, in Node. The workaround for a host is the
subpath import.

## Cause and options

`docs/plans/2026-11-08-compile-targets-implementation-plan.md`, step 3, says
"`canCompile(expr, options)` exported beside `compile()`". It is exported
from `src/compile.ts` only, not beside the free function `compile` of the
main entry (`src/compute-engine.ts`, the export list of `free-functions.js`
and `ComputeEngineGlobal`).

Fix: export `canCompile` from `src/compute-engine.ts`, and add it to
`ComputeEngineGlobal` and to the stored object (the contract of that object
is additive). Size S. A CHANGELOG line and the compile guide of cortexjs.io.

Not proposed: a handle returned by `canCompile()` that `compile()` takes to
skip its check. Tycho calls `compile()` anyway, and such a handle would have
to become invalid when a list length or a non-finite value of the document
changes, since the answer depends on both.
