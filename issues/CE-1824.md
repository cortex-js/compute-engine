The test that a value is an element of a sorted list, and the greatest common divisor of a sorted list, stay unevaluated when one of the elements is a variable.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.declare('n', 'integer');
ce.expr(['Element', 1, ['List', 3, 'x', 1]]).evaluate();           // True
ce.expr(['Element', 1, ['Sort', ['List', 3, 'x', 1]]]).evaluate(); // unevaluated, expected True
ce.expr(['Contains', ['Sort', ['List', 3, 'x', 1]], 1]).evaluate(); // True
ce.expr(['GCD', ['List', 6, 'n', 4]]).evaluate();                  // GCD(2, n)
ce.expr(['GCD', ['Sort', ['List', 6, 'n', 4]]]).evaluate();        // unevaluated, expected GCD(2, n)
ce.expr(['LCM', ['Sort', ['List', 6, 'n', 4]]]).evaluate();        // unevaluated, expected LCM(12, n)
```

Read on 0bebdaee7b63afd440151e05c12684ab9151765c.

Workaround: leave out the `Sort`, because the result does not depend on
the order; for the membership test, use `Contains`.

## Cause and options

`Sort` cannot order the variable, so it stays a `Sort` call, which is not a
collection, and the operator has no element to read. CE-1804 made `Sum`,
`Product`, `Max`, `Min` and `Count(xs, v)` read the source of such a `Sort`
(`orderIndependentSource`, `library/collections.ts`). Option: call it on
the collection operand in the `evaluate` handlers of `Element`, `NotElement`,
`GCD` and `LCM`.
