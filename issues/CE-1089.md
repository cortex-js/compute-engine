A function that calls a second function, which the same block defines after it, is applied to each element of a list argument and gives errors in place of its value.

## Witness

Checked 2026-11-07 at `61447c29ee222e9ddac51466aebdd21f626b2c22` with the
fix of CE-1057 applied:

```
Block(Assign(q, a ↦ h(a)), Assign(h, t ↦ Count(t)), q([1, 2]))
  → [Error(incompatible-type, collection, 1, "while applying 'q' element-wise …"),
     Error(incompatible-type, collection, 2, …)]
  expected: 2
```

`.N()` of the same block gives `2`. With the two `Assign` in the other
order, the value is `2`. With `ce.assign()` in this order, the value is `2`.
The test "a callee that the block assigns AFTER the caller is not read" in
`test/compute-engine/whole-collection-parameter.test.ts` pins the error.

## Cause and options

When `Assign(q, …)` runs, it installs an operator definition for `q` and
derives its signature at once. `h` has no definition then, so the call
`h(a)` gives no evidence that `a` takes a whole list, and the slot of `a`
is a scalar slot. When `Assign(h, …)` runs later, nothing derives the
signature of `q` again.

`ce.assign()` has this repair: a function whose body called a name with no
definition is registered as a dependent of that name, and the definition of
the name rebuilds it (`repairProvisionalDependents()`,
`function-utils.ts`). In a block, the call `h(a)` is bound to the
block-local placeholder of `h`, not to a provisional application, so `q` is
not registered.

Option: register the caller as a dependent when
`calledOperatorDefinition()` (`effects-inference.ts`) finds no operator
definition for a callee bound to a block-local placeholder, and let the
`Assign` of that name run the repair. Workaround: assign `h` before `q`, or
define the functions with Epsil `function` (`function q(a) { h(a) }` then
`function h(t) { count(t) }` gives `2` for `q([1, 2])`).
