A selection over lists that stops at the shortest list gives, in the form with the lists bound once, a result that is computed again at each read and that doubles or triples in size each time it passes through a function, so a chain of seven rows takes seconds to read.

## Witness

From Tycho's row MK. After Tycho bound the lists once with `Apply`, the states
`neyret/tghfaqmez7` (build 1.0 s to 11.8 s) and `neyret/l49l5stdag` (0.29 s to
2.2 s) stayed slow. Tycho measured a chain `L_k = s(L_{k-1}, c)` of 8
elements: reading the 8 elements costs 8, 14, 19, 34, 129, 442 and 2,452 ms
at depth 1 to 7, against 0 ms with CE's `Which` over lists.

Reproduced on the working tree of main at
`3b0b23f414e90ada33e633cb641cd9a8fb3c8ef6`:

```ts
const T = 'list<nan | real | signed_infinity>';
const sel = (c, v) => ['Map',
  ['Function', ['Which', ['At', c, 'j'], ['At', v, 'j'], 'True', 'NaN'], 'j'],
  ['Range', 1, ['Min', ['Length', c], ['Length', v]], 1]];
ce.assign('s', ce.box(['Function',
  ['Apply', ['Function', sel('l1', 'l2'), 'l1', 'l2'], ['Less', 'm', 'l'], 'l'],
  ['Typed', 'l', T], ['Typed', 'm', T]]));
ce.declare('L_0', { type: T, value: ce.box(['List', 3, 1, 4, 1, 5, 9, 2, 6]) });
ce.declare('c', { type: T, value: ce.box(['List', 0, 0, 2, 0, 0, 0, 0, 7]) });
for (let d = 1; d <= 7; d++)
  ce.declare(`L_${d}`, { type: T, value: ce.box(['s', `L_${d - 1}`, 'c']) });
const v = ce.box('L_7').evaluate();      // a Map; its JSON has 35,711 characters
[...ce.box(v.json).evaluate().each()];   // [3, 1, 4, 1, 5, 9, 2, NaN]
```

| Depth | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| JSON of the value, characters | 305 | 867 | 1,991 | 4,239 | 8,735 | 17,727 | 35,711 |
| read of the value boxed again, ms | 6 | 12 | 17 | 32 | 53 | 85 | 160 |
| the same with three reads of the lists per level, ms | 3 | 11 | 31 | 75 | 196 | 566 | 1,833 |

With three reads per level (`Which(l2[j] < l1[j], l1[j], True, l2[j])`) the
JSON has 299,506 characters at depth 7. Read through the same boxed object
(`[...v.each()]`), the elements take 3 to 29 ms at every depth: the copies are
one shared object until the value is serialized, substituted or boxed again.
One selection over `n` elements in this form takes 92, 278 and 925 ms for
`n` = 500, 2,000 and 8,000 (CE's `Which`: 4, 15 and 52 ms).

## Request

Tycho asks for one of: an eager `Map` over a finite source; an `Apply` that
binds materialized lists; a `Which` over lists that cuts to the shortest list
(the request of CE-1343).

## Cause and options

- The result of a call is rewritten with each parameter replaced by its
  argument at each occurrence (`bindingKeyedSubs()`, `function-utils.ts`; "a
  function literal means the same as its body with the arguments put in place
  of the parameters"). A lazy `Map` that the body returns therefore holds one
  copy of each bound list per occurrence of the parameter, and the next level
  copies that `Map` again: the size is `k^depth` for `k` occurrences.
- `Map` is lazy by contract (`docs/COLLECTIONS-MODEL.md`, "Lazy
  collections"), and `ListFrom` is the documented way to list it.
- Binding a materialized list does not help today: `Apply(Function(…),
  ListFrom(c))` takes 288, 1,120 and 3,719 ms for 1,000, 2,000 and 4,000
  points, against 133, 255 and 669 ms without `ListFrom`, because a written-out
  list of booleans is evaluated again at each read (CE-1369).

Options, for the day the request is taken up again:

- (a) A selection operator with the clauses of `Which` that cuts to the
  shortest list: `SelectShortest(c1, v1, …, True, d)` (a name to choose). One
  node, all targets; size M. This is CE-1343.
- (b) `Map` answers a list when every source is finite and listed, for
  example under an option `Map(f, xs, …, {eager: true})`. Size M; changes the
  documented rule that a `Map` is a view.
- (c) A parameter that occurs several times in a lazy result is bound once
  (a `Block` with one local per parameter around the result) in place of one
  copy per occurrence. Size L; changes what the value of a call looks like.

## CE answer

CE (`ce-compiler`, 2026-11-16): P3 (a request with a workaround). Disposition:
deferred by the user on 2026-11-16, see the Decision; no engine change.

Workaround, measured on 0.192.0 source. Each list of the piecewise is a
source of a `Map`, the callback holds the scalar piecewise, and `ListFrom`
lists the result. The sources are evaluated once and the `Map` stops at the
shortest source (`docs/COLLECTIONS-MODEL.md`, "Broadcasting and pairing"):

```json
["ListFrom", ["Map",
  ["Function", ["Which", ["Less", "a", "b"], "b", "True", "NaN"], "a", "b"],
  "W", "V"]]
```

It gives `[3, NaN]` for `W = [0, 2]`, `V = [3, 1, 4]` and `[3]` for
`W = [0, 2, 9, 9]`, `V = [3]`. The same as a host function written in
MathJSON and called at each site, declared
`(list<…>, list<…>) -> list<…>`: `sel := Function(ListFrom(Map(…, w, v)), w, v)`.

| | chain, depth 1 to 7: evaluate `L_k`, ms | read of the value, ms | one selection, `n` = 500 / 2,000 / 8,000, ms |
| --- | --- | --- | --- |
| row MK form, lists bound with `Apply` | 10, 14, 22, 20, 29, 40, 45 | 5 to 182 | 92 / 278 / 925 |
| host function `sel(w, v)` | 3.3, 2.4, 3.6, 3.7, 3.6, 6.9, 4.3 | 0 (a `List`) | 11.5 / 45 / 181 |
| the same `Map` in place | 1.9, 2.0, 2.9, 2.9, 2.4, 5.1, 2.9 | 0 (a `List`) | 12.9 / 43 / 141 |
| CE's `Which` over lists (equal lengths only) | 1.0 to 4.1 | 0 (a `List`) | 4.3 / 15 / 52 |

Limits of the workaround:

- A condition that compares two lists is written inside the callback
  (`a < b`), not as a source `W < V`: a comparison of two whole lists of
  different lengths is the `incompatible-dimensions` error (strict length
  agreement of a lifted operator).
- The existing JavaScript compiler compiles the `Map` over two lists and the
  host function, with the same values. The profile `ir` declines them with
  `fallback: false`: "Map of more than one list" and "the operator ListFrom is
  not in the slice". A host function with a `list<boolean>` parameter is
  declined by both ("the parameter c of sel is not a scalar (list<boolean>)";
  "operand 2 has elements of type 'boolean'"), so the lists passed are the
  numeric ones.
- A parameter typed `real | list<real>` is not covered: that case stays in
  CE-1343.

## Decision

User decision 2026-11-16: "Let's defer the native operators for now, but keep in mind we might need to revisit: some users other than Tycho may have used them and depending on how the migration to pure JSON works for them we might need to reconsider." Revisit when the migration of hosts from custom handlers to plain MathJSON (Tycho's and other users') shows that the existing forms are not enough.
