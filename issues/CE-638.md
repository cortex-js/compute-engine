A function that takes another function as an argument multiplies by it instead of calling it, with no warning.

## Witness

```
(g \mapsto \int_0^1 g(x)\,dx)(t \mapsto t^2)  → incompatible-type error, .N() gives NaN; expected 1/3
h(p, a) := p(a)                               → Multiply(a, p), so h(t ↦ t², 0.5) is 0.5·(t ↦ t²)
```

With `(g\colon \mathrm{function})` the first gives 0.3333. After
`ce.declare('g', 'function')`, `g \mapsto g(x)` reads a call; without it, a
product. Probed again 2026-11-06.

## Cause and options

`headHasNoTypeInformation()` (`boxed-expression/invisible-operator.ts`) returns
false for a parameter of the literal being read. `definitions-core.ts`
registers an unannotated `\mapsto` parameter as `'function'` only when the
outer scope resolves the name to a function; `parseFunctionDefinitionBody()`
always reads it as a value.

User decision 2026-11-05: option (b). Read an untyped parameter as an
undeclared head: `p(…)` is a call unless the argument contains `p` (`q(2q)`
stays a product). This reverses the CHANGELOG statement of commit `4ac8db89c`
and the test in `juxtaposition-application.test.ts` (`(x, N) \mapsto x(N+1)`
applied to (2, 3) gives 8); other changed tests are not measured.
