A value computed in one statement from a call of a function declared later can differ between the Epsil runner and a block.

## Witness

A program with a `type` statement before `function g`, and a call before it:
`let s = String(g(3))`. The stored call is resolved when it is read again, so
`g(3)` agrees with the block route, but `s` keeps the text of the unresolved
call.

## Cause and options

The runner does not prepare a `function` statement after a `type` statement,
when the body reads an earlier value with no static type, or for a generic
function. A call evaluated while its head has no value stays symbolic for the
rest of that top-level evaluation. Plan:
`docs/plans/2026-10-21-function-declaration-hoisting.md`.
