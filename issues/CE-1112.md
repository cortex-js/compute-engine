A function whose parameter has the name of a built-in function, saved and loaded again, gives an error instead of its value.

## Witness

At commit `5408577629d05c0bd64ad5caf56aafeb47b7d322` (not in 0.183.0):

```ts
const lit = ce.box(['Function', ['Block', ['N', 'a']], 'N', 'a']);
lit.json
// today: ["Function",["Block",["Apply",["Module","N"],"a"]],"N","a"]
// must be: ["Function",["Block",["N","a"]],"N","a"]
ce.box(['Apply', lit.json, ['Function', ['Multiply', 2, 't'], 't'], 3]).evaluate()
// today: Error("qualified-call-shadowed", N); must be: 6 (the boxed literal gives 6)
```

A second form: the `evaluate` handler of `D` called by a host with no
`expression` option (`def.operator.evaluate([Sin(x), x], { engine: ce })`)
gives a result whose MathJSON is `["Cos", ["Module", "x"]]`; it must be
`["Cos", "x"]`.

Two tests fail at that commit, in the full suite and alone:
`test/compute-engine/juxtaposition-application.test.ts` ("a parameter with a
library name") and `test/compute-engine/d-node-derivative-memo.test.ts` ("a
call of the evaluate handler with no expression differentiates").

## Cause and options

Not traced. CE-1099 (`acf5a9183`, `b9cda8cb5`) writes a library name as
`["Module", name]` in the MathJSON of an expression inside a scope that
shadows the name (`src/compute-engine/library-shadowing.ts`). A parameter of
a function literal is the shadowing binding itself, not a read of the
library definition, so it must stay a plain symbol. Why the `x` of the `D`
case is written as `Module` is not known. A peer session has
uncommitted changes in `library-shadowing.ts` on 2026-11-07 (plans
`docs/plans/2026-11-07-ce1109-*.md`); it may already fix this.
