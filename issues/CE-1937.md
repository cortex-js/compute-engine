A set built from the elements of a sorted list of two integers holds every integer between them, and a set built from a reversed or shortened list stays unevaluated.

## Witness

```ts
const ce = new ComputeEngine();
ce.parse('\\{k \\mid k \\in \\operatorname{Sort}([5,1])\\}').evaluate().json;
// ["Set",1,2,3,4,5], expected ["Set",1,5]
ce.parse('\\{k \\mid k \\in \\operatorname{Take}([1,5,7],2)\\}').evaluate().json;
// ["Set","k",["Condition",["Element","k",["Take",["List",1,5,7],2]]]],
// expected ["Set",1,5]
ce.parse('\\{k^2 \\mid k \\in \\operatorname{Sort}([3,2,1])\\}').evaluate().json;
// ["Set",1,4,9], as expected
```

Read on the tree of the CE-1820 fix (based on
4c015fe6e13f9e2cd56b1bd2a5a7da6ae76a6d4c). The first line has the same value
before that fix: the code is older. `Reverse` does the same as `Take`.

## Cause and options

`enumerateSetComprehension` and its async twin (`library/collections.ts`)
call `extractFiniteDomainWithReason` and, when it fails, call it again with
the evaluated domain wrapped in a new `Element` clause. That clause reads an
evaluated list of two integers as a range, as it reads a written `[a, b]`
(EL-1): `Sort([5, 1])` evaluates to `[1, 5]`, which becomes the range 1..5. A
lazy view (`Take`, `Reverse`) evaluates to itself, so no retry is made, and
the extractor is called with `evaluateCalls = false` (CE-1820) so that the
domain is evaluated once.

Option: read the evaluated domain as a collection, not as a written `Element`
set: enumerate a finite collection with `each()`, as the `evaluateCalls`
branch of `extractFiniteDomainWithReason` does for `Sum` and `Product`, on
both routes, with the caller's evaluation options.
