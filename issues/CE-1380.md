The `epsil` command line tool prints `True`, `False` and `Nothing` in quotes, so a reader cannot tell them from strings.

## Witness

`npx tsx src/cli/epsil.ts -e 'congruent(26, 11, 5)'` prints `"True"`;
`-e '[congruent(26, 11, 5), 1 == 2]'` prints `["True","False"]`, and
`-e 'let a = 3; [a, x, "s", 1 == 1]'` prints `[3,x,"s","True"]`: the string
`"s"` and the boolean look the same. The generated library reference shows the
same form (`[12,"Nothing",34]`). Main (a28dd290f). A symbol inside an
unevaluated call is quoted too: `quotientRing(Integers, 3)` prints
`QuotientRing("Integers", 3)` (main 1e146ff55).

## Cause and options

A list result is printed as JSON of its MathJSON form, where a symbol is a JSON
string. Fix: print the result in Epsil syntax (`true`, `false`, `nothing`,
strings in quotes), the same way a scalar result is printed (`x + 1`), and
regenerate the examples of the reference.
