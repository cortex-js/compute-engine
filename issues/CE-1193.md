`NIntegrate` of an integrand whose parameter has a declared type gives a wrong finite value when a sample overflows: the log-space evaluation is skipped for a typed parameter.

## Witness

```
NIntegrate(Function(x^100 * Exp(-x), x), 0, +oo)                  9.332621544394413e+157  (100!)
NIntegrate(Function(x^100 * Exp(-x), Typed(x, 'real')), 0, +oo)   1.4305122315051679e+121
                                                                  9.839659479203925e+114 on the next call
```

Run on `df139e2e6f70b317f3c81702f14b1cf0a167a412` (2026-11-10). The value
with the typed parameter changes from call to call.

## Cause and options

`withLogSpaceFallback()` in `src/compute-engine/library/calculus.ts` reads the
names of the parameters with `sym(p)`. A typed parameter is
`Typed(x, 'real')`, for which `sym()` gives `undefined`, and the function
then returns the plain runner: `if (names.some((n) => n === undefined))
return run`. A sample where `x^100` overflows is then not computed again in
log space, and the quadrature falls to a Monte-Carlo estimate.

The fix reads the name of a `Typed` parameter (its first operand), as the
other readers of a `Function` literal do.

Found during the review of the `numeric-kernel` profile switch
(`docs/plans/2026-11-10-js-profile-first-consumer.md`): the profile admits
only typed parameters, so no integrand it admits reaches the log-space path.
