In Epsil, a call or a list that ends after its opening bracket or after a comma gets the message `Unexpected symbol ""`, and the REPL does not wait for the next line.

## Witness

```
[1,
```

`parseEpsil` gives `["unexpected-symbol", ""]` at `[3, 3]` and
`["closing-bracket-expected", "]"]`. The same holds for `f(`, `f(1,`, `[` and
`f(` followed by a line break. `for x` gives `["unexpected-symbol", ""]` alone.
`[1, 2` gives `closing-bracket-expected` alone.

In the REPL, `isRecoverable('[1,', diagnostics)` (`src/cli/repl.ts`) is
`false`, so a list or a call written on several lines with the line break
after a comma or after the opening bracket is an error at the first line. It
is `true` for `[1, 2` and for `f(1`.

## Cause and options

The parser reports the `EOF` token as an unexpected token, and the text of
that token is empty: `reportUnexpected(this.current)` in the element loops of
a call, a list and a pattern, and
`this.error(['unexpected-symbol', this.current.text], …)` after `for x`
(`src/epsil/parser.ts`). `isRecoverable` continues the input only when each
error has a code from its list, and `unexpected-symbol` is not in the list.

Options: (a) `reportUnexpected` reports `expression-expected` for the `EOF`
token, the `for` site reports the missing `in`, and `isRecoverable` continues
when each error has `incomplete: true`; (b) only add the case of an empty
symbol to the message text and to `isRecoverable`. Recommended: (a). Size S.
