`Gamma(s, z)` does not end at machine precision for a very large negative integer order `s` and `0 < z < 1`.

## Witness

At `c7a0257ad`, with `ce.precision = 'machine'`:

| Program | Result |
| --- | --- |
| `ce.box(['Gamma', -1e300, 0.5]).N()` | no result after 15 s |
| `ce.box(['Gamma', -1e300, 1.386]).N()` | `0`, in 3 ms |

The value is about `0.5^(−1e300−1)·e^(−0.5)/1e300`, past the double range.

## Cause and options

The real kernel `incompleteGammaUpper` (`numerics/special-functions.ts`)
sends an integer `s ≤ 0` with `z < 1` to `upperGammaNegIntReal`, whose
recurrence from E₁(z) runs `−s` steps. For a non-integer `s` the same kernel
caps the shift at `UPPER_GAMMA_SHIFT_MAX_ORDER` (4096) and uses the Legendre
continued fraction above it. Option: the same cap for the integer route.
Past the cap the value overflows for `z` below about 0.8 (the comment at
`UPPER_GAMMA_SHIFT_MAX_ORDER`), so the route can also decline there.
