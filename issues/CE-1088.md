A function declared to take a point of integers accepts a point with a fractional coordinate and returns that fraction as its integer result.

## Witness

At `a4fe2d1e3fd197861f50a488569da21f783373dc`:

```ts
const ce = new ComputeEngine();
ce.declare('U', '(tuple<integer, integer>) -> integer');
ce.parse('U(p) := p.x').evaluate();
ce.box(['U', ['Tuple', 1.5, 2]]);         // valid, type integer, evaluates to 1.5
ce.assign('r', ce.box(['Tuple', 1.5, 2]));
ce.box(['U', 'r']);                        // valid, type integer, evaluates to 1.5
```

Expected: the same `incompatible-type` error that a scalar parameter gives
for `1.5` at `integer`. A call that maps over a list of points refuses the
same point: `U([(1.5, 2)])` evaluates to `[Error(incompatible-type, …)]`
(`fitsPointSlot()` in `src/compute-engine/boxed-expression/boxed-function.ts`
checks each component with `admissionOf()`).

## Cause and options

The argument check at boxing accepts a tuple at a point parameter when the
two tuple types overlap, and the run-time check (`runtimeConformanceError()`
in `src/compute-engine/boxed-expression/validate.ts`) does not refute the
point. Option: check each component of a `Tuple` argument with
`admissionOf()` at boxing and at evaluation, as the mapped call does. Size S.
