A `for` loop over a number or a boolean runs no iteration and reports
nothing, so a program that meant `for i in 1..n` gives a wrong result with no
error.

## Witness

On the worktree of CE-1664 (main plus CE-1664.1 to .3, `4d645c5607b2f1bf450a4d43548e01f14df0cf56`):

```epsil
let n = 5
let t = 0
for i in n { t = t + i }
t
```

`checkEpsil` gives no diagnostic and `executeEpsil` gives `0`. The same holds
for `for i in true { print(i) }` (prints nothing) and for a function value.
The comprehension `[i for i in n]` gives
`Error(ErrorCode("incompatible-type", "collection", "5"), 5)` at run time,
and `checkEpsil` gives no diagnostic for it either.

## Cause and options

The `Loop` signature is `(body: expression, iterators: expression*) -> any`,
so the static check does not read the type of the collection of an
`Element` clause, and the run of the loop (`runLoop` in
`library/control-structures.ts`; the line that skips the value is not
located) does not report a value that is not a collection. Options: report `incompatible-type`
in the static check when the static type of the collection does not overlap
`collection`, and give the same error value as the comprehension at run time.
The completion (CE-1664.4) already expects `collection` there and marks a
number `never`.
