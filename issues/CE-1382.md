A list comprehension over a list with one value of the wrong type stops the whole program, where `map` with the same body keeps an error in that cell.

## Witness

Epsil CLI, main a28dd290f:

- `map(x => x^2, [16, -4, "banana"])` prints
  `[256, 16, Error(ErrorCode("incompatible-type", "number", "string"), "banana")]`.
- `[x^2 for x in [16, -4, "banana"]]`, also with the list in a `let`, prints
  `error: Runtime error: expected \`number\`, got \`string\` at \`banana\`` and gives no
  value.

`docs/ERROR-MODEL.md` (around line 1136) says that a `Map` and a
comprehension both give each cell to the body and that the result is a list
whose cell holds the error. `map(x => sqrt(x), ["banana"])` is refused by the
static check (the element type is `string`), which is right: that type error
shows in the static type.

## Cause and options

The comprehension route reports the body's error as a run-time error and does
not keep it as the cell's value. Fix: the comprehension keeps the error in the
cell, as `Map` does. Workaround: `map`.
