A condition on the result of a function that calls another function does not compile unless the author first stores the result in a typed local.

## Witness

Tycho's Othello Prelude (`src/graph-paper/onboarding/showcase-othello.js`): `ray(B: list<integer>, k, p, dx, dy) -> integer` counts in a loop, and `flips(B: list<integer>, k, p) -> integer` adds `ray(...)` calls in a loop. With `L` declared `list<integer>`, after the CE-1179 fix `ray(L, 3, 1, 1, 0)` is `integer`, but `flips(L, 3, 1)` is still `integer | list<any>`, so `if flips(B, k, p) > 0 { … }` declines compilation. Workaround: `let count: integer = flips(B, k, p)`, which the Prelude has.

## Cause and options

The CE-1179 fix (`boxedBodyResultType`, `call-result-type.ts`) uses the type of the body as boxed only when the body calls no user function: the type of such a call was derived when the body was boxed, and it can go stale when the called function reads a name whose inferred type widens later, or when its name is assigned another function (both witnessed by the review of CE-1179). Options: (a) admit a call of a user function whose signature is declared and whose name cannot be assigned a function outside that signature, applying the same guard to the called literal transitively; (b) re-derive the called function's result at the call instead of reading the boxed type. Size M.
