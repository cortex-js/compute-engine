In the arm of a `match`, `a[1] = 2` changes nothing and gives no warning, where `a = 2` in the same place warns that it is an equation and not an assignment.

## Witness

Checked at `d13f9c832b7713e8d4def65266d471f54a579efd`, with `executeEpsil`:

```epsil
let a = [1, 2]
match 1 { 1 => a[1] = 2 }
a
```

The value is `[1, 2]` and there is no diagnostic.

Control: `let a = 5; match 1 { 1 => a = 2 }; a` gives `5` and the warning
`equation-not-assignment: a = 2`. The user who writes the first program
expects `[2, 2]` and gets no sign that the statement was read as an equation.

## Cause and options

The warning `equation-not-assignment` is made for an `=` whose left side is a
name. A left side that is an index (`a[1]`, `p.pixels[i]`) is not in its
test.

- (a) Give the warning for an `=` in the arm of a `match` whose left side is
  an index of a name or of a field, as for a name (recommended).
- (b) Read `a[1] = 2` in the arm of a `match` as the element write that it is
  as a statement. It changes what the arm of a `match` admits.
