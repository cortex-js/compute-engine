After a variable that holds a list is given a number, its type is that one number (`7`) instead of `integer`, and code compiled in that state ignores the input value.

## Witness

Run on main at `b3a2ae1065d1b8483bc5124e5ebbde813af6289a` (by the agent of the investigation; not run again by the session):

```
const ce = new ComputeEngine();
ce.assign('L', ce.box(['List', 1, 2]));
ce.assign('L', 7);
ce.box('L').type.toString();                  // '7'; a fresh `L := 7` gives 'integer'
ce.box(['Add', 'L', 1]).type.toString();      // 'integer<8..8>'
ce.box(['Equal', 'L', 7]).type.toString();    // 'true'
ce.box(['Subtract', 'L', 7]).type.toString(); // 'integer<0..0>'
const c = compile(ce.box(['If', ['Equal', 'L', 7], 1, 2]),
  { to: 'javascript', fallback: false, vars: { L: '_.L' } });
c.code;              // '1'
c.run({ L: 8 });     // 1; after a fresh `L := 7` the code is
                     // `(_.L === 7) ? 1 : 2` and the run gives 2
ce.assign('L', 8);   // accepted; the type widens to 'integer'
ce.assign('L', 2.5); // accepted; 'real'
```

`ce.parse('L := 7').evaluate()` after `L := [1, 2]` gives the same type `7`.
The next assignment of another number widens the type again, so the defect
lasts until the next assignment. `docs/TYPE-SYSTEM.md` ("A literal type
lives at an EXPRESSION position only. Every storage position widens it back
to its tier: an inferred declaration, …") says the type is `integer`, and
with `integer` the input 8 is of the type. With the stored type `7`, the
compiled code treats 8 as an input outside its type, which the contract
leaves unspecified. The probability is set to low, below the table value
for a plausible witness: the case needs an undeclared name that changes
from a list to a number, and a compile with the name as an input before
the next assignment.

## Cause and options

`deriveAndWriteAssignedType` (`src/compute-engine/engine-declarations.ts`,
`let adopted = d11 ? vt : widened;`): when the widening gives a union (a
list type and `7`), the D11 branch adopts the value's raw type `vt`. The
literal promotion (`promotedValueType()`, a few lines below) is skipped for
D11 on purpose ("adopting the raw type for an incompatible guess is
established semantics"). That comment and `TYPE-SYSTEM.md` disagree.

- (a) Adopt `promotedValueType()` in the D11 branch, as a fresh assignment
  does. Recommended; one line. The case D11 was written for (a name guessed
  `function`, then given `5`) then stores `integer`, not `5`.
- (b) No change, and `TYPE-SYSTEM.md` names this exception.
