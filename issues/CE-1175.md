An invisible box, then a visual space, then a minus sign at the start of an expression gives an error: `\phantom{x}\,-b` is `-b + Error(…)`.

## Witness

Readings of 2026-11-08, on `b057ee7820a1496a6d70a1e8113d6ebdb82b3cca` with the
CE-1173 fix applied (the fix does not change these readings), with
`ce.parse(latex, { canonical: false }).json` and `ce.parse(latex).toString()`:

```
\phantom{x}\,-b     Subtract(HorizontalSpacing(3), b)   -b + Error(ErrorCode("incompatible-type", "number", "nothing"), "Nothing")
\vphantom{x}\,-b    Subtract(HorizontalSpacing(3), b)   -b + Error(…)
\phantom{x}-b       Negate(b)                           -b     (control: no space)
\,-b                Negate(b)                           -b     (control: no box)
\displaystyle\,-b   Annotated(Negate(b), …)             -b with its style   (correct: a style switch)
```

The witness is crafted: the box, the space and the sign are chosen together.
The workaround is to remove the spacing command.

## Cause and options

Not traced. The raw form has no operand for the box, and the spacing command
is the left operand of the sign. `parsePrefixOperatorAfterSpacing()`
(`latex-syntax/parse.ts`) skips visual space before a prefix operator only at
the first token of an expression, and here the box comes first.

Options: (a) after an invisible box or a strut at the start of an expression,
apply the same rule; (b) drop a spacing operand in the canonical forms of the
arithmetic operators, which adds a rule to each operator.
