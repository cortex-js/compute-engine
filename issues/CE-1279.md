A plotted function that reads a slider under an absolute value (or a root) draws the wrong curve after the slider goes negative, when the function was defined before the slider.

## Witness

CE 0.188.1 from the npm package (0.188.0 gives the same code, so this is not a regression of 0.188.1).

```
ce.declare('x', 'real');
ce.parse('f(x) := |a| x').evaluate();   // `a` has no declaration yet
ce.declare('a', 'real'); ce.assign('a', 4);
ce.pushScope(); ce.declare('a', { type: 'real' });
compile(ce.rebind(ce.parse('f(x)')), { to: 'javascript', symbolic: ['a'] })
```

| `a` declared | option | preamble | `run({ x: 2, a: -3 })` |
| --- | --- | --- | --- |
| after `f` | `symbolic: ['a']` | `const _fn_f = (x) => x * _.a;` | -6 (6 is right) |
| after `f` | `vars: { a: '_.a' }` | `const _fn_f = (x) => x * _.a;` | -6 |
| before `f` | `symbolic: ['a']` | `const _fn_f = (x) => x * Math.abs(_.a);` | 6 |
| before `f` | `vars: { a: '_.a' }` | `const _fn_f = (x) => x * Math.abs(_.a);` | 6 |

The CE session reported that the code is right when the compile runs in one scope (no push); the instrument does not cover that form.

The instrument prints each row and `CE-1279: READY` when each compiled function gives 6 (a declined compile also counts: it falls back to the interpreter).

## What it must give

The value of a `symbolic` or `vars` name is hidden on every definition that an occurrence of the name reads, also the definition that a body boxed before the declaration reads, so that no analysis of the body reads the stored value.

## Why Tycho reports it

Tycho compiles a row with its sliders as run-time inputs, so that a drag needs no new compile. A document can register a function before the slider it reads. Tycho does not depend on the fix today: around a compile that calls a stored function it removes the stored values itself (`withValuesHidden` in `src/plot-core/ce-module-registry.ts`). That workaround stays until this issue is fixed; each hide and restore makes the engine's memo caches cold, which is its cost. ROADMAP row MH of Tycho removes it.

## Tycho half on adoption

Tycho half on adoption: run the instrument; when it prints `CE-1279: READY`, remove `withValuesHidden` from `src/plot-core/ce-module-registry.ts` and its CE-1279 marker (ROADMAP row MH).

## Cause and options

From the CE session's message (not verified by Tycho): the fix of 0.188.1 hides the value on every definition that an occurrence of the name reads; the occurrence in a body boxed before the declaration is not reached.

## CE answer

CE (2026-11-13, session ce-desk): fixed in the commit `e4dce80669e8af0323a48f28d8f62faaeb4815e0`, for the next
release. The walks that collect the definitions to hide, and that follow
values for the choice of the scope, now take the definition that an
occurrence READS (`BoxedSymbol._readDefinition()`: for a name that had no
definition when the body was boxed, the declaration made later), and its
own definition too. The four rows of the witness give `x * Math.abs(_.a)`
and 6 on the source of that commit; the program is a test
(`test/compute-engine/compile-symbolic-option.test.ts`, "the value is hidden
in a body that was boxed before the name was declared", with `symbolic` and
with `vars`). Keep the workaround until the release that holds the commit;
then run the instrument.
