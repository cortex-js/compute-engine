A full validation run can fail the deep-colour robustness test while the same file passes on an immediate rerun.

## Witness

`npm test -- --watchman=false` failed only the `ir-colors.test.ts` case
“a chain of 1,000 conditionals compiles, and a chain of 1,000 conversions…”:
`CompileDeclineError: ... an expression too deep to compile`. The run passed
85,705 tests and all 4,264 snapshots. An immediate unchanged-source rerun,
`npx jest --watchman=false -w 2 -- test/compute-engine/ir-colors.test.ts`,
passed all 68 tests in 6.071 seconds with browser access enabled.

The fixture constructs 1,000 `Which` clauses and conversion nodes; probability
is low because this deliberately reaches the host stack boundary. A rerun is
the workaround. The source already documents host-dependent depth declines.

## Cause and options

Cause is unconfirmed; worker/JIT/stack state is a hypothesis. The requested work
is stabilizing the harness expectation around conservative depth declines.
No compiler handler or additional admission is proposed. The Program task did
not change the IR implementation or this test. Raw failed-run and successful
rerun evidence is in
`docs/scratch/program-accepted-measurements-2026-11-15/`.

Seen again on 2026-11-16 (`ce-compiler`, the pipeline's jest set of 39 files
with `-w 3` on main `1e146ff55` plus batch G30; the file passed alone twice
on that tree and on main). Measured under `tsx`, the deepest chain of `Which`
clauses of this fixture that compiles: 998 on JavaScript and 1,159 on GLSL
on main `edf0cacf9`, 1,182 and 1,067 with G30: the fixture's 1,000 is at the
boundary on both trees, and the two targets move in opposite directions
between them (one run each).
