With parse diagnostics on, a free variable after an integral, with the name of its integration variable, gets no "undeclared symbol" warning when the sum is in braces or after a one-sided `\left( … \right.`.

## Witness

Readings of 2026-11-07, at commit `ea69bfd468ea07da790fa46700cec13cfd8c0635`,
with `ce.parse(latex, { diagnostics: true })`:

```
\int {\frac{x\,dx}{2} + x}                 no undeclared-symbol for the last x
\int \left(\frac{x\,dx}{2}\right. + x      no undeclared-symbol for the last x
\int \frac{x\,dx}{2} + x                   the last x has its diagnostic (correct)
```

The parse result is correct; only the diagnostic is missing.

## Cause and options

The sum branch of `parseIntegral()` (`definitions-calculus.ts`) removes the
diagnostics of the integration variable up to `integrandEndToken()`, which
counts brackets to find the top-level `+`. A group that the parser removes
(`{…}`) or a null delimiter (`\right.`) gives a wrong count, and the end is
after the free `x`. Fix: when the count is not reliable, use the empty span,
which keeps every diagnostic.
