The compiled code of a chain of helper functions grows with the product of their call counts.

## Witness

`x: real`; `f := Function(Sin(a), a)`;
`g := Function(f(b) + f(b + 1) + … + f(b + 4), b)`;
`h := Function(g(c) + g(c + 1) + … + g(c + 4), c)`;
`compile(h(x), { to: 'javascript' })`.

0.193.0: one `Math.sin(` site (shared functions), 226 characters.
0.194.0: 21 `Math.sin(` sites, 760 characters. The value is the same
(-1.427643238723515 at x = 0.3).

The IR README ("User functions", the pass `inline`) documents the rule
`'repeated'` and its budget of 4,000 instructions, so this is within the
documented behavior. Tycho's concern is the code size of deep Desmos helper
chains: Tycho has a cap on the compiled text (`COMPILED_OUTPUT_MAX_CHARS`)
past which a row takes the symbolic route.

## Expected

The code holds at most 5 `Math.sin(` sites (`f` copied into `g`, `g`
kept as a function), and gives the interpreter's value.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1471-ce1472-ce1473-ce1474-ce1475-ce1476-ce1477-ce1478-compiler-regressions-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value with the interpreter's. The last line for this issue reads `CE-1475: READY` when the code has at most 5 `Math.sin(` sites and gives the interpreter's value.

## Decision

User decision 2026-11-18: (a)
