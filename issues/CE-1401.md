`digitsFrom` gives 0 for a negative hexadecimal string such as `"-0x1F"`.

## Witness

Epsil CLI, main 412113c86: `digitsFrom("-0x1F")` and `digitsFrom(" -0x1F ")`
give 0; `digitsFrom("0x1F")` gives 31 and `digitsFrom("-31")` gives -31. It must
give -31, or an error if a sign before the prefix is not accepted.
`numberFrom(" -0x1F ")` gives the error "invalid number". Also,
`digitsFrom(x)` with `x` undeclared is the error "expected `string`, got
`character | string`", where `numberFrom(x)` and `integerString(x)` stay
unevaluated.

## Cause and options

`DigitsFrom` (`library/core.ts` around line 12189; a `@todo` there says the
`0x` prefix is not yet a documented format) reads the prefix only at the
start of the string. Fix: read an optional sign, then the prefix, or answer an
error for a string it cannot read, never 0. Make `digitsFrom(x)` stay
unevaluated, as `numberFrom(x)` does.
