The inverse of a pixel channel, `255 - p.r`, is not accepted as a byte when the byte type is written with the recommended `type alias Byte = integer<0..255>`, so `Pixel(255 - p.r, 255 - p.g, 255 - p.b, p.a)` does not compile, on JavaScript or in a shader.

## Witness

At commit `d58a3afa02ba53e4eecd5bbd9aa37b49b49e323d`, after `executeEpsil()` of
`type alias Byte = integer<0..255>`, with `ce.declare('b', 'Byte')` and
`ce.declare('c', 'integer<0..255>')`:

| Expression | Type | Expected |
| --- | --- | --- |
| `ce.box(['Negate', 'b']).type` | `Byte` | `integer<-255..0>` |
| `ce.box(['Subtract', 255, 'b']).type` | `integer<255..510>` | `integer<0..255>` |
| `ce.box(['Negate', 'c']).type` | `integer<-255..0>` | the same |
| `ce.box(['Subtract', 255, 'c']).type` | `integer<0..255>` | the same |

The type `Byte` of `-b` excludes every value that `-b` takes but 0. The
values are right: `inv(10)` with `function inv(v: Byte) { 255 - v }` is 245
in the interpreter.

The effect that a user sees: with `type Pixel = tuple<r: Byte, g: Byte,
b: Byte, a: Byte>`,
`function invert(p: Pixel) { Pixel(255 - p.r, 255 - p.g, 255 - p.b, p.a) }`
declines in compiled code on both targets ("a value of type
integer<255..510>, which does not prove Byte"), and so does an untyped
`rgba(r, g, b, a)` that builds a `Pixel` from such values. No wrong value was
found: the sign of `-b` comes from the `sgn` handler, not from the type
(`Abs(-b)` simplifies to `b`; `If(-b >= 0, 1, 2)` compiled at 10 is 2).

Workaround: clamp each channel (`min(max(255 - p.r, 0), 255)`), or declare
the value `integer<0..255>` without the alias.

The probability is `high`, not the `medium` of a plausible witness: the
guides and the array spec recommend the alias `Byte`, and `255 - channel` is
the first operation of a pixel program.

## Cause and options

The type handler of `Negate` (`src/compute-engine/library/arithmetic.ts`,
`Negate`, `type`) unfolds a transparent alias of a shape and keeps the name
of a scalar alias: "`-m` for `m: meters` is `meters`". For an alias whose
body carries a range that name is wrong: the range must be reflected
(`negateNumericType()`), as it is for the body written in full. `Add` and
`Multiply` already give the range of the body (`b + 1` is
`integer<1..256>`).

Fix: when the operand's type is a transparent alias, reflect its unfolded
type, and keep the name only when the reflected type equals the unfolded
one (an alias of `real`, of `integer`, of a symmetric range).
