Above machine precision, a number times a list keeps only about 16 digits of each element of the list.

## Witness

At precision 30:

```
2\cdot\lbrack 0.123456789012345678901234567, 1.5\rbrack
evaluate → [0.24691357802469136, 3.0]
```

The same product on the scalar, `2\cdot 0.123456789012345678901234567`, is
`0.246913578024691357802469134`. `N()` gives the same 17 digits. A sum
keeps the digits, and so does the product when a symbol holds the list.

## Cause and options

`scaleTensor()` (`boxed-expression/arithmetic-mul-div.ts`) packs the vector
into a tensor (`packTensor()`), whose cells are doubles, and multiplies the
scalar by each double. A big-number element loses the digits that a double
does not hold. Options: (a) when the vector holds a big-number float that a
double does not hold (`array` is `undefined`), multiply the boxed elements and
not the packed cells; (b) make the packed tensor keep big decimals. Option (a)
is the smaller change. The matrix route of the same function packs the same
way and needs the same check.

## Decision

User decision 2026-11-07: (a)
