With `evaluateAsync()`, a host function that has only asynchronous evaluation code runs twice when its call is an entry of a nested list, and the list holds the result of the second run.

## Witness

On main `f97a24ed495f48874b58ecc8a4f46acbe242c269`:

```ts
let n = 0;
ce.declare('g', { signature: '() -> integer', pure: false, evaluateAsync: async () => ce.number(++n) } as any);
(await ce.box(['List', ['List', ['g'], 2], ['List', 3, 4]]).evaluateAsync()).toString();
// "[[2,2],[3,4]]", n is 2  (right: "[[1,2],[3,4]]", n is 1)
```

A flat list (`['List', ['g'], 2]`) gives `[1,2]` with one call.

## Cause and options

Two stacks reach the handler: `awaitAsyncOnlyInEach()` (`boxed-expression/async-only-descendants.ts`) awaits the asynchronous-only entry, and the evaluation of the inner list (`listed-element.ts`, `evaluated`) evaluates the original entry again. Fix: the inner list uses the awaited operands, or the walk does not descend into a nested list that evaluates its own entries.
