On the interval target, a loop that must stop early when its index passes an input never stops, and gives a wrong value.

## Witness

```
Block(n ≔ 0; Loop(Block(n ≔ i; If(i > x, Break)), i ∈ 1..5); n + 1)    at x = 2
Block(s ≔ 0; Loop(Block(If(k > Pi, Break()), s ≔ s + k), k ∈ 1..5); s)
```

The first gives the point interval 6 on `interval-js` (interpreter and Python:
4). The second gives 15 (interpreter: 6); `ExponentialE` fails the same way.

## Cause and options

The statement `If` of the `Break` is emitted as
`if (_.x !== undefined && (_.x < i)) { break }`. On `interval-js`, `_.x` and a
hoisted constant are interval objects, so the JavaScript comparison is always
false. Fix: the condition of a statement `If` goes through the interval
comparison, and the compiler declines the loop when the comparison is not
certain over the whole input interval, because a loop cannot take both
branches.
