The free names of a `Block` with a declaration include the type of the declaration: `unknowns` and `symbols` list `real` for `Declare(t, real, 1)`.

## Witness

At `154153fe307c9084587b86fb0f9dc364c040cc8c`, on a fresh engine:

```ts
const ce = new ComputeEngine();
const b = ce.box(['Block', ['Declare', 't', 'real', 1], ['Add', 't', 1]]);
b.unknowns;   // ["real"]        (expected [])
b.symbols;    // ["real", "t"]   (expected ["t"]: `real` is a type, not a symbol of the program)
b.N().toString();   // 2
ce.box(['Block', ['Declare', 't', 'integer', 1], 't']).unknowns;   // ["integer"]
```

## Impact

A host that reads `unknowns` to list the inputs of a program asks for an input
named `real`, and a test for a closed expression (`unknowns.length === 0`)
says that the block above is not closed: the IR slice evaluates closed
sub-expressions with the interpreter and so does not fold this block. No value
is wrong. Workaround: drop the type names from the list.

## Notes

The same class as CE-1027 (the unknowns of a set-builder include `Integers`):
a name in a position that is not a value (here the type operand of `Declare`)
is listed as a free name.
