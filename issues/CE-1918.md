An animation that draws a circle, a segment or any other figure in each frame runs interpreted, because the code that makes a figure starts with an empty list.

## Witness

On CE 0.204.2, compiled JavaScript declines an empty list literal `[]`:

| Shape | 0.204.2 |
| --- | --- |
| `(t: real) => T("c", [t], ["x"])`, `type T = tuple<kind: string, geom: list, bad: list<string>>` (control) | compiles; `{"kind":"c","geom":[2],"bad":["x"]}` |
| `(t: real) => T("c", [t], [])` | declines: `List(): an empty list` |
| `(t: real) => do { let b = []; t }` | declines: `List(): an empty list` |
| `(t: real) => t + length([])` | compiles; `2` |

The interpreter gives each value. Tycho's drawing prelude makes every figure
with `figureOf(kind, geom)`, which sets the field `badOptions: list<string>`
of the named tuple `Figure` to `[]`. Since CE-1911 removed the decline of the
parameter `opts: dictionary = {->}`, this is the first decline of every
figure constructor: `(t: real) => circle((cos(t), sin(t)), 0.2)` with the
prelude loaded declines with `List(): an empty list` (instrument, last line;
also `scripts/repros/2026-11-20-ce-compile-figures.mts`, `figure` and
`moved`). A notebook timer callback that draws figures therefore runs
interpreted.

## Cause and options

The compiler has no element type for `[]` where it is a value. Where the
empty list is the argument of a typed field or a typed local
(`bad: list<string>`, `let b: list<string> = []`), the declared type gives
the element type; elsewhere `list<never>` (or `list<any>`) compiles to a
JavaScript `[]` with no element reads.

Workaround: none in Tycho's hands that keeps the field. With CE-1918 fixed,
the next decline of the prelude is CE-1919.

Tycho half on adoption: rerun the instrument; then rerun
`scripts/repros/2026-11-20-ce-compile-figures.mts` to see the next decline of
a prelude figure, if any.

## CE answer

CE (2026-11-27): P4 proposed, pool. The decline reproduces on CE source. A
workaround exists, so the impact is `minor`: declare the empty list once at
the top level of the prelude and use the name in `figureOf`:

```epsil
let noBadOptions: list<string> = []
```

then `badOptions` is `noBadOptions`, not `[]`. A captured empty list of a
stated element type compiles (CE-1906). Measured on CE source:
`(t: real) => T("c", [t], noBad)` with `let noBad: list<string> = []`
compiles to `{"kind":"c","geom":[2],"bad":[]}`, and the interpreter gives
the same value. If the workaround does not hold inside the prelude, say so
here and the issue goes back to `major`, P3. With it, a figure constructor
meets CE-1919, then CE-1920 (`keys(opts)` in `figureStyled`).

## Tycho reading of the workaround on CE 0.204.2 (2026-11-27)

The workaround holds inside the prelude. With `let noBadOptions: list<string>
= []` before `figureOf`, and `noBadOptions` in place of `[]`,
`(t: real) => figureOf("circle", [t, 0, 1])` compiles and gives
`badOptions: []`. `circle((cos(t), sin(t)), 0.2)` then declines at CE-1919
(`a local of type Figure`). P4 stands. Tycho applies the workaround in the
prelude when CE-1919 and CE-1920 are fixed, because no figure constructor
compiles before that.
