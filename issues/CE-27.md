The first element of an empty list of unknown elements is typed as unknown, so a static check cannot see that the value can be absent.

## Witness

`First(W)` with `W: list<any> := []` is typed `unknown`, and evaluates to
`Missing`.

## Cause and options

An access over `any` or `unknown` elements has no `missing` member in its
type. Making `withMarker` (`library/collections.ts`) answer `any` for `any` and
`missing | unknown` for `unknown` broke 44 tests in 14 suites (measured
2026-10-19). Two assert `unknown` directly (`types.test.ts`,
`At(anIndexed, 1)`; `missing-value.test.ts`, `At(Missing, 1)`). The `missing`
member then flows into use-driven inference, and Epsil reports `sol[1][1]` as a
static error (`programs.test.ts`).

User decision 2026-10-20: a design item, not a small fix. The design question:
how does a `missing` member of an access result flow through inference?
