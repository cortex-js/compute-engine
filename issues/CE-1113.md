A product or a join that holds a call of a user function named `Multiply` or `Join` computes the wrong value, because the call is read as the built-in operation.

## Witness

At commit `5408577629d05c0bd64ad5caf56aafeb47b7d322`, and also with the
uncommitted CE-1109.3 change:

```ts
ce.pushScope();
ce.declare('Multiply', 'function');
ce.assign('Multiply', ce.box(['Function', ['Add', 'a', 'b'], 'a', 'b']));
const u = ce.box(['Multiply', 2, 3]);        // user call, value 5
ce.popScope();
ce.function('Multiply', [u, 4]).evaluate()   // today 24; must be 20

ce.pushScope();
ce.declare('Join', 'function');
ce.assign('Join', ce.box(['Function', 'a', 'a', 'b']));
const j = ce.box(['Join', ['List', 1], ['List', 2]]);  // user call, value [1]
ce.popScope();
ce.function('Join', [j, ['List', 3]]).evaluate()       // today [1, 2, 3]; must be [1, 3]
```

`crafted`: the program shadows a library name and passes the user call into
a library call made in another scope. Once CE-1109.5 lets `std::multiply`
build a library call in a scope that shadows `Multiply`, the same case is a
one-line Epsil program (`std::multiply(Multiply(2, 3), 4)`), and the witness
becomes `plausible`.

## Cause and options

The canonical handlers splice an operand into the call by its name:
`unnegateInto` in `canonicalMultiply()` (`arithmetic-mul-div.ts`, the test
`isFunction(o, 'Multiply')`) and `canonicalJoin()` (`collections.ts`, the test
`isFunction(op, head)`, which also serves `ListJoin`). Test the operand with
`isLibraryOperator(op, name)` (`library-shadowing.ts`, CE-1109.1), as
CE-1109.3 did for `flatten()`. A one-line change of the `Multiply` test gave
20 in a probe. Size S.
