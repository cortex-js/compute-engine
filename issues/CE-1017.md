The list of unknowns of a block leaves out a variable declared outside the block when the block reads it and then assigns it.

## Witness

```
ce.declare('a', 'real')
Block(Assign(a, a + 1), a).unknowns                       ->  []   expected ['a']
Block(Assign(Tuple(a, b), Tuple(a + 1, 2)), a).unknowns   ->  []   expected ['a']
```

The block writes the outer `a` and its value depends on it. A host that reads
`unknowns` to find the inputs of a compiled block does not give `a`.

## Cause and options

`collectReferences()` (`abstract-boxed-expression.ts`) counts every statement
target of a `Block` as a local. `canonicalBlock()` makes no local for a name
that an enclosing scope declares. The rule "a local only when the block scope
binds it" is not correct: a name that the engine saw before is then free in
`Block(Assign(y, 5), x + y)`. A correct rule uses the order of the
statements: such a target is free when a statement reads it before the first
write.
