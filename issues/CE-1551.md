A function that indexes a list with a sum is reported as returning one number when it is called with a string, although the call gives a list of errors.

## Witness

Main after the CE-1452 fix, `new ComputeEngine()`:

```ts
ce.declare('j', { type: 'list<integer>', value: ce.box(['List', 3, 1, 4, 1, 5]) });
ce.assign('f', ce.box(['Function', ['At', 'a', ['Add', 'b', ['Range', 1, 3]]], 'a', 'b']));
ce.box(['f', 'j', { str: 's' }]).type.toString();   // "integer"
ce.box(['f', 'j', { str: 's' }]).evaluate();
// At([3,1,4,1,5], [Error(incompatible-type, number, string), …]), typed unknown
```

The type `integer` does not hold the value. It is the same walk as CE-1452
(`literalBodyResultType()`, `call-result-type.ts`) with a string argument
in place of a function: the walk types `"s" + [1, 2, 3]` as a number. The
data-argument rule (`dataArgumentCallType()`) runs only when the walk gives
no type.

## Cause and options

Type the call `error` or `unknown` when the walk reads a string argument in
an arithmetic operand, as the CE-1452 fix does for a function argument.
