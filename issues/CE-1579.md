A backslash at the end of an unclosed string marks a range past the end of the code, or takes in the next line.

## Witness

`parseEpsil('let s = "C:\\')` (a Windows path, 12 characters) gives the
diagnostics `invalid-escape-sequence` and
`string-literal-closing-delimiter-expected` with the range `[8, 13]`, one past
the end of the source. `parseEpsil('let s = "C:\\\nx')` gives the escape
`"\\\n"`: the string token takes in the line break and the next line `x`.

## Cause and options

`scanEscapeSequence` in `src/epsil/lexer.ts` sets `this.pos = bs + 2` for an
unrecognized escape, also when the backslash is the last character or comes
before a line break. Advance by one character in these two cases, so that the
string ends at the end of its line. The fixit of CE-1520
(`closingStringDelimiterFixit` in `src/epsil/parser.ts`) clamps the token end
to the source length; remove the clamp with the fix. Size S.
