An Epsil program that defines a function and then calls it is no longer compiled by `epsil --compile`; it runs in the interpreter instead.

## Witness

`epsil --compile` of

```
f(x) = x^2 + 1
f(3)
```

gave the compiled value 10 in 0.193.0 (the existing compiler). With the
compiler of 0.194.0 (the pipeline `compilation/ir/`), the program declines:
`DefineFunction` is not an operator the pipeline lowers. With `fallback`
the value is the interpreter's (10); `--compile` runs with `fallback: false`
and reports the decline. `let x = 3; x^2 + 1` compiles.

## Cause and options

The pipeline compiles a function defined in the engine (`f(t) := t^2 + 1`
declared before the compilation) and calls of it, but not a `DefineFunction`
statement inside the compiled program. Options: (a) lower a top-level
`DefineFunction` of a program as a user function of the program (the
binding the pipeline already makes for an engine definition), when its body
lowers; (b) leave the decline (a decline is acceptable) and have the CLI's
`--compile` say that a program with a function definition runs in the
interpreter. (a) restores the 0.193.0 behaviour for the plausible case.
