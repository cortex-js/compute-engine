A color written as an `oklch(…)` string loses its chroma and hue: `color("oklch(50% 0.3 240)")` gives chroma 0.131 and hue 246.

## Witness

Epsil CLI, main 3400041f5: `color("oklch(50% 0.3 240)")` gives
`Oklch(0.508…, 0.1307…, 246.01…)`; `oklch(0.5, 0.3, 240)` gives
`Oklch(0.5, 0.3, 240)`. The string must give the same color as the head.

## Cause and options

The string seems to be parsed to an 8-bit sRGB value (`parseColor`), clipped to
the sRGB gamut, and converted back to OKLCH. Fix: parse an `oklch(…)` or
`oklab(…)` string straight to its channels; gamut mapping, if any, belongs to
the output, not the parse.
