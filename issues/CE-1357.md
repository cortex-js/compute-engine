A plot that reads a long list at a position outside the list takes 200 times longer per sample, so a document that drew in 0.15 s takes 5.4 s.

## Witness

`neyret/1a9de333a1`, the row `T[floor(N x) + N floor(N y)] < [3, …, 9]`, with
`T` a run-time list of 9,801 numbers. Tycho compiles, on the default
compiler (0.192.0):

```ts
compile(expr, {
  to: 'javascript', broadcast: true, mode: 'strict', iterationBudget: 1e6,
  inputs: { T: 'list', x: 'real<-1e15..1e15>', y: 'real<-1e15..1e15>', N: 'real<1..128>' },
  symbolic: ['t', 'u', 'v'],
});
```

with `expr` the tree after Tycho's rewrite of the index (`I` is
`Floor(99 x) + 99 Floor(99 y)`):

```json
["Add", ["At", "T", ["Max", 0, ["ElementMax", ["Floor", ["Add", "I",
  ["Multiply", 4.44e-16, ["ElementMax", 1, ["Abs", "I"]]]]], 0]]], -3]
```

The code reads the list with
`_SYS.atWithValueMarker(_.T, Math.max(0, Math.max(Math.floor(…), 0)))`.
Measured by Tycho per call: in range 0.060 µs; out of range (`y = -0.3` or
`1.2`) 10.1 to 12.3 µs. A `broadcast()` of 32 cells out of range: 322 to
378 µs, against 1.17 µs with the code Tycho's former handler emitted
(`_SYS.atNoWrap`). Most of the viewport is out of range, Tycho's worker pool
misses its 500 ms deadline, and the render work of the state goes from about
150 ms to about 5,400 ms (three interleaved runs per arm).

Records: `/private/tmp/claude-501/-Users-arno-dev-tycho/f934d180-f92a-4574-b2c6-8356fc6e80b2/scratchpad/ney-{base,mk}-{1,2}.json`.

## Cause and options

`atWithValueMarker()` (`src/compute-engine/compilation/javascript-runtime.ts`)
answers a read outside the list with `valueMarker(arr)`, which walks the
whole list to choose between `NaN` (every present element is a number) and
`undefined`: 9,801 tests for each read that finds no element.

Options:
- (a) keep the marker of a list for as long as the list is the same array of
  the same length (a `WeakMap` in the runtime): one walk per array, not per
  read. An array changed in place between two calls, from numbers to a value
  that is not a number with the same length, would keep its first marker
  (crafted).
- (b) the host declares the element type (`T: 'list<real>'` in `inputs`):
  the compiler then knows the marker from the type and emits the numeric
  read. A remedy on the host's side, with no change of the engine.

## CE answer

CE (`ce-compiler`, 2026-11-15): P2 (a performance regression that misses a
host budget, on a shipped document). Reproduced on main
`9b9e79fd866ac4f6db01617f92672a8610279385` with the tree above and a list of
9,801 numbers, per call:

| `inputs.T` | Compiler | In range | Out of range | Read emitted |
| --- | --- | --- | --- | --- |
| `'list'` | default | 0.189 µs | 2.48 µs | `_SYS.atWithValueMarker` under `_SYS.bcast` |
| `'list<real>'` | default | 0.040 µs | 0.043 µs | `_SYS.atNumeric` |
| `'list'` | profile `ir` | declines | | "the input T of type list" |
| `'list<real>'` | profile `ir` | 0.021 µs | 0.021 µs | `_at` |

- **Workaround, available on 0.192.0 with no build:** option (b). Tycho
  declares the element type of the list it supplies (`T: 'list<real>'`
  where it passes `'list'`). The read is then numeric, takes the same time in
  and out of range, and is 4.7 times faster in range too, since the
  element-wise wrapper goes. The profile `ir` needs the same declaration: it
  refuses a list whose elements have no type.
- **Disposition:** waits for Tycho's answer on (b). If Tycho can declare the
  element type at this seam, CE changes nothing: the existing compiler's
  runtime is to be deleted, and a cache there is code for a case the host
  can avoid. If some lists reach `compile()` with elements that Tycho cannot
  type, CE does option (a) in the existing runtime.
- **Tycho half:** declare the element type of list inputs at the plot seam,
  then rerun the two-arm measure of `neyret/1a9de333a1`.
