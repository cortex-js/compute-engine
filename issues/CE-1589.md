In Tycho's Epsil code editor, a right-click on a name cannot show what the name is or jump to where it is defined.

## Request

Export two functions from `@cortex-js/compute-engine/epsil`, with the
options of `epsilCompletions()` (`typeNames`, `protocolNames`,
`sumVariants`):

```ts
epsilHover(ce, source, offset, options?): {
  range: [start: number, end: number]; // the name under the offset
  name: string;                        // as written
  kind: 'library-function' | 'library-constant' | 'function' | 'variable'
      | 'type' | 'keyword';
  detail?: string;          // signature or type, as in a completion item
  description?: string[];   // library paragraphs, or the doc comment
  reference?: string;       // `DocEntry.reference`, for a library name
} | null;

epsilDefinition(ce, source, offset, options?): {
  name: [start: number, end: number];   // DefinitionSite.name
  header: [start: number, end: number]; // DefinitionSite.header
} | null;
```

- `epsilHover` gives, for a library name, the entry of `describeName()`; for
  a name of the source, its declaration (the `detail` of its completion item)
  and the doc comment of `DefinitionSite.description`. `null` on no name, in
  a string or in a comment.
- `epsilDefinition` resolves the name under the offset in its scope, with
  shadowing (`definitionSitesByOffset()`), and gives the site of the
  declaration that the occurrence reads. `null` for a library name, a
  keyword, an undeclared name, or no name.

Both are static: no evaluation of the source, like `epsilCompletions()`.

## Witness

On 0.194.3 the instrument prints `epsilHover exported: false` and
`epsilDefinition exported: false`. `describeName()`
(`src/epsil/describe-name.ts`) and `definitionSites()`
(`src/epsil/definition-sites.ts`) have the data, but the `epsil` entry does
not export them, and `definitionSites()` takes the raw AST, which Tycho does
not build. Tycho could approximate the hover with the `description` of a
completion item at the end of the word, but that misses the names of the
source and their doc comments, and gives no definition.

## Cause and options

(a) The two functions above, recommended: Tycho calls them from the same
places as `epsilCompletions()` (the notebook page and the prelude check
worker). Size S, as both reuse `wordAt()`, the scope walk of completion, and
the two existing modules.

(b) Export `describeName()` and `definitionSitesByOffset()` with a parse
that keeps offsets. Tycho then repeats the scope resolution, which can drift
from the engine's.

Tycho half on adoption: the "Show Info" and "Go to Definition" items of the
editor's context menu, and F12 (`docs/COMPUTE_ENGINE_CHECKLIST.md`, the
follow-up line for CE-1589).
