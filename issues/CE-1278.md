A test of a collection view fails with a timeout when the whole suite runs on a loaded machine, and passes alone.

## Witness

`test/compute-engine/flatmap-unknown-finiteness-all-consumers.test.ts`, "a
consumer of a FlatMap of unknown finiteness › ArgMax: the value over the
listed elements", failed once, in the full run of the release 0.188.1 at
`4251e2473`:

```
CancellationError: Timeout exceeded (0ms)
    at run (src/common/interruptible.ts:503:15)
```

The file took 48 s in that run. The 5-minute load average was 17.9 on 18
cores when the run ended. At the same commit the file alone passes in about
1 s (`npx jest -w 2 -- <file>`, 90 tests, three runs), and the next full run
at that commit passed. The release was stopped by this failure.

## Cause and options

Not found. The message says that the time limit left for the evaluation was
0 ms when a step started: an enclosing time limit of the engine had run out.
The test evaluates each case three ways (`evaluate()`, a limited
evaluation, `evaluateAsync()`); which one timed out is not in the log. Two
things to find: which time limit applies in the test (the default of the
engine, or the limit of `evaluateLimited()` in the test file), and whether a
test that checks a value should run with no time limit of the engine, so
that only the limit of the test runner applies.

Since the release after 0.188.1, the publish check runs a test file that
failed in the full run again, alone, and continues when it passes
(`scripts/prepublish-check.sh`, `second_look`), so this failure no longer
stops a release.
