In an imported Desmos document, curves defined piecewise over a list of values no longer draw.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
compile(ce.box(['At', ['If', ['LessEqual', 0, 'x', 6],
  ['Add', 'x', ['List', 0, 4, 2]]], 1]),
  { to: 'javascript', mode: 'strict', inputs: { x: 'real' } });
```

0.195.1 (and 0.194.3): declines on `javascript` and on `interval-js`
(`{to: 'interval-js', symbolic: ['x']}`), "If(LessEqual(0, x, 6), Add(x,
List(0, 4, 2))): an If with no else of a list arm whose value an operator
reads". 0.192.0: compiles on both targets; javascript gives 1.5 at x = 1.5 and
NaN at x = 7. `Max(At(If(…), 1), At(If(…), 2))` behaves the same (0.192.0: 5.5
at x = 1.5). Control: the same `If` with an explicit else
`List(NaN, NaN, NaN)` compiles on 0.195.1 on both targets and gives the same
values. The `If` alone, with no operator reading it, compiles on 0.195.1.

This is not the CE-1564 form. CE-1564 (fixed in 0.195.0) is an `If` whose
condition is a list; here the condition is a scalar and the arm is a list
that `At` reads.

Document form: `s ≔ w ↦ If(0 ≤ w ≤ 1, 3w² − 2w³)`, and the line readers
compile `Max(At(C, 1), At(C, 2), At(C, 3))` with `C = If(0 ≤ x ≤ 6,
s(ElementMin(1, ElementMax(0, |Mod(x + [0, 4, 2], 6) − 3| − 1))))`, options
`{to: 'javascript', mode: 'strict', iterationBudget: 1000000, inputs: {x:
'real'}, symbolic: ['y', 't', 'u', 'v']}` and `{to: 'interval-js',
iterationBudget: 1000000, symbolic: ['x', 'y', 't', 'u', 'v']}`. 0.192.0
compiles both (javascript 1 at x = 1.5); 0.195.1 declines both with the message
above. Captures: Tycho `.cache/mg-evidence/codegen-full.json` (0.192.0,
compiled), `.cache/macro-carriers-phase-a-ce1943/codegen-full.json` (0.194.3)
and `tycho-wt-mgc/.cache/ce1602-host-review/codegen-ctrl.json` (0.195.1,
declined).

Tycho impact: `neyret/ni3ih739at` loses the compiled code of four line readers
(M, m, V = M and S = (M − m)/V; eight javascript and interval-js targets).
Two dotted horizontal lines with their points are missing from the render
(Tycho `roadmap/MACRO_CARRIERS_PHASE_A.md`, pixel comparison). Tycho has no
workaround: the `If` with no else is the imported Desmos piecewise.

## Cause and options

The decline comes from the rule that refuses an `If` with no else and a list
arm when an operator reads its value: the missing else has no list shape to
give the reader. 0.192.0 gave the no-else branch NaN in every element of the
arm's shape (the result of the control). Option (a, recommended): when the
arm's shape is known (here a list of fixed length 3), compile the missing else
as a list of NaN of that shape, as 0.192.0 did. Option (b): keep the decline
only when the arm's length is not known at compile time.

## Decision

The user approved on 2026-11-20 a narrower form of option (a). The list of
NaN replaces the missing else only for the operators that cannot tell an
absent value from a present one. Keep the decline at `lower.ts` (the
`!results.has(node)` test) when a discharge (`IsMissing`, `Coalesce`,
`AssertPresent`), `Length` or `Rest` reads the value of the `If`, because the
interpreter gives `Missing` and the list of NaN would give a wrong finite value
(`Length` 3). Compile it when `At`, `First`, `Last`, arithmetic or an
aggregate such as `Max` reads it: `At` of an absent value is NaN in compiled
code, and other operators on an absent value are unspecified (AGENTS.md). The
decline for a length made in the arm stays. Tests: the witness and the
document form on `javascript` and `interval-js`, and a `Length` reader and an
`IsMissing` reader that still decline.
