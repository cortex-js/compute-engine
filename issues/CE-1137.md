In Epsil, an error in the body of a function that a list element calls can underline another element of the list.

## Witness

```
function g(x) { Ln(x) + 1 }
let y = 5
let v = [y + 1, g("a")]
frames     ->  Ln argument 1, Add argument 1
underline  ->  y          expected: g("a") or the statement
```

## Cause and options

The breadcrumb has no frame for the call of `g`, and a list records no frame
for its element. All the frames come from the body of `g`, and
`locateError()` (`src/epsil/error-location.ts`) matches the frame
`Add argument 1` by name to the `y + 1` of the statement. The fix of CE-1070
rejects a frame of the body only when an outer frame of the statement
selects an argument that does not hold its call; here no frame of the
statement exists. A list of statement calls that record a frame
(`Max(y + 1, g("a"))`, a user function `h(y + 1, g("a"))`) already
underlines `g("a")`.

Options: (a) the call of a user function adds a frame (or a marker) to the
breadcrumb of an error that its body returns, and the locator drops the
frames before it. This changes the `ErrorTrace` of every such error, which a
host can read, and the text `in … argument …` of the message. (b) `List`
records a frame for the element whose value is an error, as `Max` does.
This fixes lists only; a `Tuple` or a record would need the same.
