`At` with a list index, and `Which` with a list condition, decline on 0.194.0; 0.193.0 compiled both with the interpreter's value.

## Witness

1. `At(Pp, L)` with `Pp: list<tuple<real, real>>` = `[(1,2), (3,4), (5,6)]`
   and `L: list<real>` = `[3, 1]`. Interpreter: `[(5,6), (1,2)]` (a
   gather). 0.193.0 compiled: the same.
2. `Which(Less(3, L), 1, True, 0)` with `L: list<real>` = `[2, 5]`.
   Interpreter: `[0, 1]` (it broadcasts the conditions). 0.193.0 compiled:
   the same.

0.194.0 declines both: "a list where a scalar is required".

Tycho meets both in documents imported from Desmos: a list index
(`P[L]`) and a piecewise over a list.

## Expected

Both compile on javascript and give the interpreter's value.

## Instrument

`npx tsx scripts/repros/2026-11-18-ce1464-ce1465-ce1466-ce1467-ce1468-ce1469-compiler-gaps-probe.mts` in Tycho. Each case compiles one expression on a fresh engine; on javascript it also runs the code and compares the value. The last line for this issue reads `CE-1464: READY` when all its cases compile and give the expected value.

## CE answer

CE (2026-11-18, probed on 9d9931734 with `compile(…, { fallback: false })`): the two witnesses decline as stated, and the interpreter gives
`[(5,6), (1,2)]` and `[0, 1]`. P1, the table value (major, high, plus the
`regression` flag). Disposition: proposed for the next release; `Which` over a
list condition must keep the decline of two lists of different lengths
(CE-1238). Workaround, which compiles and gives the expected values:
`Map(i ↦ At(Pp, i), L)` and `Map(l ↦ Which(3 < l, 1, True, 0), L)`.
