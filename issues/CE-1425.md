A selection that reads two lists by position at each element takes four times longer each time the lists double, where the same selection written with `If` takes twice as long.

## Witness

Main tree at `84e511b4cbeb4ae576fa5f1fc5bff532709f4b5a`. `CS` and `VS` are
symbols that hold the two lists (the form of CE-1358's second witness, with
the lists bound once):

```ts
const ce = new ComputeEngine();
ce.assign('A', ce.box(['Join', ['Range', 1, n], ['List', 1]]).evaluate());
ce.assign('CS', ce.box(['Less', 2, ['At', 'A', 'A']]).evaluate()); // a lazy Map
ce.assign('VS', ce.box(['At', 'A', 'A']).evaluate());              // a List
const body = ['Which', ['At', 'CS', 'j'], ['At', 'VS', 'j'], 'True', 'NaN'];
ce.box(['ListFrom', ['Map', ['Function', body, 'j'], ['Range', 1, n]]]).evaluate();
```

| Body, ms | `n` = 400 | 800 | 1,600 |
| --- | --- | --- | --- |
| `Which(At(CS, j), At(VS, j), True, NaN)` | 75 | 178 | 446 |
| `Which(At(CS, j), 1, True, NaN)` | 12 | 16 | 27 |
| `If(At(CS, j), At(VS, j), NaN)` | 14 | 21 | 34 |

The values are the same. Times vary by up to 40% between runs on the shared
machine; the growth is the signal.

## Cause and options

Not read. Only the form with `Which` and a value clause that reads `VS` grows
with the square of `n`; `If` with the same reads does not. A guess to check
first: `Which` reads the type of its value clauses at each call, the type of
`At(VS, j)` reads the element types of `VS`, and the type cache misses because
each call of the callback writes `j` and so advances the engine generation.

Workaround: write the selection with `If`, or over the lists
(`Which(CS, VS, True, NaN)`).
