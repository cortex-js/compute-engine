An animated notebook drawing runs slowly or stops at the time limit when its timer draws the picture in the same step that computes it.

## Witness

On CE 0.204.0, a compiled callback declines a call of a host function whose
argument is a list literal with an element that is a variable holding a list.
The host function is declared as Tycho declares `figureDraw`:
`ce.declare("show", { signature: "(any) -> nothing", pure: false, evaluate })`.
Run the program with `executeEpsil`, then compile the value of `frame` to
JavaScript.

```epsil
let v = [1, 2]
let frame = (t: real) => do { show([v]); 0 }
```

Declines: `show(List(v)): a call of the function show of the host, with an
argument that holds a list or a tuple that the interpreter can hold as a lazy
collection (Range, Reverse, Linspace) or that the code does not know as a List
or a Tuple literal`. The interpreter calls `show` once with
`["List", ["List", 1, 2]]` and gives no diagnostic.

Controls, which compile and call the host from the compiled code:

- `show(v)`, the list variable alone;
- `show([[1, 2]])`, the same value as a nested literal.

Tycho's notebook prelude defines `draw` as
`function draw(...args) -> nothing { figureDraw(listFrom(args)) }`
(`src/graph-paper/notebook/drawing/prelude.ts`). `draw(v)` with `v = [1, 2]`
declines with the same reason, on `show(ListFrom("args"))`. With `v = 5` it
compiles. A list of records (`[Fig([1]), Fig([2])]`) also declines, with a
reason about the record type of the argument.

In Relay Vault, the timer callback paints a 320 × 200 raster in a loop and
then calls `draw(stage)`. When the paint loop and the `draw` are in one `if`
block, the block runs interpreted and the tick ends with `timeout` at the
2000 ms limit, with no note. In the shipped notebook, the paint and the draw
are in separate blocks (a `rendered` flag), and the tick is `ok` in about
110 ms with the 256,000-byte frame. The instrument prints both ticks.

## Cause and options

`hostCall()` in `src/compute-engine/compilation/ir/lower.ts` requires a list
argument to be fully listed (`fullyListed(listedOf(cx, v))`) or listed by the
host (`listedByHost`). Not verified: a list literal whose element is a list
variable seems to fail both tests, although the control `show(v)` shows that
the code passes that variable whole. One option: treat a `List` literal as
listed when each of its elements is listed, as for a nested literal. `ListFrom`
of a rest parameter needs the same rule, because the rest parameter holds the
list of the arguments at the call site.

Tycho half on adoption: rerun the instrument. When it reads READY, combine
the render and draw statements in the timer callback of Relay Vault, remove
the rendered flag, and run the Relay Vault browser instrument of
2026-11-26 (relay-vault-raster). The marker is a comment in the notebook,
which the Tycho lint of markers does not scan.

## Fix

`captured()` in `src/compute-engine/compilation/ir/lower.ts` marks the `List`
and `Tuple` nodes of the literal value of a free name (a list of numbers) as
literals that the interpreter holds as written (`capturedLiterals`,
`heldLiteral()`), so `literalListed()` lists them as it lists a literal of
the program. `[v]` and the rest-parameter record of `draw(v)` are then
fully listed, and `hostCall()` accepts them. A name that holds a `Range`
is not a literal and still declines. The instrument reads READY; tests:
`test/compute-engine/host-call-captured-list-ce1906.test.ts`.

The instrument reads BLOCKED on the npm package 0.204.1, twice, at load 4:
`show(v)`, `show([[1, 2]])`, `show([v])` and `draw(v)` with Tycho's `draw`

the interpreter can hold as a lazy collection (Range, Reverse, Linspace) or
that the code does not know as a List or a Tuple literal`. The rest-parameter
`ListFrom("args")` inside Tycho's `draw` still declines on the real notebook
path. Tycho keeps the split render and draw statements of Relay Vault. The
file stays open.

## Fix of the 0.204.1 reading

Relay Vault's `stage` is a `Figure`, whose field `badOptions: list<string>`
is `[]`. Two declines followed from that field; `captured()` covered neither:

- `lower.ts`, case `List`: the empty list of a captured value
  (`emptyLanes`, `emptyList()`) was not marked listed, so the enclosing
  literal was not listed and `hostCall()` declined. It now goes through
  `literalListed()`.
- `stringListRefusal()` of `compilation/ir/index.ts` refused a list of
  strings as a field of a record other than a result, and as an argument of
  a host call, which `unboxable()` accepts. Both now hold it as it is.

Minimal witness: the program
`type Fig = tuple<kind: string, geom: list, bad: list<string>, handlers: string | nothing>`,
`let s = Fig("c", [1], [], nothing)`, `let frame = (t: real) => do { show(s); 0 }`.
On CE source with Tycho's evaluator, the combined Relay Vault tick is `ok`,
256000 bytes, 92 ms (split: 72 ms). The instrument has the case
"draw(s), s a figure with an empty list of strings in a field" and reads
READY; tests: `test/compute-engine/host-call-captured-list-ce1906.test.ts`.
`let v = []; show([v])` and `draw(v)` with `v = []` still decline
(crafted; no witness).
