After a dot, the completion menu lists every name of the program and of the
library, and none of the fields or protocol functions of the value before the
dot.

## Witness

```
protocol Shape {
  function area(self: Self) -> number
  function scale(self: Self, k: number) -> Self
}
type Circle = tuple<r: number> is Shape {
  function area(self: Circle) -> number { Pi * self.r^2 }
  function scale(self: Circle, k: number) -> Circle { Circle(self.r * k) }
}
const c: Circle = Circle(1)
const p: record{x: real, y: real, tag: string} = {x -> 1, y -> 2, tag -> "a"}
```

On main (0.197.1), `epsilCompletions` at the end of `c.` gives 598 items
(`Circle`, `Shape`, `c`, `p`, then the library) and not `area`, `r`, `scale`;
at `p.` the same 598 items and not `tag`, `x`, `y`; at `p.t`, `table`,
`tabulate`, `tail`, `take`, … and not `tag`. Every library name offered there
is an error once accepted (`dot-call-not-a-protocol-function`, or no such
field). The instrument prints READY when each case lists exactly its members
(exit 0); today it prints NOT READY (exit 1).

Probability high: typing a dot after a record, a tuple with named elements, or
a value of an `object` type is the basic use of those types, and the menu
opens at each dot.

## Cause and options

`src/epsil/completion.ts`: the slot after `.` (`{ kind: 'member' }`, line 901)
only removes the keywords (line 452); sections 1 to 3 still add every name of
the source and of the library. Nothing reads the type of the receiver.

Fix: at a member slot, find the static type of the expression before the dot
and list only its members:

- the fields of a record or of an `object` type, and the named elements of a
  tuple, with their types as detail;
- the `readonly` and `readwrite` properties of the protocols the type
  conforms to;
- the `function` members of those protocols, inserted as a call (`area()`),
  with the receiver's parameter left out of the detail.

No other name. When the receiver's type is not known (an undeclared `let`
whose initializer the completion cannot type), list nothing rather than every
name. The receiver's type needs the same work as part 2 of CE-1661 (the type
of a name of the source with no annotation); a declared receiver works
without it.

A member inside an argument (`sqrt(c.`) should then be ranked against the
argument's expected type as CE-1661 decides; today `expectedType` is not set
there.
