In a function whose parameter has the name of a global variable, a pipe over the parameter is checked with the type of the global, so a correct program can get an error report.

## Witness

```
xs: list<string>            (global)
(xs) ↦ (xs |> Filter(p))    the pipe is typed from the global xs
(Sqrt) ↦ 16 |> Sqrt         typed as the library Sqrt
```

## Cause and options

An operator that holds its operands (`lazy`) receives them unbound.
`heldOperandType` (`library/held-operand-type.ts`) looks a held symbol up by
name, as do `pipeImplicitTopicCallType` and `pipeShorthandApplicationType`.
`pipeNamedStageType` resolves only library names (`resolvesToSystemBinding()`,
`operand-descriptor.ts`), which a parameter with a library name defeats. Fix:
when the lazy operator is canonicalized, record which held names a local scope
binds. `TrigExpand`, `TrigToExp` and `TrigReduce` bind their operand at
canonicalization instead. This file holds the former sub-item CE-40.2, the
only one left.
