Adding two matrices, or scaling a matrix by a number, runs in the slower interpreter when the size of the matrix is known only when the program runs.

## Witness

Checked at `0c5858f1ae20f8abbd9de27ffc2795ada8370a7f`, on JavaScript, with
`A`, `B` declared `matrix<real>` and `x` declared `real`:

```
A + B, A - B, 2·A, x·A, A + 1, Sin(A), Transpose(A) + B
  declines: A of type matrix<real> other than in an element read A[i][j]
            or as an argument of a parameter of that type
G + G with G: list<list<real>>   declines the same way
```

The interpreter gives the element-wise value (`A + B` at
`A = [[1, 2], [3, 4]]`, `B = [[0, 1], [1, 0]]` is `[[1, 3], [4, 4]]`).
Controls that compile: `C + D` and `2·C` with `C`, `D` declared
`matrix<real^2x2>`, and `Map(r ↦ 2r, A)`, `MatrixMultiply(A, B)`,
`Transpose(A)`, `Determinant(A)` with `A: matrix<real>`. The CHANGELOG entry
"Compiled JavaScript reads an input of a matrix type of run-time size" lists
the cases that still decline and does not name element-wise arithmetic.

Workaround: map over the rows, `Map(r ↦ r + 1, A)`, or declare the size
(`matrix<real^2x2>`).

## Cause and options

A matrix input of run-time size is read only by `A[i][j]`, by the matrix
operators of `lower-matrices.ts`, and by `Map` over its rows; an
element-wise operation of the lowering (`add`, `mul` threaded over a list)
takes a flat list or a list of stated row length. Option: lower an
element-wise operation on a list of rows of run-time row length as a build
of rows (the lowering of `Map(r ↦ f(r), A)`, which compiles), with the
check of equal shapes that `MatrixMultiply` makes for its inner lengths.
