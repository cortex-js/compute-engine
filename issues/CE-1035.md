In an Epsil function body, a second definition of a local function with the same parameters is ignored with no message, while at the top level the same two lines are the error `function-redefinition`.

## Witness

```epsil
function g() {
  f(y) := 1
  f(x) := 3
  f(0)
}
g()
// ➔ 1, no diagnostic (HEAD 766420eef822a8a315f7aa375802b0fe51f91ac2)
```

At the top level the same lines give `1` and the error
`function-redefinition`. The value is the documented one (the second
definition is refused), but in a body nothing tells the author. Workaround:
another name for the second function.

## Cause and options

Not traced; the top-level report comes from `executeEpsil()`.

- (a) Report `function-redefinition` in a block too.
- (b) Nothing: document that the check is for the top level only.
