In the Tycho code editor, the summary of `findRoot`, `limit`, `map`, `solve` and ten other library functions stops in the middle of a sentence, because each line of their description is a separate paragraph.

## Witness

On CE 0.201.5, 14 of the 616 library names that `epsilCompletions` gives
have a `description` whose paragraphs are the lines of a hard-wrapped
source paragraph, and a `documentation` that is the first of these lines:

```
library names: 616
wrapped: 14: arbitraryConstant arbitraryInteger findRoot jacobianMatrix limit map nLimit nSolve nd replaceAll simplify solve table withRandomSeed
findRoot documentation: "FindRoot(equations, params): numerically find parameter values that"
findRoot description: [
 "FindRoot(equations, params): numerically find parameter values that",
 "zero the residuals. `equations` is an equation (`lhs == rhs`), a bare",
 "residual expression (read as `= 0`), or a list of either. `params` is",
 …
```

The other 602 names have one paragraph per element (`join`: four
sentences, four elements). `epsilHover` gives the same arrays.

## Cause and options

The `description` of these definitions is probably written as an array of
source lines, not of paragraphs. Options: join the lines of each paragraph
in the definitions, or have the loader join consecutive lines that do not
end a sentence. Tycho shows the first element as the summary of a name and
the others after "More", and reads a single line break inside an element as
a space, so either fix is enough for Tycho.
