A list comprehension whose condition reads a variable of an inner block evaluates to an empty list.

## Witness

At `d221dfaf6e34746686e2a82d32b1d055991ca73d`:

```ts
const fn = ce.box(['Function',
  ['Block', ['Block',
    ['Assign', 't', 1],
    ['Comprehension', 'j', ['Element', 'j', ['Range', 1, 3], ['Less', 0, 't']]]]],
  ['Typed', 'a', { str: 'real' }]]);
[...ce.box(['Apply', fn.json, 3]).evaluate().each()]; // []
```

The value must be `[1, 2, 3]`. With the local declared in the outer block
(`Block(Declare(t, 'real', 1), Comprehension(…))`) the interpreter gives
`1, 2, 3`. Both compilers give `[1, 2, 3]` for both forms.

## Cause and options

The comprehension is a lazy view: its elements are computed when the list is
read, after the inner block has ended, and the condition then reads `t` with
no value. Option: a lazy view that leaves the block of a local it reads
captures the value of that local, or is made an eager list at the end of the
block.
