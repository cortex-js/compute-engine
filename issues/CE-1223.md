`N()` of a call that passes a definite integral to a function with a `real` local gives an `incompatible-type` error.

## Witness

At `f56cd5f2908d403d9990aeb1171eee2a726b37b5`:

```ts
const I = ['Integrate', ['Exp', ['Power', 't', 4]], ['Limits', 't', 0.5, 1]];
ce.assign('ft', ce.box(['Function', ['Block',
  ['Declare', 'u', "'real'", 'v'],
  ['If', ['Less', 'v', 1], ['Assign', 'u', ['Multiply', 'u', 0.1]]],
  ['Multiply', 'u', ['Divide', 3, 'v']]], 'v']));
ce.box(['ft', I]).N();        // Error(ErrorCode("incompatible-type", "real", "measurement"), "u")
ce.box(['ft', 0.8]).N();      // 0.3
ce.box(['ft', I]).evaluate(); // 3
```

`N()` of the integral alone is the measurement `0.76492701406530972 ±
0.00000000000000068`, less than 1, so the value is 0.3; compiled code
(the `numeric-kernel` profile) gives 0.3. `evaluate()` gives 3: the
integral stays exact (the exactness contract), `v < 1` is undecided, and
the `If` statement is skipped, which may be the documented behavior of an
undecided condition.

## Cause and options

A `measurement` value is not admitted by a local declared `real`. Option:
admit a real measurement where `real` is declared (read its value), or
give the measurement's value to the call.
