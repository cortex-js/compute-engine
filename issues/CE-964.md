Under `.N()`, a user function whose `Filter`, `Map` or comprehension callback reads the parameter uses the rounded argument and gives a wrong list.

## Witness

```
h := x ↦ Filter([1], k ↦ x < 25k);  h((25! − 1)/24!).N()   gives [], should be [1]
```

`Map` and `Comprehension` read 25 for 24 in the same way.

## Cause and options

The collection handlers compute the elements and receive no evaluation
options, and a lazy `Map` view is computed after the function call has ended,
so the recorded exact argument is gone. The design: how a collection view
keeps the numeric request. The one existing case is
`lazyMapNumericApproximation`; `Reduce` has its own rule
(`withExactFoldFallback`). Same family as CE-179.
