The maximum of a list that is built with an asynchronous function stays unevaluated under asynchronous evaluation.

## Witness

```
slowF: an operator with only an evaluateAsync handler
await Max(FlatMap([1, 2], x ↦ [x, slowF(x)])).evaluateAsync()
  ->  Max(2, slowF(1), slowF(2))      expected 20
```

`Min` and `Sum` do the same.

## Cause and options

Not investigated. The likely cause is the one of CE-111.4 in `ROADMAP.md`: the
elements of a lazy collection are computed synchronously when they are read,
also under `evaluateAsync()`, so an operator that has only an asynchronous
handler stays unevaluated in each element. The asynchronous iterator that
CE-111.4 specifies would fix it.
