A type that declares a method with an optional options dictionary loses all the methods of its protocol, so every method call on its values fails.

## Witness

On CE 0.204.3, a protocol member `function f(self: Self, a: any, opts: dictionary = {}) -> integer`
and the implementation `function f(self: Q, a: any, opts: dictionary = {}) -> integer { 0 }`
do not match. `Q(1).g()`, a call of another member of the same protocol,
fails:

```
protocol signature mismatch: the signature of `f` does not match `P.f` at `Self = Q` — expected `(self: Q, a: any, opts: dictionary = {}) -> integer` (argument 3 declares a default value; the requirement declares {})
```

The control, the same protocol with `b: string = "none"` on both sides,
gives 7. In the protocol, `{->}` is refused ("The only dictionary default
value is the empty dictionary `{}`"), so `{}` is the only spelling.

Two effects:

1. The two defaults are the same, and the comparison says they differ. It
   looks like a comparison of the default expressions by identity, not by
   structure.
2. One mismatched member makes the type implement none of the members:
   `g`, which matches, is also missing. A diagnostic at the declaration
   would show the cause; today it shows only at the first call.

## Cause and options

Not investigated. Tycho's workaround: the default is the string sentinel
`"default"` (`opts: any = figureDefault`), and the method body replaces it
with `{->}`.

## Fix

Cause: the conformance check reads the defaults of the implementation from
its literal, which is not canonical. There, `{}` is a raw `["Dictionary"]`,
which is the empty dictionary only once canonical, so the default was read as
"not a value" and the member did not match. The check now reads the default
as the declaration of a function literal does (`uncanonicalParameterDefault()`
in `parameter-defaults.ts`). Tycho can drop the `"default"` sentinel and
write `opts: dictionary = {}` on both sides.

Effect 2 is not changed: a conformance with one mismatched member is still
refused as a whole. `executeEpsil` already reports the mismatch as a
diagnostic when it runs the `type Q is P` statement, before the first call.
