An integral whose integrand gives one value per element of a list does not compile when the list's length is known only when the program runs.

## Witness

Tycho's codegen audit of CE 0.204.1: 8 records of `neyret/2agcgxq87y`
(#3531 to #3534, #3536 and their members), nested integrals over
`ElementMax(E, …)` with `E` a document list. Repro:
`~/dev/tycho/_TASK/desmos/desmos-corpus/codegen-audit/repros-0.204.1/3531-2agcgxq87y.mts`.
A program of CE alone:

```js
ce.declare('E', 'list<real>');
compile(ce.parse('\\int_0^1 \\frac{x}{\\mathrm{ElementMax}(E, x)}\\,dx'), { to: 'javascript' });
// declines: "Block(Divide(x, ElementMax(E, x))): a list where a scalar is required"
// The interpreter, with E = [0.5, 2]: [0.75, 0.25]
```

## Cause and options

Since `cc6575f0a` the JavaScript target integrates a literal list or a call
mapped over a short list of a stated length, one integral per element
(`docs/COMPILATION-MODEL.md`, the quadrature paragraph). An integrand that is
a list of a run-time length declines. Option: on JavaScript, a loop over the
elements that runs the quadrature once per element, with the list element
bound in the integrand, and the bounds read once. The Monte-Carlo fallback and
the iteration budget apply per element. The nested case of the witness then
needs an outer integral of a list, which the same rule covers.
