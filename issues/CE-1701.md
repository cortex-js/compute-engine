A function that uses its argument both whole and element by element, through another function, reports a number as its result but returns a list.

## Witness

At `93e6d685a76ca5df50e9778186c09a44a1c51dd9`:

```js
ce.assign('S', ['Function', ['Mean', 'x'], 'x']);
ce.assign('T', ['Function', ['Add', ['S', 'x'], 'x'], 'x']);
ce.box('T').type.toString();                    // (x: collection<number> | value) -> number
ce.box(['T', ['List', 1, 2, 6]]).type.toString(); // number
ce.box(['T', ['List', 1, 2, 6]]).evaluate().json; // ["List", 4, 5, 9]
```

With `Mean(x) + x` written directly in `T`'s body, the call is typed
`list<…>`. The fix of CE-1696 extends the same case to a callee declared
`function` before it is assigned, and to Document function rows.

## Cause and options

Not investigated. The result type of `T` is derived from the body with `x`
at its scalar arm, so `S(x) + x` is `number`. But a list argument is bound
whole (the slot has a collection arm), and `Add(number, list)` is a list.
Option: derive the result type from the collection arm too, joining it with
the scalar one, as the direct body `Mean(x) + x` does.
