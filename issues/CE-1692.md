A recursive function that reads a point gets an error and draws nothing, though each call has a value.

## Witness

CE 0.198.0, Document API, no stated types (no `formalTypes`, no
`resultType`). The instrument prepares two documents:

- Mutual recursion: `a(p)=b(p)`, `b(q)=a(q)+q.x` (`q.x` is `PointX(q)`).
  Row error of `b`: `b: (q: collection<any> | tuple) any -> list<list<any> |
  number | tuple> | number | tuple does not match (unknown) any -> unknown`;
  `a` gets `invalid-document-dependency`.
- Self recursion with a base clause, in the merged form Tycho hands over:
  `f(P,n) = Which(n = 0, (0,0), True, g(P) + f(P, n-1))` with
  `g(P) = P.x (1,0)`. Row error of `f`: `f: (P: collection<any> | tuple,
  n: unknown) any -> list<list<any> | tuple<number, number>> |
  tuple<number, number> does not match (unknown, unknown) any -> unknown`.
  Every row that calls `f` gets `invalid-document-dependency`.

- A base clause that consumes a list: `K(0,x)=mean(x)`, `K(n,x)=K(n-1,x)`.
  Row error of `K`: `K: (n: unknown, x: collection<number> | value) any ->
  broadcastable<unknown> does not match (unknown, unknown) any -> unknown`
  (Tycho's `document-ce-manager-recursive-clauses.test.ts`, "a CONSUMING
  base-case clause").

Control: `g` alone prepares with no row error.

Expected: both functions bind, as before the port: `f((1,2),2) = (2,0)`.
In Tycho, stock (the host-side registration before the port) bound both and
evaluated `f((1,2),2)` to `(2,0)`.

## Cause and options

Not investigated. The message reads as a check of the inferred signature of
a recursive function against its provisional declaration `(unknown…) ->
unknown`, which a parameter inferred `collection<any> | tuple` (from
`PointX`) does not match. A recursive function whose parameters stay
`unknown` (a scalar recursion) does not get the error.

Tycho cannot state a type for these rows: under the port ruling, the types
of function rows come from CE (the Desmos point rule types a parameter read
only through `.x`/`.y`/`.z`, and `P` in `f` is also passed on whole).
