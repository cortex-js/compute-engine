A call that names its arguments is an error when the user's function has the name of a library operator, such as `Max`, `Divide` or `Complex`.

## Witness

In Epsil, at 964dca5588dbf96c2cc7046186dc5e9a23903fdb:

```
function Max(a: number, b: number) { a - b }
Max(b: 1, a: 5)
```

gives `argument-names-unavailable` ("the declared type of this variable gives
no parameter names"). It must give `4`, as `Max(5, 1)` does, and as the same
program does with a name that is not a library operator (`Foo`, or the
lower-case `max` and `gcd`). `Divide` and `Complex` give the same error.

The witness is `crafted`: an Epsil program writes its functions in lower
case, and the lower-case names are not affected.

Workaround: pass the arguments by position, or give the function another
name.

## Cause and options

Probable cause, not confirmed: the text of the error is the one of a callee
that is a variable whose declared type has no parameter names
(`valueCalleeSignature()` gives `null`, then `declaredNamesUnavailable()`, in
`makeCanonicalFunctionCore()` of
`src/compute-engine/boxed-expression/box.ts`). The definition that the lookup
finds for a function that shadows a library operator is then a value
definition without the signature of the function literal, where the
definition of `Foo` is an operator definition with its parameter names.

Option: find why the declaration of a function with a library name gives a
definition without parameter names, and give it the definition that `Foo`
gets.
