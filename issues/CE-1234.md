A numeric integral whose integrand calls a function and also passes it as a callback gives NaN when the integral was boxed before the function was defined.

## Witness

```js
const I = ce.box(['Integrate',
  ['Add', ['g', 'x'], ['At', ['Map', 'g', ['List', 'x']], 1]],
  ['Limits', 'x', 0, 1]]);
ce.parse('g(t) \\coloneq t').evaluate();
I.N().re;   // NaN; expected 1
```

At `5eb1778b5d1643108ec473a2eb040bcbfe3fd063`, at the top level. The same
expression boxed after `g` is defined gives 1, and each summand alone gives
0.5 in both orders.

`ce-626-integrand-forward-call.test.ts`, "a compiled integrand that calls g
and passes g as a callback", passed before the bound-once rule only because
it evaluated the integral inside a pushed scope, where the names were read
again. With the rule the integral reads its own scope and the test shows the
defect.

## Cause and options

Not investigated. The integral is boxed while `g` has no definition, so the
call `g(x)` and the callback `g` of `Map` are boxed as readings of an
undefined name; the two readings are not both repaired when `g` is defined.
Stored bodies and held expressions bound again when a name gets a
definition (model slice 2) is the planned mechanism for this class.
