A `Break()` or `Continue()` outside a loop silently stops the rest of an Epsil program.

## Witness

Epsil CLI, main 0417d3034: `let s = 0; do { Break() }; s = 5; s` prints
`Break()`, and the last two statements do not run; `if true { Continue() }`
in the same place prints `Continue()`. `fixedPoint(x => if x > 10 { Break(x) }
else { x + 1 }, 0)` stays unevaluated, and with a maximum of 100 it is the
error "expected `number`, got `nothing` at `Break(11)`". `FixedPoint` does not
document `Break`.

## Cause and options

A `Break` or `Continue` with no enclosing loop goes up to the program, which
stops there. Fix: the static check reports a `Break` or `Continue` that is not
inside a loop as an error (Epsil can see this from the text), and the
interpreter answers an error for one that reaches the program or a callback.
