A held argument of a hold function that names a variable of the caller reads a local of the function body when both have the same name.

## Witness

```
hold f(body, bind i, n) = do { let t = 100; Sum(body + t, (i, 1, n)) }
let t = 1
f(t*k, k, 2)
```

Gives 500; the `t` of the argument `t*k` is the caller's (1), so the value
is (1·1 + 100) + (1·2 + 100) = 203. The same call inside a caller block
`do { let t = 1; … }` gives `3t + 200`. Measured at worktree commit
`a3c0ddc6b` (the bound-once work on main's `dc51affd4`), with and without
the substitution of the held argument that the probe tried; not measured on
main.

## Cause and options

Not investigated. The held argument is read by name inside the body, so a
local of the body with the same name captures it. With the bound-once rule
the argument's names are bound in the scope of the call; the fix is
expected to come with the static read of a local (the design note above),
and this file is the test of it.

## CE answer

CE (2026-11-12): with bound-once step 1 the call inside a caller block
(`do { let t = 1; f(t*k, k, 2) }`) gives 203. The program as written above
(a top-level `let t = 1`) still gives 500. The rest is ROADMAP CE-1258.
