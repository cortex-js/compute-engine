A list built from the calls of a recursive function no longer compiles, although the function has no side effect.

## Witness

`s: real`; `r` declared `(real) -> real`,
`r := Function(Which(k <= 0, 0, True, s + r(k - 1)), k)`;
`compile(Comprehension(r(i), Element(i, Range(0, 5))), { to: 'javascript', inputs: { s: 'real' } })`.

0.193.0: compiles; at s = 2 it gives `[0, 2, 4, 6, 8, 10]`, the
interpreter's value. 0.194.0: declines, "a Comprehension with an effect (the
interpreter evaluates its elements lazily)".

It compiles when `r` is not recursive, and when `r(3)` is called once in
the expression before the `Comprehension`.

## Cause (Tycho's reading)

The IR README ("Effects") makes a recursive function `may-fail`, not
`effectful`. The pending self-call of the body lowered inside the
`Comprehension` is counted `effectful` (`lower-functions.ts` about line
937, counted in `ir.ts` about line 494), and the check of
`comprehension` in `lower-lists.ts` declines on it.

## Expected

Compiles on javascript and gives the interpreter's value.
