A curve that adds up weighted points (a spline) is computed point by point instead of by compiled code, so it draws slower.

## Witness

`P: list<tuple<real, real>>`. Compile to javascript:
`Sum(Multiply(At(P, Add(Mod(Add(k, Range(0, 1)), 2), 1)), k), Limits(k, 1, 4))`.

0.194.3: declines, "a term that is not a number". The interpreter gives
`[(18, 28), (22, 32)]` for `P = [(1, 2), (3, 4)]`, and 0.186.0 compiled the same
value. Control: `Sum(Multiply(k, L), Limits(k, 1, 4))` with `L: list<real>`
(flat list terms, the CE-1470 fix) compiles.

Found by the Tycho codegen audit of 2026-11-19: the same MathJSON, with the same options, compiled to JavaScript on CE 0.186.0 and declines on 0.194.3 and on the CE main build of 2026-11-19 16:57, in the document context and on a bare engine. Tycho's instrument `scripts/repros/2026-11-19-ce1560-js-decline-regressions.mts` prints one READY / NOT READY line per issue (READY on 0.186.0, NOT READY on 0.194.3).

## Cause and options

The CE-1470 fix compiles a `Sum` of flat list terms only. Option: accept terms
that are lists of tuples of a fixed arity, added element by element.
