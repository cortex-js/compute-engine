In Epsil, the message of an error inside a square root that is divided names a multiplication that the program does not contain.

## Witness

```
let w: any = "s"
let v = sqrt(w)/2 + 1   ->  "in Sqrt argument 1, in Multiply argument 2, in Add argument 1"
let v = ln(w)/2 + 1     ->  "in Ln argument 1, in Divide argument 1, in Add argument 1"
expected                ->  "in Sqrt argument 1, in Divide argument 1, ..."
```

The underline is `w` in both programs.

## Cause and options

The canonical form of `sqrt(w)/2` is `Multiply(1/2, Sqrt(w))`. Since CE-1139,
`renamedCallFrame()` (`src/epsil/error-location.ts`) changes the frame
`Multiply argument 2` into `Divide argument 1` through the source range of
the canonical operand, and `errorFrameChain()` prints the changed frame. The
canonical `Sqrt(w)` has no source range (the canonical `Ln(w)` keeps
`[start, end]` of the written `ln(w)`), so the frame stays as recorded.
Option: let the canonicalization of `Sqrt` keep the source range of the
written call, as `Ln` does. Check the other operators whose canonical form is
made anew (`Root`, `Abs`, ...) with the same probe.
