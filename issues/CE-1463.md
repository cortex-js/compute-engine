After an edit is rejected, a function that previously returned 6 starts returning random values between 3 and 4.

## Witness

Run with the released npm package `@cortex-js/compute-engine@0.194.0`.

```js
import { ComputeEngine } from '@cortex-js/compute-engine';

const ce = new ComputeEngine();
const setH = body => ce.box(['Assign', 'h', ['Function', body, 'x']]).evaluate();
setH(['Multiply', 2, 'x']);
ce.declare('g', {
  signature: '(number) pure -> number',
  evaluate: ce.box(['Function', ['h', 'x'], 'x']),
});
const read = () => ce.box(['g', 3]).evaluate().toString();
console.log(read());                                      // 6
console.log(setH(['Add', 'x', ['Random']]).operator);    // Error
console.log(read(), ce.lookupDefinition('g').operator.pure);
```

The last read gave 3.2629911913633407 and the purity flag was true. The new call itself reports no error. After the rejected edit it should still give 6. A host editing a helper called by a pure formula can encounter this on its next evaluation. The released version reports the effects violation when assigning the helper. The rejected experimental deletion instead reported a successful assignment.

## Cause and options

The replacement of h becomes visible before rebuilding its dependent g detects the effects violation. Validate the affected contracts before publishing the replacement, or restore the affected definitions when validation fails. A regression check should assert the rejection and then call the previously installed formula.
