A list built from a filter that keeps nothing calls the filter function twice for each element.

## Witness

```
npx tsx src/cli/epsil.ts --eval 'do { let calls = 0; function keep(j) scope { calls = calls + 1; j > 5 }; let v = [i for i in filter(1..3, keep)]; (sum(v), calls) }'
```

gives `(0, 6)`: one walk of the three elements calls `keep` 6 times. With
`j > 0` in place of `j > 5` (the filter keeps every element) the result is
`(6, 3)`. Measured 2026-11-07 on HEAD
`155d0add73c8b15874aaa93b6e46a26cafd2fa99`. A stack trace taken during
such a walk shows the `count` handler of `Filter` (`library/collections.ts`)
walking the filter before the comprehension walks it.

## Cause and options

Not traced to the end. The walk of the comprehension (`runNested()` in
`library/control-structures.ts`) evaluates the domain and walks it with
`each()`; a read of the count or the emptiness of the `Filter` on the way
walks it a first time, and the memo of the `Filter` does not keep that walk
when the predicate writes a variable. Option: find the read and make it
use the walk that follows, or skip it when the walk follows anyway.
