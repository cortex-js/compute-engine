A search in a list by a condition that reads a slider does not compile when the host passes the slider by name.

## Witness

```js
ce.declare('L', 'list<real>');
ce.declare('T', 'real');
ce.assign('T', 2);
compile(ce.box(['CountIf', 'L', ['Function', ['Greater', 't', 'T'], 't']]), {
  vars: { T: 'T' },
  hideValues: ['T'],
  fallback: false,
});
// throws: CountIf with an effect (the interpreter stops at the first element
// that decides)
```

The same program with no `vars` option compiles. With `vars`, on a0c8e81a6
plus the CE-1610 change (2026-11-20, `javascript`):

| Declines | Compiles |
| --- | --- |
| `Find`, `IndexWhere`, `CountIf`, `Position`, `Any`, `TakeWhile` with the predicate `t ↦ t > T` | `Map(t ↦ \|t − T\|, L)`, `Sort(L, t ↦ \|t − T\|)`, `ArgMin(L, t ↦ \|t − T\|)` |
| `ArgMin(Map(t ↦ \|t − T\|, L))` ("ArgMin of a list with an effect") | |

The review of CE-1610 reports the same decline for `Comprehension` with a
condition; this was not run again here.

## Cause and options

A read of a name of `vars` is the host's text, read at each use, and its
instruction is counted as an effect. The list operators of
`compilation/ir/lower-lists.ts` decline a predicate, or a list operand, whose
lowering adds an effect (`where()`, `quantifier()`, `search()`, the check
after `source()` in `more()`), because the interpreter stops at the first
element that decides and reads a lazy list only where it needs it. That
reason holds for a draw or a write. It does not hold for a read of a host
name that no instruction of the program writes.

Options:

- (a) Do not count a read of a `vars` name as an effect in these checks: count
  the effects of the predicate with the reads left out. Size S. Recommended.
- (b) Keep the decline. The workaround is to pass the name as an input of
  `run()` in place of `vars`.
