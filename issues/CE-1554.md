A drawing method cannot have an argument that the caller may leave out, so Tycho's drawing API spells `.rotate(a, about)` as `.rotateAbout(a, about)` and `.stroke(c, w)` as `.stroke(c).strokeWidth(w)`.

## Request

Allow a default value on a parameter of a protocol requirement:

```epsil
protocol Figure {
  function rotate(self: Self, angle: real, about: point = Origin) -> Self
  function stroke(self: Self, color: string, width: real = 1) -> Self
}
```

`r.rotate(a)` is then `r.rotate(a, Origin)`, and `r.stroke("red")` is
`r.stroke("red", 1)`. A tuple cannot be a default (R3 of
`docs/plans/2026-10-31-parameter-default-values.md`), so `about` names a
declared constant.

Not part of this request: `.scale(k)` / `.scale(kx, ky)`. It needs
`ky = kx`, a default that names another parameter, which R1 of the same plan
refuses. Tycho keeps `.scale(k)` / `.scale((kx, ky))`. Arity overloads of a
member are a separate feature, to be asked for when a second case needs them.

## Witness

Today the declaration is refused:

```
The signature of `Scalable.scale` declares an optional argument; a protocol member may not be optional, variadic or generic
```

(`invalid-protocol-declaration`, from `assertV1MemberShape` in
`src/compute-engine/engine-protocols.ts`; test
`test/epsil/parameter-default-values.test.ts`). Probability `medium`: the
drawing prelude is phase 1 and is not yet loaded by any shipped cell.

## Cause and options

Every consumer of a requirement reads only `signature.args` and checks one
exact arity, so the declaration refuses `optArgs`, `variadicArg` and
`typeParams` (v1 restrictions, `docs/TYPE_SYSTEM_ROADMAP.md`, "Signature
matching (ruling)"). Tycho half on adoption: add `.rotate(a, about)` and
`.stroke(c, w)` to the drawing prelude, with a constant default for `about`
that the prelude reads as the figure's center; keep `.rotateAbout` and
`.strokeWidth` as aliases.

Proposed design (agreed with the user 2026-11-19): the REQUIREMENT owns the
default, the dispatcher fills it, and every implementation receives the full
argument list. The alternative, a default owned by each implementation, was
rejected: the static arity check of the dispatcher would no longer hold, and
two conformers could give one call two meanings.

Work, all in `engine-protocols.ts` unless named:

1. `assertV1MemberShape`: accept a parameter with a default; keep refusing
   variadic, generic and default-less optional parameters. Refuse a default
   on a parameter whose type mentions `Self` (no check of the default before
   `Self` is bound, as R1 refuses one on a generic parameter).
2. `dispatcherDefinition`: carry a slot's default in the synthesized
   signature when every protocol that declares the member agrees on it, so
   the canonical fill of R5 applies. When they disagree, fill at evaluation
   after selection (the v2 rule of R9).
3. `checkMemberArguments` and `dispatchMember`: check an arity range (the
   required count to the full count) instead of one count; `dispatchMember`
   fills what the canonical fill did not, including a supplied absent value
   (R5 amendment of 2026-11-01).
4. `signatureMismatch`: keep the exact-arity comparison over the full
   parameter list; refuse an implementation that leaves out the defaulted
   parameter, and one that declares a different default.
5. `protocolMemberSignature` (the qualified form `P.m`): the defaulted
   parameters become `Optional` parameters of the wrapper literal.
6. Epsil: the parser and `src/epsil/check-epsil.ts` accept `= value` in a
   requirement, and method-call arity checks use the range.
7. Tests replace the refusal test; update the v1 lines of
   `docs/TYPE_SYSTEM_ROADMAP.md` and `docs/EPSIL-LANGUAGE-MODEL.md`, and the
   protocol page on cortexjs.io.
