A program run under a debugger cannot keep a time limit: the time spent paused counts, so the run times out at the first long pause.

## Witness

`executeEpsilAsync` with debug hooks, inside a 300 ms `withTimeLimit` span:
a hook that pauses 600 ms ends the run with `Error("Timeout exceeded (0ms)",
"timeout")` (measured 2026-11-19, ce-debugger). The contract says so
(`EpsilDebugHooks`, `src/compute-engine/types-debug.ts`). So:

- Tycho runs a debug run with no time limit (its `docs/COMPUTE_ENGINE.md`,
  step 2): an endless loop in a debug run runs until the user presses Stop.
- Tycho offers no debugger on its in-process route (B7b), where the 2 s limit
  is the only protection of the page.

Workaround: no time limit, and Stop (the `signal`, or ending the worker).

## Cause and options

User decision 2026-11-19: in a debug run, a time limit measures running time
only; the time a hook's promise is pending does not count. This changes the
documented contract.

Design: each engine keeps the total paused time; it grows while a debug
hook's promise is pending. A `DeadlineFrame` carries a reference to that
total, and every deadline test compares `Date.now() - paused` with `at`:
`src/compute-engine/index.ts` (`timeRemaining`, `_withBudget`),
`engine-runtime-state.ts` (`_timeRemaining`), `src/common/interruptible.ts`
(`frameExpired`, the deadline check, `runAsync`'s own start time and the
`run` driver). The total is per engine, so a pause does not extend the
limits of another engine. Covers `withTimeLimit`, `statementTimeLimitMs` and
the engine's time limit. Tests: one per kind of limit, a pause in a nested
span, and a second engine running during the pause. Update the contract in
`types-debug.ts`, the "Debugging" section of `src/epsil/docs/implementation.md`,
and step 2 of Tycho's `docs/COMPUTE_ENGINE.md`. Size M.
