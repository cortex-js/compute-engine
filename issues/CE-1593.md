Solving x² = a for a real x gives ±√a with no condition on a, which is not a real solution when a is negative.

## Witness

On 0.194.3 `Solve(x^2 = a, Element(x, RealNumbers))` and
`Solve(x^2 = a, x, RealNumbers)` both give `[√a, -√a]`. Controls: the same
domain spec gives `[]` for `x^2 = -1` and `[2, -2]` for `x^2 = 4`, so the
domain filter works for numeric roots and is skipped for a root that holds a
free symbol.

## Cause and options

(a) Recommended: when a root's membership in the domain depends on a free
symbol, return it with the condition (`a >= 0`), in the form the engine uses
for conditional values (`isRestriction` in `solve-domain.ts`).

(b) Use the assumptions on `a` when they decide it (`a > 0` keeps both
roots, `a < 0` gives `[]`), and decline (the `Solve` stays inert) otherwise.

Size M for (a), S for (b).

## Fix

Option (a), with (b) through the assumptions. Over the real line,
`Solve(x^2 = a, x ∈ RealNumbers)` is `[If(0 ≤ a, √a), If(0 ≤ a, -√a)]`. The
assumption `a > 0` gives `[√a, -√a]`, and `a < 0` gives `[]`. Over another
domain (`Integers`), for a root that is not `p + q·√r` (`x^4 = a`), or with a
constraint on `x` that is not decided at the root, the `Solve` stays
unevaluated.
