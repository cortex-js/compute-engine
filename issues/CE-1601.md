A notebook code cell that ends with map(u => u + 1, [5, 6]) shows Map(u ↦ u+1, [5, 6]) instead of [6, 7].

## Witness

On 0.194.3 `executeEpsil(ce, "map(u => u + 1, [5, 6])")` gives a value whose
`toString()` is `[6,7]`, but whose `json` is the `Map` call and whose `latex`
is `\mathrm{Map}(u\mapsto u+1, \bigl\lbrack5, 6\bigr\rbrack)`; `.evaluate()`
returns the same `Map`. `filter([5, 6, 7], u => u > 5)` behaves the same
(`\mathrm{Filter}(…)`). The MCP `evaluate` tool gives `mathjson: [6, 7]` with
the `Map` LaTeX. Controls: `[u + 1 for u in [5, 6]]` gives the list LaTeX,
and `evaluate({ materialization: true })` of the `map` result gives
`["List", 6, 7]`. `Range(1, 4)` serializes as `1..4`, which is readable, so
it is not part of this issue.

## Cause and options

(a) Recommended: `executeEpsil` materializes a finite lazy collection that is
the final value, so `json` and `latex` agree with `toString()`.

(b) The LaTeX serializer of a finite lazy collection writes its elements.

Tycho can also materialize the value itself, but every host would repeat
that. Size S.
