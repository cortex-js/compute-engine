A notebook code cell that ends with map(u => u + 1, [5, 6]) shows Map(u ↦ u+1, [5, 6]) instead of [6, 7].

## Witness

On 0.194.3 `executeEpsil(ce, "map(u => u + 1, [5, 6])")` gives a value whose
`toString()` is `[6,7]`, but whose `json` is the `Map` call and whose `latex`
is `\mathrm{Map}(u\mapsto u+1, \bigl\lbrack5, 6\bigr\rbrack)`; `.evaluate()`
returns the same `Map`. `filter([5, 6, 7], u => u > 5)` behaves the same
(`\mathrm{Filter}(…)`). The MCP `evaluate` tool gives `mathjson: [6, 7]` with
the `Map` LaTeX. Controls: `[u + 1 for u in [5, 6]]` gives the list LaTeX,
and `evaluate({ materialization: true })` of the `map` result gives
`["List", 6, 7]`. `Range(1, 4)` serializes as `1..4`, which is readable, so
it is not part of this issue.

## Cause and options

(a) Recommended: `executeEpsil` materializes a finite lazy collection that is
the final value, so `json` and `latex` agree with `toString()`.

(b) The LaTeX serializer of a finite lazy collection writes its elements.

Tycho can also materialize the value itself, but every host would repeat
that. Size S.

## CE answer

CE (2026-11-20): P2 confirmed. Fixed with option (a), in the commit that
sets `fixed-in` (its parent is the hash in the header). `executeEpsil()` and
`executeEpsilAsync()` list a finite lazy collection that is the value of the
last statement: `map(u => u + 1, [5, 6])` gives `["List", 6, 7]` and the
LaTeX of the list, a `map` of a set gives a `Set`, a `filter` of a
dictionary gives a `Dictionary`. A range stays a range, as the issue says.

What a host must know:

- The callback runs once for each element during the run, inside the time
  limit of the run. When a limit stops it, the value is
  `["Error", message, cause]` with the cause `timeout`, `step-budget` or
  `recursion-depth-exceeded`, which `cortexCancellation` already reads. A
  comprehension as the last statement threw the `CancellationError` to the
  caller before this fix; this is one way a cancellation reached the `catch`
  around `executeCortex`.
- A collection with more than `ce.maxCollectionSize` elements (10,000 by
  default) or with no last element stays lazy, so the read-back can still
  get a `Map` expression for those.
- A list of more than 10 elements has its full text and LaTeX, not the
  preview `[2,4,6,8,10,...,52,54,56,58,60]`.
- An element that is a range stays a range: `map(u => 1..u, [2, 3])` is
  `[1..2, 1..3]` in LaTeX and `[Range(1, 2),Range(1, 3)]` in `toString()`
  (CE-1650 is the issue for that text).

Workaround on 0.194.3 and 0.195.2:
`value.evaluate({ materialization: true })` before the read-back.
