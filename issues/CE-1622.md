The length of a sorted list that a name holds stays unevaluated when one of its elements is a variable, and a second evaluation gives it.

## Witness

```ts
const ce = new ComputeEngine();
ce.declare('x', 'real');
ce.assign('d', ce.expr(['Sort', ['List', 3, 'x', 1]]));
const once = ce.expr(['Length', 'd']).evaluate(); // Length([3, x, 1])
once.evaluate();                                  // 3
```

`IsEmpty(d)` and `Contains(d, 1)` do the same: `IsEmpty([3, x, 1])` then
`False`, `Contains([3, x, 1], 1)` then `True`. Read on 29a48852b, 2026-11-20.

In a branch condition the value is found, because the condition evaluates
the operands of its relation and then the relation over their values:
`If(k = Length(d), 1, 0)` is decided. So the defect shows where `Length(d)`
is read outside a condition.

## Cause and options

Not read. The first evaluation replaces `d` by the value of the `Sort`,
which cannot order a variable and gives the list as written, and does not
apply `Length` to that list. Workaround: evaluate the result again.
