A function that counts with a condition in a `let` line stops with an error, while the same count assigned without `let` works.

## Witness

On CE main 3e6ca4c76 (Epsil):

```
function g(c) { let i = count([2, 3], e => c > 0)
i }
g(4)
// Error("Filter predicate must return "True" or "False".")
```

`i = count(…)` without `let` gives 2; `let` and `const` fail. The same
error comes back with the data of the Apollonian gasket's `generations`
step when its tuple types do not join (for example
`g([(2, 0.5, 0, 1), (3, 0, 0.6, 1), (4, 0, 0, 1)])` with CE-1482's `g`).

## Cause and options

A function literal evaluated in the initializer of a `Declare` gets no
captured function value (`captureAtCreation`), so `Count` applies the bare
literal and its body reads `c` as a free symbol (`Less(0, c)`). CE-1482's
witness passes since 50130e4aa only because its rows share one tuple type,
so the canonical `Filter` rebuilds the predicate with a narrowed parameter.
The fix is in how a literal in a `let` initializer captures the activation
of its scope: the binding workstream's area. Deferred after 0.194.2 with
CE-1482 (user decision 2026-11-19).
