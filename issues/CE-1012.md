A plot row `\sum_{i=1}^{n} i` with a slider `n` at `10^{12}` freezes the page, also in an imported document.

## Witness

With `iterationBudget: 1e6`, `Sum(i, Limits(i, 1, 1e12))` compiled to
`javascript` returns `NaN` at once. Compiled to `interval-js`, the code is the
same with and without the option and does not return in 5 s; `Product` is the
same. `compileToPlotFunction` probes the interval lane of a plot row, so the row `x + \sum_{i=1}^{10^{12}} i` does not return in
25 s. Reading on 0.182.0: `row 509: NOT READY on 0.182.0 (the compiled code did
not stop)`.

Blocker of Tycho ROADMAP row KB. Tycho's hold prevents a second run after the
reload; nothing stops the first.

Requested: on `interval-js`, the option limits `Sum` and `Product` as on
`javascript`; an `entire` interval is enough.

Tycho half on adoption: no code; run the witness of ROADMAP row KB, then close
row KB.

## CE answer

CE (2026-11-06): fixed on CE main (commit `43b6c441b`), in the next release
after 0.182.0. Cause: the `Sum`/`Product` loop of the `interval-js` target
(`compileIntervalSumProduct()` in
`src/compute-engine/compilation/interval-javascript-target.ts`) never read
`iterationBudget`; only the `Loop` counter of that target did. The loop now
starts with `if (!(_upper - lower < budget)) return { kind: 'entire' }`, the
same test as the `javascript` loop's `NaN` exit, so a range of more passes than
the budget gives the `entire` interval before its first pass, for symbolic and
for literal bounds. Without the option the code is unchanged. Checked with the
instrument against the built package of CE main: `row 509: READY (Sum:
RETURNED; Product: RETURNED)`. No Tycho declaration changes the ask.
