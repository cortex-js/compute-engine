Compiling with the experimental `numeric-kernel` profile fails with an internal error for a list of reals that is filled with integers.

## Witness

At `6ac31a524af52fecc8744852886ebaba2fac18c8`:

```ts
const fn = ce.box(['Function',
  ['Block',
    ['Declare', 'B', { str: 'list<real>' },
      ['Comprehension', 'k', ['Element', 'k', ['Range', 1, 3]]]],
    ['At', 'B', 1]],
  'm']);
compile(fn, { profile: 'numeric-kernel', fallback: false });
```

throws a decline with the code `compile-error` and the message "an internal
error in the verification phase: JS structured representation: the operation
at of a list<integer> has a result of the type real, not integer". It must
either compile or decline with `outside-profile`. The existing compiler
compiles the program and gives `1`. With `fallback` on, the host gets the
existing code or the interpreter, so the workaround is the default option.

## Cause and options

The local is declared `list<real>` and its initial value is a comprehension
of integers, which the lowering builds as a `list<integer>`; the read `At`
then has the declared element type. Options: convert the element type of the
list at the declaration (the two have the same representation, a JavaScript
array of numbers), or refuse at admission a list local whose declared element
type differs from the element type of its initial value.
