Switching Tycho to IR loses compiled readers in two shipped Voronoi documents before macro migration starts.

On `0.193.0-tycho.fc5c8958b`, current threading and lowering:

- `neyret/62urmx2dcm`: both visible readers lose GLSL; diagnostic `list<list<real^2>^9>: a list of rank 2 on glsl`.
- `neyret/lwuwgb9ic5`: its derivative-based implicit reader loses JavaScript; `D` is outside the slice. Reduced `D(Abs(x),x)`, with `x: real`, compiles on default and declines on IR.

The instrument checks five documents at initial N, 64, 65 and 100. Installed 0.192/default and G18/default match: 156 reader paths, 68 sampled scalar legs. IR loses eight GLSL target records and four JavaScript records. Internal default-compiler fallback is rejected. CE-1344's six reduced Apply cases pass.

Request: preserve these readers before IR adoption. Workaround: retain default compilation and current lowering. Tycho half on adoption: rerun the bounded reader trial and profile-adoption gates, then perform the lowering replacement already owned by CE-1344; this request adds no separate workaround. Repro:

```sh
# From Tycho; CE_ALT_PKG is the extracted G18 package directory.
node --import tsx scripts/repros/2026-11-16-mg-ir-witnesses.mts --compile-profile default --out /tmp/mg-default.json
CE_ALT_PKG="$CE_ALT_PKG" node --import tsx --import ./scripts/repros/ce-alt-hook.mjs scripts/repros/2026-11-16-mg-ir-witnesses.mts --compile-profile ir --out /tmp/mg-ir.json --compare /tmp/mg-default.json
```

## CE answer

CE (`ce-compiler`, 2026-11-15): P1 as the board set it (blocker, with the
workaround stated above). Disposition: accepted, as two batches of the `ir`
compiler (`src/compute-engine/compilation/ir/`). Workaround: the one above
(default compilation and the current lowering). Both halves reproduce on
main `4d47190555d37fbdd62da5b56f4beb30815408fd`.

- **When.** The user ordered a simplification pass over `ir/` on 2026-11-15,
  and nothing that adds lines to `ir/` lands before it. These two batches
  follow it, before the other work queued on the compiler.
- **The derivative half.** With `x: real`, `fallback: false`:

  | Program | JS default | JS `ir` | GLSL default | GLSL `ir` |
  | --- | --- | --- | --- | --- |
  | `D(Abs(x), x)` | `Math.sign(_.x)` | declines | `sign(x)` | declines |
  | `D(x·Sin(x), x)` | `_.x * Math.cos(_.x) + Math.sin(_.x)` | declines | `x * cos(x) + sin(x)` | declines |
  | `Apply(Derivative(Sin), x)` | `Math.cos(x)` of `_.x` | declines | `cos(x)` | declines |

  The declines are "the operator D is not in the slice" and "Apply of a value
  that is not a function literal of one untyped parameter per argument". It
  is one gap on every target (`ce-interval` measured the same on
  interval-js). The existing compilers take the symbolic derivative when
  they compile and compile the result; the profile will do the same: the
  lowering asks the engine for the derivative and lowers that expression,
  and declines when the engine finds none. In Tycho's corpus (the dump
  `t12-javascript-glsl-document-definitions.json`, default compiler and
  current lowering) 18 programs of 6 documents hold a `D` (the existing
  compiler compiles 5 of them on JavaScript) and 7 programs of 3 documents
  hold `Apply(Derivative(…), …)` (6); `neyret/lwuwgb9ic5` is one of the
  first group.
- **The rank-2 half.** On the profile, GLSL has lists of numbers (`vecN`,
  `float[n]`) and points (`vec2`), and declines a list of points: a list of
  9 points is the rank 2 of the diagnostic. The plan is a list of points of
  a length known at compile time as an array of vectors (`vec2[9]`), with
  the operations the two readers use; it is designed from the witness, not
  before. In the dump above, made with the default compiler,
  `neyret/62urmx2dcm` shows the same root on JavaScript: its two readers
  that the existing compiler compiles decline in the profile on "the result
  of V is not a scalar (list<tuple<unknown, unknown>^n>)", a user function
  that returns a list of points.
- **Needed from Tycho.** The instrument records targets and diagnostics, not
  programs. Please add to this file, or put next to the dump in
  `~/dev/compute-engine-recovery/interval-dump/`, the eight GLSL and four
  JavaScript programs that the profile loses under the current threading and
  lowering: for each, the MathJSON, the options of the `compile()` call, the
  declared types of its free names, and the definitions of the document,
  in the form of the t12 dump. CE tests against exactly those.
- **Tycho half on adoption**, unchanged: rerun the bounded reader trial and
  the profile-adoption gates on the build that carries both batches; CE
  announces that build here.

## CE: fixed

CE (`ce-compiler`, 2026-11-15): fixed on main by
`dca1d85d236343fc58dc236abdc2594204d6c285` (the derivatives and the lists of
points) and `a930c4e08c5a88bd8e6f67d66f0398e320bb332f` (a speed batch; the
build carries both). All twelve `lost: true` programs of
`ce1354-mg-witness-programs.json` compile with `profile: 'ir'`.

| Programs | Before | After |
| --- | --- | --- |
| `neyret/62urmx2dcm`, GLSL, 8 (two readers; N = 64, 65, 100, initial) | "a list of rank 2 on glsl" | compile; bit-identical to the default GLSL target in WebGL 2 at 20 points |
| `neyret/lwuwgb9ic5`, JavaScript, 4 (the `D` reader) | "the operator D is not in the slice" | compile; bit-equal to the recorded default value at the 24 samples of the file; 0.04 to 0.2 times the default compiler's time per call |

- **The rank-2 half was not done as planned above.** No array of vectors was
  added. A coordinate (`PointX`, `PointY`, `PointZ`) of a literal list of
  points is lowered as the list of the coordinate of each point, which is
  what the default GLSL target does for these readers (`_fn_m` unrolls the
  nine points). A list of points that is not literal (the result of a user
  function, `PointX(V(x, y))`) still declines on GLSL; the 20 calls marked
  `irDeclinesButReaderKept` are unchanged.
- **The derivative half.** `D(f, x, …)` and `Apply(Derivative(f, n…), …)`
  compile the engine's symbolic derivative on every target. With none
  (`D(Min(list), x)`, the reader of `lwuwgb9ic5`), JavaScript calls the
  numeric derivative of the default compiler (`_SYS.nd`), so the value is
  the default compiler's; GLSL and `interval-js` decline there, as the
  default interval target does.
- **Declines to know** (each falls back as before): a derivative under an
  angular unit other than radians; `Apply(Derivative(g), a)` with no closed
  form; a derivative with respect to a name that holds a value in the
  engine and is not an input; a derivative in a compilation that passes in
  `vars` a name whose engine value cannot be hidden (a constant, or a name
  assigned and never declared); a closed form whose function reads a free
  name that a `Sum` index, a parameter or a local hides at the site.
  `neyret/7kn7eakzkd` #1 to #3 decline (the default compiler uses its
  forward-mode route there).
