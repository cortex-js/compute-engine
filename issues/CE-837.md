A sum over calls of a point function whose point has a square-root coordinate does not compile, so it runs in the slower interpreter.

## Witness

With `k := i`, `p: (unknown) -> unknown` and `p(P) := P.x + k`,
`\sum_{k=1}^{3} p((x, \sqrt{x-5}))` declines on JavaScript in both `auto` and
`strict` mode. The forms `p((x, 1)) + 1` and `\sum_{k} (k + p((x, 1)))`
compile.

## Cause and options

Not traced. The emitted definition of a user function reads the coordinates of
a point parameter as real numbers, so a point argument with a `{re, im}`
coordinate declines ("argument 1 is a point with a complex-valued coordinate").
The `strict` decline may have a cause other than CE-244, where the complex
kernel comes from `auto` mode. Find the cause, then make the point-specialized
definition accept the complex coordinate, or emit a complex variant of it.
