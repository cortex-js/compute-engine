A derivative of a built-in function, made before the user defines a function with the name of that built-in function, gives the value of the user's function when a value of its variable is put in after that definition.

## Witness

At commit `466093012b526da34be4454c61ad2888b382e1ca`:

```ts
const s = ce.box(['Sin', 'x']);           // the library Sin
ce.pushScope();
ce.declare('Sin', 'function');
ce.assign('Sin', ce.box(['Function', ['Add', 't', 100], 't']));
const d = ce.box(['D', s, 'x']).evaluate();
d.json                 // ["D", ["Apply", ["Module", "Sin"], "x"], "x"]: correct,
                       // the D stays unevaluated and holds the library Sin
const p = d.subs({ x: 1 });
p.json                 // ["EvaluateAt", ["Function", ["Block",
                       //   ["D", ["Sin", "x"], "x"]], "x"], 1]
p.N().re               // 1; must be cos 1 = 0.5403
ce.popScope();
```

The same node with no substitution keeps the library `Sin`
(`d.N()` stays unevaluated), and `s.subs({ x: 1 }).N()` is 0.8415, correct.

`crafted`: the formula is boxed, then a user function with the capitalized
name of a library function is declared in a pushed scope, and the derivative
is evaluated at a point there.

## Cause and options

`BoxedFunction.subs()` (`boxed-function.ts`) replaces the variable of `D`,
`Series` or an indefinite `Integrate` with `EvaluateAt(Function(value, x),
p)`. It makes the node raw (`_subsInParseScope(…, { canonical: false })`)
and canonicalizes it again as the body of the literal, so that the node reads
the parameter of the literal. That raw rebuild reads `Sin` by name in the
current scope, and binds the call to the user function: the library binding
of the call (`isLibraryCall()`, `library-shadowing.ts`) is lost.

Options: (a) in that raw rebuild, keep the binding of each call that is not
bound to the definition its name has in the current scope (as
`withCallableBinding()`, `binders.ts`, does for one call); (b) when the node
holds a call bound to a library definition whose name the current scope
shadows, mark the `EvaluateAt` so that it stays unevaluated under
`evaluate()` and `N()` (a decline). Related: CE-1118 (the evaluation of `Add` and
`Multiply` binds an unchanged operand again by name).
