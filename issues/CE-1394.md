Several special functions stay unevaluated at points where their exact value is a simple number: `besselJ(0, 0)` is 1, `lambertW(e)` is 1, `agm(a, a)` is `a`.

## Witness

Epsil CLI, main 64a46834c; each stays as written with `evaluate`, and `N` gives the
number:

| program | must give |
| --- | --- |
| `besselJ(0, 0)`, `besselI(0, 0)` | 1 |
| `besselJ(1, 0)` (and `besselJ(n, 0)`, `besselI(n, 0)` for an integer `n ≠ 0`) | 0 |
| `lambertW(0)` | 0 |
| `lambertW(e)` | 1 |
| `clausenCl(1, pi/3)` (`−ln(2 sin(π/6))`) | 0 |
| `agm(1, 1)`, `agm(a, a)` | 1, `a` |
| `agm(1, 0)` | 0 |

Some special points do fold today: `besselY(0, 0)` is `-oo`, `lambertW(-1/e)` is
-1 and `clausenCl(2, pi)` is 0. Workaround: `N`.

`N` is no workaround at the zeros of `Cl₁` (θ = π/3 and 5π/3 mod 2π):
`N(clausenCl(1, pi/3))` stays `ClausenCl(1, 1.0471975511965977…)`, and so does
`clausenCl(1, 1.0471975511965976)`, while `clausenCl(1, 1.05)` gives
-0.00242…. The numeric branch (`special-functions.ts` around line 1134) gives a
value only with `ce.precision` correct digits, which a value at a zero does not
have. The exact entries above make `pi/3` and `5 pi/3` fold to 0; a float
argument at a zero still stays unevaluated, by that rule.

## Cause and options

The exact-value tables of `BesselJ`, `BesselI`, `LambertW`, `ClausenCl` and
`AGM` (`src/compute-engine/library/special-functions.ts`) lack these
entries. Fix: add them, with `agm(a, a) = a` and `agm(a, 0) = agm(0, a) = 0`
for any `a`, and a test for each row.
