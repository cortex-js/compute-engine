The numeric value of an integral whose bound is a complex number is 0 instead of its value.

## Witness

On main `9ba99495e7151a56ab50ab8953e5d5847fe626eb`, no compilation involved:

```ts
const e = ce.box(['Integrate', ['Function', 't', 't'], ['Limits', 't', ['Complex', 0, 1], 0]]);
e.evaluate().toString(); // "1/2"  (right: (0 - i^2)/2 = 1/2)
e.N().toString();        // "0"
ce.box(['Square', e]).N().toString(); // "0", the value is 1/4
```

## Cause and options

Not investigated. `evaluate()` takes the closed form; `N()` takes another route (the numeric quadrature over a real interval, or a closed form evaluated with the bound's real part) that drops the imaginary bound. Option: `N()` of a definite integral uses the closed form when `evaluate()` finds one, or declines to a numeric value (stays unevaluated) when a bound is not real. A complex bound is rare: crafted.
