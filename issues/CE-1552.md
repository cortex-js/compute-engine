In a notebook, `fill(7, 3)` stops working once the drawing library defines a `fill` method for shapes.

## Witness

On 0.193.0, after `protocol Styled { function fill(self: Self, c: any) -> Self }`
and a type `Fig is Styled` that implements it, `s.fill("red")`,
`fill(s, "red")` and `Fill(7, 3)` work, but `fill(7, 3)` is the error
`protocol-implementation-missing` ("no implementation of `fill` applies to a
value of type `integer`"). Without the protocol it is `[7, 7, 7]`.

## Cause and options

This is the ruling of CE-716 (TYPE_SYSTEM_ROADMAP.md, name resolution, rule
1): a protocol member shadows the lowercase spelling of a library function.
Tycho's user expected the dispatch on the first argument to fall back.
Proposed: when no implementation applies to the first argument and a library
operator has the same lowercase name, the call is that operator. Workaround:
`Fill(7, 3)`, or a method name with no library twin.
