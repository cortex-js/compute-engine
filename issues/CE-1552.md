In a notebook, `fill(7, 3)` stops working once the drawing library defines a `fill` method for shapes.

## Witness

On 0.193.0, after `protocol Styled { function fill(self: Self, c: any) -> Self }`
and a type `Fig is Styled` that implements it, `s.fill("red")`,
`fill(s, "red")` and `Fill(7, 3)` work, but `fill(7, 3)` is the error
`protocol-implementation-missing` ("no implementation of `fill` applies to a
value of type `integer`"). Without the protocol it is `[7, 7, 7]`.

## Cause and options

This is the ruling of CE-716 (TYPE_SYSTEM_ROADMAP.md, name resolution, rule
1): a protocol member shadows the lowercase spelling of a library function.
Tycho's user expected the dispatch on the first argument to fall back.
Proposed: when no implementation applies to the first argument and a library
operator has the same lowercase name, the call is that operator. Workaround:
`Fill(7, 3)`, or a method name with no library twin. Tycho half on adoption:
remove the `Fill(…)` note from the `.fill` doc comment of the drawing prelude.

## Decision

User decision 2026-11-19: the library function of the same lowercase name is one more candidate of a bare call, and the candidates are filtered by applicability to the first argument, as in rule 3 of name resolution (`docs/TYPE_SYSTEM_ROADMAP.md`). This replaces "a protocol member shadows the library function" of CE-716 and the fallback proposed above.

- The first argument conforms (or its static type has a conforming subtype): the member. `floor(Money(3))` stays `3`.
- It does not conform and no subtype does: the library function. `fill(7, 3)` gives `[7, 7, 7]`.
- Both apply: the member wins.
- Conformance cannot be decided statically (`value`, a union of which only some arms conform): decided at run time, the member for a conforming value, otherwise the library function. When the static type settles it, the resolution is static, so compiled code calls the target directly.
- A user definition of the name still shadows both (rule 1), and `Styled.fill` and `Fill` stay available.

Cost: a forgotten conformance no longer gives `protocol-implementation-missing` at a call that the library function accepts. A warning on such a call is a possible refinement, not part of this fix. The rule text in `docs/TYPE_SYSTEM_ROADMAP.md`, `src/epsil/docs/protocols.md` and `src/epsil/docs/naming.md` changes with the fix, and so does the CE-716 test in `test/epsil/protocols.test.ts`.
