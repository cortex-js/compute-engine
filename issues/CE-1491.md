Assigning a commutator to a function declared to take two matrices returns a zero matrix even when the two matrices do not commute.

## Witness

```js
const ce = new ComputeEngine();
const A = ['List', ['List', 1, 2], ['List', 3, 4]];
const B = ['List', ['List', 0, 1], ['List', 1, 0]];
const comm = ['Subtract', ['Multiply', 'a', 'b'], ['Multiply', 'b', 'a']];
ce.declare('g', '(matrix, matrix) -> matrix');
ce.assign('g', ['Function', comm, 'a', 'b']);
ce.box(['g', A, B]).evaluate().json;
```

On npm 0.186.0 and main 489125b the signature still prints (matrix, matrix) -> matrix, but the value is [[0,0],[0,0]]. The matrix difference is [[-1,-3],[3,1]]. Assigning ce.box(['Function', comm, 'a', 'b']) to the same declaration reproduces the wrong answer. Explicit matrix annotations on the literal itself give the correct result.

For raw input, supply the declared parameter types before canonicalizing the products. For an already boxed scalar implementation, reject an incompatible assignment if its original operand order cannot be recovered. A host registering a matrix operator under a declared signature is a plausible API use. CE-1317 settled the case with no declaration; here the host declared both input types and the result before assignment. CE-1490 concerns a different route, with both parameters annotated directly as expression.
