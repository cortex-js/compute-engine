A function whose body is a parenthesized block that redefines its own parameter, f(u)=(u≔u+1; u+a), returns a formula in u instead of a number.

## Witness

CE 0.198.1, Document API, x a real input. Rows f(u)=(u≔u+1; u+a), a=1, y=f(2).

- The body as Tycho's LaTeX parse gives it:
  `["Delimiter", ["Block", ["Declare","u","'unknown'",["Add","u",1]], ["Add","u","a"]]]`.
  No row error. f(2) evaluates to `["Add","u",2]` and y to `["Add","u",1]`. The
  initializer's `u` reads a free symbol, not the parameter, and the local is
  not the argument plus 1.
- Control: the same Block without the Delimiter gives the row error
  `variable-redeclaration 'u'` on f and `invalid-document-dependency 'f'` on y,
  as compute-engine-fb said is intended (control-structures.ts, the comment
  before `duplicate`; SCOPING-MODEL "Two declarations of one name in one block").

compute-engine-fb's reading (2026-11-22): a nested scope may shadow, and its
initializer reads the outer name ("The initial value of a Declare is computed
with the outer name"), which gives u=3 and f(2)=4. So the Delimiter case should
give 4, or, if the Delimiter does not open a scope, the same
`variable-redeclaration` row error as the control. It gives neither.

The instrument prints `CE-1702: READY` when the Delimiter case gives 4 or the
row error.

## Cause and options

Not investigated on the CE side. The Delimiter seems to hide the Block from
the redeclaration check, while the Declare's initializer is still resolved in
the local's own scope.

Impact: `critical` (a wrong result with no error) and `minor` (the host has a
workaround) both fit, hence `needs-review`. Tycho's host now renames a
parameter-named Block local before prepare, also through a Delimiter
(`withParameterLocalsRenamed` in document-ce-manager.ts), so Tycho does not
wait on this. The probability is low: Desmos's `with` form and an authored
redefinition of a parameter are rare.

## CE answer

compute-engine-fb, 2026-11-22. Impact `critical`: a wrong value with no
error is `critical` by the impact table of `docs/ISSUE_TRACKING.md`, and a
workaround does not lower the impact. With `probability: low` the table
value is P3, as filed, so `needs-review` is removed. Disposition: a CE
defect, to fix from the backlog. Workaround: rename the local (Tycho's host
does this already).

It is not specific to the Document API. On main `9fd1134ca`, with `a = 1`:

```js
ce.box(['Apply', ['Function', ['Block', ['Block',
  ['Declare', 'u', "'unknown'", ['Add', 'u', 1]], ['Add', 'u', 'a']]], 'u'], 2])
  .evaluate().json;  // ["Add", "u", 2], expected 4
```

The `Delimiter` canonicalizes to the inner `Block`, so the local is in a
nested scope and may shadow the parameter, and by `docs/SCOPING-MODEL.md`
("The initial value of a `Declare` is computed with the outer name") the
initializer reads the parameter: `u = 3`, value 4. Cause not investigated.
