The double integral `\iint f\,dx\,dy` is read with its two variables in the order opposite to the one the evaluation uses.

## Witness

`\iint xy\,dx\,dy` parses to `Integrate(…, Limits(x), Limits(y))` (checked
2026-11-06). It must give `Limits(y), Limits(x)`. With a dependent bound the
order changes the value: `Integrate(x·y, Limits(x, 0, 2y), Limits(y, 0, 1))` is
`y²`, not `1/2`.

## Cause and options

User decision 2026-10-01: the first `Limits` is the outermost integral, as in
Mathematica; `evaluate()` and `nIntegrateMultiple` (`library/calculus.ts`) use
this order, and two tests of `calculus.test.ts` lock it. `Sum` and `Product`
document the same order. Fix the parser, `parseIntegral()` in
`latex-syntax/dictionary/definitions-calculus.ts`. A bounded iterated integral
on the parse route is a nested `Integrate`, which is not affected. The old
sub-item CE-296.1 named the order `Limits(x), Limits(y)`, which contradicts the
decision; the decision's order is used here. CE-296.2 is CE-1003.
