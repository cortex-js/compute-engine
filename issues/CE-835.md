An Epsil definition with the name of a library function, such as `At(xs, k) := 5`, replaces that function for every later computation on the engine.

## Witness

```epsil
let xs = [7, 8]
At(xs, k) := 5
[7, 8][2]        // [5, 5]; also ce.box(['At', ['List', 7, 8], 2]) and LaTeX L[2]
Sin(x) := 5      // then LaTeX \sin(0) gives 5; a lowercase sin(x) := 5 only shadows
```

## Cause and options

The scope of a top-level statement is the engine, and
`src/epsil/docs/naming.md` documents that a user binding shadows a library
name. Two spellings differ: `` `At`(xs, 1) := 5 `` rebinds the list, and LaTeX
`\sin(x)\coloneq 5` is the error `assignment-to-library-function` (CE-826).

- (a) An `At` head rebinds the list (`xs = ReplaceAt(xs, k, 5)`). Recommended:
  no program defines `At` on purpose.
- (b) Refuse a library head in `f(x) := …` and `f(x) = …`, as CE-826 does;
  `function` stays the way to shadow. Can go with (a).
- (c) Keep such a top-level definition local to the program; needs a design.
- (d) Nothing.

Files: `src/epsil/parser.ts`, `library/core.ts` (`DefineFunction`),
`definitions-core.ts`.

## Decision

User decision 2026-11-06: (a) and (b): an At head in an assignment rebinds the list element, and a library name as the head of f(x) := … or f(x) = … is refused, as CE-826 does for LaTeX; function stays the way to shadow a name.
