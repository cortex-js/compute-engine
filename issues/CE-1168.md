A Fresnel integral compiled for the GPU (WebGL 2) gives a shader that the browser refuses to compile.

## Witness

`FresnelC(x)` or `FresnelS(x)`, with `x` declared `real`, compiled to `glsl`
(for example in a fragment shader by `GLSLTarget.compileShader()`). The engine
writes the shader with no decline. The WebGL 2 compiler of Chromium (ANGLE,
on SwiftShader) refuses it:

```
ERROR: 0:36: '_gpu_polevl' : no matching overloaded function found
ERROR: 0:74: '_gpu_polevl' : no matching overloaded function found
```

`npm run test:glsl` (`scripts/glsl-check/glsl-driver.test.ts`, the operator
sweep) shows the two failures with the whole shader. The sweep lists the two
names as known failures: remove them from that list with the fix.

## Cause and options

`GPU_POLEVL_PREAMBLE_GLSL` in `src/compute-engine/compilation/gpu-preambles.ts`
declares `float _gpu_polevl(float x, float c[12], int n)`. In GLSL the size of
an array is part of its type, and an argument is never converted to another
array size. The Fresnel helpers pass arrays of 6, 7, 10 and 11 elements, so
only the call with a 12-element array matches.

Fix: declare each coefficient array as `float[12]`, padded with zeros after
its last coefficient (the loop reads only the first `n` elements), or write
one Horner helper per size. The first keeps one helper. Size S. A test: the
two names leave the known-failure list of the sweep, and the GLSL snapshots
of `FresnelC` and `FresnelS` change.
