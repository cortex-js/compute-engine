Two reads of the same element of a random list can give two different values.

## Witness

```
npx tsx src/cli/epsil.ts --eval 'WithRandomSeed(1, do { let v = [j for j in 1..10 if random() < 0.5]; (v[2], v[2], v) })'
```

gives `(4, 8, [1,2,4,5,7,8,9])`: the first `v[2]` is 4, the second is 8, and
the second element of the list is 2. With the seed 11 the result is
`(3, 5, [1,2,5,6,7,8,10])`. Measured 2026-11-07 on HEAD `155d0add7`.

The result must use one set of draws for `v`, as `docs/RANDOMNESS-MODEL.md`
§6 ("One instance, one draw set") states: each `v[2]` is the second element
of `v`.

## Cause and options

The `at` handler of `Comprehension` (`comprehensionCollectionHandlers()` in
`library/control-structures.ts`) reads an element through
`elementMemoFillTo()`, which walks only to the position. The element memo
keeps a partial walk for a pure instance only (`commitRecordedWalk()` and
`elementMemoFillTo()` in `boxed-expression/collection-element-memo.ts`), so
each read by position of an impure instance draws again, and a later
complete walk draws again too. Option: when the instance is impure and
finite by its form (`comprehensionIsFinite()`), read by position from one
complete walk (`each()`), which the memo keeps, as the count does since
CE-1111. The same question applies to the other operators with an element
memo (`Map`, `Filter`, `Tabulate`) whose `at()` computes one cell
(`elementMemoComputeCell()` keeps no cell for an impure instance).

A related case with a `crafted` witness: since CE-1111 the count of a
comprehension with a random guard is read from a walk that the memo keeps.
The memo keeps no walk with an element that holds a mutable object, but the
count memo (`_memoizedFacet('count')`) can keep the count of that walk, and
the next read of the elements draws again.
