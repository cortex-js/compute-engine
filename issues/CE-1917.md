An animation callback that counts its frames in a variable and then calls a raster method such as `board.compute(next)` runs interpreted, where the same call through a plain function compiles.

## Witness

On main `c61e248f40bfae01bced74cfdd16985d1287d92b` with the CE-1911 change,
compiled JavaScript, with a host function `hostTouch` and the protocol method
`touch(self: Box) -> nothing { hostTouch(self.cells) }`:

| Program | JavaScript |
| --- | --- |
| `(t: integer) => do { gen = gen + 1; box.touch(); gen }` | declines: `hostTouch(Field("self", "cells")): a write of the variable gen of the engine where a local or a parameter hides it` |
| control: `function touchAll() -> nothing { hostTouch(cells) }`, `(t: integer) => do { gen = gen + 1; touchAll(); gen }` | compiles |

No local or parameter hides `gen`. Tycho's raster methods (`compute`,
`adjust`) are protocol methods whose bodies call a host function, and a frame
callback that keeps a generation count or a time in a variable of the engine
writes it in the same body.

## Cause and options

A function that calls the host reads and writes each variable of the engine
that the root assigns (`assignedNames()` of `lower.ts`, `stateOf()`): the
lowering gives the function those variables as inputs. The walk that finds
the user functions that the root calls resolves a call with `userBinding()`
(`lower-context.ts`), which gives `undefined` for the dispatcher of a protocol
member, so the walk does not visit the implementation of `touch`. That
implementation is lowered without `gen`, and the host call's `stateWrite()`
finds no binding.
The fix makes that walk resolve a dispatched member as `protocols.dispatch()`
does. Size S.

Workaround: call a plain user function or the host function directly, or
assign the variable in another callback.
