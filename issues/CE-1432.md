When a program is refused for another reason, the refusal does not list the names that have no declared type, so a host does not learn which names to declare.

## Witness

With `x: real` and `u` undeclared,
`compile(ce.box(['Assign', 'u', ['If', ['Less', 'x', 0], 'u', 0]]), { profile: 'ir' })`
(and with `to: 'interval-js'`) declines with `outside-profile`, operator
`Assign` ("a write to a name that is not a local"), and `unsupported` is
`['Assign']`. The existing JavaScript compiler declines too, and its
`unsupported` is `['u']`: when an expression declines for another reason,
that reason is the error and the diagnostic, and `unsupported` also names
the inputs with no type (`compile-admission.test.ts`, "An input with no type
is refused (R1)"). Workaround: declare the names that the program reads.

## Cause and options

The profile refuses the untyped inputs at the end of the lowering
(`program()` in `src/compute-engine/compilation/ir/lower.ts`, `UntypedInputs`);
a decline thrown before that point carries only its own node, and
`interpreterFallback()` (`src/compute-engine/compilation/interpreter-fallback.ts`)
adds input names to `unsupported` only for the codes `untyped-input`,
`union-dispatch` and `unsettled-shape`. Options: (1) `interpreterFallback()`
adds the names that `inputNamesRead()` finds with no type (`unknown` or
`any`) to `unsupported` for every decline; (2) the lowering records the
untyped names it has seen and `sliceError()` passes them. Option 1 is smaller
and needs no lowering change. Either changes the JavaScript profile's
`unsupported`, which is why it was not made in the deletion work of the
existing interval target. Size S.
