A Tycho animation that passes a list or a tuple in an options dictionary to a drawing function, `t => figureDraw({p -> (t, 1)})`, runs interpreted instead of compiled, so it is slower.

## Witness

With CE-1771, a dictionary literal compiles on JavaScript as a record. A
function of the host that receives a dictionary with a tuple or a list value
declines:

```epsil
(t: real) => figureDraw({p -> (t, 1)})
```

"a call of the function figureDraw of the host, with an argument that holds a
list or a tuple that the interpreter can hold as a lazy collection (Range,
Reverse, Linspace) or that the code does not know as a List or a Tuple
literal". `figureDraw` is a host function declared with `evaluate`, as Tycho
declares it. The test `compile-dictionary-literal.test.ts` ("a tuple value of
a dictionary given to a function of the host") pins the decline.

Plausible: Tycho's option dictionaries hold tuples (`bounds -> ((x0, y0),
(x1, y1))`, `resolution -> (w, h)`, `range -> (lo, hi)`, `dash -> (4, 2)`),
and a figure built from such a value reaches a host function.

## Cause and options

`reach()` of `lower.ts` builds `readers` from the operands of each function
node and does not enter a dictionary, so a `Tuple` or `List` literal that is a
value of a dictionary is not a node of `readers`: `unlisted()` marks its value
not listed (`Listed`), and `hostCall()` declines on `fullyListed()`.

Option: let `reach()` enter the values of a dictionary, with a reader entry
that `nanForAbsent()` and the other readers of `readers` do not take as a
place of the value (a dictionary is not a function node). Each reader of
`readers` must be checked for the new entry kind.

Workaround: accept the interpreted tick, or pass the style with a method of
the figure instead of a dictionary value.
