Accepting the completion of a sum-type variant with no payload just before an existing `(` inserts a second pair of parentheses.

## Witness

```epsil
type light = red | green
let a = gree▮()
```

`epsilCompletions()` at `▮` gives the item `green` with `insertText:
"green()"`, so accepting it gives `let a = green()()`. The same text is
inserted after `|>` (`x |> gree▮` gives `x |> green()`, a call of `green`
with `x` as its argument).

`plausible`: retyping the name of an existing call is ordinary editing.

## Cause and options

In `src/epsil/completion.ts`, the variant items insert `${spelling}()` for an
empty payload without looking at the text after the word. A function member
after `.` already checks it (`memberCall`), and since CE-1664.7 the snippets
check `called` (`source[end] === '('`) and `piped`. Use the same two tests for
the `()` of a variant: insert the plain spelling when `called` or `piped`.
Size S, with a test in `test/compute-engine/epsil-completion.test.ts`.
