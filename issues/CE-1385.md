In Epsil, a product of matrices taken from `svd` by destructuring is computed in the wrong order, so `U * S * transpose(V)` does not give back the matrix.

## Witness

Epsil CLI, main 6be5b5f52:

```
let A = [[1, 2], [3, 4]]; let (U, S, V) = N(svd(A)); U * S * transpose(V)
```

prints `[[-2.81…, 4.69…], [0.31…, 0.19…]]`; it must print `A` (which
`matrixMultiply(matrixMultiply(U, S), transpose(V))` gives).
`U * S - matrixMultiply(S, U)` is the zero matrix: the factors were sorted.
For a 2×3 matrix the same program fails with "incompatible dimensions". With
`let T = N(svd(A))`, `T[1] * T[2]` is right, and so is a destructured tuple
of literal matrices (`let (Q, P) = ([[1, 2], [3, 4]], [[0, 1], [1, 0]]); Q * P`).
`type(U)` prints `matrix<real^(2x2)>` after the fact.

## Cause and options

`docs/BROADCAST-MODEL.md` (around line 454): factors whose type is `unknown`
when the product is boxed are sorted like numbers. The names bound by
destructuring the result of `svd` seem to be `unknown` when the product is
boxed, so `U * S` becomes `S * U`. That caveat is for a host that assigns a
matrix later; here the Epsil program binds the names first. Fix: give each
destructured name the type of its member of the tuple's static type when the
binding is made (check that `SVD`'s declared result type states three
matrices), and add the program above as a test.
