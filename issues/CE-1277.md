A list mapped through a composition of functions uses another function than the one the expression was written with, when a function of the same name is declared where it is evaluated.

## Witness

Run on main at `1d2693073f734081b74ed806451cbf2f76626688` (0.188.0 and one test commit):

```js
ce.declare('L', 'list<real>');
ce.assign('f', ce.box(['Function', ['Multiply', 2, 'y'], 'y']));
const map = ce.box(['Map', ['Composition', 'f', 'Negate'], 'L']);
const call = ce.box(['Apply', ['Composition', 'f', 'Negate'], 'x']);
ce.pushScope();
ce.declare('f', { signature: '(number) -> number', evaluate: () => ce.number(100) });
ce.withValues({ L: ce.box(['List', 1, 2]) }, () => ce.box(['ListFrom', map]).evaluate());
// [100, 100]: the `f` of the pushed scope
call.evaluate();
// -2x: the `f` the expression was boxed with
```

## What it must give

`[-2, -4]`. An expression reads each name from the scope it was boxed in
(`docs/plans/2026-11-11-bound-once-spec.md`, section 2, rule 1), and the
applied composition of the same program follows the rule.

## Cause and options

Not investigated. The step of a `Composition` given as the callback of
`Map` is found by its name when an element is computed, from the scope
current at that time. A compilation of the same `Map` declines, so compiled
code is not affected.
