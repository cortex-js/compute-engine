A result type on an Epsil function makes a compiled loop copy the whole list at each update, so the function becomes 20 to 50 times slower.

## Witness

```
function g(H: list<number>, n: integer) -> list<number> {
  let L = H
  for k in 1..n { L = replaceAt(L, k, L[k] + 1) }
  L
}
```

Compiled to JavaScript, `g(X, 3)` warns `copying-list-update` for `L`; without
`-> list<number>` it writes `L` in place. Values are equal. Tycho's Buddhabrot
step (30,001 elements): 3.28 ms a firing without the result type, 70 to 170 ms
with it; the deadline is 50 ms.

## Cause and options

The canonical body ends with `Typed(L, 'list<number>')`. `ownedLocalChains`
(`compilation/in-place-update.ts`) accepts a bare `L` statement but reads `L`
inside `Typed` as a mention that keeps the list. JavaScript compiles `Typed(x,
T)` to `x`. Fix: read `Typed(x, T)` as `x` in the same position, in `allowedAt`
and in `returnsOwned` (`Fold` step). Workaround: leave out the result type;
the inferred type is the same.

Tycho half on adoption: remove `todo: RESULT_TYPE_GAP` in
`tests/node/graph-paper/prelude/prelude-lanes.test.ts`.
