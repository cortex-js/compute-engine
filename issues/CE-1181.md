A request to Tycho: the codegen audit must call `canCompile()` before each GLSL compile and record each disagreement, so that CE can remove shader code that no program reaches.

## Witness

The GLSL target of CE now accepts only the forms of a positive list (the GLSL
fragment, CE-1166, committed in `1e5d675b7` to `43679ce5d`, not released).
`canCompile(expr, options)` answers `{ ok: true }` or
`{ ok: false, diagnostic }` with the options of `compile()`, and `compile()` to
`glsl` runs the same check first. Step 5 of CE-1166 removes the shader statement
code that the check makes unreachable. Before that removal, CE needs a whole
corpus run where each GLSL record shows the answer of the check beside the
answer of the compile. The run of 2026-11-08 at 15:57 covered the core corpus
and the showcase entries only.

## What Tycho is asked to do

1. In `scripts/audit-ce-codegen.mts`, before each GLSL compile, call
   `canCompile()` with the same expression and options. Record in the record
   the result (`ok`, and the diagnostic `code`, `operator` and `message` when
   it refuses) and a field `predicateDisagrees: true` when the check and the
   compile give different answers (check yes, compile declines; or check no,
   compile succeeds).
2. Run the whole corpus with preludes against the CE source tree
   (`CE_ALT_PKG=<CE root>`, after `npm run build` there) or the first release
   that holds CE-1166.3, and against 0.184.0.
3. Write in the `## CE answer` section below, as `Tycho (<date>): …`, the
   path of the output, the number of GLSL records, and the list of records
   that disagree. A disagreement is a CE defect: CE files it.

`canCompile()` is exported beside `compile()` (`src/compile.ts`). The
diagnostic code of a refusal is `outside-fragment`.

## Cause and options

No CE change. CE-1166 step 5 (removal of the shader statement code) waits for
this run. The measuring part of step 5 can start before it.
