With two engines at different precisions, an exact fraction and two decimals can each be "the same" as the next one, without the first being the same as the last.

## Witness

```ts
const A = new ComputeEngine({ precision: 21 });
const B = new ComputeEngine({ precision: 50 });
const s = '0.' + '3'.repeat(21);
const r = A.number([1, 3]), r2 = B.number([1, 3]);
const x = A.number(s), y = B.number(s);
r.isSame(x);  // true
x.isSame(y);  // true
r.isSame(y);  // false
r.isSame(r2); // true
r2.isSame(y); // false
```

`isSame` is documented as an equivalence relation (ARCHITECTURE.md), used
for matching and deduplication. Within one engine it is one. The witness
mixes numbers of two engines on purpose; nothing in the library does that.

## Cause and options

`same()` (`src/compute-engine/boxed-expression/compare.ts`) compares an
exact number with a decimal by rounding the exact number at a precision
(`ExactNumericValue.eq`), so that in one engine `1/3` is the same as its
value at the engine's precision (CE-1362). For a pair of engines it reads the
higher of the two precisions, which makes the relation symmetric
(`6f91641e4ea209902dfec008931bf251d32b1e65`); before, it read the left
operand's precision and `r.isSame(y)` and `y.isSame(r)` differed.

No rule that reads a precision of the pair is transitive across engines:
two exact values are the same in every engine, but each engine equates the
exact value with its own rounding (`r ~ r2`, `r ~ y`, `r2 ≁ y` with the
lower precision as well). The transitive rule compares an exact number with
a decimal exactly (`1/3` is never the same as a decimal); it changes the
result within one engine, where `isSame` of `1/3` and its value at the
engine's precision is `true` today.
