A function applied to each entry of a dictionary fails on an entry whose value is missing, although the dictionary itself was accepted.

## Witness

At HEAD `b2f4b0ce0`, a store accepts a dictionary entry or a tuple slot that
holds `Missing` where its type admits a present value (`docs/ERROR-MODEL.md`,
rule 5), but a callback refuses the same element:

```ts
ce.declare('d', 'dictionary<integer>');
ce.assign('d', ce.box(['Dictionary',
  ['KeyValuePair', { str: 'a' }, 1],
  ['KeyValuePair', { str: 'b' }, 'Missing']]));
ce.box(['FlatMap', 'd', ['Function', ['List', ['At', 'x', 2]], 'x']]).evaluate();
// [1, Apply((x) => [At(x, 2)], Error(incompatible-type,
//   "tuple<string, integer>", "tuple<string, missing>"), ("b", "Missing"))]
```

The same happens for `list<tuple<string, integer>>` holding
`("b", Missing)`, and, since CE-71 (closed records), for a record whose
field holds `Missing`. A `list<integer>` holding `Missing` is not refused:
the store rule is applied to an element, not to a slot inside an element.

## Cause and options

The callback is stamped with the element type (`tuple<string, integer>`) and
its parameter check uses the strict `matches`, not the store rule
(`matchesOrAbsent()`, `boxed-expression/effects-inference.ts`), so a
`missing` slot inside the element is refused.

- (a) Apply the store rule at a callback parameter, as for a store: remove
  the `missing` arms of the element type before the check.
- (b) Keep the refusal and document that a callback does not take an
  element with an absent slot.

Workaround: declare the callback parameter (`(x: tuple<string, any>) => …`)
or read the value with `Values(d)`.
