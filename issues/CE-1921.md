A compiled callback that draws a label, `label((t, 0), "a")` with Tycho's drawing prelude, runs interpreted, because a parameter declared `list` declines a list of numbers and a string.

## Witness

On main `33ab9b72b8a91d0fcbc0a03ee718e454c0f7bbd1`, compiled JavaScript at
`t = 3`, with
`type T = tuple<k: string, geom: list>`,
`function g(geom: list) { geom }`, `function wrap(geom: list) { T("x", geom) }`
and `function wrapAny(geom: any) { T("x", geom) }`:

| Program | JavaScript | Interpreter |
| --- | --- | --- |
| control: `[t, 2, "a"]` | `[3, 2, "a"]` | `[3, 2, "a"]` |
| control: `T("x", [t, 2, "a"])` | `{k: "x", geom: [3, 2, "a"]}` | the same |
| control: `wrap([t, 2])` | `{k: "x", geom: [3, 2]}` | the same |
| `wrap([t, 2, "a"])` | declines: `the parameter geom of wrap is not a scalar (list)` | `T("x", [3, 2, "a"])` |
| `g([t, 2, "a"])` | declines: `the parameter geom of g is not a scalar (list)` | `[3, 2, "a"]` |
| `g([t, 2])` | declines: `the result of g is not a scalar (list)` | `[3, 2]` |
| `wrapAny([t, 2, "a"])` | declines: `the field geom of T: a value of type any, here record(integer, integer, string), which does not prove list` | `T("x", [3, 2, "a"])` |

Tycho's prelude (`src/graph-paper/notebook/drawing/prelude.ts`) has
`function figureOf(kind: string, geom: list)`, and
`label(p, text, opts)` calls `figureOf("label", [N(p[1], 15), N(p[2], 15), text])`.
`Figure` declares `geom: list`. So every compiled call of `label` declines at
`figureOf`, before CE-1918. Declaring the parameter `any` does not help: the
field `geom: list` of `Figure` then refuses the value (last row).

## Cause and options

A `List` literal whose elements do not make a list (a number and a string) is
lowered as a record with no names (`src/compute-engine/compilation/ir/README.md`,
"Records"). A field of type `list` takes it from a literal (second control),
but a parameter takes a record only when it has no stated type, `any`, a
nominal tuple type or `dictionary` (`signatureTypes()` and `held()` of
`lower-functions.ts`), and the field check refuses a held value of type `any`
whose record does not prove `list`. A result declared `list` declines for a
list of numbers too.

The fix lets a parameter and a result of type `list` (bare, or of an element
type that admits the elements) hold such a record, one function per record
type as for `any` (`laneKey()`), and lets the field check accept a held record
whose elements the field type admits. No run-time test is needed: the record
type is settled at each call. Size M.

Workaround: none in the prelude; a program that builds the record with the
literal in the constructor call (`T("x", [t, 2, "a"])`) compiles.
