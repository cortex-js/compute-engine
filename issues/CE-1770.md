A reversed string that is not evaluated yet reports the number of characters of the original string, which can be more than the reversed string has.

## Witness

On main `9d73f863d402e3d0daa02e3b616d09d9033dbb9f`, with `m` the combining
acute accent U+0301:

```ts
const r = ce.box(['Reverse', { str: m + 'a' }]);
r.count;                  // 2 (right: 1)
r.evaluate().string;      // "a" + m, one character
```

`Length`, `At`, `First`, `Last` and `Characters` of the same expression give
the right values, because they evaluate the string first. Only the `count`
property of the unevaluated expression is wrong. The same holds for `Sort`
and `RandomShuffle` of a string, and for the views over them (`Take`,
`RotateLeft`) when a combining mark moves next to a letter.

## Cause and options

The `count` handler of `Reverse` (`library/collections.ts`) returns the count
of its source. For a string, the characters are grouped again after they are
reordered, so the count can change. Fix: the handler answers `undefined` when
the source can be a string (`isDisjointFrom('string')` is false), as
`peekWrappers` does since CE-1403. Check that the string-join step
(`evaluateStringPreservingCollection`, `boxed-function.ts`) still finds a
finite walk then.
