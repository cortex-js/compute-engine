In a document with complex numbers turned on, a colour made from a square root is no longer computed by compiled code.

## Witness

```ts
const ce = new ComputeEngine();
compile(ce.box(['AsOklab', ['Hsv', ['Multiply', 20, ['Sqrt', 'z']], 1,
  ['Add', 'z', ['Rational', -12, 5]]]]),
  { to: 'javascript', mode: 'complex', iterationBudget: 1000000,
    inputs: { z: 'real' } });
```

0.194.3: declines, "Hsv(Multiply(20, Sqrt(z)), 1, Add(z, -12/5)): Hsv of
complex, integer, real". 0.192.0: compiles; at `z = 4` the colour is
`{space: 'oklab', c0: 0.80158, c1: 0.04909, c2: 0.16328}`, and where the
square root is not real (`z = -4`) every channel is NaN (the emitted code
tests `cisreal()` of each operand and gives a NaN colour otherwise).
Control: the same program with `mode: 'strict'` compiles on 0.194.3 and gives
the same colour at `z = 4`. Smallest form: `Hsv(Sqrt(z), 1, 1)`, same options,
declines on 0.194.3 and compiles on 0.192.0.

Document form: the document assigns `p ≔ Hsv(20√z, 1, z − 12/5)` and Tycho
compiles `AsOklab(p)` with `{to: 'javascript', mode: 'complex',
iterationBudget: 1000000, inputs: {x, y: 'real<-1e15..1e15>', z: 'real'},
symbolic: ['t', 'u', 'v']}`. In the document context the message reads
"Hsv of complex, integer, complex". Captures: Tycho
`.cache/mg-evidence/codegen-full.json` record 1406 (0.192.0, compiled) and
`.cache/macro-carriers-phase-a-ce1943/codegen-full.json` record 1416
(0.194.3, declined).

Tycho impact: `art/lrhjtkkyls` (an imported Desmos document in complex mode)
loses the compiled JavaScript colour of its implicit surface. The document
still draws with almost the same pixels (data pixels 0.10809 → 0.10807,
Tycho `roadmap/MACRO_CARRIERS_PHASE_A.md`), so Tycho has a way around it.
Tycho compiles a colour with `mode: 'complex'` in a complex-mode document on
purpose: a domain colouring reads `Argument` and `Abs` of a complex value
(`src/graph-paper/graph/style-expressions.ts`, `colorLaneMode`).

## Cause and options

The colour constructors of the colour lane take only real operands; a
`complex` operand (here the static type of `Sqrt` of a real in complex mode)
declines. Expected: compile as 0.192.0 did, with a NaN colour where an
operand is not real at run time. No other option is proposed; a documented
decline would leave such a colour to the interpreter.

## Fix

A colour constructor (`Rgb`, `Hsl`, `Hsv`, `Oklab`, `Oklch`) of compiled code
reads a complex channel as its real part, because the interpreter reads the
real part of each channel (`library/colors.ts`). So the compiled colour
equals the interpreter's colour also where the square root is not real: at
`z = -4` the witness is `{space: 'oklab', c0: 0, c1: 0, c2: 0}`, the value
of `evaluate()`, not the NaN colour of 0.192.0. At `z = 4` it is the colour
of 0.192.0.
