A Tycho colour formula that calls `colormap` (for example a heatmap coloured `colormap(turbo, (x+1)/2)`) is no longer drawn on the GPU since 0.185.0; the CPU paints it, which is slower.

## Witness

The GLSL fragment check types every call of a `functions` entry as `real`,
whatever the declared result type of the operator. With a fresh engine:

```ts
ce.declare("x", "real");
ce.declare("g", { signature: "(any, any) -> color" });
compile(ce.box(["AsOklab", ["g", 0, "x"]]), { to: "glsl", functions: { g: "hostG" } });
// 0.185.0: success false, "No signature of `AsOklab` in the GLSL fragment
// takes operands of the types (real)."
```

Controls on 0.185.0: a `functions` entry whose operator returns `real`
(`h(x) + 1`) compiles, and `AsOklab(c)` with `c` declared `color` compiles.
On 0.184.0 the colour case compiled: Tycho's tests of the colormap GPU field
(`tests/node/graph-paper/style-fragment-field.test.ts`, 14 cases, and the GPU
spec `heatmap-formula-gpu.spec.ts`, "a colormap formula paints per pixel on
the GPU") passed on 0.184.0 and fail on 0.185.0 with this decline.

In Tycho, `colormap` is declared `(any, any) -> color` (with a `type` handler
that gives `list<color>` for a list operand) and compiled with
`functions: { colormap: "tychoColormap" }`, where `tychoColormap` is a GLSL
function of the preamble that returns a `vec3`.

## Cause and options

`callerRule` in `src/compute-engine/compilation/glsl-fragment.ts` returns
`{ kind: 'real' }` for every call of a `functions` entry. Proposed: take the
result type from the declared type of the call (`node.type`) through
`glslFragmentTypeOf()`, as a symbol does, and refuse only when that type has
no fragment type. Size S.

No Tycho workaround: Tycho's CPU lane paints such a colour with the right
values, as it does for any colour that has no GPU field, at the cost of the
GPU speed.

Tycho half on adoption: none.

When the fix ships, Tycho's 14 colour-map cases of
`tests/node/graph-paper/style-fragment-field.test.ts` and
`style-coordinate-colors.test.ts`, and the spec "a colormap formula paints
per pixel on the GPU" of `heatmap-formula-gpu.spec.ts`, pass again.

READY (the instrument's reading): `AsOklab(g(0, x))` compiles to `glsl`.

## Fix

`callerRule` in `glsl-fragment.ts` takes the result type from the declared
type of the call (`glslFragmentTypeOf(node.type.type)`) when it is a color, a
point, a complex number or a boolean, and reads every other result as a real,
as before (a head with no declaration, a number, an integer). Test:
`test/compute-engine/ce-1183-glsl-functions-entry-result-type.test.ts`. The
instrument prints READY on the working tree.

## CE answer

CE (2026-11-09): P1, planned for 0.185.1. The fix is the one under "Fix":
a call of a `functions` entry now has the declared color result type of
its operator, so `AsOklab(colormap(...))` compiles to `glsl` again. No
workaround on the Tycho side other than the CPU lane, which paints the right
values. Tycho half on adoption: none.
