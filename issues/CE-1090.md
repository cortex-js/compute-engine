A function assigned inside a sum loses the value of the sum's index once the sum ends, and a later call of the function gives an unevaluated form.

## Witness

`test/compute-engine/closure-frame-retained.test.ts`, "a closure assigned in a
big operator reads its index" (both the `debug true` and `debug false` cases)
fails at `61447c29ee222e9ddac51466aebdd21f626b2c22`:

```ts
ce.declare('g', 'function');
ce.assign('g', ce.box(['Function', 'x', 'x']));
ce.box([
  'Sum',
  ['Block', ['Assign', 'g', ['Function', ['Add', 'x', 'i'], 'x']], 'i'],
  ['Limits', 'i', 1, 3],
]).evaluate().json;                  // 6 (correct)
ce.box(['g', 1]).evaluate().json;    // ["Add", "i", 1]   (must be 4)
```

A bisect from `6e68f56c3` (the nightly run, where this test passed) gives the
first bad commit `36e9974927538c53ed5ff66d865f51187cb17186` (CE-1062: the
iteration of a `Sum` or a `Product` puts back the value of its index when it
stops).

## Cause and options

Before CE-1062, the closure gave `4` only because the index kept its last value
(3) in the scope after the sum. CE-1062 puts back the value of the index from
before the iteration (here, no value), so the closure, which reads `i` when it
is called and not when it is made, finds no value. Fix: the closure made in an
iteration keeps the binding of the index of that iteration, as a closure made in
a loop or a block keeps its frame (the other tests of the same file). Then the
closure of the last iteration gives `1 + 3 = 4`, and the index is still put
back after the sum. Size S to M.

The probability is `low`: the program assigns a function to an outer name from
the body of a sum, which a test built for the case does, not a document.
