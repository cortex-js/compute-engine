A function that is declared with a signature but has no body accepts a list of numbers at a `string` parameter, with no diagnostic, and the call is typed as a list.

## Witness

Main at `185f9a1766354950606289150ce842672d0c3c1d`:

```ts
ce.declare('h', '(tuple<real, real>, string) -> real');
ce.box(['h', ['Tuple', 1, 0], ['List', 1, 2]]);  // valid, type list<real>
ce.declare('k', '(real, string) -> real');
ce.box(['k', 1, ['List', 1, 2]]);               // valid, type vector<real^2>
```

Expected: `incompatible-type` at the second argument, as for a named-tuple
constructor with the same signature (CE-1745) and as for a function with a body,
whose evaluation gives one `incompatible-type` error per element
(`function k(a: real, s: string) { s }; k(1, [1, 2])`).

## Cause and options

The value route of `box.ts` reads a declared function symbol as a user
function: `threadableGate(…, paramsAreScalar(…), true)` makes the `string`
slot threadable, and the threadable check of a user function
(`liftedOperandCannotFit`, `validate.ts`) admits a literal list on purpose:
the application of a body maps over its elements and reports an error for
each element that does not fit. A function with no body is never applied, so
no check runs. Option: in `checkThreadableOperand`, refuse a finite list whose
element type shares no value with the slot when the callee has no body.
Size S.
