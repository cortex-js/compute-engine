Three test files fail at the current main: each one expects a compilation to decline in a form that the compiler no longer uses.

## Witness

At bc4f32fbb481d78a9ce93b82d2c18af0cddd0da1 (no local change),
`npx jest -w 4` of these files gives 3 failures in 221 tests:

- `test/compute-engine/ce-712-2-callback-variants.test.ts:243`, "a literal
  list of elements of two shapes (decision D7)":
  `Map(f, [1, [2, 3]])` still declines, but with the code
  `outside-profile`, where the test expects `unsettled-shape` (rule R3 of
  `docs/COMPILATION-MODEL.md`).
- `test/compute-engine/block-scope-capture.test.ts:669`, "a function body
  with a parameter that has no declared type": the decline message is now
  "a function value that is not the program or the literal of a Map, a
  Filter or an Apply", where the test expects "the result of f is not a
  scalar (collection<unknown>)".
- `test/compute-engine/ce-1163-pool-call.test.ts:125`:
  `compile(ce.parse('(n: integer) \\mapsto [n, [n+1, 2n]]'))` gives
  `success: true` in the test's engine, where the test expects a decline.
  In a new engine with the default options it gives `success: false`, with
  the fallback message "At with an index for each level".

## Cause and options

Not traced. Commit 4a5cea61192dc4b16deb61ff6f978e916dc027f2 (2026-11-22,
`list<list<…>>` read row by row, #638) changes the lowering of lists of
rows, and is probably the cause of the third failure. For each test: find
the commit that changed the result, then either update the test to the new
decline (when the new decline is correct and the shape of the result is
still settled) or restore the old decline code. The values that compile
must be checked against the interpreter before a test is changed.
