The diagnostic for a name that is read before its `let` has the general code `static-type-error` and the range of the whole statement, not a code of its own and the range of the read.

## Witness

An Epsil program `let a1 = b1 + 1` followed by `let b1 = 2`: the diagnostic
is `static-type-error`, "`b1` is used before the statement that declares it
in this block", with the range of the whole first statement (`[0, 15]`).
Tycho's prelude runner reported the same condition itself with the code
`read-before-definition` and the range of the read; since bound-once step 1
the engine reports it first.

## CE answer

CE (2026-11-12): P3, accepted. The engine's error is
`read-before-declaration`; the Epsil diagnostic should carry that code and
the source range of the occurrence that is read. Workaround: map the
message text. Not started; it belongs with the `Program` operator
(ROADMAP CE-1255), which keeps the diagnostics per statement.
