A compiled function that tests whether an integer input is an integer falls back to the interpreter, although the answer is known from the declaration.

## Witness

From the decline census on GitHub #638: 10 items of a combinatorics corpus
(4 statistics, 6 maps). On main f42a02d1323b9e40cf2def511715fc3034ae8d6c, JavaScript target:

```ts
ce.declare('n', 'integer');
compile(ce.box(['Element', 'n', 'Integers']), { fallback: false });
// Could not compile: Element(n, "Integers"): Element of a value that the
// interpreter may hold exactly
```

`fallback: true` gives the interpreter's value (the workaround). `IndexOf(P, 3)` with `P: list<integer>` compiles.

## Cause and options

The host supplies a value of the declared type, so `Element(x, S)` is decided
at compile time when the static type of `x` is a subtype of the type of `S`
(`true`), or disjoint from it (`false`), as CE-1652 does for `MatchesType`.
Only a type that does not decide it keeps this decline.
