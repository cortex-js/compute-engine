A shader does not compile a program that uses a named type of two to four numbers, such as a point `P2(x, y)` or a color `C3(r, g, b)`; the same program compiles to JavaScript.

## Witness

At commit `74595f4c6168d444a223289f7b370e8a045300f4`, after `executeEpsil()` of

```
type P2 = tuple<x: real, y: real>
type C3 = tuple<r: real, g: real, b: real>
function norm2(p: P2) { p.x * p.x + p.y * p.y }
function mid(a: P2, b: P2) { P2((a.x + b.x) / 2, (a.y + b.y) / 2) }
function gray(c: C3) { 0.3 * c.r + 0.6 * c.g + 0.1 * c.b }
```

and `x`, `y` declared `real`, each of these declines with
`compile(expr, { to: 'glsl', fallback: false })` and compiles with
`to: 'javascript'`:

| Program | Message on `glsl` |
| --- | --- |
| `P2(x, y).x` | `P2(x, y): a value of the type P2, a record: records compile on javascript only` |
| `norm2(P2(x, y))` | the same |
| `mid(P2(x, y), P2(y, x)).x` | the same |
| `P2(x, y)` as the result | the same |
| `gray(C3(x, y, x))` | `C3(x, y, x): a value of the type C3, a record: records compile on javascript only` |

The interpreter gives `norm2(P2(3, 4))` = 25.

Workaround: an unnamed tuple whose elements are read by position
(`p[1]`, `p[2]`), which is a `vec2` to `vec4` on GLSL. A read by name of an
unnamed tuple type (`p.x` with `p: tuple<x: real, y: real>`) does not compile
on either target ("Field of a value that is not a record").

## Cause and options

GLSL declines every record but a value of the nominal type that is a tuple
cell of four bytes (`docs/COMPILATION-MODEL.md`, "Arrays", "On GLSL";
`lower-records.ts`, `vectorRecord()` of `ir.ts`). A value of a nominal tuple type of two to four
numbers of one lane fits a `vec2`, a `vec3` or a `vec4`.

The nominal type that is a tuple cell of four bytes (`type Pixel =
tuple<r: Byte, g: Byte, b: Byte, a: Byte>`) is lowered as a `vec4` on GLSL by
the user's decision of 2026-11-26 (session compute-engine-57). This issue is
the rest: every other nominal tuple type of two to four numbers of one lane.

Option: extend that lowering. The constructor is the vector, a field read is
one element, a parameter and a result are the vector, and `Equal` of two
values of the type is the equality of the vectors. The value keeps the name
of its type in the IR, because the interpreter gives `False` for the equality
of a value of a nominal type and an unnamed tuple (CE-1872). A record with a
field that is not a number, with fields of two lanes, or with more than four
fields keeps declining.
