The numeric value of a list divided by a number has a wrong last digit: `[1, 2, 3]/3` gives `0.999…9` for the last element, not `1`.

## Witness

On `adcfe196a8e5c200689cc972409980865dcca6b8`, at the default 21 digits:

```ts
const ce = new ComputeEngine();
ce.box(['Divide', ['List', 1, 2, 3], 3]).N().json;
// ['List', {num: '0.333333333333333333333'},
//          {num: '0.666666666666666666666'},
//          {num: '0.999999999999999999999'}]
ce.box(['Divide', 2, 3]).N().json; // {num: '0.666666666666666666667'}
```

The second and third elements should be `0.666666666666666666667` and `1`:
`.N()` gives a value correct to the working precision, and each element is an
exact rational. `Range(1, 3)/3` gives the same list.

Since CE-1603 the comparisons have no tolerance. A comparison whose
operands have exact values (literals, and variables that hold exact values)
is decided on the exact values under `.N()` (CE-1603), so
`Less([1, 2, 3]/3, 1).N()` is `[True, True, False]`; the digit shows in the
value itself and in a comparison of the result after `.N()`
(`Equal(N([1, 2, 3]/3)[3], 1)`).

`needs-review`: the impact is `critical` by the table (a wrong finite value,
no error), though the error is in the last digit; `confidence` is the other
reading.

## Cause and options

The canonical form is `Multiply(Rational(1, 3), List(1, 2, 3))`. Under `.N()`
the rational is rounded to `0.333333333333333333333` first, and each element is
multiplied by that float, so the rounding of `1/3` is multiplied by the
element. The fix: under `.N()`, multiply the exact factor by each element
first and round the exact product, as the scalar `Multiply(1/3, 3)` does
(it gives `1`).
