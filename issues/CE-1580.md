In Epsil, a block comment that is not closed after code gets the message "unexpected symbol" instead of "end of comment expected".

## Witness

```
let a = 1 /* note
```

`parseEpsil` gives `["unexpected-symbol", "/* note"]` at `[10, 17]`. The same
comment at the start of the source (`/* note`) gives `end-of-comment-expected`.
In a block, `f(1 /* x` gives `closing-bracket-expected` and
`["unexpected-symbol", "/* x"]`.

## Cause and options

The lexer gives the unclosed comment as an `ERROR` token that carries the
diagnostic `end-of-comment-expected`. The statement-boundary checks of the
parser (`parseProgram`, the block loop near the `'unexpected-symbol',
this.current.text` errors) call `this.error(['unexpected-symbol', …])` on that
token instead of `reportUnexpected(token)`, which harvests the lexical
diagnostic. Fix: call `reportUnexpected` at these sites. Since CE-1522 the
diagnostic has `incomplete: true` at the end of the input, so an editor already
waits for it; only the message is wrong. Size S.
