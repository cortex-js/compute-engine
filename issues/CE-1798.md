A function that the user declares with a generic signature is shown to return a list of integers when one argument has no known type, and that argument can be any value.

## Witness

At `4f694bdc4b8a1407558f253027bc1b0af162a17f`, with the change of CE-1769 applied:

```ts
ce.declare('ff', '(indexed_collection<T>, T) -> list<T> where T: any');
ce.declare('tt', 'unknown');
ce.box(['ff', ['List', 1, 2], 'tt']).type.toString();   // list<integer>
ce.assign('g', ce.box(['Function', ['ff', ['Range', 1, 'u'], 't'], 'u', 't']));
ce.box('g').type.toString();   // (u: unknown, t: unknown) -> list<integer>
```

Both must be `list<unknown>`: `tt` can hold `0.5`.

## Impact

No value is wrong. The result type is too narrow. The library operators
`Append`, `Insert` and `ReplaceAt` have a `type` handler that keeps an
`unknown` stored value in the element type (`storedElementType`,
`library/collections.ts`); a signature without a handler does not.

## Cause and options

The solver absorbs an operand typed `unknown` (D8 in `validate.ts`): the
variable gets its binding from the other operands only, and the result type
is instantiated with that binding.

1. When an operand at a bare variable is absorbed as `unknown`, join
   `unknown` into the binding that instantiates the result type, and remove
   the per-operator handlers of `Append`, `Insert` and `ReplaceAt`. This
   changes the result type of every generic library operator that has such an
   operand (for example `Max(t, 1)`): measure the changed tests first.
2. Keep the per-operator handlers and document the limitation for
   user-declared signatures.
