A sum or a product over the elements of a sorted, reversed or shortened list stays unevaluated.

## Witness

```ts
const ce = new ComputeEngine();
const sum = (xs) => ce.expr(['Sum', ['Power', 'k', 2], ['Element', 'k', xs]]).evaluate().json;
sum(['List', 3, 2, 1]);                 // 14
sum(['Range', 1, 3]);                   // 14
sum(['Sort', ['List', 3, 2, 1]]);       // unevaluated, expected 14
sum(['Reverse', ['List', 3, 2, 1]]);    // unevaluated, expected 14
sum(['Take', ['List', 3, 2, 1], 2]);    // unevaluated, expected 13
```

Read on 0bebdaee7b63afd440151e05c12684ab9151765c. `Product` does the same.
Every element is a number: no variable is necessary.

Workaround: sum a `Map`,
`Sum(Map(k ↦ k^2, Sort([3, 2, 1])))`, which gives 14.

## Cause and options

Not investigated. The collection of an `Element` clause seems to be read as
written: a literal `List` and a `Range` are read, and a call that gives a
list when it is evaluated (`Sort`) or a lazy view (`Reverse`, `Take`) is
not. Option: evaluate the collection of the clause before the elements are
read, as the one-operand form `Sum(xs)` does (`reduceBigOp`,
`library/utils.ts`).
