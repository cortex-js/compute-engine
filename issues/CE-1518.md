Reading the type of one call in a cycle of three recursive functions first takes about half a minute.

## Witness

CE-1515's definitions (`a_2`, `b_2`, `c_2` declared `function`, an integer
base case): reading `b_2(m).type` first takes 23.5 to 31 s; every other
first read takes about 0.3 s. The same on 0caa86406 (before cbd971112), so
older than CE-1515.

Measured again on 3aac6f3bb052eadf3e94d8f258ea7ca85e7fe2f1 (2026-11-20):
`ce.box(['b_2', 'm']).type` takes 21.5 to 23 s when it is the first read
after the four assignments; the same read of `a_2` or `c_2` first takes
1 ms, and so does every later read. The type is `number` in each order.
The probe of that measurement (`/tmp/cebatch-1518/repro.ts`) no longer
exists; rebuild it from CE-1515's definitions before the next measurement.

## Cause

Cause: the cause of CE-1516, with the heads declared `function` (the
skeleton of `_wildcardRecursiveSignature`). The boxing of `b_2(m)` reads the
signature of `c_2`, and the derivation of `c_2` types its body. In that body,
each read of the signature of `a_2` (by `boundCallType`, `callResultType`,
`inferredPointSignature`, `argumentOutsideInferredSignature`, and the
effects read `literal.type` in `_wildcardRecursiveSignature`) types the
literal of `a_2` again. That typing derives `b_2`, which reads the
provisional signature of `c_2`. So the derivation of `b_2` is tainted
(`noteReentrantSignatureRead`) and is not memoized, and the next read
derives it again. Counts for the one slow read: 12 derivations of `c_2` at
the top, 3,264 of `b_2` inside them (3,264 tainted), and 12,288 of `a_2`
inside those. Leaving out the effects read alone makes it worse: the read did
not finish in 3.5 minutes.

The frame memo of CE-1516 (`signatureDerivedInFrame`,
`declared-parameter-result.ts`) is on main since 28b6409e72e01cbe701c905399d3b2c036f504a1.
It finds the cycle only after the fact, through a re-entrant read, and
limits the work done again. A check of the frame memo before `v.type` in
`_deriveSignatureOnce` would keep that design and its limit: a kept
signature can read a stack-dependent answer that changes later in the same
pass of the parent, and a later read gets the earlier result.

## Design to write

Derive the signatures of a cycle of calls as one group. The cycle is found
from the static call graph, so no derivation reads a provisional answer
from outside the group.

1. When the derivation of a function starts, find its strongly connected
   component in the graph of calls between function literals. Each call
   whose head is a name bound to a function literal is an edge.
   `cycleMembers`, `callsReach` and `calleeLiteral` in
   `declared-parameter-result.ts` already walk this graph for
   `verifiedListHypothesis`.
2. Derive the callees outside the component first, with the normal memo of
   the definition. They are not tainted.
3. Iterate on the component. Each member has a candidate result. Each round
   types every body, with a call of a member typed by that member's
   candidate (the mechanism of `_recursionResult` and
   `provisionalResults`), and joins the result into the candidate. Stop when
   no candidate changes. After a fixed number of rounds, use the declared
   result or `unknown`: a broader type, so the fallback is sound.
4. Store the signature of every member at once in its `_signatureMemo`.

Points for the plan:

- `verifiedListHypothesis` becomes the case where the seed candidate is a
  list. The plan says whether it can be removed.
- A result that nests one level deeper at each round (`m := n ↦ Map(x ↦
  If(x < 1, 0, m(x − 1)), [n])`) needs a widening rule. The round limit is
  the minimum.
- A function reached through a value, not through its name (`F(n) = G(F,
  n)` with `G` applying its argument), is not in the graph. Its reads keep
  the taint path of `noteReentrantSignatureRead`: correct, possibly slow.
- The frame memo of CE-1516 and the taint may then be removed, or kept only
  for the case above.
- The order of the first reads must not change a type: with the frame memo,
  `ce.box(['b_2', 'm']).type` read after `ce.box(['a_2', 'm']).type` is
  `any`, not `number` (CE-1516).

The witness of CE-1516's collection variant, and the test "a list base
clause derives a list" of `recursive-function-result-type.test.ts`, are
acceptance cases of the plan.

The other dispositions: (b) time tracking for each stack-dependent answer
(CE-1516 option (b), size L, on the hot paths of the type cache); (c) leave
it, with a first read of about 20 s and correct values and types.
