A step that adds samples to a picture could take 100 times more samples per frame on the GPU, but the engine cannot compile it for the GPU.

## Witness

Goal: Tycho's `buddhabrot` prelude function, unchanged
(`src/graph-paper/onboarding/template-data.js`):

```
function step(H: list<number>, n: integer)
  for k in 1..n: iterate (a, b) := (a² − b² + p, 2ab + q) up to 500 times,
  then L = replaceAt(L, c, L[c] + 1) for each cell c the orbit crosses
```

To `wgsl` on 0.182.0: "Could not compile `Apply`: the body of the function
has more than one statement"; a list-writing loop: "a matrix/tensor-valued
local has no GPU declaration".

A handwritten compute shader (one invocation per `k`, `atomicAdd`), Metal:

```
samples   GPU + read-back   JavaScript (handwritten)
5,000     0.5 ms            0.9 ms
500,000   0.9-1.1 ms        87.5-91 ms
```

f32 changes some escapes: counts differ by 2.9 % median per cell.

## Options

Writable storage list, `replaceAt` as a store, `atomicAdd` for a
cross-invocation increment, a compute entry point, an independence proof for
the outer loop. Study: Tycho `roadmap/BUDDHABROT_CODE_STUDY.md`
§ 7.
