A shader function whose parameter is named `input`, `output`, `sample` or `filter` is reported as compilable, but the compilation then fails.

## Witness

```ts
ce.declare('x', 'real');
ce.assign('rp', ce.box(['Function', ['Add', 'filter', 1], 'filter']));
canCompile(ce.box(['rp', 'x']), { to: 'glsl' }); // { ok: true }
compile(ce.box(['rp', 'x']), { to: 'glsl' });
// declines: "filter" is a reserved word in glsl and cannot be used as a
// variable name.
```

GLSL ES 3.00 reserves these names. With the parameter declared,
`['Typed', 'filter', "'real'"]`, both give success: the body is written at
the call site (`x + 1.0`), and the name is never written
(`compile-glsl-fragment.test.ts`, "a parameter with a name that GLSL reserves
is in when the call is inlined"). Measured at `c8bf12127` and with the CE-1177
change: the same result.

## Cause and options

The typing pass (`glslFunctionOf()` in `glsl-fragment.ts`) assumes that a
call of a function with a reserved parameter name is written in place
(`inlinedUserFunctionCall()`, key `h#inlined`). The emitter first tries the
copy of the function typed by the arguments
(`trySpecializedUserCall()`, `compile-user-functions.ts`, about line 1684),
which a parameter with no declared type takes for a `real` argument. The
`define` hook of that copy throws on the reserved name
(`gpuCheckIdentifier()`), and on GLSL the throw is not caught, so the call
never reaches the route that writes the body in place.

- (a) The emitter does not take the typed copy for a call that the pass
  wrote in place: it tries `tryInlineUserFunctionCall()` first when a
  parameter name is reserved on the target. Size S.
- (b) The pass refuses the call when the emitter would take the copy. This
  removes a form that works when the parameter is declared.

Option (a) is recommended. Renaming the parameter is a workaround.
