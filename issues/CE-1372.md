A plot of `0^x`, or of `x^n` with the slider `n` at 0, is given the value 1 at the point where zero is raised to the power zero, where the engine itself says there is no value there.

## Witness

At `d6e29c7e9`, with `x: real`, `y: real`, at machine precision:

```ts
const e = ce.box(['Power', 'y', 'x']);
e.subs({ x: 0, y: 0 }).N();                              // NaN
compile(e, { to: 'javascript' }).run({ x: 0, y: 0 });    // NaN, with or without profile: 'ir'
compile(e, { to: 'interval-js' }).run({
  x: { lo: 0, hi: 0 }, y: { lo: 0, hi: 0 } });           // { kind: 'interval', value: { lo: 1, hi: 1 } }
// the same with profile: 'ir'

const c = ce.box(['Less', 0, ['Add', ['Multiply', 'y', ['Power', 'y', ['Floor', 'x']]], 1]]);
c.subs({ x: 0.5, y: 0 }).N();                            // False
compile(c, { to: 'interval-js' }).run({
  x: { lo: 0.5, hi: 0.5 }, y: { lo: 0, hi: 0 } });       // 'true', with or without profile: 'ir'
```

`docs/COMPILATION-MODEL.md` ("For a form with no value (`0/0`, `0 · ∞`,
`0^0`, `Mod(x, 0)`) the interpreter answers `NaN` … and every compiled
target answers the IEEE `NaN`") gives the rule. Both interval targets
answer the point `[1, 1]`, and a comparison built on it is decided where
the interpreter decides the other way.

The witness is `plausible`: `0^x` is a common way to write "1 at `x = 0`,
else 0" in documents imported from Desmos, where `0^0` is 1; the corpus
document `neyret/mrbspdqeqo` holds powers of the base 0 with the plotted
variable as the exponent.

## Impact

A box that holds the point where base and exponent are both 0 gets an
interval, or a decided verdict, that the interpreter's value at that point
does not support. For a plot it is one point of a curve; for a comparison
(an inequality region, a condition of a piecewise function) the box is
decided `'true'` or `'false'` where the interpreter's answer at that point
differs.

## Cause and options

The kernel of the interval library: `powRaw(base, 0)` in
`src/compute-engine/interval/elementary.ts` returns 1 for every base, a
base that is or holds 0 included, and `powInterval` with a point integer
exponent goes to it. The JavaScript targets give `NaN` there.

Options:

1. The interval power answers no value at that point: `empty` for the
   point base `[0, 0]` with the point exponent 0, and for a base that
   holds 0 with an exponent that holds 0 the value over the rest of the
   box marked `partial` (the box is partly outside the domain). This
   follows the rule of the compilation model. It changes both interval
   targets, and Tycho's plots of documents that rely on `0^0 = 1` lose
   that point on the interval path, as they already do on the JavaScript
   path.
2. Leave the kernel, and record the difference as a known limitation of
   `interval-js`.
3. Change the rule: `0^0` is 1 in the engine, as in IEEE `pow` and in
   Desmos. That is a change of a documented contract (the user's decision
   of 2026-11-02 on forms with no value), for the board.

Not investigated: the other forms with no value on the interval targets
(`0/0`, `0 · ∞`, `Mod(x, 0)`), and what the host does with
such a point.

## Decision

User decision 2026-11-16: (1) for consistency between the interpreter, the JS and IntervalJS targets

User decision 2026-11-16: (2)

User decision 2026-11-16, after the new evidence below (to session ce-interval, in answer to the two forms of the question): "CE-1372: (a2)": the narrow form, option 2 of the question below: `empty` only when the whole box is the point; a box that holds the point and others keeps its `interval` kind.

## New evidence after the decision (2026-11-16, session ce-interval)

Option 1 is implemented and tested in a worktree (patch
`_TASKS/2026-11-15-interval-mode/b31.patch`, on main `412113c86`); it is
not landed, because it changes two behaviours that Tycho asked for and that
tests pin, and it marks as `partial` boxes that Tycho reads as a break.

What option 1 changes beyond the witness, on both interval targets:

- A box whose base holds 0 and whose exponent holds 0 is `partial` where it
  was `interval`: `[0, 2]^[0, 1]`, `[-1, 2]^0`, `[0, 0]^[0, 0.5]`
  (`partial [0, 0]`, was `interval [0, 1]`).
- A polynomial written as a sum from `k = 0`: `Sum(x^k, k = 0..3)` over
  `x = [-1, 1]` is `partial [-1, 4]`, was `interval [-1, 4]`. The
  interpreter gives `NaN` for that sum at `x = 0` (its term `x^0` is
  `0^0`), so the interval answer is consistent with it; a plot of a power
  series written this way gets a `partial` box at `x = 0`.
- `∫₀ˣ Σ_{k=0}^{4} t^k/k! dt`: the closed form is withheld (the scan of the
  integrand meets a `partial` at `t = 0`), and the result at `x = 0.15` is
  `partial [0.16179, 0.16188]`, was the point `0.161834…`.
- Tests named after Tycho's requests change:
  `tycho-item-260-interval-power-at-zero.test.ts` (`[0, 2]^[0, 1]` and
  `[0, 2]^[0, 3]` were `interval`; item 260 was "reporting `partial` made a
  smooth field read as discontinuous on every box, and a consumer that
  treats `partial` as a break saw one in every cell") and
  `tycho-row-417-interval-zero-base-power.test.ts` (`[0, 0]^[0, 0.5]`,
  `[0, 0]^[0, 0]`; row 417 was "a row with a slider at 0 drew nothing").
- Corpus (Tycho's dump, the sweep's boxes): 7 boxes change in 3 documents
  (`neyret/b2kz2ptcw2` #0 and #1, `b4fa9jsmsq` #3, `5a9mrz2bpu` #0), the
  same on both targets. The sweep draws few boxes that hold an exponent of
  exactly 0, so this count says little about what a plot meets.

The question for the board: which boxes are marked.

1. As decided, in full: `empty` at the point, `partial` for every box that
   holds the point. Consistent in kind with `sqrt` and `ln`. Tycho then
   sees a `partial` box at `x = 0` in every power series written from
   `k = 0`, and at a slider value of exactly 0 in an exponent; the two
   Tycho tests change as above.
2. Narrow (recommended by ce-interval): `empty` only when the whole box is
   the point (the point base 0 with the point exponent 0); a box that holds
   that point and others keeps its `interval` kind, since its enclosure
   holds every value the interpreter has in the box. The witness of this
   issue is fixed (the point is `empty`, the comparison at the point is
   `'false'`); Tycho's two tests keep their expectations except at the
   exact point `[0, 0]^[0, 0]`; a verdict decided over a box that holds the
   point can still differ from the interpreter at that one point.
