The interpreter evaluates a list expression again at each index when a `Filter` or `Map` lambda reads one element of it, so one row of a Desmos document takes 5 times longer.

## Witness

Corpus state `art/khpocp8io0` (a Gomoku document), CE 0.192.0, interpreter
(`evaluate()`), Tycho's document evaluation pass. Row
`W_howin = join(C_heckH[|C_heckH|>0], C_heckV[…], C_heckD1[…], C_heckD2[…])`.
Each `C_heckX` is a `Comprehension` of 121 to 165 elements, for example
`Comprehension(Which(Equal(Abs(Sum(At(P_iecepos, ListJoin(List(m+n), Range(m+n+15, m+n+60))))),5), At(P_iecepos, m+n), True, 0), m∈Range(0,150,15), n∈Range(1,15))`.

Before (one whole-list read):

```json
["ListJoin", ["At", "C_heckH", ["Less", 0, ["Abs", "C_heckH"]]], "…×4"]
```

After (Tycho's rewrite of the Desmos mask):

```json
["ListJoin",
  ["Map", ["Function", ["Block", ["At", "C_heckH", "_tycho_i"]], "_tycho_i"],
    ["Filter",
      ["Range", 1, ["Min", ["Length", "C_heckH"], ["Length", ["Abs", "C_heckH"]]], 1],
      ["Function", ["Block", ["Less", 0, ["At", ["Abs", "C_heckH"], "_tycho_i"]]], "_tycho_i"]]],
  "…×4"]
```

Measured (warm passes, both arms on 0.192.0; the only difference is the form):

| | before | after |
| --- | --- | --- |
| `evaluate()` of the row | 86 ms | 432 ms |
| element-body evaluations of the comprehensions | 572 | 1,336 |
| time per element body | 0.14 ms | 0.37 ms |
| `At(Abs(C_heckX), i)` | none | 572 calls, 583 ms |

`Abs(C)` and `C` are evaluated again inside the lambdas at each index, and the
elements of the lazy comprehension are not kept across these reads. Part of
the per-element cost (about 0.07 ms of 0.34 ms) is Tycho's own
`Map(k ↦ Max(k, 0), idx)` around index lists; Tycho will remove it where the
index cannot be negative.

The instrument loads the document, boxes the row in both forms in the same
engine (the whole-list form with Tycho's rewrite switched off for that box),
evaluates each with the comprehension memos dropped, and prints NOT READY on
0.192.0: the Map/Filter form costs 2.9× and 3.1× the whole-list form in two
runs (READY at 1.5× or less). Its absolute times vary between runs; the ratio
is the signal.

**Instrument on hold (2026-11-16).** Tycho backed out the rewrite that emits
the Map/Filter form (Tycho row MK, `roadmap/MK_DESMOS_LIST_REWRITE.md`). Until
the rewrite returns, the instrument boxes the same form on both sides and can
print READY falsely; do not read its result as an answer. The request stands
for when row MK resumes.

**Second witness (tycho-18, 2026-11-16; states `art/nxlddeh5zv`,
`art/2ki2hjsouf`, `art/s8ishknvhe`, which hang with row MK).** The selection
over lists of CE-1343's answer, `Map(j ↦ Which(At(c, j), At(v, j), True, NaN),
Range(1, Min(Length(c), Length(v)), 1))` with `c` and `v` whole-list
expressions, evaluates `c` and `v` again at each `j`: the time grows with the
square of the length. Tycho: a gate `Which(2 < PointZ(A), 0, True, 1)` in this
form over 1,000, 2,000, 4,000 and 8,000 points takes 0.4, 1.1, 3.9 and 14.4 s
(1.55 GB), against 23 to 55 ms for CE's `Which`. Reproduced by CE, see the CE
answer.

## Request

When a `Filter` or `Map` lambda reads `At(E, i)` with `E` free of the lambda's
parameter, evaluate `E` once per evaluation of the `Filter`/`Map`. Or name the
form that a host writes to bind it once (ce-compiler suggests
`Filter(C, k ↦ 0 < Abs(k))` for an element-wise mask, or
`Block(Declare(L, 'list<real>', ListFrom(C)), …)`; not yet measured).

## CE answer

CE (`ce-compiler`, 2026-11-16): the recorded priority is P1 (board,
2026-11-16). CE proposes P3 at the next review: a slow case with a
workaround, in a form that Tycho no longer emits (flag `workaround` added).
Disposition: backlog; the form that binds each list once exists and is
measured below, and the engine change is option (b).

Reproduced on the working tree of main at
`3b0b23f414e90ada33e633cb641cd9a8fb3c8ef6`, each form inside `ListFrom(…)`,
in ms. With an operator that counts its evaluations around `v`, the row MK
form evaluates it 21, 41 and 81 times for 11, 21 and 41 elements; the other
forms evaluate it twice.

```ts
// numeric: A = Join(Range(1, n), [1]); c = 2 < At(A, A); v = At(A, A)
const mk = ['Map', ['Function', ['Which', ['At', c, 'j'], ['At', v, 'j'], 'True', 'NaN'], 'j'],
  ['Range', 1, ['Min', ['Length', c], ['Length', v]], 1]];
const apply = ['Apply', ['Function', /* mk with l1, l2 */, 'l1', 'l2'], c, v];
const sources = ['Map', ['Function', ['Which', 'cj', 'vj', 'True', 'NaN'], 'cj', 'vj'], c, v];
const stock = ['Which', c, v, 'True', 'NaN'];
// gate: A a list of n points; c = 2 < PointZ(A); the value 0, the default 1
```

| | row MK form | lists bound with `Apply` | lists as sources of the `Map` | CE's `Which` |
| --- | --- | --- | --- | --- |
| numeric, `n` = 400 | 240 | 83 | 5.7 | 3.9 |
| numeric, `n` = 800 | 507 | 196 | 9.8 | 5.6 |
| numeric, `n` = 1,600 | 1,351 | 653 | 15 | 9.6 |
| numeric, `n` = 3,200 | 4,691 | 2,040 | 30 | 17 |
| gate, `n` = 1,000 | 733 | 117 | 13 | 8.9 |
| gate, `n` = 2,000 | 2,441 | 275 | 30 | 19 |
| gate, `n` = 4,000 | 9,039 | 583 | 44 | 27 |

The four forms give the same list. Times vary by up to 40% between runs on
the shared machine; the growth is the signal. Tycho's numbers for
`n` = 100, 200 and 400 (215, 468, 1,568 ms) are 3 to 6 times the ones
measured here (84, 131 and 240 to 390 ms); the cell declarations differ.

**Contract.** The source slots of a lazy operator are evaluated once per
evaluation (`docs/COLLECTIONS-MODEL.md`, "Lazy collections"). The body of the
callback is a function body: it is evaluated at each element, and a name it
reads is read when the element is computed (`docs/SCOPING-MODEL.md`,
"Callable resolution"). Nothing moves an expression that does not depend on
the parameter out of the body (`mapIteratorImpl()` and `mapAtCell()` in
`library/collections.ts` call `applicable(expr.op1)` per element). So the
behaviour is as documented, and the cost is real.

**Workaround, on 0.192.0.** Write each list as a source and keep only
scalars in the callback:

- a mask that is a function of the element: `Filter(C, k ↦ 0 < Abs(k))`. On
  a computed list of 165, 330 and 660 elements (a comprehension as
  `C_heckH`): whole-list form 107, 72, 128 ms; row MK form 331, 526, 742 ms;
  this form 71, 81, 174 ms; same values.
- a selection over several lists: `Map((cj, vj) ↦ Which(cj, vj, True, NaN),
  c, v)`, the third column above, 1.5 to 2 times CE's `Which`, cut to the
  shortest source. The measured variants, their limits (a comparison of two
  lists of different lengths goes inside the callback) and what compiles are
  in CE-1365.
- `Apply(Function(…), c, v)` binds once but stays slow (second column), and
  its value is a `Map` that holds a copy of each list (CE-1365). Binding
  `ListFrom(c)` is slower still for booleans and points (CE-1369).

**Options for the engine.**

- (a) No change; the hosts write the sources form.
- (b) Before a walk of a `Map`, `Filter` or other callback view, evaluate
  once each largest sub-expression of the callback body that is pure and
  names no parameter and no local that the body assigns, and walk with the
  values. Within one walk of a pure callback the state cannot change, so the
  values are the same. A single `at()` read is not a walk and gains nothing.
  Size M.
- (c) Keep the value of a pure closed sub-expression across reads, dropped
  when a name it reads changes, as the element memos are. Covers `at()`.
  Size L.

CE (`cebatch-1358`, 2026-11-17): fix with option (b) done, not committed yet
(see "State of the work"). In one walk of a `Map` or `Filter` (also the lowered `Map`
chain), a pure sub-expression of a pure callback body that reads no name
bound in the callback and no parameter or local of an enclosing call is
evaluated once, when its value is a collection; a write between two elements
discards the values. The row MK form over the numeric lists: 241, 1,346 and
4,601 ms for `n` = 400, 1,600 and 3,200 before, 55, 66 and 91 ms after. The
mask form `Map(i ↦ At(C, i), Filter(Range(…), i ↦ 0 < At(Abs(C), i)))` over
a comprehension: 167, 416 and 768 ms before, 78, 163 and 277 ms after (the
whole-list form: 7, 15 and 28 ms). A read by position (`at()`) gains
nothing. Tycho: verify with the instrument when row MK resumes, then delete
this file. Found while measuring: CE-1425 (`Which` with a value clause that
reads a list by position grows with the square of the length; `If` does
not).
