A grid variable updated from its own cells, such as one step of the Game of Life written inline, holds a value that refers to itself, so reading it gives NaN or a recursion error.

## Witness

At 686d014e42487bae32d36fba9635e056fb0aeab5, in Epsil:

```
let n = 3
let g = map(i => map(j => Mod(i + j, 2), Range(1, n)), Range(1, n))
let tick = (t: real) => do { g = map(i => map(j => 1 - g[i][j], Range(1, n)), Range(1, n)) }
```

After one evaluation of `tick(16)`, `g` holds
`[Map(j ↦ 1 - g[1][j], Range(1, n)), Map(j ↦ 1 - g[2][j], …), …]`: the inner
`Map`s are kept lazily and read `g`, which is now this list. Reading the
elements of `g` throws "Recursion limit exceeded"; with
`count(g, i, j) * 0.5` in place of `1 - g[i][j]` every element is NaN. The
expected value is `[[1, 0, 1], [0, 1, 0], [1, 0, 1]]`, which the compiled
function gives (CE-1721). The same update through a function,
`step(g: list) = map(i => map(j => 1 - g[i][j], …), …)` and `g = step(g)`,
gives the expected value in the interpreter.

## Cause and options

Not investigated. The decision of 2026-09-30 (see CE-1245) says that a stored
collection keeps the variables that it reads at the assignment; the inner
lazy `Map` of a list of lists keeps a reference to the variable that it is
assigned to. Option: when a collection is stored in a variable, evaluate the
inner lazy collections that read that variable, or substitute its value in
them, as is done for the outer collection.
