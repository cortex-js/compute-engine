A Document row whose parameter type is misspelled either stops the whole document from loading or loads with the type left out, with no message on the row.

## Witness

At `07d4d5090ef7d5f5f5971b146da21838c5def776`, a row given as `bodyJson`:

```js
const ce = new ComputeEngine();
const imports = createDocumentEnvironment(ce, () => {}).createImports(() => {});
const syntax = {
  split: () => ({ head: 'g', body: '' }),
  recognize: () => ({ role: 'function', head: { name: 'g', params: ['q'] }, bodyJson: 1 }),
  normalize: (raw) => raw,
};
imports.prepare([{ id: 'g', latex: 'g', formalTypes: { q: 'Nope' } }], syntax);
// prepared, rowErrors is empty: `q` is read as `unknown`
imports.prepare([{ id: 'g', latex: 'g', formalTypes: { q: 'Nope' }, resultType: 'real' }], syntax);
// throws: Failed to parse type "(Nope) any -> real"
```

The same holds for `tuple<`. After the CE-1658 fix, a row whose LaTeX body
CE reads gives the row error `invalid-type-annotation` for the same
`formalTypes`. The Document contract
says that `prepare` throws only for host contract violations and
cancellation.

## Cause and options

`formals()` in `src/compute-engine/document-preparation/prepare-document.ts`
writes the stated type into `['Typed', q, "'Nope'"]`, and boxing a `Typed`
with a type that does not parse gives `unknown` with no error
(`ce.box(['Function', 'q', ['Typed', 'q', "'Nope'"]])` is valid, type
`(unknown) -> unknown`). The typed-row contract builds the signature string
from `formalTypes` and `resultType` and calls `ce.type(signature)`, which
throws.

Fix: parse each `formalTypes`, `resultType` and `valueType` entry of a row
once with `ce.type` before the row is read, and give the row the error that
`formalTypes()` of `prepare-document.ts` gives a LaTeX row
(`signatureStringError`) when one does not parse, on every path.
Workaround: the host checks its type strings with `ce.type()` first.
