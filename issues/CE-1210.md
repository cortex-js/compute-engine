With binding units on, symbolic work on expressions whose symbols are not declared is slower: parsing and simplifying by about 1.3 times, loading the integration rules by about 1.7 times.

## Witness

```
const ce = new ComputeEngine();
for (let i = 0; i < 2000; i++) ce.parse('a x^2 + b x + c').simplify();
```

Measured 2026-11-11 under the box lock, one worker, at
`950f70f962bbf39e14786091dca564835e5a4dc1` plus the constant-factor changes
of the commit that files this issue (units off / units on):

| Case | Off | On |
|---|---|---|
| parse-and-simplify loop of ten expressions, 2,000 rounds | 3.0 to 3.3 s | 4.0 s |
| `integration-rules.test.ts` | 8.5 s | 15 to 16 s |
| `rubi-utils.test.ts` | 6.1 s | 10.5 to 13 s |
| `integration-rules-substitutions.test.ts` | 13.5 s | 22 to 23 s |
| `ce-882-shared-copies.test.ts` (CE-1200) | 5.7 s | 27 to 30 s |

With the symbols declared (`ce.declare('x', 'real')` for each), the loop
takes the same time with units on and off within 5 to 9% (CPU time, 3,000
rounds: 443 to 450 ms off, 477 to 483 ms on). A host that declares its
symbols does not see the slowdown.

Tycho's codegen audit (115 documents, Tycho `000255f66`, a scratch build
of `8868a2aba`, one run for each arm): no changed code and no new decline
with units on; the sum of the document times is 41.0 s off and 52.5 s on
(1.28 times; median 1.16 for the 41 documents of 100 ms or more).

## Cause and options

A free name has no definition. Each read of its type finds the entry of its
unit and resolves the name in the current scope
(`BoxedSymbol._unitType()`, `boxed-expression/boxed-symbol.ts`); the loop
above reads a symbol type 3.4 million times. The cached type of a compound
expression records three reads for each free name under it (the entry, the
variable record, the resolution; `binding-unit.ts`), and each hit of the
cache computes the three versions again and merges them into the caches that
are being computed (`objectDepsValid()`, `mergeObjectDeps()`,
`boxed-expression/object-deps.ts`). Without binding units a hit compares one
number (`ce._typeCacheGeneration()`).

With the three versions made free (an unsound experiment), rule loading
goes from 1.70 to 1.47 times the time with units off.

Options:

1. One engine-wide counter that moves at every change that the type of a
   free name can depend on: a write in a unit environment, the start and the
   end of an operation or a trial, a change of the current scope, a write of
   a binding of a scope (about 60 sites), a change of a scope's parent, a
   change of the static view. A cached type is then valid with one comparison. A
   missed site gives a stale type.
2. One recorded read for each free name in place of three, with a version
   that combines the three results. It divides the walk at each hit by
   three and leaves the computation of the versions.
3. Leave it: document that a host declares the symbols of expressions that
   it processes in a loop.
