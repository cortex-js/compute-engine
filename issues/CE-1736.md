A compiled function that builds a list of lists of varying length inside the program declines.

## Witness

From the decline census on GitHub #638: 234 items of a combinatorics corpus
(201 statistics, 12 family operations, 21 maps). The census gives this
program as the repro, with the message "a list of lists of run-time length":

```
Map(i ↦ Map(j ↦ i + j, Range(1, n)), Range(1, n))     n: integer
```

Also a `Map` or `Filter` whose value for each element is a list, and a step
function applied twice (`step(step(g))`) to a `list<list<integer>>`.
`fallback: true` gives the interpreter's value (the workaround).

## Cause and options

The `rows` lane reads a host's array of arrays in place, but no lowering
builds one: the result of an inner `Map` of run-time length has no carrier.
This needs a design of how a program allocates and fills rows (an array of
arrays, or one flat buffer with offsets), which consumers read it, and how it
crosses a `Loop`, `Reduce` or `Fold` boundary. The census on #638 gives the
forms that matter most.
