A compiled function that builds a list of lists of varying length inside the program declines.

## Witness

From the decline census on GitHub #638: 234 items of a combinatorics corpus
(201 statistics, 12 family operations, 21 maps). The census gives this
program as the repro, with the message "a list of lists of run-time length":

```
Map(i ↦ Map(j ↦ i + j, Range(1, n)), Range(1, n))     n: integer
```

Also a `Map` or `Filter` whose value for each element is a list, a step
function applied twice (`step(step(g))`) to a `list<list<integer>>`, a list
literal whose elements are lists of different lengths
(`List(Map(i ↦ i + 1, P), List(Length(P)))`, "elements of two types"), and
a `Fold` that joins rows to an accumulator (CE-1735).
`fallback: true` gives the interpreter's value (the workaround).

## Cause and options

The `rows` lane reads a host's array of arrays in place, but no lowering
builds one: the result of an inner `Map` of run-time length has no carrier.
The readers of the lane (`rows.count`, `rows.len`, `rows.get`, `rows.at`,
`rows.row`, the region `rows.flat`) take an SSA value, but `symbol()`,
`rowsLaneOf()` and `wholeRows()` of `lower.ts` admit only an input or a
parameter.

## Decision

User decision 2026-11-25: the design below is approved.

- **Carrier.** Every list of lists whose inner length is not a constant is a
  value of the lane `rows`: on JavaScript an array of arrays, the
  representation of a host input. A new region (`rows.build`,
  `rows.build.int`) makes it from a count and a body that gives a flat list of
  run-time length. A constant inner length keeps today's rank-2 list. Rejected:
  one flat buffer with offsets (a second set of readers), a ragged shape in
  `IRType` (core cost), fusion only (does not serve the result or a loop
  carry).
- **Readers.** The existing readers read a `rows` value whatever made it: the
  gate depends on the value, not on the name.
- **Elements.** Integers and reals only. Booleans, points and complex numbers
  decline. GLSL, the interval mode and the `bigint` mode decline the lane, as
  today.
- **Loops.** A `rows` value is one carried value of a `Loop`, a `Reduce` or a
  `Fold`.
- **Matrix operators.** No run-time validation and no change to "Caveats of
  compiled code". A built table whose inner length does not depend on the
  outer index records "every row has this length" in a side table of the
  lowering. `Transpose` and `MatrixMultiply` read that fact, and `order()`
  accepts a table whose count and row length are the same value. Where the
  fact is lost (an `If` join, a loop carry, a function boundary) the operator
  declines. A `list<list<real>>` input to a matrix operator keeps declining:
  its type admits rows of different lengths. `Determinant` and `Inverse` of a
  run-time order stay declined.

Steps, each a change of its own:

1. The gate by value, and `Map` and `Filter` whose value for an element is a
   list of run-time length (also as the body of a user function).
2. The loop carry, and `step(step(g))`.
3. `Join(a, [row])` in a `Fold` from `List()`, and a `List` literal of rows of
   run-time length.
4. The row-length fact, `Transpose` and `MatrixMultiply` of a built table.
