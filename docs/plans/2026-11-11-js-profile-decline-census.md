# Census: what the `numeric-kernel` profile still declines

Read-only census of the compilations that the existing JavaScript compiler compiles and the `numeric-kernel` profile declines, by first refusal, with a next-refusal measure. Nothing in the repository was edited.

## Method

- **Source.** Main tree `/Users/arno/dev/compute-engine`, commit `d9b93a4199035ea00130ed1b85875ff307c4b426` (0.187.1). The brief named `114403d0b44156730f1f943b12362d0c74f90fc8`. Between the two, six commits landed during my first run, and they change the structured route: `javascript-fragment-target.ts`, `javascript-structured-*.ts`, `structured-ir.ts`, `structured-verify.ts`, plus CE-1213 in `binding-unit.ts`. I discarded that mixed run and ran again at `d9b93a419`, with a clean `src` at the start. A peer session then edited files of `src` while batches 04 to 08 ran (`binding-unit.ts`, `boxed-symbol.ts`, `diophantine.ts`, `engine-infer.ts`, `epsil/signature-notes.ts`); no compilation file was among them. The two runs gave the same totals (9,777 declines, 18,883 admissions).
- **Logger.** A Jest setup file in the scratchpad, `log-setup.ts`, passed on the command line with `--setupFilesAfterEnv test/jest-config.ts <scratchpad>/log-setup.ts`. It wraps `compile()` of `src/compute-engine/compilation/compile-expression`. For each JavaScript compilation (no `profile`, no `target`, `to` is `javascript` or absent) that the existing compiler compiles, it compiles again with `{ ...options, profile: 'numeric-kernel', fallback: false }`. It logs each decline: MathJSON, options, the type, value and kind of each free symbol, the signature of each user operator, the message, the test file and test name, and the existing code. There is one JSONL file per worker. A compilation that starts inside another one is not measured: it has its own guard, like the shadow measure.
- **Test files.** The 844 files under `test/` that contain `compile` or `Compile`, in 9 batches of at most 95 files, each run as `timeout -k 30 900 npx jest -w 4 …`.
- **Test failures** come from the census itself, not from the engine. The stand-ins declare fresh symbols, so `compile-broadcast-engine-unchanged` fails 2 tests. The extra profile calls are seen by a spy in `compile-javascript-profile.test.ts` (1 test). `compile-call-broadcast-result-operand.test.ts` ran out of memory in both runs; only its first 22 declines are logged.
- **Classification** is by the first refusal (`cls.py`, adapted from the first census's `classify.py`). The excluded classes have notes of their own and are counted, not broken down: colours, strings, points (and tuple values), records, absence operators, `Integrate`/`D`/`Limit`.
- **Normalized message.** The message with its names and sub-expressions replaced by `<n>`, `<e>`, `<f>` and `<p>` (`norm.py`). An `unsupported binding` row also gives whether the symbol has a value (a captured value) or not (an input), and its type.
- **Witness.** By file name only. *Real-use* is a test whose name says that it mirrors a user or Tycho document: `tycho`, `item-N`, `items-N`, `row-N`, `issue-N`, `62urmx2dcm`, `compile-e2e`, `census-head`, or a test under `epsil/`. *Operator edge* means that every witness is in another test file. *Fuzz* counts `js-profile-fuzz` and `structured-fuzz`. I did not read each test to confirm this rule.
- **Next refusal.** In the same engine and scope, the logger replaces the refused form by a stand-in that the profile admits (`standins.js`) and asks the profile again, up to 8 times. The stand-ins are:
  - a root-function parameter typed `any`, `collection<…>`, `indexed_collection<…>` or `broadcastable<…>` is retyped `real` or `list<real>`;
  - an input or parameter of `list<number>`, `vector<n>`, `list<complex>`, `list<unknown>`, `list<any>` or `list<expression>` is renamed to a fresh symbol declared `list<real>`;
  - for a refusal about a complex or `number` value, every input of type `number`/`complex` (or a list of them) is declared real, otherwise `mode: 'complex'` becomes `strict`;
  - a captured binding is replaced by its value, written in place;
  - a node that reads no input is replaced by its `N()` value;
  - an `If`/`Which` with a constant condition is replaced by the branch it selects;
  - `ParallelLoop` becomes `Loop`;
  - `Mod(x, 1)` becomes `x - Floor(x)`;
  - `Declare(x, T, v)` becomes `Declare(x, 'real', v)`;
  - `At(M, i, j)` becomes `At(At(M, i), j)`.

  A stand-in does not keep the meaning of every program. It measures how many programs are blocked *only* by the refused form.
- **Scripts and logs**: `/private/tmp/claude-501/-Users-arno-dev-compute-engine/8bcfeb12-d329-4bad-8e72-141c448e7087/scratchpad/census2/`. They are `log-setup.ts`, `standins.js`, `run.sh`, `cls.py`, `norm.py`, `gen.py`, `analyze.py` and `shapes.py`, with the logs in `logs/` (the discarded mixed run is in `logs-old/`).

## 5. What could not be determined

- **The gain of the unmeasured items** (1, 3, 4, 7, 10, 11, 12). There is no stand-in that keeps a nested list, a matrix function, a union input, a user operator or a helper capture, so their next refusals are unknown. The 40–65% range is borrowed from the measured rows.
- **Whether a witness is real use.** This is judged by the file name only. The rule counts `epsil/` tests and `item-N` files as real use; some of them may be tests of one operator. I did not read the tests.
- **The overlap between items.** A program counts once, under its first refusal, but its later refusals can belong to other items. The chain counts only the stand-ins that exist, so an item's measured gain assumes that the items before it in the chain are done.
- **The meaning of the `complex` → `strict` and `number` → real stand-ins.** They admit a program by changing what it computes. Their counts say that the complex lane is the only blocker, not that the result would be equal.
- **`compile-call-broadcast-result-operand.test.ts`** ran out of memory under the logger in both runs; its declines after the first 22 are missing.
- **Compilations started inside another compilation** (an `implicitCompile` from inside `compile`) are not logged. The first census's shadow hook had the same limit.
- **The difference from the shadow measure** (20,959 of 31,049 at `4c0828dff`): this census covers only the 844 test files that name `compile`, with its own consumer filter. Its 28,660 and 18,883 are not the same population.
- **Lists of tuples** are counted at `d9b93a419`, which holds the slices of `114403d0b`; work under review that is not in that commit is not seen.
