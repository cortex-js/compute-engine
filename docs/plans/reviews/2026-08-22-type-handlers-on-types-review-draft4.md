# Spec review — docs/plans/2026-08-22-type-handlers-on-types.md (fourth draft)

Dual review (Claude on Sonnet + Codex at high), 2026-08-22. Focus: ready to
implement? The third draft's 18 findings were all addressed; this pass
judged the fourth draft on its own terms.

**18 findings — 1 critical, 12 high, 5 medium · 2 flagged by both reviewers · 1 open question (R4 re-ratification)**

1. [CRITICAL] [Codex] [consistency] §4.5 "Every derived type … is checked"; §5.1 "the result passes … the ceiling" — **The signature ceiling, applied after broadcast shaping, erases every broadcast result.** `list<number>` from `Sin` over a list fails the `(number) -> number` ceiling and falls back to scalar `number`, contradicting the one-lift rule in `docs/COLLECTIONS-MODEL.md`; and a literal-result signature such as `(0) -> 0` would restore a literal the widener removed. → Apply the ceiling to the per-element result *before* broadcast shaping, then lift result and ceiling through the same transform; state whether literal results in declared signatures survive widening, with a `fib(0)` test.

2. [HIGH] [Both] [completeness/feasibility] §4.3 "total transformer over the Type AST" — **Not exhaustive and not cycle-correct.** The list names a `map` kind that does not exist in `src/common/type/types.ts` and omits `negation` (which can wrap a numeric value node), `symbol` and `expression`. Returning an already-visited *old* node by identity breaks a rebuilt cyclic graph: a recursive record containing a numeric value gets a new root whose back-edge points at the old root, leaving the literal reachable. → An exhaustive `switch` over `Type['kind']` with a compile-time `never` case; an old→new memoized graph rewrite that preserves back-edges (or an explicit opaque boundary for recursive types); tests for a cyclic type with a value node before and after the cycle.

3. [HIGH] [Both] [question/feasibility] §4.2, §6 R4 "needs re-confirmation" — **R4 is an unratified blocking decision, and its termination property is asserted, not measured.** The pure live read removes the once-per-generation gate that also served as a re-entrancy guard for mutually dependent inferred symbols; the replacement (`cachedValue`'s in-flight window on the expression memo) is keyed on expression identity across two definitions and is "not pinned today". The R-D5 display projection's dependence on `BoxedType` identity is unverified. → Re-ratify R4 as the pure live read; promote the mutual-recursion/depth-8 termination pins, the zero-mask staleness pin and the R-D5 identity check to prerequisites of §4.2, not follow-ups.

4. [HIGH] [Codex] [consistency] §5.1 "`{ type, facts: {} }` per operand"; "unknown participation treated as possibly a collection" — **Synthetic descriptors violate the facts contract and discard type-provable facts.** `isValid` is required, so `{facts:{}}` is invalid; and an empty facts object throws away what the type proves (`finite_integer` is finite and scalar), so a nested `context.derive('Add', …)` over finite integers could become `broadcastable<…>` and lose finiteness — defeating the `Map` derivation the primitive exists for. → One descriptor-normalization constructor for real and synthetic operands that derives finiteness and definite scalar/collection status from the type and leaves only genuinely undecidable facets `undefined`; an explicit fallback per derivation step rather than one rule for every absent fact.

5. [HIGH] [Codex] [completeness] §5.1 `collection?: { finite: boolean; indexed: boolean; … }` — **Collection facts cannot express the tri-states steps 14–16 distinguish** (definitely scalar / possibly collection / known collection with unknown finiteness or indexedness). → Independent `boolean | undefined` facets, or a `scalar | collection | unknown` discriminant with tri-state facets; cases for symbolic-length `Range`, unbounded collections, fixed-shape lists, definite scalars, top-typed applications.

6. [HIGH] [Codex] [consistency] §5.1 `facts.concrete`; §5.3 "only 0/1 carry a value"; §4.4 literal admission — **The concrete-value channel contradicts the 0/1-only handler contract.** Admission and value-arm overload resolution need every literal's value (`1.5` must refute `integer`), but handlers see the whole descriptor, so populating it for admission restores every value-reading path R2 removed; withholding it breaks admission. → Separate primitive-private admission data from handler-visible facts; state exactly which literal forms populate each.

7. [HIGH] [Codex] [architecture-fit] §5.1 `OperandStructure`; §5.4 — **The structure vocabulary does not cover the handlers that read structure today**: `Hold` (symbol vs string vs number vs application), `ReleaseHold` (a `Hold` child), `Typed` (a raw type-name string or symbol), `Subscript` (string / ring constant / symbol name / indexed forms) in `library/core.ts`; `Pipe` needs to tell an authored parameter annotation from a derived signature, which `parameters: readonly string[]` discards. → Audit every flipped handler for structural reads; define an inert, exhaustive vocabulary (symbol name, application head and required children, parameters with authored annotations) with a compile-time exhaustiveness check.

8. [HIGH] [Codex] [feasibility] §4.4 "a lazy handler's own operand handling runs first, and the check applies to what the handler evaluates" — **Infeasible as a generic post-handler check**: the dispatcher cannot observe which held operands a lazy handler evaluated, short-circuited, transformed or acted on before returning. → An explicit lazy-runtime protocol (handlers request evaluation through a checked callback, or return evaluated operands before the body runs, or keep mandatory per-handler checks); state whether conformance must precede any handler effect; lazy short-circuit and effect-order tests.

9. [HIGH] [Codex] [architecture-fit] §4.4 "the selected arm's instantiated parameter types (overloads and generics resolved by then)" — **Runtime arm selection is undefined and conflicts with the type-system model.** Who reselects when static selection was blocked or evaluation changed an operand; what "conform" means for value components, arrows, collections, still-symbolic values; `docs/TYPE-SYSTEM.md` names `MatchesType` as the single runtime-membership primitive and requires `no-matching-clause` for an undecidable multi-clause call, where §4.4 universally prescribes `incompatible-type`. → A runtime resolution algorithm over evaluated operands reusing `MatchesType`/value membership, preserving `no-matching-clause`; the verdict and error for every parameter kind, including no arm, ambiguous arm, generic solve failure, arrow slot, still-symbolic operand.

10. [HIGH] [Claude] [completeness] §4.4 insertion point "value-definition function application (`apply()`)" — **That check is gated on `ce.strict` today** (`function-utils.ts` ~2808, ~2957; `strict` defaults true). Under R1 a non-strict engine would admit a provably wrong operand at boxing (overlap) *and* never check it at evaluation — silent acceptance. → State whether the runtime check stays gated on `strict` (and whether R1's relaxed static admission is then also conditional on `strict`) or becomes unconditional, with the non-strict cost; add `strict: true/false` as a route-parity axis.

11. [HIGH] [Codex] [consistency] §5.1 "`Set` comprehension: the domain's element type widened" — **Unsound**: a comprehension's elements have the *body's* type (`{String(k) | k ∈ Integers}` has string elements), so a widening of the domain element type is not a supertype of the result. → Derive the body type with the bound variable replaced by a descriptor of the domain element type (as for `Map`), falling back to `unknown` when the substitution is unsupported; body-changes-type, filtered, empty, unknown-domain, nested tests.

12. [HIGH] [Codex] [feasibility] §5.1 `body: Expression`; §5.2 `PureEngineView` definition lookup; §5.5 — **The capability boundary still exposes live expressions and definitions**, and through them `.canonical`, `.evaluate()`, `.N()`, the engine and construction; the test/dev guard only detects a mutation after the fact and does not cover production user handlers. → Inert structural data and read-only definition facades instead of live objects; if user handlers must satisfy the invariant, enforce the guard in production or run handlers under a rollback/capability boundary; otherwise narrow the §1 invariant to built-ins and say so.

13. [HIGH] [Codex] [completeness] §5.3 step 4 — **The seven rewrites are outcomes, not contracts**: `JacobianMatrix`'s result when the operand type cannot decide system vs gradient, `Sqrt`'s answers once closed numeric sign is gone, `Pipe`'s literal-only and authored-annotation exceptions — each left to the implementer, and each decides whether the 57-row baseline shrinks or grows. → A per-offender table: descriptor fields consumed, derivation algorithm, conservative fallback type, evaluation moved or retained, expected changed test rows.

14. [MEDIUM] [Claude] [architecture-fit] §4.4 "the existing collection-kind deferral (`overlapsForDeferredValidation`) is one case of this" — **Not true of the code**: it never calls `typesOverlap`; the two have different semantics (same-head collections with disjoint elements: non-overlapping for `typesOverlap`, admitted by the deferral), and the draft does not say which governs a collection-kind classic parameter once both exist. → State the dispatch rule: `typesOverlap` supersedes the deferral for collection kinds too (noting the semantic change), or is scoped to non-collection parameters with the deferral unchanged.

15. [MEDIUM] [Claude] [consistency] §4.1 (R7) vs §5.1/§4.5 — **The accepted `Dot` rewrite bypasses the primitive and the ceiling the draft calls universal**: `componentProductType` calls `Multiply`'s raw handler directly, skipping normalization, overload resolution, instantiation, absorption, broadcast shaping and the §4.5 check. → State it as the deliberate, narrow exception it is (`Multiply` has one non-overloaded, non-generic handler, so the skipped steps are no-ops for this callee — and it is the prototype of `context.derive`), or route it through the primitive once that exists, with the ceiling applied to the product before the sum.

16. [MEDIUM] [Codex] [testability] §5.5 parity harness — **Does not exercise the synthetic-descriptor path**, the one most dependent on the absent-fact rules, and an operator with no corpus passes vacuously. → Require a non-empty corpus per flipped handler; a second parity matrix with type-only descriptors and each optional fact absent; nested `context.derive`, `Map` body substitution, top types, finite scalars, value arms, definite/possible collections.

17. [MEDIUM] [Codex] [consistency] §5.3 steps 2 and 6 — **The compatibility release is self-contradictory**: step 6 removes the old shape *and* keeps it one release for user definitions; step 2 leaves `ce.declare` on the old shape; no public flag, deprecation diagnostic, or invariant boundary for old user handlers. → Define the flag/API, release sequence and diagnostics; keep the dual dispatcher for the compatibility release and remove it the release after, once old user callbacks are rejected or isolated.

18. [MEDIUM] [Claude] [consistency] §6 R3 "costs nothing" vs §5.2's accepted loss for `facts.sgn` on compound operands — → Reword R3: precision kept unconditionally for closedness and the `0`/`1` literal value; for sign only at pure leaves, with the compound-operand loss named inline.
