# Observable Program changes and witnesses

These are intentional changes under the accepted rules, distinct from defects
that the patch must repair. Final validation and accounting are reported
separately. Source witnesses are also pinned by the named tests.

| Kind | Rule / observable change | Witness and required result |
| --- | --- | --- |
| Public container | Parsing always yields Program, including empty/single statement input | `parseEpsil('5')[0]` is `['Program',5]`; empty input is `['Program']`. Parser payload tests extract a single operand only for grammar assertions. |
| Runtime / P1 | Program uses caller scope; Block always uses lexical scope, including direct host evaluation | `do {let x=2;x};5` yields5 without publishing x; direct Block tests construct Block explicitly. Host Block per-statement epochs and library-constant deferral are retired. |
| Runtime / P2–P5 | Shared preparation hoists types, protocols and accepted function declarations before ordinary statements | `let a=h(1);function h(x){x+1};a` yields2; `let a=h(1);let h=x=>x+1;5` still diagnoses read-before-declaration. A function value can write the persistent Program variable in `let t=0;let g=k=>do{t=k+1;t};[g(1),t]`, yielding[2,2]. |
| Runtime / P7 | Declaration admission uses authored order; a later Program may replace its caller binding | `const c=1;function c(x){x};c` retains1 and reports one later duplicate with the first site. A bad first initializer reserves its name within that Program. Notebook replacement controls remain. |
| Runtime / clause ordering | Existing clause collision admission remains separate from value assignment | `f(n)=1;f=(x=>42);f(m)=2;f(0)` yields42 and one function-redefinition at the refused second clause. |
| Public type / runtime | Mutable numeric contracts use existing Block widening, not initializer literals | `let x=1;type(x)` gives number; assigning a string is refused and retains1. Explicit annotations remain strict. Numeric collection widths are erased under the same existing widener. No new real default is introduced. |
| Public type / runtime | Callable variables and callable aliases use coarse function contracts; replacements do not promote them to operators or pin the first replacement signature | Integer function followed by string function followed by integer function accepts both replacements; the last string argument is refused by the current integer literal. Explicit arrows and const writes retain their original contracts. |
| Runtime / callable value | The current function value retains parameter names, defaults, partial application, closure and effects | `function bob(x:number,factor:number){x*factor};let alias:function=bob;alias(3,factor:5)` yields15. The binding stays function; host nameless-signature controls remain. |
| Runtime / P2 captured types | Later declarations settle the literal's captured type during common preparation | `let g=x=>[-x,y];let y="abc";g(3)` yields[-3,"abc"] rather than a history-derived vector type error. Host captured-value contract controls remain. |
| Runtime / P9 | Final declarations and assignments yield Nothing; ordinary values remain | `let x=1` and `x=2` finish with Nothing. `let x=1;x` yields1. A final function name remains that name. Direct underlying store operators retain their assigned value. |
| Diagnostic | Flow facts are read-only, attached to canonical uses and conservatively discarded | Integer calls through `let x=1.5` and `let x:number=1.5` retain a bad-call diagnostic without refining x's binding contract; destructuring writes discard stale scalar facts. |
| Diagnostic / P2 | Earlier function bodies see later constant contracts; invalid ordinary earlier uses still fail | `function f() scope {c=2};const c=1` reports constant-assignment; `do{c=2};const c=1` reports read-before-declaration. First-site notes and error source spans remain. |
| Diagnostic / P2–P9 | Refused function declarations can be reported before an ordinary final declaration returns Nothing | Protocol-property pure-function tests assert the refusal through diagnostics and verify that caller objects are unchanged. Duplicate static/runtime reports are suppressed without dropping human detail. |
| Diagnostic / invalid input | An invalid valueless declaration does not prevent the following undecided loop from reporting its condition | `let x;while x!=5{x=5};x` reports declaration-without-value and an incompatible boolean condition; the body does not provide the missing value. |
| Public API | Execute adapters expose existing statement hooks and budgets | onStatement reports original source index/range in canonical execution order; statementTimeLimitMs supplies a per-statement budget. Sync/async cancellation and debugger exception identity are tested. |
| Compilation | Program is adapted to the existing Block compiler, without publishing declarations or requiring checker compilation | Program compile tests retain values and isolate publication. Three previously expected failures now pass the original compilation assertions. |
| Compilation decline | Stable widened contracts can remove prior inferred-shape coverage | The original unannotated loop-filter input remains interpreted as[4,5,6] but declines compilation because number does not prove the inferred integer callback annotation. An explicit list<integer> fixture compiles the same output. A persistent abstract collection declines At; the original lexical Block control still compiles5 through its existing array guard. No compiler handler or shape analysis is added. |
| Shared math consumer | Existing implicit-limit function extraction is reused when there is no eligible numeric implicit variable | `function f(){let L=[1,2];limit(sum(L),1)};f()` changes1→3; the length version changes an unevaluated result→2. Explicit-variable controls remain. |
| Shared canonicalization guard | Runtime-local zero values must be evaluated before symbolic quotient cancellation | `let x=0;x/x` remainsNaN. The matched baseline gives1 for `const x=0;x/x`; the candidate givesNaN. Runtime-local aliases defer cancellation too. Host-declared constant-zero quotients remain1 in both arms (CE-1361). Existing numeric context is unchanged. |
| Serialization | Program JSON must preserve authored order while internal operands stay canonical | `const W=5;function f(k=W){k+1};f()` and fresh-engine reboxing of its JSON both yield6; default admission cannot be bypassed by avoiding serialization in tests. |

The three authorized Tycho changes recognize Program roots in the existing
prelude and notebook consumers. They retain their current preparation and
publication owners; they are not a Document migration.
